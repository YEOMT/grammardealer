## 0.3 현재 결정

- 새 언어는 기존 0.2.2 registry를 복제·확장한다. 옛 registry/원정 계약은 유지한다. 문법 판정은 지역·룬·해금과 독립적이며 원본 유한 VP 시간 증거와 보너스 대상 분석을 분리한다.
- WILL → 완료 HAVE → 진행 BE → 본동사의 유한 4카드 체인을 기존 bounded parser에 연결한다. 전체 NLP 엔진이나 수동태/비교를 추가하지 않는다. 본동사가 Frame을, 첫 유한 형태가 주어 일치·시간 계열을 결정한다. 같은 철자는 문맥으로 연결하고 독립 read의 명시적 과거 선택만 별도 존중한다.
- 골렘은 순수 단일 활성 부위 제안으로 처리한다. RunController만 카드·턴·피해·milestone을 커밋하고 Presentation은 확정 before/after만 표시한다. 초과는 다음 부위나 재화로 이월하지 않는다.
- 사용자 확정 문형·시간·룬 배수와 설계 초깃값 HP를 그대로 사용한다. 자동 정책의 정상 패배를 줄이기 위한 배수/HP 조정은 하지 않았다.
- 과거 무작위 실습 손패 검사는 0.2.2 언어 계약으로 고정한다. 새 실습은 실제 고정 카드와 동일 점수 엔진을 쓰며 0.3 일반 시작 손패 10,000건도 별도로 검사한다. 옛 assertion을 삭제하거나 완화하지 않는다.
- 고정 학습 예문 UI는 제거하되 검수 데이터는 보존한다. 읽기 전용 최신 교육 재검토와 과거 원정 실행/집계는 분리한다.
- branch/PR만 공개한다. Pages workflow는 기존 main 전용 조건을 유지한다. 이 절 이후의 버전별 결정은 역사적 기록이다.

아래 0.1/0.1.1 절은 당시 결정을 보존한다. 현재 0.2 변경은 마지막 절과 0.2 변경 명세가 우선하며, 실행 결과는 `TEST_REPORT_0.2.md`를 따른다.

- 문법/점수/룬/스테이지/연출은 독립 모듈, 상태 커밋은 RunController에서만 한다.
- 기술: Node 24.19.0, Vite 8.3.2, Node 내장 테스트, Playwright Chromium. 설치 버전은 package-lock.json에 고정.
- 공개 배포/계정 연결 없이 소스와 정적 빌드 ZIP을 제공한다.

## 제작목록과 지원 범위

- 제작목록 116개를 모두 데이터로 옮겼다. `recently` 한 개는 대표 용법이 과거·완료 Pack에 의존하므로 현재 덱·보상에서 비활성화했다. 나머지 115개는 등록된 대표 현재형 용법을 검사했다. 이는 명세의 불확실한 어휘 제외 원칙에 따른 것이며 미래 시제를 성공 처리하지 않는다.
- 내부의 SVC 형용사/명사구와 be 위치 구문 Frame은 1·2·3형식의 실제 판정을 위한 구분이다. 4·5형식 Pack을 활성화하지 않는다.
- 같은 표면형의 대명사 형태(예: `you`)는 형태 메뉴의 주격·목적격 설명과 고유 Form ID로 구분한다. 물리 카드를 복제하지 않는다.
- 관계 연결선과 면역으로 0 피해가 되는 사례는 명시적인 격리 연출/엔진 fixture다. 실전 콘텐츠나 문법 지원으로 계산하지 않는다.

## 구현·검증 환경

- Node 테스트는 이 작업 환경의 자식 프로세스 격리 제한을 피해 `--test-isolation=none`으로 실행한다. 실패 canary가 실제 실패하는 것을 확인했으며 0.1 최초 보고서는 당시 188개 개별 테스트 실행 로그를 사용했다. 현재 결과는 TEST_REPORT를 참조한다. 테스트 파일 수만 집계하지 않는다.
- Playwright 1.51.1과 해당 Chromium을 설치해 실행했다. 브라우저 버전은 실제 검증 환경 기록이며 최신 브라우저 지원을 보장한다는 뜻이 아니다.
- UI 최대 카드 수 검사에는 합성 배치 fixture가 포함된다. 전체 전투 완주는 실제 드로우·카드·형태·턴·보상을 사용하는 별도 Controller 및 배포 브라우저 검사로 입증한다.
- 저장 실패는 실제 IndexedDB 트랜잭션 중단을 주입해 복구를 검사한다. 디스크를 실제로 채운 quota 실험과 구분한다.
- 한글/이모지 캡처를 위해 검증 Linux에 로컬 Noto 글꼴을 설치했다. 게임은 외부 웹폰트를 요청하지 않는다.

## 0.2 언어·점수·레거시 정책

- 이번 출발점은 기존 소스 이관 및 UI 배치 수정이 병합된 작업 시작 시점 최신 `origin/main`이다. 과거 Work ZIP을 다시 소스 기준으로 적용하지 않는다.
- 기존 NP/PP parser에 IO와 DO를 합성하는 작은 SVOO 분기를 추가했다. give/show/make/send의 실제 binding만 활성화하고 다른 예약 문법은 유지한다. 문법 정오는 지역 해금과 분리하며 새 0.2 Stage1에서도 SVOO를 판정한다.
- `registryForVersion`은 공통 모듈에서 동결된 현재/레거시 view를 선택한다. 레거시 view는 기존 카드/형태/후보 순서와 1~3형식 범위를 유지한다. 별도 복제 엔진이나 이전 원정을 자동 확장하는 마이그레이션은 만들지 않는다.
- `send`와 `for` 외에 필수 문법 사례의 `picture`가 기존 데이터에 없었으므로 최소 명사 카드 한 장을 추가했다. 세 신규 정의는 모두 starterEligible=false다. 기존 28장 시작 덱 역할 분포·기존 카드 ID·등급·현재형은 그대로다.
- SVO+to/for의 대응 관계는 비점수 metadata다. 같은 PP를 두 번 가산하거나 4형식으로 재분류하지 않는다. for의 다른 정상 수식 용법은 전역 오류로 거절하지 않는다.
- SVOO ×2, 토파즈 ×1.5/2/2.5는 신규 명세값이다. 기존 카드·완전문장·수식·열 종류 룬 수치는 유지한다. 후보 풀은 기본 열 종류 + 현재 원정에서 실제 해금된 토파즈이며 runtimeReady만으로 자동 해금하지 않는다.
- 한글 참고는 구조/선택 형태로 만들되 문법·점수와 분리한다. SVOO의 작은 오류나 불확실한 템플릿은 성분별 뜻으로 표시한다. 소유한정사를 단순 주어 대명사 뜻으로 번역하지 않고 해당 역할의 선택 surface를 사용한다.
- 테스트의 기존 미지원 4형식 기대값은 삭제·완화하지 않고 0.1.x registry context로 명시했다. 별도 0.2 테스트로 실제 허용 문형을 검증한다. 현재 데이터 개수 119/118과 활성 룬 11에 맞춰 수량 기대값과 생성 조합 목록을 확장했다.
