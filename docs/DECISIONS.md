# 구현 결정

모든 수치와 범위는 첨부 명세를 유지한다. 신규 기능 기획 또는 밸런스 변경 없음.

- 데이터는 순수 ES 모듈로 작성하여 Node 테스트와 Vite가 같은 registry를 사용한다.
- 문법/점수/룬/스테이지/연출은 독립 모듈, 상태 커밋은 RunController에서만 한다.
- 기술: Node 24.19.0, Vite 8.3.2, Node 내장 테스트, Playwright Chromium. 설치 버전은 package-lock.json에 고정.
- 공개 배포/계정 연결 없이 소스와 정적 빌드 ZIP을 제공한다.

## 제작목록과 지원 범위

- 제작목록 116개를 모두 데이터로 옮겼다. `recently` 한 개는 대표 용법이 과거·완료 Pack에 의존하므로 현재 덱·보상에서 비활성화했다. 나머지 115개는 등록된 대표 현재형 용법을 검사했다. 이는 명세의 불확실한 어휘 제외 원칙에 따른 것이며 미래 시제를 성공 처리하지 않는다.
- 내부의 SVC 형용사/명사구와 be 위치 구문 Frame은 1·2·3형식의 실제 판정을 위한 구분이다. 4·5형식 Pack을 활성화하지 않는다.
- 같은 표면형의 대명사 형태(예: `you`)는 형태 메뉴의 주격·목적격 설명과 고유 Form ID로 구분한다. 물리 카드를 복제하지 않는다.
- 관계 연결선과 면역으로 0 피해가 되는 사례는 명시적인 격리 연출/엔진 fixture다. 실전 콘텐츠나 문법 지원으로 계산하지 않는다.

## 구현·검증 환경

- Node 테스트는 이 작업 환경의 자식 프로세스 격리 제한을 피해 `--test-isolation=none`으로 실행한다. 실패 canary가 실제 실패하는 것을 확인했으며 0.1 최초 보고서는 당시 188개 개별 테스트 실행 로그를 사용했다. 현재 결과는 TEST_REPORT를 참조한다. 테스트 파일 수만 집계하지 않는다.
- Playwright 1.51.1과 해당 Chromium을 설치해 실행했다. 브라우저 버전은 실제 검증 환경 기록이며 최신 브라우저 지원을 보장한다는 뜻이 아니다.
- UI 최대 카드 수 검사에는 합성 배치 fixture가 포함된다. 전체 전투 완주는 실제 드로우·카드·형태·턴·보상을 사용하는 별도 Controller 및 배포 브라우저 검사로 입증한다.
- 저장 실패는 실제 IndexedDB 트랜잭션 중단을 주입해 복구를 검사한다. 디스크를 실제로 채운 quota 실험과 구분한다.
- 한글/이모지 캡처를 위해 검증 Linux에 로컬 Noto 글꼴을 설치했다. 게임은 외부 웹폰트를 요청하지 않는다.

## 0.1.1 수치 변경과 보존

패치 명세에 따라 시작 덱 28장, HP 91/156/286, 남은 행동 턴 ×1 재화, 슬롯별 혼합 보상으로 변경했다. 카드·형식·완벽문장·지역 점수, 룬 10종의 수치, 턴/교환/손패/문장 한도는 보존했다. be 원형 진단은 명세의 단일 -10이다. 지정되지 않은 추가 밸런스 보정은 하지 않았다.

기존 보상 단위·30장·빠른 연출을 기대하던 테스트는 제거하지 않았다. 레거시 보상 검사는 version 0.1.0 fixture로 남기고 신규 혼합 보상 검사를 별도로 추가했다. 덱/공격/완주 기대값은 0.1.1 수치로 갱신했다. 기존 행동 테스트의 준비된 비튜토리얼 상황은 설명 ACK를 명시하고, 실제 가이드 경계는 신규 테스트로 검증한다.

이번 기준 소스는 사용자 제공 0.1 source ZIP과 실제 작업 폴더의 일치를 확인한 뒤 수정했다. 원본 해시와 대조는 evidence-0.1.1/baseline-identity.json. 과거 보고서는 history/0.1에 보존하고 이번 PASS로 합산하지 않는다.
