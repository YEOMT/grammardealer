# UI·테마 검토 0.8

기존 grid/손패·조합대/룬/조작 영역을 유지하고 Stage 8에만 남청색 수로 반사, 낮은 대비의 석조 선, 청동 문 장식을 더했다. 하늘섬의 구름/부유섬을 복제하지 않는다. 수문장은 기존 emoji 방식의 기마기사와 CSS 문 실루엣이며 처치 IMPACT와 완료 화면에서 열린 문을 표시한다. 인장 해제만으로 처치나 경로 개방을 선언하지 않는다.

항상 보이는 안내는 한 문장 안의 주격+목적격, 생략 가능, 공격 간 누적 없음, HP 1 보호를 나눠 짧게 표시한다. 상세 공략은 44px 버튼으로 연다. 진행 체크박스와 편집 중 정답/점수/인장 자격 미리보기는 없다.

확정 후 실제 선행사와 관계절 첫 카드를 얇은 청동선으로 연결하고 실제 절 범위에 푸른 테두리를 표시한다. 주격/목적격/관계부사와 생략 라벨을 공격 종료까지 유지한다. 관계사 생략은 작은 설명이며 가상 카드가 아니다. 질문은 도감에서 별도 역할로 표시하며 보스 조건으로 쓰지 않는다.

지정 상태 검사는 Chromium/Firefox/WebKit에서 실제 카드·형태 버튼·제출·선택·상점·IndexedDB를 조작한다. 해상도는 1024×768, 1280×800, 1366×768, 1920×1080이며 10/14손패·16조합·4룬을 검사한다. 실제 초과 손패의 가로 스크롤과 룬 세로 스크롤은 기존 동작이다. 숨기거나 자르거나 전체 화면을 축소해 PASS 처리하지 않는다.

개발 중 확인한 문제와 조치:

1. 로컬 서버 접근 거절/초기 응답 지연은 navigation 전에 발생했다. 권한 범위를 localhost 검증으로 맞추고 응답을 확인한 뒤 재실행했다. 원인을 확정한 게임 오류로 보고하지 않는다.
2. 관계절 라벨이 다음 채점 이벤트에서 곧 지워져 가독성 검사가 실패했다. 제출 후 연결 근거를 공격 종료까지 유지하도록 개선했다.
3. 작은 해상도에서 조작 버튼의 실제 높이가 43px였다. Stage 8 버튼 최소 높이를 44px로 설정했으며 오차 허용치를 바꾸지 않았다.
4. 캡처 검토에서 신규 QA harness가 본 앱의 `beginPresentation()`과 OS reduce 옵션을 생략한 사실을 발견했다. harness를 본 앱의 시작/설정 전달과 일치시키고 점수 표시 assertion을 추가했다. 앞선 114 checks 결과를 최종 점수·OS reduce 검증으로 재사용하지 않는다.

최종 엔진별 검사 수·캡처·영상 출처는 [검증 보고](TEST_REPORT_0.8.md)와 `validation/v0.8/`를 따른다. WebKit 자동화는 실제 Safari/iPad 검사가 아니다. 영상은 무음이며 스피커 청취·학생 사용성·교사 최종 검수는 NOT_RUN이다.
