# 다음 작업과 재개 지점

현재 구현 파일을 이어서 사용한다. 첨부 명세·`DECISIONS.md`·`PROGRESS.md`·`TEST_REPORT.md`를 먼저 읽고, 이미 검증한 엔진을 다시 작성하지 않는다. 이 문서는 후속 작업의 순서를 남기며, 미래 기능이 이미 구현되었다는 뜻이 아니다.

## 0.1 재개 또는 수정

1. `npm ci` 후 `npm test`, `npm run validate:data`를 실행한다. 바뀐 파일과 관련된 실패를 먼저 해결한다.
2. `TEST_REPORT.md`에서 미실행/실패 항목을 확인한다. 실제 브라우저에서 이름 → 설정 → 문장 편집 → 세 전투 → 첫 룬 → 보스 → 완료 → 새 원정을 확인한다.
3. 저장 3슬롯, 동결 보상 재로드, 실패한 저장, 무효 문장, 마지막 턴 승리, 교환·준비·룬 교체 취소를 변경 범위에 맞춰 재검사한다.
4. UI를 수정했다면 지정 네 viewport와 터치 에뮬레이션을 다시 확인한다. 실제 iPad·저사양 학생 기기의 미실행 항목은 별도의 실기기 검사로 남긴다.
5. `npm run build`로 새 정적 빌드를 만들고 임의 하위 경로/새로고침/로드 후 오프라인 진행을 확인한다. 소스 ZIP과 배포 ZIP을 함께 다시 생성하고 결과를 기록한다.

## 유지할 경계

- 문법 판정은 제출 뒤에만 공개한다. 샌드박스 자동 분석을 실전 편집 화면으로 옮기지 않는다.
- Grammar에는 점수·룬·보스 정보를 넣지 않고, Presentation에는 피해 계산이나 보상 지급을 넣지 않는다.
- 실제 상태 변경은 Controller가 검증한 제안 상태의 커밋으로 유지한다.
- 형태는 물리 카드 slot의 선택이며, 카드 합성으로 여러 단어를 한 장에 넣지 않는다.
- 첫 룬 기회는 매 원정 1-2에서 유지한다. 프로필 첫 소개와 매 원정 보유 룬을 혼동하지 않는다.
- 새 고급 문법을 검사하지 못하면 안전하게 미지원으로 반환한다. 미래 메타데이터를 성공 판정으로 사용하지 않는다.
- 밸런스 수치를 바꾸면 이전값·근거·새값·영향·재검증을 `DECISIONS.md`에 남긴다.
