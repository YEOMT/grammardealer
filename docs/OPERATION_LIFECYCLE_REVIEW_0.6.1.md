# 0.6.1 운영·입장·상점 수명 검토

이 문서는 실제 구현과 지정 상태 검사의 근거다. 첨부 JSON의 최초 `NOT_RUN`을 과거 통과 기록으로 사용하지 않았다. 자연 원정과 production UI의 실제 결과는 `TEST_REPORT_0.6.1.md`에 따로 기록한다.

## 효과와 소유 경계

| 영구 운영 | +0 획득 | +1 획득 | +0 사용 후 | +1 사용 후 |
|---|---:|---:|---|---|
| 보급 | 최대 2 | 최대 2 | 사용 완료 | 버린 더미 |
| 탐색 | WORD 1장 선택 | WORD 1장 선택 | 사용 완료 | 버린 더미 |
| 명사 탐색 | 최대 2 | 최대 3 | 사용 완료 | 사용 완료 |
| 동사 탐색 | 최대 2 | 최대 3 | 사용 완료 | 사용 완료 |
| 형용사 탐색 | 최대 2 | 최대 3 | 사용 완료 | 사용 완료 |
| 연결어 탐색 | 최대 1 | 최대 2 | 사용 완료 | 사용 완료 |
| 재활용 | 무작위 최대 1 | 무작위 최대 2 | 사용 완료 | 사용 완료 |

영구 운영은 최대 +1, WORD는 최대 +3이다. 사용 완료는 전투당 사본별 1회라는 뜻이며 다음 전투에 영구 사본이 돌아온다. 사슴의 빙정 탐색은 기존 탐색 정의의 임시 OPERATION 사본으로, +0 고정·연마 불가·결정 파괴 불가다. 새 보상 정의나 영구 소유 카드가 아니다.

`data/operationSpec.js`는 버전·연마·수명을 받아 획득 수/대상/방식/목적지를 반환한다. `cardCatalog`의 `maxPolish/canPolish`를 보상·상점·저장·UI가 공유한다. 운영 연마 결과에는 WORD의 `beforeScore/afterScore`를 만들지 않는다.

## 원자적 이동과 재사용

`operations`는 RunController 소유 제안에서만 이동한다. 손에서 source를 제거한 다음 기존 DRAW/DISCARD를 대상으로 효과를 해결하고, 마지막에 +1 보급/탐색 source를 DISCARD 앞에 놓는다. 다른 운영 source는 EXHAUSTED에 들어간다. 성공 후 FINISH는 표시 잠금만 풀며 추가 드로우나 이동을 하지 않는다.

획득 수는 `min(요청 수, 실제 대상 수, handLimit - (사용 전 handCount - 1))`이다. 만패에서도 source 자리 한 칸만큼 획득한다. 대상 0장이면 카드·턴·교환·재화·RNG·Undo·사용 이력이 모두 불변이다. 보급의 재셔플에 사용 중 source를 먼저 넣지 않는다.

품사 탐색은 현재 DRAW의 canonical lexeme를 앞에서부터 읽으며 남은 카드 순서를 보존한다. `her`는 PRONOUN, `reading`의 lexeme는 VERB, `bigger`의 lexeme는 ADJECTIVE다. 연결어는 and/but/or/because/when/if/that만 대상으로 한다. 직접 탐색은 공개 정렬 목록을 읽고 실제 선택 ID 하나만 옮긴다. 재활용은 실제 DISCARD에서 deck RNG로 중복 없이 균등 추첨하며 나머지 순서를 보존한다.

새 영수증은 source의 연마/수명/목적지, 명령·revision·effect/sequence, 전후 모든 관련 pile과 RNG, 실제 획득 ID 및 그 당시 사본 snapshot을 가진다. `operationHistory`는 같은 순수 이동 함수를 재생해 기록을 검증한다. 같은 +1 source를 다시 뽑아 새 명령으로 쓰는 것은 정상이다. 같은 명령이나 FINISH를 다시 보내는 것은 효과를 다시 정산하지 않는다.

## 수급·연마 거래

0.6.1의 세 상점은 각각 1룬/1WORD/1OP, 2룬/2WORD/1OP, 2룬/2WORD/1OP다. 마지막 카드 칸만 영구 운영 7종 중 같은 가중치로 한 번 뽑는다. 다른 WORD 칸에는 운영 분기를 실행하지 않는다. 이 동일 가중치는 명세의 구현 초깃값이다. 가격은 일반 6·고급 10·희귀 14, 연마 8 및 방문당 1회다. 유료 제거의 누적 가격과 고정 상품은 유지한다.

혼합 보상은 기존 외부 타입·희귀도 가중치 뒤의 20/80 분기만 확장한다. 같은 희귀도 운영 후보를 균등 선택하고 offer당 운영 최대 1개, 지역 관련 보호 칸과 첫 실습의 WORD-only 정책을 유지한다. 공개 연마 대상에는 운영 +0이 들어가고 +1은 빠진다. 취소와 중복 확정은 소비하지 않는다.

Stage 4는 현재 영구 WORD만 보고 직접 절 연결어가 없을 때 and/but/because 중 한 장을 선택한다. that 단독은 자격을 채우지 않는다. think/that 부족분은 선택 확정과 함께 최대 3장까지 지급한다. pending choice는 기존 STAGE_INTRO에 저장하고, 선택 전에는 카드나 새 상점을 만들지 않는다. 선택 후 제거·재입장·중복 명령으로 다시 지급하지 않는다.

## 실제 집중 검사와 구분

`tests/v061-operations.test.js`는 O001~O069의 운영 경계를 지정 물리 카드 상태에서 실제 Controller 명령으로 검사한다. 60번의 같은 턴 수동 보급 재사용과 저장 복원 후 61번째 사용, 탐색→재활용→같은 탐색, 각 +0/+1/0대상/만패, 실제 필터 순서, 영수증 위조, 스핑크스 봉인 교환·회수, 임시 탐색 저장·패배 정리를 포함한다. 이 유한 stress의 상한을 게임 사용 제한으로 옮기지 않았다. 공격/HP를 대입한 승률이나 자연 완주 검사도 아니다.

`tests/v061-progression.test.js`는 Stage 4 자격과 고정 선택·원자적 명령·저장 복원, 세 상점의 칸/가격/고정 RNG, 모든 운영의 도달 가능성과 +1 연마, 보상 분기·상한·취소를 검사한다. 140개 고정 상점 seed에서 7종 모두 실제로 나왔으며, 이는 사람의 구매 분포나 장기 확률의 통계적 합격 선언이 아니다.

`tests/v061-save-integrity.test.js`는 세 상점 각각의 실제 운영 구매와 +1 연마 전후에 상품·가격·서비스·RNG 전체를 직렬화/복원한다. 미사용 임시 탐색의 실제 교환→재활용, 과거 0.6 저장에 신규 5종 주입 거부, 사용한 운영 사본을 실제 승리 보상으로 제거한 뒤에도 저장 가능한 경계까지 확인한다.

최종 집중 명령은 `node --test tests/v061-operations.test.js tests/v061-progression.test.js tests/v061-save-integrity.test.js`이며 **97/97 PASS, 실패·skip 0, 종료 코드 0**이다. 각각 66/26/5개의 실제 Node 검사다. 전체 단위·데이터·빌드 검사의 수치와 혼용하지 않는다.

개발 중 다음 검증 누락을 실제 실패 테스트나 실행 probe로 재현하고 수정했다.

초기 운영 58/58 통과 후 추가 59번째 검사에서 첫 누락을 발견했고, 확대 감사 88개 중 4개가 실패했다. 수정 후 92/92, 마지막 저장 검사를 추가한 97/97이 통과했다. 새 저장 검사의 최초 2개 실패는 지정 fixture의 Stage2 룬 슬롯 수 및 이전 설원 임시 사본 정리 오류였다. fixture만 바로잡았으며 이를 게임 버그로 보고하지 않는다. 기존 실패 로그와 첫 PASS 기록을 보존한다.

상세 O001~O069/P001~P050 범위는 [실행 결과 JSON](validation/v0.6.1/operation-progression-results.json)에 기록한다. 이 집중 실행 기준으로 O068의 실제 탭 숨김·UI 예외, P017의 실제 창 닫기, P042의 설원 승리 cleanup, P044의 과거 운석 수치, P045의 이전 완료 경계, P049의 위조 임시 운영 조합대 저장은 **NOT RUN**으로 남겼다. 각각의 Controller 부분 통과는 함께 적었으며, 다른 브라우저·레거시 검사 근거가 있어야 전체 항목의 상태를 올릴 수 있다.

집중 원본 로그는 `.local-validation/v061/operations-focused*.log`, `operations-progression-integrity-audit.log`, `operations-progression-save-final.log`, `save-integrity-focused*.log`, `progression-*.log`에 보존한다. 최종 단위/브라우저/production 결과는 `TEST_REPORT_0.6.1.md`와 `docs/validation/v0.6.1/`의 해당 실행 증거를 따른다.

설원 덱 검사 도구는 새 기본 0.6.1을 사용하며 `SB_SNOW_CAMPAIGN_VERSION=0.6.0`으로 과거 정책을 선택할 수 있다. 임시 WORD만 기존 셔플/예문/가시성 보정에 넣고 지원 OP를 마지막에 추가한다. 원래 28장·고정 have·문장 witness·빙정 접근성·보존 검사는 유지했고, 기존 6장 및 DRAW/RNG가 지원 추가로 변하지 않는지와 보스 7번째 지원 사본을 추가로 확인한다. 두 버전 각각 20개 opening smoke 검사는 통과했다. 공식 10,000개 실행 결과는 최종 보고서의 별도 결과를 따른다.

## 레거시 보존

0.6 이하의 운영 정의는 기존 보급/탐색 2종·연마 +0·EXHAUSTED 정책 그대로다. `operationPool`의 이전 경로는 원래 분기 조건과 단일 후보 선택의 RNG 소비를 유지한다. 이전 Stage 4의 최대 4장 지급, 상점 schema와 상품, 보상 후보·룬 정책도 원정 버전으로 분리한다.

기존 0.6 테스트가 새 원정 기본값을 상속하지 않도록 `legacy-060-controller`에 원본 contentVersions/manifest를 고정했다. 0.3/0.4 테스트 helper는 이미 보존한 원본 golden의 버전 계약을 사용하고 0.5 helper도 전체 계약을 유지한다. 기존 golden이나 게임 기대값을 새 결과로 다시 만들지 않았다.
