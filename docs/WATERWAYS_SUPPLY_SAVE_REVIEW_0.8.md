# 수로도시 공급·상점·저장 검토 0.8

`ancientWaterways.js`는 공개된 선택 offer와 지급 receipt만 제안하고 RunController가 커밋한다. 선택은 offer ID/revision/command ID를 검증하며 RNG를 사용하지 않는다. WHO/WHICH는 고정 ID의 한 사본, NONE은 0사본이다. 그 뒤에만 shop stream으로 네 번째 고정 상점을 만든다. 이미 선택한 offer를 다시 처리하지 않는다. 제거한 입장 카드를 로드로 재지급하지 않는다.

Shop 4는 기존 두 번째/세 번째 상점과 같은 2룬·2WORD·1운영 구성, 기존 가격, 독립 연마/제거 각 1회, 누적 제거 가격을 사용한다. Stage 2/4/6 기록을 history에 유지하며 저장으로 재추첨하지 않는다.

`waterwaysFrost.js`는 8-3의 where/when만 `ANCIENT_WATERWAYS` 출처로 관리한다. 전투/종류/수량/사본 ID/연마 0/지원용·비결정 메타데이터를 검증한다. 첫 손패 교환은 기존 실제 문장 witness를 보존하고 RNG 호출 없이 이루어진다. 불가능하면 이유를 trace에 남긴다. 일반 WORD와 같이 이동·복귀·교환·보급/탐색/재활용할 수 있고, 정상 접수한 INVALID_CORE 제출도 해당 실물 사본을 소모한다. 엔진/기술 오류는 자원을 소모하지 않는다.

기존 설원·먼지는 dispatcher에서 각자의 엄격한 검증으로 들어간다. 운영 receipt의 과거 도시 카드 정의는 고정 공급 trace로 확인하며 현재 덱에 가상의 카드를 삽입하지 않는다. 전투 종료 정리 후 다음 전투에 들어가지 않고 영구 덱은 늘지 않는다.

0.8은 독립 campaign manifest/언어/점수/entry 정책을 사용한다. 운영 계약은 0.7, 기존 상점·보상·룬 계수는 0.6.1 정책을 유지한다. 기존 0.7 이하 저장은 원래 registry와 종료 경계를 사용한다. IndexedDB 이름/version, 수동 3슬롯, 개인 프로필 ID는 바꾸지 않는다. 새 프로필 보상 풀 해금은 이미 진행 중인 원정의 baseline을 바꾸지 않으며 새 시작 덱에 관계사를 자동 투입하지 않는다.

독립 기준 증거: 수정 전 registry/룬/8덱/56보상/8개 첫 상점/9공격을 포착했다. 추가로 시작 main을 **별도 읽기 전용 소스 참조**로 추출해 24개 Stage 2/4/6 상점 전체 상태를 비교했다. 추가 포착은 구현 후에 수행했으므로 수정 전 포착과 구분한다. 두 비교 모두 최신 구현의 0.7 view와 대조한다.

구체적 PASS/FAIL/NOT_RUN과 실제 슬롯 복원 범위는 최종 [검증 보고](TEST_REPORT_0.8.md)에 기록한다. 부속 자체검사는 이 결과의 근거가 아니다.
