# 테스트 행렬과 실행 시 구분

`fixtures/`는 **작성된 기대 입력/출력**이다. 게임에서 실행하거나 PASS 판정한 기록이 아니다.

## 1. 문법 48사례

`grammar_cases.json`의 각 문장을 실제 카드 사본과 registry form ID로 조립하고, parser → evidence → scoring → encounter 순서로 실행한다. 기대 mainFrame은 주절 기본 문형을 뜻한다. 비워 둔 것은 미지원·기존 세부 문형을 확인해야 함을 뜻한다.

`SUPPORTED_TARGET`은 새 지원 목표, `SUPPORTED_NO_TARGET`은 정상 기존/기본 문장이지만 새 Stage10 콤보가 아님, `FORM_ERROR_NO_TARGET`은 해당 신규 구문을 정상 채점하면 안 되는 오류다. 이 자료가 모든 오류에 무조건 동일 `INVALID_CORE` 코드를 강제하는 것은 아니다.

`OUT_OF_NEW_TARGET_SCOPE`/`SCOPE_REVIEW_NO_TARGET`은 실제 영어 가능성·현재 파서 범위를 구분해야 한다. 이 사례를 통과시키려고 미합의 문법을 추가하거나, 모든 영어에서 비문이라고 단정하지 않는다.

물리 카드맵은 문장에 필요한 최소 사본을 확인하는 참고다. 실제 lexeme/form 존재 여부, 그 단계의 보상 해금, 그 seed에서 획득했는지는 별도로 검증한다. 특히 I가 두 번 나오거나 have/can이 두 번 나오는 문장에 사본 하나를 재사용하지 않는다. 실제 DB에 없는 부수 어휘가 발견되면 동일 구문을 보존하는 등록 어휘로 교체하고 변경을 기록한다.

## 2. 계산 기대값

`encounter_cases.json`:
- 저항: 산술 24사례 + 적용 제외 5사례.
- 예견: 18사례. 정상 문형·가정법 여부를 미리 지정한 합성 입력이다. 실제 문법이 그런 근거를 생성하는지는 별도 통합 검증이 필수다.

`frost_cases.json`: 13사례. 영구 활성 사본과 각 라운드의 공급 최소량을 비교한다. 같은 카드가 선택형 would/could라고 소유 수가 달라지지 않도록 추가 검사한다.

## 4. 자연 원정 검증

실제 신규 시작 덱에서 시작하고 합법적 보상·상점·사본·룬·턴만 사용한다. 최소 1개의 완주 경로를 확인하도록 시도하고, 발견하지 못하면 시도 seed/정책/도달전투/실패 원인을 그대로 보고한다. 미지원 자동 플레이 정책 때문에 실패한 경우와 게임 자체의 결함을 구분한다.

모든 seed를 통과시키는 목표는 아니다. 가정법 전문 경로와 서로 다른 문형을 교대하는 경로를 각각 확인하고, 서로 다른 seed/덱에 대한 검토 범위를 명시한다. 보스전에 가정법 카드가 없다는 이유로 자동 보충하지 않는다.

기록: 버전/seed/보상선택/상점구매/영구덱 크기/희귀도/룬 레벨·순서/빙정수/준비·공격·교환횟수/저항전 공격력/최종공격력/실제HP감소/예견키·우회·차단/남은턴/승패이유.

합성 전투나 자동 분석 정책의 성공을 사람 플레이 난이도 또는 모바일 실기 검증이라고 부르지 않는다. 고정 공격력 산술이 6턴 완주를 보장하는 것도 아니다.
