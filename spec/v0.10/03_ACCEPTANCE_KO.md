# Stage 10 인수 조건 — 110항목

모든 상태는 작성 시 **NOT RUN**이다. 체크박스가 비어 있는 것은 게임에서 아직 검증하지 않았다는 뜻이다. 실행자는 PASS/FAIL/NOT RUN/BLOCKED와 증거 경로를 기록한다. 수치 초깃값의 적정 승률을 증명하는 표가 아니다.

## A. 기준·범위
- [ ] **A01 · 기준 소스** — 최신 main/작업 브랜치/HEAD/미커밋 변경을 확인하고 기존 사용자 작업을 보존했다.
- [ ] **A02 · 개발 버전** — 0.10.0 개발 버전과 Stage 10 기능 뷰가 일치하며 1.0/스토리 최종 완결을 표시하지 않는다.
- [ ] **A03 · 전투 수** — 새 원정 Stage 1~10은 실제 47전투이며 43~47이 Stage 10이다.
- [ ] **A04 · 전투명** — 갈림길의 광대·평행세계의 여행자·과거의 순례자·후회의 기사·운명의 직조자를 정확히 사용한다.
- [ ] **A05 · Stage 10 HP** — 2500/2900/3300/3800/5000이 실제 전투 HP와 HPMax에 일치한다.
- [ ] **A06 · 지역 콘셉트** — 야외 우주·밤하늘·거대 기둥의 회랑이며 천문대·새 실내 지역으로 변경하지 않았다.
- [ ] **A07 · 최종전 제외** — 48~50 최종 3연전/최종 상점/엔딩/승천이 이번 버전에서 활성화되지 않는다.
- [ ] **A08 · 덱·턴 보존** — 28장 시작 덱, 기존 품사 구성/손패/드로우/교환/6턴/16카드 규칙이 보존된다.
- [ ] **A09 · 0.9 보존** — 기존 9개 보스 HP와 기믹·다이아몬드·help·카드 희귀도/UI가 버전 누락으로 후퇴하지 않는다.
- [ ] **A10 · 범위 제한** — I wish·might·혼합/도치 가정법 등 미합의 확장을 추가하지 않았으며 기존 정상 용법도 부당하게 삭제하지 않는다.

## B. 카드·조동사
- [ ] **B01 · will 형태** — 한 will 사본에서 will/would를 선택하고 실제 snapshot/표시/분석이 선택형과 일치한다.
- [ ] **B02 · can 형태** — 신규 고급 can 한 사본에서 can/could를 선택할 수 있다.
- [ ] **B03 · 중복 카드 금지** — would/could 별도 영구 카드 및 같은 사본의 중복 사용을 만들지 않는다.
- [ ] **B04 · 원형 요구** — will/would/can/could 뒤 형태 오류가 올바른 조동사 연결로 인정되지 않는다.
- [ ] **B05 · 완료 결과절** — would/could have + p.p.의 각각 다른 물리 사본·원형/pp 연결을 검증한다.
- [ ] **B06 · 미래 오인정** — would를 lemma will 때문에 TIME.FUTURE_WILL로 채점하지 않는다.
- [ ] **B07 · could 역할** — 과거 능력/단독 가능성과 가정법 could를 구분하고 단독 could로 예견을 우회하지 않는다.
- [ ] **B08 · 형태 범위** — can의 명사·cans·coulds·ing·pp 등 미등록 용법을 자동 생성하지 않는다.
- [ ] **B09 · 시작 덱 제외** — can을 시작 덱에 추가하지 않고 기존 have 고정·help 제외 등 정책을 유지한다.
- [ ] **B10 · 등급·소유** — can 고급·일반 WORD 점수/연마/스타일을 적용하고 기존 will 등급·강화·사본을 보존한다.

## C. 문법 분석
- [ ] **C01 · 현실 조건절** — if 현재 + will/can 원형 대표 문장을 실제 카드 snapshot으로 정상 분석한다.
- [ ] **C02 · 절 순서** — if절 선행·후행 모두 결과절을 동일한 주절로 판단한다.
- [ ] **C03 · 가정법 과거** — if 과거 + would/could 원형 및 조건절 could의 대표 경로가 성립한다.
- [ ] **C04 · were 경계** — if절의 irrealis were를 지원하고 일반 문장의 잘못된 were까지 허용하지 않는다.
- [ ] **C05 · 과거완료** — had+pp를 판정하고 lexical had와 구분하며 외부 문맥을 이유로 반드시 when 카드를 강제하지 않는다.
- [ ] **C06 · 가정법 과거완료** — if had+pp와 would/could have+pp의 올바른 연결을 검증한다.
- [ ] **C07 · 현재완료진행** — have/has been -ing를 독립 근거로 분석하며 별도 라운드를 만들지 않는다.
- [ ] **C08 · 완료진행 오인정** — has been happy/read, had been -ing 등을 현재완료진행으로 오분류하지 않는다.
- [ ] **C09 · 미지원과 오류** — 모호한 혼합 조건문·미지원 용법과 실제 구조 오류를 구분하고 가짜 정상 콤보를 만들지 않는다.
- [ ] **C10 · 기존 절 보존** — 명사절 if/that, what절, 관계절, 수동/분사, 기존 형태 선택·어휘 제약을 회귀 검증한다.

## D. 채점·해금
- [ ] **D01 · 새 배율** — 조건1.6/가정과거1.8/과거완료1.4/가정과거완료2.0/현재완료진행1.8을 데이터에서 사용한다.
- [ ] **D02 · 조건/연결 중복** — 같은 if절에 조건절과 기존 LINK.CLAUSE를 중복 적용하지 않는다.
- [ ] **D03 · 가정형 시제** — 가정법 과거형을 같은 근거의 실제 과거·would 미래로 중복 채점하지 않는다.
- [ ] **D04 · 가정완료 포함관계** — 가정법 과거완료를 구성하는 had/have+pp에 하위 완료/과거완료/가정과거를 재곱하지 않는다.
- [ ] **D05 · 과거완료 중복** — 실제 과거완료 동사구에 일반 과거+완료를 중복 적용하지 않는다.
- [ ] **D06 · 현재완료진행 중복** — 동일 have-been-ing에 완료·진행·현재완료진행을 세 번 곱하지 않는다.
- [ ] **D07 · 독립 근거 보존** — 별개 절/동사구의 실제 시제·관계절·수동 등 유효 효과는 새 콤보 때문에 전역 삭제하지 않는다.
- [ ] **D08 · 지역 보너스** — Stage 10 네 학습 문법의 유효·해금 근거에 지역1.25를 공격당 한 번만 적용한다.
- [ ] **D09 · 해금 정책** — Stage 10 신콤보 해금과 분석을 구분하고 완료진행은 새 버전의 기존 완료/진행 동시 해금에 연결한다.
- [ ] **D10 · 정수·표시 일치** — 각 곱셈 버림·안전 정수·0 바닥·동일 종류 1회 및 실제 이벤트/설명이 일치한다.

## E. 빙정 공급·수명
- [ ] **E01 · 10-1** — if/will 최소1씩에서 영구 활성 덱의 부족분만 지급한다.
- [ ] **E02 · 10-2** — if/will/can 최소1씩에서 부족분만 지급한다.
- [ ] **E03 · 10-3** — have 최소1에서 부족분만 지급한다.
- [ ] **E04 · 10-4** — if/will 최소1, have 최소2. have 보유0/1/2/3이면 각각2/1/0/0 지급한다.
- [ ] **E05 · 보스0** — 10-5에 모든 보유 상태에서 빙정/무료 공략 지원이0이고 10-4 임시 카드가 이월되지 않는다.
- [ ] **E06 · 소유 기준** — 현재 손패나 선택형이 아닌 영구 활성 사본으로 계산하며 임시·제거된 카드는 제외한다.
- [ ] **E07 · 1회 생성** — 전투 재진입/저장/중복 생성으로 추가 지급하거나 소모 후 재지급하지 않는다.
- [ ] **E08 · 소멸 규칙** — 접수된 성공·실패 공격에 제출한 빙정은 소멸, 미접수 오류·단순 편집에서는 미소멸이다.
- [ ] **E09 · 분리·정리** — 빙정은 영구 덱·보상에서 분리되고 승패/이동 후 잔여분 정리·재활용 방지를 검증한다.
- [ ] **E10 · 가시성** — 기존 첫 문장 보정과 손패한도를 지키며 목표 재료 가시성·불가 사유·RNG를 검증한다.

## F. 직조자 예견
- [ ] **F01 · 초기 상태** — HP5000, 기억없음, 첫 유효 공격은 정상 피해다.
- [ ] **F02 · 동일 문형** — 같은 주절 키의 유효 일반 공격은 50%가 아니라 최종 피해0이다.
- [ ] **F03 · 문형 전환** — 다른 주절 키는 정상 피해이고 새 기억을 남긴다.
- [ ] **F04 · 가정법 우회** — 정상 가정과거/가정과거완료는 같은 문형도 우회하고 그 결과절 문형을 기억한다.
- [ ] **F05 · 거짓 우회 방지** — 일반 조건절/과거완료/완료진행/단독would·could/명사절if는 자동 우회하지 않는다.
- [ ] **F06 · 키 정규화** — SVC명사/형용사는 같고 SVO내용절도 SVO이며 문두 조건절로 주절을 잘못 고르지 않는다.
- [ ] **F07 · 기억 유지** — 준비/교환/형태/운영/모달/룬재정렬로 기억을 바꾸지 않는다.
- [ ] **F08 · 실패 악용 방지** — INVALID_CORE/0점/엔진오류/불완전주절로 기억을 초기화하지 않고 경미한 감점과 구분한다.
- [ ] **F09 · 격파 우선** — 우회 또는 다른 문형/첫타로 HP0이면 마지막 턴도 승리, 차단된 큰 공격은 승리하지 않는다.
- [ ] **F10 · 멱등성** — 동일 attackId·연출완료·watchdog 재전달로 HP/기억/턴/보상 중복 커밋이 없다.

## H. 상점·보상·원정
- [ ] **H01 · 입장 흐름** — 새 원정 도서관장 승리/보상/Stage9클리어 뒤 Stage10 소개와 상점에 진입한다.
- [ ] **H02 · 입장 상점** — 43전투 전에 기존 후반 상점 규칙을 확장한 상점이 정확히 한 번 생성된다.
- [ ] **H03 · can 후보** — can이 입장 상점과 10-1 보상부터 합법적 후보이며 보스후 해금의 순환의존이 없다.
- [ ] **H04 · 희귀도 보존** — if/will/have/기존 카드 후보·희귀도·가격·다이아몬드 추첨정책을 유지한다.
- [ ] **H05 · 무료 구제 금지** — 상점 entry receipt가 영구 can/will/have 지급이나 고정정답 재고를 만들지 않는다.
- [ ] **H06 · 서비스·이력** — 기존 제거 가격 증가/연마/서비스 횟수/이전 상점 이력/취소를 보존한다.
- [ ] **H07 · 공개 후보 고정** — 보상3중1·취소·재방문·저장 후 후보와 가격/RNG가 바뀌지 않는다.
- [ ] **H08 · 진행 정산** — 43~47 순서·승리/패배/보상 건너뛰기·중복명령을 검증한다.
- [ ] **H09 · 완료 경계** — 47승리 후 지역보상1회→STAGE10_END. 48진입이나 엔딩/승천해금이 없다.
- [ ] **H10 · 무승리보장** — 목표 카드 획득을 보장하지 않고 덱 선택/보상에 따른 정상 패배를 허용한다.

## I. 표현·학습·조작
- [ ] **I01 · 안내문** — 4개 라운드 제목/형태/한줄설명을 정확히 표시하고 독립 Iwish/완료진행 라운드가 없다.
- [ ] **I02 · 보스 설명** — 확정3문장 공략과 기억키·차단·우회 상태를 읽기 쉽게 표시한다.
- [ ] **I03 · 예상 정답 금지** — 편집 중 실제 주절/가정법/예상점수·차단예상을 새로 알려주지 않는다.
- [ ] **I04 · 형태조작** — will/would·can/could 클릭/터치/드래그 후 형태·snapshot 일치와 기존 동사 활용을 검증한다.
- [ ] **I05 · 손패 정보** — 빙정 긴 설명을 복원하지 않고 고급 can·점수·품사·연마의 정보가 겹치지 않는다.
- [ ] **I06 · 피드백 전환** — 공격 중 점수/저항/예견 피드백을 보존하고 다음 편집 때 학습 안내로 돌아온다.
- [ ] **I07 · 도감·실습** — 신규5콤보와 조동사 역할을 사후 기록/도감 및 기존 학습코스 구조에 연결한다.
- [ ] **I08 · 자료 구분** — 설명용 실습 덱·영구 원정·자연 보상 원정을 섞지 않는다.
- [ ] **I09 · 자산 폴백** — 전용 아트/BGM 미제공 또는 로드 실패에서 게임 진행이 막히지 않는다.
- [ ] **I10 · 가시성과 입력** — 현재 지원 화면/터치에서 모든 카드·상점·보상·도움말 조작이 가능하다.
