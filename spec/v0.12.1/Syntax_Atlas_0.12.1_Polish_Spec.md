## 0. 문서 우선순위와 작업 범위

### 0.1 최신 확정사항

1. `look`은 새 원정의 공급 풀에서 제외하고 **동사 smile, 1형식**으로 대체한다.
2. `room`은 새 원정의 공급 풀에서 **대체 없이 제외**한다. `game`은 기존 카드 그대로 유지한다. `bedroom`을 넣지 않는다.
3. 기본(중급)에 **write, solve, visit, gift**, 심화에 **protect, discover, result, method**를 추가한다. 이 8개 외의 추천 후보는 승인되지 않았다.
4. **hard·fast·well의 대표 형용사/부사 용법**, **answer·watch·show의 명사/동사 용법**, **too의 정도/첨가 용법**을 지원한다.
5. **try·remember + to부정사/-ing**는 이미 구현된 범위를 보존하고 실제 경로를 확인한다. **notice·remember + that절**, 신규 **discover + that절**을 지원한다.
6. **possible·necessary·clear의 가주어·진주어**, **for/of 의미상 주어를 포함한 관련 구문**을 형용사별 결합 범위 안에서 지원한다.
7. **like의 신규 전치사 용법은 보류**한다. 기존 동사 용법을 삭제하거나 약화하지 않는다.
8. 형태 선택창의 동사 원형 라벨은 **‘원형’만** 표시한다.
9. 정상 플레이에 테스트 점수·fixture 표지·데모 버튼을 넣지 않는다.
10. 간헐적인 **카드 집결→돌진 소실**을 실제 공격에서 고친다.
11. BGM은 **이전 곡 페이드아웃 완료 → 1초 BGM 무음 → 다음 곡 페이드인**으로 바꾼다. 이전 ‘3초 유지 후 크로스페이드’와 중첩하지 않는다.
12. 일반 몬스터 크기는 유지하고 **보스의 실제 보이는 체격은 일반 대비 약 2배를 목표**로 확대한다. UI 침범·잘림 방지가 우선한다.

이 명세는 `Syntax_Atlas_0.12_Followup_Form_Attack_BGM_Boss_v2.txt`의 다섯 항목을 모두 포함한다. 이전 후속 파일을 별도로 중복 실행하지 않는다. 0.12.0 전체 패치 역시 다시 실행하지 않는다. 로컬 브랜치에 이미 적용된 항목은 보존하고 미충족 부분만 고친다.

## 1. 절대 보존

### 1.1 게임과 데이터

- Vanilla JS + ES Modules + Vite, 로컬 결정론 문법 엔진을 유지한다. 외부 LLM 판정·서버·새 프레임워크를 도입하지 않는다.
- 상태 변경과 턴·HP·골드·보상 정산은 기존 RunController 경계에서만 수행한다.
- 50전투와 최종 3페이즈, 기존 HP·저항·룬 수치·기믹·상점 시점·지역 해금은 그대로 유지한다.
- 초반을 편하게 하겠다는 이유로 잘못된 영어를 정상 판정하거나 전치사·관사를 자동 삽입하지 않는다.
- 의미가 어색하다는 이유로 추가 감점을 만들지 않는다. 이번에 정한 기본 의미·구조의 언어 계약과 의미 자연스러움 평가는 구분한다.
- 기존 저장 카드·공개 보상·상점·RNG·연마·랭킹·도감·공격 기록을 보존한다. 과거 공격 재채점 금지.
- 카드 하나는 물리적으로 한 장이다. 겸용·동형 형태 때문에 카드나 점수가 복제되지 않는다.

### 1.2 화면과 연출

- 현재 헤더/몬스터 무대/상태창·조합대·룬/손패의 외곽 구역, 한 줄 손패와 페이지, 12×2 조합대, 중앙정렬, 장수별 조합 카드 스케일을 유지한다.
- 손패 하단 실제 여백, 카드와 드로우·버린 카드 더미의 높이 정렬을 되돌리지 않는다.
- 카드 외형·품사색·현재 글꼴 계열·단어 한 줄 표시를 보존한다. 새 겸용 표지는 기존 작은 표지 규칙 안에 넣는다.
- 원형 라벨 제거 외에 형태 선택창을 다시 축소하지 않는다. 영어 형태와 ‘과거분사 · p.p.’ 가독성, 패딩·간격을 유지한다.
- 점수 오버레이의 중앙 앵커, 패널 클리핑 회피, 단계별 상승, 감점/방어 구분과 공격 기록을 유지한다.
- 점수 경계 **100/300/600/1000/1500/2000/3000/4000/5000/6000/10000**를 바꾸지 않는다. UI 조작 중 정답·예상 점수는 표시하지 않는다.
- 로비·입장·상점·배경 원본·몬스터 원본·BGM 파일을 재생성하지 않는다. 추가 아트·외부 이펙트 팩은 이번 범위가 아니다.
- 소리 패널, 음소거·볼륨 저장, 패드 재생 시작/복구, 전체화면 실패 시 안내, reduced motion을 유지한다.

## 2. 단어 풀 변경과 공급 정책

### 2.1 제거/대체

| 대상 | 최신 원정 처리 | 레거시 처리 |
|---|---|---|
| look | 획득·상점·보상·신규 예문 후보에서 제외. smile 추가 | 구 저장의 look/looked/looking, 판정·기록은 유지 |
| smile | 미소 짓다, **동사만, SV** | 새 정의·새 ID 사용. look 카드 ID 재활용 금지 |
| room | 공급 풀과 신규 안내 예문에서 제외. 대체 명사 없음 | 구 저장의 room/rooms와 방/공간 용법은 유지 |
| game | 기존 정의·사본·역할 유지 | 중복 ‘대체 game’ 카드 생성 금지 |

smile의 어휘 밴드는 교체 대상 look의 기본(중급) 밴드를 계승하는 것을 기본값으로 한다. `smile / smiles / smiled / smiled / smiling`을 등록한다. `I smile.`, `She smiles.`, `They smiled.`, `Smile.`이 성립해야 한다. look의 SVC나 감각동사 성질을 복사하지 않는다. 명사 ‘미소’ 및 수동태는 이번에 추가하지 않는다.

제거는 새 콘텐츠 프로필의 공급 제외를 뜻한다. 전체 레지스트리에서 삭제하거나 기존 card.look을 card.smile로 덮지 않는다. 신규 도움말·튜토리얼/시작 덱 생성·검증용 예문에 look/room 의존이 남았는지 확인한다. 역사 테스트와 저장 읽기용 정의는 삭제하지 않는다. room 삭제가 관계부사 장소 예시를 망가뜨리지 않도록 school/home/park 등 기존 실제 단어로 새 예문만 조정한다.

### 2.2 확정 신규 어휘 8개

아래 문형은 이번 기본 지원 범위이다. 이는 해당 단어의 모든 사전적 의미를 구현하라는 뜻이 아니다. 단어 전체 정답문장 예외 목록을 만들지 말고 기존 문법 구성요소에 용법을 연결한다.

| 밴드 | 단어 | 기본 품사·뜻 | 최소 지원 범위 | 예시 |
|---|---|---|---|---|
| STANDARD | write | 동사 · 쓰다 | SV, SVO. 수여 write + 사람 + 글의 SVOO도 기존 4형식으로 연결 | I write a story. / I write you a story. |
| STANDARD | solve | 동사 · 해결하다 | SVO | I solve the problem. |
| STANDARD | visit | 동사 · 방문하다 | SVO, 사람/장소 목적어 앞에 to를 요구하지 않음 | I visit the school. |
| STANDARD | gift | 명사 · 선물 | COUNT, gift/gifts | I give you a gift. |
| ADVANCED | protect | 동사 · 보호하다 | SVO | I protect the child. |
| ADVANCED | discover | 동사 · 발견하다 | SVO, 목적어 that 내용절 | I discover a problem. / I discover that she is happy. |
| ADVANCED | result | 명사 · 결과 | COUNT, result/results | I see the result. |
| ADVANCED | method | 명사 · 방법 | COUNT, method/methods | I try the method. |

- write의 활용은 **write/writes/wrote/written/writing**. `writed`, `writeing` 생성 금지.
- solve: solve/solves/solved/solved/solving.
- visit: visit/visits/visited/visited/visiting. `visitted` 금지.
- protect: protect/protects/protected/protected/protecting.
- discover: discover/discovers/discovered/discovered/discovering.
- 새 타동사의 정상 목적어 용법은 기존 진행·완료·수동태·비정형절·관계절 처리와 연결한다. 새 동사만 수동태 화이트리스트에서 빠지는 문제를 방지한다. write의 모든 수여 수동태나 discover의 모든 wh 보어까지 새로 확장하는 것은 필수가 아니다.
- gift/visit/result의 다른 품사, method의 파생형, smile의 명사 용법은 추가하지 않는다.
- **추가하지 않음**: bedroom, message, goal, solution, device, planet, support, achieve, consider 및 기타 승인되지 않은 추천 단어.
- 모든 새 카드의 기본 점수·연마 산식은 기존 단어 공통 규칙을 사용한다. 기본값은 기존 일반 카드 수준(기본 10, COMMON, 일반 공급 가중치 1)이다. 밴드가 심화라고 점수·희귀도를 자동 상향하지 않는다. 기존 동형/동일 카드가 실제 최신 코드에 있으면 중복 정의 대신 확인·연결한다.

### 2.3 ‘단어 풀 추가’의 의미

1. 새 명사 gift/result/method는 해당 밴드의 명사 추첨 후보에 들어갈 수 있다. 고정 지급은 아니다.
2. 새 동사는 전체 획득·보상·상점 후보와 사전에서 사용 가능하게 하되 **이미 고정된 시작 동사 8장을 바꾸지 않는다.**
3. 현재 보상은 시작 어휘 밴드와 별개로 얻을 수 있는 구조다. ‘중급에 추가’를 이유로 전투 중 난이도별 배타 획득 제한을 새로 만들지 않는다. 시작 후보 밴드와 실제 보상 게이트는 분리한다.
4. 정의가 등록돼도 카드 카탈로그·manifest·상점·보상 가중치·저장 검증에서 누락되지 않게 연결한다. 단어 목록을 UI에만 넣고 실제 획득 불가인 상태로 끝내지 않는다.
5. 이전 공급 donor를 복사할 때 이미 존재하는 donor 카드의 확률·가격·자격을 덮지 않는다. 기존 생성 알고리즘 안에서 신규 후보만 반영하고, 총 드롭 규칙·룬 비율은 바꾸지 않는다.

### 2.4 시작 덱 계약 — 28장 고정

기본 배분: **명사 6 + 대명사 4 + 동사 8 + 형용사 3 + 부사 2 + 한정사 3 + 전치사 2 = 28장**.

| 모드 | 공통 4장 | 수준별 3장 | SV 1장 |
|---|---|---|---|
| BEGINNER | be×2, have×1, make×1 | see, need, like 각 1장 | go 또는 run 중 1장 |
| STANDARD | be×2, have×1, make×1 | watch, want, try 각 1장 | go 또는 run 중 1장 |
| ADVANCED | be×2, have×1, make×1 | notice, allow, remember 각 1장 | go 또는 run 중 1장 |

- smile·write·solve·visit·protect·discover를 이 고정 슬롯에 끼워 넣지 않는다.
- go/run을 둘 다 지급하거나 전치사 to/of를 무료로 덧붙여 29장 이상으로 만들지 않는다.
- free 모드와 튜토리얼의 기존 별도 정책은 보존한다. 튜토리얼의 임시 덱 때문에 원래 원정 덱에 카드가 남거나 사라지지 않아야 한다.
- 겸용 카드는 원래 대표 품사 슬롯으로 **한 번만** 집계한다. watch는 동사 슬롯, answer는 명사 슬롯이다.

## 3. 대표적인 겸용·다중 용법 보완

### 3.1 hard / fast / well

| 카드 | 유지할 대표 품사 | 추가·보완 역할 | 반드시 정상 판정할 최소 쌍 |
|---|---|---|---|
| hard | 형용사 | 노력·강도를 나타내는 부사 | The work is hard. / I work hard. |
| fast | 부사 | 빠른 상태·성질의 형용사 | You are fast. / You run fast. |
| well | 부사 | 건강한·몸이 괜찮은, 서술형 형용사 | I am well. / I work well. |

- 기존 카드 정의 하나에 역할을 연결한다. 형용사 카드·부사 카드를 따로 새로 뽑게 하지 않는다.
- harder/hardest, faster/fastest, better/best는 기존 형태를 보존하며 실제 사용 역할을 판정한다. well의 better/best와 good의 better/best를 문자열만 보고 하나의 물리 카드로 합치지 않는다.
- hard/fast는 정상 명사 수식에도 연결한다. well은 우선 be/feel 뒤의 건강 의미로 제한한다. ‘a well student’를 무조건 정상으로 만들기 위해 모든 한정적 형용사 위치를 풀지 않는다.
- 부사는 실제 동사구/부사구를 꾸민 근거로, 형용사는 실제 보어/명사 수식 근거로 기록한다. 두 역할의 콤보를 한 번에 중복 지급하지 않는다.
- 문법이 맞는 정도 수식 `very hard`, `very fast`, `very well` 및 기존 비교 구문을 보존한다.
- hardly, well=우물, fast=단식 등은 범위 밖이다. 단어 철자를 새 활용형으로 자동 생성하지 않는다.
- fast가 튜토리얼 전용 메타데이터에 묶여 있다면 최신 프로필에서 일반 부사 후보로도 획득 가능하게 연결하는 것을 기본값으로 한다. 튜토리얼 사본을 일반 덱에 복사하는 뜻이 아니다.

### 3.2 answer / watch / show 명사·동사 겸용

| 카드 | 대표 외형 유지 | 명사 의미 | 동사 지원 |
|---|---|---|---|
| answer | 명사색 | 답·대답, COUNT | SV/SVO(대답하다), answers/answered/answering |
| watch | 동사색 | 손목시계, COUNT | 0.12의 목적어 및 지각동사 원형/-ing 구조 유지 |
| show | 동사색 | 공연·프로그램, COUNT | 기존 보여주다·수여·내용/의문절 등 지원 범위 유지 |

- 명사 복수 answers/watches/shows와 동사 3인칭 단수 동형을 문장 구조로 구분한다.
- answer의 명사형에 동사형을, watch/show의 동사형에 명사형을 더한다. help 전용 설명 문자열을 재사용하지 않는다.
- show의 **showed/shown**, watch의 **watched**, answer의 **answered** 등 기존/추가 형태를 정확히 유지한다.
- 기본 색상 유지, 작은 ‘명·동/동·명’ 표시, 형태 선택과 사전/상세 설명은 데이터 기반으로 통일한다. 자동 품사 추측을 편집 중 정답 표시로 노출하지 않는다.
- 한 카드로 두 자리를 동시에 채울 수 없다. `I watch the watch.`는 별개의 watch 사본 2장이 필요하다.
- 기존 plan/work/change/help의 겸용·가산성·형태 정책은 그대로 보존한다.

### 3.3 too — degree와 additive를 구분

- `The book is too big.`: 정도 의미. 기존 `too + AP/AdvP` 및 기존 too…to 구조 유지.
- `I like you too.`: 절 끝의 첨가 의미. 정상 문장·실제 부사 근거로 판정.
- 첨가 too만으로 `DEGREE.TOO` 또는 설원 정도 보너스를 주지 않는다. 정도 표지를 찾는 문자열 검사로 두 용법을 합치지 않는다.
- `I run too fast.`와 `I run fast too.`가 모두 정상이어도, 앞 문장만 too의 정도 사용을 가진다.
- `Me too.` 같은 대화 응답/단편까지 새로 독립 공격문으로 허용하지 않는다. 명령문·완전한 절을 포함하는 현재 지원 문장 유형은 그대로다.
- ‘너무’가 긍정/부정 의미인지 등 의미 적합성 때문에 감점을 만들지 않는다.

### 3.4 try / remember / notice / discover

- try와 remember의 to부정사·동명사 목적어는 보존·재확인이다. 이미 들어간 정의를 이중 추가하지 않는다.
- notice/remember/discover에 **that + 완전한 절을 목적어로 받는 구조**를 연결한다.
- notice는 기존 지각동사 목적격보어 구조를 잃지 않는다. remember의 to/-ing를 content clause로 대체하지 않는다.
- that절은 관계절이나 독립 문장 하나로 오인하지 않는다. 주절 SVO, 내용절 경계·주어·동사 근거를 실제 카드 ID로 기록한다.
- 내용절 내부의 시제·수동·수식은 기존 엔진을 재사용한다. ‘that 다음을 전부 받아들임’ 같은 우회 금지.
- that 생략·wh 보어·새 명사적 의미는 이번 필수 확장이 아니다. 기존 지원분은 유지한다.
- like의 전치사 ‘~처럼’ 및 다른 새 용법은 추가하지 않는다. 기존 like + 명사/to/-ing 등 지원분은 그대로다.

## 4. 가주어·진주어 및 for/of 의미상 주어

### 4.1 지원해야 할 정확한 구조

A. `It + be + ADJ + to + 동사원형 …`

B. `It + be + ADJ + that + 주어 + 정형동사 …`

C. `It + be + ADJ + for + 명사구/목적격 대명사 + to + 동사원형 …`

D. `It + be + ADJ + of + 명사구/목적격 대명사 + to + 동사원형 …`

형용사는 be 뒤, to 뒤에는 동사원형이 온다. `for/of + 목적격 + to + 형용사`라는 토큰 나열 자체를 허용하지 않는다. ‘to be happy’처럼 to 다음 실제 be 원형이 있고 그 뒤 형용사가 오는 것은 기존 정상 비정형절 처리로 읽는다.

이 문서의 D는 학교문법 기준의 **가주어·진주어 계열**로 표시·보너스 처리하되, 구현 내부에서는 for 의미상 주어와 of 평가 대상의 관계를 구별한다. for/of의 모든 문법 이론상 지위를 똑같은 노드라고 주장할 필요가 없다.

### 4.2 형용사별 최소 허용 계약

| 형용사 | TO | THAT | FOR + 목적격 + TO | OF + 목적격 + TO |
|---|---:|---:|---:|---:|
| good | 기존 유지 | 기존 유지 | 지원 | 지원 |
| bad | 기존 유지 | 기존 유지 | 지원 | 이번 신규 보장 대상 아님 |
| important | 기존 유지 | 기존 유지 | 지원 | 보장하지 않음 |
| easy / hard / difficult | 기존 유지 | 이번 신규 대상 아님 | 지원 | 보장하지 않음 |
| possible | 지원 | 지원 | 지원 | 보장하지 않음 |
| necessary | 지원 | 지원 | 지원 | 보장하지 않음 |
| clear | 자동 일반화하지 않음 | 지원 | 자동 일반화하지 않음 | 자동 일반화하지 않음 |
| kind | 기본 TO도 연결 | 이번 신규 대상 아님 | 자동 일반화하지 않음 | 지원 |

- 이는 **이번에 보장할 대표 의미의 범위**이다. 빈 칸을 모든 영어 맥락의 절대 비문 선언으로 바꾸지 않는다. 기존에 다른 정상 구조로 판정되던 문장은 유지한다.
- possible/necessary에 적용한 TO 허용을 clear까지 일괄 복사하지 않는다.
- `It is good for you to run.`과 `It is good of you to help me.`를 모두 지원한다. good이 항상 of만 받는 것으로 단순화하지 않는다.
- `It is clear that she is happy.`는 정상. `It is clear.`는 지시대명사 it을 쓴 일반 문장으로도 가능하며, 뒤 절이 없는데 가주어·진주어 보너스를 주지 않는다.
- necessary의 that절은 기존 평서절 판정으로 가능한 내용을 우선 사용한다. 이번에 모든 동사에 요구·당위 원형 가정법을 추가하지 않는다.

### 4.3 구성요소와 근거 계약

- `for me`, `for the student`, `of you`, `of the teacher`를 명사구로 분석한다. I/he/she/we/they를 목적격 자리에서 그대로 정상 처리하지 않는다.
- 의미상 행위자를 뒤의 비정형절과 연결한다. 전치사구를 무관한 문장 끝 부가구로 떼어서 to부정사 주어를 잃지 않는다.
- dummy it, 주절 be, 평가 형용사, 의미상 주어 표지, 명사구, to, 비정형 동사구 또는 that 내용절의 범위를 저장한다.
- to 뒤의 목적어/보어·활용형 검사는 기존 동사별 요구를 유지한다. 명령문 지원을 빌미로 to 안쪽의 잘못된 동사형을 받아들이지 않는다.
- of/for가 있다는 사실만으로 가주어·진주어를 인정하지 않는다. 주절 구조와 뒤 절이 모두 있어야 한다.
- 새 근거를 기존 가주어·진주어 콤보·관련 룬·Stage9 지역 보너스·도서관장 회복 저지·해당 최종전 과제와 연결한다. 획득/해금 시점과 실제 판정/보너스 자격은 기존 규칙을 따른다.
- 같은 구조의 for/of와 to 부분을 중복 조각내 동일 근거를 여러 번 보상하지 않는다. 기존 서로 다른 문법 근거의 중첩 정책은 그대로 유지한다. 새 배율 추가·기존 배율 삭감은 하지 않는다.
- ‘인정’은 정확한 예문의 **VALID + 올바른 구조 근거**를 뜻한다. 예문마다 이름표만 붙이고 파싱은 실패한 채 점수만 주는 처리는 금지한다.

### 4.4 of 카드와 획득 가능성

먼저 실제 최신 데이터에 of가 있는지 확인한다. 있으면 기존 정의를 확장·재사용하고 중복 생성하지 않는다. 없다면 **지원용 기능어 `of` 한 장의 카드 정의**를 추가한다.

구현 기본값:
- 대표 품사 PREPOSITION, 기본 표면형 of, 기본 점수/연마는 기존 전치사와 동일, COMMON.
- 신규 8개 콘텐츠 단어와는 별개로, 사용자가 승인한 of 구문을 실제 조합하기 위한 지원 카드이다.
- **Stage5의 to부정사 해금 이후** 상점·보상 후보에 포함되게 하는 것을 기본값으로 한다. Stage4 보스 후 Stage5 준비 상점도 해당 시점이라면 후보가 될 수 있다. Stage9 이전에 합법적으로 얻을 수 있는 경로를 둔다.
- 기존 for/to는 재사용한다. 시작 덱의 전치사 2장 슬롯에 of를 강제로 추가하지 않는다. 무료 정답 카드 지급·손패 보장도 하지 않는다.
- 공급·언어 레지스트리·사전·형태 표시·저장 manifest까지 함께 연결한다. QA 문자열만 있는 가짜 카드는 금지한다.
- of의 모든 소유·부분·숙어 용법을 이번에 전부 새로 구현하지 않는다. 미구현 용법을 영어 자체의 오류라고 안내하지 않는다.
- 보스가 새 of 구문을 목표로 선택한다면 기존 ‘보유 카드로 가능한 과제’ 원칙을 지킨다. 공개된 과제를 UI 열기/로드 때 재추첨하지 않는다.

## 5. 사전·형태 선택·전투 준비 안내 정돈

### 5.1 형태 선택창

- 동사 원형 및 명사/동사 겸용 원형 선택지의 라벨은 **원형**만 표시한다.
- `문장 구조로 용법 판정` 문구를 원형 선택지에서 제거한다. 대신 또 다른 장문의 주석을 넣지 않는다.
- 일반 명사 단수까지 모두 ‘원형’으로 바꾸지 않는다. 과거/과거분사 · p.p./-ing형/복수·3인칭 단수의 필요한 구분은 유지한다.
- alias ID·역할 후보·저장된 선택 ID는 문구 삭제 때문에 바꾸지 않는다.
- 팝업 내 영어 형태·라벨의 확대, 일정 버튼 높이, 여백과 간격은 유지한다. 카드 종류가 바뀌어도 현재 선택이 명확하게 보이게 한다.
- 겸용 설명은 사전·카드 상세에서 단어마다 정확히 제공한다. 해당 글자가 게임의 실제 지원 용법과 일치해야 한다.

### 5.2 전투 준비 화면

0.12의 학습 안내와 실제 몬스터 그래픽 연결은 보존하며 이번 어휘 변경 때문에 잘못된 예문만 고친다. 전투 화면까지 다시 디자인하지 않는다.

4형식 안내 기준 문안:

> 목표 문법　4형식  
> 형태　주어 + 동사 + 간접목적어 + 직접목적어  
> 뜻　~에게 ~를 주다.  
> 예문　I give you a book.  
> 전투 효과　4형식 문장 사용 시 보너스 배율 적용

- ‘뜻’은 짧은 해석 틀로 유지한다. 실제 보너스 조건과 보스의 필수 해제 조건은 혼동하지 않게 짧게 분리한다.
- 신규 예문은 현재 프로필에서 실제 등록된 카드/형태로 검증한다. 삭제된 room/look, 미등록 단어를 새 안내에서 요구하지 않는다.
- 목표 문법은 고정된 전투 학습 안내이지 현재 손패를 풀어주는 정답 추천이 아니다.
- 준비 화면의 보스도 안전 슬롯에서 더 크게 표시할 수 있으나, 안내·버튼이 잘리지 않게 한다. 전투 시작/프리뷰 표시로 셔플·보상·과제 추첨을 재실행하지 않는다.
- 버리기 버튼의 커진 터치 영역, 위치와 선택 장수 표시는 보존한다. ‘조합대 비우기’와 혼동하지 않는다.

## 6. 카드 집결→돌진 소실 수정

### 6.1 확인된 정적 단서 / 미확정 원인

검토 기준 소스의 `src/engine/presentation.js`는 `atlas:viewport` 수신 시 `visualSnapshot=null`로 만들고 애니메이션·공격 레이어를 정리한다. 스냅샷은 begin에서 생성되고, charge/lunge의 mount가 스냅샷 없이 조용히 끝날 수 있다.

이는 우선 재현할 **코드 경로**이며, 사용자의 모든 간헐 소실을 실기기로 확인한 확정 진단은 아니다. 타이밍만 늘리거나 이 함수 하나만 수정하고 해결됐다고 보고하지 않는다.

### 6.2 구현 계약

- 정상 문장·효과 켜짐·reduced motion 꺼짐에서 **집결 → 돌진 → 접촉**이 매 공격에서 보여야 한다.
- 제출한 물리 카드 목록·표면형·시각 기준을 공격 ID에 귀속된 표시 자료로 보존한다. 원본 카드가 내부 상태에서 이동해도 화면 자료가 먼저 없어지지 않아야 한다.
- 같은 크기의 중복 viewport 신호에는 전체 효과를 파괴하지 않는다. 실제 크기 변경은 앵커·좌표 재측정으로 대응한다.
- CHARGE 이전 자료가 사라지면 살아 있는 현재 공격의 복사본을 복구한다. 도중 실제 resize/fullscreen 전환은 현재 단계의 남은 시간에 맞춰 재배치·짧게 이어 재생한다.
- 이미 끝났거나 취소된 공격의 복사본을 낡은 비동기 완료로 되살리지 않는다. 세션/attackId·취소 토큰을 유지한다.
- 카드의 실제 UI 컨테이너를 이동시키지 않는다. 비상호작용 복사본만 모이고 날아가며 `pointer-events:none`을 유지한다.
- 전체화면 부모·좌표계·z-index·opacity/visibility·마운트 시점·cleanup을 확인한다. 점수 오버레이가 공격 복사본을 계속 가리는지 확인한다.
- 타격점은 확대된 보스의 알파 실물/기존 명시 앵커를 사용한다. 투명 캔버스 중앙이나 촉수 끝이 기본 타격점이 되어서는 안 된다.
- HP·턴·골드·카드 소모는 기존 커밋 결과 그대로 한 번만 반영한다. 시각 복구는 재제출·재정산이 아니다.
- 효과 끄기/reduced motion은 의도된 정적 피드백을 제공한다. 사용자 접근성 설정을 강제 해제하지 않는다.
- 불완전한 문장, 0위력, 보스 차단, 탭 비활성으로 인한 중단을 정상 양수 공격 소실과 구분한다. 0피해에 성공 피격·격파를 거짓 표시하지 않는다.

### 6.3 점수 오버레이와 연동

현재 단계별 열기, 누적 점수, 카드 근거 반응, 룬 빛, 감소량/이유는 그대로 유지한다. 마지막 위력 표시가 끝나면 집결과 돌진을 가리지 않는 타이밍으로 넘긴다. 새 문법을 점수 오버레이가 자체 해석하거나 가짜 중간값으로 연출하지 않는다. UI 테두리를 넘는 효과 때문에 스크롤이나 구역 재배치가 생기면 안 된다.

## 7. 보스 크기 — 일반 몬스터는 유지

- 일반 몬스터의 현재 크기·위치·슬롯은 변경하지 않는다.
- 같은 화면에서 **일반 몬스터의 실제 보이는 체격 대비 약 2배**가 목표다. 면적만 2배가 되도록 조금 확대하는 것과 구분한다. 이미 커진 보스 배율에 무조건 또 2를 곱하지 않는다.
- PNG의 투명 캔버스가 아니라 알파 몸체 범위를 기준으로 한다. 기존 bounds/anchor를 사용하고 매 프레임 픽셀 스캔은 하지 않는다.
- 보스는 고정된 중앙 무대의 사용 가능한 공간을 충분히 쓰되, 헤더·좌측 공략·이름/HP·기믹·조합대를 침범하거나 화면 밖으로 잘리지 않아야 한다.
- 2배가 안 들어가면 안전하게 들어가는 최대 크기로 제한한다. 높이 약 85~90% 활용은 비교 시작값일 뿐, 체형과 피격 여유를 무시하는 강제치가 아니다.
- 크라켄의 촉수·닻을 포함한 공통 외곽 범위를 고려한다. 가로로 넓은 보스를 세로 기준에 맞추려고 잘라내지 않는다.
- 기본/피격 두 자세에 같은 확대·중앙축·하단 기준을 사용한다. 피격 때만 갑자기 축소하거나 발이 튀지 않아야 한다.
- 일반 몬스터를 줄이거나 무대 높이·정보 패널 위치·손패 여백·배경 크롭을 바꿔 목표를 맞추지 않는다.
- 초원 수호자, 항구 수문장 실제 그림으로 우선 확인한다. 보스 판별은 encounter 종류/명시적 메타데이터를 사용하고 이름 문자열에 의존하지 않는다. 최종 48~50도 보스 대상에 포함될 수 있게 한다.
- 그래픽이 없는 보스는 기존 fallback을 유지한다. 이번에 새 원화·프레임·HP 강화·화면 흔들림·오라를 추가하지 않는다.
- 목표 대비 제한된 보스는 이유와 실제 표시 크기만 간단히 보고한다.

## 8. BGM 순차 전환 — 최신 지시가 이전 정책을 대체

### 8.1 정상 지역 이동

**새 지역 입장화면 표시 → 이전 곡 페이드아웃 → 이전 곡 출력 0 및 종료 → BGM만 1초 쉼 → 새 곡 페이드인**.

- 기존 ‘3초 유지’를 없앤다. 크로스페이드로 두 곡을 겹치지 않는다.
- fade-out/fade-in은 각각 **1.5초를 구현 시작값**으로 둔다. 확정 핵심은 순서와 완전 종료 후 1초 쉼이다.
- 예시: 입장 시각 t=0, 구곡 fade t=0~1.5, BGM 무음 t=1.5~2.5, 신곡 fade t=2.5~4.0. 파일 로드 지연이 없을 때의 설계 예시이지 실행 측정 결과가 아니다.
- 1초를 새 지역 진입 시점부터 세지 않는다. 구곡이 아직 들리는 동안 새 곡을 아주 작게 시작해 무음인 것처럼 보고하지 않는다.
- 새 음원은 미리 로드/디코드할 수 있으나 허용 시점 전에는 들리지 않아야 한다. 늦게 준비되면 준비 후 시작하고 게임 진행은 막지 않는다.
- BGM 쉼 동안 효과음은 계속 동작한다. 전체 AudioContext나 효과음 버스를 멈추지 않는다.

### 8.2 수명·취소

하나의 취소 가능한 상태로 관리한다: PLAYING → FADING_OUT → SILENT_GAP → FADING_IN → PLAYING. 이는 구현 예시이며 새 대형 오디오 프레임워크를 요구하지 않는다.

- 같은 지역의 전투·보상·상점·팝업·재렌더에서 곡/재생 위치/전환 예약을 초기화하지 않는다.
- 보스 후 준비 상점은 이전 지역 BGM을 유지한다. 내부 데이터가 다음 stageId를 가리킨다고 먼저 바꾸지 않는다.
- 지역 소개에서 즉시 전투로 넘어가도 진행 중 순서를 유지한다.
- 로비·새 원정·다른 저장으로 바뀌면 낡은 예약/로딩 완료를 무효화하고 현재 목적지의 곡만 선택한다. 빠른 이동에서 이전 곡이 뒤늦게 켜지지 않게 한다.
- 동시 가청 BGM은 최대 1개. 끝난 소스·gain·타이머는 정리한다.
- 무음/잠금/앱 백그라운드 동안 오디오 시간이 멈췄다면 실제 재생 상태에 맞춰 복구한다. 숫자 타이머만 끝났다는 이유로 정지 중 곡들이 한꺼번에 시작하지 않는다.
- 파일이 없는 지역에는 다른 지역 음악을 임의로 반복하지 않는다. 구곡 종료 후 기존 미등록 처리로 유지한다. 로딩 실패는 게임을 멈추지 않게 한다.
- 실제로 이전 곡이 없는 첫 시작·직접 로드에는 불필요한 가짜 fade-out/1초 대기를 만들지 않는다.
- 로비 왕복의 기존 정상 처리와, BGM 기준 출력 **0.8 × 사용자 볼륨**, mute·태블릿 unlock/resume·상단 소리 UI는 보존한다. 80%를 두 번 곱하지 않는다.

## 9. 테스트 장치와 플레이 화면 분리

- 정상 전투·설정·점수·공격 기록에 fixture, 가상 점수, 데모 재생, 합성 전투 진입 버튼을 표시하지 않는다.
- 이번 작업용 별도 테스트 화면이나 플레이어용 재현 버튼을 새로 만들지 않는다.
- 테스트 코드 내부의 입력 데이터와 단위검사 도구는 사용할 수 있고 기존 테스트를 삭제할 이유는 없다. 테스트와 게임 기능을 혼동하지 않는다.
- 실제 HP·점수·랭킹은 실제 확정 AttackResolution/scoreTimeline에서만 나온다. 브라우저 확인을 위해 테스트 저장을 사용할 경우 테스트 자료라고 보고하고 자연 완주·사람 승률로 주장하지 않는다.
- 배포 번들에서 개발 경로에 접근할 수 없는지도 해당 경로만 짧게 확인한다.

## 10. 버전·저장·일관성

### 10.1 신규 규칙과 기존 저장 분리

- 새 단어 공급·삭제·새 용법은 **이번 최신 콘텐츠 정책으로 시작한 새 원정**에 적용하는 것을 기본값으로 한다.
- 이전 0.12.0 및 그 이전 원정은 저장된 덱·카탈로그·공개 제안·기존 문법 계약을 보존한다. 새 어휘 정책으로 자동 승격하지 않는다.
- UI 라벨/연출 안정화/보스 표시/BGM은 표시 계층 개선으로 기존 저장에도 적용 가능하다. 과거 카드의 언어 해석·점수 기록은 바꾸지 않는다.
- 후속 버전 식별자 및 language/content/acquisition 정책 식별자를 명시적으로 연결한다. 기존 grammar registry.version과 앱 버전이 다를 수 있으므로 모든 문자열을 무작정 0.12.1로 치환하지 않는다.
- registryForVersion, manifest, formsForCard, score/region/rune/boss 정책, 상점/보상, 진행/저장 validation의 최신 정책 연결을 점검한다. 배열에서 0.12.1만 빠져 후반 기능이 사라지는 일을 방지한다.
- 전체 버전 시스템을 갈아엎지 않는다. 꼭 필요한 최신 정책 분기만 추가한다.

### 10.2 공급 제외와 예문

새 run에서 look/room이 정상 드롭되지 않아도 구 저장의 해당 카드는 정상 렌더·형태 선택·저장/로드되어야 한다. 과거 도감/랭킹 문장의 room을 game으로 바꾸지 않는다. 새 학습 안내만 최신 풀에 맞춘다.

### 10.3 문법 변경의 효과 전파

올바른 역할·절 구조를 하나의 분석 근거에서 공급하여 문장 판정·점수·룬·지역·보스·도감이 다른 결론을 내지 않게 한다. UI 문자열/철자/선택 버튼 이름을 점수 근거로 쓰지 않는다. 특히:
- watch 명사 사용으로 지각동사 룬 발동 금지.
- 첨가 too로 정도 룬/설원 보너스 발동 금지.
- well 형용사 사용으로 부사 수식 효과 자동 추가 금지.
- for/of 의미상 주어가 붙어도 같은 가주어·진주어 구조의 판정·보너스가 누락되지 않음.
- 신규 동사로 구성한 정상 수동/완료/내용절에도 기존 해금과 점수의 동일 기준 적용.
- 명령문은 기존 정상 판정을 유지하고 전용 보너스를 추가하지 않음. 생략된 주어를 물리 카드로 생성하지 않음.

## 12. 적정 검증 — 게임 규칙은 정확히, 디자인은 짧게

동봉한 `Language_Cases.md`는 **단위검사용 기준 문장표**이다. 그대로 UI/보상에 주입하는 기능이 아니다. 하나의 짧은 테스트 파일에 묶어 검사하고, 모든 문장을 브라우저에서 반복 촬영하지 않는다.

### 12.1 필수 검사 묶음

| 묶음 | 확인할 핵심 | 범위 제한 |
|---|---|---|
| A 어휘/공급 | 새 8개+smile, look/room 제외, game 중복 없음, of 연결 | 레지스트리·공급 후보 직접 검사 |
| B 덱/저장 | 모드별28장·동사8장·고정카드, 구 저장 look/room 유지 | 고정 seed 몇 개와 구 저장 1개 |
| C 언어 | 대표 긍정/경계 문장, 형태·역할·중복점수 방지 | 문장표 단위검사, 대량 자동문장 생성 안 함 |

최종 코드에서 `npm test`, `npm run validate:data`(현재 저장소에 존재하면), `npm run build`, 변경 영역 관련 브라우저 검사를 실행한다. 프로젝트 AGENTS의 실제 필수 조건을 우선한다. 기계 검증 성공을 실기기 청취 성공이라고 바꾸지 않는다.

### 12.2 하지 않는 검증

50전투 자연 완주, 수천 seed, 전 브라우저/전 기기 교차 순회, 수백 장 캡처, 기존 모든 역사 증거 재생성은 요구하지 않는다. 테스트를 삭제·skip하거나 실패를 무시해서 시간만 줄이지 않는다. 관련 실패를 고치고 영향받은 범위만 다시 검사한다.

패드 실기기나 카톡 환경이 없으면 해당 부분은 NOT RUN으로 남긴다. 구현과 대표 확인이 끝났는데 디자인의 미세 취향 때문에 인계를 계속 미루지 않는다. 실제 플레이 피드백으로 다음 폴리싱을 이어간다.

### 12.3 완료 보고

- 실제 기준 SHA/브랜치, 변경 요약, 구현된 항목/미실행 항목.
- 언어 사례 결과와 실제 연속 공격에서 집결·돌진이 보인 조건.
- 보스 크기가 안전 제한을 받은 경우 그 이유.
- BGM 순서 및 1초 쉼이 확인된 방법(로그/실제 청취 구분).
- 테스트·데이터·빌드의 실제 결과. 대표 캡처는 2~4장 정도면 충분하다. 촬영만으로 소리 확인을 주장하지 않는다.
- main 직접 push/merge, Pages 설정 변경, 공개 배포는 별도 승인 없이 하지 않는다. 허용된 작업 브랜치/PR 상태와 실제 공개 배포 상태를 구분한다.

## 13. 근거와 해석 범위

사용자 결정은 위 0.1에 반영했다. 현재 소스에서 확인한 상태와 외부 문법 근거는 동봉 `Sources.md`에 구분했다. 영어 예문과 구현 매핑은 본 작업을 위해 작성한 계약이며 사전의 원문 예문을 그대로 복제한 목록이 아니다.

핵심 외부 확인 범위: hard/fast/well 대표 역할, too 두 의미, notice/remember/discover 내용절, possible/necessary/clear의 대표 보어, for/of 선택의 차이. 이 근거가 게임의 새 희귀도·수치·모든 파생 용법을 승인하는 것은 아니다.
