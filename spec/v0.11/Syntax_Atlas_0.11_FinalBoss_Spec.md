제안 릴리스: **0.11.0**. 이 문서는 구현 지시이며 코드 수정·검증·배포 완료 보고가 아니다.

## 0. 한 문장 목표와 최우선 기준

**기존 47전투 뒤에 Surface Structure → Deep Structure → Universal Grammar를 추가하여 총 50전투를 완성하고, 완주한 원정의 최고 공격 점수와 실제 문장을 상위 20 기록에 남긴다.**

여기서 ‘50스테이지’는 지역 50개가 아니다. 기존 Stage 1~10의 47전투와 최종 3전투다. 화면에서는 `FINAL I / III`, `FINAL II / III`, `FINAL III / III`와 `48 / 50` 등으로 구분한다.

이 문서와 사용자의 가장 최근 지시가 과거 보스 제안에 우선한다. **현재 안정화된 전투·손패·입장·상점 UI는 다시 디자인하지 않는다.** 새 보스 상태와 랭킹/완료 화면에 필요한 최소 표시만 추가한다.

## 1. 현재 구현에서 보존·확인할 것

작업 전 `AGENTS.md`, 현재 `README.md`, 관련 코드와 작업 트리 차이를 읽는다. 과거 ZIP이나 0.10.0 UI로 현재 소스를 덮어쓰지 않는다. 조회 기준 이후 변경이 있으면 최신 사용자 변경을 보존하고 차이만 기록한다.

앱 패키지 0.10.4와 원정 계약 0.10.2는 실제 소스에서 구분되어 있다. **버전 문자열을 소수로 비교하거나 0.10.4가 새로운 원정 규칙이라고 추정하지 않는다.** 새 0.11 원정만 50전투를 사용하고 기존 저장은 원래 완료 경계를 유지한다.

현재 소스에서 확인한 중요한 접점:

- `src/data/campaignFeatures.js`: 현행 원정 최대 47전투와 명시적인 버전별 기능 목록.
- `src/contracts.js`: 앱 패키지와 별개의 원정·문법·저장·보상 계약 버전.
- `src/game/runController.js`: 전투 진입/턴 진행/승리/보상/완료 상태를 소유. 기존 승리 경로는 모든 전투에서 보상 생성으로 이어지므로 최종 페이즈별 분기가 필요.
- `src/game/emberDust.js`: Stage 7 전용이며 기존 검증기는 빙정과의 동시 사용을 전제하지 않는다.
- `src/game/frostCards.js`: 전투 임시 카드, 제출 소멸, 종료 정리. 기존의 일괄 cleanup을 최종전의 혼합 임시 카드에 무작정 두 번 호출하지 않는다.
- `src/game/turnHandSeal.js`: 기존 스핑크스 한 장 봉인과 Stage 5 경계가 하드코딩되어 있다. 기존 계약을 두 장 봉인으로 일괄 변경하면 안 된다.
- `run.stats.bestAttack`은 최고 숫자이고, `run.stats.history`는 최근 12개만 보존한다. 랭킹 최고 문장은 이 이력에서 사후 복원하지 말고 별도 불변 스냅샷으로 갱신해야 한다.

UI 보존: 12×2 조합대·최대 24장, 행별 중앙정렬, 한 줄 손패와 페이지·확대한 손패·단어 세로 중앙정렬, 손패 아래 소량 여백, 좌측 기능/우측 룬, 지역 안내의 몬스터 왼쪽 배치, 전체화면, 모바일 가로 정책, 자수정과 기존 토파즈 구분, 대명사 진한 파랑, 골드 명칭, 입장/상점 분리를 유지한다.

## 2. 원정 흐름과 세 페이즈의 자원

### 2.1 47 → 50 전투

새 0.11 원정의 흐름:

`47 운명의 직조자 격파 → 기존 47전투 보상 1회 → Stage 10 정리 → 최종전 소개 → 마지막 준비 상점 1회 → 48 Surface Structure → 49 Deep Structure → 50 Universal Grammar → 원정 클리어·기록`

- 마지막 준비 상점은 이전 회의의 최종전 직전 상점 제안을 이번 구현 기본안으로 채택한다. 기존 후반 상점의 상품 수·가격·서비스·희귀 룬 정책을 재사용한다. 특별 골드나 정답 카드 무료 지급 없음.
- 최종전용 상점 재고는 진입 때 한 번 고정한다. 뒤로 가기/닫기/로드로 재고·가격·추첨을 초기화하지 않는다.
- 최종전 소개는 이름·짧은 설명·진행만 표시한다. 풍경을 가리는 새 정보표를 만들지 않는다. 각 페이즈 진입 전 별도 전투 안내에서 규칙을 읽을 수 있게 한다.
- `stage.final` 등의 명확한 내부 콘텐츠 ID와 최종 3라운드를 사용할 수 있다. 기존 `stage.01`~`stage.10`의 ID를 바꾸거나 48개의 지역을 만들지 않는다. `Number(stageId.slice(-2))` 등의 기존 UI 가정에서 NaN이 나오지 않게 최소 수정한다.
- 모든 최종 페이즈는 일반 몬스터 저항 대상이 아니다. Stage 10 지역 배율/직조자 예견도 상속하지 않는다.

### 2.2 독립 전투 + 연속 연출

각 페이즈 시작 시 기본 6턴과 기존 `deriveCombatRules` 결과를 사용하여 손패·교환 횟수·드로우·운영 카드 전투당 사용 상태를 새 전투처럼 초기화한다. 남은 턴을 다음 페이즈에 합산하지 않는다. 룬의 전투 진입 효과는 페이즈당 한 번만 적용한다.

영구 카드의 소유/연마/효과, 룬의 소유/레벨/순서, 골드, 원정 기록은 유지한다. 48·49 뒤에는 짧은 변형 연출과 다음 페이즈 버튼만 두고 **카드/룬 선택 보상과 중간 상점을 생성하지 않는다.** 기존 보스 격파·잔여 턴 골드 정산은 동일 정책으로 한 번만 수행하되 보상 선택 화면을 호출하지 않는다.

초과 피해는 다음 페이즈로 이월하지 않는다. 50에서 HP 0이면 마지막 턴 여부와 관계없이 승리다. 죽은 보스가 회복하거나 다음 봉인을 만드는 일은 없다.

### 2.3 안전 저장

기존 수동 저장 3슬롯과 안전 저장 지점을 유지한다. 최종전 시작 전, 마지막 상점 거래 종료, 각 페이즈의 첫 조작 전/전투 사이, 최종 완료를 기존 safe-point 체계에 연결한다. 새 전투 중 자유 저장이나 자동 체크포인트 부활을 추가하지 않는다.

세 페이즈 사이 저장에는 이미 고정된 RNG·보스 설정·기여도·최고 공격 스냅샷이 들어간다. 저장 복원은 봉인/먼지/빙정/보상/골드를 다시 생성하는 계기가 아니다. 실패 후 수동 저장에서 재도전은 기존 정책대로 허용한다.

## 3. 공통 과제 판정과 출제 가능성

### 3.1 카드 철자가 아니라 실제 문법 근거

모든 과제 판정은 현재 Grammar 결과의 구문·절·동사구·카드 인스턴스 근거에서 결정한다. 문자열에 `to`, `that`, `if`, `had`, `been`이 있다는 조건으로 성공시키지 않는다. 정규식이나 고정 예문 목록이 문법 엔진을 대신하면 안 된다.

정상 해제 공격은 다음을 만족한다.

1. 엔진이 정상 처리한 제출이며 핵심 문장 구조가 성립한다.
2. 과제에 해당하는 근거가 `VALID`이고 해금/대상 범위에 맞는다. 자동복구/누락/고아 카드가 만든 근거는 인정하지 않는다.
3. 방어막의 HP 1 상한을 적용하기 전 공격 위력이 양수다. 2페이즈에서는 룬 해방 보너스 전의 기본 채점이 양수여야 한다.

기존 `VALID_WITH_ISSUES`의 전체 허용 정책을 일괄 바꾸지는 않는다. 다만 해당 과제의 필수 성분에 걸린 오류로 근거가 `RECOVERED`라면 그 과제는 실패한다. 목표 밖의 의미 어색함만으로 감점/해제 실패를 새로 만들지 않는다.

태그의 유무만으로 구조를 판정하지 않는다. 기본 채점이 복합 문법의 하위 배율을 억제했더라도 실제 구문이 사라지는 것은 아니다. 과제 매처는 원본 구조와 해금 자격을 함께 읽고, 배율 중복 억제를 해제하거나 새 문법 배율을 생성하지 않는다. 반대로 가정법의 형태상 과거를 실제 과거시제 과제로 인정하지 않는 의미 구분은 유지한다.

### 3.2 보유 덱으로 가능한 문제

출제 후보는 **영구 활성 덱의 실제 카드 사본 수·선택 가능한 형태·지원 문형**에서 만든다. 현재 손패에 정답이 있다는 보장이 아니다. 사용 완료/일시 소모가 영구 소유를 바꾸는지 기존 규칙을 따라 구분한다.

- 1페이즈: 영구 덱만으로 가능하거나, 부족한 핵심 사본 한 장을 빙정으로 더하면 가능한 과제.
- 2페이즈: 영구 덱만으로 가능한 시제 과제. 빙정·탐색 카드·추가 드로우를 주지 않는다.
- 실제 등록 어휘로 된 합법적인 조합 증거(witness)를 내부에서 확인한다. 그 정답 조합을 플레이어에게 표시하지 않는다.
- 전 순열 완전탐색은 하지 않는다. 기존 문형 후보 생성기를 재사용하고 등록된 구조별 제한 탐색으로 증거를 찾는다. 탐색 시간 초과/미확인은 ‘가능’으로 처리하지 않는다.
- 1페이즈 지원은 해당 과제에만 의존해 판단하고, 다른 층에서 소모될 빙정을 두 번째 과제의 필수 재료로 계산하지 않는다.
- 특정 동사는 물리 사본별이 아니라 사용 가능한 **서로 다른 동사 렉심** 후보에서 균등 추첨한다. 같은 동사 3장 보유가 출제 확률 3배가 되지 않는다.

보통 정상 문장을 만들 수 있는 덱에는 `문형`과 그 문장의 `보유 동사` 두 유형이 가능하다. 어떤 합법적 증거도 찾지 못하면 무한 재추첨/전체 단어 무료 지급/가짜 성공을 하지 않는다. 생성 실패 원인을 남기고 안전한 진입 전 상태와 오류 안내로 복구한다. 이를 ‘일반 패배’나 검증 PASS로 숨기지 않는다.

### 3.3 난수와 공개 상태

출제·먼지 수·두 장 봉인은 encounter 전용 난수 또는 새 최종전 전용 스트림을 사용한다. 기존 deck/reward/shop 스트림을 렌더링에서 소비하지 않는다. RNG 선택은 Controller의 명령 정산 경계에서만 일어난다.

저장 후 로드/창 크기 변경/사전 열기/손패 페이지/룬 위치 변경으로 문제나 봉인 대상이 바뀌면 안 된다. 동일 원정·동일 입력 경로는 동일 결과를 낸다. 플레이어에게 이미 공개한 문제는 교환/턴 넘기기로 새로 뽑지 않는다.

## 4. 1페이즈 — Surface Structure

### 4.1 컨셉과 기본값

고대 중갑으로 무장한 거인. 무거운 외피의 두 겹을 서로 다른 문제로 벗겨낸다. HP **5,000**, 카드 봉인 없음, 룬 봉인 없음.

현재 합의에서 ‘방어막’은 **해제하지 않으면 HP 1을 남기는 잠금 장치**다. 별도 방어막 HP/피해 반감/시간별 부위/회복 저지 과제/추가 약점 배율을 더하지 않는다.

### 4.2 두 과제의 순서

유형은 `FRAME`, `GRAMMAR`, `OWNED_VERB` 세 개뿐이다.

1. 입장 시 가능한 유형 중 첫 유형을 균등 추첨한다.
2. 해당 유형 안에서 가능한 상세 문제를 균등 추첨한다.
3. 첫 층 파괴 뒤에는 **사용하지 않은 두 유형** 중 가능한 유형을 균등 추첨한다.
4. 두 번째 층도 파괴하면 추가 출제/방어막 재생 없음.

저장 결정론과 재료 검증을 위해 두 층의 계획을 입장 시 내부적으로 미리 고정해도 된다. 이 경우 두 번째 과제는 첫 층 파괴 뒤에만 표시하며, ‘남은 유형에서 추첨’과 동일한 비복원 분포여야 한다.

**한 공격은 현재 활성 층 한 겹만 파괴할 수 있다.** 두 과제를 동시에 충족한 문장도 다음 층까지 연속 파괴하지 않는다. 새 문제는 다음 공격부터 판정한다.

### 4.3 FRAME — 주절 1~5형식

`SV / SVC / SVO / SVOO / SVOC` 중 하나를 지정한다. 엔진의 주절/결과절 판정을 사용한다. 문두 if절을 주절로 오인하거나 종속절이 지정 형식이라는 이유로 인정하지 않는다.

- 2형식의 명사 보어/형용사 보어는 모두 2형식.
- 4형식과 `give + 목적어 + to 전치사구`를 구분한다. 후자가 엔진상 3형식이면 4형식 해제 실패.
- 5형식은 등록 동사의 실제 목적격보어 문형이 성립해야 한다.
- 수동태의 문형은 현재 엔진이 분석한 표면 주절 문형을 사용한다. 능동태 원형 문형으로 임의 환산하지 않는다.

표시 예: `방어막 1/2 · 주절 4형식으로 공격하세요` / 작은 안내 `S + V + IO + DO`.

### 4.4 GRAMMAR — 정확히 다섯 계열

| 계열 | 인정 범위 | 대표 불인정 |
|---|---|---|
| 수동태 | 기존 엔진의 정상 수동 동사구. 주절/유효한 종속절 중 존재하면 인정 | 형용사 보어인 be+형용사, 단순 p.p. 수식만 존재 |
| to부정사 | 실제 부정사 구문으로 분석된 to+동사원형 | 전치사 to, 원형 오류, 고립된 to |
| 가주어·진주어 | 기존 지원 `It … to부정사`, `It … that절` 중 하나 | 지시대명사 it+일반 보어, 강조구문을 겉모양으로 오인 |
| 관계절 | 선행사를 수식하는 기존 지원 관계대명사절/관계부사절. 주격/목적격 중 하나면 충분 | what 명사절, that 내용절, when 시간 부사절 |
| 가정법 | 기존 가정법 과거 또는 가정법 과거완료의 정상 조건절·결과절 쌍 | 현실 조건절, would/could 단독, 과거형이 있다는 이유만의 판정 |

위 인정 범위는 모호한 표제를 실제 엔진 계약으로 좁힌 구현 세부 정의다. 관계절 문제에 주격·목적격 **둘 다** 요구하지 않는다. 정상적으로 지원되는 관계사 생략형은 동일 구문으로 인정한다.

비교급·최상급·as…as·배수 비교는 **출제하지 않는다**. 현재완료 단독·동명사 단독을 여섯 번째 목표로 추가하지 않는다. 다만 기존 게임에서 정상인 이러한 문장은 계속 공격/콤보가 가능하다. 출제 제외가 문법 사용 금지는 아니다.

가정법 과거완료처럼 재료가 많이 드는 구문도 이론상 인정되지만, 문제를 뽑을 때 영구 덱+최대 한 장으로 가능한 간단한 경로가 없으면 그 후보를 제외한다.

### 4.5 OWNED_VERB — 보유 동사 사용

영구 활성 덱에 실제 보유하고 정상 문장에 사용할 수 있는 동사 렉심 하나를 선택한다. 명사·형용사·운영 카드·먼지는 대상이 아니다.

표시: `방어막 2/2 · 동사 help를 사용해 공격하세요` / `시제·활용형 변경 가능`.

구현 세부 정의:

- 원형·3인칭·과거·분사·부정사/동명사 내부의 동사 사용 등, 기존 엔진이 해당 렉심의 정상 동사 역할로 분석한 사용을 인정한다.
- 같은 동사의 다른 영구 사본도 인정한다. 특정 인스턴스를 손패에 강제로 찾아야 하는 과제가 아니다.
- help를 순수 명사 용법으로 사용한 것은 ‘동사 help’ 과제의 정답으로 취급하지 않는다.
- be/have는 정상적인 본동사/연결동사 용법의 증거가 있을 때 후보로 쓸 수 있다. 보조동사만으로 쓰인 다른 구조를 근거 없이 본동사 사용으로 인정하지 않는다. will/can 같은 조동사 전용 렉심은 이 출제 풀에서 제외한다.
- 조합대에 올려만 놓고 문장에 기여하지 않거나 채점 제외된 카드로는 해제할 수 없다.

이 유형은 원래 보유 동사를 지정하므로 추가 빙정 지급이 없다.

### 4.6 조건부 빙정

과제 확정 때 영구 덱의 필요한 사본을 검사하여 **필수 사본 하나가 부족한 경우만** 무연마 빙정 WORD 한 장을 지급한다. 현재 손패에 없을 뿐이라면 지급하지 않는다. 두 사본 이상을 새로 줘야 가능한 과제는 제외한다. 보유 have 한 장에 두 번째 have 사본이 필요한 경우도 ‘부족 사본 한 장’으로 처리할 수 있다.

지급 카드는 현재 등록된 어휘·형태·문형만 사용한다. 완성된 정답 문장을 채워주거나 운영 탐색 카드·추가 턴·골드를 무료 지급하지 않는다. 첫 과제와 두 번째 과제 각각 최대 1장, 전투 전체 최대 2장.

발급은 층 활성화 시 한 번. 손패에 여유가 있으면 손패로 넣고, 꽉 찼으면 드로우 더미 맨 위에 두고 안내한다. 손패 초과·영구 카드 강제 폐기·무한 재지급 금지. 기존 opening witness 경로를 훼손하지 않고 첫 과제 발급 시점을 연결한다.

사용하지 않은 앞 층 빙정은 해당 페이즈가 끝날 때까지 유지할 수 있다. 하지만 다음 문제를 만들 때 그 소모 가능 카드에 의존하지 않는다. 정상 접수되어 턴/카드가 소비된 제출은 비문이어도 빙정을 소모하고, 엔진 오류·stale command로 접수 거절된 제출은 소모하지 않는다.

### 4.7 먼지

페이즈 시작에 기존 검은 먼지 카드 4장 또는 5장을 1회 생성해 전투 덱에 섞는다. 턴마다 추가 생성하지 않는다. 기존 먼지의 비제출·교환·순환 규칙을 사용하며 점수나 문장 카드 수에 넣지 않는다.

초기 손패 먼지 과다 방지 등 기존 opening 정책은 보존 가능한 범위에서 재사용한다. 단계 해제·로드·재렌더링은 추가 먼지 지급 사유가 아니다.

먼지와 빙정은 별도 `source/type/lifetime` 메타데이터로 같은 전투 임시 카드 영역에서 공존한다. 한 공급 객체를 펼쳐쓰며 다른 공급의 ID 배열을 덮어쓰지 않는다. 임시 카드는 영구 `activeCardIds`에 넣지 않는다. 종료 정리는 모든 임시 사본을 한 번만 제거하며 영구 카드를 삭제하지 않는다.

### 4.8 HP 1 잠금·회복·정산 순서

공격 처리 순서:

`정상 제출/과제 판정 → 현재 층 최대 1개 해제 → 남은 층으로 처치 가능 여부 결정 → 피해 → HP0 즉시 승리 또는 턴 종료 회복 → 턴 소진 패배 여부 → 다음 턴/다음 과제 공개`

- 과제 실패해도 정상 공격은 피해를 준다.
- 한 겹이라도 남으면 `actualHpLoss = min(attackPower, max(0, hpBefore - 1))`.
- 두 번째 층이 깨진 공격은 즉시 잠금 해제 상태로 계산하여 그대로 처치 가능.
- 이미 HP 1인 보스에게 실제 HP 감소가 0이어도, 양수 위력과 정상 과제 근거가 있으면 층을 깰 수 있다. `actualHpLoss > 0`을 해제 조건으로 쓰지 않는다.
- 잠금에 막힌 피해는 `preventedBySeal`로 기록한다. 살아 있는 적에게 이를 ‘오버킬’로 표시하지 않는다. 공격 위력 자체를 1로 잘라 랭킹에 저장하지 않는다.
- 살아 있고 최대 HP 미만이면 `min(400, maxHp - hpAfterAttack)` 회복한다. 준비가 이름만 변경된 **턴 넘기기**도 같은 턴 종료 처리 대상.
- **두 층을 모두 깬 뒤에도 회복은 계속**된다. 명사절이나 가주어로 회복을 막는 도서관장 규칙을 가져오지 않는다. 최신 합의에는 그 별도 과제가 없다.
- 교환·카드 편집·형태 선택·사전·손패 페이지·턴을 쓰지 않는 운영 카드는 회복을 발생시키지 않는다.
- 마지막 턴에 살아 있으면 회복 처리 후 패배. 마지막 턴에 처치했다면 승리가 우선.

UI는 `방어막 2 → 1 → 0`, 현재 과제, `턴 종료 회복 +400`을 분리해 표시한다. 방어막은 원상복구되지 않는다.

## 5. 2페이즈 — Deep Structure

### 5.1 컨셉과 범위

갑옷이 깨지고 드러난 신비로운 인간형 본체. HP **6,000**. ‘다양한 조건’ 대신 ‘제한된 자원’으로 쉬운 시제 과제를 해결한다.

적용하는 기믹은 **공격형 룬 최대 2회 순차 봉인 + 매 턴 단어 카드 최대 2장 봉인**뿐이다. 먼지·빙정·회복·피해 반감·HP 1 보호·문형 변경 강제는 추가하지 않는다. 과제를 풀지 않아도 다른 정상 공격으로 HP 0을 만들면 승리한다.

### 5.2 실제 기여도에 따른 봉인 대상

첫 페이즈의 정상 양수 공격마다 각 장착 공격형 룬의 기여도를 순수 계산으로 측정한다.

`marginal(r, attack) = max(0, allRunesPostScore - withoutRuneRPostScore)`

`contribution(r) = max(marginal(r, attack))`  — 1페이즈 유효 공격 전체에서의 최대값.

여기서 `withoutRuneRPostScore`는 같은 분석 결과·기본 점수·카드·룬 레벨·장착 순서로 **그 룬의 모든 효과만 제외해 룬 계산을 다시 한 결과**다. 제외 룬 뒤에 곱해지는 효과까지 고려한다. 단순히 이벤트의 `after-before`를 비교하면 앞쪽 가산 룬의 최종 기여도를 놓치므로 사용하지 않는다.

- HP 감소량·방어막으로 잘린 피해·오버킬과 무관한 룬 적용 후 수치로 비교한다.
- Grammar를 다시 분석하거나 실제 룬 소유/레벨을 바꾸지 않는다. 애니메이션·난수·재화에 부작용 없는 계산이다.
- `ADD_SCORE`, `MULTIPLY_SCORE` 등 공격 점수 효과만 대상. 시작 손패/손패 한도/교환/드로우/기타 자원형 룬은 등급과 무관하게 제외.
- 실제 기여도가 양수인 보유 공격형 룬을 내림차순 정렬한다. 동률은 레벨 내림차순 → 고정 rune ID 순으로 결정한다. 희귀도만으로 선정하지 않는다.
- 서로 다른 상위 룬 **최대 2개**를 2페이즈 진입 때 고정한다. 순서를 옮기거나 로드해도 대상 목록은 바뀌지 않는다.
- 대상 1개면 한 번만 봉인한다. 0개면 룬 봉인은 생략하고 카드 봉인만 시행한다. 자원형 룬을 대신 봉인하거나 같은 룬을 두 번 쓰지 않는다.
- 현재 문장의 실시간 가상 기여도를 보여주지 않는다. 화면에는 제출 뒤 실제 결과만 표시한다.

### 5.3 시제·동사구 형태 과제

현재 능동/수동 등 다른 문법을 막는 시험이 아니다. 아래 표의 **주절 유한 동사구**를 확인한다. 종속절만 해당 시제인 문장으로 우회하지 않는다. 기존 파서의 mainClause/verbPhrase 연결을 사용한다.

| 과제 | 인정 조건 | 불인정/주의 |
|---|---|---|
| 현재 | 현재 계열의 단순형. 현재 be 서술 포함 | 현재진행/현재완료로 단순형 과제를 대체하지 않음 |
| 과거 | 실제 과거 계열의 단순형. was/were 서술 포함 | 가정법의 형태상 과거, could 단독 추정, 과거완료 |
| 현재진행 | 현재 be + V-ing, 실제 진행 동사구 | 동명사, 형용사/분사 수식, 현재완료진행 |
| 현재완료 | have/has + p.p., 진행 아님 | had+p.p., have를 단순 소유 동사로 사용, 현재완료진행 |
| 미래 | will + 원형의 정상 미래 동사구 | would/could, 부사만 미래, 지원되지 않는 미래 표현 |

이는 시제·상을 게임 안내상 묶은 과제 풀이지, 진행·완료를 별개의 문법적 시제라고 새로 정의하는 교육 설명이 아니다. 과거완료·가정법·현재완료진행은 이번 해제 과제에서 제외하지만 일반 공격으로는 정상 지원한다.

덱에 be/have/will 등이 없으면 해당 복합 동사구 과제를 제외한다. ‘형태만 바꾸면 된다’고 무조건 출제하지 않는다. 첫/둘째 룬 과제는 가능한 시제에서 무작위로 고정하고, 가능 종류가 둘 이상이면 연속으로 같은 과제를 내지 않는 것을 기본안으로 한다. 하나뿐이면 같은 시제로 서로 다른 룬을 해제할 수 있다.

과제는 영구 덱 기준이며, 특정 턴의 두 장 봉인 때문에 잠시 어려워졌다고 자동 재출제/빙정 지급하지 않는다. 교환·턴 넘기기·운영 카드로 자원을 준비한다. 이름/페이지/설정으로 재추첨되지 않는다.

### 5.4 해제 보상과 연쇄 순서

한 번에 봉인된 룬은 하나다. 룬 인스턴스는 제자리에 있으며, `sealedRuneInstanceId` 같은 전투 상태로 해당 룬의 점수 효과만 비활성화한다. 영구 소유·레벨·슬롯·순서를 삭제/변경하지 않는다.

**해제 성공 공격의 순서**:

1. 제출 문장으로 현재 시제 과제의 정상 성공을 판정한다.
2. 봉인된 룬을 **이번 공격의 룬 계산 전** 활성화한다.
3. 현재 장착 순서대로 룬을 계산한다. 해제된 룬도 자기 발동 조건이 맞을 때만 발동한다.
4. 별도 이벤트 `룬 해방 ×1.25`를 그 공격에 한 번 적용한다.
5. 피해를 적용하고 HP 0이면 즉시 격파한다.
6. 보스가 생존하고 다음 턴이 있으면 다음 턴 시작 시 두 번째 룬을 봉인한다.
7. 두 번째 해제 후에는 추가 룬 봉인이 없다. 카드 봉인은 계속된다.

해제 성공 공격에 다음 룬을 미리 봉인하거나, 보상 직후 그 공격을 재계산하지 않는다. 해방 보너스는 해당 룬의 문법 조건과 시제 과제가 서로 달라도 성공 보상을 주기 위한 **이번 명세의 ×1.25 초깃값**이다. 잘못된 룬 조건까지 억지로 발동시키는 것이 아니다.

예: 3형식 룬을 봉인했지만 과거시제 2형식 문장으로 해제한 경우, 룬 봉인은 풀리지만 3형식 룬은 그 공격에 발동하지 않는다. 그래도 해방 보너스는 한 번 받는다.

과제 실패한 정상 공격은 봉인 룬을 제외한 상태로 피해를 준다. 비문을 엔진이 접수해 턴을 소비하더라도 해제는 없다. 엔진 오류나 오래된 명령으로 거절되면 룬·카드·턴·RNG는 그대로다.

### 5.5 손패 두 장 봉인

전투 첫 손패가 정해진 뒤와 매 실제 턴 시작의 드로우 완료 뒤, **현재 손패의 WORD 인스턴스**에서 균등 비복원 추첨하여 최대 두 장을 봉인한다. 운영 카드·먼지·조합대 카드·다른 더미의 카드는 선택하지 않는다. 페이지에서 안 보이는 손패 카드도 손패 전체의 정상 후보다.

후보가 1장이면 1장, 0장이면 0장만 봉인한다. 그 턴의 이전 봉인은 해제한 뒤 새 턴 봉인을 정한다. 같은 카드가 다음 턴에 우연히 다시 선택될 수 있으며, 현재 손패를 완벽하게 풀 수 있게 조작하지 않는다.

- 봉인 카드는 조합대에 추가/드래그 삽입/맞교환으로 들어갈 수 없다. 정보 확인은 가능하다.
- 기존 봉인 카드처럼 버리기/교환은 허용한다. 이때 다른 손패 카드를 다시 봉인해서 수를 보충하지 않는다.
- 같은 봉인 인스턴스가 같은 턴에 다시 뽑히면 봉인은 유지한다. 선택 형태/페이지 변경으로 해제되지 않는다.
- 새로 드로우한 비봉인 카드는 사용할 수 있다. 봉인은 ‘그 턴 시작 때 뽑은 두 ID’에 걸린다.
- 2회 룬 봉인을 모두 풀어도 손패 봉인은 생존 중 매 턴 계속된다.
- 2페이즈 종료·패배 시 룬/카드 봉인을 전부 정리한다. 3페이즈에는 이월되지 않는다.

## 6. 3페이즈 — Universal Grammar

HP **10,000**. 갑옷과 육체의 형태가 풀린 원초적이고 몽환적인 빛/실루엣. 기존 카드와 룬으로 강한 문장을 완성하는 최종 화력전이다.

- 두 층 방어막, 턴 회복, 먼지, 빙정 지원, 룬/손패 봉인을 모두 사용하지 않는다.
- Stage 10 직조자의 같은 문형 무효화나 일반전 저항도 적용하지 않는다.
- 현재 정상 룬·문법·폴리싱·운영 카드 규칙만 사용한다.
- 새 전투의 6턴과 정상 손패로 시작한다. 추가 보스전 전용 무료 자원은 없다.
- 한 번에 HP를 전부 깎으면 그대로 승리. 강제 HP1 정지/추가 조건 없음.
- 24장을 반드시 채워야 하는 조건 없음. 짧은 문장/가산 룬/전문 문법 덱도 원래 방식으로 공략한다.
- 초과 피해와 최고 단일 위력을 기록하되, 예시 화력에 맞추려고 배율이나 HP를 자동 조정하지 않는다.

50번째 격파를 실제 원정 클리어로 처리한다. `CONTENT_COMPLETE`와 별개 `clearKind:'FINAL_CLEAR'`, `FINAL50_CLEAR` 경계·완료 receipt 등 기존 모델에 맞는 명시적 표식을 추가한다. 단순히 47전투 구간 완료와 같은 플래그로 랭킹에 등록하지 않는다.

## 7. 점수·카드·상태의 정산 계약

### 7.1 공격 타임라인

기존 Grammar → Scoring → Rune → Stage → Presentation 경계를 보존한다. **해제의 성공 여부는 룬보다 먼저 판단할 수 있지만**, 상태 커밋은 Controller만 한다. 순수 평가 결과에 `sealRelease`, `effectiveDisabledRuneIds`, `bonusEvent`, `bossStateAfter`를 담아 한 번 커밋한다.

`finalPower`는 실제 화면의 최종 공격 위력이다. 남은 HP 상한과 구별하며, HP 1 잠금은 `preventedBySeal`로 기록한다. 실제 HP 감소, 회복, 오버킬, 페이즈 전환은 별개 항목이다. ‘회복으로 감소한 누적 피해’를 공격 점수에서 역으로 빼지 않는다.

페이즈의 턴 종료 효과는 실제 턴 소비 명령당 한 번이다. 공격 완료 animation callback/watchdog/창 전환은 두 번째 정산을 일으키지 않는다. 회복/해제/봉인 전환도 동일 action receipt와 turn key로 중복을 막는다.

### 7.2 상태 구조의 최소 권고

기존 state 형태에 맞춰 이름은 조정할 수 있으나 다음 정보는 직렬화되어야 한다.

```text
finale:
  version / bossPolicyVersion
  phaseIndex / battleNumber
  fixedTaskPlan / taskCursor / randomTrace
  runeContributions / orderedSealTargets / completedRuneSeals
  shopReceipt / phaseClearReceipts
  bestAttackSnapshot
combat.bossMechanic:
  phaseId / layersRemaining / activeTask
  regenPerTurn / turnEndReceipts
  sealedRuneInstanceId / pendingNextRuneSeal
  sealedWordIds / sealedForTurn / cardSealReceipts
combat temporary:
  instance IDs + source + battleId + lifetime + per-source consumed state
```

막연히 배열 길이만 맞추지 말고, 각 층·봉인·공격·턴·발급 사이의 참조가 맞는지 검사한다. 불필요한 대규모 상태관리 프레임워크는 도입하지 않는다.

### 7.3 골드·보상·전환 멱등성

47번째 기존 보상은 한 번, 마지막 상점은 한 번. 48·49는 보상 선택 없이 다음 페이즈로, 50은 완료 화면으로 간다. 기존 보스 골드 정산을 적용한다면 phase battle ID를 키로 한 번만 지급한다.

성공한 공격이 뒤늦게 다시 전달되거나, 완료 화면을 새로 그리거나, 안전 저장을 다시 불러와도 층/봉인/클리어 수·골드·랭킹이 중복되지 않는다.

## 8. 클리어 기록과 Top 20 랭킹

자세한 인터페이스·저장 정책은 동봉 `02_Clear_Leaderboard.md`를 따른다.

### 8.1 반드시 구현할 기록

원정 1~50에서 **엔진이 정상 접수한 실제 공격의 최종 위력 최고값**과 동일 공격의 실제 문장을 함께 저장한다. 50을 모두 완료했을 때만 클리어 랭킹에 등록한다. 연습/샌드박스/개발용 지정 상태는 별도 QA 모드이며 실기록에 등록하지 않는다.

각 최고 기록의 필수 정보: 플레이어 식별자, 표시 이름, 원정 ID, 규칙 버전, 최고 점수, 공격 ID, 전투 번호, 선택형을 포함한 문장 토큰/문장 문자열, 클리어 식별자. 최고 기록은 최근 12공격 캐시와 별개로 보존한다.

점수는 **실제 HP 감소량이 아니다**. HP 200인 적에게 최종 위력 12,000이면 기록은 12,000이다. 피해감소/예견/봉인으로 점수가 수정되는 전투에서는 실제 엔진이 표시하는 최종 위력을 사용한다. 보스의 HP1 잠금으로 피해만 제한된 경우 원래 최종 위력은 유지한다.

동일 원정의 최고 점수가 같으면 먼저 기록된 공격을 유지한다. 같은 플레이어의 동점 재클리어는 기존 대표 기록을 유지한다. 플레이어 간 동점은 기록 저장 순번(공용은 서버 순번)으로 안정 정렬한다. 쉬운 단어 모드와 어려운 단어 모드는 기존 게임에서 수치가 같으므로 따로 점수 가중치를 주지 않는다. 추후 난이도·수치 계약이 바뀌면 다른 ruleset으로 분리한다.

### 8.2 표시

```text
1  별빛여행자
   18,420점 · “실제로 제출했던 영어 문장 …”
```

랭킹은 최대 20명, 플레이어별 최고 완주 기록 하나. 이름 아래 점수와 문장을 한 줄로 두고 긴 문장은 말줄임+선택 시 전체 표시. 작은 화면에서 글자를 지나치게 줄이거나 카드 문장을 고쳐 쓰지 않는다.

클리어 화면은 보스 격파 → 원정 완료 → 이번 원정 최고의 문장 → 랭킹 결과 순서로 간결하게 표시한다. 새 대형 UI 시스템이나 공유 이미지 생성은 필수가 아니다.

### 8.3 로컬과 공용은 구분

기존에 확인한 서비스 계층에는 로컬 저장 모듈이 있고, 이번 검토에서 공용 랭킹의 운영 엔드포인트·인증 계정은 확인하지 못했다. 따라서 **로컬 Top20을 전 세계/학급 공용 랭킹이라고 표시하지 않는다.**

동봉 계약에 따라 로컬 실기록 어댑터와 공용 API 연결 지점을 구현한다. 작업 환경에 이미 승인된 서비스가 있다면 그 연결을 재사용한다. 없다면 외부 계정·비용·배포를 임의로 만들지 않고 `공용 랭킹 미연결`로 보고한다. 같은 기기의 기록은 즉시 쓸 수 있어야 하며, 공용 연결 미확보가 최종 보스 플레이와 로컬 클리어 보존을 막아서는 안 된다.

공용 운영까지 완료되지 않았다면 **게임 50전투 구현 완료와 공용 랭킹 운영 완료를 별도 상태**로 보고한다. 요구를 조용히 축소하지 않는다.

## 9. UI·연출·이름·아트 범위

영문 고정 이름은 정확히 `Surface Structure`, `Deep Structure`, `Universal Grammar`다. 이전 Ironclad/Unbound/Primordial 접두사명이나 세 페이즈 공통 Deep Structure 명칭으로 돌아가지 않는다. 한국어 보조 표기는 각각 서피스 스트럭처/딥 스트럭처/유니버셜 그래머.

아트 방향: 1페이즈 고대 중갑 거인 → 2페이즈 갑주를 벗은 신비로운 인간형 → 3페이즈 원초적인 빛과 실루엣. 비실사 게임 일러스트 방향이며 실제 원화는 별도 제작. 이번 패치에는 기존 이미지 로딩 체계와 단계별 fallback만 연결한다. 이미지 미제공 때문에 기능 작업을 지연하지 않고, 완성 아트를 제작했다고 보고하지 않는다.

현재 좌측 안내·중앙 적·우측 HP/상태, 조합대 양옆 기능/룬 위치를 유지한다. 긴 이름은 적 정보 영역에서 합리적으로 줄바꿈하되 조합대나 손패를 밀지 않는다.

최소 표시:

- Surface: 방어막 남은 수, 활성 문제의 종류와 요구, 생존 시 턴 종료 +400, 먼지 투입과 빙정 발급 알림.
- Deep: 봉인된 룬의 이름/레벨, 현재 시제 과제, 해제 횟수 `0/2`(실제 대상 수 기준), 두 단어 봉인 표시.
- Universal: HP와 최종 페이즈 표시. 가짜 약점/기믹 안내 없음.

과제 정답 여부는 **제출 뒤에만** 표시한다. 현재 문장에 대한 초록 체크·예상 점수·추천 정답 순서 금지. ‘시제: 과거’나 ‘주절 4형식’ 같은 문제 자체와 간단한 형식 설명은 상시 보여도 된다.

기존 점수·근거 카드 탄성·룬 비행·문장 집결/돌진·피격은 유지한다. 층 해제/룬 해방/회복을 그 타임라인에 짧게 연결한다. 새로운 긴 컷신, 게임플레이 타이밍을 바꾸는 강제 지연은 추가하지 않는다. 효과 OFF·모션 감소에서도 상태 변화는 글자와 정적 표시로 읽혀야 한다.

## 10. 버전·저장 호환

새 원정 계약을 0.11.0으로 도입하되 기존 언어/카드 정의를 무의미하게 복제하지 않는다. 새 게임 정책에 현행 문법 분석 결과가 연결되도록 버전 분기·기능 판정·저장 validator·콘텐츠 목록을 빠짐없이 점검한다. `'0.10.2'`를 모든 파일에서 일괄 치환하지 않는다.

- 새 0.11 원정만 50전투. 구원정 47전투/42전투 등은 당시 경계를 유지.
- 구 0.10.x 완료 저장을 몰래 최종전으로 연장하거나 공용 클리어로 등록하지 않음.
- 새 게임의 기존 1~47 규칙·HP·룬 획득·UI는 현행 최신 정책을 그대로 상속.
- 최고 문장 스냅샷이 없는 구원정에 문장을 추정하여 랭킹을 생성하지 않음.
- 운영 중 local DB 이름/프로필 ID를 바꾸거나 기록을 초기화하지 않음. 필드가 추가되면 명시적 schema 호환 적용.
- 테스트용 finale 진입은 개발 도구/전용 fixture로만 제공. 운영 플레이에 디버그 클리어 버튼이나 점수 주입 메뉴를 노출하지 않음.

## 11. 구현 순서·검증·인계

### 11.1 구현 순서

1. 실제 최신 트리·버전·기존 기능 확인, finale 데이터/정책 상수와 새 원정 경계 연결.
2. 출제 가능성 + 동사/시제/목표문법 근거 매칭 + 고정 난수 계획.
3. Surface의 두 층·HP1·회복·먼지/빙정 공존을 순수 함수/Controller에 연결.
4. 룬 기여도·최대2회 연쇄·동사구 시제·두 장 봉인과 해방 보너스 연결.
5. 47보상/마지막 상점/48→49→50/최종 완료·정리·안전 저장 연결.
6. 최고 공격 스냅샷·Top20·최소 클리어 화면·공용 어댑터 계약 연결.
7. 실제 UI에서 최종 3전투를 연속 진행하고 핵심 규칙/빌드를 확인하여 인계.

### 11.2 검증 강도

이번은 실제 규칙 패치이므로 **층 처리·봉인·카드 보존·원정 완료·기록 저장**은 확인한다. 하지만 전체 50전투 자연 완주, 전 브라우저/실기기 조합, 대량 시드와 수백 캡처를 무조건 작업 완료 조건으로 만들지 않는다.

동봉 `03_Focused_Verification.md`의 **20개 핵심 검사 묶음**을 기존 테스트와 작은 추가 테스트로 검증한다. 각 묶음을 별도의 대형 브라우저 스크립트로 만들 필요 없다. 기존 `npm test`, `npm run validate:data`, `npm run build`를 최종 코드에서 한 번 실행하고, 관련 수정 뒤 영향 있는 검사만 재실행한다.

PC 일반 창에서 지정된 합법적 덱으로 47종료→상점→48~50연속→기록까지 실제 UI 진행, 태블릿 가로에서는 신규 상태 문구와 버튼 접근을 간단히 확인한다. 지정 덱 검사는 자연 보상으로 성장한 원정이나 사람 승률이 아니다. 실제 후반 덱을 가진 저장이 제공되면 그 저장을 별도 복사로 플레이하고 원본을 보존한다.

자연 플레이가 준비되지 않았으면 ‘HP/회복/해방 배율의 실제 난이도 미검증’을 명확히 남긴다. 자동 플레이 정책이 패배했다고 확정 HP를 낮추거나, 매번 카드 주입으로 PASS를 만들지 않는다. 미세 디자인은 사용자 피드백으로 후속 수정한다.

### 11.3 완료 보고

보고는 구현된 기능, 핵심 테스트/빌드 실제 결과, 1~2개 대표 캡처, 미검증/제약, 브랜치·커밋·PR을 간결히 제시한다. 게임·로컬기록·공용연결·실기기·아트의 완료 상태를 구분한다. 기존 원화·전체 UI 패치를 재수행하지 않는다.

별도 브랜치(예: `codex/v0.11-final-trilogy`)에서 커밋·push·PR을 준비한다. **main 자동 병합·Pages 설정 변경·공개 배포는 별도 승인 없이 하지 않는다.** 권한이 없어 push/PR이 실패하면 로컬 커밋 또는 패치 파일과 정확한 차단 사유를 인계하고 원격 완료를 주장하지 않는다.
