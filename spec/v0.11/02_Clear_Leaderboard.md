# 0.11 클리어 기록 · Top 20 · 공용 연결 계약

이 문서는 보스 본명세 §8을 보완한다. 랭킹의 종류를 사용자에게 숨기거나, 로컬 기록을 공용 결과로 꾸미지 않는다.

## 1. 사용자 요구와 아직 확정되지 않은 운영

확정: **최종 3페이즈를 모두 클리어한 플레이어**, **최고 공격 점수 순 20명**, **이름 밑에 점수와 그 실제 문장 한 줄**.

이번 명세의 구체화: 원정 전체 최고 단일 최종 위력, 플레이어별 한 기록, 동점 시 기존 기록 유지, 규칙 버전별 구분.

공용/기기별이라는 운영 범위와 서버·로그인 제공자는 아직 사용자가 지정하지 않았다. 이에 따라 이번 구현은:

1. **실제 동작하는 기기 내 Top20**과 최고 문장 스냅샷을 완성한다.
2. 저장·화면과 분리된 공용 API 어댑터 계약을 만든다.
3. 승인된 기존 공용 서비스/설정이 발견되면 같은 계약으로 연결한다.
4. 서비스/권한이 없으면 `로컬 완료 / 공용 미연결`을 보고한다. 새로운 외부 계정·유료 서비스·공개 배포를 임의로 만들지 않는다.

이 정책은 사용자에게 필요한 범위를 명확히 하는 것이며, 여러 기기의 공용 랭킹 요구가 자동으로 충족되었다는 뜻이 아니다. 공유가 필요하면 공용 저장과 검증 운영이 별도로 완료되어야 한다. 게임 완성이나 오프라인 클리어를 그 준비 때문에 막지 않는다.

## 2. 점수와 대표 문장

`bestAttackSnapshot`은 매 실제 접수된 공격이 이전 최고보다 높을 때 즉시 갱신한다. 같은 공격의 아래 정보를 원자적으로 저장한다.

```text
rulesetId, campaignVersion, languageVersion, scorePolicyVersion
runId, attackId, battleNumber, stageId, phaseId(optional)
finalPower (safe integer)
actualHpLoss, overkill, preventedBySeal(optional)
submittedTokens[{cardDefId, lexemeId, selectedFormId, surface, position}]
sentenceText
recordedActionSequence
```

- `finalPower`와 HP 상한/회복/오버킬을 구분한다. 남은 HP가 200이어도 위력 12000이면 점수 12000.
- 과제 해제의 합법적인 ×1.25 보상도 실제 finalPower에 들어갔으면 포함한다. 1페이즈 HP1 보호는 위력 자체를 낮추지 않음.
- 점수와 문장 텍스트를 서로 다른 공격에서 가져오지 않는다.
- 대소문자·선택형·단어 순서는 실제 제출 상태를 보존한다. 화면 조립용 공백/구두점 표준화는 원문 토큰을 잃지 않는 범위만 허용한다. 문법 교정/단어 바꾸기 없음.
- 레코드는 참조가 아니라 deep copy다. 다음 턴이나 다른 카드의 형태 선택으로 과거 기록이 변하지 않는다.
- 구버전 캐시의 최고 숫자만 남아 있고 문장이 없다면 그 숫자에 임의 문장을 붙이지 않는다.
- 같은 점수면 먼저 만든 공격을 유지한다. 평가를 통과한 실제 공격만 대상이며 연습 튜토리얼·샌드박스·fixture 공격은 제외한다.

## 3. 클리어 자격

최종50완료 receipt에 48/49/50의 서로 다른 성공 정산 ID와 해당 원정의 완료 경계가 있어야 한다. 47구간완료, 48/49만 완료, 패배 원정은 등록하지 않는다.

`clearId = stable(runId + rulesetId + FINAL50_CLEAR)` 형태의 안정된 키를 사용한다. 화면 재진입·저장 로드·재전송으로 새 clearId를 만들지 않는다. 상세 키 구현은 기존 ID 규칙을 따르되 무작위 재생성 금지.

수동 저장·불러오기는 기존대로 허용한다. 이 기능을 썼다는 이유로 점수 벌점/별도 난이도를 만들지 않는다. 단, 같은 완료의 중복 등록은 막는다. 승인되지 않은 구원정 변환/개발자 상태 주입으로 공용 기록을 만들지 않는다.

## 4. 로컬 보드

- 이름: **이 기기의 클리어 랭킹**. 동일 origin·동일 브라우저의 프로필 기록만 보인다는 설명.
- `playerId`로 한 사람의 기존 최고 레코드를 찾는다. 닉네임 문자열을 신원 키로 사용하지 않는다.
- 점수 내림차순 → 기존 저장 순번 오름차순 → 안정 ID로 정렬, 앞 20명 표시.
- 플레이어별 최고가 갱신될 때만 교체한다. 동점/낮은 점수면 기존 문장·기록 유지.
- 개인 클리어 완료 기록은 Top20 바깥이어도 보존한다. 랭킹 밖이면 ‘클리어 완료 · 현재 Top20 밖’으로 표시한다.
- 새 원정 시작/프로필 변경이 다른 프로필의 랭킹을 삭제하지 않는다. 저장소 이름을 바꾸지 않는다.
- 닉네임은 기존 표시 이름을 사용하되 실명·학번·학교명 입력을 요구하지 않는다. 기록 화면 텍스트는 HTML로 삽입하지 않는다.
- 클리어 저장과 로컬 보드 upsert는 기존 IndexedDB 트랜잭션 등 일관된 저장 경계로 묶는다. 메모리 모드라면 ‘이번 세션 기록 — 브라우저를 닫으면 사라질 수 있음’을 표시한다.

## 5. 서비스 어댑터 경계

다음은 신규 코드에 대한 인터페이스 제안이며 이미 존재하는 엔드포인트가 아니다.

```text
LeaderboardRepository
  mode: LOCAL | REMOTE
  listTop({rulesetId, limit:20}) -> entries
  upsertClear(clearRecord, {idempotencyKey}) -> persisted result
  getOwnBest({playerKey,rulesetId}) -> own record | null
```

UI·완료 로직은 특정 제공자의 SDK를 직접 호출하지 않는다. 로컬 어댑터로 실제 저장/정렬을 먼저 검증하고, remote 어댑터에서만 네트워크를 사용한다.

공용 엔드포인트의 제안 계약:

```text
GET  /leaderboard?ruleset=<id>&limit=20
POST /clears
```

POST는 인증된 서버 측 player key, stable clearId, ruleset, 실제 bestAttackSnapshot, completion evidence를 받는다. 응답에는 저장 여부, 자신의 최고값, 상위20목록/순위, 검증 수준을 포함한다. displayName은 사용자 입력이라도 player key를 마음대로 바꾸게 해서는 안 된다.

- 서버 비밀키·관리자 토큰을 프런트 번들/브라우저 localStorage/저장소에 넣지 않는다.
- 네트워크 실패 시 게임 클리어를 취소하거나 버튼을 잠그지 않는다. 로컬 완료를 보존하고 같은 clearId로 재전송할 수 있게 한다.
- 실패 요청이 재시도돼도 점수가 합산되거나 참가자 행이 늘지 않는다.
- 로컬 순위와 공용 순위를 섞지 않는다. 공용이 끊기면 ‘연결 안 됨’이지 자동으로 로컬 순위를 공용이라고 표시하지 않는다.
- 외부 전송 대상은 닉네임·점수·해당 문장·필요한 검증 정보다. 로그인/개인정보 수집을 새로 정할 필요가 있다면 운영 결정이 필요함을 보고한다.

## 6. 검증 수준과 위조 가능성

브라우저가 계산한 수치와 `cleared:true`만 받아서는 공용 기록의 정당성을 입증하지 못한다. JSON 해시를 만들거나 클라이언트에 서명 비밀을 넣었다고 보안이 완성되는 것도 아니다.

본 패치에서 구분할 수준:

| 수준 | 실제 의미 |
|---|---|
| LOCAL_UNVERIFIED | 같은 브라우저의 게임 엔진/저장 흐름으로 만든 기록. 외부 변조에 안전하다는 보장은 없음 |
| SERVER_SCORE_CHECKED | 서버가 제출 문장의 점수 계산을 재현함. 그 카드/룬을 정당하게 얻고 원정을 끝냈다는 검증은 별개 |
| SERVER_RUN_VERIFIED | 서버 권위 상태 또는 고정 버전·시드·허용 명령 로그로 카드 획득/진행/완료와 대표 공격까지 확인함 |

공용 서비스를 연결할 때 어느 수준인지 명시한다. 경쟁성이 있는 공용 순위의 정당성을 주장하려면 마지막 수준이 필요하며, 단순 점수 재계산을 원정 전체 검증으로 부풀리지 않는다. 현재 사용자에게 서버/인증/검증 비용이 승인되지 않은 상태에서 대형 리플레이 인프라부터 새로 만들며 게임 패치를 지연하지 않는다.

원정 재현을 채택한다면 안전 저장에서의 재시도는 기존 정책대로 모델링하고, 서버가 받아들인 완료 실행 경로를 검사한다. 고스트/AI가 시뮬레이션한 승리와 실제 사용자 플레이를 섞지 않는다.

## 7. 최소 화면

완료: `원정 클리어 · 50 / 50` → `이번 원정 최고의 한 문장` → 점수·문장 → 로컬 또는 공용 상태.

보드: 닉네임 밑에 점수·문장 한 줄. 긴 문장은 생략 표시 후 누르면 전체 문장과 달성 전투를 확인. 실제 제출 문장만 표시. 가상의 20명을 넣거나 예시 순위를 운영 데이터처럼 보여주지 않는다.

기존 기록/로비에서 보드로 접근하는 작은 버튼이면 충분하다. 전투 중 상시 랭킹 패널, 새로운 온라인 로비, 친구 시스템, 공유 이미지/애니메이션은 이번 범위가 아니다.
