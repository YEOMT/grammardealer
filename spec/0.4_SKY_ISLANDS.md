## 0. 가장 먼저 읽을 지시

현재 작업 시작 시점의 최신 `origin/main`이 유일한 **코드 기준**이고, 이 문서가 이번 **변경 내용 기준**이다. 위 SHA는 명세 작성 당시의 읽기 기준이며 작업을 그 SHA로 되돌리라는 뜻이 아니다.

1. `AGENTS.md`, 최신 README·인계·아키텍처·언어 범위·0.3 테스트와 실제 코드를 읽는다. 미커밋 변경을 보존하고, 원격 fetch 후 main과 현재 작업의 차이를 확인한다. 독립 작업 브랜치 또는 worktree에서 진행한다.
2. 0.3의 정상 기능을 확장한다. 과거 Work ZIP, 단일 HTML, 배포 번들로 최신 소스를 대체하지 않는다. 다른 DS 게임·배틀로얄 코드를 사용하지 않는다.
3. Vanilla JS + ES Modules + Vite를 유지한다. 새로운 서버·AI API·번역기·상태관리 프레임워크·마나 시스템을 도입하지 않는다.
4. 이번 목표는 **Stage 1~4 총 17전투, 두 번째 상점, 실제 접속사/절 판정, 보급/탐색 운영 카드, 합의된 명칭·형태 메뉴·덱 보완**이다. 기획 요약·UI 데모·정답 문자열 목록만 만들고 종료하지 않는다.
5. 구현 중 관련 테스트부터 실행하고 안정된 뒤 최종 필수 회귀를 수행한다. 이미 정상인 부분을 반복 재작성하거나 무거운 검사를 작은 CSS 수정마다 전부 반복하지 않는다. AGENTS의 필수 검사 자체를 생략하지 않는다.
6. 완료 후 작업 브랜치를 push하고 main 대상 PR을 만든다. **main 직접 push·자동 merge·Pages 설정 변경·승인 없는 공개 배포는 금지**한다.
7. 확정 요구와 미정 수치 보완을 구분한다. 아래 `구현 초깃값`은 작업을 막지 않기 위해 이번 명세가 정한 설계값이다. 이를 이미 플레이 검증된 값이라고 주장하지 않는다.

## 1. 업데이트 목표와 최상위 원칙

사용자는 0.3의 고점, 원킬, 룬 조합, 골렘의 긴장감과 기본 진행에 만족했다. 따라서 기존 체력/점수/턴을 다시 광범위하게 조정하는 업데이트가 아니다.

- **단어 카드는 문장 재료**, **룬은 문장/운영의 강화**, **운영 카드는 필요한 재료를 확보하는 도구**다.
- 학습은 안내하되 일반전의 정답 빌드를 강요하지 않는다. 올바른 짧은 문장, 긴 문장, 지역 핵심 문법과 변칙 빌드가 함께 유효해야 한다.
- 비어 있지 않은 합법적인 단어 조합은 제출 가능하다. 핵심 구조 실패도 카드·턴을 소모하며 0피해. 기술 오류는 무소모 복구다.
- 문법 성립은 해금·보스·룬과 독립적이다. 기본 판정으로 확인한 정상 구조를 미해금 때문에 오답/미지원으로 바꾸지 않는다. 반대로 분석 실패를 무조건 정답으로 바꾸지 않는다.
- 단어 뜻의 부자연스러움, 인물·사물의 상식적 부조화로 전투 점수를 깎지 않는다.
- 학생에게 보여주는 문법·역할·수치는 실제 분석/정산 증거에서 나오며 교육 설명은 검토 가능한 고정 데이터다.
- 아직 존재하지 않는 문법·시스템을 가짜로 지원하지 않는다. 런타임에서 'UNSUPPORTED이면 VALID' 같은 통과 처리는 금지다.

## 5. 사용자 이름·형태 메뉴

### 5.1 브랜딩

로비·브라우저 document title·전투 작은 로고·결과·새 사용자 안내의 이름을 `Syntax Atlas` / `신택스 아틀라스`로 통일한다. 대문자 로고 `SYNTAX ATLAS` 허용. 기존 버전·가제 기록은 history에서 보존한다.

저장소 `grammardealer`, URL base `/grammardealer/`, local storage/IndexedDB 이름, profile ID, card/rune ID는 그대로다. `package.json` 버전만 0.4.0으로 올리고 배포 경로까지 이름에 맞춰 바꾸지 않는다.

### 5.2 형태 메뉴 레이아웃

데스크톱/태블릿 가로 기준:

```text
현재 / 원형                 (전체 너비)
[ be ] [ am ] [ is ] [ are ]

과거                        (전체 너비)
[ was ] [ were ]

과거분사 · p.p.     |   -ing형
[ been ]           |   [ being ]
```

- 현재/원형은 여러 선택지가 한 줄에 여유 있게 배치된다. 폭이 부족하면 그룹 내부에서만 줄바꿈. 과거와 섞지 않는다.
- 셋째 줄의 두 칸은 가독성/터치 최소폭이 부족할 때만 세로로 접는다. 태블릿에서 텍스트/버튼/모달 하단 잘림 금지.
- `be` 기본 label은 **원형**. `활용 선택 필요`라는 화면 문구만 제거하며 `requiresConjugation`/판정은 삭제하지 않는다.
- '완료'만을 형태명으로 사용하지 않는다. p.p.는 과거분사이고 구문에 따라 역할이 달라진다. -ing는 형태명으로 표시한다.
- 같은 철자라도 실제 formId가 다른 과거/과거분사는 각 그룹에서 선택 가능해야 한다. 예: had/had, read/read, run/run.
- 선택 위치·keyboard focus·터치·기존 카드 회수/좌우 이동·드래그 대안·튜토리얼 targetId 보존.
- 단어카드 클릭은 조합대 이동이라는 기존 행동을 유지한다. 새 메뉴에서 자동 활용·정답 미리보기를 넣지 않는다.

| 전치사 | 2 |
| 합계 | 28 |

동사 8장은 `be 2 + 서로 다른 기본 SV 2 + have 고정 1 + 무작위 SVO 2 + 다중 기본 Frame 1`이다. 기존 SVO3 중 한 자리를 have로 **대체**한다. have는 고정 최소 1장이고 기존 사본 상한 내에서 무작위 추가 사본이 나오는 것은 허용한다. be 2장 규칙 유지.

`I / you / they` 각1 + `he 또는 she`1, `a/a/the`, 부사 역할/형용사 다양성/명사 다양성/1~3형식 첫패 witness를 보존한다. 새 접속사·내용동사·운영 카드는 시작 후보에 추가하지 않는다.

have가 선택 어휘 수준에서 제외되어 고정 생성이 실패하지 않게 CORE 기본재료로 처리한다. 기존 어휘모드 가중치의 나머지 동작은 보존한다.

### 6.2 고급으로 변경할 네 카드

`card.be`, `card.have`, `card.you`, `card.i` → `UNCOMMON`. I의 표시 철자는 I 유지. 기본점수10·연마+5·최대3 유지. 희귀도는 보상/상점 후보와 외형에만 영향을 주며 판정·피해·문법 보너스를 바꾸지 않는다.

그 외 대명사, a/an, the 등을 한꺼번에 상향하지 않는다. 고급 시작 카드를 허용하며 starterEligible을 rarity==COMMON으로 제한하지 않는다.

새 0.4는 새 generator/version view를 사용한다. 동일 seed로 0.3과 0.4 덱이 달라지는 것은 의도된 변경이며, **각 버전 내부 재현성**을 검사한다. 구버전 저장/새로 복원한 구버전의 카드·RNG는 바꾸지 않는다. 새 실습의 주차된 normal deck 검증도 have 고정 구성에 맞춰야 한다.

## 7. 운영 카드 계약

### 7.1 두 종류만 제공

| ID 제안 | 이름 | 등급 | 효과 | 시작 덱 | 강화 |
|---|---|---|---|---|---|
| `operation.supply` | 보급 | 고급 | 카드 2장 뽑기 | 제외 | 이번 없음 |
| `operation.search` | 탐색 | 희귀 | 드로우 더미에서 단어 카드 1장 선택 | 제외 | 이번 없음 |

물리 카드 정의 ID는 기존 네이밍에 맞게 `card.operation.supply/search` 등으로 정할 수 있다. 명세 전체 참조를 일관되게 맞춘다. 실제 기능은 위 두 가지로 고정한다.

카드 앞면에 **운영**, 이름, 효과, **전투당 1회**, 사용 버튼을 표시한다. '1회성'만 적어 원정 영구 삭제로 오해하게 하지 않는다.

### 7.2 Word와 Operation을 엄격히 분리

`cardKind: WORD | OPERATION` 또는 동등한 discriminated type을 도입한다. 구버전 WORD는 명시적 버전 migration에서 WORD로 해석한다. lexemeId가 없다고 임의의 손상 카드까지 OPERATION으로 인정하지 않는다.

- 운영 카드에는 Lexeme/Sense/동사형/품사/문장 기본점수가 없다. 가짜 명사 lexeme을 등록해 오류를 피하지 않는다.
- 언어 registry는 단어만 다룬다. 통합 card definition 조회를 사용하더라도 Grammar 입구에서 WORD 타입만 받는다.
- 생성·첫패 witness·지역재료검색·어휘 사전·의미/문법 데이터는 WORD 필터를 사용한다.
- 보상·상점·소유목록·손패·DRAW/DISCARD/사용완료 보기·저장 validator는 두 타입을 모두 안전하게 처리한다.
- `ADD_CARD`, drag-to-board, SWAP, SET_FORM 등 모든 진입점에서 OPERATION의 조합대 진입을 거부한다. UI만 막고 Controller는 통과하는 구현 금지.
- 오염된 SentenceSnapshot에 운영 카드가 있다면 무결성 오류로 무소모 rollback. 조용히 빼고 나머지만 정답으로 만들지 않는다.

### 7.3 사용 조건·비용

일반 전투의 편집 상태에서 손패에 있는 운영 카드만 사용한다. 실습, 공격/운영 연출, 탐색 대상창, 보상·상점·패배·완료 상태에서는 사용 불가. 운영 카드가 여러 장이면 같은 턴에 각각 사용할 수 있다. 새 '턴당 1스킬 제한'을 만들지 않는다.

사용은 행동 턴·교환 횟수·점수·적 HP를 직접 바꾸지 않는다. `turnIndex/actionSequence`를 공격/준비처럼 늘려 턴 보너스를 줄이지 않는다. 별도의 operation sequence와 effect ID로 중복을 방지한다.

사용 성공 시 해당 **사본**을 `exhaustedIds`(또는 기존 체계에 맞는 동일 개념)로 이동한다. 소유 activeCardIds에서 제거하지 않는다. 미사용 스킬은 일반 교환으로 discard에 보내도 된다. 교환은 기존 교환 1회와 같은 수 드로우 규칙을 따르고 효과는 발동하지 않는다.

### 7.4 보급의 원자 처리

1. 카드 타입·소유·손패·phase·revision·미사용 상태를 검증한다.
2. 그 사본을 손패에서 빼고 사용 완료 영역으로 옮긴 **제안 상태**에서 공간을 계산한다.
3. 기존 drawCards와 해당 run의 deck RNG를 사용해 최대 2장을 뽑는다. 이는 섞인 drawIds의 다음 카드이며 전체 소유목록에서 두 장을 새 추첨하는 것이 아니다.
4. draw가 비면 기존 discard 재셔플은 허용한다. exhausted/sentence/hand는 섞지 않는다.
5. 스킬도 실제 draw pile에 있으면 뽑힐 수 있다. 다만 자신을 다시 뽑지는 못하며 모든 성공 사용은 한 사본을 소진하므로 유한하다.
6. 손패 한도를 넘기지 않는다. 사용할 때 본인 한 칸이 비므로 10/10 손패는 보통 1장만 받고 10장이 된다. 9/10이면 2장을 받고10장이 된다.
7. 받을 카드가 전혀 없으면 무소모 실패. 받을 수가 1이면 '현재 1장만 받을 수 있습니다'를 사용 전 UI에 표시한다. 미래 카드 정체는 보여주지 않는다.
8. 모든 검증 후 카드 이동·RNG·효과 기록을 한 번 커밋한다. 취소/예외는 모두 보존한다.

### 7.5 탐색의 대상 선택

- 대상은 **현재 drawIds 안의 WORD 카드**만. discard/exhausted/hand/조합대/도감 이력에서 가져오지 않는다.
- 대상 목록은 단어 이름 등 공개 가능한 기준으로 정렬한다. 실제 덱 순서·다음 카드·RNG를 표시하지 않는다.
- 같은 단어의 여러 사본은 물리 ID·연마 상태가 다른 실제 후보로 구분한다. UI는 연마를 표시하되 내부 ID를 학생에게 노출하지 않는다.
- 창 열기와 취소는 자원·카드·RNG를 바꾸지 않는다. 열기 전/선택 시 revision·스킬 사본·대상 위치를 검증한다.
- 타깃 확정 시 스킬을 exhausted로, 대상 하나를 draw에서 hand로 옮긴다. 나머지 draw 상대 순서는 유지하고 RNG는 소비하지 않는다.
- 스킬 자신이 손패에서 빠지므로 가득 찬 손패에서도 대상 1장을 받을 수 있다.
- 대상이 없으면 사용 불가 안내. 자동 재셔플하거나 discard를 대신 열어 검색하지 않는다.
- 무효 target·stale click·중복 확정·닫기/재열기·탭 복원은 무소모이거나 멱등이어야 한다.

### 7.6 전투 사용완료 영역과 저장

새 전투 중 카드 보존식:

`소유 카드 집합 = DRAW ⊔ HAND ⊔ SENTENCE ⊔ DISCARD ⊔ EXHAUSTED`

다섯 집합은 겹치지 않고 누락도 없다. SENTENCE는 WORD만, EXHAUSTED는 그 전투에 성공 사용한 OPERATION만. 사용완료 카드는 안전한 더미/덱 보기에서 위치를 확인할 수 있다. 한도를 피하려고 소유카드 목록에서 숨기지 않는다.

다음 전투 시작에서 기존 전체 소유 덱으로 셔플할 때 사용완료 사본도 복귀하고, 새 exhausted는 비운다. 원정/보상/상점에서는 combat=null 상태의 소유 카드가 기준이다.

기존 안전 저장점은 유지한다. 진행 중 탐색/효과 표시 중 저장 금지. 안전 상태에 저장 가능한 정책이면 exhausted·남은 draw 순서·RNG·operation 처리 이력을 함께 저장해 재사용 리셋을 막는다. 새 중간전투 자동저장은 추가하지 않는다.

### 7.7 연마·제거·되돌리기

- 0.4 운영카드는 **연마 대상에서 제외**한다. 보상·상점의 연마 팝업에 끼어 유료 무효 강화가 되지 않게 한다.
- 영구 카드 제거에서는 운영카드도 선택 가능하다. 제거 취소는 보존한다. 원정 사전에 가짜 영단어를 남기지 않는다.
- 성공 사용은 RNG/정보를 공개한 확정 행동이므로 편집 Undo로 되돌릴 수 없다. 성공 후 기존 편집 undo stack을 비워 이미 사용한 카드를 복원하지 못하게 한다.
- 대상 취소/불가/기술 예외에서는 이전 undo stack을 보존한다.
- 단어카드 복사·연마 효과를 운영카드에 자동 상속하지 않는다. 미래 업그레이드 schema를 위한 자리만 필요하면 두고 runtime 미구현을 성공 처리하지 않는다.

### 7.8 외형·효과

- 단어 카드와 같은 폭/높이/손패 레이아웃. OPERATION 전용 class를 사용하고 품사색 stripe와 POS 태그를 제거한다.
- 기본 흰색/은색 테두리·중립 바탕·종류 아이콘. 등급 배지는 별도. 품사 없는 카드에 기본 NOUN 색을 fallback으로 적용하지 않는다.
- 동일한 위치와 터치 크기의 버리기 체크. 체크는 사용과 독립적이다.
- 본체 클릭은 설명/선택 상태 표시, **사용 버튼이 실제 발동**. 조합대 이동과 혼동되는 onActivate 공유 금지.
- 사용 확정 후 카드가 사사삭 흩어지는 짧은 VFX(초깃값 180~300ms), draw 또는 선택 카드의 진입 연출. 효과 수치와 실제 받은 장수 일치.
- 기존 presentation clock/감소효과/음소거 정책 활용. 연출 재생·watchdog·탭 전환으로 카드를 다시 주지 않는다. 명령 결과는 한 번 커밋, 화면은 그 결과를 재현한다.

## 8. 운영 카드의 보상·상점 통합

### 8.1 외부 보상 확률은 유지

| 선택지 한 칸의 타입 | 일반전 | 지역 보스 |
|---|---:|---:|
| 일반 카드 | 50% | 0% |
| 고급 카드 | 10% | 10% |
| 희귀 카드 | 5% | 10% |
| 연마 | 15% | 25% |
| 제거 | 10% | 5% |
| 룬 | 10% | 50% |

혼합3칸 중1, 같은 서비스 중복/무효 타깃 필터, 고정 공개 후보·취소·건너뛰기 재화를 보존한다. 운영 전용 7번째 외부 보상 타입과 별도 슬롯을 추가하지 않는다.

### 8.2 내부 카드 분기 초깃값

- 외부 타입이 `CARD_UNCOMMON` 또는 `CARD_RARE`이고 슬롯 역할이 GENERAL/WILDCARD인 경우에만, 운영 후보를 선택할 내부 확률을 **20%**로 둔다.
- 고급 운영 후보는 보급, 희귀 운영 후보는 탐색이다. 나머지80%는 해당 등급 WORD 후보를 기존 정책으로 뽑는다.
- `LOCAL_SYNTAX_RELEVANT` 보호 슬롯에는 운영 카드를 넣지 않는다. 보상 팝업당 운영은 최대1칸. 운영을 이미 뽑았으면 다음 카드 슬롯은 WORD로 간다.
- 유효 후보 부족/같은 카드 중복/형태의 role fallback을 trace로 기록한다. 이20%를 실제로 모든 전투에서 운영을 볼 확률이라고 설명하지 않는다.
- 최초 1-1의 고정 일반 카드, 매 원정 1-2의 룬 선택은 유지한다. 실습과 샌드박스 보상에 운영을 자동 지급하지 않는다.
- 0.4 새 원정에서 스킬은 이후 일반 보상·상점에 등장 가능하다. Stage4까지 절대 잠그지 않아 골렘 대비에 쓸 수도 있다. 새 영구 업적 잠금은 추가하지 않는다.
- skip은 WORD/OPERATION 중 CARD 칸이 있으면 기존 +3, 카드 칸이 없으면 +2. 스킬 때문에 skipGold가 누락되지 않게 한다.

### 8.3 상점

| 구간 | 룬 상품 | 카드 상품 | 서비스 |
|---|---:|---:|---|
| Stage2 첫 상점 | 1 | 2 | 연마1회 + 제거1회 |
| Stage4 두 번째 상점 | 2 | 3 | 연마1회 + 제거1회 |

카드상품 첫 슬롯은 WORD 지역재료 보호, 나머지에서 위 운영 내부 확률을 사용한다. 한 상점 운영 카드 최대1개. 기존 상품 크기와 배치를 활용한다.

가격: 단어 일반6/고급10/희귀14, 룬18/24/32, 연마8, 제거6에서 누적 유료 제거당 다음+2. **보급10·탐색14**. 골드에 따라 가격을 바꾸지 않는다. 네 핵심 단어의 새 등급은 새상품의 가격에 정상 반영한다.

한 상점 연마와 제거는 각각1회다. 두 번째 상점에서는 새로운 서비스 사용기록을 만들지만 누적 유료 제거 횟수는 유지한다. 첫 상점을 재방문하거나 새로 추첨하지 않는다.

closed shop1을 history로 보관하고 새 shop2를 만드는 최소 구조를 사용한다. currentShop 하나와 history map 등 실제 코드에 맞게 구현하되, Stage2 전용 guard/id/entry 검사만 복사해 두 번째 상점이 거절되지 않게 한다.

## 9. Stage 4 월드·진행

| 전체 전투 | 지역 전투 | 적 | 권장 경험 | HP 초깃값 |
|---:|---|---|---|---:|
| 13 | 4-1 | 구름양 | and와 두 덩어리 연결 | 440 |
| 14 | 4-2 | 갈래바람 정령 | but/or, 대조·선택 | 480 |
| 15 | 4-3 | 매듭뱀 | because/when/if, 이유·시간·조건 | 520 |
| 16 | 4-4 | 메아리 새 | that 명사절, 내용 담기 | 560 |
| 17 | 4-5 | 하늘길의 문지기 | 절 연결로 보호막 해제 | 640 |

일반전은 특정 접속사의 강제 사용·면역·랜덤 피해감쇠가 없다. 추천 주제를 짧게 소개하되 모든 합법 빌드로 이길 수 있다. 지역 보너스는 네 전투 모두 동일한 정상 절 연결 기준이며, 예컨대4-2에서 and를 썼다고 지역 이득을 박탈하지 않는다.

공중섬/흰 돌다리/구름/바람을 CSS·기존 자산 manifest·이모지 placeholder로 표현한다. 구름양🐑, 정령🌬️, 매듭뱀🐍, 메아리 새🐦, 문지기🧙 등을 사용 가능하나 이름과 차이는 명확해야 한다. 실제 미술 이미지 생성·외부 GIF/BGM 호출은 하지 않는다. 단일 적·단일 체력바 유지.

진행:

`Stage3 골렘 완전 격파 → STAGE3_CLEAR/룬4칸 및 새 링크 Pack 해금 → 골렘 보상 → Stage4 전환 → 문지기 실루엣·방어규칙 공개 → 입장 카드 → 두 번째 상점 → 4-1~4-5 → 최종 보상 → STAGE4_END`

- Stage3에 새 상점을 넣지 않는다. 총 장기 상점 일정 2/4/6/8/10/최종전 직전 유지.
- 4번째 룬 슬롯은 기존 Stage3 완료의 원정 성장으로 이어받는다. 새 원정은3칸. Stage4에서 슬롯5를 주지 않는다.
- Stage4 완료가 실제48전투 스토리 클리어는 아니다. 난이도/새 캐릭터/보스변형/무한모드 해금을 일으키지 않는다.
- 기존 Stage2/3 완료 기록을 CONTENT_COMPLETE에서만 처리하지 않는다. 중간 지역이 되어도 실제 milestone은 멱등 정산한다.

## 10. 접속사/내용동사 데이터와 입장 재료

### 10.1 신규·재사용 단어

| 단어 | 역할 | 등급 초깃값 | 시작 덱 |
|---|---|---|---|
| and / but / or | 등위접속사 | 일반 | 제외 |
| because / when / if | 종속접속사: 이유/시간/조건 | 고급 | 제외 |
| that | 기존 지시어·관계사 보존 + 명사절 접속사 | **기존 희귀 유지** | 기존 제외 유지 |
| think / know / say | 기본 that 목적어절을 받는 동사 | 일반 | 제외 |

최신 DB에 이미 있으면 기존 Lexeme/Card ID를 재사용한다. 안에 동일 that 카드를 하나 더 만들지 않는다. 새 수업에 필요하지 않은 although/so/unless/while/after/before/what/which/whether 등을 덧붙이지 않는다.

새 내용동사는 한국어 단어 뜻·Sense·Frame·형태와 정상/오류 예문을 작성한다. 단어 사전에만 뜻을 제공한다. think/thinks/thought/thought/thinking, know/knows/knew/known/knowing, say/says/said/said/saying을 어휘 근거로 확인한다. 동사구의 이전 시제와 결합 테스트를 작성한다.

기본 용법: think는 자동사 사고 활동 및 (that) 내용절, know는 목적어/문맥상 목적어 생략/(that) 내용절, say는 목적어 및 (that) 내용절. 목적어 두 개나 object+to를 모든 새 동사에 일괄 허용하지 않는다. know의 기본 지식 Sense는 보통 진행형을 쓰지 않으므로 `knowing`의 존재와 그 Sense의 진행 허용을 구분한다. 현재 기본 용법에서 진행을 활성화하지 않을 경우 형태의 존재를 부정하지 말고 단어 사전의 한 줄 안내로 정확히 표현한다. 관련 음성 테스트에서 이를 정상 무오류 진행 콤보로 통과시키지 않는다. 이번 know 기본 지식 Sense의 진행 사용은 `ASPECT_USAGE` 정확성 오류(-10)로 복구하며 완전문장 보너스와 해당 진행 보너스를 제외한다. 문장 전체를 기술 오류로 돌리지 않는다. 새 문법 오류 표시는 'know의 기본 뜻은 보통 진행형으로 쓰지 않습니다.'로 고정한다. 이는 know의 해당 Sense에 한정하고 기존 think/have/be 등의 용법에 통째로 적용하지 않는다.

모든 새 기능어·내용동사는 검증 후 0.4의 전체 보상 풀에 들어간다. Stage4 이전에 얻어 정상 문장을 만들면 기본 판정/일반 공격이 가능하고 전용 콤보만 Pack 해금에 따른다.

### 10.2 입장 공급 — 최대 네 장

Stage4 안내 뒤 combat=null인 시점에 실제 소유 WORD를 점검한다.

1. and가 없으면 and 1장.
2. because/when/if 중 하나도 없으면 because 1장.
3. 실제 that-목적어절을 받는 동사 카드가 하나도 없으면 think 1장.
4. that이 없으면 기존 that 1장.

확인 순서/정렬/기본 대표는 고정한다. 손패가 아니라 activeCardIds에 남은 소유가 기준이다. 운영 카드·단어를 제거한 이력만으로 보유 판정을 하지 않는다. 이미 있으면 추가 사본을 무료 지급하지 않는다. `entryGrants['stage.04']`로 1회 멱등 처리하며 주어진 카드는 실제 물리 ID를 갖는다.

이후 필요한 모든 접속사를 매 라운드 강제 지급하지 않는다. but/or/when/if의 접근은 새 상점·지역 관련 보상 가중치 안에서 확보하고, 특정 카드가 안 나왔다는 이유로 일반전의 승리를 막지 않는다. 핵심 and/종속절/명사절 재료는 입장 공급으로 가능 경로를 제공한다. 공급後 정답 손패를 강제하지 않는다.

Stage4 진입 28장 유지가 아니다. 정상 보상·기존 입장 카드·이번 부족분 때문에 실제 덱은 커질 수 있다. 임의로 다른 카드를 삭제하지 않는다.

### 10.3 해금

실제 Stage3 클리어에서 `pack.clauseLink`(또는 대응 metadata)를 원정+프로필에 한 번 해금한다. 기존0.3 프로필에 검증 가능한 Stage3 클리어 사실이 있으면 새0.4 원정의 baseline에 자격을 반영할 수 있다. 완료 사실을 이름/최고 점수로 추측하지 않는다.

기본 판정은 Pack을 읽지 않는다. 잠긴 연결 문장은 정상 채점하되 새 절/구 연결 보너스만 제외한다. 기존 시간·문형·룬이 해당 구조에서 성립하면 정상 적용한다. 이미 해금한 프로필은 다음 원정 Stage1에서도 새 연결 콤보를 쓸 수 있다. 공개 보상/기존 원정의 eligibility는 소급 변경하지 않는다.

## 11. 문법 지원 범위 — 단어/구와 절을 구별

기존 NP/AP/PP·동사 Frame·비정형절·관계절·시제 엔진을 재사용한다. 문장을 split('and')로 잘라 앞뒤 각각 regex 검사하는 대체 엔진 금지. 문법 구역·절별 동사구·전체 카드 사용 증거를 보존한다.

### 11.1 and/but/or

필수:
- 독립절 + and/but/or + 독립절: `I like music and she likes books.`
- 주어/목적어 자리의 NP and/or NP: `You and I are happy.` / `I like books and music.`
- AP and/but/or AP: `She is kind and happy.` / `The book is small but useful.`
- 동일 주어 공유 동사구의 기본 병렬: `I run and play games.` / `She will run and work.`
- 필요한 PP/AdvP 같은 동종 구의 병렬은 기존 파서 성분을 재사용해 bounded하게 지원한다. 사례와 지원경계를 명시한다.

독립절 병렬과 같은 주어의 동사구 병렬은 별개로 기록한다. 공유주어 동사구를 완전한 두 독립절이라고 가짜 표시하지 않는다. 병렬 성분이 동일한 역할에 맞는지 검사한다. `I am happy and she.`처럼 남은 덩어리를 무시하고 성공시키지 않는다.

NP 병렬에서는 전체 주어의 인칭·수가 일치 검사에 반영된다. 최소 `You and I are`, `He and she are`, `The dog and the cat run` 정상; 같은 자리에 is/runs를 쓰면 복구 가능한 일치 감점. `or` 주어는 지원하는 학교문법 대표 agreement 규칙을 고정 데이터·음성/양성 테스트로 명시하고 명백한 수 일치를 오류 없이 처리한다. 도메인 밖의 단일개념 예외를 semantic 추론으로 일반화하지 않는다.

### 11.2 because/when/if

- 주절 뒤 부사절, 부사절 앞+뒤 주절 두 순서를 모두 지원한다.
- `I am happy because you are here`처럼 here 카드가 없으면 기존 at home 등으로 fixture를 대체하되 구조 자체는 빼지 않는다.
- 이유/시간/조건 관계 label만 다르며 접속사 개수에 따라 다른 필수 피해를 만들지 않는다.
- because절/when절/if절만 제출한 단편은 이번 독립 서술문 모드에서 핵심 실패. 문맥 속 짧은 대답 전체를 잘못된 영어라고 일반화하는 설명은 금지.
- 각 절의 주어와 실제 finite verb를 확인한다. 종속절 뒤의 명사/동사를 아무 형태로나 허용하지 않는다.
- 일반 조건·미래 시간 표현 예시에서는 if/when절 현재형, 주절 will을 보여준다. 일반 조건과 가정법을 같은 것으로 소개하지 않는다.
- 시제 의미를 완전 추론하지 않으므로 모든 'if+과거'를 가정법 또는 오류로 강제하거나 모든 'if+will'을 일괄 오답 처리하지 않는다. 의지·결과를 나타내는 will 등 정상 용법을 문맥 없이 부정하지 않는다. 새 가정법 보너스는 없음.
- 실제 의미가 이상한 because 연결이어도 구조가 맞으면 의미 감점하지 않는다.

### 11.3 that 명사절

- `I think that she likes music.` / `They know that I am happy.` / `She says that he is working.`
- matrix verb별 that-목적어절 Frame을 실제 등록한다. `I run that she likes music.`을 명사절 Frame처럼 통과시키지 않는다.
- `I think she likes music.`처럼 that 생략도 실제 허용 동사의 내용절로 분석한다. 생략 때문에 오답/감점/가짜 삽입 카드를 만들지 않는다.
- 명사절 전체가 matrix verb의 목적어다. `I think`와 내부 `she likes music`을 무관한 독립절 두 개로 저장하지 않는다.
- 기존 that의 지시대명사/한정사, 관계사 역할과 **실제 문맥으로 구별**한다. 동일 철자의 다른 보너스 중복 금지.
- 관계절의 gap·선행사 증거와 명사절의 완전한 내부 절은 다르다. `I think that she likes`에서 likes의 목적어가 없는 것을 관계절 gap처럼 구제하지 않는다.
- 명사절이 주어/보어/동격인 모든 범위, what절, 간접의문문 if/whether/when 전체는 이번 신규 필수 범위가 아니다. 추후 가능성을 막지 않되 정확한 완료 범위로 보고한다.

### 11.4 중첩·기존 문법과 결합

최소 다음 조합을 16장 한도 안에서 처리해야 한다.
- 기존 시간 동사구 + 접속사: `I played games and she will read books.`
- 현재완료/진행 + 부사절: `I have read the book because you are reading it.`
- 명사절 + 부사절: `I think that she is happy because you help her.`
- 기존 관계절 + 등위절: `I like the book that she reads and you like music.`
- 등위절 3개: `I run and you work and she plays games.`
- 지시 that와 명사절 that가 한 문장에 별도 사본으로 나오는 경우.

같은 물리 카드를 둘 이상의 실제 위치에 복제하지 않는다. 자식 성분이 부모 성분 범위에 포함되는 것은 구조 표현으로 허용하되 base 점수·modifier 점수는 물리 카드별 한 번이다.

중의성은 정상적인 전체 분석 후보 중 기존 학교 기준에 맞는 고정 우선순위로 하나를 선택한다. 룬·보스·해금·피해가 가장 큰 분석을 고르는 것은 금지. 등록 순서가 바뀌어 정오/피해가 달라지지 않게 한다.

파서 작업량·후보·깊이 예산과 memoization은 실제 16장 worst case로 검증한다. 단순히 기존 12,000 작업량 등의 숫자를 유지하느라 필수 예문을 기술실패로 보내는 것, 반대로 무제한 탐색으로 메인스레드를 멈추는 것 모두 실패다. 구조 예산 초과/기술 예외는 학생의 오답으로 기록하지 않고 무소모 안전복구·개발로그에 남긴다. 명세 필수 fixture가 이 경로에 머물면 완료가 아니다.

### 11.5 구두점·대소문자

한 장=한 단어인 기존 입력은 유지한다. 쉼표 카드를 새로 요구하지 않는다. 부사절 전치의 쉼표가 카드에 없다는 이유로 감점하지 않는다. 필요한 쉼표·대문자·마침표는 **판정 후 표시 서식**이며 점수/단어수/물리 Snapshot을 바꾸지 않는다. 개발 text fixture에 쉼표/마침표가 있어도 punctuation을 단어카드로 세지 않는다.

## 12. 제출 결과·오류 비용

0.2.2/0.3 철학을 그대로 유지한다.

|---|---|---|

실패 문구:

> 문장을 완성하지 못하면 데미지를 줄 수 없습니다.  
> 주어와 동사의 위치를 다시 확인해 보세요.

원인이 입증되면 'because 뒤에 주어와 동사가 있는 절을 완성해 보세요' 같은 고정 피드백을 추가할 수 있지만, 엔진이 증명하지 못한 구체 원인을 지어내지 않는다. 모든 오류·안내는 사전 정의된 한국어다. VALID/NP/UNSUPPORTED 등 raw 개발 상태는 학생 UI에 출력하지 않는다.

작은 오류가 내부 절에 있어도 구조적 절 연결 자체가 성립하면 연결 증거를 남길 수 있다. 같은 원인에 여러 영역에서 감점을 중복하지 않는다. 어떤 절의 주어·동사가 틀렸는지 정확한 카드 범위와 연결한다.

- base10, polish+5/max3, 완전문장+30.

- 루비/사파이어/에메랄드1.6/2.2/2.8, 토파즈1.7/2.4/3.2, 호박1.4/1.8/2.4.
- 수정+20/+35/+50, 비취·철+5/+8/+12, 기존 운영 룬 값 유지.
- 운석 룬은 현재0.3의 실제 값/구간을 보존(5~9장 Lv1×2/Lv2×2.25/Lv3×2.5, 10장 이상×3/×3.5/×4).
- 시간 계열 과거1.2, 진행1.3, 완료1.4, will미래1.2 각각공격당1회.
- 각 배수 단계마다 FLOOR, 유리수/안전정수 정책 유지.

### 13.2 문형 기준 절

하나의 문장에 두 주절이 있어도 기존 문형 배율을 무조건 두 번 곱하지 않는다.

- 종속절/명사절이 붙은 문장: **바깥 matrix 주절**이 기준.
- 독립절 등위연결: **왼쪽 첫 독립절**이 점수 기준. 학생 UI에는 '첫 번째 절 · 3형식'처럼 표시한다. 다른 절을 종속절이라고 부르거나 전체 문장을 단일3형식이라고 단정하지 않는다.
- 첫 독립절 안의 명사절/관계절은 그 절의 실제 Frame을 따른다. 후속 절의 문형은 도감/역할에서 정확히 보여준다.
- 주절 문형 룬(루비~토파즈), 항구의 주절4형식 약점 등은 같은 기준 절을 사용한다. 관계절/둘째절4형식을 첫절4형식인 것처럼 연결하지 않는다.
- 일반 현재가 포함되었다고 TIME.PRESENT 배수를 새로 만들지 않는다. 골렘 조건은 전체 정상 finite clause들의 실제 시간 계열을 기존 정책대로 본다.

주절 하나만 갖는 예전 문장의 판정/점수는 바뀌면 안 된다. 새 문형 기준은 사용자에게 검사 화면을 새로 띄우지 않고 점수 event·도감의 정확한 라벨로 표현한다.

### 13.3 새 연결 효과와 순서

0.4 처리 순서:

`카드합 → 정확성감점/제외 → 완전문장+30(한 번) → 기준 절 문형(한 번) → 기존 시간 계열 → 절 연결×1.6(한 번) → 구 연결+10(한 번) → 기존 형용사/부사/PP → 룬 순서 → 지역×1.25(한 번) → 보스 → 최종`

- `절 연결`은 실제 독립절 연결, because/when/if 부사절, 명사절 결합 중 하나 이상이면 공격당×1.6 한 번이다. 세 종류가 섞여도1.6을 세 번 곱하지 않는다.
- 동일주어 VP 병렬·NP/AP/PP/AdvP 병렬은 구 연결로 처리한다. '+10'은 그 공격에서 한 번. 이 노드를 절 연결로 중복 계산하지 않는다.
- 독립된 구 병렬과 절 연결이 실제로 각각 존재하면 +10과×1.6을 모두 받을 수 있다. 같은 `and` 하나를 두 히트로 중복 발급하지 않는다.
- 명사절 that 생략은 실제 명사절 구조가 입증되므로 기본 정상/해금된 절 연결 콤보를 받을 수 있다. 물리 카드가 없는 connector를 문장 길이에 더하지 않는다.
- `that` 관계절만 있는 문장은 기존 상대절 규칙을 따르며 Stage4 명사절/접속사 점수로 이름을 바꾸지 않는다.
- 각 연결 hit에 실제 source connector 카드(있으면), 연결된 node IDs, clause level/role, scope, validity, 교육 라벨을 남긴다. label이 아니라 ID/증거로 계산한다.

## 14. 하늘길의 문지기 — 50% 보호막

### 14.1 규칙

기존 항구와 같은 **한 번 해제 후 유지되는 보호막**이다. 매 공격마다 다시 접속사를 써야 하는 50% 상시 세금이 아니다.

- 시작: `active=true`, 비공략 피해×0.5.
- 공략: 정상적으로 절을 잇는 **실제 접속사 카드**의 역할 증거가 있는 제출이면 **그 공격부터** active=false, 피해감쇠없음.
- 이후: 접속사 없는 정상 문장도100% 피해. 보호막 재생 없음.
- 큰 비공략 공격도50% 피해로 원킬 가능. 절대면역·구간체력·최소공격횟수·피해cap없음.
- 보호막 해제가 별도 추가 턴/재화를 주지 않는다.

### 14.2 공략의 경계 — 문법 판정과 적의 규칙은 별개

| 실제 사용 | 정상 영어/공격 | 보호막 해제 |
|---|---|---|
| and/but/or로 완성된 두 독립절 연결 | 예 | 예 |
| because/when/if로 완성된 주절+부사절 | 예 | 예 |
| that을 실제 명사절 접속사로 사용 | 예 | 예 |
| that이 지시어 또는 관계사 역할 | 기존 정책대로 | 아니오 |
| 단어/구만 and/or 등으로 연결 | 예 | 아니오 |
| 같은 주어를 공유하는 VP 병렬 | 예 | 아니오 |
| that을 생략한 정상 명사절 | 예, 정상 연결 콤보 가능 | **물리 접속사가 없으므로 보호막은 유지** |
| 접속사 뒤 핵심 절 미완성 | 실제 제출·0피해 | 아니오 |

마지막에서 두 번째 규칙은 **접속사 카드를 사용해 결계를 푼다는 이번 보스 규칙**이지, 영어에서 that을 생략하면 틀린다는 뜻이 아니다. 학생 피드백은 '문법 오류'가 아니라 '보호막 유지 · 접속사로 절을 이어 해제'로 구분한다. 자동으로 that을 삽입하지 않는다.

문장의 작은 관사/일치 오류가 연결 구조를 파괴하지 않으면 기존 부분감점 후 보호막 해제를 허용한다. 핵심실패면 해제 없음. 기술 실패면 모든 자원/보스 상태 보존.

### 14.3 문구

입장/보스 예고:

> 연결의 보호막: 절을 잇는 접속사 공격으로 해제합니다.  
> 보호막이 남아 있으면 피해가 50%로 줄어듭니다.

보호막 유지:

> 보호막에 피해가 반감되었습니다. 접속사로 절을 이어 보호막을 깨 보세요.

해제:

> 절이 이어지며 보호막이 깨집니다!

일반 판정실패 문구와 혼용하지 않는다. 실제50% 받은 공격에 '공격이 전부 막혔습니다'라고 표시하지 않는다.

### 14.4 정산·연출

Stage resolver가 구조 전체 증거를 읽고 shieldBefore/After와 damage 제안을 만든다. 콤보 해금으로 필터된 hit만 보아 정상 구조의 공략 증거가 사라지지 않게 한다. Controller가 revision/attackId로 카드·턴·HP·보호막·기록을 한 번 커밋한다.

해제 공격: 일반 점수 연쇄 → 연결 구간/접속사 강조 → 결계 균열 → 카드조립체 충돌 → 온전한 실제HP 감소. 화면에서 보호막이 먼저 다시생기거나 half damage가 잠깐 보이면 안 된다. 최종 state를 연출 전 적 렌더에 노출해 먼저 사라지는 문제도 막는다.

매번 공격 끝 UI가 최신 boss snapshot을 보여준다. 취소/탭 숨김/애니메이션 복원/FINISH 중복은 방어를 재계산하지 않는다.

### 14.5 체력 기준

초깃값640은 다음 **설계 산술**에 근거한다. 초기 full shield, 오류없음, 시간보너스/연마/룬없음, Pack해금, Stage4지역1.25 전제다.

| 문장 | 카드 수 | 계산 | 피해 |
|---|---:|---|---:|
| I am happy and you are kind | 7 | (70+30)×1.6×1.6×1.25 | 320 |
| I like music and she likes books | 7 | (70+30)×1.8×1.6×1.25 | 360 |
| I read a book when she comes home | 8 | floor(floor((80+30)×1.8)×1.6)×1.25 후내림 | 395 |
| I like the book because she reads very well | 9 | floor(120×1.8)=216 →×1.6=345 →부사+10=355 →지역 | 443 |

첫 문장을 두 번이면640, 둘째를 두 번이면720으로 처치한다. **동일 카드를 공짜로 손패에 재생성해서 두 번 제출한다는 뜻이 아니다.** 실제17전투 E2E와 덱 시뮬레이션에서는 서로 다른 카드/재셔플/교환/준비로 두 번째 공격을 만들 수 있는지 별도 검사한다.

약간의 오류가 있는 문장까지 항상 두 번 처치하도록 만들지는 않는다. 평범한 연마/일반 룬0~1종 정도의 정석 빌드, 운영카드 미보유 상태에서도 충분한 도전 경로가 있어야 한다. 희귀 탐색·운석Lv3를 전제해HP를 올리지 않는다.

좋은 룬/운석/시간결합으로 단번에 넘는 것은 의도된 성공이다. 최고 위력에 맞춰 적 HP를 동적으로 올리지 않는다. 목표의 '두 번'은 강제최소2가 아니라 일반적인 준비 부담 기준이다.

## 15. 학습·문장 도감·피드백

- 0.3의 밝은 흰색/볼드/크기 상승 플레이어 문장, 붉은 오류 피드백을 유지한다.
- 자동 한글 문장/성분 번역, 단어별 번역 tooltip을 도감에 다시 넣지 않는다. 뜻은 나의 덱 단어 사전.
- '고정 학습 예문 · 실전 기록 아님' 펼침 영역은 되살리지 않는다. 고정 예문은 내부 QA/교육 설명 검수 데이터로 보존한다.
- 새 접속사/절 역할 설명을 한국어 고정 데이터로 작성한다. '모든 접속사는 완전한 문장 두 개를 연결한다'는 오개념 금지.
- 제안 문구: 접속사='단어·구·절을 연결하며, 문장에서 쓰임에 따라 역할이 달라집니다.'; 절='주어와 동사를 중심으로 이루어진 덩어리입니다.'; 등위절='대등한 두 절을 연결합니다.'; 부사절='이유·시간·조건 등의 정보를 주절에 덧붙입니다.'; 명사절='절 전체가 명사처럼 목적어 등의 자리를 맡습니다.'
- 실제 문장 `I think that she likes music`: I 주어, think 동사, **that she likes music 전체 목적어 명사절**; 내부 she/likes/music 역할도 별도로 표시. 전체 cardIds의 소유권과 교육적 중첩범위를 구분한다.
- `I like music and she reads books`의 두 절은 대등하다. 계산기준이 왼쪽이라고 오른쪽을 '종속절'로 표시하지 않는다.
- `when` 부사절과 `that` 관계절, 지시어 that를 카드철자만으로 같은 종류에 넣지 않는다.
- 첫/최고 정상 예문은 실제 정확한 제출만. 부분오류/핵심실패는 최근시도에서 명확히 구분한다. 운영 사용은 문장 사용횟수·문법도감 예문에 저장하지 않는다.
- 운영 카드 설명은 내 덱에서 '운영 카드' 구역/필터로 볼 수 있다. '뜻: 없음'·fakePOS·undefined·rawID를 출력하지 않는다.
- 운영 사용결과와 접속사 해제 이펙트는 실제 committed 기록을 읽고 열람만으로 다시 실행하지 않는다.

## 16. UI/UX와 기존 화면 보존

1. 기존 상단 적·중앙 점수/조합대·하단 손패·오른쪽 룬·왼쪽 상태 배치를 유지한다. 이미 작동하는 16장/긴단어/손패스크롤/터치카드 크기를 다시 축소하지 않는다.
2. 새 지역은 배경 class/theme만 최소 확장한다. 하늘섬 미술을 이유로 기능 검증을 미루지 않는다.
3. 접속사 연출은 **제출 후** 두 절을 선/밑줄/테두리로 구분하고 연결 카드가 잠깐 다리처럼 빛난다. 명사절은 바깥 목적어 구역에 내부 절이 들어가는 모양으로 구분한다.
4. 점수와 구조를 조합 중 실시간 정답표로 제공하지 않는다. 공개 보스/카드/문법 설명은 가능하지만 제출문별 '공략 가능'은 미리 계산하지 않는다.
5. 여러 절의 강조·시간보너스·기존 룬 비행·보호막 파괴를 하나의 결과 timeline과 함께 처리한다. 중복 카드 하이라이트는 표시상 통합 가능하지만 실제 계산 event를 삭제/조작하지 않는다.
6. 효과 감소·음소거·속도설정·watchdog·hidden탭·터치 취소는 기존 정책 유지. 스킬의 짧은 사라짐과 드로우가 이에 참여한다.
7. 첫 운영카드를 처음 손패에 받았을 때 한 번 짧게 '운영 카드는 사용 버튼으로 발동합니다. 이번 전투에 한 번 쓸 수 있어요.'를 표시 가능. 기존 강제 실습을 운영 수업으로 다시 작성하지 않는다.
8. 룬 순서 ▲▼/드래그·4칸 레이아웃·utility resource snapshot 유지. 교환 체크/UI와 운영 사용 버튼 클릭영역이 겹치지 않는다.
9. 두 번째 상점에2룬/3카드가 보여도 태블릿 가로1024×768에서 가격·구매/서비스 버튼·나가기 접근가능해야 한다.

- 기존 IndexedDB 이름/프로필 ID/수동3슬롯 유지. Syntax Atlas로 표기한다고 DB를 새로 만들어 기록을 잃지 않는다.

## 20. 검증 전략 — 속도와 신뢰성

1. 작은 수정 중에는 해당 parser/operation/shop/UI 검사 우선. final에서는 AGENTS의 `npm test`, `npm run build`, 필요한 브라우저 검사와 아래 회귀를 수행한다.
2. 실제 명령명은 package.json에서 확인한다. 데이터 validator와 seed시뮬레이터가 있으면 재사용한다. 예전보고서의 '몇백PASS'를 이번실행값으로 복사하지 않는다.
3. 새 starter는 네어휘모드×2,500=10,000seed를 권장한다. 구조witness/28장/have보장/중복상한을 동시에 검사한다. 레거시generator는 독립golden 비교.
4. 새연결양성/음성/부분오류/원형/시간/관계절교차/16장·중첩경계 테스트. 단어를 바꾼 hold-out 문장도 검사해 whitelist아님을 확인한다.
5. 보스 순수수치검사와 실제원정 성능을 분리. '미리 만든7장공격두번' 산술이 드로우접근성 증거는 아니다.
6. 자동원정 정책은 현재공개손패만 본다. 미래RNG/덱순서치트·정답카드생성·HP감소·가짜승리 금지. 정상패배를 FAIL/engine오류로 섞지 않으며 사람승률로 해석하지 않는다.
7. 최소 실제production UI 한 원정을 **17전투** 끝까지 실행한다. 시드/선택/입력기록을 남기고 새프로필실습,상점1/2,골렘3단계,접속사,스킬 실제획득/사용,저장복원을 포함한 증거를 확보한다. 특정스킬이 랜덤으로 나오지 않은 완주는 스킬검증과 구분하고 별도합법fixture에서 검증한다.
8. 보급사용+탐색사용+취소+재셔플+손패한도+nextbattle복귀는 실제Controller와UI 양쪽. 마우스와Chromium터치가실제iPad검증인것처럼 보고하지 않는다.
9. 1366×768,1280×800,1024×768 및 기존지원해상도에서 형태메뉴/10장손패/확장손패/16장조합/4룬/SHOP2 캡처. 실제기기없으면 NOT RUN.
10. 성공적실행후 최신소스를 다시고정하고 최종필수검사 재실행. 실행중코드수정으로증거가섞이지 않게 한다. test를 지우거나 assertion 약화/skip으로 통과시키지 않는다.
