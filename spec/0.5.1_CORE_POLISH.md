## 0. 기준과 우선순위

사용자 최종 지시 → 이 명세의 확정 정책 → 최신 코드/AGENTS.md의 보존 계약 → 부속 기대값 순으로 읽는다. 이전 0.5 명세의 새 콘텐츠 요구를 다시 구현하거나 배포 번들에서 소스를 재구성하지 않는다. 기존 정상 기능은 전면 재작성하지 않는다.

이 패치의 불변 목표는 **문장을 스스로 조립해 점수 연쇄를 읽고, 강한 공격을 실제로 느끼는 것**이다. 사용자가 다른 컴퓨터에서는 공격 모션이 정상이라고 확인했다. 따라서 '0.5에서 모션 코드를 지웠다'는 전제를 세우지 않는다. 특정 컴퓨터에서 보이지 않았던 원인은 아직 독립적으로 확정되지 않았다.

이번 작업은 저장소 읽기·로컬 개발·테스트·별도 브랜치 push·PR까지다. **main 직접 push, 자동 merge, Pages 설정 변경, 승인 없는 공개 배포는 금지한다.** 기존 workflow의 PR 검사와 main 배포 경계를 유지한다.

### 0.2 확정 정책과 설계 초깃값의 구분

**확정:** 위 합의사항, 점수/룬/문법/자원 보존, 핵심 피드백 유지, 튜토리얼 스킵의 무보상 정상 1-1 복귀, 동일 철자 대명사 중복 UI 제거, 사전/도감 간소화, 22전투 범위.

**보류:** Stage 6 및 남은 지역, 시작 덱 축소, 운영 카드 전면 아트 리디자인/연마/재사용, 희귀 룬 대개편, 신규 문법 엔진 확장, 지도/배경/몬스터 최종 이미지·BGM, PWA·계정·서버·랭킹, 의존성 업그레이드. 운영 카드의 현행 흰색/은색 계열 구분과 사용/체크 영역은 보존한다.

## 2. 보존할 플레이 계약

### 2.1 게임/경제

- 5지역, **22전투**, `STAGE5_END`. Stage 6·전체 스토리 완료·새 슬롯 해금을 추가하지 않는다.
- 시작 덱 **28장 WORD**, be 2장/have 고정/대명사 구성, be·have·you·I 고급, 4개 어휘 수준과 점수 비연동 유지.
- 기본 첫패 6, 손패 한도 10, 턴 드로우 3, 교환 4회, 행동 6턴, 조합대 16장 유지. 이미 있는 운영 룬의 규칙 스냅샷도 유지.
- 기본 카드 10, 연마 +5씩 최대 +3, 완전문장 +30, 1~5형식·시간·연결·준동사·지역·룬 수치는 **0.5.0 그대로**.
- 보상은 혼합 3칸 중 1개, 최초 룬 예외와 모든 외부 확률/가격/지급/skip 재화/남은 턴 보너스를 유지.
- 상점은 Stage 2/4 두 번. 방문별 서비스 한도·누적 유료 제거 가격 보존.
- 룬 순서 조작, 초반 연결어 보상, 쉬운 어휘로 장문 만들기, 준비→교환→강한 한 방은 정상 전략이다. 데이터 근거 없이 이를 억제하는 너프/숨은 상한을 넣지 않는다.
- 보급/탐색은 HAND에서 사용, 전투당 사본 1회/EXHAUSTED/다음 전투 복귀/WORD가 아님. 기능·획득률·희귀도·연마 불가를 바꾸지 않는다.

### 2.2 문장·해금·기록

- `해금 = 해당 문법 콤보 점수의 활성화`다. **맞는 문장이 새로 정답이 되는 것이 아니다.** 이미 엔진이 지원하는 문장/형태를 Stage나 프로필 때문에 거절하지 않는다.
- 문장 성립은 실제 구조 증거, 콤보는 eligibility. 미해금 구조를 1형식으로 위장하거나 UNSUPPORTED를 무조건 VALID로 바꾸지 않는다.
- 의미가 어색하다는 이유로 점수 감점하지 않는다. 모든 자연어를 지원하는 엔진으로 범위를 넓히는 것도 이번 작업이 아니다.
- 핵심 실패 제출도 실제 카드·턴 소모/0피해, 기술적 실패는 거래 전 무소모. 비어 있는 조합대는 기존 제출 비활성 유지.
- 단일 -ing Form과 같은 철자 다중 후보, want+to / want+O+to, 실제 IO/DO·목적격보어 구간, 전치사 to와 부정사 to, that 역할 구분을 보존.
- 한국어 문장 자동 번역, 성분별 단어 번역, 고정 학습 예문 패널, VALID/UNSUPPORTED 같은 내부 상태 문자열을 학생 도감에 다시 넣지 않는다.
- 문구 변경으로 과거 공격의 당시 위력·HP·집계·문법 태그를 다시 채점하거나 늘리지 않는다.


## 3. 전투 피드백: 효과 감소와 접근성의 분리

### 3.1 문제 정의

공격 모션은 현재 코드에도 있고 다른 컴퓨터에서 정상 표시되었다. 한 환경의 미표시만으로 삭제 회귀라 단정하지 않는다. 기존 설정값·OS motion preference·브라우저 기능·연출 중 DOM 생존·좌표·overflow/z-index·document.hidden·실제 bundle 버전을 **비파괴적으로 관찰**한다. 원인을 재현하지 못하면 그렇게 보고한다. 사용자에게 OS 설정을 바꾸게 하거나 IndexedDB/프로필을 지우는 방법을 정식 해결책으로 삼지 않는다.

### 3.2 두 종류의 효과

**CORE_COMBAT_FEEDBACK**: 문장 공격의 출발과 적중, 적 피격 반응, 피해 숫자와 HP 변화, 읽을 수 있는 격파/막힘 상태, 실제 적중에 맞는 기본 타격음. 정상 motion 환경에서는 짧은 hit-stop·국소 반동과 §4의 제한된 오버킬 반동도 핵심으로 취급한다.

**DECORATIVE_VFX**: 추가 광원·룬 광원 비행·잔상·다량 파티클·과한 네온·주변 장식. 효과 감소로 줄이거나 생략할 수 있다. 룬이 발동했다는 이름·배수·해당 슬롯의 최소 표시와 학습용 역할/절 강조는 남긴다.

'기본 타격음 유지'는 **음소거/음량0/브라우저 오디오 권한을 무시한다는 뜻이 아니다.** 효과 감소만으로 음원을 끄지 않는다. 음소거 및 사용자의 오디오 설정은 항상 우선한다.

### 3.3 실행 행렬

| 효과 감소 | OS 동작 줄이기 | 핵심 피드백 | 장식 |
|---|---|---|---|
| OFF | 일반 | 정상 돌진·피격·HP·제한 오버킬 반동 | 기존 효과 |
| ON | 일반 | **동일한 핵심 경로/판정/최소 강도** | 파티클/광원/잔상 축소 |
| OFF | reduce | **비이동 대체 경로**: 출발 카드/적의 짧고 부드러운 테두리·명도 변화, 피해/HP/격파 상태 | 큰 이동·화면 흔들림·반복 점멸 없음 |
| ON | reduce | 위와 같은 비이동 핵심 피드백 | 장식 최소 |

이것은 사용자 합의의 접근성 보완이다. **효과 감소가 타격감을 없애면 안 되지만, OS의 동작 줄이기를 무시하고 큰 카메라 shake를 강제하지도 않는다.** reduce 상태에는 transform 이동을 요구하지 않는다. 낮은 자극의 비이동 피격 표시가 실제로 보여야 한다. 강한 화면 전체 백색 섬광·빠른 반복 점멸은 넣지 않는다.

현재 `effectsOff` 저장 키를 단순 삭제하거나 false로 강제하지 않는다. 의미는 '장식 감소'로 연결하며, 설정 설명은 짧게 `장식 효과를 줄입니다. 공격·피격 표시는 유지됩니다.`로 표시한다. OS reduce가 감지되면 `기기의 동작 줄이기를 적용 중입니다.`를 설정창에서만 짧게 안내할 수 있다.

### 3.4 렌더 구현

- 단일 animate early-return을 유지한 채 core에도 effectsOff를 전달하지 말 것. `animateCore/animateDecorative` 또는 동등한 분리 정책을 둔다.
- 정상 환경의 현재 돌진→적중→피격 연계를 보존한다. UI 구조를 전면 개편하지 말고 기존 실제 카드 조립체 또는 비상호작용 시각 복제만 사용한다.
- 시각 복제는 새 물리 카드가 아니다. 동일 data-card-id/조작 버튼/접근성 초점이 두 개가 되지 않게 inert·aria-hidden 처리한다.
- 원본 위치/적 위치/스크롤/확대율을 정확히 측정한다. 부모 overflow에 가려지거나 변환 좌표가 틀리면 국소 수정한다. 전체 UI의 overflow를 무작정 해제하지 않는다.
- score 계산 동안 적 HP와 외형은 before 상태. **IMPACT에서 HP·피격·보스 상태를 함께** 바꾼다. Controller는 이미 확정한 결과를 한 번만 커밋한다.
- 충돌 이전 카드/적을 지우거나 REWARD 화면으로 교체하지 않는다. 약한 공격도 최소 피격 반응이 있어야 한다.
- `Element.animate` 부재/예외라면 짧은 CSS/DOM fallback 또는 비이동 피격 표시로 복구한다. 오류를 숨긴 채 조용히 무반응으로 끝내지 않는다. 개발용 진단과 실제 fallback 실행 여부를 남긴다.
- 프레임 누락/숨김 탭/배속 변경/중단 후 최종 HP·격파·잠금 해제는 항상 일관되어야 한다. 애니메이션 취소가 피해 재계산을 유발하지 않는다.
- 보급/탐색 소멸 효과도 core 거래 피드백을 잃지 않되 새 효과/카드 성능은 추가하지 않는다.

### 3.5 시간과 오디오

기존 읽기 시간(카드170ms, 문법550ms, 룬 비행220ms+읽기520ms, 사용자가 선택한 속도)을 기본 보존한다. 점수와 역할을 미리 표시하지 않는다. 오버킬 구간만 늘린 만큼 watchdog의 계획 시간도 갱신한다. 테스트를 빨리 끝내려고 wait를 즉시 resolve시킨 검사를 실제 체감 증거로 쓰지 않는다.

일반 탭 숨김 시 기존 fast-forward 정책은 유지 가능하다. 튜토리얼 gate/hidden 시간의 watchdog 제외·중단 복구는 유지한다. 비동기 finalizer는 자신이 소유한 attackId·session·DOM에만 작동한다.

실제 진동 하드웨어/`navigator.vibrate`는 이번 필수 구현이 아니다. 사용자가 요구한 '진동'의 본체는 화면 속 국소 피격 반응이다. 미지원 기기를 이유로 판정·진행이 달라지지 않는다.


## 4. 오버킬 Combat Feel

### 4.1 숫자의 단일 근거

Presentation은 확정 `AttackResolution`의 `finalPower`, `actualHpLoss`, `enemyHpBefore/After`, `overkill`, `killed`, `visualBasis`, 골렘의 `phaseBreak/phaseExcess`를 읽는다. 새 피해/오버킬/재화 공식은 만들지 않는다.

일반 적의 `finalPower`는 현행 엔진에서 지역·보스 감산까지 처리한 최종 위력이다. **보호막 전 점수로 오버킬을 판정하지 않는다.** `actualHpLoss=0`이면 큰 점수였더라도 명중/처치/오버킬 연출로 위장하지 않는다. 핵심 문장 실패·보스 차단·정확성으로 0점인 경우를 기존대로 구별한다.

### 4.2 강도 판정 초깃값

`H = 공격 직전 남은 HP`, `B = visualBasis의 정상 최대 HP(없으면 H, 최소1)`, `P = finalPower`로 둔다. 읽기 전용 시각 계산만 허용한다.

- 실제 피해가 있고 적이 생존: 기존 LIGHT/HEAVY 기준을 유지한다.
- `killed=true`이고 `overkill=0`: 일반 격파. 정확히 남은 HP만큼 때린 것은 오버킬이 아니다.
- `killed=true`, `overkill>0`: 최소 초과 피해 피드백을 제공한다.
- `P/H >= 1.5` **그리고** `P/B >= 0.5`: **LARGE** 초과 피해.
- `P/H >= 2.5` **그리고** `P/B >= 1.0`: **MASSIVE** 초과 피해. 더 높은 조건을 우선한다.
- 위 기준에 못 미치는 초과 피해: **SMALL**. 남은 HP1에 20을 때렸다는 이유만으로 대형 폭발을 만들지 않는다.

이 두 축은 직전 대화의 남은 HP 기준 아이디어를 유지하면서 '거의 죽은 적의 1HP 분모'가 강도를 부풀리는 것을 막는 기술적 가드다. 무한 배수·음수·0분모·안전정수 초과가 없어야 한다. 표의 수치는 연출 초깃값이며, 새로운 피해·경제 규칙이 아니다.

| 단계 | hit-stop 초깃값 | 적 국소 반동 | 짧은 화면 충격 | 읽기 표시 |
|---|---:|---:|---:|---|
| SMALL | 90ms | 8px | 최대 3px | 격파/초과 피해 +N |
| LARGE | 120ms | 14px | 최대 5px | 더 굵은 초과 피해 +N |
| MASSIVE | 150ms | 22px | 최대 8px | 더 큰 충격과 초과 피해 +N |

화면 흔들림은 최대 약180ms, 피격/격파 반동은 약450ms 이내에서 시작한다. 실제 화면으로 확인하고 과하면 amplitude/duration만 조정한다. 효과 감소 ON만으로 core 반동을 0으로 만들지 않는다. **OS reduce에서는 위 이동량을 전부 0으로 하고 비이동 대체 표시**를 쓴다. 텍스트 전체를 지속적으로 흔들거나 다음 조작까지 화면을 불안정하게 두지 않는다.

### 4.3 연출 순서와 정리

점수 연쇄 완료 → 힘 모으기 → 문장 돌진 → 적중 시 HP/짧은 정지 → 적 진동/제한 화면 충격 → 격파 방향 반동 → 다음 화면. 충격 링/색 강조는 적중점에 정렬한다. 기본 링 한 개는 core 대체일 수 있지만 다중 파티클/큰 광원은 decorative다.

오버킬 표시는 `초과 피해 +620`처럼 **이미 계산된 초과분의 설명**이다. 추가 공격력·추가 재화처럼 `보너스 +620`이라고 표시하지 않는다. 기존 기록의 위력/실제 피해/overkill 값을 변경하지 않는다.

### 4.4 골렘과 특수 보스

골렘은 기존 엔진에서 일반 `overkill=0`과 별도 `phaseExcess`를 사용한다. 앞 두 부위 파괴를 보스 전체 격파로 처리하지 않는다. **부위 초과 피해는 이월되지 않으며 오버킬 보상도 생기지 않는다.** 부위 파괴의 국소 충격과 읽기 시간을 유지하고 마지막 부위에서만 보스 격파 연출을 한다.

문지기는 기존 보호막50%/정상 접속사 절 첫 공격부터 해제/재생 없음 유지. 스핑크스 봉인은 턴·사본·교환·운영·저장 정책 그대로다. 연출을 위해 봉인을 다시 뽑거나 다음 턴을 미리 시작하지 않는다.


## 5. 튜토리얼 명칭·건너뛰기·재시청

### 5.1 학생 노출 이름

Stage 1-1 고정 안내의 '실습'은 **튜토리얼**로 통일한다. 시작 안내·말풍선·중단 복구·설정 버튼·기록의 제외 안내·저장 오류 등 현재 학생에게 보이는 문자열을 확인한다.

- `튜토리얼 시작`
- `튜토리얼 건너뛰기`
- `튜토리얼 다시 보기`
- `튜토리얼을 건너뛰고 일반 전투를 시작할까요?`
- `일반 덱으로 1-1 전투를 시작합니다. 튜토리얼 보상은 지급되지 않습니다.`

내부 GUIDED_VERSION, tutorial.021 카드 ID, 과거 문서의 실행 당시 용어는 보존한다. '실습'이라는 글자를 모든 소스에 무차별 replace하지 않는다. 개발 fixture의 이름 변경 때문에 기존 증거를 덮어쓰지 않는다.

### 5.2 시작/프로필 정책

새 플레이어가 처음 튜토리얼에 들어갈 때 시작과 건너뛰기를 명확히 제공한다. 완료한 플레이어의 새 원정에 강제 재실행하지 않는 기존 원칙을 유지하고, **직접 건너뛰기를 선택한 플레이어도 이후 새 원정에서 반복 강제하지 않는다.**

완료와 스킵은 별도 상태다. 기존 `guidedTutorialCompletedVersion`을 스킵 시 가짜 완료로 채우지 않는다. 예를 들어 `guidedTutorialSkippedVersion` 또는 동등한 별도 필드를 두고, 설치 여부를 `완료 || 명시적 스킵`으로 판단한다. UI 용어만 바꿨다고 GUIDED_VERSION을 올려 모든 사용자에게 다시 강제하지 않는다.

튜토리얼을 끝까지 완료하면 기존 40/126 두 공격·덱 복원·Stage 1-1 승리/보상 흐름을 보존한다. **완료 흐름과 스킵 흐름을 합치지 않는다.**

### 5.3 스킵은 일반 1-1을 처음 시작하는 것

스킵 후 상태는 튜토리얼 시작 전에 보관한 **그 원정의 정상 28장 덱과 RNG**로 일반 Stage 1-1 전투를 새로 시작한 상태와 같다.

- seed/runId/선택 어휘수준/정상 카드 ID/연마/해금 baseline을 보존한다.
- 일반 S1-1의 HP77·행동6·교환4·초기 손패6을 해당 원정 버전의 실제 규칙으로 적용한다. 코드에 77/6/4를 새로 여러 번 하드코딩하지 않는다.
- 고정 튜토리얼 카드와 drawStream, 선택 체크, 열린 패널, pending attack, 임시 score label, 잔여 transform, disabled 상태가 남지 않는다.
- 정상 카드 재생성/새 seed 추첨/공개 보상 재추첨은 하지 않는다. 첫 손패를 만드는 데는 복원한 deck RNG와 기존 opener 규칙을 **한 번만** 사용한다.
- Stage 1-2로 바로 넘어가지 않는다. 원정 gold/보상/처치/문법 사용횟수/최고 공격 기록은 증가하지 않는다.
- 스킵은 '이긴 뒤 보상만 건너뛰기'가 아니고, 튜토리얼의 부분 피해를 정상 적에게 이월하지 않는다.
- 초기부터 스킵했든 첫 공격 후 스킵했든, 같은 정상 원정 시작 결과가 나와야 한다. 단 프로필의 스킵 기록과 거래 revision은 별도다.

### 5.4 진행 중 스킵과 비동기 안전

첫 화면뿐 아니라 진행 중에도 확인 후 건너뛰는 경로를 제공한다. 일반 편집/안내 단계와 점수 설명 gate에서 가능해야 한다. **단순한 나가기 버튼**을 스킵이라고 바꾸지 않는다.

애니메이션 한 프레임 중간에 즉시 게임을 바꾸기 어렵다면 버튼으로 스킵 의사를 받고, 자신이 소유한 연출/gate를 안전하게 취소한 뒤 전환한다. 확인을 취소하면 진행하던 튜토리얼을 이어가며 카드/RNG/점수는 바뀌지 않는다. 재료 선택은 사라졌는데 버튼만 잠겨 있는 상태를 만들지 않는다.

Controller 명령은 `SKIP_TUTORIAL` 또는 동등한 전용 명령으로 둔다. 정확한 이름은 코드 구조에 맞추되 sessionId/revision/commandId를 검증한다. 이미 처리한 스킵, 오래된 gate ACK, 늦게 온 FINISH_PRESENTATION은 **무효 요청**으로 처리하고 새 일반전 상태를 덮어쓰지 않는다.

권장 거래 순서:

1. 현재 튜토리얼/세션/스킵 가능 상태를 검증하고 확인 취소는 무변경 처리한다.
2. 기존 비동기 작업의 소유 epoch/session을 무효화하고 animation/clock/gate/listener의 종료를 요청한다.
3. Controller의 제안 복사본에서 parked 정상 상태를 복구한다. 과거 함수 `restoreTutorialDeck()`은 완료 전용 가정을 검토한 뒤 재사용 여부를 정한다.
4. tutorial 종료 사유는 **SKIPPED**로 남긴다. step32/completedSteps를 위조해 완료 validator를 통과시키지 않는다.
5. 일반 1-1 전투를 초기화하고 카드 보존/경제/난수/상태 invariant를 통과시킨 뒤 한 번 커밋한다.
6. 스킵 프로필 사건을 한 번 기록하고 새 DOM/입력 잠금을 정상화한다. 저장 실패는 알리되 같은 스킵을 재정산하지 않는다.

튜토리얼 중 정상 run stats는 parked로 복원한다. 경제/보상/프로필 사건이 튜토리얼 완료 전에 발생하는 경로가 없는지 실제 코드를 검사한다. 필요한 경우 튜토리얼 소유 상태만 복원·차단하고, **사용자의 전체 프로필을 옛 snapshot으로 덮어써서 다른 기록·설정을 지우지 않는다.**

### 5.5 다시 보기와 구버전

설정/도움말의 `튜토리얼 다시 보기`는 기존 독립 연습 Controller 또는 동등한 격리 경로를 사용한다. 현재 원정 카드·RNG·적 HP·재화·보상·도감을 바꾸지 않는다. 완료/스킵을 다시 보면서 보상이나 문법 사용횟수를 농사 짓지 못한다.

기존 완료 프로필은 그대로 완료로 인정한다. 별도 스킵 필드가 없는 프로필을 스킵으로 추정하지 않는다. 구버전 active guided 저장에 스킵을 제공할 경우 **원래 원정 버전의 정상 1-1**로 복원하고 .5.1 새 HP/콘텐츠로 마이그레이션하지 않는다. 이전 저장의 일반 재개/완료 경로는 원형 유지. 새 스킵 이후 저장한 상태는 정상 전투 안전 지점으로 읽혀야 한다.


## 6. 사전·문장 도감의 간결한 교육 UI

### 6.1 한 항목의 기본 구성

**제목(형태) → 핵심 역할 설명 1~2문장 → 사용/위력 기록 → 내가 만든 영어 문장** 순서다. 제목 바로 오른쪽에 괄호 형태를 붙인다. 제목 밑에 공식을 중복해서 별도 단락으로 출력하지 않는다.

문법 제목은 실제 heading 요소로 표현한다. 같은 heading 안의 이름/형태 span 분리는 가능하나 제목과 형태가 시각적으로 이어져야 한다. 좁은 화면에서는 자연스럽게 줄바꿈하되 형태를 잘라내거나 축소해서 읽을 수 없게 만들지 않는다.

### 6.2 확정 표시 순서와 문구 초안

표시 전용 `order/titleKo/pattern/shortDescriptionKo` 등을 두고 **객체 삽입 순서·사전순·획득순·사용횟수순에 의존하지 않는다.** 1~5형식은 해금 시점이 달라도 맨 앞에 묶는다. 그 이후는 현재 구현의 학습 흐름을 따른다.

현재 .5.0에 존재하는 17개 학습 항목을 모두 보존하며 다음 순서로 표시한다. 이후 미구현 문법을 이번에 빈 카드로 늘어놓지 않는다.

### 6.3 사용자 제안 문구에서 정확성 때문에 명시적으로 다듬은 두 지점

원문 의도는 설명을 늘리려는 것이 아니라 간결화다. 다음 조정은 **이번 명세의 교육 검토안**이며, 이미 교사가 최종 승인한 문구라고 주장하지 않는다.

- 사용자 예시: `절은 주어와 동사로 이루어져 있으며, 문장보다 작은 단위입니다. 접속사로 연결할 수 있습니다.` → 최종 초안에서는 **'문장보다 작은 단위'를 '주어와 동사를 중심으로 이루어진 덩어리'로** 바꿨다. 한 절만으로 된 문장도 있어서 항상 더 작다고 가르치지 않기 위한 최소 조정이다. `절+접속사+절`은 대표 모양이며 that 명사절/앞선 부사절의 모든 배치를 그 공식으로 강제하지 않는다.
- 사용자 예시: `과거에 발생한 일이 지금까지 영향을 주고 있다는 것을 표현합니다.` → **현재완료 설명의 취지는 보존**하되, 게임의 `TIME.PERFECT`는 과거·미래완료도 포함하므로 공통 설명과 현재완료 한 문장을 나눴다. 모든 완료형의 기준을 '지금'으로 잘못 고정하지 않는다.

이 검토는 UI 문구에 한한다. 관련 파서·점수·해금·용법을 추가/수정하는 핑계로 범위를 늘리지 않는다. 외부 언어 근거는 §13에 명시한다.

### 6.4 설명의 길이/중복 제거

- 기본 설명은 **1문장 우선, 최대 2문장**. 프로그램의 줄임표/truncate로 자르는 것이 아니라 검수한 짧은 문자열을 쓴다.
- `Object.values(CLAUSE_GUIDE).join(' ')` 같은 모든 설명 이어 붙이기를 없앤다. 절 종류/계산 기준/that의 모든 역할을 항목마다 장문으로 덧붙이지 않는다.
- 예외는 필요한 항목의 짧은 TIP 최대 1개로 둔다. `enjoy + -ing`, `give/show/send는 to, make는 for` 같은 핵심은 없애지 않는다.
- 이미 제거했던 '고정 학습 예문 · 실전 기록 아님' 패널을 부활시키지 않는다. 내부 예문 데이터/테스트 근거는 보존한다.
- 현재의 학습 증거 전체, 모든 역할, 전체 점수표는 **명시적으로 펼치는 기존 기록 상세**에서 접근할 수 있게 한다. 기본 항목에서는 장문 문법 강의나 같은 절 원문을 중복 반복하지 않는다.
- 틀린 문장의 피드백은 원인 기준으로 중복만 줄인다. 정확한 오류/0피해 이유를 삭제하거나 '다 맞음'으로 보이게 하지 않는다. 보스 방어 메시지는 문법 오류색과 구분한다.

### 6.5 사전은 단어를 찾는 곳

기본 표시는 **영단어·품사 / 한국어 뜻 / 보유·희귀도 / 간결한 형태 목록 / 필요한 짧은 사용 팁**으로 구성한다.

동사마다 '과거는 과거형, 진행은 be..., 완료는 have...'와 긴 `verbUsage` 목록을 전부 반복하지 않는다. 공통 형태 설명은 공통 도움말 한 곳에 두고, 단어별로는 등록된 중요한 결합만 압축한다. want/need의 `to V / O + to V`, enjoy의 `-ing`, 주요 수여동사의 to/for 등 실제 검수한 규칙만 쓴다.

형태 목록·다중 의미·연마 사본별 수량 등 필요한 정보는 짧은 칩/접기 등으로 여전히 확인할 수 있어야 한다. 기계적으로 문자열을 자르거나 sense를 삭제하지 않는다. 일반/가산/불가산 표시는 짧게 하되 `BOTH` 정보를 잃지 않는다.

사전의 한국어 단어 뜻은 유지한다. **문장 도감에 문장 전체/성분별 한국어 번역을 되살리지 않는다.** 사전은 지금 원정에서 만난 단어/현재 보유 단어 필터와 검색, 제거 카드의 만남 기록을 그대로 유지한다. 운영 카드는 단어와 분리한 간단한 설명으로 보인다.

### 6.6 시각적 위계 초깃값

| 요소 | 데스크톱 | 태블릿 가로 | 의도 |
|---|---|---|---|
| 문법 항목 제목 | 22px, weight 750~800 | 20px 이상 | 항목에서 가장 먼저 읽힘, 기존 gold/teal 중 일관된 강조색 |
| 제목의 괄호 형태 | 17px, weight 650 이상 | 16px | 바로 오른쪽, 설명보다 뚜렷하게 |
| 역할 설명 | 15px | 14~15px | 회백색, line-height 약1.5 |
| 플레이어 영어 문장 | 20~22px, weight 700~800 | 18~20px | 선명한 흰색, 기록의 주인공 |
| 오류·조언 피드백 | 14~15px | 14px | 부드러운 적색 + '피드백' 같은 텍스트 표식 |
| 기록 수치/메타 | 13~14px | 13px 이상 | 제목/문장보다 낮은 위계 |

최종 수치는 화면 검증으로 조정 가능하나 제목이 설명보다 작아지면 안 된다. 공용 `.dictionary-entry strong` 전체에 일괄 확대를 걸지 말고 grammar heading/player sentence/word heading을 분리한다. 한·영 긴 문장과 괄호는 ellipsis 없이 읽히고, 도감 전체 순서대로 세로 스크롤이 가능해야 한다.

색상만으로 오류를 구별하지 않게 텍스트/표식을 함께 쓴다. `INVALID_CORE`의 안내도 `.muted`만 남겨 묻히지 않게 한다. 최소 터치/키보드 초점 영역은 기존 44px 수준을 유지한다.

### 6.7 해금 안내

기존에 해금 메시지가 있는 곳은 `4형식 콤보 활성화`처럼 **점수 효과**가 열린다고 표현한다. '이제 4형식 문장을 제출할 수 있습니다', '아직 배우지 않아 틀린 문장입니다' 같은 안내를 만들지 않는다.

이미 구조가 인정된 미해금 문장은 일반 계산 경로로 공격하고 잠긴 배수만 빠진다. 도감 문법 항목의 기본 열람을 콤보 잠금으로 막지 않는다. 아직 사용 기록이 없으면 `아직 사용 기록이 없습니다.`처럼 짧게 표시한다. 새로 긴 잠금 경고/설명 모달을 추가하지 않는다.


## 7. 형태 UI와 동일 철자 대명사

### 7.1 표기와 위치

`과거분사 · p.p.`/`과거분사 p.p.`를 **`과거분사(p.p.)`**로 통일한다. 메뉴 제목/해당 형태 설명/사전·접근성 label 등 학생 표시를 확인한다. 기존 Form ID, grammaticalFeatures, p.p. 실제 표기는 바꾸지 않는다.

기존 3줄 배치는 보존한다: 첫 줄 현재/원형 전체 너비 → 둘째 줄 과거 전체 너비 → 셋째 줄 과거분사(p.p.)와 -ing형 두 칸. be 기본형 설명은 `원형`만 표시한다. 이미 제거된 '활용 선택 필요'가 다시 나타나지 않게 한다. 단일 -ing 형태 원칙 유지.

### 7.2 대명사에 한정한 표시 그룹

**같은 lexeme의 대명사, 같은 표면 철자(surface)의 격 Form만 UI에서 한 버튼으로 묶는다.** 대표 선택 ID는 기존 ID 중 결정론적으로 고르고, aliasFormIds/현재 group 표시는 보기 모델에서 관리한다.

| 원래 카드 | 보여줄 형태 | 합쳐지는 역할 |
|---|---|---|
| she | she / **her** | her의 목적격·소유격(한정형) |
| you | **you** / your | you의 주격·목적격 |
| it | **it** / its | it의 주격·목적격 |
| he | he / him / his | his가 이미 가진 역할 유지, 중복 버튼이 있으면 그룹 |
| I | I / me / my | 서로 다른 철자이므로 그대로 |

그룹 버튼은 단어를 한 번 크게 표시하고, 필요한 짧은 라벨은 `목적격·소유격`처럼 붙일 수 있다. 두 라디오 옵션으로 다시 격을 고르게 하지 않는다. 사전의 같은 표면형 중복도 같은 보기 규칙으로 정리하되 뜻/역할 정보는 보존한다.

`I like her.`와 `I like her book.`은 같은 her 버튼으로 만들어야 하며 각각 실제 목적격/소유격으로 분석한다. 사용자에게 카드를 놓기 전에 역할 정답을 고르라고 요구하지 않는다. 그렇다고 한 her 사본이 문장 속 두 자리를 동시에 차지할 수는 없다.

### 7.3 변경 금지선

- 엔진의 same-surface 후보 확장 및 모든 기존 Form ID·저장된 selection을 보존한다.
- 다른 lexeme/cardDef의 동음 철자를 하나의 카드로 합치지 않는다.
- read의 현재/과거/과거분사, had의 과거/과거분사 등 **동사의 시간·형태 메뉴는 그룹 대상이 아니다.** 기존 학습 위치/라벨을 유지한다.
- 단순 `forms.filter(uniqueSurface)`를 모든 품사에 적용하지 않는다.
- 새로 소유대명사 hers/mine/yours를 만드는 것은 이번 범위가 아니다.
- 이미 지원하는 판정에 UI 그룹만 연결한다. 전반적 파서 개편이나 의미 추정 기능을 추가하지 않는다.
- 구버전 저장에서 object-her/possessive-her 어느 ID를 읽어도 해당 단일 버튼의 선택 표시가 자연스럽고 재선택 없이 계속 제출된다.

### 8.2 이전 두 방 목표와의 관계

이번 상향은 최신 합의가 우선한다. 이전 0.4 문지기 HP640에서 `320 × 2`로 처치하던 산술 목표를 **760에서도 여전히 두 번이라고 주장하지 않는다.**

| 예시 위력(기존 계산 보존) | 두 공격 합계 | 새 보스 HP | 필요한 같은 위력 공격 수(산술) |
|---|---:|---:|---:|
| 하늘섬 7장 SVC 연결 320 | 640 | 760 | 3 |
| 하늘섬 7장 SVO 연결 360 | 720 | 760 | 3 |
| home 수식 포함 기존 사례 401 | 802 | 760 | 2 |
| 사막 5형식 437 | 874 | 960 | 3 |
| 사막 수식 포함 5형식 537 | 1074 | 960 | 2 |

`I read a book when she comes home.`의 기존 place-adverb +5 보존으로 나온 **401**을 다시395로 되돌리지 않는다. 같은 문장을 실제로 두 번 만들 수 있다는 뜻도 아니다. 합성 산술과 실제 카드 운영을 분리한다.

실제 학생 난이도가 높아졌다면 **위 HP 초깃값에 한해** 이유/재현 seed/행동 로그/최종 수치를 기록하고 최소한으로 조정할 수 있다. 점수·룬·교환을 몰래 버프/너프해 시험을 맞추지 않는다. 미사용 자동 정책의 낮은 승률만으로 HP를 바꾸지 않는다.

### 8.3 보존 정책

기존 save의 적 현재HP/최대HP/난이도/룬/공개 보상/난수는 그대로. 저장을 열거나 도감 보기만 해도 HP가 올라가는 일이 없어야 한다. 구 0.5 원정의 다음 전투도 원래 0.5 표를 사용한다. 새 원정만 새 표를 사용한다.

문지기 보호막과 스핑크스 봉인을 상향하지 않는다. 높은 공격은 새 HP도 넘을 수 있고, 그렇게 준비한 빌드의 원킬을 허용한다. 추가 피해 상한·최소 공격 횟수·장문 감쇠·준비 페널티는 금지한다.


## 9. 버전·저장·프로필 호환

### 9.1 단순 버전 올리기의 회귀 방지

0.5.1은 새 앱/원정 버전이지만 **문법 데이터/점수/룬/운영 카드의 새 의미 버전은 아니다.** 새 원정의 HP·튜토리얼 정책·표시 정책만 명확히 분리한다.

`version === '0.5.0'`, `['0.3.0','0.4.0','0.5.0']` 등을 쓰는 위치를 감사한다. 무작정 문자열 전체치환/`startsWith('0.5')`/문자열 대소 비교로 버전군을 추정하지 않는다. 최신 .5.1이 기본 .1 언어/짧은 원정/운영 불가 경로로 떨어지면 안 된다.

권장 방식은 실제 코드의 version selector를 작은 명시적 표로 확장하는 것이다. 프로젝트 전체의 버전 아키텍처를 재설계할 필요는 없다.

| 도메인 | 새 0.5.1 | 기존 0.5.0 이하 |
|---|---|---|
| game/새 원정 저장 | 0.5.1 식별 | 원래 버전 그대로 |
| language/grammar/score/runes | 0.5의 같은 구현과 의미를 명시 매핑 | 원래 view |
| starter/reward/shop/operation/seal RNG | 기존 0.5 동일 정책 | 원래 정책/공개 결과 |
| Stage HP | 새 4~5 표 | 원래 HP 표 |
| tutorial 완료 여부 | 기존 완료 + 별도 명시적 스킵 | 완료 기록을 새로 강제하지 않음 |
| Presentation/문구 UI | 새 비파괴 표시 가능 | 원래 확정 결과를 새 UI로 표시할 수 있음 |

새 .5.1 저장 round-trip에서 모든 activeCardIds가 DRAW/HAND/SENTENCE/DISCARD/EXHAUSTED 중 정확히 한 곳에 있다. 스핑크스 봉인 사본/턴/RNG 및 사용 완료 카드가 재추첨·재생성되지 않는다. 문지기 shield·골렘 부위 상태도 그대로다.

### 9.2 금지 사항

- 저장소/IndexedDB 이름, GitHub repo명, `/grammardealer/` base URL, 저장 슬롯 수를 바꾸지 않는다.
- 구버전 run을 최신 버전이라고 덮어써 HP·보상·문법을 바꾸지 않는다.
- 새 UI를 적용하려고 과거 공격을 새 parser로 일괄 재채점하지 않는다.
- 프로필 필드 추가는 idempotent한 최소 확장. skip/complete/readOnlyGuide/실제 정상전 기록을 구분한다.
- 알 수 없는 버전/변조된 상태를 조용히 초기화하지 않는다. 기존 저장 보존 후 명확한 복구 메시지를 쓴다.
- 3개 수동 슬롯과 기존 안전 저장 정책을 유지하며 autosave/클라우드 저장을 새로 만들지 않는다.

### 9.3 레거시 증거

변경 전0.5의 정상·핵심실패·시간·연결·준동사·원정/상점/보상/봉인/운영 사례를 독립적으로 고정한다. 새 HP가 필요한 사례는 새 .5.1 사례로 추가하고, 옛 fixture의 기대 HP를 최신표로 수정해 회귀를 감추지 않는다.

같은 언어 입력/카드/룬/해금/적HP를 준다면 .5.0과 .5.1의 계산은 동일해야 한다. 바뀌는 것은 **새 전투가 초기화될 때 선택하는 HP 표**와 그에 따른 실제 처치/남은 턴이며, 후속 보상까지 모든 원정결과가 동일해야 한다는 요구는 아니다.

기존 파일명 prefix `SentenceBalatro_...` 및 소스 ZIP의 `sentence-balatro/` 루트는 자동화 호환을 위해 이번에는 유지한다. 사용자가 보는 안내 제품명은 Syntax Atlas다. 내부 폴더명 변경을 브랜딩 완료의 조건으로 만들지 않는다.

빌드 → 패키징 순서로 실행하고 ZIP을 **다시 열어** 안내/버전/index/assets/.nojekyll/manifest를 검사한다. 배포 ZIP에 src/node_modules/.git가 없고, 참조 자산이 실제 들어 있는지 확인한다. 오래된 dist를 새 버전명으로 포장하지 않도록 같은 최종 소스로 새 build를 수행한 근거를 남긴다.

테스트에서는 임시 패키지 버전 두 가지로 안내를 생성해 버전 자동 반영·버전 중립 본문을 확인한다. 실제 저장소의 버전/소스를 시험용 값으로 덮어쓴 채 남기지 않는다. 자동화된 로컬 테스트의 fake dist와 실제 release build를 구분한다.

패키징은 install/build/push/deploy를 몰래 수행하지 않는다. Windows의 Python 명령 차이는 기존 환경 내 실행 방법으로 해결하고 새 의존성 설치/전역 PATH 변경을 동반하지 않는다. 출처가 불분명한 로컬 캐시/개인 파일을 ZIP에 새로 추가하지 않는다.


## 11. 실제 브라우저 검증과 회귀 계획

### 11.1 검증 수준을 분리

| 종류 | 증명하는 것 | 증명하지 않는 것 |
|---|---|---|
| 순수 정책·산술 fixture | HP 선택/오버킬 분기/문구/순서의 기대값 | 실제 게임 플레이·브라우저 가시성 |
| 지정 상태 DOM 검사 | 실제 UI/엔진에서 해당 상태의 작동 | 자연 획득·자연 승률 |
| 실제 production UI 원정 | 해당 seed/선택으로 진행/22전투 흐름 | 모든 seed의 승리 가능성 |
| Firefox/WebKit smoke | 실행한 핵심 기능의 타 엔진 결과 | 실 iPad Safari·전체 22전투 회귀 |
| 실제 기기·교사 플레이 | 해당 기기의 조작/체감/교육 관찰 | 수행하지 않은 환경의 PASS |

상태값/클래스 추가/animation callback 호출만 보고 '타격감 검증 PASS'라 하지 않는다. 반대로 대규모 주관적 품질 점수를 꾸며내지도 않는다.

### 11.2 핵심 VFX 검사

실제 프로덕션 스타일과 DOM에서 `LUNGE` 중간 프레임의 조립체 위치/가시영역, `IMPACT`의 피격 표시, `RECOIL`의 적 반응을 관찰한다. **정상 motion**에서는 transform/좌표가 실제로 변하고 적 방향으로 접근해야 한다. **reduce**에서는 이동 대신 명도/테두리/피해 표시가 나타났는지를 검사한다.

1. effectsOff false/true × OS 일반/reduce 네 조합.
2. 일반 환경에서 speed1/2의 공격, 약한 비처치/일반처치/오버킬/큰 오버킬/피해0/골렘 부위파괴.
3. WAAPI 없음/예외에서 fallback과 잠금 해제.
4. 실제 before HP가 점수 단계에서 유지되고 IMPACT 이후 확정 HP와 일치.
5. clip/opacity/display/z-index/viewport를 함께 확인. `getComputedStyle().transform !== 'none'`만으로 안 보이는 애니메이션을 통과시키지 않는다.
6. 서로 다른 시점 캡처 또는 짧은 무음 영상 + 관찰 수치. 테스트 시계 즉시 진행/모션 강제 꺼짐 영상으로 실제 이동을 증명하지 않는다.
7. 연출을 예외/숨김/스킵으로 중단해도 점수·피해·RNG·보상 한 번만 적용, 대기 상태 해제.

Chromium에서 1366×768/1280×800/1024×768을 사용한다. 16조합/14손패/4룬 스트레스는 기존 공개 스냅샷의 **지정 상태 검사**로 구분한다. 브라우저 확대125%도 핵심 제목/형태·공격 가시성을 최소 점검한다. 테스트 중 소스를 편집해 Vite 자동 reload로 실행을 오염시키지 않는다.

### 11.3 튜토리얼·형태·도감

초기 스킵, 첫 공격 뒤 스킵, score gate에서 스킵, 취소, 두 번 클릭, 오래된 콜백을 각각 검사한다. 동일 seed의 '처음부터 일반전'과 스킵 이후 정상 카드/RNG/첫 손패를 비교한다. 정상 튜토리얼 40/126 완료와 보상도 별도 실행한다.

her의 옛 두 selection ID를 로드/선택한 경우 둘 다 `I like her.` / `I like her book.`에 대응하는지 실제 parser를 호출한다. UI 메뉴의 her 버튼은 하나, I/me/my와 동사 read의 서로 다른 시간 그룹은 보존한다.

도감은 17개 표의 정렬/제목+괄호/본문 문장 수·금칙 메타 노출/피드백 색과 텍스트 표식·내 문장 강조·검색을 확인한다. 열고 닫기 전후 run/profile/RNG/당시 공격 값이 같아야 한다. 저장·해금·record 뷰에는 새 긴 안내를 붙이지 않는다.

### 11.4 Firefox + WebKit 핵심 smoke

예: `test:browser:cross`를 추가한다. 이름은 실제 저장소 관행에 맞춰 명시한다. 기존 Playwright/lockfile을 유지하고 **그 버전에 맞는 브라우저 바이너리만** 로컬 테스트 경로에 준비한다. `@latest` 설치나 시스템 Chrome 교체를 하지 않는다.

각 엔진에서 최소: 앱 로드/새 원정/스킵/카드 클릭·드래그/형태/her/공격 핵심 표시/효과 감소/OS reduce/보급 또는 탐색/모달/사전·도감/IndexedDB 저장→로드/가로 화면을 확인한다. 복잡한 후반 상태는 명시한 지정 상태를 사용 가능하다. Chromium의 전체 묶음을 그대로 세 번 돌리거나 모든 엔진에서 22전투 완주할 필요는 없다.

Firefox/WebKit은 실제 실행을 시도한다. 설치·OS 제약 때문에 못 돌리면 엔진별 **NOT RUN/이유**를 남기고 나머지 가능한 검증을 마친다. 설치는 되었는데 assertion이 실패했다면 **FAIL**로 보고 수정한다. '미검증 공개를 했다'는 이유로 브라우저 기능 검증을 PASS에 포함하지 않는다. 타 엔진 미실행은 공개 가능한 한계로 남길 수 있으나 '모든 브라우저 검증 완료'로 보고하면 안 된다.

### 11.5 실행 효율과 최종 명령

- 변경 전 baseline: 기존 `npm test`, `npm run build`, 필요한 0.5 golden 기록. 이미 같은 checkout/동일 소스 baseline이 있으면 그 SHA와 로그를 명시하되 이번 결과와 구분한다.
- 작업 중: 관련 단위/DOM 검사 우선. CSS 한 줄마다 10,000덱·80원정·22전투를 반복하지 않는다.
- 최종 고정 소스: `npm test`, `npm run validate:data`, `npm run build`, 기존 `npm run test:browser`, 새 core-polish VFX/튜토리얼/도감 검사, cross smoke, packaging 검사, `npm run test:e2e`의 현재 22전투를 실행한다.
- production 실제 UI 22전투 중 하나는 새 스킵 경로로 시작한다. 정상 튜토리얼을 끝까지 하는 별도 짧은 검증을 병행한다. 실제 seed/카드·룬 선택/상점/운영/22전투 완료/저장 복원을 기록한다.
- generator 정책은 변경하지 않는다. 버전 매핑 회귀를 위해 네 어휘 모드의 고정 seed 표본을 검사하고 28장/witness/opener를 확인한다. 실제 생성 정책을 수정했다면 기존10,000검사를 재실행한다.
- 후반 HP는 실제 플레이/공격·준비·교환 수를 비교한다. 자동80원정은 추가 근거로 선택 실행 가능하지만 사람 승률로 해석하지 않는다.
- Windows는 기존 환경의 `npm.cmd`/Python 명령을 사용할 수 있다. 성공한 종료코드와 실패/재시도 이력을 그대로 보존한다.


## 12. 구현 순서·인계·완료 기준

### 단계 A — 기준과 버전 연결

실제 main/미커밋 확인 → baseline/golden → .5.1 도메인 매핑과 기존 .5 저장 회귀 → 이번 변경 목록 작성. 아직 화면을 바꾸지 않은 상태에서 .5.1이 .5 언어/22전투/운영·봉인 경로를 읽는지 먼저 확인한다.

### 단계 B — 핵심 피드백과 오버킬

CORE/DECORATIVE 분리 → OS reduce 대체 → WAAPI fallback → capped overkill → 실제 중간 프레임 검사. 오디오 설정과 피해0/골렘의 예외를 연결한다. 모션 코드를 없었다고 가정한 전면 재작성은 하지 않는다.

### 단계 C — 튜토리얼 스킵

전용 거래·프로필 구분·parked 복구 → 초기/진행 중/gate 취소 → stale callback 차단 → 기존 튜토리얼 완료 회귀 → 명칭 통일.

### 단계 D — 교육/형태 UI

문법 표시 catalog·정렬·간결한 문구 → 도감/사전 중복 제거 → 제목·내 문장·피드백 위계 → 대명사 surface grouping·p.p. 표기. 기록/언어 수치 불변 검사를 같이 수행한다.

### 단계 E — 후반 HP와 패키징

새 원정 HP view → 기존 .5 저장/보스 회귀 → 버전 중립 DEPLOY_KO와 ZIP 열기 검사. 공격 계산식을 HP에 맞춰 조정하지 않는다.

### 단계 F — 최종 검증과 PR

고정 소스로 최종 검사 → 소스 freeze 이후 캡처/로그 → 알려진 문제와 미실행 항목 → 작업 브랜치 push → main 대상 PR. 자동 merge/Pages 변경은 하지 않는다.

중간 정지가 생길 때를 대비해 `PROGRESS.md`에 완료한 단계·다음 한 단계·현재 실패·실행 명령·기준 SHA를 남긴다. 다음 실행은 이미 완료한 기능을 재개발하지 않고 이 상태에서 이어간다.

필수 결과물: `PATCH_NOTES_0.5.1_KO.md`, `TEST_REPORT_0.5.1.md`, `ACCEPTANCE_0.5.1.md`, `EDUCATION_UI_REVIEW_0.5.1.md`, `CORE_FEEL_REVIEW_0.5.1.md`, 최신 인계/KNOWN_ISSUES, `docs/validation/v0.5.1/`의 실제 명령·선별 캡처·필요한 짧은 영상. 문서 이름은 저장소 관례에 맞추되 서로 링크한다. 예전 증거 디렉터리를 덮어쓰지 않는다.

보고는 **구현됨 / 테스트 PASS / FAIL / NOT RUN / 실제 사람 검수**를 구분한다. 실행하지 않은 실기기·교사 최종 검수·스피커 청취는 NOT RUN. 원격 main 반영·공개 Pages 배포 여부는 push/PR과 별도로 보고한다. 최종 실패를 숨기기 위해 assertion 삭제·skip·timeout 무한증가·예외 삼키기로 통과시키지 않는다.
