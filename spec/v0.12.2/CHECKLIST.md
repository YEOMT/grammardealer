배포와 같은 base에서 로비 진입 → 기존 저장 불러오기 또는 새 원정 → 화면 이동 → 새로고침 또는 뒤로/앞으로 복귀를 짧게 확인한다.

## B. 탭·드래그·다중 터치

서로 다른 카드 3장을 빠르게 탭 → 한 장 드래그 삽입 → 재정렬 → 두 번째 손가락 접촉 → 손을 떼고 다시 정상 조작한다. 취소·바깥 drop도 이 흐름 안에서 확인한다.

확인: 페이지 확대/축소가 생기지 않는가? 정상 탭을 버리지 않는가? 드래그 후 click으로 즉시 회수되지 않는가? 멀티터치 안전 취소로 사본·턴·교환 횟수가 유지되는가? 놓는 마지막 지점이 실제 target인가? cleanup 후 다음 조작이 가능한가?

자동화가 실제 pinch를 재현하지 못했다면 DOM/포인터 상태 확인과 실기기 확대 확인을 별도로 기록한다. scale을 코드로 강제로 1로 맞춘 뒤 PASS 처리하지 않는다.

## D. 전체화면·회전·수명

일반 창/전체화면에서 각각 카드 드래그 → 드래그 중 실제 크기/방향 변화 → 취소 후 재조작 → 정상 공격을 확인한다. 미지원은 기존 안내를 확인한다.

확인: ghost가 현재 host에 보이는가? 변하지 않은 viewport 통지만으로 드래그가 죽지 않는가? 회전 복귀 뒤 잠금이 풀리는가? 완료된 공격이 두 번 처리되지 않는가? 공격 집결·돌진이 이전 정상 구현대로 보이는가?

카카오톡 인앱 실행이 불가능하면 그 환경은 NOT RUN이다. PC touch context로 카톡 성공을 대신 주장하지 않는다.

## E. 소리·복구·BGM 정책

등록 음악이 있는 지역에서 첫 탭 → 효과음과 BGM → 음소거/볼륨 → 앱/탭 전환 후 복귀 → 새 지역 이동 → 로비 복귀를 확인한다. 자연 전체 원정 대신 기존 안전 저장·기존 검사 흐름을 사용할 수 있다. 플레이어용 테스트 페이지나 가상 점수 버튼은 만들지 않는다.

확인: 신뢰된 사용자 입력으로 재생/재시도가 가능한가? 음소거·0볼륨을 임의로 풀지 않는가? 음원 중복/매번 처음 재생이 없는가? 지역 전환이 페이드아웃 완료→1초 BGM 무음→신곡 페이드인인가? 다른 장면으로 나갔는데 옛 예약이 실행되지 않는가?

등록되지 않은 후반 지역의 무음은 분리한다. AudioContext running, source 수, HTTP 성공만으로 '실제로 들림'을 PASS로 처리하지 않는다.

## F. 무변경·기본 회귀

같은 상태와 뷰포트의 대표 화면을 비교하고, 게임값·사본 수·수동 저장/불러오기를 확인한다. 필요 캡처는 전체 합계 2~4장 수준이다.

확인: 카드 외형·글꼴·색·배치·손패 여백·몬스터 크기와 점수 연출을 유지했는가? 기존 28장/원정 버전/RNG/연마/룬/골드가 입력 정책 때문에 바뀌지 않았는가? fixture·추가 디버그 메뉴가 플레이 화면에 없는가?

기존 최소 폭·가독성 문제는 보고만 한다. 이번 검사에서 모바일 레이아웃을 새로 설계하지 않는다.
