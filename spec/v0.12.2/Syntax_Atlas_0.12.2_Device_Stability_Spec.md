# Syntax Atlas 0.12.2 — 접속·터치·오디오 안정화

> **디자인은 그대로, 입력과 접속의 실패 경로만 수정한다.**
> 이번 문서는 개발 명세다. 게임 구현·브라우저 실행·실기기 청취 완료 보고서가 아니다.

사용자 최종 결정: “디자인을 막 건드리기보다 접속이나 터치확대방지 등 안정화만 하자.”

이번 범위는 다음 다섯 가지다.

| 우선순위 | 작업 | 완료의 의미 |
|---|---|---|

| P0 | 카드 입력의 일관성 | 탭·드래그·취소·두 번째 손가락을 구분하고 한 제스처를 한 번만 정산한다. |

| P1 | 기존 오디오와 전체화면의 복구 | 첫 탭, 앱 복귀, 미지원 환경에서 기존 재시도·안내를 활용한다. |

## 1. 변경 금지 — 디자인과 게임 규칙

### 1.1 시각적 보존 계약

로비·지역 입장·전투 준비·전투·상점·보상의 현재 배치와 색감, 배경·몬스터 이미지, 버튼 위치, 폰트 계열과 크기, 카드 외형·품사색, 패널 크기·간격·여백을 바꾸지 않는다.

특히 다음을 보호한다.

- 조합대 12장 × 2줄, 중앙정렬, 기존 장수별 카드 크기, 한 줄 손패와 손패 페이지 전환.
- 손패 하단의 실제 여백, 카드 줄과 더미 정렬, 기존 버리기 버튼·형태 선택창의 크기와 위치.
- 일반 몬스터와 보스 크기, 상단 무대와 헤더 배경, 고정된 전투 구역.
- 점수 오버레이의 단계적 확대·빛, 감점/방어 구분, 카드 집결·돌진·피격 연출.
- 입장·준비 화면의 짧은 안내 문구. 새 개발 안내·테스트 문구를 플레이 화면에 추가하지 않는다.

허용하는 CSS 변경은 `touch-action`, 조작용 요소의 선택/롱프레스 제어, 적절한 스크롤 전파 제어, 입력 레이어의 포인터 처리처럼 **동작 안정화를 위한 비시각적 속성**이다. 전체화면에서 드래그 복사본이 가려지는 오류에 한해 레이어 부착 위치를 고칠 수 있다. 새 애니메이션이나 디자인 레이어를 추가하지 않는다.

정상 상태에서 같은 뷰포트·같은 게임 상태의 변경 전후 화면은 같아야 한다. 자동 픽셀 비교나 대량 캡처는 요구하지 않는다.

### 1.2 이번에 하지 않는 것

기존 시작 덱 28장·동사 8장과 수준별 핵심 동사 구성, 50전투, 해금·상점 흐름, 어휘·문법 판정, 카드/룬 점수·연마·HP·턴·보상·랭킹·RNG·저장 계약을 유지한다. 이번에는 원정 재생성이나 밸런스 조정이 없다.

스마트폰 전용 레이아웃, 사이드 패널 접기, 메뉴 재배치, 카드·글자 자동 축소, 전체 화면을 `transform:scale()`/CSS `zoom`으로 맞추기, breakpoint 재설계, UI 미관 수정, 콘텐츠·단어·문법·룬·HP·점수·상점·랭킹 변경은 제외한다.

새 서버, 계정 로그인, 클라우드 저장, PWA/Service Worker, 외부 브라우저 강제 호출, 신규 라이브러리·프레임워크 도입, 에셋 재가공도 하지 않는다.

### 1.3 작은 화면의 기존 제한은 숨기지 않는다

현재 CSS에는 1,159px 이하에서 전투 영역에 `min-width:1160px`을 주는 규칙이 있다. [R6] 이번에는 이 레이아웃 정책을 고치지 않는다.

따라서 이번 완료 기준은 **모든 휴대폰에서 모든 정보가 무스크롤로 보이는 것**이 아니라, **현재 UI를 유지하면서 터치로 확대되거나 조작이 꼬이지 않는 것**이다. 기존에 화면 밖 내용에 도달하기 위한 스크롤·페이지 전환이 있다면 그대로 보존한다. 확대로 보기 어려운 문제와 기존 최소 폭 문제를 혼동하지 않는다.

확대를 막는다는 이유로 페이지에 전역 `overflow:hidden`을 적용해 기존 접근 경로까지 없애면 실패다. 기존 작은 화면의 불편은 후속 디자인 검토 사항으로 짧게 보고하고 이번 작업을 확장하지 않는다.

## 2. 접속·진입·복귀 안정화

### 2.1 확인할 정상 진입

프로젝트의 실제 배포 base를 사용한다. 현재 프로젝트 경로는 `/grammardealer/`이며, 빌드 설정과 자산 URL 헬퍼를 먼저 확인한다.

| 흐름 | 필수 동작 |
|---|---|
| 브라우저에서 게임 주소 직접 열기 | 기존 로비와 버튼이 표시되고 새 원정/불러오기가 동작한다. |
| 카카오톡 등 앱 안의 링크로 열기 | 지원되는 기능은 그대로 실행하며, 인앱이라는 이유만으로 게임을 차단하지 않는다. |
| 배포 base + 기존 hash 경로에서 새로고침 | 세션이 없으면 기존 로비·저장 불러오기 경로로 복구한다. 빈 전투 상태를 만들지 않는다. |
| 뒤로가기·앞으로가기·탭/앱 복귀 | 리스너 중복, 유령 카드, 오래된 입력 잠금, 이전 장면 오디오 예약이 남지 않는다. |
| 선택적 그림·BGM 파일 실패 | 기존 대체 표시/재시도를 사용하고 카드 조작 자체는 유지한다. |

`/assets/...` 같은 루트 절대 경로로 프로젝트 base를 유실하지 않는다. 개발 서버에서만 성공한 것을 배포 경로 성공으로 보고하지 않는다. 새로고침은 기존 저장 정책을 따른다. 미저장 진행이 자동 보존되는 기능을 새로 만들거나 약속하지 않는다.

### 2.2 필요한 경우에만 좁은 실패 처리

기존 로딩 문구·toast·오류 안내·저장 fallback을 우선 재사용한다. 메인 모듈이나 초기화 실패로 진짜 빈 화면이 재현될 때만 기존 로딩 영역에 최소한의 실패 안내와 사용자가 선택하는 재시도를 제공한다. 실행 중 예외 하나에 게임 전체 DOM을 지우거나 무조건 재접속시키지 않는다.

이미지·BGM의 재시도는 제한된 시도 또는 사용자 명시적 재시도로 처리한다. 매 탭마다 실패한 URL을 새로 요청하거나 자동 새로고침 루프를 만들지 않는다. 오디오 시작은 이미지·음원 다운로드 완료를 기다리는 앱 진입 조건이 아니다.

저장소 이용 실패와 저장 없음은 구분한다. 기존 IndexedDB/메모리 fallback을 보존하고, 복구 명목으로 localStorage·IndexedDB·프로필·진행·사용자 설정을 삭제하지 않는다. 새로운 autosave/저장 마이그레이션은 이번 범위가 아니다.

## 3. 우발적 확대·브라우저 제스처 방지

### 3.1 사용자 경험 계약

게임 내부의 조작 가능한 영역에서 연속 탭, 카드 드래그, 실수로 겹친 두 손가락 때문에 페이지가 확대·축소되지 않도록 한다. PC 마우스의 클릭·드래그와 모바일/태블릿의 한 손가락 조작은 기존대로 동작한다.

이 제한은 **게임 조작에서 생기는 우발적인 브라우저 제스처**를 대상으로 한다. OS 접근성 확대, 브라우저 메뉴의 수동 확대, PC `Ctrl/Cmd + +/-/0`, 사용자 보조 기능까지 제거하지 않는다. 모든 WebView/OS 동작을 웹페이지가 강제할 수 있다고 보고하지 않는다.

이미 사용자가 확대해 놓은 페이지를 강제로 scale=1로 되돌리거나 확대 감지 시 자동 reload하지 않는다. 제스처 시작 전의 정책을 바로잡는 작업이다.

### 3.2 영역별 정책 — 스크롤을 살리면서 확대를 차단

현재 DOM에서 실제로 스크롤이 필요한 요소를 먼저 분류한다. 아래 표는 동작 계약이며 새 화면 구조를 만들라는 뜻이 아니다.

| 영역 | 허용 | 방지 |
|---|---|---|
| 손패·조합대 카드 본체·룬 드래그 핸들 | 기존 탭, 커스텀 드래그, 재정렬 | 브라우저 pinch/더블탭 확대, 카드 위에서 시작하는 페이지 팬, 텍스트 선택, 이미지 네이티브 드래그 |
| 스크롤이 필요 없는 게임 버튼·무대 | 클릭/탭 | 더블탭 확대와 다중 터치 확대 |
| 사전·도감·공격 기록·형태 목록 등 내부 scroller | 해당 축의 한 손가락 스크롤, 항목 탭 | pinch 확대, 바깥 게임까지 이어지는 불필요한 스크롤 전파 |
| 좁은 화면에서 기존에 필요한 페이지/컨테이너 스크롤 | 기존 접근에 필요한 축의 스크롤 | 확대와 카드 드래그로 잘못 인식되는 동작 |
| 소리 조절 슬라이더 | 손잡이 드래그, 키보드 조절 | 카드 드래그 오인, 확대, 상위 영역으로의 잘못된 드래그 전달 |
| 검색·이름·시드 입력, 주소 복사 필드 | 커서·선택·복사·붙여넣기·IME·키보드 | 게임 제스처 핸들러가 입력을 훔치는 동작 |

`touch-action:none`은 실제 커스텀 조작 면에 사용한다. 세로 목록은 `pan-y`, 가로 접근이 필요한 곳은 `pan-x` 등 필요한 pan만 허용하는 식으로 분리하고 pinch 허용을 제거한다. 두 축 스크롤이 필요한 기존 컨테이너는 두 축 접근을 보존한다. 최종 선택은 실제 DOM과 브라우저 동작을 확인해 적용한다. [W1, W2]

**`touch-action:manipulation`만 넣고 pinch까지 막았다고 보고하면 안 된다.** manipulation은 pinch를 허용한다. 또한 브라우저가 조상 요소까지 정책을 함께 보므로, 스크롤 가능한 자식의 공통 조상에 none을 주고 자식에 pan-y만 주는 것으로 복구된다고 가정하지 않는다. 제스처가 시작된 뒤 정책을 바꾸는 방법에도 의존하지 않는다. [W1]

`html`, `body`, `#app` 전체를 일괄 none 처리하는 접근, 모든 `touchmove`/`touchend`에 preventDefault를 거는 접근은 금지한다. 모달이 #app 밖에 붙는 경우도 포함해 적용·해제 범위를 명확히 한다.

### 3.3 Safari·인앱 보완

CSS와 Pointer Events를 먼저 사용한다. 정상 CSS 정책으로 막히지 않는 것이 특정 환경에서 재현됐을 때만 그 게임 영역의 다중 터치/비표준 gesture 기본 동작을 취소하는 작은 fallback을 추가한다.

fallback은 대상 영역·열린 모달·현재 입력 상태를 검사하고, `cancelable`인 이벤트만 필요한 때 취소한다. preventDefault가 필요한 핸들러는 해당 범위에서만 `passive:false`로 등록한다. 브라우저 이름 문자열만으로 모든 입력을 일괄 차단하지 않는다. [W1, W2]

전역 dblclick 차단, 모든 키/휠 차단, 무차별 stopImmediatePropagation, hidden input focus 트릭, 반복 viewport meta 수정은 금지한다. `user-scalable=no`/`maximum-scale=1`만 넣고 완료 처리하지 않는다.

### 3.4 롱프레스와 입력 예외

카드·게임 전용 이미지에 필요한 범위에서만 선택/이미지 저장 callout/네이티브 drag를 막는다. 사전 텍스트, 검색창, 주소 필드의 복사·선택과 기본 컨텍스트 메뉴까지 전역으로 없애지 않는다.

키보드가 열리고 닫힐 때 기존 입력 포커스가 사라지거나 문장이 다시 조립되지 않아야 한다. 입력창 자동 확대가 남으면 게임 드래그 확대와 분리해 보고한다. 이를 빌미로 전역 폰트 크기를 바꾸지 않는다.

## 4. 탭·드래그·멀티터치 일관성

### 4.1 기존 입력 경로를 통합해서 보완

현재 `bindCardDrag()`는 한 active pointer와 8px 드래그 문턱을 사용한다. ghost를 body에 붙이고 일부 위치를 고정 오프셋으로 잡는 코드가 있다. [R3] 이 사실만으로 특정 기기 오류를 확정하지 말고, 현재 탭·드래그 로직 위에서 필요한 경로만 수정한다.

별도의 touch와 mouse 구현을 중복으로 추가하지 않는다. Pointer Events를 중심으로 두고, 호환 fallback은 동일한 상태 전이에 들어오게 한다.

| 상태 | 이벤트 | 처리 |
|---|---|---|
| 대기 | 유효한 첫 pointerdown | 대상 사본 ID·pointerId·시작 좌표·영역·현재 revision을 기억한다. |
| 탭 후보 | 기존 문턱 이내 이동 후 놓음 | 기존 click 경로로 한 번만 배치/회수한다. |
| 드래그 | 문턱 초과 이동 | 복사본과 삽입/맞교환 후보만 표시한다. 실제 카드 상태는 아직 바꾸지 않는다. |
| 드래그 | 유효 위치에서 pointerup | 마지막 좌표의 유효 대상을 다시 확인하고 기존 Controller 명령을 한 번만 보낸다. |
| 탭 후보/드래그 | 취소·입력 자격 상실 | 아무 명령도 보내지 않고 ghost·하이라이트·capture·임시 상태를 정리한다. |

문턱은 기존 값을 우선 유지한다. 현재 디자인·배치·드래그 스타일을 바꾸기 위한 튜닝은 하지 않는다.

### 4.2 두 손가락 접촉의 기본안

게임에는 다중 카드 동시 드래그를 추가하지 않는다. 게임 커스텀 조작 면에서 두 번째 터치가 닿으면 진행 중 카드 제스처를 **안전 취소**한다. 관련 터치가 모두 떨어질 때까지 새 카드 이동과 잔여 click을 막고, 모두 떨어지면 다음 단일 터치를 즉시 받는다.

취소 결과는 원래 카드 배치·손패·턴·교환 횟수 유지다. 두 번째 손가락의 pointerup으로 첫 카드의 drop을 확정하지 않는다. 여러 손가락으로 공격·구매·보상을 두 번 처리하지 않는다.

다중 터치 제어는 게임 조작 scope에 한정한다. OS 입력, 텍스트 편집, 슬라이더의 정상 입력을 카드 트랜잭션으로 묶지 않는다. 이 정책으로 기존 오디오의 trusted 사용자 입력 감지까지 끊지 않는다.

### 4.3 취소와 마지막 좌표

`pointercancel`, `lostpointercapture`, 창 blur, 숨김/화면 회전, 모달 열기, 페이지 전환, 전체화면 host 변경, 실제 뷰포트 크기 변경에서 미완료 드래그를 정리한다. cleanup은 여러 번 호출해도 안전해야 한다. 정상 drop 직후 capture 해제로 발생한 정리 이벤트가 완료 명령을 되돌리거나 다시 실행하지 않아야 한다. [W2]

마지막 pointerup에서 바깥으로 벗어났는데 이전 pointermove의 target을 그대로 사용해 drop하지 않는다. 유효하지 않은 경계·뒤의 모달·비활성 카드면 원위치 취소한다.

동일 크기를 재통지하는 viewport 이벤트만으로 정상 드래그를 불필요하게 취소하지 않는다. 실제 크기·orientation·fullscreen host가 달라졌는지 비교한다. 기존 연출의 viewport 복구도 유지한다.

### 4.4 연속 탭과 중복 실행

드래그 끝에 따라오는 합성/호환 click은 해당 제스처에 한해 소비한다. 서로 다른 카드에 대한 사용자의 빠른 정상 탭을 전역 300ms~1초 잠금으로 버리지 않는다. 정상 탭 여러 번은 순서대로 반영되어야 한다.

`pointerup`과 `click` 양쪽에서 같은 배치·공격·구매 명령을 보내지 않는다. 사본 ID·현재 revision·활성 뷰 소유자를 기준으로 낡은 요청을 버린다. 기존 공격 중 busy/presenting 보호와 정산 멱등성은 그대로 사용한다. 연속 탭 때문에 두 원정 생성·두 공격·두 보상·중복 구매가 발생하면 실패다.

형태·버리기 체크·ⓘ·손패 페이지·룬 순서 버튼은 카드 본체의 배치/회수 이벤트로 새지 않아야 한다. 모달에서 형태 선택 후, 같은 터치가 뒤 카드에 전달되어 카드가 회수되는 관통 입력도 방지한다.

### 4.5 좌표·레이어·원본 보존

pointer의 client 좌표, 대상의 bounding rect, hit test를 같은 좌표계로 맞춘다. 스크롤·visual viewport·전체화면 변화 후에도 동일하다. 실제 CSS 변환이 없다면 임의로 devicePixelRatio를 곱하지 않는다.

fullscreen 사용 시 현재 전체화면 요소 안의 입력 비간섭 overlay host를 사용한다. body에 붙여 보이지 않는 ghost를 방치하지 않는다. 일반 모드에서는 기존 루트를 재사용하고, 복사본은 `pointer-events:none`, 비포커스, 비상호작용으로 둔다.

고정 오프셋 때문에 손가락과 카드 위치가 틀어지는 경우에만 눌렀던 지점 기준 오프셋으로 보정한다. 새로운 드래그 확대·튀기기·추가 효과는 넣지 않는다. 실제 카드 DOM을 overlay로 이동하지 않는다.

다음 공격·모달 종료·로비 복귀·새 원정에서 ghost, capture, timer, observer, event listener가 누적되면 안 된다.

## 5. 뷰포트·전체화면·가로 모드

기존 `--viewport-height`와 가로 플레이 안내를 유지한다. 브라우저 UI 변화에 필요한 높이 갱신만 수행하고, 카드 탭·형태 변경·이미지 로딩이 상단 무대나 조합대 크기를 재분배하게 하지 않는다.

전체화면은 기존 버튼의 직접 사용자 동작으로만 요청한다. API 지원 여부와 실제 성공/실패를 확인하고, 표시 상태는 실제 fullscreen 상태와 맞춘다. 탭할 때마다 자동 재요청하지 않는다. 지원하지 않는 환경을 가짜 전체화면으로 표시하지 않는다. [W5]

현재 존재하는 실패 안내와 `주소 복사 / 현재 화면에서 계속` 경로를 보존한다. [R2] 다른 브라우저를 열도록 강제 redirect하거나 저장을 자동 공유한다고 안내하지 않는다. 복사 권한이 없으면 기존 주소 선택·수동 복사를 유지한다.

기기 회전 중에는 미완료 드래그만 안전 취소하고 기존 가로 안내를 표시한다. 다시 가로가 되면 정상 조작으로 돌아온다. 강제 회전·전체화면이 거부되었다고 게임을 영구 잠그지 않는다. 방향 안내가 필요한 화면 범위를 새로 넓히거나 별도 세로 UI를 만들지 않는다.

공격 연출 중 viewport 변화는 이전 패치의 집결·돌진 복구를 사용한다. 입력 취소 신호가 공격 결과 자료까지 지우거나 피해·턴을 재정산해서는 안 된다.

## 6. 모바일·패드 오디오 — 정상 기능 보존과 좁은 복구

### 6.1 이미 구현된 부분을 활용

현재 AudioManager에는 `AudioContext/webkitAudioContext` 생성, 초기화 중복 방지, suspended/interrupted 재개 시도, BGM 전용 0.8 배율 버스가 있다. [R4] 정상 재생 코드를 교체하지 말고 입력 정책 변경으로 첫 탭·슬라이더·재시도가 막히는지 먼저 확인한다.

첫 유효 탭/클릭/키보드 조작에서 필요한 생성·resume을 trusted 이벤트 경로 안에서 요청한다. setTimeout이나 음원 fetch 완료 뒤의 임의 호출을 사용자 제스처로 간주하지 않는다. 새로 클릭을 합성해 권한을 얻으려 하지 않는다. 자동 재생 거부는 정상적으로 발생할 수 있으므로 재시도 경로로 복구한다. [W3]

상단 기존 소리 버튼을 재사용한다. 소리를 켜기 위한 새 시작 화면, 새 배너, 새 슬라이더를 만들지 않는다. 터치 확대 방지 핸들러가 기존 캡처 단계 오디오 unlock을 막지 않게 한다.

### 6.2 복귀와 상태

탭 복귀·pageshow·잠금 해제 등에서 기존 단일 manager의 상태를 확인한다. 정상 running이면 트랙을 재생성하지 않는다. suspended/interrupted이면 제한된 재개를 시도하고, 추가 제스처가 필요하면 기존 소리 버튼으로 다시 시도하게 한다. closed일 때만 필요한 범위에서 재생 자원을 복구한다. [W4]

재개 promise가 실패하거나 오래 대기해도 게임 조작을 막지 않는다. 실패 이후 초기화 잠금이 영구적으로 남지 않고 다음 정상 탭이 재시도할 수 있어야 한다. 반복 resume polling·무한 재생 시도·중복 AudioContext는 금지한다.

사용자의 음소거, BGM 0, 효과음 0은 고장이 아니다. 임의로 풀거나 기본값으로 되돌리지 않는다. 오디오 context가 running이라는 이유만으로 실제 기기에서 들렸다고 표시하거나 보고하지 않는다.

### 6.3 BGM 정책은 변경하지 않는다

- 기본 BGM 출력 = 기존 `0.8 × 사용자 BGM 설정`을 한 번만 적용한다.
- 같은 지역의 입장·전투·보상·보스 후 준비 상점에서는 같은 곡이 이어진다.
- 실제 새 지역 이동: 구곡 페이드아웃 완료 → BGM 무음 약 1초 → 신곡 페이드인.
- 이 무음은 BGM만이다. 클릭·카드·공격 효과음은 유지한다.
- 빠른 화면 이동·로비 복귀·다른 저장 불러오기 시 이전 전환 예약이 새 곡을 덮지 않는다.
- 기존 정책의 소유권과 전환 시계를 유지하고, 새 터치 정책을 이유로 3초 대기나 크로스페이드로 되돌리지 않는다.

현재 명세 작성 기준 등록 BGM은 로비·Stage 1·Stage 2다. [R5] 이후 미등록 지역의 무음은 음원 미제공 상태와 구분한다. 다른 지역 음악을 몰래 복사하거나 음원을 생성·추가하지 않는다. 실제 공급된 곡의 로딩 실패에는 기존 재시도, 의도된 미등록에는 재시도 폭주 없이 기존 무음 동작을 사용한다.

### 6.4 배경 진입 중 중단

오디오가 중단된 동안 플레이하지 못한 효과음을 나중에 한꺼번에 재생하지 않는다. 재생 위치·무음 구간 처리는 현재 정책을 유지한다. 복귀 시 채점이나 피해 정산을 재시작하지 않는다. 배경 진입 전 확정된 공격 결과를 이중 적용하지 않는 것이 우선이다.

## 7. 변경 파일과 버전 원칙

### 7.1 변경 후보 — 실제 구조를 먼저 확인

| 위치 | 허용할 변경 |
|---|---|
| `src/ui/cards.js`, 기존 룬 드래그 경로 | 포인터 수명, 취소, 중복 입력, 마지막 drop 좌표, ghost host |
| `src/ui/viewport.js`, `orientation.js` | 실제 뷰포트 변경 판별, 기존 fallback과 회전 후 입력 복구 |
| 기존 입력 CSS 또는 작은 전용 CSS | touch-action·선택·롱프레스·스크롤 전파 정책만 |
| `src/main.js`, 초기화/라우팅 | 제스처·복귀 리스너 1회 등록, 현재 흐름의 명확한 오류 처리 |
| `src/services/audio.js`, 기존 소리 UI | 실제 재현되는 시작/복구/중복 문제만 |
| 자산 URL 헬퍼·엔트리 HTML | 실제 base 경로 오류 또는 초기 진입 실패가 재현될 때만 |
| 관련 tests와 패치 노트 | 집중 검사와 실제 결과 기록 |

`musicContext.js`, 공격 presentation, 저장 모듈은 가능한 한 그대로 둔다. 입력 안정화 때문에 재현된 결함만 좁게 고치고 변경 이유를 기록한다. 대규모 CSS 정리, 데이터 registry 재생성, 새로운 의존성 설치는 하지 않는다.

### 7.2 0.12.2는 앱 안정화 버전

패키지·앱 표시 버전은 0.12.2로 갱신하되, 이미 사용 중이면 충돌을 보고하고 기존 태그를 덮어쓰지 않는다.

이번에는 게임 규칙을 바꾸지 않으므로 **원정/언어/점수/보상/시드 계약은 기존 0.12.1을 유지**한다. 앱 버전과 원정 콘텐츠 버전을 구분한다. 기존 구조에서 표시가 콘텐츠 버전에 묶여 있다면 표시용 버전 값을 좁게 분리한다.

문자열 `0.12.1`을 저장소 전체에서 `0.12.2`로 일괄 치환하지 않는다. 버전 확인을 제거하거나 모든 저장을 최신 registry로 읽게 하지 않는다. 새 앱에서 예전 원정을 열어도 사본 ID·연마·룬·턴·RNG·골드·언어 판정이 달라지면 실패다.

## 8. 구현 순서

1. 현재 정상 화면·입력·접속 baseline을 짧게 확인하고, 작업 시작 SHA와 변경된 파일을 기록한다.
2. 실제 scroll 영역과 게임 gesture 영역을 분류한다. CSS 기본 동작을 먼저 좁게 수정한다.
3. 기존 카드/룬 포인터 경로에 다중 터치·취소·중복·전체화면 ghost 처리를 연결한다.
4. 기존 접속·복귀·오디오·전체화면 경로로 짧게 플레이한다. 새 정책에 의해 깨진 부분 또는 재현된 결함만 수정한다.
5. 최종 코드에서 필수 테스트·빌드와 집중 smoke를 실행하고 인계한다. 작은 미관 차이를 고치려고 다음 디자인 작업을 시작하지 않는다.

요구를 이미 만족하는 모듈은 '확인·보존'으로 표시한다. 미구현을 문서만 써서 완료했다고 하지 않는다.

## 9. 적정 검증 — 짧은 흐름 6묶음

`CHECKLIST.md`의 여섯 흐름으로 확인한다. 같은 실행에서 여러 항목을 함께 검증한다.

| 묶음 | 짧은 확인 흐름 | 핵심 판정 |
|---|---|---|
| A | 배포 base 진입 → 새 원정/저장 불러오기 → 새로고침·복귀 | 빈 화면·영구 잠금·잘못된 asset 경로 없음, 기존 저장 의미 유지 |
| B | 카드 여러 장 빠른 탭 → 드래그 → 두 번째 손가락 → 취소 후 재조작 | 페이지 확대 없음, 카드 명령 정확히 한 번 또는 안전 취소 |
| C | 사전 스크롤·검색 → 형태 선택 → 버리기 선택 → 소리 슬라이더 | 필요한 스크롤·입력·클릭이 살아 있고 배경 카드로 관통하지 않음 |
| D | 창모드/전체화면 → 드래그 → 회전·크기 변경 → 정상 공격 | ghost와 공격 효과 유실·고착·이중 정산 없음 |
| E | 첫 탭 오디오 → 음소거/볼륨 → 앱 복귀 → 지역 이동 → 로비 | 재생/복구/취소가 기존 정책대로, 곡 중복 없음 |
| F | 같은 상태의 화면·저장·핵심 게임값 비교 | 의도하지 않은 디자인·규칙·덱·저장 변경 없음 |

### 9.1 명령과 검사 수준

최종 코드에서 `npm test`, `npm run build`를 실행한다. [R7] 이번 변경에 해당하는 기존 입력·viewport·오디오 브라우저 검사를 재사용하고, 누락된 경계만 작은 검사로 추가한다. 언어·데이터를 바꾸지 않으므로 별도의 언어 대검증이나 `validate:data` 확대 실행은 저장소 지침상 필요할 때만 한다.

대표 PC 창모드·전체화면, 태블릿 가로, 휴대폰 가로를 사용한다. 기존 자동화 도구와 설치된 엔진을 먼저 활용하고, 테스트 환경을 새로 구축하느라 범위를 늘리지 않는다.

자동화가 가능하면 CSS 적용 결과·pointer state·명령 수·cleanup·중복 source를 검사한다. touch emulation이나 합성 이벤트만 통과한 것을 **실제 iPad 확대 방지·실제 오디오 청취·카카오톡 성공**이라고 보고하지 않는다.

실기기가 있으면 Android 또는 iPad의 실제 터치/소리 흐름을 먼저 짧게 확인하고, 가능한 추가 환경을 기록한다. 없으면 해당 항목만 `NOT RUN`으로 정확히 남기고 구현과 확인된 검사 결과를 인계한다. 실기기가 없다는 이유로 작업을 무한 반복하거나 임의로 PASS 처리하지 않는다.

### 9.2 하지 않는 검증

50전투 자연 완주, 대량 seed, 전 브라우저×전 해상도 조합, 수백 장 캡처, 픽셀 퍼펙트 이미지 비교, 플레이어 화면의 fixture·점수 데모·개발 패널은 추가하지 않는다.

대표 화면 비교는 2~4장 수준이면 충분하다. 필요한 경우 짧은 입력 로그 또는 짧은 영상 1개로 실제 동작을 남긴다. 문제가 없는 전체 검사를 스타일 한 줄 수정마다 반복하지 말고, 영향받은 검사 후 최종 필수 명령을 수행한다.

`force:true` 클릭, 자동 viewport scale 리셋, assertion 삭제, 실제 입력 대신 내부 함수만 호출하는 방식으로 사용자 재현 문제를 숨기지 않는다. 미지원 browser 기능과 제품 결함을 구분한다.

## 10. 완료·인계 조건

가장 중요한 완료 조건은 **겉보기는 그대로인데 연속 탭·드래그·복귀가 안정된 것**이다.

완료 보고는 다음만 간결하게 담는다.

- 변경 파일과 실제 원인/수정 요약. 정상 확인 후 그대로 둔 기능도 구분.
- 실행 명령·종료 코드와 A~F 상태: PASS / FAIL / NOT RUN / 기존 제한. 자동화와 실기기 증거를 구분.
- 실제 터치 확대 확인 환경, 실제 소리 청취 여부. AudioContext 상태만으로 청취 PASS를 쓰지 않는다.
- 디자인·규칙·저장 계약을 바꾸지 않았는지, 기존 작은 화면 제한 등 남은 사항.
- 커밋·브랜치·PR·배포 여부. main 직접 병합과 공개 배포는 별도 승인 사항.

작업 지시를 충족한 뒤 새로운 UI 아이디어나 범위 밖 최적화를 계속 덧붙이지 말고 플레이 가능한 결과를 먼저 인계한다.
