- Vanilla JS + ES Modules + Vite의 기존 모듈 구조. 새 프레임워크·거대 상태관리·범용 언어학 시스템 도입 금지.

## 3. P01 — 채점 연출을 읽을 수 있도록 약 2배 길게

### 목표

학생이 ‘무슨 문법과 룬 때문에 점수가 올랐는지’ 읽을 시간이 있어야 한다. 카드 조작 속도, 계산 성능, 최종 돌진의 속도까지 느리게 하는 패치는 아니다.

### 구현

- 기존 1× 대비 점수 연쇄의 읽기 시간을 대략 2배로 늘리고, 새 1× 기본값으로 사용한다.
- 기존 1/1.5/2배속 설정은 유지하되 새 기본 템포 기준으로 동작하게 한다. 단순히 저장된 speed를 몰래 바꾸지 않는다.
- 카드별 기본점수 표시는 대략 150~180ms, 문형·문법 보너스 표시는 최소 500~600ms, 룬 핵심 효과는 빛 이동과 읽기 시간을 포함해 약 650~850ms부터 시험한다.
- 절대 밀리초는 설계 기준값이다. 먼저 기존 화면을 계측하고 소수 항목이 과하게 지루해지지 않는 범위로 조정·보고한다.
- 현재처럼 긴 연쇄를 전체 2050ms 안으로 압축해 핵심 항목이 안 읽히는 처리 금지. 긴 문장에서는 기본 카드 합산 연출을 시각적으로 묶을 수 있지만, 실제 ScoreEvent·최종값은 보존하고 핵심 문법·룬 이름은 생략하지 않는다.
- 한 번에 큰 문법 이름은 하나. 직전 결과는 작은 로그로 남기고 역할명·연결 강조도 해당 이벤트의 읽기 시간 동안 유지한다.
- 최종 위력은 350~500ms 정도 응축 후 공격. 돌진 자체는 기존의 민첩함(약 180~240ms)을 유지한다.
- `effectsOff`와 `prefers-reduced-motion`은 장식·움직임을 줄이는 옵션이다. 읽기 시간까지 .06/.58배로 줄이지 않는다. ‘효과 끄기’와 ‘빠르게 재생’을 분리한다.
- 기존 5000ms 고정 watchdog을 그대로 두지 않는다. 실제 타임라인 총 길이+안전 여유로 산정해 정상적인 긴 연출이 중간 종료되지 않게 한다.
- 탭 숨김·Abort·뷰 오류·watchdog 등 기존 정리 경로는 유지한다. 정리 과정에서 실제 피해/재화가 두 번 반영되지 않게 한다.
- 점수 계산은 먼저 완료하고 화면은 확정된 이벤트를 재생한다. 화면에서 부동소수점 계산을 다시 해 실제 값과 달라지게 하지 않는다.

### 인수 기준

같은 고정 AttackResolution의 새 1× 점수 표시 구간이 기존 대비 약 2배이고, 이벤트 수가 많아져도 주요 항목이 순식간에 사라지지 않는다. 모든 배속·효과 설정에서 최종 점수와 게임 상태가 동일하다.

## 4. P02 + P10 — 콤보 누적·룬 색상 연출 강화

### 단계적인 증폭

- 평범한 짧은 문장에도 최소 타격감은 유지하지만, 처음부터 모든 점수에 최대 진동·폭발을 쓰지 않는다.
- 기본 카드 수만으로 ‘많은 콤보’를 판정하지 않는다. 실제 문형·추가 문법·발동 룬의 의미 있는 이벤트 수와 기준 공격력 대비 확정 위력을 함께 참고한다.
- 점수판은 연쇄가 쌓일수록 글자 무게, 제한된 확대, 테두리 빛, 소량의 불꽃/잔광, 미세 진동 순으로 강화한다.
- 점수 숫자/한글 라벨이 잘리는 확대, 장시간 blur, 가독성을 가리는 파티클 금지. 레이아웃 높이는 고정하고 transform/opacity 중심으로 처리한다.
- 연쇄 중 진동은 주로 점수판·전장에 한정한다. 편집 중 손패, 좌우 메뉴, 읽는 문법명까지 계속 흔들지 않는다.
- 최종 타격의 강도는 확정 피해량 기준 원칙을 유지한다. 콤보 수가 많다고 낮은 위력의 최종 공격까지 최대 충격으로 위장하지 않는다.

### 룬별 색상·빛 이동

- 기존 runeId와 `runeColors` 등 색상 정의를 통합해서 재사용한다. 색 때문에 룬 효과나 희귀도 규칙을 추가하지 않는다.
- 공격 룬: 오른쪽 실제 슬롯의 보석이 점등·들썩임 → 해당 룬색 빛이 곡선 궤적으로 문장/점수판으로 약 180~260ms에 이동 → 작은 팡 이펙트와 함께 해당 ScoreEvent의 after 숫자를 표시한다.
- 게임 점수는 이미 확정되어 있다. 빛 도착 시 바꾸는 것은 표시 숫자뿐이다. 도착 콜백이 실제 점수·피해·재화를 다시 계산하면 안 된다.
- 현재처럼 모든 룬에 같은 노란 pulse만 사용하는 대신 각 룬의 고유색을 활용한다.
- 대상 카드가 명확한 룬은 해당 카드에도 같은 색의 짧은 강조를 주고, 문장 전체를 강화하는 룬은 조합대 외곽을 강조한다.
- 여러 룬은 실제 위→아래 발동 순서와 동일하게 재생한다. 효과가 없는 룬을 멋을 위해 가짜로 발동시키지 않는다.
- 운영 룬은 첫 손패/교환 자원 등 실제 규칙이 적용되는 순간 반응한다. 공격 때 가짜 배수 이펙트를 만들지 않는다.
- SVG/Canvas/DOM의 소규모 재사용 이펙트로 구현한다. 새 GIF, 외부 이미지/영상 API, 대형 그래픽 프레임워크를 도입하지 않는다.
- 태블릿 resize·화면 스케일에 맞춰 실제 슬롯/타깃 위치를 계산하고, overlay는 pointer-events:none으로 조작을 막지 않는다.
- 동작 줄이기·효과 끄기를 지원하고 반복적인 강한 전체 화면 섬광은 쓰지 않는다. 진동은 기본적으로 시각적 화면 흔들림이며 하드웨어 진동이 필수는 아니다.

## 5. P03 — 카드를 먼저 선택한 뒤 한 번에 버리기

### 기존 클릭 조립을 보존하는 선택 방식

사용자는 현재 문장 조립 속도에는 만족했다. 따라서 카드 본체 클릭을 전부 ‘선택’으로 바꾸어 문장 조립에 확인 버튼을 하나 더 요구하지 않는다.

- 손패 카드에 항상 접근 가능한 ‘선택’ 체크 영역을 마련한다. 단어를 가리지 않고 태블릿에서도 누르기 쉬운 hit area를 확보한다.
- 카드 본체 클릭: 기존대로 조합대 끝에 추가.
- 체크 영역 클릭: 손패에 그대로 둔 채 버리기 선택을 토글. 여러 장 동시 선택 가능.
- 선택된 카드는 올라옴/테두리/체크 상태로 명확히 구분한다.
- 하단 버튼은 `버리기 (N장) · 잔여 4회`처럼 표시한다. 별도의 ‘버리기 모드 진입’을 선행하지 않는다.
- N>0일 때 누르면 N장을 한 번에 버리고 같은 수만큼 즉시 보충한다. 행동 턴은 줄이지 않고 교환 횟수만 1 감소한다.
- N=0, 교환0, 처리 중에는 자원 소모 없음. ‘선택 해제’ 및 Esc를 제공할 수 있으나 필수 조작에 키보드·우클릭·길게 누르기를 요구하지 않는다.
- 클릭/키보드 체크는 드래그를 시작하거나 카드를 조합대에 넣지 않는다. `pointercancel`, 드래그 후 click 중복, touch-action을 처리한다.
- 선택 카드가 조합대로 이동하면 그 ID만 선택에서 제거한다. 남아 있는 손패 선택은 보존한다.
- 형태 메뉴·덱/사전 팝업·룬 상세를 여닫을 때 의미 없이 선택 상태를 잃지 않는다. 성공한 교환, 턴/전투 전환에서는 안전하게 해제한다.
- 선택은 UI 편집 상태일 뿐 RNG·카드 영역·턴을 바꾸지 않는다.
- 기존 `EXCHANGE_SELECT`를 새 UI의 필수 진입 상태로 남기지 않는다. 실제 EXCHANGE 명령의 검증과 카드 보존 로직은 재사용한다.
- 조합대 카드는 직접 교환 대상에 넣지 않는다. 기존 회수·맞교환 규칙을 유지한다.

## 6. P04 — be의 기본 표시는 be, 활용은 직접 선택

- 손패, 보상, 덱 보기의 be 기본 표시는 `be`로 한다.
- 조합대에 처음 올린 be도 `be`로 표시하고, 별도 형태 버튼으로 현재 지원하는 `am / is / are`를 선택하게 한다.
- 주어에 맞추어 자동으로 정답을 골라 주지 않는다. `I → am`, `she → is`를 학생이 선택한다.
- 카드의 표시용 기본 원형과, 현재형 문장에서 문법적으로 허용되는 활용형을 분리한다.
- 기존 소스에서는 `form.be.base`가 inactive라 기본을 단순 교체하면 모든 be 카드가 UNSUPPORTED로 떨어질 수 있다. `formsForCard`, snapshot, 입력 검증, 기본 형태, 저장 복원을 함께 확인한다.
- 원형 be를 UI에 제공한다고 명령문/to부정사 등 미구현 문법 전체를 활성화하지 않는다.
- `I be happy.`를 완전한 문장으로 인정하지 않는다. 현재형 기본 구조에서 be 활용 선택이 누락된 경우, 구조는 알아볼 수 있다는 기존 부분점수 철학에 맞춰 ‘be동사 형태’ 진단과 기존 형태/일치 수준의 감점(10)을 한 번만 적용한다. 내부 예외나 무조건 미지원으로 숨기지 않는다.
- `She are happy.` 등은 기존 일치 오류 유지. 올바른 `I am happy. / She is happy. / They are happy.` 점수는 바뀌지 않는다.
- 기존 저장에 학생이 명시적으로 선택한 am/is/are는 보존한다. 손패 회수 시 원형으로 돌아가는 기존 정책을 일관되게 적용한다.
- 다른 단어의 형태 선택, formId/surface 구분, 올바른 후보만 보여주는 메뉴는 보존한다.

## 7. P05 — Stage 1-1에서 핵심 조작을 실제로 수행하는 튜토리얼

### 범위와 연출

- 순서형 말풍선 가이드는 Stage 1-1에 집중한다. 상단의 작은 설명 배너만 바꾸는 것으로 완료하지 않는다.
- 해당 UI에 연결된 말풍선·spotlight·진행도(예: 3/7)를 사용한다. 대상과 문장이 가려지지 않게 배치하고 화면 크기 변경 시 재배치한다.
- 실제 성공한 명령을 확인해 단계가 진행된다. 다음 버튼만 눌러 모든 행동을 수행한 것으로 기록하지 않는다.
- 항시 ‘안내 건너뛰기’를 제공한다. 다회차 강제 반복 없음. 설정의 다시 보기는 실제 전투를 초기화해 보상을 중복 지급하는 방식이 아니라 분리된 연습/가이드 재생으로 처리한다.

### 첫 공격 전까지의 권장 흐름

1. 손패·조합대·상단 적·6턴·4회 교환을 짧게 안내한다.
2. 카드 본체 클릭 또는 드래그로 주어·be·형용사를 조합한다.
3. 형태 버튼에서 be→am/is/are를 실제로 바꾼다.
4. 남아 있는 불필요한 손패를 체크해 선택하고 ‘버리기’를 누르게 안내한다. 같은 수가 보충되고 교환 횟수만 줄어드는 것을 확인한다.
5. 조합대를 유지한 상태에서 ‘준비·다음 턴’을 한 번 수행한다. 남은 턴이 줄고 카드가 추가되는 것을 안내한다.
6. 첫 SUBMIT이 실제로 계산·커밋되기 직전에 한 번만 설명한다: ‘카드 점수 → 형태/문법 확인 → 문형·룬으로 증폭 → 최종 피해로 공격합니다. 지금은 룬이 없어도 문장 콤보가 점수를 올려요.’ 확인 후 실제 제출한다. 구체 정답 점수는 미리 보여 주지 않는다.
7. 첫 타격 뒤 HP 감소·남은 턴을 확인하고 자유 플레이로 전환한다.

### 막힘 방지

- 초기 6장은 기존 덱 안에서 뽑되, 튜토리얼용으로 실제 be·적절한 주어·형용사, 교환해도 되는 여분 카드, 짧은 SV 경로를 만들 수 있게 seeded opener를 구성한다.
- 예문 단어는 해당 원정의 실제 카드에 맞춘다. 모든 원정을 같은 고정 28장으로 바꾸거나 없는 카드를 튜토리얼이 생성하지 않는다.
- 이미 행동을 했다면 충족한 단계를 감지해 건너뛴다. 목표 카드가 다른 영역으로 이동해도 ID를 찾아 진행한다.
- 남은 교환이0이거나 손패가 가득 찬 경우 행동 가능한 대안을 안내한다. 가이드 때문에 무한 대기·빈 화면을 만들지 않는다.
- 튜토리얼에서 수행하는 교환과 준비도 실제 자원을 소모한다. 숨은 무한 턴·무료 교환·강제 승리·HP 환급을 추가하지 않는다. 시작 라운드의 접근성을 먼저 검증한다.
- 단, 가이드 자체를 읽는 시간은 턴을 사용하지 않는다. 대기 시간으로 턴이 감소하면 안 된다.
- `guideSeen`을 전투 시작 순간 완료 처리하지 않는다. 단계 완료와 안내 건너뛰기를 구분하고 `tutorialVersion/completed/skipped` 등 최소 상태로 관리한다.
- 기존 프로필에서 이미 가이드를 본 사용자는 자동 강제 재교육하지 않는다. 명시적인 다시 보기 경로를 제공한다.
- Stage 1-2의 룬 선택은 유지하고, 그때는 짧은 룬 안내만 한다.

## 8. P06 — 항상 세 칸인 혼합 보상 팝업

### 확률의 의미 변경

기존: 팝업 전체 type 1회 추첨 → 같은 유형 후보.
변경: 후보 슬롯 3개 각각에 유형을 추첨 → 서로 다른 종류가 섞일 수 있음 → 최종적으로 1개만 획득.

| 슬롯의 기본 유형 가중치 | 일반 전투 | 지역 보스 |
|---|---:|---:|
| 일반 단어 카드 | 50 | 0 |
| 고급 단어 카드 | 10 | 10 |
| 희귀 단어 카드 | 5 | 10 |
| 카드 연마 | 15 | 25 |
| 카드 제거 | 10 | 5 |
| 룬 | 10 | 50 |

- 위 가중치를 팝업 type 확률로 다시 곱하지 않는다.
- 순수 독립 추첨일 때의 참고값: 일반 전투에서 카드 선택지가 2칸 이상일 확률 71.825%, 룬이 하나 이상 보일 확률 27.1%. 보스의 룬 하나 이상은 87.5%. 이는 아래 중복·유효성 조건을 적용하기 전 참고값이며 최종 실측 분포와 혼동하지 않는다.
- 카드의 희귀도, 룬 내부 일반60/고급30/희귀10, 전투 보상 유형 확률은 서로 다른 층이다.
- 지역/범용/변칙 성격은 ‘카드 유형이 뽑힌 슬롯의 구체 카드를 고를 때’ 후보 가중치로 활용한다. 세 역할을 강제해 세 슬롯을 모두 카드로 만들지 않는다.

### 팝업과 선택

- 적 처치 후 정산 요약과 함께 중앙 모달에 큰 선택지 정확히 3개를 보여준다. 뒤의 전장은 어둡게 남기고 입력을 막는다.
- 단어 카드 칸: 실제 카드 한 장을 보여 주고 선택하면 그 카드 한 장을 획득.
- 룬 칸: 실제 룬 하나와 Lv.1 효과/중복이면 +1 강화 여부를 보여준다.
- 연마 칸: ‘보유 카드 1장 연마 +1’이라는 서비스 선택지. 클릭하면 그다음 보유 카드 대상 선택 화면을 연다.
- 제거 칸: ‘보유 카드 1장 제거’. 클릭하면 보유 카드 대상 선택 화면을 연다.
- 연마·제거 대상 선택은 3칸 보상 팝업의 다음 단계다. 처음부터 전체 덱을 보상 선택지로 펼치지 않는다.
- 대상 선택에서 취소하면 원래의 동일한 세 후보로 돌아온다. 보상·재화·강화·제거는 아직 소모되지 않는다.
- 룬 슬롯 만석의 교체도 기존 원자적 선택/취소 정책을 유지한다.
- 최종 선택 성공 시 세 후보 중 한 보상만 정산하고 나머지는 사라진다. 카드+룬+제거를 한 번에 받지 않는다.

### 3칸 유효성

- 같은 offer 안에서 동일 카드 정의/동일 룬을 의미 없이 반복하지 않는다. 보유 카드의 추가 사본은 허용한다.
- 동일한 ‘연마 서비스’는 최대1칸, 동일한 ‘제거 서비스’도 최대1칸. 이미 뽑은 서비스 유형은 다음 슬롯에서 제외하고 남은 유효 유형을 정규화한다.
- 최고레벨 룬만 남았거나 모든 카드가 연마+3이면 해당 불가능 유형은 제외한다. 같은 등급의 카드 풀이 부족하면 후보 검사를 거쳐 가능한 대체를 선택한다.
- 중복/불가능 조건에 따른 보정은 명시적으로 trace에 남긴다. 무한 재추첨 금지. 유효 전체 풀이 3개 미만이면 사전 데이터 검증에서 실패시키고 합법적인 기본 카드 대체 경로를 마련한다. 정상 플레이 보상에 빈칸·미구현 기능·누를 수 없는 더미 보상을 쓰지 않는다.
- 보스 일반 카드0 가중치를 정상 보상 생성에서 훼손하지 않는다. 특수한 데이터 오류 fallback은 명시·로그하며 정상 테스트 통과로 위장하지 않는다.
- 정확히 세 칸을 채우되 선택할 실제 유효 콘텐츠를 사전 확보한다. 없으면 원인을 고치고 배포한다.

### 기존 예외와 경제

- 매 원정 Stage 1-2는 ‘첫 룬 선택’ 예외로 유지: 3칸 모두 룬.
- 최초 경험 후보는 수정/호박/구리, 이후에는 기본 중심 랜덤 2칸+해금·구현된 전체 풀 1칸. 같은 ID 중복 없음.
- 첫 튜토리얼 원정의 Stage 1-1은 기존 firstEverR1Override=일반 카드 3칸 예외를 유지한다. 이렇게 해야 최초 고정 룬 소개(1-2)보다 먼저 무작위 룬이 나오는 모순을 피한다. 튜토리얼이 아닌 이후 원정의 1-1은 혼합표를 사용한다. 이 예외도 3칸 중 1선택이라는 UI 규칙은 지킨다.
- 전체 보상 건너뛰기는 하단 별도 버튼. 카드 슬롯이 하나라도 있는 혼합 팝업은 +3, 카드 슬롯이 전혀 없으면 +2라는 규칙으로 기존 두 skip 값을 재사용한다. 슬롯별 skip 돈을 합산하지 않는다.
- 후보마다 `choiceId, kind, rarity?, cardDefId?, runeId?, serviceKind?`를 저장한다. offer는 `MIXED`와 `RUNE_INTRO` 등을 구분하며 타입별 취소/복원에 같은 객체를 쓴다.
- 공개한 후보·가격/skipGold·룬 레벨 판정은 저장/닫기/대상 취소로 바뀌지 않는다. 같은 offerId의 중복 정산 금지.

## 9. P07 — 도감에 ‘한글 뜻 참고’, 문법과 자연스러움을 분리

### 목표

학생은 자신의 영어 문장이 무슨 뜻인지 확인할 수 있어야 한다. 다만 게임은 범용 번역기나 의미 정오 판정기가 아니다. 전투 점수를 의미상의 어색함 때문에 깎거나, 해석을 만들기 위해 영어 원문을 고치지 않는다.

### 필수 구현

1. 도감의 첫 문장·최고 문장 아래에 한글 의미 참고 영역을 추가한다.
2. 공통 안내 한 줄: `게임은 문장 구조를 중심으로 점수를 계산합니다. 뜻과 자연스러움은 문맥에 따라 달라질 수 있어요.`
3. 검증한 현재형 SV/SVC/SVO는 기존 AnalysisResult의 역할·선택된 Sense와 별도 한국어 템플릿으로 짧은 ‘뜻 참고 · 자동 구성’을 만든다.
4. 주어/목적어/보어와 동사·형용사·기본 부사·전치사구의 대응을 사용한다. 영단어 한국어 뜻들을 원래 영어 순서대로 붙인 결과를 정확한 번역이라고 표시하지 않는다.
5. 완전한 한 문장으로 안전하게 구성할 수 없으면 `주어: … / 행동: … / 대상·상태: … / 수식: …`라는 성분별 한글 뜻을 보여준다. 빠진 성분을 생략한 매끄러운 번역으로 위장하지 않는다.
6. 원래 문장에 관사/일치 오류가 있었다면 기존 구조 결과를 함께 표시한다. 의미 참고가 있다고 ‘문법적으로 완벽한 문장’으로 격상하지 않는다.
7. 다의어나 등록되지 않은 한국어 활용 때문에 확실한 해석을 만들 수 없으면 ‘이 문장은 단어별 뜻을 참고해 보세요’와 성분/단어 뜻으로 fallback한다.
8. 학습자에게 상시 한글 뜻을 보여주지 않기로 한 손패·조합대는 바꾸지 않는다. 한글 의미는 도감/공격 기록 상세에서만 제공한다.

### 예시(표현은 검증 후 조정 가능)

| 영어 원문 | 기대하는 의미 참고 |
|---|---|
| I run. | 나는 달린다. |
| She is happy. | 그녀는 행복하다. |
| I like books. | 나는 책을 좋아한다. |
| The book likes dogs. | 그 책은 개를 좋아한다. (의인화·상상 표현으로 읽힐 수 있다는 짧은 참고는 가능) |
| music gives new home. | 음악은 새로운 집을 준다. / 원문의 관사 오류 기록은 별도 유지 |
| they play the culture. | 등록된 play 뜻과 목적어 문화를 표시. 자연스럽게 보이도록 목적어를 바꾸지 않음 |
| you often play a useful student. | 주어 너 / 행동 play의 등록 뜻 / 대상 유용한 학생 / 빈도 종종 등 안전한 의미 참고. ‘학생을 연기하다’ 용법이 실제 데이터에 없다면 몰래 의미를 확정하지 않음 |

`play + 사람`을 항상 의미 오류라고 판정하지 않는다. play에는 역할을 연기한다는 실제 용법도 있으므로, 이번 작은 모듈이 그런 문장을 일률적으로 잘못되었다고 단정하면 안 된다.

### 의미 경고의 제한

- 전체 문장에 ‘의미가 어색한 문장’이라는 빨간 오답 배지를 자동 부여하지 않는다.
- 이 패치에서 모든 영어의 자연스러움을 판정할 분류기를 만들지 않는다.
- 선택적으로 소수의 명확한 태그 조합에만 ‘게임에 등록된 뜻으로는 낯선 조합일 수 있어요’ 등 약한 참고 문구를 제공할 수 있다. 금지/감점/보스 조건에 사용하지 않는다.
- ‘문법적으론 옳지만 실제론 자연스럽지 않음’을 모든 기록에 고정 문구로 달지 않는다. 문법 오류 여부와 의미 상태가 각각 다르기 때문이다.

### 구조와 저장

- `MeaningPreview`는 작은 독립 로컬 표시용 모듈로 두고 `AnalysisResult + SentenceSnapshot + KoreanSenseTemplates`를 읽는다. Grammar/Scoring은 역으로 이 모듈을 참조하지 않는다.
- 출력 예: `{status: 'COMPLETE_HINT'|'PARTIAL_HINT'|'UNAVAILABLE', textKo, segments, noteKo, meaningVersion}`. 근거 없는 0.99 같은 신뢰도 수치를 생성하지 않는다.
- 필요한 한국어 활용은 등록 단어의 템플릿/형태를 명시해 검사한다. 한국어 조사 처리는 작은 헬퍼로 하되 일반 번역 엔진을 재개발하지 않는다.
- 최초/최고 기록에 해당 당시의 소형 의미 요약과 기존 grammar status/issue 요약을 보존한다. 모든 공격을 무제한 저장하지 않는다.
- 옛 기록에는 문자열만 있을 수 있다. 원본 공격 구조가 없으면 정확한 전체 번역을 복원했다고 주장하지 않고 단어·성분 참고 또는 ‘이전 기록: 해석 정보 없음’으로 처리한다. 옛 점수를 재계산하거나 기록을 삭제하지 않는다.
- 해석 실패·없는 템플릿·오래된 기록 때문에 도감이나 전투가 멈추면 안 된다.
- 외부 AI/번역 API·인증키·네트워크·대형 모델 다운로드를 요구하지 않는다.

## 10. P08 — 일반 몬스터·보스 HP 1.30배 상향

- 본 패치의 새 원정 Stage 1 HP는 70→91, 120→156, 220→286.
- 런타임에서 열 때마다 곱하지 말고 밸런스 버전의 최종 기준값으로 저장한다. 불러오기·다음 전투·보상 닫기로 재상향 금지.
- 어휘 모드에 따른 HP 차이 없음. 난이도1/현재 구현 범위 전체에 동일 적용.
- 새 HP에 맞춰 화면 maxHp/currentHp·게이지·오버킬·시뮬레이션 기대값을 함께 변경한다.
- 고점 한방을 막기 위한 피해 상한, 플레이어 화력에 따라 올라가는 숨은 HP, 일반 문형 배율 너프는 추가하지 않는다.
- 첫 튜토리얼에서 준비 한 번과 교환 한 번을 해도 실제 제공 카드로 이길 경로가 있는지 확인한다.
- 1형식만으로 Stage 1을 공략하는 기준은 단순 50×6=300 산술만 보지 말고 실제 28장/첫손패/교환/재셔플에서 검사한다.
- 새 HP와 혼합 보상으로 무엇이 달라졌는지 보고하되, 지정되지 않은 추가 수치 조정은 임의 적용하지 않는다.

## 11. P09 — 연마 표시와 연마 획득 연출 강화

- 단어·품사 색상은 보존한다. 연마 때문에 모든 카드가 같은 금색이 되지 않게 한다.
- +1/+2/+3을 읽기 쉬운 고정 배지로 표시한다. 별/각인/테두리 단계로 ‘몇 번 강화했는지’도 구분한다.
- 카드 기본점수는 총값(10/15/20/25)을 명확히 표시하고 상세에서는 기본10+연마추가5/10/15의 근거를 확인할 수 있게 한다.
- 손패·조합대·덱 보기·사전 보유 카드·연마 대상 화면에 동일 규칙 적용. 긴 문장으로 카드가 작아져도 연마 정보가 전부 사라지지 않게 한다.
- 연마 확정 시 선택 카드 확대·짧은 빛/제련 효과·`+1 → +2`와 `15 → 20` 표시 후 다음 상태로 이동한다.
- 공격의 카드 합산 때 연마된 카드는 기본 카드와 구분되는 짧은 반짝임을 주되, 별도의 연마 점수를 다시 더하지 않는다.
- 철 룬의 별도 보너스와 카드 자체 연마를 혼동하지 않는다.
- 연마 +3인 카드 재강화, 취소 시 변경, 중복 확정 시 +2 증가 같은 오류를 막는다.

## 12. P11 — 남은 턴이 재화가 되도록

### 공식

`turnBonusGold = max(0, turnsRemainingAfterKillingAction) × 1`

`victoryGold = existingBaseKillGold + turnBonusGold + 이미 구현된 별도 처치효과`

- 일반 기본2/보스 기본6은 유지한다.
- 전투6턴에서 1/2/3/4/5/6번째 행동으로 처치하면 각각 +5/+4/+3/+2/+1/+0.
- 준비 행동도 턴을 쓴다. 예: 준비2회+공격2회로 처치하면 총4행동이므로 +2.
- 마지막 공격에 쓴 턴을 차감하기 전 값을 사용해 +6을 주는 off-by-one 오류 금지.
- 화면 예: `승리 +2 / 남은 턴 3개 +3 / 획득 +5`. 그다음 보상 선택/건너뛰기 재화를 별도로 정산한다.
- 전투 중 남은 턴 옆에 ‘남겨서 클리어하면 턴당 +1 재화’ 한 줄을 제공한다. 제출 전 점수 미리보기는 만들지 않는다.
- 남은 교환 횟수에는 이번 패치에서 별도 재화를 주지 않는다. 교환을 아끼도록 강요하는 새 시스템을 추가하지 않는다.
- 면역으로0피해·패배·무효 제출·샌드박스·리플레이에서는 지급하지 않는다.
- `(runId,battleId,VICTORY)` 정산키로 기본재화와 턴보너스를 함께 한 번만 지급한다. 연출 재생/보상취소/로드로 반복 지급 금지.
- 첫 상점까지의 기존 기본수입10은 이후 콘텐츠에서 턴보너스로 최대25가 될 수 있다(3전투 모두 첫행동 처치, 다른 효과 제외). 이번엔 상점이나 가격을 새로 만들거나 몰래 조정하지 말고 0.2 경제 검토 항목으로 보고한다.

## 13. P12 — 28장 덱·기본문형 보장·첫 손패 접근성

### 28장 제안 구성

| 분류 | 장수 |
|---|---:|
| 명사 | 6 |
| 대명사 | 4 |
| 동사 | 8 |
| 형용사 | 3 |
| 부사 | 2 |
| 관사·한정사 | 3 |
| 전치사 | 2 |
| 합계 | 28 |

기존 대명사1장·형용사1장만 줄인다. 문장의 핵심인 동사와 관사는 줄이지 않는다.

- 대명사: `I / you / they`를 유지하고 `he 또는 she` 중 하나를 시드로 선택한다. 둘 중 하나가 빠지면서 3인칭 단수/비3인칭 주어 경로는 모두 유지된다.
- 동사8장은 기존 역할 배분을 유지한다: be2 + 명확한 SV 동사2 + SVO 역할3 + 다중문형 역할1.
- SV2는 가능하면 서로 다른 Lexeme의 직관적인 자동사 용법으로 뽑는다. 현재 등록된 go/come/run/live 등에서 선택하고, 필요없는 새 단어를 대량 추가하지 않는다.
- be만 보고 ‘1형식 있음’으로 세지 않는다. `be+장소` 경로는 추가 가능성이며 명확한 SV 행동 동사 경로를 대체하지 않는다.
- be의 SVC_ADJ/SVC_NP, SVO를 각각 현재 실제 파서로 검증한다. 태그 카운트만 보고 완료라고 하지 않는다.
- 형용사3장과 명사6장의 실제 구문 가능성, 관사/단복수, 물리 카드 중복 사용 금지를 검사한다.
- `BALANCE.starter.slotCounts`와 deck 모듈 하드코딩, 30장 고정검사, 고정 대명사 검사, 난수 fallback, UI 안내, 문서, 테스트를 모두 맞춘다. 가능하면 같은 설정값을 읽게 한다.

### 첫 손패

- 덱 전체에 SV가 있는 것과 첫6장에서 쓸 수 있는 것은 다르다.
- Stage 1-1 첫6장은 짧은 실제 SV 문장을 만들 카드 경로를 포함한다. 튜토리얼이 켜져 있으면 위의 be 활용 체험 경로도 같은 6장 안에 확보한다.
- 학생에게 완성 정답을 자동 배열하지 않는다. 실제 카드 순서는 섞어서 보여준다.
- 이후 전투는 현재 덱에서 최소 하나의 정상 기본문장 경로를 가진 기존 opener를 유지하고, 특정 문형이 의도적으로 focus인 경우만 그 문형 경로를 우선한다.
- 매 턴 몰래 필요한 동사를 만들어 주거나, 제거한 카드를 복구하거나, 모든 드로우를 정답 맞춤으로 바꾸지 않는다.
- 검증에 사용한 frame/form/card witness는 개발 로그에만 남긴다.
- 새 알고리즘 버전에서 seed 재현을 검사한다. 구버전과 새버전의 덱이 같을 필요는 없지만 동일한 새버전 실행끼리는 동일해야 한다.

## 14. P13 — 좌우 메뉴 글자만 읽기 좋게

- 카드 영단어의 기존 크기·배치·이미지 스타일은 유지한다.
- 왼쪽 메뉴·자원 라벨, 오른쪽 룬 이름·효과 문구를 중심으로 소폭 확대한다.
- 초기 목표: 주요 사이드 본문 약14px, 룬 이름14~15px, 효과/보조 설명12~13px부터 시험. 기존의 큰 남은턴 숫자까지 일괄 키우지 않는다.
- 단순히 전체 페이지 zoom/scale을 올려 카드·작업대가 잘리게 하지 않는다. 패널 폭·줄바꿈·간격을 함께 조정한다.
- 1920×1080, 1366×768, 1180×820, 1024×768 가로에서 긴 룬 설명·3슬롯·손패10장·확장손패14장·조합대16장을 확인한다.
- 필요한 경우 좌우 패널 내부 스크롤만 허용하되, 공격 버튼·현재 자원은 항상 접근 가능하게 한다.
- 확대 폰트와 튜토리얼 말풍선·형태 메뉴·보상 팝업이 충돌하지 않아야 한다.

## 16. 권장 구현 순서

A. 기준 확보: 원본 실행·기존 테스트·스크린샷·수치/모듈 매핑.
B. 입력/데이터: 선택 후 버리기, be 표시·진단, 28장 덱·첫 손패.
C. 상태/경제: 혼합 보상·2단계 대상선택·턴보너스·HP·저장 호환.
D. 교육: 행동 기반 튜토리얼, 도감 의미참고.
E. 연출: 점수 템포·watchdog·룬색 빛 이동·콤보 증폭·연마·사이드 폰트.
F. 통합: 새 원정 3전투 완주, 마지막턴·취소·재접속/로드·효과설정·반복플레이.

각 단계에서 관련 테스트를 갱신하고 전체 회귀를 돌린다. 오래된 명세의 동작(30장/동일유형보상/빠른연출)을 기대하는 테스트는 근거를 기록해 새 규칙으로 바꾸되, 테스트를 삭제해 PASS 수만 만드는 것은 금지한다.
