## 0. 제품 목표와 원칙

### 실제 사용 환경
- **학교 수업:** 학생이 교실에서 iPad/Android 태블릿으로 교사가 제시한 QR코드, 카카오톡 링크 등으로 곧장 접속한다. **PWA 설치를 요구하지 않는다.**
- **가정·개인 플레이:** iPhone/Android 스마트폰으로 카카오톡·인스타그램·QR·일반 브라우저 링크에서 접속한다. 자주 이용하면 **홈 화면 앱(PWA) 설치는 선택 가능**하다.
- **우선 목표:** 사용자가 직접 가로로 돌리고 가능한 경우 '가로 전체화면 시작'을 한 번 누르면 집중해서 플레이한다. 브라우저가 전체화면을 허용하지 않아도 **실제로 보이는 영역 안에서 조합대·손패·공격/버리기·저장/다음 버튼이 잘리지 않고 조작 가능**해야 한다.
- **정확한 한계:** 일반 URL의 최초 방문에서 주소창을 강제로 숨기거나, iPhone Safari/카카오톡/인스타그램 인앱 브라우저에서 시스템 전체화면·가로 방향 잠금을 보장하는 코드는 없다. 지원 여부를 **실제 기능 검사**하고 불가능하면 가로 최적화로 정상 플레이하게 만든다. 설치형 PWA의 `display`는 URL 첫 접속에 적용되지 않는다.

### 이번 범위만 수정
1. 링크 접속에 적합한 **진입·전체화면·가로 전환 안내 및 예외 처리**.
2. **브라우저 주소창/도구 모음·동적 가용 높이·안전 영역에 대응하는 뷰포트 계측과 UI 재배치**.
3. 모든 화면에서 잘림 없는 상호작용: 로비, 지역 입장, 상점, 전투 준비, 전투, 보상, 결과, 저장/사전/설정/형태 선택 등의 모달.
4. **가벼운 PWA 메타데이터(선택적 홈 화면 실행)**. 미설치 상태도 주력 사용 경로.
5. 이에 필요한 최소한의 회귀 테스트·실기기 검증.

### 보존·금지
- 기존 **PC·큰 태블릿 화면의 완성된 디자인, 배경, 몬스터, 카드 품사색, 폰트, 룬, 점수·공격 연출·사운드/BGM 정책**을 보존한다. 새로운 UI 콘셉트를 만들거나 전면 리디자인하지 않는다.
- 현재 모바일 전투의 **한 행 최대 8장 카드 배치**, 8장 초과 시 연속 행/세로 스크롤 및 위아래 컨트롤, **좌측 공격·턴 넘기기·조합대 비우기**, 우측 룬 열, **손패 페이지(최대 7장/화면, 실제 너비에 맞는 장수)**를 보존한다. 최대 24장 문장·카드 순서·중복·형태 선택도 보존한다.
- `RunController` 외 상태 변경 금지. 문법 판정·점수·피해·전투 50회·보상·RNG·카드 보존·저장 호환을 변경하지 않는다. 화면 크기/방향/전체화면/PWA 여부는 원정 상태가 아닌 **UI 상태**다.
- 모바일 확대를 막는다며 전역 `user-scalable=no`, `maximum-scale=1`, 모든 영역 `touch-action:none`, `preventDefault()` 남용, `window.scrollTo(0,1)` 주소창 숨기기 해킹은 금지. OS 접근성 확대·텍스트 입력·스크롤을 보호한다.
- 앱 자동 설치, 강제 PWA 안내, 외부 브라우저 강제 실행, 비표준 앱 URL 스킴 무단 도입, 모든 링크 클릭마다 새 창 띄우기, 새 탭에 원정 정보를 자동 복사하는 방식 금지.
- 저장소에 서비스워커를 일괄 도입하거나 오프라인 플레이를 약속하지 않는다. **이번 패치는 manifest 중심의 설치 준비만** 하며, 캐시 전략은 별도 승인 전까지 추가하지 않는다.
- 사용자 별도 승인 없이 `main` 병합, 공개 Pages 배포, 기존 배포 설정 변경 금지. `AGENTS.md`를 우선 적용.

## 1. 우선순위와 사용 시나리오

### P0: 주소창이 남아도 핵심 UI가 **절대 사용 불가능해지지 않을 것**
- 지원 기기별 주소창·하단 도구모음 높이가 서로 다르며 **접속 직후, 페이지 스크롤 중, 전체화면 진입·종료, 가로 회전, 앱 복귀, 키보드 열림**에 가용 높이가 변한다.
- 가용 영역이 줄어들면 **몬스터·배경/장식 영역부터 유연하게 감소**한다. 카드 조합대·손패·조작 레일과 주요 버튼은 마지막까지 보존한다.
- 정상 높이에서는 배경과 몬스터가 충분히 보여야 한다. 단지 작은 기기를 위해 정상 기기의 화면을 항상 납작하게 만들지 않는다.
- 물리적으로 한 화면에 전체 내용을 실을 수 없는 극단적 높이에서는 **해당 콘텐츠 패널의 내부 스크롤** 또는 명시적 안전한 페이지 스크롤을 허용한다. 잘린 요소가 영구히 접근 불가능한 상태, 사용자에게 보이지 않는 '다음' 버튼을 금지한다.

### P1: 가능한 환경에서 1회 제스처로 가로 전체화면
- 사용자가 **로비 또는 게임 상단의 ‘가로 전체화면 시작/전체화면’** 버튼을 터치하면 지원 API를 확인하고 실제 전체화면 진입을 시도한다. 가능하면 그 뒤에 `screen.orientation.lock('landscape')`를 시도한다.
- `requestFullscreen()` 호출은 **사용자 터치 콜백의 동기 실행 구간**에서 시작한다(제스처 활성화 상실을 유발하는 사전 `await` 금지). 전체화면 성공 확인 후 방향 잠금 실패는 별개로 취급한다.
- 미지원·권한 거부·인앱 브라우저 제한·방향 잠금 실패 시 **게임 플레이를 계속 허용**, '기기를 가로로 돌려 플레이하세요'와 단순한 대안을 표시한다. 무한 재시도/모달 루프 금지.
- 전체화면 버튼 상태는 실제 `document.fullscreenElement`, PWA 표시 모드는 `matchMedia('(display-mode: standalone|fullscreen)')`에 근거해 표시하며, '실제 시스템 전체화면'과 '주소창 없는 설치형 앱'을 혼동하지 않는다.

### P2: 반복 플레이용 선택적 PWA
- 공식 주소/QR 그대로 접속하여 설치 없이 플레이 가능해야 한다.
- 홈 화면에 추가한 경우에는 **가능한 브라우저 UI 없는 앱형 화면**을 제공한다. iOS와 Android의 표시 모드 지원은 서로 다름을 인정한다.
- 설치를 원하지 않는 학생에게 설치 안내를 강요하지 않는다.

## 3. 동적 가용 화면 계측 — 단일 근거와 우선순위

1. **`visualViewport`가 제공되는 경우:** `height`, `width`, `offsetTop`, `offsetLeft`, `scale`을 참고한다. `scale≈1`의 정상 게임 플레이 시 실사용 화면을 기준으로 뷰포트 상태를 갱신한다. 실제 사용자 접근성 확대(zoom) 중에는 확대된 화면을 다시 역으로 축소하는 오류를 만들지 않는다.
2. **CSS fallback:** `100dvh`를 사용 가능한 브라우저에서 적용하고, 불가할 때 `innerHeight`/`100vh`로 안전하게 후퇴한다. `100svh`가 필요한 초기 접속 조건은 기기별 검증 후 활용한다.
3. **안전 영역:** iPhone 홈 인디케이터·노치·기기 모서리를 위해 `viewport-fit=cover`와 `env(safe-area-inset-*)`를 활용한다. **visualViewport 보정과 safe-area padding을 중복 차감하지 않는다.** 실제 CSS 좌표계를 검증한다.
4. **키보드:** 이름 입력·저장 이름·사전 검색의 키보드가 열린 동안은 '브라우저 도구 모음 변화'와 구분하여 해당 폼이 정상 입력/스크롤되게 한다. 키보드 열릴 때 로비의 모든 레이아웃을 강제로 게임 전투 뷰로 만들지 않는다.
5. **이벤트:** `resize`, `visualViewport.resize/scroll`, `orientationchange` 또는 `screen.orientation.change`, `fullscreenchange/fullscreenerror`, `pageshow`, `visibilitychange`, 화면 내 실제 크기 변화(필요한 `ResizeObserver`)를 이용하되 **한 프레임에 최대 한 번 계측**하고 구독자를 중복 등록하지 않는다. 단순 `visualViewport.scroll`이 상태 변경이나 불필요한 조합대 리렌더를 유발하면 안 된다.
6. **안정성:** 유효하지 않은 측정(0px, NaN, 회전 도중 일시적인 값)은 무시/유예하고 마지막 정상값을 유지한다. 주소창의 연속 애니메이션 중 UI 흔들림·점멸을 최소화한다. `atlas:cancel-drag`는 실제 좌표계·방향이 달라져 기존 드롭이 위험할 때에만 보내고, 정상 한 손가락 조작 중 무관한 브라우저 이벤트로 남용하지 않는다.
7. **데이터:** 이 값들은 전부 DOM/CSS 변수/UI 서비스에만 보관한다. 저장된 원정/보상/스테이지 상태와 로컬 저장 스키마에는 기록하지 않는다.

구현 예시 이름(고정 API 강제는 아님): `--atlas-visual-height`, `--atlas-visual-top`, `--atlas-visual-width`, `data-compact-height`, `data-display-mode`. 기존 `--viewport-height`와 병행하거나 안전하게 통합한다. **높이 변수 하나만 바꾸고 화면별 고정 수치 때문에 잘리는 결과는 미완료**다.

## 4. 높이 재배치 우선순위 — ‘기능 보존 먼저’

### 전투 화면의 필수 우선순위
**A. 절대 조작 가능해야 할 요소:** 현재 조합대 8열의 카드 조작 및 형태 버튼, 좌측 `공격 확정`/`턴 넘기기`/`조합대 비우기`, 아래 손패와 페이지 좌우 이동, 카드 선택 후 `버리기`, 필요한 오류·피격 피드백. 화면상 완전히 사라지거나 시스템 바에 가려지면 안 됨.

**B. 중요하지만 내부 스크롤 허용:** 룬 열 및 발동 순서, 보스 HP/핵심 상태, 목표 문법, 드로우·버린 카드·설정/저장/도감 진입. 필요시 패널 자체가 스크롤되고 버튼은 도달 가능해야 함.

**C. 우선 축소 가능한 영역:** 배경이 보이는 상단의 여유 공간, 몬스터 주변 장식, 부가 설명 여백. **몬스터·보스가 불필요하게 사라지지 않을 것**. 정상 높이에서는 기존 연출/존재감을 보존.

추천 동작:
- 충분한 높이: 현재 v0.13.0/PR#33 전투 레이아웃 그대로.
- 주소창/도구 모음 노출로 높이 감소: 사용 가능한 높이를 재산출 → 상단 몬스터/주변 공간 및 간격부터 줄임 → 정보 패널 내부 스크롤 필요 시 활성화 → 조합대·손패/주요 버튼이 보이는 상태 유지.
- 매우 낮은 가용 높이: 8열·최대 24장 조합 유지, 추가 행은 **기존 조합대 내부 스크롤+상하 버튼**으로 접근. 물리적으로 불가능하면 게임 전체를 가려 버리는 대신 **명시적인 수직 스크롤 안전 경로**를 제공한다. 숨어 있는 조작 대신 사용자가 스크롤로 도달 가능해야 한다.
- 높이 회복: 복원 가능한 공간을 다시 상단 몬스터/배경에 반환. 페이지/카드/룬 상태는 그대로.

### 다른 화면
- **로비/프로필:** 제목과 배경은 유지. '새 원정/이어하기'가 주소창 아래로 내려가면 우선 접근 가능하게 정돈. 이름 입력 포커스/키보드로 시작 버튼을 완전히 가리지 않도록 폼 자체 스크롤/포커스 영역을 마련한다.
- **지역 입장:** `entry` 배경과 기존 시작/카드 선택 버튼 보존. 높이가 짧아져도 다음 행동 버튼 접근 가능.
- **전투 준비:** **이미 구현된 긴 전투 파노라마를 자르거나 늘리지 않는다.** 중앙 몬스터, 보스 크기 규칙 유지. 높이 감소 시 파노라마·문법 정보·`다음 전투`/`여기서 저장`을 같은 화면 또는 안전한 내부 스크롤로 접근 가능하게 한다.
- **상점·보상:** 상품·보상 카드 개수, 가격, 클릭 가능성 그대로. 상품 내부 스크롤은 허용하지만 **구매/선택/건너뛰기/다음 단계**를 누를 수 있어야 한다. 페이지 전환 시 상품 순서/재고를 다시 만들면 안 된다.
- **결과·기록·사전·설정:** 모달 헤더/닫기 버튼과 내용 스크롤 유지. 최상위 모달이 주소창이나 iPhone 안전영역 밖으로 나가지 않아야 한다.
- **공격 연출:** 실제 카드·점수 위치를 확대/축소 없이 추적, `viewport` 이벤트에 맞춰 고스트·룬 빛·점수 오버레이를 위치 보정. 이미 확정된 공격이 반복 적용되거나 숨겨진 대화상자 뒤로 가면 안 된다.

## 5. 진입·전체화면 및 외부 앱 링크: 사용자에게는 단순하게

### URL과 QR
- 현재 정식 URL `https://yeomt.github.io/grammardealer/`와 QR은 **그대로**. `#lobby`, `#game` 등 기존 라우트, 신규 원정/저장 불러오기 흐름과 충돌 금지.
- 출발 경로(CAMERA / Kakao / Instagram / 문자 / Safari / Chrome)를 정확한 권한 없이 알아내는 로직에 의존하지 않는다. User-Agent는 안내를 다듬는 정도에만 사용하고 **기능 탐지 우선**.

### 사용자가 한번 누르는 시작 흐름
1. 진입 시 플레이는 바로 가능. 방해되는 필수 모달이나 설치 안내를 억지로 띄우지 않는다.
2. 세로 화면이면 기존의 가로 안내를 보여주되 '가로로 플레이'를 권장하고 **'현재 방향에서 계속'** 경로 유지. 회전 불가 환경에서 영구 잠금 금지.
3. 가로 화면에서 게임 시작/전체화면 버튼을 누르면 `requestFullscreen` 지원 여부를 동기적으로 확인하고 1회 요청; 성공 시 `orientation.lock('landscape')` 시도; 가로 방향만 가능하더라도 정상 플레이 허용. 이미 fullscreen이면 중복 요청 없음.
4. API가 없거나 거절되면 **주소창 있는 화면에서도 높이 맞춤으로 바로 플레이**. 짧은 안내(예: “이 브라우저에서는 전체화면이 제한됩니다. 가로로 플레이하거나 일반 브라우저로 열어 보세요.”)와 `현재 화면에서 계속` 제공. 같은 세션에서 매번 팝업하지 않는다.
5. 전체화면에서 나올 때(사용자 종료/앱 전환/OS 스와이프)도 그 즉시 가용 높이 갱신. 게임 상태, 조합대 카드, 손패 페이지, 룬, 사운드 재설정 금지.

### 외부 브라우저 대안
- 인앱 브라우저에서 전체화면이 막히면 **현재 인앱 화면에서도 계속 플레이 가능**해야 함. 외부 브라우저 이용은 선택 안내만. 앱마다 지원하지 않는 'Safari 강제 열기' 버튼·`window.open()` 가짜 약속 금지.
- `공식 링크 복사`와 OS/앱의 `브라우저에서 열기` 메뉴를 간결하게 안내한다. 외부 브라우저 전환 시 **IndexedDB/localStorage와 저장 상태가 자동 공유되지 않을 수 있음**을 정확히 표시. 복사한 URL만으로 같은 원정이 이어진다고 단정하지 않는다.
- 기기별 UI의 정확한 메뉴 명칭은 매번 바뀔 수 있으므로 확정되지 않은 화면 단계를 하드코딩하지 않는다.

## 6. PWA — 반복 사용자에게만, 첫 접속에 영향 없이

### 필수
- `public/manifest.webmanifest` 등의 manifest + 아이콘을 추가한다. `start_url`, `scope`, `id`는 **GitHub Pages `/grammardealer/` 하위 경로 기준**으로 선언하며 `#lobby` 진입과 충돌 없이 확인한다. `display: "standalone"`을 **기본안**으로 제안하고, 실제 Android 전체화면 요구가 강하면 별도 표시 모드 선택을 검증 후 적용할 것. `orientation: "landscape"`는 **선호 설정이지 OS 강제 잠금이 아님**을 명시한다.
- `index.html`에 manifest 연결, `theme-color`, iOS `apple-mobile-web-app-capable`/타이틀/상태 바 설정을 적용할 때 실제 지원 환경을 확인한다. 아이콘은 **기존 사용자 제작 게임 에셋에서 새로 최적화한 원본 이미지**, 출처가 불분명한 웹 폰트나 외부 이미지를 끌어오지 않는다.
- 설치된 상태에서도 `fullscreenElement`가 null일 수 있으므로 **PWA 표시 모드와 Fullscreen API 상태를 별도 판단**한다. 현재 게임 상단에 있는 버튼은 앱 표시 상태에 따라 오해 없이 표현.
- 설치 강요 금지. Android의 `beforeinstallprompt` 지원 시에만 사용자가 요청한 설치 동작을 연결할 수 있다. iOS에는 설치 버튼 대신 홈 화면 추가를 설명하는 간단한 안내를 선택적으로 제공한다. 설치되지 않았다고 게임 기능 제한 금지.
- **서비스 워커/오프라인 모드 미도입.** GitHub Pages 배포가 새 버전인데 구버전 JS를 캐시한 채 실행되는 불일치를 피한다. 필요한 경우 후속 릴리스에서 별도 캐시 무효화 설계로 검토.

### 저장소 차이 고지
- 사파리 탭, 카카오톡 내장 브라우저, 인스타그램 내장 브라우저, 홈 화면 앱은 저장 공간이 서로 다를 수 있다. 동일 링크는 동일 저장을 보장하지 않는다. 기존 내보내기/불러오기 기능이 있다면 그 정상 작동을 검증한다. 미구현인 저장 동기화를 만들어냈다고 주장하거나 원정 복사를 강제하지 않는다.

## 7. 절대 유지해야 할 게임플레이·성능 조건

- **모바일 8열 조합대와 스크롤 조작**: 정상 높이에서 카드 글씨 가독성·형태 선택 그대로; 1/7/8/9/16/24장 배치 확인. 주소창 줄어든다고 카드 DOM을 교체해 무작위로 재정렬하거나 존재하지 않는 카드 생성 금지.
- **손패 페이지**: 선택된 카드/버리기 예약이 페이지 변경·뷰포트 변화에 보존되고, 실제 손패가 바뀔 때만 적절히 갱신. 공격 확정/버리기 클릭 중복 금지.
- **룬·보스 기믹**: 현재 룬 열의 발동 순서 유지. `보스 보호막/HP 1 잠금/빙결핵/상태` 등 핵심 정보의 읽을 수 있는 경로 보장.
- **전투 연출**: `attackLayer`, 점수 오버레이, 몬스터 피격 좌표가 주소창 변화와 fullscreen 입출입에서 어긋나지 않음. 보스 크기와 파노라마 배경/그라데이션 변경 금지.
- **오디오**: 기존 WebAudio의 사용자 터치 시작, 앱 복귀/중단 재개, 현재 BGM 재생 위치/전환 원칙 유지. `atlas:viewport`를 이유로 새 BGM source 반복 생성 금지. 재생 성공을 실기기 청취 없이 단정 금지.
- **리소스·안정성**: ResizeObserver 이벤트 루프·중복 모달·해제되지 않는 핸들러·무한 재시도·빈 화면 방지. 잦은 뷰포트 변화에도 DOM을 통째로 다시 만들지 않는다. 불필요한 재flow/레이아웃 점프 제거.

7. 단위+짧은 브라우저 회귀검사, 실제 지원 가능 기기만 실기기 점검, `npm test`, `npm run build`, 변경 파일/결과/미확인 항목 보고. 별도 승인 없는 main 배포 금지.

## 9. 핵심 인수 조건 (AC) — 각 조건 PASS / FAIL / NOT RUN 보고

### 접속·전체화면·PWA (AC01–AC10)
- **AC01** 공식 주소/QR/카카오톡·인스타 링크가 같은 기존 게임 URL로 연결, 미설치 상태에서 바로 플레이 가능.
- **AC02** 지원 브라우저의 실제 사용자 탭 1회로 requestFullscreen 정상 진입. 지원되면 가로 잠금 요청, 실패는 독립적 처리.
- **AC03** Fullscreen API 미지원/거부 시 정상 가로 게임 화면으로 진행. 불필요한 재시도 루프·차단 모달 없음.
- **AC04** 전체화면 진입과 종료 후 카드·룬·점수·스크롤 위치·사운드 상태가 보존됨.
- **AC05** 세로 안내는 현재 방향에서 계속 기능을 보존하며 실제 회전 후 사라짐. 키보드가 열렸다는 이유로 회전 모달이 반복되지 않음.
- **AC06** QR/카톡/인스타 첫 접속 시 PWA 설치를 강요하지 않으며, 외부 브라우저 열기는 대안으로만 제공.
- **AC07** `주소 복사`가 실제 공식 URL을 복사하고(보안·권한 실패 시 수동 선택 경로), 브라우저 이동 시 저장 비공유 가능성을 안내.
- **AC08** PWA manifest/아이콘/시작 URL/Scope가 `/grammardealer/`에서 404 없이 로드됨.
- **AC09** 설치형 PWA와 탭 모드를 구분해 UI 처리. `standalone`을 실제 시스템 fullscreen으로 오판하지 않음.
- **AC10** PWA 추가 후에도 버전 캐시·오프라인 오작동 없이 기존 GitHub Pages 페이지를 사용. SW 미도입/불필요한 권한 없음.

### 가용 높이와 화면별 잘림 (AC11–AC24)
- **AC11** 초기 주소창 노출 시 화면 유효 높이로 UI가 배치되어 손패·공격·턴 넘기기 접근 가능.
- **AC12** 주소창이 확장/수축할 때 뷰포트를 다시 측정하고 잘림 없이 재배치. 배경/몬스터가 우선 유연하게 공간을 반환함.
- **AC13** Fullscreen on/off, 가로↔세로, 앱 배경화/복귀, iPad 화면 크기 변경 시 헤더·조합대·손패가 일관된 위치로 복원됨.
- **AC14** iPhone 노치/홈 인디케이터, Android 시스템 바 및 가로 safe-area에 버튼이 가리지 않음; 여백 이중 계산 없음.
- **AC15** 8열 조합대 1·7·8·9·16·24장 모두 접근 가능, 내부 스크롤·위아래 조작 정상. 단어·형태를 읽고 수정 가능.
- **AC16** 손패 페이지 이동 후 버리기 선택·체크 표시·전체 수량·드래그가 보존됨.
- **AC17** 우측 룬 열에 스크롤 접근 가능, 실제 발동 순서와 표시 일치.
- **AC18** HP·보스 기믹·목표 문법을 읽을 수 있고, 정보창 때문에 중앙 몬스터 전체가 영구히 사라지지 않음.
- **AC19** 로비 프로필/새 원정/불러오기 버튼이 접근 가능, 키보드 열린 상태에서 입력과 확정 정상.
- **AC20** 지역 입장·전투 준비 파노라마 원본 비율과 몬스터/보스 크기 보존, `다음 전투`/`저장` 도달 가능.
- **AC21** 상점 재고·상품/보상 선택·건너뛰기·다음 버튼이 숨지 않고 모두 도달 가능.
- **AC22** 사전·설정·형태 선택·저장 모달이 화면 안에서 열리고, 닫기/확인 가능, 내부 스크롤·슬라이더 정상.
- **AC23** **매우 낮은 화면**이라 한 화면 동시 노출이 불가능하면, 조작 가능한 명확한 내부/페이지 스크롤로 전부 도달 가능. 필수 조작이 화면 밖에 영구 고립되지 않음.
- **AC24** PC(1280×720, 1920×1080)에서 기존 화면 구성, 모바일이 아닌 일반 브라우저의 수동 확대/휠 조작, 키보드 접근성이 회귀하지 않음.

### 입력·오디오·성능·정합성 (AC25–AC32)
- **AC25** 화면 높이 변화 중 카드 1회 탭/드래그가 2회 커밋되지 않으며 카드 소실·유령 카드 잔류가 없음.
- **AC26** 클릭·드래그·형태 변경·선택 후 버리기·턴 넘기기·공격을 반복해도 제스처 잠금이 남지 않음.
- **AC27** 공격 중 주소창/전체화면 변동으로 점수 오버레이·타격 위치가 어긋나지 않으며 중복 피해가 없음.
- **AC28** 화면 복귀 후 오디오 재개 경로를 유지하고, 단순 resize 때문에 BGM이 재시작되거나 겹치지 않음.
- **AC29** resize/scroll 이벤트 과다 발화에도 페이지가 깜박이거나 무한 layout thrashing/ResizeObserver 오류를 일으키지 않음.
- **AC30** 저장·불러오기·시드·보상·문법·데미지 등 엔진 결과는 이전 버전과 동일한 시나리오에서 변하지 않음.
- **AC31** `npm test`, `npm run build` PASS. 변경 영역에 맞는 브라우저 검증 PASS; 실행 불가 항목은 정확히 NOT RUN.
- **AC32** 최종 보고에 변경 파일, 화면별 검증, 지원/미지원 전체화면 동작, 실제 기기 사용 여부, 주요 잔여 제약, PR 링크를 구분해서 기재. 병합·배포는 사용자의 별도 승인 이후.

## 10. 짧고 결정적인 검증 매트릭스

| 환경 | 테스트 경로 | 핵심 확인 |
|---|---|---|
| 학교 **iPad** Safari 가로 | QR/직접 URL | 주소창 표시/접힘, 준비·전투·모달·상점, 화면 공간 및 손패/공격, 가능할 때 전체화면 |
| 학교 Android 태블릿 Chrome | QR/직접 URL | 사용자 제스처 fullscreen+orientation lock(지원 시), 시스템 내비/화면 회전/복귀 |
| **iPhone** Safari 가로 | QR/직접 URL | fullscreen 불가 시 바로 정상 플레이, 주소창 변화·노치·홈바와 8열 조합대, 선택적 홈 화면 설치 |
| Android 스마트폰 Chrome | QR/카톡 링크 | 주소창 변화 및 뒤로/전환, 드래그·버리기, fullscreen 성공/실패 fallback |
| 카카오톡·인스타 인앱 | 공유 링크 | 인앱에서도 차단 없이 플레이, 외부 브라우저 안내·저장 비공유 고지 |
| PC Chrome | 직접 URL | 기존 1280×720/1920×1080 UI 보존, fullscreen·키보드·마우스 조작 |

**자동 테스트(최소):** Playwright에서 가로 viewport `844×390`, `915×412`, `1024×768`, `1194×834`, `1280×720` 등을 사용한다. **주소창에 의해 보이는 높이가 40~100px 줄었다가 회복되는 상황**과 짧은 높이 300~340px를 *테스트용 환경에서* 계측/시뮬레이션한다. 실제 브라우저 주소창 동작·iOS Safari API·카톡/인스타 인앱 제한은 에뮬레이션만으로 PASS 처리하지 않는다. 중요한 화면 2~3곳의 1~2장 캡처와 조작 경로 검사로 제한한다. 모든 스테이지 50전투 완주·대량 스크린샷·방대한 성능 실험은 요구하지 않는다.

**실기기 테스트 결과는 별도 기입:** 실제 iPad/iPhone/Android 장치 접근이 없다면 **NOT RUN**. browser emulation 성공은 '에뮬레이터 검증'으로 표시. 지원하지 않는 전체화면을 '전체화면 성공'으로 허위 보고 금지.

## 11. Codex 최종 인계 형식

1. 기준/완료 SHA·작업 브랜치·PR 및 변경 파일 목록.
2. P0 화면 잘림 해결 방식(실제 높이 계측과 화면별 영역 분배) 및 한계.
3. Fullscreen 지원/미지원별 동작, PWA 설치/미설치 동작과 공식 링크 유지 증빙.
4. `AC01~AC32` PASS/FAIL/NOT RUN 간단 표, 실패/제약 조건을 구체적으로 보고.
5. `npm test`, `npm run build`, 짧은 관련 브라우저 검사 결과(실제 실행한 것만).
6. 기존 룰/점수/카드/룬/음악/이미지의 불필요한 변경 없음 확인.
7. **main 병합·배포하지 않고 PR 상태로 인계.** 사용자의 다음 승인 대기.
