## 2. 정적·단위 검증

현재 프로젝트의 실제 `npm test`, 데이터 검증, build 스크립트를 확인해 실행한다. 새 룬 종류/레벨/ID, HP 범위, 골렘260×3, 버전별 registry·manifest·save, 일반/고급 조기 후보, 희귀0 보장, 룬표시+점수 일치를 검사한다.

복합용법의 룬 증거와 기본 채점 증거를 따로 assertion한다. 현재완료진행에서 석영·백금이 발동한 사실이 기존완료×진행 배율을 되살린 것이 아닌지 확인한다. 룬을 모두 빼면 요청하지 않은 기본 문법 점수 차이가 없는지 대조한다.

추첨 맥락은 최종 결과에 희귀가 우연히 없었다는 검증만으로 부족하다. 후보 필터/가중치/등급/선택ID/최대레벨/초회예외와 출처를 함께 검증한다.

## 3. 분포 검증

고정한 seed 목록으로 실제 룬 선택기 반복 시험을 한다. **검증 제안**: 각 기본 맥락에서 순수 룬 선택20,000회 정도로 등급별 비율을 확인하고, 실제 혼합 보상 생성도 별도로 여러 seed에서 확인한다. 이 표본수는 성능에 맞춰 조정할 수 있으나 변경과 이유를 보고한다.

표에는 eligible pool 구성, 등급별 후보수, 빈/최대레벨 제외, 기대 가중치, 실제 출현수/비율, 일반/고급 Stage1 등장 여부, 희귀 일반전0, 각 희귀의 노출을 포함한다. 3%는 전체 보상중 희귀 비율이 아니라 룬 칸의 조건부 등급 비율이다. 새 rarity 천장이나 희귀확정으로 PASS를 만들지 않는다.

## 4. 브라우저 기능·레이아웃

다음 순서로 검사한다.

1. 기존 PC 화면과 새 낮은-height 화면 비교.
2. tablet 가로/세로, fullscreen 전/후, 주소창 보여짐/숨김.
3. phone 세로/가로, keyboard 열림/닫힘, 안전영역, 분할창.
4. 손패0/1/6/10/14, 조합대0/1/8/16, 기존/신규4룬, 장문카드/큰점수.
5. 사전 검색, 형태선택, 드래그, 교환, 룬정렬, 저장/로드, 보상, 상점, 로비.
6. 효과중 회전/전체화면/키보드/백그라운드/모달, 마지막 턴 보스격파.

`scrollWidth<=clientWidth` 같은 수치와 **필수요소 boundingClientRect의 가시영역 포함/클릭 가능 여부**를 같이 본다. overflow:hidden으로 숫자만 통과시키지 않는다. tablet은 모든카드동시식별을 우선한다. phone/Split 예외 paging을 썼다면 화면·상태·이유를 기록한다.

Desktop Chromium/Firefox/WebKit 검사는 각 설치본 실제버전을 기록한다. WebKit자동화가실제iPadSafari를대체하지는않는다. fullscreen mock이 실제 API 성공을 증명하지도 않는다. 제공되지 않은 브라우저/실기기는NOT RUN이다.

## 5. Game Feel 시각 검수

문법/룬당 정확한 사본의 탄성반응과 텍스트/숫자 타이밍을 녹화한다. 보스 차단과 실제 점수효과를 구분한다. 동일 문장을효과전/후·speed1/1.5/2·effectsOff·reducedMotion에서 비교한다.

저콤보1~2, 중콤보3~7, 고콤보8~14+를 비교하고, 희귀Lv.3과 일반Lv.1이 같아보이지 않는지 본다. 반대로 고콤보/희귀가 글자를 지우거나 다음문구를 읽지못하게 가리지 않는지도 본다. 디스플레이 캡처/동영상 파일명은 문장/상태/기기별로 고유해야 한다.

## 6. 성능·누수·멱등성

같은 합법적 지정덱 상태에서 모션켬/끔 baseline을 비교한다. 측정 시작/끝과 hidden 구간을 구분하고 p50/p95 프레임간격, 50/100ms초과, 입력 지연, 활성입자/DOM수,30회공격후 잔존FX를 기록한다. 정상 FPS목표를 충족 못하면 이유와 완화안을 보고하며 임의로 게임 규칙을 바꾸지 않는다.

점수·HP·회복·예견·골렘부위·보상은 각각 한 번만 commit되는지 assert한다. 프리젠테이션이 종료되지 않아도 기존watchdog 경로가 뚫려 있어야 한다. fullscreen/resizing 때문에 재시작·저장손실·locked 상태가 남으면 기능 실패다.

## 7. 통합 플레이

### 지정 상태

각 신규 룬과 2~4룬 시너지 덱, 기존유틸리티덱, 신구토파즈동시소유를 Controller/실제 UI에서 검사한다. 지정 상태는 분명히 표시한다. 예상치 못한50만점같은 고점도 숨기지 말고 기초문법/룬/지역/저항을 분리해 기록한다. 고점 때문에 HP를 자동 조정하지 않는다.

### 자연 보상 원정

새0.10.1에서 시작하여 카드/룬/재화/드로우를 조작하지 않은 시도들을 남긴다. Stage2~5 HP구간과 룬 조기획득/아직미발동상태를 확인한다. 후반에 도달한경우 총소모턴과저항전후피해,희귀획득·레벨을 기록한다. 플레이어/자동QA정책/합성원정은 별도 열로 분리한다.

가능하면 신규룬을활용하는자연경로와기존룬중심경로를비교한다. 반복패배로후반에못가면그후반자연검증은NOT RUN이다. 지정 덱으로 대신 PASS로 쓰지 않는다. 모든seed승리나사람승률을자동정책으로보장하지 않는다.
