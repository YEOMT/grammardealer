# 0.10.1 작업 완료 후 이어서 적용할 UI 후속 지시

첨부한 「Syntax_Atlas_0.10.1_UI_Followup_Handoff.zip」을 현재 0.10.1 결과에 이어 적용하라.
이 패키지는 기존 개발 지시 전체를 대체하는 소스가 아니라, 최신 UI 변경 사항의 우선 명세다.

먼저 AGENTS.md, 현재 HEAD/브랜치/미커밋 작업, 기존 PR/병합 여부와 완료된 0.10.1 결과를 확인하라.
기존 작업이 미병합이면 같은 작업 브랜치의 결과를 보존하며 후속 커밋으로 수정하라.
이미 0.10.1이 병합·배포됐으면 최신 main에서 새 UI 패치 브랜치로 이어가며, 공개된 버전을 중복 사용하지 마라.
원래 ZIP의 오래된 소스로 덮어쓰거나 게임을 처음부터 다시 만들지 마라.

본명세, 02_SUPERSESSION_MAP_KO.md, 03_UI_ACCEPTANCE_KO.md, 04_TEST_MATRIX_KO.md를 먼저 읽어라.
충돌하는 UI 요구는 이 후속 명세가 우선한다. 기존 HP·룬·보상·게임 규칙 변경은 그대로 보존한다.

1. 조합대의 가독성을 최우선으로 한다. 사용자가 만족한 기존 손패 카드의 너비와 영어 글자 크기를 기준으로,
   같은 viewport에서 조합대의 같은 단어/선택형을 동일하게 렌더링하라.
   카드가 적다고 가로로 늘리지 말고, 카드가 많다고 조합대만 좁히거나 영어를 작게 하지 마라.
2. 문장은 1줄에서 2줄, 필요하면 3줄 이상으로 이어진다.
   2줄까지는 여백 등 세로 공간만 압축하고, 3줄부터 세로를 한 단계 더 압축하라.
   글자와 카드 전체의 scaleY/전역 축소를 사용하지 말고, 버튼·상태가 겹치지 않는 최소높이를 지켜라.
   조합대를 두 줄로 제한하거나 페이지/스크롤/말줄임으로 문장 카드를 숨기지 마라.
3. 헤더는 왼쪽 SYNTAX ATLAS, 화면 정중앙 스테이지 단계·이름,
   오른쪽 [전체화면] [로비] 순서로 배치하라. 전체화면은 로비 바로 왼쪽이다.
4. 좌우의 도감·사전·저장·내 덱·룬 정렬 등 텍스트·버튼·클릭 영역이 패널 밖으로 나오지 않게 하라.
   현재 구성을 먼저 보존하고, 좁은 화면의 국소적 배치만 보정하라.
   overflow:hidden으로 가리거나 핵심 버튼을 깊은 하위 메뉴로 숨기는 방식은 사용하지 마라.
5. 휴대전화·태블릿은 가로 플레이만 제공하라. 명시적 입력에서 전체화면/가로잠금을 요청하고,
   미지원·거절 시에는 직접 회전 안내를 표시하라. 기기가 가로면 API가 실패해도 플레이 가능해야 한다.
   실제 기기 방향과 검색 키보드에 의한 visual viewport 축소를 혼동하지 마라.
   세로 안내가 팝업/키보드 입력까지 안전하게 막고, 복귀 후 같은 문장/게임 상태를 보존해야 한다.
6. 몬스터·배경에 넓은 공간을 강제 예약하지 마라. 현재 화면을 크게 바꾸지 말고,
   조합대 위의 작은 이미지 교체 여지만 둬라. 전용 원화·이미지 해상도 확정·팔레트 전면개편은 추후다.
7. 기존 또잉 카드 반응, 선명한 콤보 글자, 점진적 글로우·입자와 룬 등급/레벨 효과는 유지하라.
   여러 줄/회전/전체화면에서 정확한 카드 ID와 좌표로 재생하고, layout과 게임 정산을 건드리지 마라.
8. 기존 4형식 토파즈 룬은 유지하고, 새 동명사 룬은 최종 변경명인 자수정 룬으로 통일하라.
   기존 명세의 임시 ‘토파즈·동명사’ 표기를 되살리지 마라.

84개 후속 인수 조건과 기기/행 경계/모달/정산 매트릭스로 실제 구현·회귀검사·빌드를 수행하라.
원래 130조건 중 세로 플레이 등 충돌 항목은 SUPERSEDED로 명시하고 새 조건을 검증하라.
화면 캡처뿐 아니라 카드 너비/글자 크기, 요소 containment, 실제 클릭 가능성도 확인하라.
진행 중 화면을 보지 않고 추정한 원인을 확정 버그라고 쓰지 마라.
실물 iPad/휴대전화와 에뮬레이션, 전체화면 mock과 실제 성공을 구분하라.
미실행은 NOT RUN, 미충족은 FAIL로 보고하고, 지원 크기나 기대값을 바꿔 PASS로 만들지 마라.

단순히 계획만 작성하지 말고 위 범위의 실제 수정과 최종 코드 검증까지 진행하라.
변경 사항·확인한 손패 기준·84조건 결과·남은 한계와 기존/신규 PR을 보고하라.
사용자 승인 없이 main 직접 push·자동 병합·공개 배포를 하지 마라.
