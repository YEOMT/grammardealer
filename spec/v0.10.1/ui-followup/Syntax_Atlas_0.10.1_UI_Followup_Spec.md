# 신텍스 아틀라스 — 0.10.1 UI 후속 수정 명세

**조합대 가독성 최우선 · 손패 동일 너비/글자 · 행별 세로 압축 · 가로 전용 · 패널 넘침 정리**

문서 리비전: UI-FOLLOWUP-1.0 | 작성일: 2026-10-15
대상: 진행 중인 0.10.1 결과에 이어서 적용하는 UI 추가 수정
기준 저장소: `YEOMT/grammardealer`

이 문서는 구현 지시 및 검증 기준이다. 진행 중인 작업의 최신 화면·로컬 소스에 대한 실측 보고서, 게임 구현 결과, 브라우저 테스트 통과 보고서가 아니다. 현재 대화에는 사용자가 보고한 새 화면의 캡처가 첨부되지 않았다. ‘도감·사전 등이 패널 밖으로 튀어나온다’, ‘조합대 카드의 가로 길이가 달라진다’는 사용자의 관찰을 재현 대상으로 사용한다.

## 0. 적용 순서와 작업 인계

### 0.1 정상 진행 중인 작업은 강제 중단하지 않는다

현재 0.10.1 구현·테스트가 정상 진행 중이면 먼저 해당 작업을 완료시키고 최종 보고와 변경 상태를 받는다. 그 결과를 이 후속 작업의 기준으로 사용한다. 취소 후 처음부터 다시 생성하거나 원래 ZIP의 오래된 소스로 되돌리지 않는다.

- **아직 미병합:** 같은 작업 대화와 기존 0.10.1 작업 브랜치에서 후속 커밋으로 수정하고, 기존 PR에 반영한다. 기존 변경이 다른 브랜치에 있으면 먼저 확인하며 무조건 새 main checkout으로 바꾸지 않는다.
- **이미 병합·배포됨:** 실제 최신 main에서 별도 UI 수정 브랜치를 만든다. 이미 배포한 0.10.1을 덮어 재사용하지 않고 0.10.2 등 다음 패치 버전을 프로젝트의 기존 방식대로 정한다. 이 문서 파일명의 0.10.1은 원래 작업과의 연관 표기이지, 이미 배포한 버전을 재사용하라는 명령이 아니다.
- **실제 오류나 진행 중단 상태:** 완료 지점·미커밋 파일·마지막 실행 명령을 먼저 확보한다. 본 문서는 정상적으로 진행되는 작업의 강제 종료를 요청하지 않는다.

UI를 고친 뒤에는 최종 변경본에서 관련 테스트를 재실행한다. 앞선 실행 결과를 새 UI의 검증으로 재사용하지 않는다. 사용자의 별도 승인 없이 main 병합·공개 배포·기존 PR 종료를 하지 않는다.

### 0.2 우선순위와 명세의 충돌

최신 사용자 지시 → 이 후속 명세 → 충돌하지 않는 기존 0.10.1 명세 순으로 적용한다.

기존 본명세 8.2의 ‘모바일 세로에서도 플레이를 막지 않는다’, ‘작은 화면에서 조합대 페이지 전환을 허용한다’는 규칙은 교체한다. 앞선 제안의 ‘조합대는 최대 두 줄’, ‘큰 몬스터 무대에 약 1/4 화면을 배정한다’, ‘좌우 패널을 상단으로 전면 이동한다’도 이번의 필수 요구가 아니다.

원래 130개 인수 조건 중 충돌하는 항목은 삭제나 임의 PASS 처리 대신 **SUPERSEDED — UI-FOLLOWUP-1.0의 해당 조건으로 대체**라고 추적한다. 충돌하지 않는 HP·룬·게임 규칙 검증은 그대로 유지한다. 후속 84개 검증 항목은 원래 항목과 일부 겹치므로 합계 테스트 수를 단순 합산하지 않는다.

## 1. 이번 수정의 목표와 비목표

### 1.1 최종 목표

**지금까지 만족했던 손패와 화면 구성을 유지하면서, 조합대의 문장이 길어져도 단어가 읽히고 모든 핵심 조작이 실제 화면 안에 안정적으로 배치되도록 한다.**

우선순위는 다음과 같다.

1. 조합대의 단어, 선택된 형태, 문장 순서와 카드 조작의 가독성.
2. 손패 가독성, 공격/준비/교환, 적 HP와 공략 상태, 남은 턴.
3. 사전·도감·저장·내 덱 접근, 룬 이름/레벨/순서.
4. 선명한 콤보 문구·숫자와 이미 요청한 탄성/글로우/파티클.
5. 몬스터 그림을 나중에 넣을 여지와 현재 지역 테마.

### 1.2 이번에 새로 하지 않을 것

새 몬스터/배경 원화 제작, 고해상도 이미지 규격 확정, 넓은 전투 무대 신설, 전면적인 스테이지 팔레트 리디자인, 신규 배경 연출, 메뉴 기능 삭제, 새 힌트/자동 정답, 게임 난이도/점수/루프 변경은 하지 않는다.

기존 스테이지 색감은 유지한다. 각 테마에서 텍스트·버튼·경계의 대비를 확인하고 필요한 국소적 가독성 보정만 한다. 전체 색상 설계와 몬스터/배경의 최종 배치는 추후 논의 항목이다.

## 2. 진행 중인 작업을 보존하는 기준선

작업 전 현재 브랜치, HEAD, 미커밋 상태, 기존 PR/병합 여부, 0.10.1에서 실제 완료된 범위를 기록한다. 기존 ZIP은 기능 계약이며 현재 소스를 대체하는 배포본이 아니다.

사용자가 만족한 **기존 손패 카드**를 측정 기준으로 삼는다. 진행 중인 UI 변경이 손패까지 이미 왜곡했다면 승인된 이전 손패 표현과 비교하여 기준을 확인한다. 문제 있는 조합대 규격을 손패에 적용하여 둘을 ‘똑같이’ 만드는 것은 실패다.

다음 값은 화면 프로필별로 기준선에 기록한다: 카드 외곽 너비, 기본/긴 단어의 글자 크기, 헤더/단어/형태선택/상태 영역, 손패 높이, 조합대 가용 폭, 패널 폭, 버튼 크기. 사용자 제공 캡처가 없으면 소스와 기존 결과에서 선택한 기준을 보고한다. 확인하지 못한 값은 임의로 ‘사용자가 승인한 픽셀’이라고 표시하지 않는다.

## 3. 손패와 조합대의 공통 카드 계약

### 3.1 바뀌지 않는 가로 규격

같은 viewport·화면 프로필·동일 단어/동일 선택형에서 다음을 만족한다.

- 조합대 카드의 **외곽 가로 너비 = 기준 손패 카드 가로 너비**.
- 영어 단어의 font-family, font-size, font-weight, 가로 자간, 긴 단어 처리 규칙을 공통으로 사용한다.
- 카드 수가 1장이어도 남는 조합대 폭을 채우려고 확대하지 않는다.
- 2줄·3줄·그 이상이 되어도 조합대 카드만 좁히거나 글자를 작게 만들지 않는다.
- 카드의 선택·드래그·호버·콤보 연출이 끝나면 같은 규격으로 돌아온다.
- 기기별 화면 프로필은 달라질 수 있다. 그러나 같은 프로필에서 카드 개수만 바뀌었다는 이유로 카드 너비나 영어 글자 크기를 바꾸지 않는다.

공통 규격 변수를 사용한다. 예: `--play-card-width`, `--play-card-word-size`, `--play-card-word-line-height`. 실제 이름은 현재 구조를 따른다. 조합대 item은 `flex-grow:0`, `flex-shrink:0`에 해당하는 동작을 보장한다. `1fr` 셀을 쓰더라도 카드 자체가 셀 너비로 늘어나지 않는다.

### 3.2 허용하는 세로 변화

조합대 카드의 높이는 손패보다 줄일 수 있다. **상하 여백·단어 위아래 margin·영역 사이 간격**부터 줄인다. 그 과정에서도 영어 단어의 글자 크기와 줄 높이는 바꾸지 않는다.

`scaleY()`로 카드 전체나 글자 자체를 찌그러뜨리지 않는다. 넓이·높이를 함께 줄이는 전역 scale/zoom도 조합대 문제의 해결책으로 사용하지 않는다.

품사, 점수, 연마/겸용 표시, 봉인/빙정 등의 핵심 상태와 형태선택 접근을 보존한다. 같은 한 줄에 정보를 재배치할 수는 있지만, 압축을 이유로 버튼을 잘라 없애거나 상태를 숨기지 않는다. 기존 카드의 기본 시각 구성을 유지한다.

### 3.3 긴 단어와 형태 변경

장문 단어를 위한 기존 공통 fit 규칙이 있다면 손패와 조합대에서 동일하게 사용한다. 예를 들어 `give → giving`, `will → would`, `can → could`를 바꾸었을 때 두 위치가 같은 렌더링 규칙을 따른다. 카드 수와 줄 수는 fit 계산에 넣지 않는다.

폼 메뉴를 열었다는 이유로 카드 외곽 너비가 달라지면 안 된다. 긴 영어를 임의의 중간 줄바꿈이나 말줄임표로 잘라서 문장을 이해할 수 없게 만들지 않는다.

## 4. 줄 수에 따른 조합대 배치

### 4.1 한 줄 → 두 줄 → 세 줄 이상

| 실제 줄 수 | 카드 너비·영어 글자 | 카드 높이 | 원칙 |
|---|---|---|---|
| 1줄 | 손패와 동일 | 기본 또는 가벼운 압축 | 소수 카드를 가로로 키우지 않음 |
| 2줄 | 손패와 동일 | 필요한 만큼 세로 여백 압축 | 두 번째 줄까지 같은 크기의 단어가 계속 이어짐 |
| 3줄 이상 | 손패와 동일 | 한 단계 더 세로 압축 | 가로/글자 축소 없이 영역 간격과 높이만 절제 |

**두 줄이 상한이 아니다.** 실제 폭과 최대16장에 따라 세 줄 이상을 허용한다. 단, 세로 압축은 정보가 겹치기 전의 최소 높이까지만 가능하다.

### 4.2 행 수 계산

조합대의 실제 안쪽 가용 폭 `W`, 공통 카드 외곽 너비 `C`, 카드 간격 `g`를 기준으로, 균일 카드일 때 한 행의 수용량은 `floor((W+g)/(C+g))`이다. 카드 수 `N`의 필요한 행 수는 수용량이1이상일 때 `ceil(N/columns)`이다. 카드가0장인 경우 빈 조합대 상태를 사용한다.

이 계산은 구현 지침이며 브라우저 실측으로 검증한다. 드래그 ghost·삽입 미리보기·탄성 애니메이션의 변형된 box는 실카드 수와 행 수에 넣지 않는다. 실제 DOM 읽기 순서는 항상 sentenceSlots 순서와 일치해야 한다.

### 4.3 조합대 높이와 세로 예산

해당 화면 프로필에서 **최대16장·최대 손패 상태**를 먼저 시험하여 조합대 가용 높이와 압축 단계를 정한다. 여유 있는 기기에는 처음부터 필요한 행 영역을 안정적으로 확보한다. 카드 한 장을 추가할 때마다 공격 버튼·손패가 화면 밖으로 밀리면 안 된다.

같은 화면에서 실제 행 수에 따라 내부 카드 높이·행 간격을 바꿀 수 있으나, 헤더/주요 조작/손패의 기준 위치는 되도록 안정적으로 유지한다. 행 전환을 애니메이션하며 매 프레임 높이를 측정·수정하는 반복 루프는 금지한다.

세로 예산이 부족할 때의 순서는 **불필요한 여백 축소 → 반복 설명 간결화 → 좁은 화면에서 패널의 국소적 재배치 → 조합대 세로 압축**이다. 몬스터 무대에 고정 비율을 먼저 주고 남은 공간에 문장을 억지로 넣지 않는다.

압축 후 최소높이는 헤더·영어 단어·필요 상태·형태 조작에 필요한 실제 높이를 합하여 계산한다. 숫자 하나를 정해 모든 기기에 강제하지 않는다.

### 4.4 문장 순서와 드래그

각 행은 왼쪽에서 오른쪽으로 읽고, 다음 행은 앞 행의 마지막 카드 다음에 이어진다. 행 시작점이 일관되도록 배치한다. 시각적 줄바꿈은 문법적 절 경계가 아니므로 절 표시/괄호/보너스를 자동 추가하지 않는다.

여러 줄의 삽입 위치 계산은 x좌표만이 아니라 실제 행의 y영역도 사용한다. 위·아래 행 사이 이동, 행 끝과 다음 행 시작, 마지막 행 빈칸, 원위치 취소, 맞교환/삭제/되돌리기를 검증한다. 시각 압축과 관계없이 같은 instanceId는 하나의 slot에만 존재해야 한다.

### 4.5 페이지/잘림 금지와 작은 화면 한계

이번 조합대는 **문장 앞부분을 다른 페이지로 숨기는 방식을 사용하지 않는다.** 가로 스크롤, 세로 스크롤, 말줄임표로 문장 카드를 감추거나 `overflow:hidden`으로 잘린 카드가 없는 척하지 않는다.

작은 화면에서 모든 요구가 물리적으로 양립하지 않는 경우, 읽기 크기와 핵심 입력을 먼저 보존하고 정확한 viewport/카드 수/부족한 높이를 보고한다. 특히 극소형 가로창의 미충족을 일반 태블릿의 성공으로 대체하지 않는다. 미지원 최소 가용 크기를 새로 확정해야 한다면 **추가 승인 필요** 항목으로 남기며, 지원 크기를 임의로 높여 PASS 수를 만들지 않는다.

손패도 기존 읽기 규격을 보존한다. 이미 명시적 손패 페이지가 구현되었다면 작은 화면의 유예 항목으로 별도 기록한다. 그것을 조합대까지 확대하지 않는다. PC/태블릿에서는 최대 손패의 동시 식별을 우선한다.

## 5. 헤더 배치

**왼쪽: `SYNTAX ATLAS` / 화면 전체의 중앙: `STAGE 10-1 · 별의 회랑` / 오른쪽: `[전체화면] [로비]`**

전체화면 버튼은 항상 로비 바로 왼쪽이다. 중앙은 좌우 컨트롤을 제외한 남은 공간의 중심이 아니라, 게임 화면 전체의 중심이다.

좌우 너비가 달라져도 중앙 그룹이 움직이지 않는 구조를 사용한다. 예: 좌우 균형 트랙 또는 중앙 독립 배치와 좌우 충돌 방지 폭. `전체화면 종료`처럼 라벨이 바뀌는 상태, 가장 긴 스테이지명, 폰트 로딩 전후를 시험한다.

좁은 화면에서는 게임명은 작게, 스테이지명/번호는 필요한 경우 같은 중앙 그룹 안의 두 줄로 정리한다. 우측 버튼의 탭 영역을 줄여 해결하지 않는다. 아이콘형 전체화면 컨트롤을 사용한다면 상태를 설명하는 accessible name과 툴팁/상세를 제공하며 위치는 유지한다.

## 6. 좌우 패널·도감·사전·저장 정돈

### 6.1 이번에 반드시 재현·수정할 결함 유형

도감·사전 등의 버튼, 글자, 아이콘, 포커스 테두리와 클릭 영역이 패널 밖으로 튀어나오거나 다른 영역과 겹치는지 조사한다. 특히 다음을 검사한다.

- 패널 안의 두 열 버튼에서 긴 한글 라벨이 이웃 칸을 침범하는 경우.
- 버튼의 padding/min-width가 grid/flex의 실제 폭보다 큰 경우.
- 세로 공간이 부족한데 고정 min-height/자동 margin 때문에 하단 버튼이 밀려나는 경우.
- 룬 정렬 컨트롤, 설명, 긴 이름과 레벨 표시가 패널 밖으로 나가는 경우.
- 투명 오버레이/FX가 사전·도감·저장 버튼 위에서 포인터를 가로채는 경우.
- 다른 스테이지, 봉인/빙정/보스 안내가 추가될 때만 넘치는 경우.

작은 빛 번짐 자체와 실제 텍스트/버튼 넘침을 구분한다. 장식 때문에 페이지 스크롤이 생기면 안 되며, 포커스 표시는 잘라 숨기지 않는다.

### 6.2 수정 원칙

현재 배치와 메뉴의 이름/기능을 먼저 보존한다. 도감과 사전을 합치거나 없애지 않고, 저장/불러오기와 내 덱 접근도 유지한다. 패널을 맞춘다며 이 기능들을 깊은 하위 메뉴로 옮기는 것을 기본 해법으로 쓰지 않는다.

폭이 좁아지는 브레이크포인트에서 국소적으로 2열→1열 또는 명시적인 작은 기능 바를 사용할 수 있다. 다만 사전·도감·저장 등 자주 쓰는 기능은 한 번의 선택으로 열려야 하고, PC의 정상 레이아웃을 전면 바꾸지 않는다.

구현 후보: `box-sizing:border-box`, 부모/자식의 `min-width:0`·`min-height:0`, `minmax(0,1fr)`, 실제 버튼 내용에 맞는 열 너비, 줄바꿈 정책, 최소 padding. 무조건 새로운 `!important`를 덧붙이기보다 기존 cascade와 중복 규칙을 정리한다. 이는 CSS 설계 제안이며 실측으로 결과를 확인한다.

라벨은 가능한 한 한 줄로 읽히게 하며 불가피한 두 줄도 패널 안에 완전히 들어오게 한다. 글씨를 지나치게 작게 하거나 핵심 이름을 ‘…’로 잘라 무엇을 여는지 알 수 없게 만들지 않는다.

## 7. 모바일/태블릿 가로 전용과 전체화면

### 7.1 최종 제품 정책

휴대전화·태블릿의 **실제 전투/조립 플레이는 가로만 지원**한다. 세로용 플레이 화면을 별도로 만들지 않는다. 세로 상태는 회전 안내 및 안전한 이동/취소 UI만 제공한다. PC의 창이 세로로 길다는 이유만으로 휴대기기로 판단하지 않는다.

가로로 플레이하기 버튼의 명시적 입력에서 지원되는 경우 전체화면 진입 후 가로 잠금을 요청한다. 브라우저가 잠금을 지원하지 않거나 거절하면 ‘기기를 가로로 돌려 주세요’ 안내로 대체한다. 전체화면이나 방향 잠금이 불가능해도 사용자가 실제로 가로로 돌리면 플레이할 수 있어야 한다. [W01][W02]

모든 브라우저에서 물리적으로 자동 회전된다고 약속하지 않는다. CSS `rotate(90deg)`로 화면 전체를 속여서 방향 지원을 가장하지 않는다. 설치/PWA/서비스 워커를 새 전제로 추가하지 않는다.

### 7.2 방향 판정과 안전

방향 판정은 지원되는 화면 방향 정보와 레이아웃 상태를 조합하되, 가상 키보드로 VisualViewport의 높이만 줄어든 것을 기기 회전으로 오인하지 않는다. `visualViewport.width > height` 하나로 가로 여부를 판단하는 방식은 피한다. [W03]

세로 진입 시 드래그/임시 선택 조작은 안전 취소하고, 확정된 문장/형태/게임 상태는 보존한다. 회전 안내 뒤에서는 클릭·키보드·터치가 전투 명령으로 새어나가지 않아야 한다. HTML dialog 등 최상위 팝업이 열려 있어도 안내가 실제 입력을 통제하는지 확인한다.

공격 연출 중 방향이 바뀌면 기존 단일 정산과 watchdog을 유지한다. 이미 확정된 공격은 기존의 정상 완료 또는 안전한 사후 표시 경로로 **한 번만** 마무리한다. 회전으로 추가 턴/회복/보상/RNG 소비를 만들지 않는다. 가로 복귀 후 편집 화면이 영구 locked 상태로 남지 않는다.

### 7.3 전체화면의 생명주기

모달과 FX를 포함하는 안정된 앱 루트를 사용한다. 화면 재렌더로 루트가 교체되어 전체화면이 반복 해제되지 않도록 한다. 실제 `fullscreenElement`, `fullscreenchange`, Promise 실패를 반영하여 버튼을 갱신한다. 요청 성공 전에 켜짐 상태를 저장하지 않는다. [W02][W05]

일반 가로창에서도 조합대와 버튼이 들어와야 한다. 전체화면 종료 시 새 게임을 시작하거나 드로우를 재실행하지 않는다. API 미지원, iframe 권한 제한, 사용자 거절은 정상적인 fallback 상태로 처리하고 실패 로그를 분리한다.

## 8. 실제 가용 화면·모달·전체 UI 검수

주소창과 하단 브라우저 UI가 보이는 가로 태블릿을 핵심 대상으로 삼는다. `dvh`/지원 fallback과 실제 가시 viewport, 안전 영역을 조합하고 같은 inset을 두 번 차감하지 않는다. 키보드·확대 때문에 시각 viewport가 바뀔 수 있다는 점을 고려한다. [W03]

회전/resize/VisualViewport 이벤트의 레이아웃 갱신은 한 프레임으로 합쳐 처리한다. ResizeObserver 루프와 매 프레임 강제 layout을 피한다. 단순 화면 맞춤을 위해 RunController를 재생성하지 않는다.

전투 외에도 **보상3칸, 룬교체, 연마/제거 대상, 상점, 로비, 소개, 완료 화면**의 주 행동이 화면 안에서 접근 가능한지 확인한다. 긴 목록만 모달 내부 스크롤을 허용한다. 사전 검색/도감/저장3슬롯의 닫기·검색·확인·취소는 잘리지 않아야 한다.

닫기/취소 후 원래 카드 선택·드래그 허용 상태·키보드 초점을 되돌린다. 바깥 클릭과 카드 클릭이 동시에 실행되거나, 저장창을 닫았는데 전투가 재시작되는 문제가 없어야 한다.

100% 확대·키보드 닫힘의 무스크롤 조건과 접근성 확대/키보드 상태를 구분한다. 핀치 확대를 막거나 브라우저 zoom을 강제 초기화하지 않는다. 이 경우에도 중요한 확인/취소와 내용 접근을 유지한다.

## 9. 콤보·룬 Game Feel 보존

기존 0.10.1에서 요청한 **근거 카드의 ‘또잉’, 선명한 콤보명/수치, 누적 콤보에 따른 점진적 글로우·입자, 룬 등급·레벨 표현**은 유지한다. 화면 잘림을 해결한다며 모두 제거하지 않는다.

카드의 바깥 슬롯은 정적인 크기다. 내부 시각 레이어만 transform/opacity 등으로 짧게 반응하고 원복한다. 글자의 영구 축소나 다른 위치로의 재배치가 아니다. layout을 자주 바꾸는 속성보다 transform/opacity 중심의 연출을 우선하고 실측한다. [W04]

여러 줄에서 연출 대상은 정확한 cardInstanceId 집합으로 매핑한다. 줄바꿈으로 다른 사본이 하이라이트되거나, 같은 이벤트가 새로 마운트되면서 두 번 재생되지 않는다. 카드→점수의 좌표는 현재 레이아웃 기준이며 fullscreen·회전·row 전환 이후 낡은 좌표를 사용하지 않는다.

콤보 표시 영역은 읽기 가능한 고정 공간을 유지한다. 3줄 문장이라고 콤보명을 숨기거나 숫자를 카드 위에 겹치지 않는다. 파티클은 오버레이에서 그리되 포인터를 가로채지 않고 헤더/모달/사전 버튼을 막지 않는다.

효과 끄기·모션 감소에서는 장식 대신 정적 핵심 피드백을 유지한다. 한 공격의 콤보 카운트, 점수, HP, 보스 기믹, 보상, 읽기 속도·watchdog은 UI 수정으로 바꾸지 않는다. 재정렬/컴팩트 프로필 전환 후 잔여 transform·타이머·노드가 쌓이지 않는다.

## 10. 몬스터·배경·테마는 작은 여지만 남긴다

현재 만족한 전체 구도를 기본으로 유지한다. 몬스터 표시는 조합대 위에 두고, 가능한 한 이름·HP·간단한 기믹을 옆 그룹으로 묶는다. 이모지를 나중에 그림으로 바꿀 수 있는 slot/contain 구조 정도만 고려한다.

조합대 가독성을 희생하여 큰 이미지 구역을 예약하지 않는다. 고정 25%/대형 보스 전용 여백 등은 이번 요구가 아니다. 미래 이미지의 정확한 해상도·비율·발 위치 메타데이터와 레이어 확장은 추후 결정한다.

기존 지역별 색감은 유지한다. 각 테마에서 HP·글자·사이드버튼·형태버튼·룬테두리·콤보가 잘 보이는지만 확인한다. 배경 리디자인이나 모든 스테이지의 팔레트 재설계를 이번 UI 후속 작업에 포함하지 않는다.

## 11. 반드시 보존할 게임 내용

0.10.1 원래 명세의 HP 조정과 룬 10종·등급·배율·획득 경로는 유지한다. **신규 동명사 룬의 최종 이름은 자수정 룬**이다. 기존 4형식 토파즈의 ID·효과·강화 상태를 바꾸거나 두 룬을 합치지 않는다.

초중반 HP 최종값: Stage2 `[200,270,360,750]`, Stage3 `[300,320,360,400,780]`·골렘260×3, Stage4 `[500,530,570,600,1000]`, Stage5 `[640,680,740,800,1300]`. 이 문서는 그 수치를 추가 조정하지 않는다.

47전투/STAGE10_END, Stage7~10의 일반전 저항, 사전/안전 저장·불러오기, help 겸용, 다이아몬드 성능, 기존 보스의 실제 절/문형/빙정 조건, 기존 원정 버전 격리는 그대로 보존한다. 사전 활용/불러오기에 벌점을 추가하지 않는다. 최종 보스·엔딩·승천·보류 룬은 이번에도 제외한다.

7. 마지막 코드에서 회귀·빌드·브라우저/실기기 및 성능 검증을 하고 변경 PR/보고서를 갱신한다.

각 단계에서 실패하면 그 원인을 고친다. UI를 맞추기 위해 카드 최대수/게임규칙/테스트 기대치/시드/손패를 몰래 바꾸지 않는다.

## 13. 검증 기준 요약

이 패키지의 `03_UI_ACCEPTANCE_KO.md` 84항목과 `04_TEST_MATRIX_KO.md`를 실행 기준으로 사용한다. fixtures는 기대 조건과 재현 매개변수이며 실행 완료 증거가 아니다.

주요 검증은 다음을 함께 수행한다.

- 카드 너비·글자 크기의 손패/조합대 일치와 N 변화 시 불변.
- 실제 줄 경계의 N: `columns`, `columns+1`, `2*columns`, `2*columns+1`, `16` 중 유효값.
- 사용자가 보는 영어 전체와 실제 버튼 hit 영역이 패널·viewport에 포함되는지, 가림/클릭 가로채기가 없는지.
- 주소창 표시/전체화면/회전/키보드/팝업/애니메이션 중 상태 전이와 단일 정산.
- 원래 저장·게임 규칙·룬 수치와 동일한 fixture의 전후 결과.

실기기 미확보와 브라우저 에뮬레이션을 구분한다. 실제 iPad/휴대전화의 자동회전·주소창·터치가 검증되지 않았다면 NOT RUN이다. 모든 화면에서 완벽하다고 추정하지 않는다.

## 14. 완료 보고

기준 브랜치/HEAD, 최종 검증 커밋, 대체한 기존 UI 조건, 승인된 손패 기준의 근거, 실제 명령/종료코드/스크린샷, 84항목 PASS/FAIL/NOT RUN, 카드 수/행 수/viewport/overflow 수치, 실기기 여부, 정상 종료/정산/성능, 남은 한계와 PR을 보고한다.

오래된 130조건의 모순된 항목은 SUPERSEDED로 명시하되 새 조건은 별도 결과를 남긴다. 통과하지 못한 작은 화면을 의도된 지원 제한처럼 사후 포장하지 않는다. 작업 권한 문제는 구현과 구분해 보고하며, 자동 배포하지 않는다.

## 기술 근거와 출처 구분

- **U01 — 이 대화의 최신 사용자 지시:** 조합대 최우선, 손패 동일 너비·글자, 2줄/3줄+ 세로압축, 가로 전용, 헤더 위치, 사이드메뉴 넘침, 이미지/팔레트 후순위. 제품 규칙의 직접 근거다.
- **F01 — 첨부된 0.10.1 원본 명세/ZIP:** 8.2의 세로 허용/조합대 페이지 예외는 대체한다. 나머지 게임 내용과 Game Feel 계약은 보존한다. 원본 해시는 `manifest.json`에 기록한다.
- **W01 — MDN ScreenOrientation.lock:** 방향 잠금은 지원/조건의 차이가 있으므로 성공 탐지와 직접 회전 fallback이 필요하다. `https://developer.mozilla.org/en-US/docs/Web/API/ScreenOrientation/lock`
- **W02 — MDN Element.requestFullscreen:** 사용자 활성화·비동기 요청·실패 처리를 확인하는 근거다. `https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen`
- **W03 — MDN VisualViewport:** 키보드/확대에 따른 실제 가시 영역과 layout viewport의 차이를 다루는 근거다. `https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport`
- **W04 — web.dev Animation guide:** transform/opacity 중심 연출과 layout/paint 비용 검토의 기술 근거다. `https://web.dev/articles/animations-guide`
- **W05 — MDN fullscreenchange:** 실제 전체화면 상태와 UI 동기화 근거다. `https://developer.mozilla.org/en-US/docs/Web/API/Element/fullscreenchange_event`

W01~W05는 2026-10-15 확인한 외부 기술 문서다. 카드 치수·행 수·기능 위치 등의 제품 규칙을 외부 문서가 정한 것으로 해석하지 않는다. 본 명세의 구현 후보는 사용자 지시를 구체화한 설계 제안이다.
