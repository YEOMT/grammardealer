# UI 후속 검증 계획

## 1. 검증 수준

정적 코드 확인, 순수 레이아웃 산술, 실제 DOM 지정 상태, 게임 Controller 회귀, 자연 플레이, 실물 기기를 구분한다. 이 패키지에는 게임 소스와 테스트 실행 결과가 없다.

## 2. 기준선과 비교

수정 전의 승인된 손패를 화면 프로필별로 기록한다. 기준 프로필에서 손패→조합대 이동 전후의 **동일 단어·동일 선택형**을 비교한다. 효과 중 변형된 getBoundingClientRect와 정지 상태를 섞지 않는다. 폰트 로딩을 기다린 정지 상태의 레이아웃 박스와 ComputedStyle을 기본으로 사용하고, 탄성 효과의 중간 프레임은 별도 시각 검사한다.

카드 너비는 CSS px로 비교하며 최대 1px의 반올림 차이는 수치 오차용 한계로만 둔다. 실제 카드 늘어남을 허용하는 오차로 확대하지 않는다. computed font-size/family/weight는 동일해야 한다. 같은 프로필에서 카드 수가 증가한 전후도 대조한다.

## 3. 카드와 행 경계

손패 0/1/6/10/14장, 조합대 0/1/8/16장과 실제 한 행 수용량의 경계 주변을 검사한다. columns+1, 2*columns+1 중 16 이하에서 2행·3행 진입을 확인한다. 산술 예시의 W/C는 제품의 확정 크기가 아니며 본 구현의 값으로 같은 시험을 추가한다.

전체 sentenceSlots는 최대 16장이며 같은 사본을 중복 배치하지 않는다. 큰 조합대와 큰 손패의 순수 DOM 스트레스 시험은 합법적인 게임 진행과 구분한다. 게임 Controller 검사에서는 실제로 충분한 카드가 있는지 확인한다.

위→아래 행, 아래→위 행, 행 끝과 다음 행 첫 칸, 마지막 빈칸, 선택형 변경, 삽입 취소, 드래그 취소, 맞교환, 되돌리기를 시험한다. 영어 단어의 순서는 화면 읽기와 엔진 snapshot에서 동일해야 한다.

## 4. 패널·뷰포트·입력 검사

페이지 scrollWidth/Height와 clientWidth/Height뿐 아니라 각 필수 요소의 박스가 **소속 패널과 실제 가시 뷰포트**에 포함되는지 측정한다. clipping ancestor의 영역도 교차 검사한다. elementsFromPoint 같은 hit-test로 중심과 모서리 부근의 입력 수신을 확인한다.

overflow:hidden만으로 스크롤 검사를 통과해도 글자·버튼을 볼 수 없거나 누를 수 없으면 FAIL이다. 장식 글로우·그림자와 실제 텍스트·버튼 박스를 구분한다. 포커스 가시성도 별도 확인한다.

viewport_matrix의 14개 항목은 CSS 가시 영역 예시다. 실제 iPad·휴대전화 모델의 화면 크기라고 주장하지 않는다. stress와 desktop-narrow의 결과도 정확히 보고하고, 자동으로 지원 대상에서 제외하지 않는다.

## 5. 방향·전체화면·팝업

세로 항목은 플레이 PASS가 아니라 회전 안내·입력 차단·복귀 상태의 검증이다. 가로 잠금 API의 지원·미지원·거절을 모두 검사한다. 브라우저 mock만 실행했다면 실제 자동 회전 지원을 완료했다고 쓰지 않는다.

다음 팝업을 포함한다: 사전 검색, 도감, 저장 3슬롯, 내 덱, 룬 상세·정렬, 형태 선택, 보상 3선택, 룬 교체, 연마·제거 대상, 설정. 여러 모달과 전체화면·회전 안내 사이의 최상위 레이어 관계 및 초점 복원을 검사한다.

## 6. Game Feel과 성능

단문·중간 문장·장문, 1/2/3행 이상, 낮은·높은 콤보, 일반 Lv.1·희귀 Lv.3에서 확인한다. 속도 1/1.5/2, 효과 끄기, 모션 감소를 비교한다. 같은 기기와 상태에서 수정 전후 frame interval p50/p95와 50/100ms 초과 구간을 측정하고, 30회 공격·반복 팝업·회전 후 활성 FX·타이머·노드 잔류를 확인한다.

실제 기기 없이 GPU·프레임 성능을 보장하지 않는다. 60fps는 목표이며 측정 결과는 별도다. UI 변경으로 점수·HP·턴·RNG·저장 중복이 생기면 기능 실패다.

## 7. 실제 실행 명령

AGENTS.md와 현재 package.json의 실제 스크립트를 읽고 단위 시험, 데이터 검증, 빌드, 관련 기존·신규 UI 시험을 실행한다. 새 파일명과 명령은 실제로 추가한 것만 보고한다. 실행하지 않은 스크립트가 있다면 그 범위를 NOT RUN으로 표시한다.

고정 치수나 세로 허용 등 기존 계약을 수정하는 테스트는 옛 기대값과 대체 근거를 기록한다. 게임 판정 테스트를 삭제하거나 완화하지 않는다. 마지막 코드 변경 이후 시험을 다시 실행한다.

## 8. 캡처와 보고

권장 파일명: `device_viewport_orientation_fullscreen_state_handN_boardN_rowsN_frame.png`.
같은 문장·다른 상태의 캡처를 덮어쓰지 않는다. 기준선·수정 후, 서로 다른 행 수, 다른 테마, 팝업·키보드, 효과 중간 프레임을 남긴다.

최종 표에는 커밋, 브라우저 버전, 실기기 여부, 가시 화면 크기, 손패·조합대 장수, 행 수, 너비·글자 차이, 넘침, 가림, 실제 입력, 상태 보존, 결과를 포함한다. 84개 조건과 각 증거를 연결한다. 실제 미리보기를 확인하지 않은 것을 시각 PASS로 쓰지 않는다.
