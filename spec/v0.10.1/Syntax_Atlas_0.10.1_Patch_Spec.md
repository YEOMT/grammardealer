전체화면을 위해 새 서버·React·대형 렌더러·PWA 오프라인 캐시·서비스 워커·로그인/클라우드 저장을 도입하지 않는다. 특정 브라우저에서 전체화면이 안 된다고 동영상을 가짜 전체화면으로 띄우거나 주소창을 강제로 감추는 꼼수를 쓰지 않는다.

룬과 가산 보강으로 점수가 올라가더라도 이를 상쇄하려고 HP·저항·문법 배율을 다시 임의 상향하지 않는다. 기존 방어 기믹도 단어/구 연결만으로 해제되게 완화하지 않는다.

## 4. 신규 룬 10종 [이름·등급·효과 방식 확정]

기존 룬은 삭제하지 않는다. 고급·희귀 수치는 사용자가 채택한 앞선 제안값이고, 일반 가산량은 이번 문서의 **검증 초깃값**이다. 모든 신규 룬은 조건 만족 시 **공격당 1회**, Lv.1~3이다.

| 이름 | 등급 | 조건 | Lv.1 | Lv.2 | Lv.3 |
|---|---|---|---:|---:|---:|
| **화석 룬** | 일반 | 실제 과거 계열의 정상 유한 동사구 | **+30*** | **+50*** | **+70*** |
| **석영 룬** | 일반 | 정상적인 진행 동사구 | **+30*** | **+50*** | **+70*** |
| **가넷 룬** | 고급 | 주절 5형식 | ×1.7 | ×2.4 | ×3.2 |
| **백금 룬** | 고급 | 현재완료 | ×1.4 | ×1.7 | ×2.0 |
| **라피스 룬** | 고급 | 실제 절 연결 | ×1.4 | ×1.7 | ×2.0 |
| **아쿠아마린 룬** | 고급 | 정상적인 to부정사 | ×1.35 | ×1.65 | ×2.0 |
| **토파즈 룬** | 고급 | 정상적인 동명사 | ×1.35 | ×1.65 | ×2.0 |
| **흑요석 룬** | 희귀 | 정상적인 수동태 | ×1.9 | ×2.55 | ×3.2 |
| **아다만티움 룬** | 희귀 | 선행사를 수식하는 주격·목적격 관계절 | ×2.1 | ×2.8 | ×3.6 |
| **미스릴 룬** | 희귀 | 정상적인 가정법 과거 조건·결과쌍 | ×2.0 | ×2.7 | ×3.5 |

*일반 룬 +30/+50/+70은 사용자가 숫자까지 정한 것이 아니다. ‘배율 대신 가산으로 낮은 점수를 보강한다’는 의도를 반영한 첫 적용 제안이며, 보고서에서 별도 표시한다.*

주석→화석, 월장석→석영, 석류석→가넷, 청금석→라피스, 형석→아쿠아마린, 호안석→토파즈, 흑진주→흑요석, 성운석→아다만티움, 예언석→미스릴로 명칭을 정리한다. 과거 제안 이름을 별개 룬으로 추가하지 않는다. 기존 ‘수정 룬’과 새 ‘석영 룬’도 다른 ID/효과로 유지한다.

### 4.1 토파즈 중복 명칭 [구현 세부안]

현재 이미 **4형식 토파즈 룬 `rune.svoo`**가 존재한다. 새 동명사 룬으로 덮어쓰기·합치기·기존 사본 변환을 하지 않는다. [S02]

이번 문서의 안전한 표시 기본안은 다음과 같다.

- 기존: **토파즈 룬 · 4형식** (`rune.svoo` 유지)
- 신규: **토파즈 룬 · 동명사** (별도 `rune.gerund` 제안)

이는 최종 단독 이름을 새로 확정한 것이 아니라 **두 기능을 구분하기 위한 임시 부제 정책**이다. 기존 룬의 이름을 임의의 다른 보석으로 개명하지 않는다. 보상·상점·장착·도감·사후 로그·접근성 이름에 동일하게 구분한다.

## 5. 룬의 실제 발동 판정과 점수

### 5.1 문법 근거를 재사용한다

단어의 문자열·품사색·카드 장수만으로 수동태·동명사·관계절·가정법을 판정하지 않는다. 현재의 실제 clause/VP/노드/사본 ID를 이용해 **유효한 근거**를 찾는다. 전체 문장이 공격 가능한 상태이고 해당 근거가 정상이며 해당 문법의 원정 해금 조건을 만족해야 한다. 오류 회복으로 만들어진 근거는 신규 룬의 정상 발동 근거로 승격하지 않는다.

전혀 다른 부분의 경미한 오류가 있어도 해당 구조 자체가 정상이고 현재 규칙상 공격 가능하면 그 부분은 판단할 수 있다. 반대로 불완전한 문장·엔진 오류에 가산 룬으로 피해를 만들어주지 않는다.

### 5.2 기본 문법 배율과 아이템 보너스는 구분한다 [구현 세부안]

기본 문법의 같은 근거를 두 번 배율로 계산하지 않는 **0.10 중복 억제 규칙은 그대로 유지**한다. 그러나 별개의 장착 룬 두 개가 각각의 정상 조건을 만족해 연쇄 발동하는 것은 의도한 덱 시너지다.

룬 판정을 위해 raw 분석의 모든 태그를 무조건 복원하지 않는다. **정상성·해금 검사를 통과한 문법 구조**를 별도 읽기 전용 뷰로 만들고, 기본 배율의 단순 중복 대체와 문법 오류/미해금을 구분한다. 예컨대 현재완료진행에서 기본 완료·진행 배율을 또 계산하지 않으면서도 아래 명시한 아이템 조건은 평가할 수 있다.

이번 명세의 복합 용법 기본안:

| 구조 | 신규 룬 판정 |
|---|---|
| 실제 과거진행 | 화석 + 석영 각 1회 가능 |
| 실제 과거완료 | 화석 가능; 백금은 현재완료가 아니므로 제외 |
| 현재완료진행 | 석영 + 백금 각 1회 가능. 기본 완료×진행 배율을 추가하지 않음 |
| 정상 조건절/가정법의 if 연결 | 실제 절 연결이므로 라피스 가능. 기본 절 연결 배율 재추가는 금지 |
| 가정법 과거의 had/were | 화석의 ‘실제 과거’ 조건으로 쓰지 않음 |
| 가정법 과거완료 한 쌍 | 미스릴(가정법 과거 전용) 제외; 구성 had로 화석, have로 백금 자동 발동 금지 |
| 수동태를 포함한 관계절 | 흑요석 + 아다만티움 각 1회 가능 |

이는 사용자가 복합 용법의 세부까지 직접 정했다는 뜻이 아니라 **구현 시 해석이 흔들리지 않게 정한 정책**이다. 실제 엔진 근거와 충돌하면 무리하게 가짜 태그를 만들지 말고 테스트와 함께 충돌을 보고한다. 세부 양성·음성 사례는 동반 룬 문서/fixture를 따른다.

### 5.3 계산 순서를 유지한다

`카드/정확성/문형/문법 → 장착된 룬의 순서 → 지역 → 저항/보스 → 최종 위력`을 유지한다. 기존 이벤트 단계와 버림 처리를 따른다. 가산 룬은 **해당 룬이 놓인 순서에서** 더하며 자동으로 모든 곱셈 앞에 이동시키지 않는다. [S03]

합성 예시: 룬 전 점수100에서 화석 Lv.1(+30)→×1.6 룬은208, 반대 순서는190이다. UI의 +숫자/×숫자는 엔진의 동일 값에서 나온다. 연출을 강하게 해도 추가 점수·콤보 배율을 붙이지 않는다.

보류한 미래·전치사구·비교·명사절/가주어·과거완료 전용·현재완료진행 전용·가정법 과거완료 전용 룬은 추가하지 않는다.

## 6. 룬 획득 경로 [사용자 확정]

### 6.1 문법 진행과 획득을 분리한다

**일반·고급 룬은 Stage 1부터 보상 후보 자격을 갖는다.** 후반 문법 룬이라는 이유, 현재 덱에 적절한 카드가 없다는 이유로 후보에서 제거하지 않는다. 기존 4형식 룬도 새 버전에서는 조기 획득 정책에 포함한다. 룬을 획득했다고 문법·카드 팩 자체를 자동 해금하지는 않는다.

원정의 문법 발동 준비가 안 됐다면 상세에서 조건/준비 상태를 짧게 보여준다. 조기 빌드 선택의 장점과 현재 슬롯을 차지하는 부담을 모두 유지한다. 새 강제 안내나 자동 룬 교체는 추가하지 않는다.

### 6.2 맥락별 후보

| 맥락 | 일반 | 고급 | 희귀 |
|---|---:|---:|---:|
| Stage 1부터 일반전 보상 | 가능 | 가능 | **금지** |
| Stage 1부터 지역 보스 처치 보상 | 가능 | 가능 | 가능 |
| Stage 2 입장 상점 | 가능 | 가능 | **금지** |
| **Stage 4·6·8·10 입장 상점** | 가능 | 가능 | 가능 |
| 최초 고정 튜토리얼 보상 | 기존 예외 보존 | 기존 고정 구성 | **금지** |

**‘4스테이지 상점’은 Stage 4 입장 상점이지 네 번째 상점(Stage 8)이 아니다.** 현재 상점 위치 2/4/6/8/10은 유지하며 Stage 1 상점을 새로 추가하지 않는다. [S04]

이 제한은 신규 희귀 3종뿐 아니라 **기존 다이아몬드와 희귀 룬의 중복 획득/레벨업 후보에도 적용**한다. 희귀를 이미 소유했어도 일반전에서 레벨업 후보로 나오면 안 된다.

### 6.3 확률과 예외 [기존 비중 유지]

룬이 등장할 칸을 정하는 기존 보상 종류 가중치는 유지한다. **룬 칸 안의 등급 추첨**에 현재 `일반194 : 고급97 : 희귀9`를 사용한다. 세 등급에 후보가 있을 때 각각 약64.67%/32.33%/3%이며, 3%는 전투별 획득 확률이 아니다. [S05]

희귀 금지 맥락은 희귀를 **후보/가중치 양쪽에서 먼저 제외**하고 나머지194:97을 정규화한다. 같은 등급 내부는 기존 균등 추첨, 한 offer에서 같은 ID 중복 금지, 최대 레벨 제외, 기존 대체/가격 정책을 유지한다.

희귀 4종이 모두 유효한 첫 룬 칸이라면 개별 희귀는 3%÷4=0.75%라는 기준 계산이 가능하다. 룬 개수가 늘었다고 희귀 총비중을 몰래 올리지 않는다. 후보 소진 시의 실제 정규화 결과는 trace에 기록한다.

초회 1-1 고정 일반 카드, 초회 1-2 수정/호박/구리 소개, 이후 1-2의 기본풀/전체풀 슬롯 역할은 보존한다. 다만 ‘전체풀’과 예외 fallback에도 희귀 금지 필터가 빠져서는 안 된다. 일반/고급 전체풀 후보 자격은 Stage 1부터 열어둔다.

유효 일반/고급이 소진됐다고 금지된 희귀로 채우지 않는다. 일반 혼합보상에서는 룬 타입을 제외하고 남은 유효 타입에서 뽑고, 상점은 해당 룬 칸을 비우는 기존 빈 후보 정책에 맞춘다. 모든 변화는 공개 offer 생성 전에 일어나고 저장/닫기/취소로 재추첨하지 않는다.

## 7. 전체화면 옵션

### 7.1 동작

로비·전투에서 접근 가능한 **‘전체화면 / 전체화면 종료’** 컨트롤을 둔다. 설정에서도 접근할 수 있게 하되 좁은 화면을 버튼으로 가득 채우지 않는다. 플레이어의 명시적 클릭/터치에서 Fullscreen API를 요청한다. 기능 탐지와 실제 성공/실패를 처리한다. [W01]

안정적으로 유지되는 루트(예: `document.documentElement`)를 대상으로 한다. 전투마다 교체되는 `.game-shell`만 대상으로 해 사전·보상 모달이나 FX 레이어가 사라지게 만들지 않는다. Esc·시스템 종료·`fullscreenchange` 후 실제 DOM 상태를 기준으로 버튼 문구를 바꾼다. 새로고침 시 과거 설정만 보고 실제 전체화면이라고 표시하거나 자동 재진입하지 않는다.

거절·미지원에서도 게임은 계속된다. 안내 예: **‘이 브라우저에서는 전체화면을 켤 수 없습니다. 화면 맞춤은 계속 적용됩니다.’** 전체화면 미지원이 화면 잘림을 허용하는 이유가 되어서는 안 된다.

이미 지원되는 홈 화면 실행 방식이 있으면 추가 안내를 사용할 수 있지만 설치를 필수로 하거나, 전체화면 지원을 위해 이번에 새 오프라인/PWA 체계를 만들지는 않는다. 브라우저/기기별 지원 여부를 일괄 보장하지 않고 작업 시 실제 조합을 확인한다.

### 7.2 상태 보존

진입/종료/회전/주소창 변화는 **HP·턴·카드 순서·조합대·선택 형태·교환 횟수·룬 순서·RNG·저장 슬롯을 바꾸지 않는다.** 공격 중 전환되면 레이아웃/FX 좌표만 갱신하거나 표시만 안전 종료하며 이미 확정한 점수·정산을 반복하지 않는다.

## 8. PC·태블릿·모바일 화면 맞춤

### 8.1 최우선 목표

**전투의 필수 상태와 조작을 페이지 가로/세로 스크롤 없이 사용할 수 있어야 한다.** 특히 태블릿의 브라우저 주소창/하단 막대가 표시된 상태를 기준으로 설계한다. 전체화면일 때만 통과하는 레이아웃은 불합격이다.

고정 최소 높이/너비를 선언만 바꾸는 방식으로 끝내지 않는다. 브라우저의 실제 가시 영역을 기준으로 `dvh/svh`, 필요한 `VisualViewport` 보정, safe-area를 함께 처리한다. `vh`와 실제 가시 높이가 달라질 수 있으며 키보드/확대도 영향을 준다. [W02][W03]

**`overflow:hidden`으로 잘린 카드를 숨기거나 전체 화면을 무조건 축소하는 것은 해결이 아니다.** 화면 높이에 맞게 여백·적 장식·룬 설명·보조 패널을 재배치한다. 글자/탭 영역을 읽을 수 없을 정도로 줄이지 않는다.

### 8.2 기기별 기본안

- **PC**: 넉넉한 화면의 현재 구성을 보존한다. 낮은 노트북 창에서는 상하 여백과 적 표시를 압축하고 손패/문장 영역에 높이를 우선 배분한다.
- **태블릿 가로·세로**: 적 HP/턴을 간결한 헤더로 모으고, 룬은 짧은 요약으로 표시한다. 손패 최대14장과 조합대16장을 실제 가용 높이에서 다룬다. 모든 카드 동시 식별을 우선하며 2행 배치를 활용한다.
- **휴대전화**: PC의 3열 화면을 그대로 940px에 고정하지 않는다. 터치 가능한 소형 카드/단어 중심 배치, 요약 룬 바, 고정 핵심 조작을 사용한다. 가로 권장 안내는 가능하지만 세로에서 플레이를 막지 않는다.

**작은 휴대전화의 최대 카드 상태**에서는 읽기 크기와 동시 표시가 충돌할 수 있다. 다음 순서로 해결한다: 장식 축소 → 정보 재배치 → 카드의 비필수 설명 접기 → 명시적인 손패/조합대 페이지 전환. 마지막 방식은 **예외 세부안**이며 스크롤로 몰래 숨기지 않는다. `1/2`, 전체 장수, 현재 선택, 문장 전체 순서 요약을 보여준다. 사용한 기기/상태와 예외를 보고하고 ‘모든 카드 항상 동시 표시 PASS’라고 쓰지 않는다. PC/태블릿에서 이 예외를 기본 해결책으로 쓰지 않는다.

### 8.3 보조 창과 입력

사전·도감·공격 상세처럼 긴 내용은 **모달 내부 스크롤**을 허용한다. 이는 전투 페이지 스크롤과 다르다. 닫기·검색·확인/취소는 항상 접근 가능하게 둔다. 저장/불러오기 3슬롯과 보상 3칸, 상점의 구매/서비스 조작도 창 밖으로 잘리지 않는다. 작은 화면의 긴 목록은 명시적 탭/페이지와 내부 스크롤을 이용하되 파괴적인 조작을 숨기지 않는다.

키보드가 열렸을 때 검색칸과 닫기/취소를 가리지 않는다. 닫으면 전투 레이아웃으로 돌아오며 검색 초점 때문에 게임이 재시작되지 않는다. 사용자의 핀치 확대나 브라우저 확대를 강제로 취소하지 않는다. 100%·키보드 닫힘의 무스크롤 검증과 접근성 확대 시 검증을 구분한다.

카드 터치/드래그, 형태선택, 교환 선택, 룬 정렬은 기존 기능을 유지한다. 가로세로 전환 중 드래그는 안전 취소해 제자리에 두며 의도하지 않은 SUBMIT/EXCHANGE를 일으키지 않는다.

## 9. 사전·저장/불러오기 보존과 학생 사용성

사용자가 보고한 사실은 **기초학력이 부족한 학생들이 사전과 저장/불러오기를 이용해 Stage 1을 어렵게나마 클리어했다**는 것이다. 이를 전체 학습효과/승률의 검증으로 확대 해석하지 않는다.

다음 원칙을 적용한다: 사전/저장을 작은 화면에서 숨기지 않고 쉽게 열 수 있게 유지한다. 뜻·형태·구조를 읽을 수 있어야 한다. 기존 안전 저장 위치와 재도전 방법을 바꾸지 않는다. 사전을 열거나 불러왔다는 이유로 새 감점·보상 감소·재시도 벌점을 만들지 않는다.

자동 정답 생성이나 새 ‘기초 힌트 모드’는 이전 검토 제안일 뿐 이번 확정 기능이 아니다. 구현하지 않는다. 안정된 기존 사전과 저장의 접근성을 먼저 다듬는다.

## 10. 문법·룬 발동 카드의 탄성 반응 [사용자 확정]

### 10.1 무엇이 움직이는가

**현재 적용되는 문법 또는 룬의 근거가 된 제출 사본만** 움직인다. 주절 문형은 그 주절의 구성 카드, 진행/수동은 해당 동사구, 관계절은 해당 관계절과 선행사, 부사 수식은 해당 수식 근거를 사용한다. 다른 절·손패·같은 단어의 사용하지 않은 사본을 일괄 흔들지 않는다.

기존 `ScoreEvent.evidenceRefs/highlightCardIds`를 우선 사용하고, 넓거나 빠진 근거만 구조에서 정확히 보충한다. 관련 카드 ID를 못 찾았다고 전체 보드를 흔드는 fallback은 금지한다. DOM상 숨긴 모바일 페이지의 근거는 요약 표시를 반응시키고 정산을 바꾸지 않는다.

### 10.2 반응 형태

사용자가 원하는 ‘발라트로 같은 또잉’은 **짧은 압축 → 작은 오버슈트/들림 → 감쇠 복귀**로 해석한다. 계속 진동하거나 카드 위치가 뒤섞이는 효과가 아니다. 전용 모션 래퍼에 transform/opacity를 사용해 외부 배치·선택·드래그 transform과 충돌하지 않게 한다.

검증 초깃값: 약280ms, scale `1→0.97→1.045→0.99→1`, 최대 위로4px/회전1.2도. 다수 카드의 지연은18ms씩·총90ms 이내로 제한한다. 숫자는 시각 검증값이며 실제 읽기와 겹침을 보고 조정한다. 큰 카드일수록 화면 밖으로 날아가지 않는다.

**룬 비행/숫자 반영은 같은 점수 이벤트**다. 비행과 SCORE에서 콤보를 두 번 세거나 같은 이벤트의 카드를 이중 바운스하지 않는다. 서로 다른 룬이나 다른 문법 이벤트가 같은 사본을 다시 사용하면 그 다음 이벤트에서 다시 반응할 수 있다.

효과는 이미 확정한 결과를 재생할 뿐이다. 카드/턴/점수·보상/RNG를 변경하지 않는다. 룬 발동을 추가 공격으로 처리하지 않는다.

## 11. 콤보 문구·숫자의 가독성과 점진적 강화

### 11.1 문구를 먼저 읽게 한다

문법명/룬명, `+50` 또는 `×2.4`, 누적 점수의 위계를 명확히 한다. 문구 크기·굵기·대비를 조금 높이고 복잡한 배경에서 분리한다. 긴 이름은 최대2행 등 예약된 영역에 넣어 카드가 아래로 밀리지 않게 한다. 작은 글씨를 과도한 블러와 흰빛으로 덮지 않는다.

권장 시작값: 콤보 문구 PC20px 이상·태블릿18px 이상·작은 폰16px 이상. 화면/접근성 설정에 맞춰 검증한다. `아다만티움 룬 · Lv.3 ×3.6`, 긴 문법명, 큰 점수의 전체 숫자를 테스트한다. 축약 K/M만 남겨 정확한 점수를 읽을 수 없게 하지 않는다.

### 11.2 콤보 누적은 시각 강도다

카드 기본점수의 장수, 페널티, 보스 방어/저항, 최종값 재표시, 무효/미발동 이벤트를 누적 콤보로 세지 않는다. **실제로 점수를 양수 가산하거나 1초과 배수로 높인 문법/룬 이벤트**를 eventId 기준 한 번씩 센다. 완전문장과 주절 문형은 기존 의미 있는 점수 단계에 포함하되, 같은 이벤트 재전달은 제외한다.

기존 사본별 부사/연마 룬의 독립적인 실제 점수 이벤트는 각각 세되, 이번 신규 룬은 공격당1회다. 한 공격에서 누적하고 다음 제출에서 초기화한다. 콤보 수가 높다고 새로운 배율을 주지는 않는다.

| 실제 누적 | 시각 초깃값 |
|---|---|
| 1~2 | 선명한 글자, 작은 반응과 얇은 글로우 |
| 3~4 | 빛 테두리와 소량의 입자 |
| 5~7 | 문구/숫자 양쪽의 강화된 글로우·짧은 확산 |
| 8~11 | 더 넓은 빛과 입자 꼬리, 강조된 숫자 반응 |
| 12 이상 | 상한 안에서 가장 풍부한 연출; 이후 무한 증폭 금지 |

단계 경계만 갑자기 바꾸지 않고 내부에서 점진 보간한다. 글자는 밝은 중심을, 파티클/큰 빛은 외곽을 장식한다. 새 점수가 표시된 후 다음 효과를 읽을 안정 구간을 둔다. 숨쉬는 광택을 계속 키워 화면 전체를 가리지 않는다.

### 11.3 룬 등급과 레벨을 함께 표현한다

일반은 명료한 짧은 반응, 고급은 세공 빛/강한 꼬리, 희귀는 특징적인 광륜·분광/금속성 반응을 준다. **같은 룬의 Lv.1<2<3** 차이도 면 반사·선 굵기·입자량·짧은 펄스로 나타낸다. 매 효과의 길이를 늘리는 방식은 피한다.

기존 룬도 동일 등급/레벨 정책으로 통일한다. 다이아몬드는 기존 특유의 디자인을 보존한다. 유틸리티 룬은 전투 시작 자원 적용 시 표현하고, 제출 공격에 가짜 점수 이벤트를 만들지 않는다.

## 12. 읽기 시간·성능·접근성·복구

현재 기본 문법 SCORE550ms, 룬 비행220ms+SCORE520ms 등 **기존 타임라인의 읽기 시간과 속도 옵션**을 기준으로 한다. 카드 바운스·글로우를 그 안에서 겹쳐 재생하여 모든 이벤트마다 별도 대기 시간을 누적하지 않는다. 속도1/1.5/2에서 숫자와 근거 순서를 보존한다. [S06]

입자는 풀/재사용 또는 동등한 유한 자원 관리로 제한한다. 초기 권장 상한은 동시입자 PC48·태블릿/폰24이며 `reducedMotion/effectsOff`에서는 장식 입자0이다. 숫자/텍스트는 항상 남긴다. 프레임마다 DOM 레이아웃 읽기/쓰기 반복, 상시 무제한 발광, 화면 전체 대형 블러, 유효하지 않은 RAF 체인을 피한다.

효과 낮춤은 **게임 RNG와 별도인 시각 설정**으로만 결정한다. 필수 소리/읽기 피드백을 왜곡하지 않는다. 스피커 실청취 없이 음질을 검증했다고 쓰지 않는다. 새 BGM 제작은 범위 밖이다.

prefers-reduced-motion 및 기존 효과 끄기를 존중한다. 탄성/회전/흔들림 대신 정적인 강조를 쓴다. 강한 전면 섬광이나 빠른 반복 점멸은 피한다. 이펙트는 `pointer-events:none`, 장식용 접근성 숨김, 짧은 생성/제거를 지킨다.

화면 회전/전체화면/백그라운드/탭 복귀/모달/오류/연출 중단에서 **표시만 안전하게 종료**한다. watchdog은 계획된 전체 길이에 맞게 유지하며 보상·피해·부위 파괴·회복·예견 기억은 한 번만 정산한다. FX 잔해·유령 카드·입력 잠김이 남지 않아야 한다.

## 13. 버전·저장·이름 호환

신규 원정만 `0.10.1`의 HP/새 룬/획득 정책을 사용한다. `0.10.0` 이하 원정은 기존 HP·후보·사본·룬효과·RNG·종료 경계를 보존한다. UI/반응형/전체화면/가독성 같은 순수 표시 개선은 구버전 원정에서도 사용할 수 있으나 계산 정책을 바꾸지 않는다.

버전은 문자열/버전 구성요소로 비교한다. `parseFloat`나 소수 비교로 `0.10.1`을 `0.1`처럼 취급하지 않는다. 현재 코드의 명시적 버전 배열과 기본 fallback을 전부 검토해 0.10.1에서 Stage 10/문법/룬/빙정/보상/상점/저장 검증이 옛 초기 정책으로 떨어지지 않게 한다.

기존 runeId와 카드 ID를 유지한다. 신규 룬 ID는 의미 중심으로 독립 등록하고 미구현 로드맵에 같은 이름이 있어도 일괄 활성화하지 않는다. 기존 4형식 토파즈를 새 동명사 룬으로 바꾸지 않는다. 전체화면/시각 품질 설정은 게임 판정 상태와 분리한다.

## 14. 구현 순서

1. 최신 기준/미커밋 상태 확인, 기존 회귀 실행, 정책/명칭/버전 영향도 표 작성.
2. 새 버전 분기와 HP19개·골렘260×3, 기존 버전 비변경 검증.
3. 신규 룬 정의·정상 근거 매칭·가산/배율·순서·중복·강화/저장.
4. 보상/상점 맥락 필터·초회 예외·희귀 업그레이드 제한·분포/고정 offer.
5. 안정 루트 전체화면과 실제 viewport 기반 레이아웃·터치·사전/저장 접근.
6. 이벤트 근거의 카드 바운스·문구 개선·누적 콤보·등급/레벨 FX.
7. 통합 회귀·브라우저/실기기·성능·자연 원정·production 빌드.
8. 변경 목록·인수 조건·검증 범위·미완료·재현 경로를 정리하고 별도 브랜치/PR로 인계.

문법 판정기를 재작성해서 룬을 만들지 않는다. 기존의 정확한 근거와 UI 이벤트를 필요한 최소 범위에서 확장한다. 스냅샷마다 파일을 무작정 복제하거나 기본 CSS를 뒤에 덮어쓰는 것만 반복하지 않는다.
