# v0.10.1 룬·획득·근거 판정 상세 계약

본명세의 사용자 확정 명칭·등급·HP를 우선한다. 이 파일은 특히 **이름 충돌, 복합 구문, 조기 획득과 발동 해금, 추첨 맥락**을 구체화한다. 숫자 최적화 결과가 아니다.

## 1. ID와 명칭

`data/rune_catalog.json`은 의미 기반 ID 제안이다. 실제 저장소의 미구현 roadmap과 라이브 ID를 먼저 대조한다. 같은 효과의 빈 예약 ID가 있다면 재사용할 수 있으나 기존 정상 룬을 덮어쓰지 않는다.

| 제안 ID | 표시 | 비고 |
|---|---|---|
| rune.past | 화석 룬 | 신규 가산 |
| rune.progressive | 석영 룬 | 수정 룬(rune.perfectSentence)과 다름 |
| rune.svoc | 가넷 룬 | 5형식 |
| rune.presentPerfect | 백금 룬 | 현재완료 |
| rune.clauseLink | 라피스 룬 | 절 연결 |
| rune.infinitive | 아쿠아마린 룬 | to부정사 |
| rune.gerund | 토파즈 룬 · 동명사 | 기존 rune.svoo와 분리 |
| rune.passive | 흑요석 룬 | 수동태 |
| rune.relative | 아다만티움 룬 | 수식 관계절 |
| rune.unrealPresent | 미스릴 룬 | 가정법 과거 |

기존 `rune.svoo`는 ‘토파즈 룬 · 4형식’으로 구분하되 기존 저장/레벨/효과는 유지한다. 사용자 결정 전 임의의 새 보석 이름으로 바꾸지 않는다. 이름 중복과 대응표를 최종 보고서에 남긴다.

기존 버전에서 12종이 유효한 기준이면 새 버전은 **22종(신규10)**이다. 실제 최신 main이 바뀌었다면 기존 수를 다시 세고 사용자 승인 없이 옛 신규 후보를 함께 활성화하지 않는다.

## 2. 문법별 구체적 발동 [구현 세부안]

모든 신규 룬은 전체 공격 성립 + 관련 구조 정상 + 현재 원정의 필요한 문법 자격을 전제로 한다. 같은 룬은 관련 구조가 여러 개여도 한 공격에서 한 번만 발동하며, event의 근거 ID 목록은 중복 없이 합친다.

### 화석

실제 과거 계열의 유한동사구를 읽는다. 일반 과거, 실제 과거진행/과거완료의 과거 기준은 인정한다. 비유한 과거분사, 형용사로 된 p.p., 가정법의 비현실 과거형은 ‘실제 과거’가 아니다. 명사절/관계절 안에도 실제 과거의 정상 유한동사구가 따로 있으면 인정할 수 있다.

### 석영

정상적인 유한 진행 동사구를 읽는다. 현재·과거진행과 현재완료진행의 실제 진행 특성을 인정한다. 단순 be동사, 수동태만 있는 be+p.p., 진행이 아닌 동명사/명사 수식 -ing는 제외한다. 반복 -ing 카드 개수만큼 가산하지 않는다.

### 가넷

현재 엔진에서 정상 주절로 확정한 5형식(FRAME.SVOC)에만 발동한다. 다른 절이 5형식이라는 이유로 주절 5형식 룬을 발동시키지 않는다. if절이 문장 앞에 있어도 실제 결과절이 주절인 0.10 정책을 유지한다.

### 백금

유한 현재 have/has가 이끄는 정상 완료 동사구에 발동한다. 현재완료진행의 실제 현재완료 특성도 인정한다. 본동사 have(가지다), 과거완료 had, 가정법 결과의 would/could have+p.p.는 현재완료가 아니므로 제외한다.

### 라피스

정상적인 연결 구조가 실제 **절과 절**을 이어야 한다. 지원되는 등위/종속/내용절 연결을 현재 엔진의 구조로 확인한다. 조건/가정의 if 연결도 실제 절 연결이므로 룬 조건이 될 수 있다. 이것이 기본 절 연결 배율을 다시 곱한다는 뜻은 아니다. 그 기본 배율은 0.10의 중복 대체 규칙을 유지한다.

`difficult and different`, 명사 목록, 전치사 목적어 연결만으로 발동하지 않는다. 해당 연결에 주어·유한동사 등 필요한 구조가 정상인지 확인한다. 관계절이라는 이유만으로 라피스도 자동 발동시키지 않고, 별도 연결 구조가 있거나 기존 엔진이 지원하는 실제 절 연결 근거가 있는지를 본다.

### 아쿠아마린

현재 지원 범위의 정상적인 to부정사(명사/형용사/부사적 역할)에 발동한다. 가주어 진주어인 to절도 해당한다. 전치사 to, modal 뒤 원형, 사역/지각의 원형부정사는 to부정사가 아니다. 새 문형을 만들기 위해 허용 동사를 일괄 확장하지 않는다.

### 토파즈(동명사)

문장 안에서 명사 역할로 정상 판정된 동명사에 발동한다. 동사의 목적어, 주어/보어 등 기존 지원 역할을 따른다. 진행형·현재분사 수식·지각동사 목적격보어 -ing라는 이유만으로 동명사 룬을 발동시키지 않는다. 기존 4형식 토파즈와 효과/표시를 혼동하지 않는다.

### 흑요석

정상 수동태 근거(기존 VOICE.PASSIVE와 동사구 연결)를 사용한다. 본동사의 타동성/활용/필수 성분 검증을 유지한다. p.p. 카드 하나나 수식 분사만으로 수동태를 인정하지 않는다. 기존 엔진이 구별하는 수동/상태 해석을 임의로 점수 최대 해석으로 바꾸지 않는다.

### 아다만티움

**선행사를 수식하는 정상 주격 또는 목적격 관계절**에 발동한다. 정상 목적격 관계사 생략도 인정한다. 자유관계절 what, 간접의문문 who/what/where, 접속사 that 내용절, 관계부사절만으로 발동하지 않는다. 하나의 모호한 관계절을 주격·목적격 두 개로 증식시키지 않는다.

### 미스릴

실제 가정법 과거의 조건절+결과절 쌍(0.10 UNREAL_PRESENT)을 확인한다. 조건부 과거형과 would/could의 역할, 두 절의 연결이 필요하다. 일반 조건절, 과거 능력의 could, 단독 would/could, 일반 과거완료는 제외한다. **가정법 과거완료(UNREAL_PAST)는 이번 미스릴의 대상이 아니다.** 해당 전용 운명석 룬은 보류다.

## 3. 복합 구문과 점수 중복을 구분한다

이번 복합 용법 기본안은 기존 문법 기본 배율을 바꾸지 않고 **서로 다른 룬의 실제 조건**을 평가한다. 아래 항목은 사용자가 모든 경계 사례를 개별 승인했다는 뜻이 아닌 구현 세부 계약이다.

- 과거진행에는 화석·석영, 현재완료진행에는 석영·백금이 각각 한 번 가능하다.
- 수동태 관계절에는 흑요석·아다만티움이 각각 한 번 가능하다.
- 가정법 과거에는 미스릴과 실제 if 절 연결에 대한 라피스가 각각 한 번 가능하다. had/were만 보고 화석을 얹지 않는다.
- 기본 현재완료진행 점수에 완료×진행을 또 곱하거나, 가정법 점수에 같은 if연결 배율을 또 곱하지 않는다.
- 미해금/오류 때문에 부적격인 원시 태그를 단순히 다시 꺼내 발동시키지 않는다. 단순 수치 중복 대체와 문법 부적격은 다른 사유다.

현재 `applyRunes`가 받는 필터된 분석만으로 이런 구분이 불가능하면, **원시 구조+문법 자격에서 읽기 전용 rune evidence view를 만들고 판정 이유를 기록**한다. 파서를 다시 만들거나 scoreableAnalysis를 모두 무시하는 방식은 금지한다.

모든 event는 사용 사본의 ID와 근거 ID를 가지며, 같은 단어의 손패 사본/이전 턴 소멸 사본을 참조하지 않는다. FX에서 이 목록을 그대로 활용한다.

## 4. 가산과 레벨

화석/석영의 +30/+50/+70은 검증 초깃값이다. ‘기본문장 보너스’ 단계로 옮기지 않고 기존 룬 슬롯에서 ADD로 계산한다. 본명세가 선택한 고급/희귀 배수는 각각 유리수로 저장해 매 곱셈의 정수 버림을 보존한다.

기존 최대 Lv.3, 같은 ID 재획득 레벨업, 최대 레벨 후보 제외, 동일 ID 다중 장착 금지, 슬롯 부족 시 선택 교체/취소, 룬 순서 변경을 유지한다. 신규 룬이 강하다고 기존 룬을 임의로 약하게 만들지 않는다.

## 5. 획득 맥락 알고리즘

1. 새 원정 manifest에 이번에 사용할 룬만 포함한다.
2. 실제 보상 출처(일반전/지역 보스/소개) 또는 실제 상점 stageId를 결정한다.
3. **획득 가능한 등급을 먼저 필터**한다. 일반전/R2 소개/Stage2 상점은 RARE가0이다.
4. 사용자가 지정한 조기 획득을 막는 문법 해금·현재 덱 적합성 필터는 일반/고급 후보 자격에 적용하지 않는다. 희귀도 출처 자격을 따르며 임의의 후반 등장 제한을 추가하지 않는다.
5. 최대레벨/같은 offer 중복/해당 원정 라이브 정의 조건을 적용한다.
6. 남은 등급만 현재194:97:9에서 정규화해 추첨하고, 그 등급 내부 ID를 균등 선택한다.
7. offer를 고정해 공개한다. 선택/교체취소/모달/로드가 다시 RNG를 소모하지 않는다.

희귀를 거를 때 ‘새 룬 목록’만 검사하지 않는다. 다이아몬드도 RARE이므로 동일하게 제한한다. 희귀 업그레이드도 똑같다.

### 해금과 UI

룬을 일찍 얻을 수 있다고 Stage1에서 과거·5형식·수동태 문법을 모두 자동 해금하지 않는다. 기존 문법 진행은 유지한다. 룬 상세의 발동 조건/준비 상태를 통해 ‘얻었지만 아직 조건을 못 맞추는 상태’를 이해할 수 있게 한다. 제출 전 정답/성공 예상 점수는 만들지 않는다.

### 확률의 의미

- 정상전 룬 칸: 모든 일반/고급이 유효하면2:1.
- 보스 보상 또는 Stage4+ 상점의 룬 칸: 모든 등급이 유효하면194:97:9.
- 희귀4종이 모두 유효한 첫 추첨에서는 개별 희귀0.75%. 후보제외 후 값은 달라질 수 있다.
- 보상 타입의 RUNE 가중치와 룬 등급의3%는 서로 다른 추첨 단계다.
- 이번에는 새로운 확률상향·천장·장착 룬 가중치·확정 희귀 지급을 도입하지 않는다.

## 6. 보존 조건

초회1-1 일반카드와 첫1-2 고정3룬을 보존한다. 이후1-2의 기존2 BASIC+1 전체풀 방식도 유지하되 전체풀/부족 fallback은 RARE 금지다. Stage1부터 신규 일반/고급이 전체풀의 유효 후보가 될 수 있어야 한다.

현재 상점은 Stage2/4/6/8/10 진입에 있다. ‘Stage1부터 상점에도 나올 수 있게’는 새로운 Stage1 상점 건설 지시로 확대하지 않는다. 첫 실제 상점(Stage2)부터 일반·고급을 적용한다. **Stage4 입장 상점은 두 번째 상점**이다.

상점 가격은 기존 일반18/고급24/희귀32 정책을 유지한다. 카드 가격/희귀 카드 보상 제한과 룬 제한을 섞지 않는다. 사용자 지시는 룬 획득 규칙이며, 일반전의 희귀 WORD 카드를 금지하는 지시가 아니다.

## 7. 검증 결과의 요구 수준

기존12종 보존, 신규10종3레벨, 신구 토파즈 별도 사본, 무효 발동0, 근거 기반FX, 모든 맥락의 희귀 제외와 레벨업, 후보 소진, 확률 trace, 신규/구버전 저장을 확인한다.

분포 검증은 고정 seed의 다수 추첨으로 등급 조건부 빈도와 개별 후보 빈도를 함께 보고한다. 실제 보상 화면에서의 빈도와 순수 룬 선택기 빈도를 구분한다. 모든 등급 후보가 있다는 조건을 결과표에 적고, 단순히 특정 희귀가 한 번 보였다고 분포 PASS라고 쓰지 않는다.
