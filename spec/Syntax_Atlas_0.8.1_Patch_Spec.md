# 신텍스 아틀라스 0.8.1 통합 패치 명세

- 프로젝트: 신텍스 아틀라스(Syntax Atlas)
- 문서 기준일: 2026-10-11
- 기준: 기존 개발 회의 기록, 첨부 「붙여넣은 텍스트(1).txt」, 새 회의방에서 최종 확정한 help 설계
- 작업 대상: 작업 시 제공되는 최신 0.8 계열 실제 소스와 그 소스에 이미 적용된 수정
- 문서 상태: 개발·검증 지시용 명세. 이번 문서 작성에서 게임 소스 수정, 버그 재현, 테스트 실행, 빌드 및 배포를 수행한 것은 아니다.

## 1. 패치의 목적과 범위

0.8.1은 신규 콘텐츠 확장이 아니라 **현재 카드로 만드는 문장의 판정 정확도와 전투 화면의 가독성을 개선하는 정밀 감사·폴리싱 패치**다.

게임의 정체성은 “모든 영어 문장을 자유롭게 인정하는 도구”가 아니라 “제한된 카드와 지원 용법으로 정확한 영어 문법을 조합하는 게임”으로 유지한다. 해석이 가능하다는 이유만으로 문장을 통과시키거나 문법 콤보를 지급하지 않는다.

| 작업 영역 | 이번 패치에서 변경하는 것 | 변경하지 않는 것 |
|---|---|---|
| 문법 판정 | 현재 DB·형태 변화·지원 문법 안에서 발생하는 오인정과 오거부 | 미지원 문법의 포괄적 추가, 느슨한 의미 추측 |
| help | 동사·불가산명사 겸용, 고급 전투 보상 전용, 보조 품사 표시 | 다른 단어의 자동 겸용, 겸용 보너스 |
| 손패 정보 | 운영·빙정·방해 카드의 긴 설명을 상세 보기로 이동 | 카드 크기, 기본 조작, 효과·사용 횟수 |
| 희귀도 | WORD 카드의 고급·희귀 테두리 구분 개선 | 상아색 바탕, 기존 품사색, 등급별 수치 |
| 연마 | 품사색 단계 배지와 +3 안쪽 장식 | 연마 효과·비용·단계·상한 |
| 전투 안내 | 정식 문법명·형태·한 줄 설명·실제 지역 보너스 표시 | 보너스 대상·배율, 제출 전 정답·예상 점수 비공개 원칙 |
| 보스 설명 | 짧고 자연스러운 공략 문구, 세부 규칙은 상세 보기 | 보스 기믹·공략 난도·승패 조건 |

위 변경 이외의 새 카드, 룬, 적, 스테이지, 경제·전투 밸런스 조정을 추가하지 않는다. help의 명사 용법 등록은 합의된 예외이며, 별도의 신규 카드 한 장을 만드는 작업이 아니다.

## 2. 작업 기준과 보존 조건

### 2.1 실제 소스를 기준으로 수정

작업 시작 시 브랜치, 커밋, 변경 중인 파일, 표시 버전을 확인하고 현재 상태를 기준점으로 남긴다. 과거 0.1·0.2 소스나 최초 설계로 되돌아가 재작성하지 않는다. 이미 적용된 후속 수정과 사용자의 미커밋 변경을 덮어쓰지 않는다.

본 문서의 기존 코드 설명은 회의 기록에 따른 확인 대상이다. 실제 파일명, 데이터 구조, 함수명, 생성 경로는 작업자가 소스에서 확인한다. 과거 답변의 “코드를 확인했다”는 문구를 이번 작업의 검증 결과로 인용하지 않는다.

### 2.2 보존할 요소

카드 크기와 손패 공간, 클릭·드래그 조립, 선택·교환·버리기·형태 변경, 운영 카드 사용, 준비·턴 진행, 공격 연출과 읽기 시간, 점수 계산식, 룬·인장 조건, 연마 수치, 보상 구조, 상점·스테이지 구성, 기존 보스 기믹을 유지한다. 문법 버그를 바로잡은 결과 판정이 달라지는 것은 허용하지만, 그와 무관한 점수·배수·확률을 조정하지 않는다.

기존 원정·보유 카드·연마·룬·진행 상태를 삭제하거나 초기화하지 않는다. UI 개선을 이유로 카드나 글씨를 일괄 축소하거나 상세 창을 열 때 카드를 사용·소모하게 만들지 않는다.

## 3. 문법 정밀 감사

### 3.1 감사 대상

현재 실제 단어 카드 DB, 카드가 허용하는 형태 변화, 기존에 지원하는 문형·문법을 연결한 범위를 감사한다. 특정 신고 문장만 예외 처리하지 않고 같은 원인을 공유하는 판정 경로를 확인한다.

현재 구현에 존재하는 범위에서 기본 문형, 명사구·가산성·수량 표현, 동사 활용·시제·일치, to부정사·동명사·분사, 수동태·5형식, 접속사·절 연결, 비교·정도 표현, 관계절과 관련 룬·인장을 점검한다. 이 목록은 검수 축이며 미구현 문법을 새로 추가하라는 지시가 아니다.

검수는 다음 세 층을 구분한다.

| 층위 | 판단할 내용 |
|---|---|
| 문장 성립 | 전체 문장의 구조가 성립하는가? |
| 지원 범위 | 현재 카드와 명시적으로 등록된 용법으로 분석 가능한가? |
| 콤보 성립 | 해당 콤보가 요구하는 실제 구문 구조가 존재하는가? |

### 3.2 오인정 방지

단어가 나타났다는 이유만으로 문법 콤보를 주지 않는다. 관계대명사, more·than, to, -ing 등의 표면 형태만 확인하고 구조 검증을 생략하지 않는다.

일부 구간만 맞는 경우, 나머지 토큰을 버리고 전체 문장을 완전한 문장으로 인정하지 않는다. 주절·종속절·관계절의 연결, 동사의 필수 성분, 관계절의 실제 역할을 검사한다. 관계절 하나의 모호한 분석을 주격·목적격의 두 성립 근거로 중복 계산하지 않는다. 반대로 실제로 여러 관계절이 성립하는 기존 정상 문장은 보존한다.

기존 룬·인장은 판정이 확정된 실제 구문 근거를 참조한다. 이중 연결 인장의 조건 자체를 완화하거나 강화하지 않는다.

### 3.3 오거부 방지

기존 지원 용법으로 성립하는 정상 문장은 계속 인정되어야 한다. 오인정을 막기 위해 관계절 전체, 특정 동사 활용 전체, 명사구 전체를 차단하는 방식으로 수정하지 않는다.

용법 누락, 구조 분석 실패, 실제 비문을 감사 기록에서 구분한다. 확인된 미지원 표현에는 그 사실에 맞는 안내를 제공하되, 모든 실패를 “맞지만 미지원”으로 단정하지 않는다. 반대로 지원 범위의 한계를 모두 “영어 문법 오류”로 표시하지 않는다. 문법의 정오나 미지원 여부가 확정되지 않은 사례는 미확정으로 기록한다.

의미의 자연스러움을 임의의 새 감점 기준으로 도입하지 않는다. 빈 문장 성분을 채우기 위해 미등록 품사를 추측하거나 생략된 단어를 임의로 삽입하지 않는다.

### 3.4 반드시 다룰 신고 사례

| 사례 | 현재 확인 수준 | 이번 패치의 기대 처리 |
|---|---|---|
| `they environments that will be thinking knew live` | 복원된 이전 회의 기록의 관계절 오인정 신고. 정확한 원인과 이번 소스에서의 독립 재현은 미확정 | 당시 카드·형태를 확인해 재현한다. 비정상 구조를 완전문장으로 통과시키거나, 성립하지 않은 주격·목적격 관계절과 이중 연결 인장 근거로 사용하지 않는다. |
| `I need more help.` | 첨부 기록의 오거부 신고 | help를 명사 ‘도움’으로 분석하여 지원한다. more가 등장했다는 이유만으로 비교급 콤보를 지급하지 않는다. |
| `I help you.` | help의 기존 동사 용법 보존 예문 | 기존 동사 분석·문형·채점을 보존한다. |
| `She is more than the problem.` | 회의에서 검토했으나 일반 비교급으로 인정하는 범위 확장은 채택하지 않음 | 이 사례를 통과시키려고 비교급 파서를 넓히지 않는다. 비교급 콤보나 보스 공략 예외를 새로 부여하지 않는다. 미지원과 비문을 구분하는 감사 대상으로 기록한다. |

첫 번째 사례는 “이번 작업에서 이미 재현 완료한 버그”로 보고하지 않는다. 원문 문자열 시험과 실제 카드·형태를 거치는 시험을 구분하고, 복원하지 못한 조건은 기록한다.

### 3.5 감사 방법과 산출물

실제 DB와 문법 지원 경로를 목록화하고, 각 수정 경로에 정상 문장과 최소 변경한 오류 문장을 짝지어 추가한다. 회귀 범위에는 제출 문장의 성립 여부, 분석 품사, 문형·문법 콤보, 룬·인장, 진단 내용을 포함한다.

무한한 문장 조합을 전수 검사했다고 표현하지 않는다. “어떤 DB 항목·형태·구문·분기와 경계 조건을 검증했는가”를 커버리지 표로 제시한다. 감사표에는 사례, 사용 카드·형태, 수정 전 결과, 기대 결과, 원인, 수정 위치, 검증 결과, 미지원·미확정 여부를 기록한다.

## 4. help 고급 겸용 카드

### 4.1 카드 정체성과 획득

| 항목 | 최종 규칙 |
|---|---|
| 카드명 | help |
| 등급 | 기존 고급(UNCOMMON) 유지 |
| 주 품사 | 동사 — 돕다 |
| 보조 품사 | 명사 — 도움 |
| 명사 범위 | 우선 불가산명사 ‘도움’ 용법만 |
| 신규 획득 | 전투 보상의 고급 카드 후보로만 등장 |
| 시작 덱·상점 | 제외 |
| 기존 저장 | 보유한 help와 그 사본·연마 상태 유지 |
| 추가 보상 | 겸용 자체의 추가 점수·배수 없음 |

“기본 단어 풀에서 제외”는 시작·입수 후보 제한이다. 어휘 DB나 도감에서 help 자체를 삭제하라는 뜻이 아니다. help를 제외한 결과 시작 덱의 카드 수·기존 구성 규칙이 깨지지 않도록 현재 생성 경로를 확인한다. 임의의 신규 대체 카드를 추가하지 않는다.

### 4.2 용법 등록과 판정

기존 동사 어휘 항목과 별도 명사 어휘 항목을 하나의 카드에 연결한다. 회의에서 사용한 개념 식별자는 `lex.help.verb`와 `lex.help.noun`이며, 실제 필드명·연결 방식은 현 소스의 스키마에 맞춘다.

동사 help의 기존 활용형과 문형은 보존한다. 명사 help는 기본형 help와 불가산성 정보를 별도로 가진다. 동사형 helps·helped·helping을 일괄적으로 명사 ‘도움’으로 인정하지 않는다. 다만 helping이 기존 동명사·분사 규칙으로 분석되는 경로까지 막지는 않는다.

수동 “명사 모드/동사 모드” 버튼은 만들지 않는다. 문장 제출 후 전체 구조가 성립하는 등록된 용법을 선택한다. 여러 해석이 가능한 경우에도 점수 최대화를 선택 기준으로 삼지 않고 일관된 문법 분석 규칙을 사용한다.

분석에서 선택한 품사를 채점과 피드백이 함께 참조하게 한다. 명사로 쓴 help를 동사로 다시 계산하거나, 동사로 쓴 help를 명사로 중복 계산하지 않는다. 형태를 자동으로 다른 철자로 바꾸거나, 제출 전에 정답·예상 품사를 실시간 힌트로 알려주는 기능은 추가하지 않는다.

### 4.3 카드 UI

상단 품사색은 **기존 동사색 단색 그대로** 사용한다. 파랑/빨강 반반 분할, 보조색 띠, 대각선 배색을 적용하지 않는다. 현재 코드의 동사색을 재사용하며 색상 매핑을 추정해 새로 정하지 않는다.

우측 상단에 작은 `동·명` 배지를 표시한다. 이 배지는 희귀도 테두리·연마 배지·이름과 겹치지 않게 한다. 상세 보기에는 “동사: 돕다 / 명사: 도움(셀 수 없는 명사)”과 두 대표 예문을 제시한다.

카드의 주 품사와 외형은 문장마다 바꾸지 않는다. 실제 사용 품사는 제출 후 기존 피드백 경로에서 확인할 수 있게 한다. 세부 설명을 카드 본문에 길게 다시 넣지 않는다.

### 4.4 덱·효과·저장 연동

덱 안에서는 한 사본을 한 장으로 취급한다. 겸용이라는 이유로 덱 수, 보상 후보 수, 추첨 결과를 두 장처럼 중복 집계하지 않는다. 문장 사용 품사에 따른 채점은 확정된 분석 결과를 따르되, 전투 밖 품사 탐색·추첨까지 임의로 양쪽 품사에 확대하는 기능은 추가하지 않는다. 관련 코드의 영향을 점검하고 기존 주 품사 기반 규칙은 보존한다.

신규 원정 생성기가 레거시 고정 풀·버전별 풀·캐시를 참조하는지 확인한다. DB의 시작 가능 플래그만 바꾸고 실제 시작 덱에서 여전히 나오는 상태를 완료로 보지 않는다. 전투 보상에서 실제로 선택·획득·사용할 수 있고, 상점 등 다른 신규 입수 경로에는 나오지 않는지 검사한다.

기존 원정에 있는 help를 제거하지 않는다. 저장·불러오기 후 카드 정체성, 사본 수, 연마 상태와 겸용 판정이 유지되어야 한다. 다른 단어에는 새 명사·동사 용법을 자동 등록하지 않는다.

## 5. 손패 정보 간소화

### 5.1 운영 카드

손패에서는 카드 이름과 작은 **‘전투당 1회’**를 중심으로 표시한다. 긴 효과 설명은 상세 보기로 옮긴다. 기존에 필요한 사용 가능·불가 등 상태 표시는 유지하되 손패에 운영 설명을 다시 길게 싣지 않는다.

효과, 사용 횟수, 사용 조건, 교환 가능 여부는 변경하지 않는다. 상세를 여는 동작과 실제로 사용하는 동작을 혼동하거나 동시에 실행하지 않게 한다.

### 5.2 빙정 카드

손패에는 이름과 최소한의 식별·상태 정보를 표시하고, 효과·전투 한정 여부·사용 조건 등 자세한 설명은 상세에서 제공한다. 빙정의 수급, 소모, 지속, 문장 사용, 보스 상호작용을 변경하지 않는다.

거울뿔 사슴의 핵 파괴 대상 빙정과 지원용 빙정은 상세 설명에서 실제 효과가 정확히 구분되어야 한다. 이 작업을 이유로 새 공략 표시나 보스용 보조 기능을 추가하지 않는다.

### 5.3 방해 카드

검은 먼지의 카드 이름은 유지하고 공식 표시 카테고리는 **‘방해’**로 통일한다. 긴 효과는 상세로 옮긴다. 명칭 변경을 이유로 효과를 약화·강화하거나 교환·제거·지속 규칙을 변경하지 않는다.

### 5.4 상세 보기와 조작 보존

기존 상세 열기 동작 또는 정보 아이콘을 이용하여 클릭·터치로 전체 내용을 확인할 수 있게 한다. 마우스 hover만 가능한 설명으로 대체하지 않는다.

상세를 열고 닫아도 선택 카드, 조합대, 카드 순서, 턴, 행동 횟수가 바뀌지 않아야 한다. 기존 클릭·드래그·형태 변경·교환 조작을 정보창이 가로채지 않게 한다. 손패 폭과 카드 크기를 유지하고 정보량을 줄여 가독성을 확보한다.

## 6. 희귀도와 연마 디자인

### 6.1 WORD 카드의 희귀도

| 요소 | 적용 규칙 |
|---|---|
| 바탕 | 기존 상아색 유지 |
| 상단 | 기존 주 품사색 유지 |
| 일반 | 기존 디자인 유지 |
| 고급 | 은빛 테두리로 구분 |
| 희귀 | 세공·문양이 있는 금빛 테두리로 구분 |

테두리로 희귀도를 나타내며, 카드 바탕 전체를 금색·은색으로 바꾸거나 품사색을 덮지 않는다. 다른 종류의 특수 카드까지 근거 없이 같은 WORD 디자인으로 통일하지 않는다. 단어·형태·상태 정보를 읽기 어렵게 만드는 장식은 넣지 않는다.

### 6.2 연마

+1·+2·+3의 단계별 배지는 카드의 품사색을 따른다. 숫자 또는 단계 표시는 실제 연마 상태와 일치해야 한다. 최고 단계 +3에는 희귀도 테두리와 겹치지 않는 **카드 안쪽의 품사색 장식**을 더한다.

희귀도와 연마는 별개의 정보다. 고급·희귀 여부와 관계없이 연마 단계를 구분할 수 있어야 하며, 연마로 희귀도 테두리가 사라지지 않아야 한다. help는 주 품사가 동사이므로 동사색을 기준으로 하고 `동·명` 배지와 충돌하지 않게 한다.

배지의 정확한 문양·픽셀 치수는 회의에서 확정되지 않았다. 현재 디자인 안에서 구현하되, 새 등급 체계·연마 단계·능력치 효과로 확장하지 않는다.

## 7. 라운드·스테이지 문법 안내

### 7.1 수급 안내와 학습 안내 분리

별길 낙타 아래 점수·안내 영역의 “입장 준비: enjoy · 지급은 원정당 한 번입니다.”와 같은 상시 수급 안내는 제거한다. 부족한 기본 재료를 기존 조건에 따라 지급하는 기능과 원정당 지급 제한은 그대로 둔다.

지급 사실은 기존 지역 입장 화면 또는 짧은 획득 알림에서 한 번 안내한다. 추가 지급, 중복 알림, 새 상점·새 보상 절차를 만들지 않는다.

### 7.2 기본 안내 구조

문장 편집 단계에는 다음 정보를 분리해 읽을 수 있게 한다.

| 정보 | 표시 원칙 |
|---|---|
| 이번 라운드의 학습 주제 | 익숙한 정식 문법명 |
| 형태 | 필요한 경우 대표 형태를 짧게 병기 |
| 한 줄 설명 | 교과서처럼 짧고 정확하게 |
| 지역 보너스 | 실제 적용되는 문법 대상과 배율 |

학습 주제와 보너스 규칙은 다르다. 특정 용법을 소개하는 라운드라는 이유로 그 용법에만 별도 보너스가 있는 것처럼 표시하지 않는다. 공격 시작 후에는 같은 영역에 기존 점수·콤보·피드백을 표시하고, 다음 문장 편집 단계로 돌아오면 학습 안내로 복귀한다. 기존 결과 읽기 시간과 연출을 줄이지 않는다.

제출 전에 정답 여부·예상 점수·성공할 콤보를 보여주지 않는 원칙을 유지한다. 일반 학습 안내는 현재 조립 문장을 분석해 주는 실시간 정답 힌트가 아니다.

### 7.3 사막 안내 문안

다음은 첨부 회의의 제안을 정리한 교체 기준이다. 실제 라운드 학습 데이터와 대응을 확인한다.

| 전투 | 제목·형태 | 한 줄 설명 |
|---|---|---|
| 별길 낙타 | to부정사의 명사적 용법 (to + 동사원형) | ‘~하는 것’이라는 뜻으로 명사 역할을 합니다. |
| 금빛 전갈 | to부정사 (to + 동사원형) | 명사를 꾸미거나, 행동의 목적을 나타냅니다. |
| 별꽃 선인장 | 동명사 (동사원형 + -ing) | ‘~하는 것’이라는 뜻으로 명사 역할을 합니다. |
| 신기루 여우 | 5형식 (S + V + O + C) | 목적격보어가 목적어의 상태나 동작을 설명합니다. |

사막의 지역 보너스는 회의 기록상 “to부정사·동명사·5형식 ×1.25”다. UI는 실제 보너스 데이터를 참조하여 표시하고, 라운드별 배수를 새로 만들지 않는다. 소스 값이 기록과 다르면 문구에 맞추기 위해 밸런스를 조정하지 말고 불일치를 보고한다.

### 7.4 용어와 설명의 정확성

“to구”, “명사 뒤 to구 · 목적을 설명하기”처럼 짧지만 모호한 표현을 피한다. to부정사와 to부정사구 등 필요한 정식 용어를 사용한다. 명사를 꾸미는 형용사적 용법과 행동의 목적을 나타내는 부사적 용법을 하나의 조건처럼 섞지 않는다.

상세 설명에서는 회의에서 제시한 예시처럼 구분한다.

- `I have a book to read.`: 명사를 꾸미는 용법.
- `I went to the park to read.`: 행동의 목적을 나타내는 용법.

설명 예문은 전투에서 해당 카드를 지급하거나 새 구문을 지원하라는 지시가 아니다. 실제 게임에 넣는 예문은 해당 안내의 지원 범위와 일치하는지 검수한다.

### 7.5 적용 범위

Stage 1~8의 라운드 안내·지역 보너스 표기·관련 도감 제목을 같은 원칙으로 검수한다. 사막만 고치고 다른 지역의 혼란스러운 문구를 남기지 않는다. 내용의 일관성을 맞추되 기존 커리큘럼·보너스 대상·배율은 바꾸지 않는다. 보스에서는 일반 학습 설명보다 실제 처치 조건을 우선 안내한다.

## 8. 보스 설명 정리와 거울뿔 사슴 보존

### 8.1 보스 설명 공통 원칙

전투 화면에는 “보스의 특징 → 해야 할 행동 → 처치 조건”이 짧고 자연스럽게 읽히도록 작성한다. 내부 판정 조건·예외·계산식은 상세 설명에서 확인하게 한다. 화면에서 설명을 줄였다는 이유로 상세에서도 중요한 예외를 삭제하지 않는다.

보스 설명을 RPG다운 문장으로 다듬는 것과 공략 규칙을 바꾸는 것을 분리한다. 보스 공급 카드, 보호, 피해·승리 조건은 보존한다.

### 8.2 거울뿔 사슴 기본 문안

> 거울뿔 사슴의 뿔에는 신비로운 빙결핵 5개가 빛나고 있습니다.
>
> 이번 전투에서 얻은 핵 파괴 효과가 있는 빙정을 올바른 문장에 넣어 공격하면, 사용한 빙정 한 장마다 빙결핵이 하나씩 깨집니다.
>
> 모든 빙결핵을 깨뜨리기 전에는 거울뿔 사슴을 쓰러뜨릴 수 없습니다.

이는 기존 설명을 간소화한 구현용 문안이다. “핵 파괴 효과가 있는”은 지원용 빙정까지 모두 파괴 카드로 오해시키지 않기 위한 설명이며 새로운 카드 카테고리가 아니다.

### 8.3 그대로 유지할 상세 규칙

| 항목 | 보존 조건 |
|---|---|
| 빙결핵 | 5개 |
| 빙정 공급 | 기존 수량·타이밍 유지 |
| 파괴 대상 | 이번 전투에서 지급된 than·as 두 사본·more·most·too·enough·twice의 해당 빙정 사본 |
| 공격 조건 | 문법적으로 성립한 양수 피해 공격에 실제 사용되어야 함 |
| 파괴 계산 | 실제 사용된 대상 사본마다 핵 1개 |
| 비교 문장 여부 | 비교 문장일 것을 새 필수 조건으로 추가하지 않음 |
| 제외 대상 | 일반 영구 카드 및 지원용 the·to·good |
| 보호 | 핵이 남아 있으면 HP가 1 아래로 내려가지 않음 |
| 격파 가능 시점 | 마지막 핵을 깨는 공격부터 격파 가능 |

동일한 철자의 영구 카드와 전투용 빙정을 구분한다. 보호 해제 시점을 다음 공격으로 지연시키거나, 마지막 핵 파괴만으로 남은 HP와 무관하게 즉사시키는 변경을 하지 않는다. 소스와 회의 기록의 불일치는 별도로 보고하고, 난이도 조정으로 해결하지 않는다.

### 8.4 이번 패치에 넣지 않는 항목

핵 수·빙정 공급량·파괴 조건·HP 보호를 변경하지 않는다. 실패 문장을 인정해 주거나 `She is more than the problem.`에 특별 통과 규칙을 만들지 않는다. 앞서 제안만 했던 ◆ 핵 파괴 표시, 공략 자동 추천, 제출 전 성공 여부 표시는 확정 요구가 아니므로 추가하지 않는다.

## 11. 최종 산출물과 완료 보고

수정된 실제 소스와 변경 요약, 문법 감사표, 추가·변경 테스트, 테스트·브라우저·빌드 결과, 화면 검증 자료, 기존 저장 호환 결과를 제공한다. 화면 검증에는 운영·빙정·방해 손패, 희귀도·연마 조합, help, 사막 안내와 사슴 설명을 포함한다.

최종 보고는 다음 상태를 구분한다.

| 상태 | 의미 |
|---|---|
| 구현·검증 완료 | 수정했고 해당 검증을 실제 수행함 |
| 구현 완료·검증 미완료 | 코드는 수정했으나 해당 검증을 끝내지 못함 |
| 미지원 유지 | 이번 범위 밖이므로 기존 지원 범위를 유지함 |
| 미재현·미확정 | 필요한 조건이나 원인이 아직 확정되지 않음 |

실행하지 않은 테스트를 PASS로 보고하지 않는다. “전체 영어 문법이 완벽하다” 또는 “가능한 모든 문장을 검사했다”고 표현하지 않는다. 현재 지원 범위와 실제 검증한 내용을 보고한다.

버전 표시는 검증된 산출물과 일치하도록 0.8.1로 갱신한다. 실제 커밋·push·PR·merge·배포는 해당 작업에서 주어진 지시에 따라 수행하고, 이 명세 작성 자체를 배포 승인이나 배포 완료로 취급하지 않는다.

## 12. 최종 경계

0.8.1에서 확정한 것은 **문법 판정 정밀화, help의 제한적 겸용 및 획득 개편, 손패 간소화, 희귀도·연마 시각화, 문법 안내 정리, 보스 설명 간소화**다.

문법을 쉽게 통과시키는 패치, 사슴 공략을 쉽게 만드는 패치, 겸용 카드 시스템을 전 단어로 확대하는 패치가 아니다. help 이외의 추가 겸용, 비교급 범위 확장, 보스 공략 보조 기능, 새로운 밸런스·콘텐츠는 후속 논의 없이 포함하지 않는다.
