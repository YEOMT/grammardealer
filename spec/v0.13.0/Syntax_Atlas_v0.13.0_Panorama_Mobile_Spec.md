## 0. 한 문장 목표

**기존 판타지 일러스트·카드 디자인·게임 규칙을 유지한 채, 전투 준비 화면에서는 1900×330 내외의 기존 전투 파노라마를 원본 비율로 펼치고 중앙 몬스터(보스는 훨씬 크게)를 보여준다. 모바일은 로비에서 결과·상점·전투까지 가로 방향으로 통일하고, 상단의 몬스터와 배경을 충분히 보존하면서 하단 문장 조합·손패 페이지·룬·공격을 손가락으로 편하게 조작할 수 있도록 배치한다.**

### 0.1 이 명세에 포함하는 것

1. 전투 **준비/다음 전투** 화면 (`renderBetween`, `BETWEEN_BATTLES`)의 파노라마+몬스터+하단 정보 재배치. PC·태블릿·모바일 공통 적용.
2. **모바일 핸드헬드 가로 화면**에 한정한 전투·로비·지역 입장·상점·보상·지역 클리어·결과·덱/도감/사전/저장/설정 모달의 반응형 배치.
3. 전투 상단의 압축 HUD·몬스터 양옆 정보, 문장 조합대의 점진적인 카드 크기 조정, 옆 룬, 손패 페이지 전환.
4. 전체 게임 흐름의 가로 방향 안내·수동 회전 fallback, 0.12.2 터치 안정화 회귀 검사.
5. 파노라마 이미지 미등록 지역의 **지역 팔레트 기반 fallback**과 안전한 화면 정리.

- `src/main.js`와 `AGENTS.md`: 기존 배포/상태 관리 계약을 따른다. 먼저 `README.md`, `docs/PROJECT_HANDOFF.md`, `docs/ARCHITECTURE.md`를 읽는다.

# A. 전투 준비 화면 — 원본 파노라마 + 중앙 몬스터 + 하단 정보

## A1. 적용 범위와 화면 구조

이 화면은 **전투가 시작되기 직전의 `BETWEEN_BATTLES` 준비 화면**을 우선 대상으로 한다. 사용자가 말한 ‘전투 입장 화면’은 이 화면을 의미한다. 기존 `STAGE_INTRO`의 **지역 입장 전경(entry)**은 그대로 보존하며, 별도의 전투 단계·확인 버튼을 새로 끼워 넣지 않는다.

정상 가로 화면 배치:

```text
┌──────────────────────────── 지역/전투 진행 표시 ────────────────────────────┐
│                                                                          │
│  [기존 combat 파노라마 전체 폭 — 원본 비율 유지 / 여백은 지역 팔레트]        │
│                         [중앙 일반 몬스터]                                │
│                    [보스라면 훨씬 크고 위압적으로]                         │
│                                                                          │
├──────────────────────────────────────────────────────────────────────────┤
│   몬스터 이름 · 일반/보스 구분 · 전투 번호                                │
│   목표 문법 / 형태 / 뜻 / 예문 / 실제 전투 효과 / 핵심 보스 기믹            │
│   덱 n장 · 룬 n개 · 보유 골드                                              │
│                [다음 전투]      [여기서 저장]                              │
└──────────────────────────────────────────────────────────────────────────┘
```

상단의 파노라마와 몬스터가 시각적 중심이며, 하단은 **전투 정보와 행동 버튼을 빠르게 읽는 공간**이다. 하단 정보가 모자란 경우 **하단 정보 영역 내부만 스크롤 가능**하게 한다. 다음 전투·저장 버튼은 항상 접근 가능해야 한다. 다른 화면의 전투 슬롯을 밀거나 현재 PC 전투 레이아웃을 바꾸지 않는다.

## A2. 전투 배경 파노라마 — 절대로 자르거나 늘리지 말 것

1. `SCENE_ASSETS[stageId].combat`가 있을 때 **기존 실제 전투 배경을 그대로** 사용한다. 원본이 약 `1900×330`과 같은 긴 파노라마이므로, 전체 폭을 균일한 비율로 축소·확대해 사용한다.
2. **`object-fit:contain`에 준하는 비율 유지**: `<img width:100%; height:auto>` 또는 배치 측정에 맞춘 동등한 방식. `cover`, 왜곡되는 독립 `width`/`height`, 좌우·상하 crop, 임의 중앙 확대는 금지.
3. ‘화면에 쭉 깐다’는 뜻은 **현재 화면에서 사용 가능한 가로 폭에 원본의 좌우 끝까지 보이게 배치**한다는 의미이다. 여백이 생기면 잘린 것처럼 보이지 않도록 주변·아래의 **기존 지역 테마 색상으로 연결**한다.
4. 파노라마 아래·좌우 여백에 지역별 **단색/절제된 그라데이션**만 사용한다. 새 에셋 없음. 초원은 녹색·올리브, 항구는 청록·남청·청동처럼 기존 스테이지 팔레트에서 파생하되, 이미 정의된 `data-stage-theme` / CSS 토큰을 우선 재사용한다.
5. 실제 이미지가 로딩되기 전·누락·실패한 경우에도 대비 있는 지역색 fallback을 즉시 보여준다. 고장 난 이미지 아이콘이나 투명한 공백만 남기지 않는다. 없는 Stage 3~10 그림을 가짜로 대체하거나 Stage 1 그림을 재사용하지 않는다.
6. 고해상도 기기에서도 같은 원본 이미지 한 장만 사용한다. 너비·시점·재개·화면 회전이 변경돼도 재다운로드·재장착·깜박임이 불필요하게 반복되지 않게 한다.

## A3. 중앙 몬스터와 보스의 실제 크기

1. `next.enemyId`의 기존 투명 PNG 기본 이미지를 파노라마 위 별도 계층에 둔다. 이미 저장된 `MONSTER_ASSETS.bounds`를 참고해 **투명 캔버스 여백이 아닌 실제 보이는 몸체**를 기준으로 정렬한다.
2. **일반 몬스터는 충분히 크고 선명한 몸 전체가 보이게**, 지역 보스는 일반 몬스터 대비 **실제 몸체 크기 약 2배 목표**로, 가능한 안전 영역 내에서 더 큰 위압감을 주도록 한다.
3. 보스가 원래 가로로 넓거나 크기가 다를 때는 개별 bounds/anchor로 제한한다. 머리·촉수·무기가 자르지 않고, 안내문·상단 nav·하단 버튼을 침범하지 않아야 한다. 목표 배율보다 안전한 표시가 우선이다.
4. 몬스터는 시각적으로 **파노라마의 중앙**에 접지한다. 파노라마 띠보다 몸체가 클 때는 위로 자연스럽게 돌출 가능하나, 배경을 늘려 빈자리를 메우지 않는다.
5. 이미지의 표시 크기 계산이 0.12.1 전투 보스 스케일/타격 위치를 변형하지 않도록 `preview` 전용 계산으로 분리한다. 프리뷰는 공격/피격 애니메이션을 하지 않는다.
6. 몬스터 PNG가 없는 미래 스테이지에서는 기존 emoji fallback을 보여준다. 없는 몬스터 파일을 생성하지 않는다.

## A4. 하단의 반드시 유지할 정보

우선순위: **몬스터 이름 → 목표 문법 → 형태 → 뜻 → 예문 → 전투 효과 → 보스 핵심 기믹 → 보유 덱·룬·골드 → 다음 전투/저장**.

- 데이터는 기존 `preparationGuide(preview)`의 `targetLabel`, `patternKo`, `meaningKo`, `example`, `effectLabel`, `boss`를 그대로 사용한다. HTML에 임의로 `4형식`을 박아넣지 않는다.
- ‘목표 문법’은 권장 목표와 실제 보너스·보스 방어 해제 조건을 **같은 말로 뭉개지 말고** 현재 데이터에 맞게 구분한다.
- 보스 기믹은 한눈에 볼 수 있는 **짧은 요약은 표시**하고, 긴 설명은 펼쳐보는 상세 영역 또는 기존 팝업으로 제공한다. 설명 데이터 삭제 금지.
- `여기서 저장`은 `다음 전투`보다 보조적인 시각 계층이되, 숨기거나 삭제하지 않는다.
- `NEXT_BATTLE` 명령은 기존 handler로만 1회 처리한다. 더블 탭으로 두 번 이동하거나 카드·재화가 중복 지급되면 실패다.
- 초원 0.12 명령문 안내 등 기존 조건부 공지, 덱/룬/골드, 진행 회차도 여전히 접근 가능해야 한다.
- `STAGE_INTRO`의 지역 입장화면은 기존 entry 배경을 유지한다. 새로운 배경이 없는 미래 지역은 기존 fallback 유지.

## A5. 반응형 준비 화면 원칙

- **PC 및 태블릿 가로:** 파노라마 상단, 중앙 몬스터, 정보 하단. 충분한 여백 확보.
- **휴대폰 가로:** 같은 3단 구성. 파노라마가 원본 종횡비 때문에 얇게 표시되므로 **그림 자체를 늘리지 말고**, 몬스터가 조금 위로 올라올 수 있다. 하단 정보는 compact 2열 또는 줄바꿈, 필요하면 내부 스크롤. 행동 버튼은 하단 안전영역에서 터치 가능.
- 화면 높이가 짧은 경우에도 `다음 전투`와 `저장`을 화면 밖에 숨겨놓지 않는다. 중복 스크롤(문서와 정보 패널 두 곳이 동시에 스크롤)도 피한다.

# B. 모바일 전 화면 가로형 UI

## B1. 적용 대상 및 장치 판정

1. **스마트폰 접속 시 로비·난이도/프로필 선택·지역 입장·전투 준비·전투·보상·상점·지역 클리어·결과·모달 등 전 게임 흐름을 가로형으로 설계**한다. 중간에 세로 화면으로 돌아갈 필요가 없게 한다.
2. 가로 안내는 현재 `orientation.js`의 `needsRotation`과 gate를 확장하되, **전투 화면만** 조건으로 삼던 로직을 전체 게임 루트에 안전하게 적용한다. 화면 전환, modal, 로딩, 저장 불러오기에서도 방향 안내가 뒤에 남아 UI를 막아서는 안 된다.
3. iOS Safari·Android Chrome·카카오톡 인앱처럼 방향 잠금/전체화면 요청을 거부할 수 있는 브라우저에서는 **가로 회전 안내 + 직접 회전 fallback**을 제공한다. 전체화면·방향 잠금을 자동 반복 요청하지 않는다. 실제로 기기 회전이 불가능한 환경에서 앱·저장 접근이 영구 봉쇄되지 않도록 탈출/안내 경로를 마련한다.
4. PC는 화면이 좁아졌다는 이유만으로 터치폰 전용 배치나 강제 회전 gate를 적용하지 않는다. **실제 coarse pointer/터치 가능 여부 + CSS viewport 크기 + landscape 상태**를 함께 판정한다. 태블릿(충분히 넓은 화면)은 기존 PC/패드 레이아웃을 우선 유지하되 가로 방향을 기본으로 안내한다.
5. `visualViewport`, notch / safe-area, 브라우저 바/키보드에 따른 실제 가용 높이를 반영하되, 브라우저 확대/스와이프를 막기 위한 0.12.2 입력 설정을 덮어쓰지 않는다. 포인터·드래그·줌·모달 내부 스크롤은 제스처별로 분리한다.

### 화면 전반의 디자인 규칙

**기존 진한 녹색·지역 팔레트, 크림색 품사 카드, 기존 라벨·폰트·보석·몬스터·그림체는 유지한다.** 스마트폰용 추가 메뉴·접기·페이지 컨트롤은 기존 컴포넌트/스타일을 재사용한다. 타 게임 스타일로 바꾸지 않는다.

## B2. 전투 화면 — 중앙 몬스터를 보여주는 상단

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ STAGE/지역                        턴 · 교환 · 골드   [소리] [전체화면] [메뉴] │
│ ┌ 목표 문법·보너스 ┐       [중앙 몬스터]          ┌ 이름·HP·보스 상태 ┐ │
│ └ 간단 공략       ┘       [기존 전투 배경]       └ 기믹 요약/상세   ┘ │
├──────────────────────────────────────────────────────────────────────────┤
│ [문장 점수/채점 시 표시]                                              │
│ [문장 조합대 — 순서 보존, 카드 수 증가에 따라 자동 축소]  [장착 룬 레일] │
│ [비우기]             [공격 확정]       [턴 넘기기]                    │
├──────────────────────────────────────────────────────────────────────────┤
│ 손패  n/m    [◀ 이전]   [손패 카드 5~7장]   [다음 ▶]                   │
│ 드로우·버린 카드 / 선택 해제 / 버리기                               │
└──────────────────────────────────────────────────────────────────────────┘
```

- 기존 전투 배경·몬스터는 계속 보여주되 **몬스터를 상단 중앙의 주요 시각 요소**로 둔다. 좌측 문법 목표, 우측 이름·HP 바·보스 상태는 **좁고 반투명한 요약 영역**으로 정리한다.
- 상단 우측의 compact HUD는 사용자가 좋다고 평가한 아이디어를 따른다. 남은 턴, 교환, 골드, 사운드, 메뉴를 쉽게 볼 수 있게 한다. 기존 메뉴의 사전·도감·공격기록·덱·저장·설정 진입 가능성을 모두 유지한다.
- 긴 보스 기믹/진행 수치는 핵심 상태만 상단에 상시 표시하고 원문 설명은 상세 버튼/패널에서 읽게 한다. **HP 잠금·보호막 해제·빙결핵·페이즈 정보 등 공략에 필수적인 상태를 아예 감추지는 않는다.**
- 공격 애니메이션·룬 발동·점수 오버레이가 UI 변화 때문에 몬스터나 카드/버튼 뒤로 숨지 않도록 앵커·z-index를 재계산한다. 게임에 새로운 FX는 만들지 않는다.

## B3. 조합대 — 실제 12장과 24장을 유지하면서 점진적 축소

사용자가 확정한 핵심: **빈 조합대에서 첫 카드들은 비교적 크게, 카드가 추가될수록 카드와 글자가 과도한 단계 점프 없이 점진적으로 축소되어 최대 12장이 한 묶음으로 보이게 한다. 13~24장은 기존 순서대로 두 번째 12장 묶음으로 이어진다.**

- `sentenceRows`/`observeBoard`를 기준으로 **12장 + 12장, 물리적 카드 순서·ID·absoluteIndex 유지**. 드래그·교체·회수·형태 변경·자리 바꾸기의 대상은 항상 실제 카드 하나다. 가짜 카드 복제, 일부 카드를 DOM에서 버림, 새 `RunState` 금지.
- 모바일 보드 안에서 실제 사용 가능한 폭·높이, 룬 레일 폭, 여백, 카드 개수, 단어 길이까지 고려해 `--mobile-card-width` / 비례 폰트/형태 버튼 크기를 계산한다. 카드 6→7→8장 전환에 급격한 폭 점프가 일어나지 않게 제한한다. 기존 데스크톱의 `--board-scale` 경로는 보존한다.
- **가로로 넉넉한 휴대폰에서는 한 줄 12장씩 × 최대 2줄**을 기본 시각 형태로 한다. **가로 폭이 극히 좁아 12장을 억지로 넣으면 영어 단어가 읽히지 않을 경우**, 전체 12장에 접근 가능한 좁은 화면용 6×2 임시 행 배치 등 검증된 가독성 fallback을 허용한다. 이 예외는 *가독성 위반을 감추기 위한 자동 축소*를 피하기 위한 것이며, 12장 동시 확인·최대 24장 조합 기능은 반드시 보존한다. fallback을 사용했다면 해당 화면 폭과 이유를 결과 보고서에 남긴다.
- 카드 텍스트를 자동 줄바꿈해 낱글자를 깨거나 `...`로 생략하지 않는다. 긴 단어가 작은 카드에 들어갈 수 없는 경우 활성 카드/형태 선택에서 **전체 단어를 큰 글씨로 확인할 경로**가 반드시 있어야 한다.
- 현재 **선택 후 버리기**와 **카드를 탭하여 조합**, **드래그 조합/순서 변경/스왑/조합대 회수**, 형태 선택 모달이 모두 작동해야 한다. 카드 아래 정보·형태 버튼이 사라지거나 터치할 수 없게 되면 실패다.
- 파서 미리보기·정답 힌트·공격 전 가상 점수는 추가하지 않는다. 실제 숫자는 기존처럼 공격의 채점 연출 시에만 보여준다.

## B4. 룬 — 조합대 바로 옆에 항상 있는 작은 세로 레일

- PC 우측 룬 패널의 **장착된 룬 실물·순서·발동 강조**를 모바일에서는 조합대 오른편 좁은 레일로 표현한다. 좌측 상태 패널을 모바일 상단 HUD로 정리해 확보한 폭을 이용한다.
- 한 슬롯을 보석 아이콘 + 짧은 룬명/레벨 정도로 압축한다. 터치하면 원래 효과 설명을 팝업/패널에서 읽을 수 있어야 한다. 슬롯이 많으면 **룬 레일 내부만 스크롤**하며 공격 버튼이나 카드 위를 덮지 않는다.
- 기존 룬 순서 교체(▲▼/드래그), 슬롯 활성/비활성, 희귀도·레벨, 룬 발동 효과의 실제 출처를 보존한다. 레일의 상하 시각 순서는 실제 발동 순서와 동일하다.
- 숨긴 룬 때문에 공격 계산이 바뀌거나, 정렬이 잘못 저장되거나, 룬 하나가 중복 표시·발동되는 것은 금지.

## B5. 손패 — 페이지 버튼으로 넘기며 카드 크기는 안정적으로

- 이미 있는 `cardPager()` 기반. **한 페이지에 보이는 카드 수는 실제 공간을 측정해 약 5~7장**, 기기 폭에 따라 조절하며, 손패의 카드가 많아도 텍스트를 지나치게 작게 축소하지 않는다.
- `이전/다음`은 누르기 쉬운 크기로 고정한다. 페이지 상태는 조합·버리기 선택·형태 변경 후 필요할 때 유효 페이지로 보정하고, 숨김 카드를 새로 셔플/드로우하지 않는다.
- 여러 페이지에서 선택한 버리기 카드는 선택 목록/버리기 수와 함께 유지된다. **버리기는 확정 누를 때 정확히 한 번만 처리**된다.
- 카드 탭·드래그·페이지 버튼이 서로 충돌하지 않도록 0.12.2의 입력 취소·중복 처리 방어를 보존한다. 첫 버전은 **페이지 버튼만 필수**이며, 추가 가로 스와이프 제스처는 입력 충돌 위험이 있으므로 필수로 구현하지 않는다.
- 드로우 더미·버린 카드 더미, 교환 남은 횟수, 선택 해제·버리기 버튼은 여전히 접근 가능해야 한다.

## B6. 주요 조작 버튼 및 모달

- **공격 확정**은 시각적으로 가장 분명한 주 행동. `조합대 비우기`, `턴 넘기기`, `버리기`는 원래 의미와 확인·비활성 조건 유지. 버튼을 옮겨도 기존 command를 그대로 호출한다.
- 형태 선택 모달은 0.12에서 크게 조정한 폰트/버튼을 최대한 유지하고, 화면이 짧으면 **본문만 스크롤**하며 모든 형태와 하단 취소/확정이 접근 가능해야 한다. 모달이 뷰포트 아래로 튀어나가거나 화면을 확대시켜 누르는 상황이 없어야 한다.
- 오버레이/공격/보상 중 화면을 회전하거나 화면 크기를 바꿔도 입력 잠금과 표시층이 정상 정리된다. 현재 공격 snapshot과 점수 오버레이의 앵커를 바꾸는 경우 반드시 회귀 검증한다.
- 룬·사전·도감·덱·공격 기록·설정·저장 등은 기존 **동일한 정보와 기능**을 유지하고, 좁은 모바일 가로 뷰포트에서는 팝업 내부 페이지/스크롤을 허용한다.

## B7. **전투 외 모든 흐름** — 전부 가로 화면으로 정리

| 화면 | 가로 모바일 배치 원칙 | 절대 누락 금지 |
|---|---|---|
| 로비/프로필/난이도 | 기존 대표 일러스트·제목과 설정 카드를 가로 2영역 또는 접이식 구성으로 배치, 주 행동 버튼 항상 접근 | 프로필, 난이도, 새 원정/불러오기, 접근성/사운드 |
| 지역 입장 `STAGE_INTRO` | **기존 entry 배경** 유지. 지역 제목·소개·입장 버튼은 작은 높이에서도 접근 | Stage 4/8 입장 선택 모달과 버튼 |
| 전투 준비 `BETWEEN_BATTLES` | **본 명세 A의 파노라마** 적용 | 문법·보스 안내·다음 전투/저장 |
| 상점 `SHOP` | 기존 상품 페이지 활용. 가로폭에 따라 2~3개 이상 볼 수 있도록 하되 구매·취소가 분명 | 골드/가격, 실제 상품 고정, 연마/제거/룬 슬롯 및 선택 |
| 보상 `REWARD` | 3개 보상 선택지(카드/룬/연마/제거)를 가로 3칸으로 우선 표시하고 부족하면 접근 가능한 페이지/스크롤 | 3개 중 1개 선택, 대상 선택, 건너뛰기/저장 |
| 지역 클리어·결과 | 핵심 통계와 다음 지역/새 원정 버튼을 화면 내 또는 안전 스크롤 영역에 배치 | 이력·재도전·저장·이동 |
| 사전/도감/내 덱/공격 기록/저장/설정/확인 모달 | 제목·닫기·본문 스크롤·선택 버튼 배치. 원본 텍스트/카드 표시 | 현재 데이터, 접근성, 저장/불러오기/확인 기능 |
| 튜토리얼/연습 | 말풍선·단계 잠금이 카드/형태 선택을 가리지 않도록 가로 안전영역 사용 | 행동 기반 안내, 스킵, 실제 게임과 동일 입력 |

전투 외 화면을 한 줄 헤더만 바꾸고 '가로 대응 완료'로 보고하지 않는다. **전체 흐름에서 세로 방향을 요구하는 화면이 남지 않는지** 확인한다.

## B8. 화면 해상도·안전 영역 원칙

검증 대상의 예시 CSS 뷰포트(디바이스 스케일과 다를 수 있음): **667×375, 812×375, 844×390, 932×430, 1024×768, 1366×768, 1920×1080**.

- 기기별 단일 하드코딩 숫자로 레이아웃을 유지하지 않는다. `visualViewport`, `safe-area-inset-*`, 내부 스크롤, 사용 가능한 보드 폭을 계측한다.
- 높이가 매우 낮은 환경은 콘텐츠 전체를 물리적으로 한 화면에 고집하지 않고, **문장·손패·공격 핵심 조작은 화면 중심에 유지**, 기타 설명은 내부 스크롤/접기/상세 패널로 처리한다.
- **가로 스크롤을 페이지 전체에 강제하거나, 몸체보다 큰 빈 영역을 만들어 브라우저가 패닝되는 현상**이 있어서는 안 된다.
- 작은 단어 폰트를 강요해서 가독성을 망가뜨리는 것은 실패다. 실제 12/24장 렌더 결과와 `information`, `remember`, `necessary` 같은 긴 단어를 눈으로 확인한다.
- iPad 등 큰 가로 화면은 불필요하게 작은 스마트폰 레이아웃으로 강등하지 않는다. PC/태블릿의 기존 쾌적한 카드 크기를 보존한다.

2. **A 전투 준비 화면부터:** Stage 1/2 실제 파노라마로 가로 띠와 알파 bounds 몬스터, 하단 정보 구현. 배경 실패 fallback, 보스 안전 스케일, PC 화면 검증.
3. **B 가로 UI 지원 범위:** `orientation.js`를 전 화면으로 확장하고, 각 화면에 명확한 모바일 가로 레이아웃 범위를 붙인다. PC/태블릿 기본 상태를 보호한다.
4. **B 핵심 전투:** 상단 HUD/몬스터 양옆, 중앙 보드/우측 룬, 손패 페이지, 주요 버튼, 애니메이션 오버레이 좌표·터치 검증. 기존 핸들러 재사용.
5. **B 보조 흐름:** 로비·지역 입장·상점·보상·클리어·결과·모달/튜토리얼 가로 검증과 필요한 CSS 조정. 콘텐츠·보상 개수 변경 금지.
6. **최종 경량 검증:** 아래 인수 조건, `npm test`, `npm run build`, 관련 브라우저 E2E. 미완료 실기기는 `NOT RUN` 보고. 이상 없으면 개발 브랜치 push 및 PR 생성, merge/배포 금지.

### 변경 예상 파일 (실제 구조에 맞춰 최소로 수정)

`src/ui/progression.js`, `src/services/sceneAssets.js` (필요할 경우 레이어 helper만), `src/ui/learning012.css` 또는 한 개의 별도 scope CSS, `src/ui/responsive.css`, `src/ui/combat.js` (필요한 뷰 재배치 범위), `src/ui/boardLayout.js`, `src/ui/viewport.js`, `src/ui/orientation.js`, 모바일 뷰 관련 브라우저 테스트.

**포함시키면 안 되는 파일의 예:** Grammar/Scoring/Rune/Stage core/balance/draw RNG/saves의 데이터 구조·메커닉 수정. 어떤 파일이 의외로 필요한 경우에는 구현 결과에서 이유를 설명한다.

### 배경 관리와 퍼포먼스

- Stage 1~2의 현존 이미지와 현재 에셋 경로를 사용한다. Stage 3~10 이미지/BGM이 아직 등록되지 않았다고 해서 이번 패치에서 임의 이미지를 만들거나 기존 이미지를 복사하지 않는다.
- 이미 보이는 파노라마는 GPU-friendly DOM 이미지로 표시하고 페이지 이동/리사이즈 때 불필요하게 레이어를 새로 생성하지 않는다.
- 드래그 도중 확대·흔들림이 생기지 않게 기존 gesture 정책 유지. 터치 보정 코드를 두 겹으로 넣거나 전역 `preventDefault`를 추가하지 않는다.

# D. 필수 인수 조건 (PASS / FAIL / NOT RUN)

## A: 준비 화면 (A01–A12)

- **A01** Stage 1·2 전투 준비 화면에서 해당 지역의 **실제 `combat` 배경**이 원본 전체 폭·원본 비율로 표시된다(크롭·비율 왜곡 없음).
- **A02** 배경과 주변·하단 패널의 색이 지역 팔레트로 자연스럽게 연결된다. 다른 지역 그림을 대용으로 쓰지 않는다.
- **A03** 몬스터 PNG는 상단 파노라마 중앙에 보이고 투명 테두리로 인해 비정상적으로 작아지지 않는다.
- **A04** 지역 보스는 일반 몬스터보다 실제 보이는 몸체가 훨씬 크고, 약 2×를 목표로 안전 범위에서 확대된다. 크라켄의 촉수·무기·상단이 잘리지 않는다.
- **A05** 작은 모바일 가로 화면에도 이름·목표 문법·형태·뜻·예문·전투 효과·핵심 기믹·덱/룬/골드가 읽히며 상세 안내를 잃지 않는다.
- **A06** `다음 전투`·`여기서 저장`이 접근 가능하고 클릭/터치 한 번당 원래 행동이 정확히 한 번 처리된다.
- **A07** 전투 준비에서 다음 전투로 넘어갈 때 실제 몬스터·배경·HP와 데이터가 맞으며 화면이 어긋나지 않는다.
- **A08** 미래 지역에 `combat` 에셋이 없으면 스타일 fallback이 보이고 JS 예외·깨진 이미지가 없다.
- **A09** 이미지를 로드하지 못해도 준비 화면 정보·다음 전투·저장 기능은 계속 작동한다.
- **A10** PC 전투·보상·지역 입장 화면의 실제 배경 배치·음악·게임 흐름은 기존과 동일하다.
- **A11** Stage 1과 Stage 2의 일반 몬스터 및 지역 보스 프리뷰가 모두 보이고 프리뷰 인스턴스가 메모리 누수·이벤트 누적을 만들지 않는다.
- **A12** 가로 전체화면/브라우저 모드 및 재시작 후 준비 화면의 파노라마 비율·몬스터 위치가 유지된다.

## B: 모바일 (B01–B22)

- **B01** 휴대폰에서 로비·지역 입장·전투 준비·전투·상점·보상·클리어·결과·설정/덱·모달이 **가로로** 사용 가능하다.
- **B02** 가로 회전 안내는 해당 화면에서 정상 표시/해제되고, 방향 잠금 미지원·인앱 브라우저 거절 시 영구 입력 차단이 없다.
- **B03** PC와 넓은 iPad의 기존 레이아웃/카드·폰트 크기/전투 배경을 의도치 않게 변경하지 않는다.
- **B04** 가로 휴대폰 전투 상단에서 몬스터 몸체가 중앙에 충분히 보이고 지역 배경 노출이 줄지 않는다. 좌우의 문법 목표·HP·필수 기믹 상태도 읽힌다.
- **B05** 상단 우측의 턴·교환·골드·사운드·메뉴와 기존 모든 기록/저장/사전 진입 경로가 제공된다.
- **B06** 조합대 1·5·8·11·12장 단계에서 폭/글자가 점진적으로 맞춰지고 카드 누락·과도한 크기 점프가 없다.
- **B07** 실제 **13장 및 24장**을 순서대로 보여주며 기존 12+12 카드 구조와 문법 적용 순서를 보존한다.
- **B08** 좁은 휴대폰에서도 12장에 접근 가능하고 단어가 극단적으로 작아지지 않는다. fallback을 사용한 경우 화면 폭과 보이는 배치를 보고한다.
- **B09** 긴 단어(예: `information`, `necessary`, `remember`)의 전체 표기를 확인할 수 있고 형태 버튼과 카드 선택 조작에 접근 가능하다.
- **B10** 모바일에서 카드를 **탭해서 조합 / 드래그해서 조합 / 문장 내 순서 변경 / 손패와 스왑 / 원위치 회수 / 형태 선택**할 수 있다.
- **B11** 보드 옆 룬 레일이 실제 장착 순서대로 표시되고, 룬 상세·순서 변경·희귀도·레벨을 확인할 수 있다.
- **B12** 손패 페이지 버튼은 실제 손패의 부분집합만 보여주며 카드 인스턴스·드로우·셔플 순서를 바꾸지 않는다.
- **B13** 여러 페이지에서 버릴 카드를 선택한 뒤 1회 확정하면 정확한 카드만 1회 버린다. 선택 해제·잔여 횟수·버린 카드 더미가 정상이다.
- **B14** 공격 확정·턴 넘기기·비우기·원래 메뉴·룬 정렬의 입력 잠금/비활성 조건이 바뀌지 않는다.
- **B15** 공격 시 점수·룬·카드 집결→돌진·몬스터 피격·HP가 실제 위치에 맞게 보이고, 듀얼 오버레이·유령 카드·클리핑이 없다.
- **B16** 보스 보호막·빙결핵·페이즈 등 기믹이 좁은 화면에서도 표시·상세 접근되고 공략의 보너스/해제 판정은 기존과 동일하다.
- **B17** 상점 페이지·보상 3택·연마/제거 대상 선택·저장/불러오기/사전/도감/결과 버튼이 가로 모바일에서 모두 접근 가능하다.
- **B18** 0.12.2의 더블탭/핀치 확대 방지·멀티터치 취소·드래그 중복 방지가 회귀하지 않는다. 대신 사전 스크롤/설정 슬라이더는 정상이다.
- **B19** BGM 처음 재생·음량/음소거·앱 복귀·지역 전환이 기존 정책을 유지한다. 실기기 청취 미확인은 `NOT RUN`.
- **B20** 667×375, 844×390, 932×430, 1024×768 및 1366×768, 1920×1080에서 페이지 수준의 원치 않는 가로 패닝, 잘린 핵심 버튼, 무한 스크롤이 없다.
- **B21** 보상·상점·전투 중 화면 회전/전체화면 전환/복귀 후 페이지 상태·카드 입력·오버레이가 재진입 가능한 상태로 유지된다.
- **B22** 기존 0.12.2 저장을 불러오고 진행·공격·보상을 이어갈 수 있으며, 새 저장 포맷/게임 규칙 도입 없이 동작한다.

## D2. 검증 범위 제한

- 테스트용 조합 상태·가상 점수 fixture는 **테스트 코드에서만** 사용한다. 일반 UI에 개발 버튼/가상 점수/fixture 라벨을 추가하지 않는다.
- `npm test`, `npm run build`는 필수, 관련 브라우저 검사에서 위 핵심 시나리오만 검증한다. 50전투 전부 자연 완주·전 장치 전수 검사·수백 장 캡처는 요구하지 않는다.
- **기기 에뮬레이션은 실기기 시험이 아니다.** iOS Safari/iPad/Android/Kakao 환경을 직접 실행하지 못했으면 해당 결과를 `NOT RUN`으로 보고한다. 추측으로 PASS하지 않는다.
- 짧은 검증 동안 결과가 달라지면 원인을 기록하고 회귀 우려가 큰 변경부터 철회·수정한다. 테스트를 삭제하거나 기대값을 바꿔 PASS를 만들지 않는다.

## 핵심 최종 문장

> **이 패치는 PC를 새로 그리거나 모바일 게임을 따로 만드는 작업이 아니다.** 현재 신텍스 아틀라스 한 게임의 기존 그래픽·카드·판정·데이터를 이용해, **전투 준비에서는 아름다운 기존 전투 파노라마와 큰 몬스터를 살리고, 모바일에서는 가로 화면 안에 문장·룬·손패·전투 정보가 안정적으로 들어오게 하는 UI 레이아웃 패치**다. 시각적 성취만큼 **실제 카드 조작의 정확성과 기존 시스템 회귀 없음**을 중요하게 취급하라.
