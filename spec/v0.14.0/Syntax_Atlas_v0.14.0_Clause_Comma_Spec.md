# Syntax Atlas v0.14.0 — 쉼표·분사구문·후반 학습 재편

## 0. 문서의 지위와 작업 범위

이 문서는 현재 구현을 교체하는 최초 설계서가 아니라, v0.13.1 이후 소스에 적용할 **신규 원정용 문법·교육과정·보스 패치**다. 작업명 v0.14.0은 이번 문법 확장을 구분하기 위한 제안이다. 이미 같은 버전을 사용 중이라면 충돌하지 않는 다음 버전을 쓰고 모든 새 정책 참조를 일관되게 맞춘다.

작성 시 확인한 기준은 `YEOMT/grammardealer`, `main@cc3b75da280aa93366fa75636c3c970d68621a2a`다. 당시 앱은 0.13.1이고 기존 원정·언어 정책은 0.12.1 계열이다. 실제 구현은 작업 시작 시점의 최신 main, 현재 작업 브랜치, AGENTS.md를 우선 확인한다. 이 해시로 되돌리거나 사용자 작업을 덮어쓰지 않는다.

이번 변경은 다음 네 가지다.

1. **갈색 재사용 문장부호 도구 ‘쉼표’**와 정상적인 절 경계 판정.
2. **현재분사·과거분사 분사구문**의 구조 분석, 학습 안내, 콤보 연동.
3. **43~46전투 학습 목표·몬스터 명칭 재편**, 47전투 운명의 직조자 공략 교체.
4. **48전투 목표 문법 후보 확장**, 새 정책의 저장·기록·랭킹 구분.

현재 UI, 모바일 8열, PC/태블릿 12열, 손패 페이지, 가시 영역 대응, PWA, 오디오, 공격 연출은 보존한다. 신규 pixelfx 도입·배경 제작·UI 리디자인·새 스테이지·신규 룬·전체 단어 풀 재편은 이번 범위가 아니다.

**명세와 검사용 사례를 작성한 것이며, 이 패키지에 실행 가능한 게임 패치나 게임 테스트 통과 결과가 들어 있는 것은 아니다.**

### 1.2 구현 기본안 — 사용자 확정 밸런스와 혼동 금지

아래는 바로 구현을 시작할 수 있도록 정한 제안값이다. 코드의 별도 정책 상수에 두고, 보고서에 ‘초기값’으로 표시한다. 임의로 다른 게임 수치를 재조정하지 않는다.

| 항목 | 기본안 |
|---|---|
| 신규 분사구문 콤보 | 현재분사형·과거분사형 각각 ×1.60, 문장당 해당 구조 1회. 두 유형을 난도만으로 차등 보상하지 않음 |
| 회복 가능한 문장부호 오류 | 공격당 ×0.90 한 번, 정수 내림. 기존 룬 계산 뒤·지역/저항/보스 처리 전에 적용 |
| 새 보스 기믹 | 세 실, 자유 순서, 공격 사이 성공 누적, 미완료 시 HP 1 보호. 추가 피해 감소·회복·시간제한 없음 |
| 한 공격에 여러 목표 성립 | 서로 다른 정상 증거가 있으면 해당 실들을 각 1회 해제 가능. ‘한 공격 한 실’ 제한은 추가하지 않음 |
| 실제 카드 지원 | 기존 공급 정책 안에서 공략 재료를 알리고 확인. 보스전 무료 정답 카드·정답 자동 조합은 추가하지 않음 |
| 쉼표 배치 정보 | 단어 카드와 별도 저장. runtime은 왼쪽 단어 ID에 연결, 제출 시 gapIndex로 고정 |
| 미지원 문장부호 | 새 분사구문은 우선 문두 기본형. 나열·삽입·독립/완료분사구문 등을 틀린 영어라고 단정하지 않음 |

수치에 문제가 있으면 이 표의 값만 좁게 조정 제안하고, 결과를 사용자에게 먼저 인계한다. 밸런스 최적화·수백 seed 탐색을 선행 조건으로 삼지 않는다.

## 2. 반드시 보존할 계약

- 시작 덱 28장과 기존 품사별 배분, 핵심 동사 구성, go/run 중 한 장을 보존한다.
- 손패 한도, 단어 조합대 최대 24장, 기존 단어의 실물 카드 ID 보존을 유지한다.
- PC/태블릿 한 줄 최대 12장·최대 2줄, **현재 스마트폰 한 줄 최대 8장·최대 24장 접근**을 유지한다. 예전 12열 휴대폰 시안으로 되돌리지 않는다.
- 손패는 한 줄 페이지 방식. 카드 밑 여백, 더미 정렬, 원래 영어 글꼴, 단어의 두 줄 표시 금지를 유지한다.
- 공격 중 조합대/손패/몬스터 무대의 구역 크기는 카드 소비 때문에 달라지지 않는다.
- 공격은 확정 결과를 표시한다. 연출 종료·쉼표 UI·화면 회전이 피해를 재계산하지 않는다.
- 문법 → 채점 → 룬 → 지역/보스 → 연출 경계를 보존하고, 상태 변경은 RunController 명령으로만 한다.
- 편집 중 정답 위치·완성 문장·예상 점수·보스 성공 미리보기는 제공하지 않는다.
- 기존 긍정 명령문, 겸용 카드, for/of 의미상 주어, that절·관계절·부사절을 회귀 보호한다.
- 기존 몬스터/배경/BGM 파일은 바꾸지 않는다. 이름 수정 때문에 없는 이미지 파일을 자동 생성·조회하지 않는다.
- BGM 페이드아웃 → 1초 BGM 무음 → 페이드인, 사용자 볼륨, 터치 재생/복귀, PWA/전체화면·주소창 대응을 유지한다.
- 47전투 뒤 최종 상점, 기존 지역 보스 뒤 상점, Stage 4·8 입장 선택과 총 50전투 흐름은 그대로다.
- 구버전 저장을 자동 승격하거나 과거 최고 점수·문장·몬스터 명칭을 소급 변경하지 않는다.

## 3. 쉼표 도구의 공급·수명

### 3.1 해금

새 정책의 원정이 **전체 15전투에 들어갈 때**, 전투 시작 상태 확정과 함께 쉼표 도구를 해금한다. 화면을 열어 보거나 도움말을 보는 것만으로 해금/RNG/카드 지급이 발생하지 않는다.

해금 후 15~50전투의 일반전·지역 보스·최종 보스에서 도구를 계속 노출한다. 저장/로드 후에도 유지한다. 구버전 원정에는 새 기능을 강제로 붙이지 않는다. 새 원정을 시작하면 그 원정의 해금 순서를 다시 따른다; 계정 전체 영구 업적으로 바꾸는 기능은 이번에 추가하지 않는다.

15전투의 첫 설명은 한 번만 짧게 표시한다.

> 쉼표로 앞 절과 뒤 문장을 구분해 보세요. 반복해서 사용할 수 있어요.

고정 예문은 `Because I am happy, I smile.` 등 실제 등록 어휘로 검증한 문장을 사용한다. 도구 해금을 알리는 설명 때문에 새 튜토리얼 단계 전체를 만들지 않는다.

### 3.2 덱과 분리

쉼표는 `WORD` 실물 카드가 아니다. 다음 모든 대상으로부터 제외한다.

- 시작 덱/영구 덱/드로우/버린 카드/사용 완료/실물 카드 보존 집계.
- 손패 한도, 드로우 수, 교환 선택, 덱 압축, 카드 제거, 연마, 판매/구매 후보.
- 일반·고급·희귀 확률, 보상 선택, 상점 상품, 특정 보유 동사 과제.
- 봉인·먼지·빙정 대체·무작위 카드 대상 선택.
- 카드 기본점수, 글자 수, 단어 수, 문장 길이, 품사 수, 드로우·사용량 기반 룬 근거.

‘0점 WORD 카드’를 추가하는 방식은 금지한다. 기본점수가 0이어도 길이 룬·패 크기·보상·봉인에 영향을 줄 수 있기 때문이다.

### 3.3 제출과 정리

손패 옆에는 도구가 계속 남고, 사용하면 조합대에 쉼표 표식 1개가 생긴다. 사용한 도구를 다시 뽑게 하지 않는다.

- 정상적으로 커밋된 공격 뒤에는 조합대의 쉼표 표식을 정리한다. 다음 공격에서 곧바로 다시 사용 가능하다.
- 기존 규칙상 턴을 소비하는 오류 공격도 같은 커밋/정리 계약을 따른다. 오류가 났다고 새 소비 규칙을 만들지 않는다.
- `ENGINE_ERROR`, 입력 검증 거절, 현재 엔진의 비소비 `UNSUPPORTED` 경로에서는 카드·턴·표식을 보존한다.
- 화면 전환/회전/모달 열기/이펙트 취소만으로 도구나 편집 표식을 잃지 않는다.
- 빈 조합대나 쉼표만으로는 제출할 수 없다. 쉼표 설치·이동·회수는 턴/교환/RNG를 소비하지 않는다.

## 4. 쉼표 UI·조작

### 4.1 카드 생김새

| 요소 | 기준 |
|---|---|
| 기본 면 | 따뜻한 밤색·갈색. 예: `#704A2D`, 어두운 면 `#3E291D` |
| 경계 | 밝은 갈색/절제된 황동. 예: `#AF8659` |
| 기호 | 큰 상아색 `,`. 예: `#FFF0CF` |
| 이름 | 쉼표 |
| 부가 표시 | 문장부호 · 반복 사용. 좁은 화면은 상세창으로 이동 가능 |
| 제거할 장식 | 품사 띠·점수·0점·희귀도·레벨·연마·가격·상시 발광 없음 |

색상 값은 조정 가능한 초깃값이다. 기존 품사색을 변경하지 않고 이 도구만 구별한다. 카드 코너·서체 계열은 기존 게임과 어울리게 한다.

### 4.2 손패 옆 고정 보조칸

손패 오른쪽 부근의 독립 보조칸에 둔다. 기존 버린 더미·버리기·페이지 버튼과 겹치지 않도록 **필요한 최소 가로 폭만** 예약한다. 손패 데이터나 페이지 항목에는 끼워 넣지 않는다.

- 모든 손패 페이지에서 접근 가능해야 한다.
- 패가 0장이어도 보조칸과 손패 영역의 외곽 높이는 유지한다.
- PC/패드/스마트폰을 다시 배치하지 않는다. 폭이 부족하면 현재 손패 페이지당 표시 장수만 측정에 따라 줄인다.
- 모바일 도구 버튼의 실제 누를 수 있는 면적은 약 40~44px를 목표로 한다. 겹치는 가짜 확장 히트박스는 금지한다.

### 4.3 배치·이동·회수

1. 도구 탭 → 조합대의 단어 사이 경계 선택. 또는 도구 드래그 → 경계에 놓기.
2. 경계 표시는 ‘놓을 자리’만 안내한다. 정답 위치·문법적 적합 여부는 표시하지 않는다.
3. 이미 쉼표가 있으면 새것을 추가하지 않고 이동한다.
4. 표식을 선택하면 이동/회수 가능. 탭만으로도 가능해야 하며 작은 기호 드래그만 강요하지 않는다.
5. 쉼표 배치 모드에서 단어 카드를 잘못 탭해 회수하지 않도록 모드를 구별한다. 취소하면 기존 편집 상태로 돌아온다.
6. 카드 드래그와 동시에 두 포인터가 활성화되면 기존 입력 취소 규칙을 따른다. 취소 후 잠금·고스트가 남지 않아야 한다.

문장 앞·끝 같은 위치도 사용자가 넣었다면 조용히 정답 위치로 고치지 않는다. 제출 시 오류를 설명한다. 단어가 하나도 없을 때는 배치하지 않고 ‘단어를 먼저 놓아 주세요’ 정도만 안내한다.

### 4.4 조합대의 쉼표는 좁은 표식

일반 갈색 카드 한 장을 통째로 문장 사이에 끼우지 않는다. 기존 카드 사이 간격 또는 앞 단어 끝의 좁은 인접 영역에 기호를 표시한다. **24단어+쉼표**가 가능하며 가로 카드 수는 기존 8/12 기준을 유지한다.

표시를 위해 예약한 폭만 레이아웃 계산에 반영한다. 글자를 가리거나 인접 카드의 형태 버튼을 덮지 않는다. 쉼표를 독립 grid item으로 넣어 9번째/13번째 단어처럼 행을 밀지 않는다.

줄 경계에서는 앞 절의 마지막 단어와 함께 보여 다음 줄 맨 앞에 혼자 놓이지 않게 한다. 모바일 문장 스크롤·손패 페이지·카드 집결에서 표식의 화면 좌표가 데이터상 위치와 어긋나지 않게 한다.

## 5. 편집 데이터와 스냅샷

### 5.1 권장 표현

아래 이름은 예시이며 저장소의 계약에 맞게 조정할 수 있다. 의미와 불변조건은 유지한다.

```js
// 편집 상태: 실제 단어 카드 배열과 별도
punctuation = {
  comma: null
  // 또는 { afterCardInstanceId: 'word-instance-id' }
  // 또는 { afterCardInstanceId: null } // 문장 맨 앞: 제출 시 진단 가능
};

// 새 제출 스냅샷: 쉼표는 WORD 토큰이 아님
{
  schemaVersion: 2,
  languageVersion: '0.14.0',
  orderedTokens: [/* 실제 단어 카드 토큰만, 최대 24 */],
  punctuation: [{ kind: 'COMMA', gapIndex: 2 }]
  // gapIndex = 쉼표 앞에 놓인 단어 수, 0..N
}
```

기존 스키마에 선택 필드를 추가하는 방식도 가능하지만, 새 정책/새 스키마와 과거 데이터를 명확히 식별해야 한다. 모든 구버전 `schemaVersion:1`을 강제로 재작성하지 않는다.

### 5.2 결정적인 위치 규칙

- 일반 재정렬에서는 쉼표가 기준이 된 **왼쪽 카드**를 따라간다. 재정렬 후 어색해져도 자동 교정하지 않는다.
- 그 카드를 회수/제거하면 쉼표 표식도 회수한다. ‘옆 카드쯤’으로 임의 이동하지 않는다.
- 맞교환처럼 같은 슬롯의 단어를 다른 카드로 대체하는 명령은 그 **슬롯 경계**를 유지하도록 새 ID에 연결한다.
- 조합대 전체 비우기/실제 턴 종료의 편집 정리에는 표식 정리가 포함된다. 일부만 회수하면 위의 기준 카드 규칙을 따른다.
- 문장 맨 앞 표식은 첫 단어 변경만으로 사라지지 않지만 모든 단어가 없어지면 정리한다.
- 제출 시 실제 순서를 기준으로 `gapIndex`를 확정하고 이후 UI/연출은 이를 변경하지 않는다.

### 5.3 저장·검증·카드 보존

스냅샷, 입력 지문/fingerprint, 문법 캐시 키, 공격 기록, 최고 문장, 보스 증거, 저장 무결성 검사에 쉼표 위치를 포함한다. 같은 단어 배열이라도 쉼표 위치가 다르면 별개의 입력이다.

반대로 실제 카드의 유일 ID·카드 보존 집계에는 쉼표를 넣지 않는다. 토큰 한도 검사는 단어 토큰 24개와 문장부호 최대 1개를 별도로 한다. `gapIndex` 범위, 종류, 중복, 연결 ID를 검증한다.

정상 게임은 실제 카드 스냅샷+문장부호를 파서에 넘긴다. 테스트용 `snapshotFromText()`에서 쉼표를 지워서 통과시키는 구현은 금지한다. 테스트 변환기도 새 정책에서는 쉼표를 별도 표식으로 보존하고, 구정책의 역사적 해석은 그대로 둔다.

## 6. 문장부호와 절의 판정 범위

### 6.1 이번에 지원할 쉼표 위치

A. 문두 부사절 경계: `Because / When / If + 절, 주절` 등 **이미 지원하는 접속사**.

B. 조건절 선행: `If + 조건절, 결과절`. 결과절이 앞에 오는 기존 무쉼표 형태도 보존한다.

C. 완전한 절의 등위 연결: `독립절, and/but/or + 독립절`. 기존 접속사의 지원 범위만 사용한다.

D. 새 문두 분사구문: `V-ing …, 주절` 또는 `V-en …, 주절`.

쉼표는 접속사·생략된 주어·빠진 동사를 대신하지 않는다. 두 독립절을 쉼표만으로 연결한 `I smile, you run.`은 이번 교육용 판정에서는 연결 구조 오류다. 모든 쉼표 용법을 영어 전체의 절대 규칙으로 단순화하지 않는다. [문법 근거: SOURCES.md W1~W4]

### 6.2 기존 무쉼표 문장을 갑자기 막지 않기

현재 엔진이 이미 허용한 쉼표 없는 유한 부사절·조건절·등위절은 이번 패치로 소급 불성립 처리하지 않는다. 새 쉼표 사용을 선택지로 추가한다.

특히 `I would help you if I had time.`처럼 뒤에 조건절이 오는 정상 문장은 그대로 인정하고 보스 가정법 근거에도 사용할 수 있다. ‘가정법 성공에는 쉼표 카드 필수’라는 규칙을 만들지 않는다.

문두 유한 조건절의 쉼표 생략은 기존 정책과 호환되게 처리하고, 필요하면 제출 후 짧은 표기 안내만 제공한다. 새 분사구문 학습의 경계 요건과 혼동하지 않는다.

### 6.3 오류의 세 단계

| 상태 | 예시 | 처리 |
|---|---|---|
| 정상 | `Seeing you, I smile.` | 구조·역할·쉼표 경계가 정상일 때만 새 콤보/공략 근거 생성 |
| 회복 가능한 표기 오류 | `I, like games.` | 전체 단어 구조는 정상으로 분석할 수 있으나 쉼표 오류 1회 감점. 잘못된 부분에 새 절 보상 금지 |
| 구조 자체 실패 | `I smile, you run.` / `Seeing you, I happy.` | 연결/주절 성립 실패. 기존 불성립 정책을 적용; 쉼표만 지워 정답으로 만들어 주지 않음 |
| 범위 밖이지만 가능한 영어 | 독립분사구문·삽입·후치 분사구문 등 | 명확히 미지원으로 안내. 틀린 영어라는 허위 감점 금지. 기존에 지원하던 것은 보존 |

새 문두 분사구문에서 쉼표가 빠졌을 때, 유일한 분사부/주절 경계를 제한된 파싱으로 확인할 수 있다면 `VALID_WITH_ISSUES` + ‘분사구문 뒤에 쉼표를 넣어 주세요’로 처리한다. 새 분사구문 콤보·보스 근거는 주지 않고 문장부호 오류 감점을 한 번 적용한다. 구조가 모호하거나 주절도 성립하지 않으면 억지로 경계를 발명하지 않는다.

잘못된 위치가 단순 명사절·필수 관계절을 끊는 경우도 해당 구조의 증거를 무효화한다. 정상인 다른 부분까지 전부 제거하지는 않는다. 감점 이유는 제출 후 보여주고 편집 중 판정하지 않는다.

나열/호격/삽입 등의 판정은 새로 구현하지 않는다. 미지원과 실제 오류가 애매한 경우에는 무조건 문장부호 감점으로 처리하지 말고 지원 범위를 명시한다.

## 7. 현재분사·과거분사 분사구문의 실제 구조

### 7.1 공통

이번 필수 범위는 **명시적인 주절 주어에 연결되는 문두의 기본 분사구문 하나**다. 새 분석 노드는 주절의 시제/문형과 독립적으로 분사구문의 종류·절 경계·생략된 주어의 연결을 기록한다.

- 왼쪽에는 동사 카드의 실제 `-ing` 또는 `p.p.` 활용이 있어야 한다.
- 오른쪽에는 정상적인 유한 주절이 있어야 한다.
- 분사구문 안의 목적어·보어·전치사 결합도 해당 동사의 등록 용법을 따라야 한다.
- 생략된 주어는 **주절의 주어 노드**에 연결한다. 주절 목적어나 if절의 주어로 임의 연결하지 않는다.
- 실제로 제출하지 않은 주어 카드나 be/접속사 카드를 만들어 점수/카드 수에 추가하지 않는다.
- 현재분사·과거분사라는 형태 이름을 현재/과거 시제로 판정하지 않는다. 시제는 주절 동사구 등 실제 유한 동사구가 결정한다.
- 의미상 어색함을 임의 감점하지 않는다. 이 분석이 상식적 의미까지 판단하는 완전한 dangling-modifier 검출기라고 주장하지 않는다.

주절의 생략 주어 명령문, 가주어 it 구조, 독립 주어를 가진 absolute 구문까지 이번 새 분사구문으로 억지 확장하지 않는다. 기존 정상 명령문·가주어 구문 자체는 보존하고, 새 복합형은 미지원으로 구분할 수 있다.

### 7.2 현재분사형: 능동 부사적 분사구문

대표 학습형: `Seeing you, I smiled.`

가능한 간단한 예: `Running, I am happy.`, `Reading a book, she smiled.`

동사 `-ing`가 앞에 있다는 이유만으로 인정하지 않는다. 동명사 명사구, 진행형 동사구, 명사 수식 분사와 구별한다. `I am running.`, `I like reading.`, `The smiling student runs.`에는 새 부사적 분사구문 근거가 생기지 않아야 한다.

### 7.3 과거분사형: 수동 부사적 분사구문

대표 학습형: `Helped by you, I smiled.`

가능한 간단한 예: `Helped, I smiled.`, `Made by you, the game is good.`

`by + 행위자`는 선택 요소다. 있어야만 인정하는 규칙을 만들지 않는다. 다만 사용했다면 전치사의 목적격 등 기존 검사를 수행한다.

동사별 수동 가능성을 따르고, 자동사 smile/run의 과거분사를 아무렇게나 수동화하지 않는다. p.p.와 과거형의 철자가 같은 경우 선택 버튼의 내부 ID만으로 강제하지 말고 실제 표면형+문맥에서 구별한다.

`I was helped by you.`는 수동태이고 새 분사구문은 아니다. `tired` 같은 독립 형용사 카드의 철자만 보고 p.p. 동사 증거를 생성하지 않는다. 실제 동사 카드에서 도출된 과거분사 활용과 구분한다.

### 7.4 파서 통합 계약

새 구조의 증거에는 최소한 다음 관계가 있어야 한다.

```text
kind: PARTICIPIAL_ADJUNCT
voice: ACTIVE | PASSIVE
participleCardId / participleForm
adjunctWordRange
commaBoundary (gapIndex)
mainClauseId
controllerSubjectNodeId
validity / issueIds
wordCardIds / evidenceRefs
```

태그 예시는 `CLAUSE.PARTICIPIAL.ACTIVE`, `CLAUSE.PARTICIPIAL.PASSIVE`로 한다. 기존 `PARTICIPLE.*` 명사수식 태그를 재사용해 다른 룬/지역 효과가 오발동하지 않게 한다.

분사구문은 새 유한 주절이 아니다. mainClauseId, 주절 문형, 주절 시제는 오른쪽의 실제 주절을 가리켜야 한다. `clause count`·‘절 두 개’ 등을 검사하는 기존 룬은 **원래 집계하던 절의 종류와 범위를 확인해 보존**한다. 유한절만 세던 룬에 새 non-finite 절을 무조건 더하지 않는다. 기존에 비정형절을 별도로 다루던 룬도 그 명시적 조건을 유지한다.

기존 파서가 처리하는 결과절 선행 가정법과의 결합은 한 가지 이상 지원한다. 예: `Seeing you, I would smile if I had time.`에서 분사구문은 결과절의 I에 연결되고 가정법 근거도 별도로 성립한다. 둘을 결합했다고 두 개의 쉼표를 요구하지 않는다.

입력은 최대 24단어+쉼표 하나이므로 새 문법 분기를 제한적으로 추가한다. 문장별 예외 whitelist, 자연어 AI 호출, 정규식으로 `-ing/p.p. + comma`만 찾는 판정은 금지한다.

## 8. 학습·해금·채점

### 8.1 문법 성립과 보상 해금을 분리

문법 파서는 유효 구조를 분석하고, 기존 `comboEligibility` 계열은 현재 원정의 학습 진행에 따라 점수/공략 자격을 결정한다.

- 쉼표 도구: 15전투 진입부터.
- 현재분사 분사구문 콤보 학습: 43전투 진입부터.
- 과거분사 분사구문 콤보 학습: 44전투 진입부터.
- 가정법은 기존 10지역 capability·재료 해금 정책을 보존하고 45·46전투에서 집중 학습한다. 이미 사용 가능했던 것을 다시 잠그지 않는다.

학생이 앞선 지역에서 구조적으로 옳은 분사구문을 만들었다고 ‘틀린 영어’로 처리하지 않는다. 실제 활용형이 사용 가능하고 구조가 성립하면 문장은 인정하되, 아직 배우지 않은 새 분사구문 배율/공략 근거는 해금 정책으로 제외할 수 있다.

### 8.2 새 콤보

초기값은 두 유형 모두 ×1.60이다. 이름은 `현재분사 분사구문`, `과거분사 분사구문`으로 선명하게 표시한다. 해당 분사부·주절 주어·경계 표식을 **하나의 구조 증거**로 강조하되 쉼표 자체 점수는 띄우지 않는다.

단어 기본 점수와 정상 주절 문형 등 기존 점수는 유지한다. 같은 분사부를 동명사·명사 수식·진행형·수동태 본절로 다시 보상하지 않는다. 그러나 실제 주절에 별도 진행/완료/수동 구조가 있다면 그 독립된 근거의 기존 보상까지 제거하지 않는다.

기존 ‘실제 -ing/p.p. 동사 카드 사용’ 룬은 본래 계약대로 검토한다. 특정 명사수식이나 동명사에만 반응하는 룬을 범용 분사구문 룬으로 바꾸지 않는다. 신규 룬을 만들지 않는다.

### 8.3 문장부호 감점

단어 구조는 회복 가능하지만 배치한 쉼표가 잘못된 경우, 오류를 기록하고 **공격당 ×0.90 한 번** 적용하는 초기안을 사용한다.

- 위치: 기존 grammar/rune 계산 후, 지역 보너스·일반전 저항·보스 판정 전.
- 계산: 저장소의 안전한 유리수 곱셈/내림 함수를 재사용. 독자적 반올림 금지.
- 표기: `쉼표 위치 오류 · −실제 감소량` 및 짧은 이유.
- 감점 순간은 기존 부정적 점수 피드백을 재사용. 축하·돌파 파티클로 표시하지 않는다.
- 신규 분사구문/쉼표 경계의 오류가 있다면 그 근거로 보스 실·48 과제를 풀 수 없다.
- 문장부호 문제와 무관하게 성립한 기존 부분의 점수는 기존 부분 유효성 정책을 따른다.
- `INVALID_CORE`의 0점에 문장부호 감점을 다시 곱해 이중 처벌하지 않는다.

실제 숫자는 예컨대 보정 직전 1,000이면 900이다. 이것은 제안 초기값의 산술 예이지 게임 플레이 측정값이 아니다.

### 8.4 10지역 보너스

현재 지역 배율 ×1.25는 유지한다. 기존 10지역에서 보너스 자격이 있던 현실 조건절·가정법·과거완료는 유지하고 새 두 분사구문을 추가한다. **같은 공격의 지역 배율은 한 번만** 적용한다.

기존에 지역 보너스 대상이 아니었던 현재완료진행을 문구 수정만으로 슬쩍 추가하지 않는다. 준비 화면의 주요 목표는 새 순서로 보여주되 상세 도움말에는 실제 허용 조건 전체를 적는다.

## 9. 43~47전투 확정 라인업

전투 번호는 전체 진행 번호다. 모두 기존 **10지역 ‘별의 회랑’** 안의 다섯 전투이며 새 지역을 만드는 것이 아니다.

| 전체/지역 순번 | 새 이름 | 핵심 목표 | 유지 HP | 아트 방향 메모 |
|---|---|---|---:|---|
| 43 / 10-1 | 춤추는 광대 | 현재분사 분사구문 | 2500 | 춤 동작과 유려한 몸짓, 짧은 별빛 잔상. ‘스스로 하는 동작’의 인상 |
| 44 / 10-2 | 추방당한 왕자 | 과거분사 분사구문 | 2900 | 낡은 왕실 망토·기울어진 작은 왕관, 봉인/추방의 흔적. ‘어떤 일을 당한 인물’의 인상 |

HP·턴·골드·보상·일반전 저항은 바꾸지 않는다. 위 콘셉트는 추후 이미지 제작용 메모이며 이번 패치에서 새 이미지를 생성할 의무가 아니다. monster ID와 배틀 ID는 위치 기반 기존 ID를 보존하고, 새 정책의 이름/목표/아트 매핑을 분리한다.

이름은 전투 준비·실전·도감·기록·지역 안내의 **새 원정 참조**에서 일치해야 한다. 과거 공격의 이름 스냅샷이나 구원정의 상대를 새 인물로 바꾸지 않는다. 아트가 없는 경우 현재의 안전한 placeholder를 쓰되 44 왕자에게 예전 여행자 이미지를 의도 없이 연결하지 않는다.

### 9.1 교체되는 학습 목표

기존 43전투 현실 조건절과 45전투 과거완료의 **단독 학습 자리**를 분사구문 두 자리로 전환한다. 두 문법의 엔진 지원·기존 콤보는 삭제하지 않는다.

현실 조건절은 4지역의 if 부사절 및 10지역 도움말에서 복습한다. 과거완료는 46전투 가정법 과거완료 안내에 `had + p.p.` 선행 설명으로 통합한다. 가정법 과거는 새 45전투로 옮긴다.

### 9.2 기존 앞 지역

7지역의 분사 명사수식·수동태·사역·지각은 유지한다. 8지역 관계절·9지역 명사절/가주어도 이번에 교체하지 않는다. 4지역에는 쉼표 도입과 부사절 앞뒤 배치 예시만 좁게 보강한다.

## 10. 전투 준비·도움말 문구

문구는 짧은 형태와 해석 틀을 유지한다. 몬스터 이름은 위 라인업을 사용하고 기존 파노라마/하단 정보 배치를 보존한다.

### 43 — 춤추는 광대

- 목표 문법: **현재분사 분사구문**
- 형태: `동사-ing …, 주어 + 동사 …`
- 뜻: `~하면서 / ~해서`
- 예문: `Seeing you, I smiled.`
- 전투 효과: `현재분사 분사구문 사용 시 보너스 배율 적용`

### 44 — 추방당한 왕자

- 목표 문법: **과거분사 분사구문**
- 형태: `과거분사 …, 주어 + 동사 …`
- 뜻: `~되어 / ~을 받아`
- 예문: `Helped by you, I smiled.`
- 전투 효과: `과거분사 분사구문 사용 시 보너스 배율 적용`

### 45 — 망상의 순례자

- 목표 문법: **가정법 과거**
- 형태: `If + 주어 + 과거형, 주어 + would/could + 원형`
- 뜻: `만약 ~라면, …할 텐데`
- 예문: `If I had time, I would help you.`
- 전투 효과: `가정법 과거 사용 시 보너스 배율 적용`

### 46 — 후회의 기사

- 목표 문법: **가정법 과거완료**
- 형태: `If + 주어 + had + p.p., 주어 + would/could + have + p.p.`
- 뜻: `만약 ~했더라면, …했을 텐데`
- 예문: `If I had seen you, I would have helped you.`
- 전투 효과: `가정법 과거완료 사용 시 보너스 배율 적용`

반복된 I/you/have 등은 실제 플레이에서 **서로 다른 실물 사본**이 필요하다. 학습 예문이 보인다고 사본을 자동 지급하지 않는다. 최종 예문은 실제 등록 형태로 빠르게 검사한다.

47전투는 세 목표의 완료/미완료와 HP 1 보호를 한눈에 보여준다. 자세한 설명은 기존 공략 상세에서 연다. 현재분사 ‘현재’, 과거분사 ‘과거’라는 잘못된 해석을 붙이지 않는다.

편집 중의 학생 문장을 분석해 정답 예문으로 바꾸는 기능은 추가하지 않는다.

## 11. 47전투 운명의 직조자: 세 실 공략

### 11.1 대체할 것과 남길 것

새 정책에서는 기존 `FATE_FORESIGHT`(직전 주절 문형 기억·같은 문형 차단)를 **세 실 기믹으로 교체**한다. 둘을 동시에 적용하지 않는다. 구정책의 기존 예견은 그대로 실행·검증한다.

새 기믹 ID 예시: `FATE_CLAUSE_THREADS`. 보스 이름과 HP 5000, 전투번호47, 전투 자원·보상은 유지한다.

| 실 | 성공 근거 |
|---|---|
| 행동의 실 | 해금된 정상 현재분사 분사구문 |
| 흔적의 실 | 해금된 정상 과거분사 분사구문 |
| 가능성의 실 | 정상 가정법 과거 또는 가정법 과거완료 |

세 실은 자유 순서로 해제하고 전투 내 공격 사이에 누적한다. 한 번 해제된 실은 회복/턴 넘기기/화면 재생성으로 다시 생기지 않는다. 한 문장에 세 구문을 모두 넣을 필요는 없다.

### 11.2 정확한 해제 조건

- 커밋할 공격의 보스 처리 직전 위력 > 0.
- 실제 구조 분석 증거가 있고 해당 학습/콤보 자격을 만족.
- 그 증거에 해당하는 분사부/주절/조건 구조와 필요한 쉼표 경계가 유효.
- 단순 -ing/p.p. 존재, 쉼표 존재, 높은 점수, 목표와 무관한 1~5형식만으로는 성공하지 않음.
- 같은 목표의 중복 증거는 실 하나에 한 번만 사용.
- 서로 다른 정상 근거를 동시에 만들었다면 복수 실 해제 가능. 이 규칙을 48전투의 ‘한 공격 한 겹’과 혼동하지 않음.

‘가능성의 실’은 현실 조건절·과거완료 단독·진행/완료형으로는 풀리지 않는다. 가정법 결과절이 앞에 있어 쉼표를 쓰지 않은 정상 공격도 자격을 갖는다.

### 11.3 상태 변경과 피해 순서

1. 기존 채점/룬/문장부호/지역/해당 저항까지 계산해 보스 직전 위력을 얻는다.
2. 해당 공격의 정상 구조 근거로 실 해제 후보를 계산한다.
3. **해제 후** 남은 실이 있는지 판정한다.
4. 남은 실이 있으면 HP 하한 1, 모두 해제됐으면 하한 0으로 피해를 적용한다.
5. 공격 결과와 실 해제 영수증을 같은 상태 커밋에 기록한다.

```text
remainingAfter = 아직 해제되지 않은 실의 수 (이번 공격 반영 후)
floorHp = remainingAfter > 0 ? 1 : 0
actualHpLoss = min(preBossPower, max(0, hpBefore - floorHp))
hpAfter = hpBefore - actualHpLoss
killed = hpBefore > 0 and hpAfter == 0
```

보스 HP가 이미 1이어도 **양수 위력+유효 구조**면 실을 해제할 수 있다. 실제 HP 감소가 0이라는 이유로 해제를 막지 않는다. 마지막 실을 해제하는 바로 그 공격부터 격파할 수 있다.

표시 위력을 HP 하한이나 오버킬 때문에 가짜 감점하지 않는다. 실제 HP 감소와 보호된 피해를 분리한다. HP 1에서 실만 해제됐어도 ‘문장 오류/공격 실패’로 잘못 표현하지 않는다.

### 11.4 멱등성과 저장

완료 플래그, 각 실을 해제한 attackId와 evidenceRefs, 처리한 공격 ID를 기록한다. 같은 공격 결과의 재생·중복 명령·로드가 실을 다시 끊거나 피해를 다시 적용하지 않게 한다.

검증기는 실제 제출 스냅샷과 해당 버전 분석 결과로 실/HP 변화의 영수증을 재구성한다. 저장의 완료 Boolean만 믿지 않는다. 기록 보존 수 제한 때문에 최초 해제 근거가 잘리지 않게 보스 전용 compact receipts를 둔다.

### 11.5 표시

예: `행동 ○  흔적 ○  가능성 ●`와 짧은 라벨. 작은 화면에서는 아이콘과 완료 상태를 보이게 하고 상세는 탭으로 연다. 플레이 중인 문장에 대한 실 해제 예상값은 표시하지 않는다.

제출 후 관련 실과 해당 문장 구조만 기존 강조/짧은 빛으로 반응시킨다. 새 pixelfx, 상시 파티클, UI 전체 흔들기, 새 보스 그림은 이번 범위 밖이다.

## 12. 후반 재료 수급과 공략 가능성

현재 10지역 일반전 빙정 지원표는 옛 학습 순서를 전제로 한다. **roundIndex만 유지한 채 기존 if/will/have 지원표를 그대로 두면 안 된다.**

- 새43/44는 실제 동사 -ing/p.p.·정상 주절을 쓰는 학습이다. 자동으로 조건절 재료를 주지 않는다.
- 새45는 이전 가정법 과거 학습의 지원 정책을 목표에 맞춰 옮긴다.
- 새46은 가정법 과거완료 정책을 보존하되 `had`와 `have`에 필요한 have 사본 수를 실제로 계산한다.
- 의미 없는 지원 카드를 무조건 주거나 단어를 자동으로 문장에 삽입하지 않는다.
- 쉼표는 별도 무료 도구이지 빙정/손패 지원량이 아니다.

**47보스에서는 기존처럼 빙정으로 정답 재료를 무료 지급하지 않는다.** 대신 10지역 진입 전 기존 상점/지역 안내와 43~46 준비 화면에서 ‘보스에서는 영구 덱으로 분사구문 두 종류와 가정법을 사용해야 함’을 짧게 알려준다.

새 문법을 공략 목표로 강제하면서 일상적인 플레이 경로에 사용할 수 있는 동사/형태/접속사 공급이 아예 없지 않은지 확인한다. 최소 검증은 세 수준별 대표 실제 덱에서 세 종류의 가능한 문장을 **24단어 이내, 별개 실물 사본, 지원 형태만 사용해** 작성할 수 있는지다.

기존 최종전의 가능 문장 탐색기를 재사용할 수 있으면 범위 제한 하에 재사용한다. 수백 시드·완전 탐색·정답 생성 AI를 새로 만들지 않는다. 실제 witness를 찾으면 ‘가능’, 제한 탐색 실패는 ‘미확인’이지 곧바로 ‘불가능’이 아니다.

대표적인 정상 덱에서 구조적으로 막히는 문제가 확인되면 그 원인을 보고하고 **기존 상점/보상의 관련 재료 노출 조정만** 제안한다. 승인 없이 새 필수 카드팩·무료 보스 사본·추가 상점·자동 통과를 넣지 않는다. 플레이어가 핵심 재료를 의도적으로 제거한 임의 덱까지 승리를 보장하는 기능은 요구하지 않는다.

## 13. 최종 48~50전투 연동

### 13.1 48 서피스 스트럭처

기존 세 과제 범주 FRAME / GRAMMAR / OWNED_VERB, 두 겹 방어막, 중복 범주 제외, 한 공격 한 겹, 턴 종료 회복·먼지·기존 한도 내 빙정 정책은 유지한다.

GRAMMAR 후보에 현재분사 분사구문/과거분사 분사구문을 추가한다. 가정법 후보는 유지한다. 매번 반드시 분사구문이 나오게 하거나, 두 겹을 세 겹으로 늘리지 않는다.

이 원정의 실제 보유 카드와 해금으로 가능한 경우에만 후보에 넣는다. 가능성 판단에 재사용 쉼표를 **별도 사용 가능 도구**로 반영하되 실물 카드 한 장을 빼앗거나 빙정 한도를 써버리지 않는다.

기존 최대 1장/과제·최대 2장/페이즈 등 지원 한도와 정책을 보존한다. 쉼표 포함 새 증거가 과제 계획·선정·해제·로드 검증에서 모두 일치해야 한다.

### 13.2 49 딥 스트럭처

기여도가 큰 공격 룬 최대 두 번 봉인, 자원형 제외, 손패 단어 봉인, 주절 시제 과제, 해방 보너스를 유지한다. 쉼표 도구는 손패 단어 봉인 대상이 아니다.

분사구문의 -ing/p.p.를 주절 현재진행/과거/완료 근거로 잘못 읽지 않는다. 예를 들어 `Helped by you, I smile.`의 주절은 현재형이며, helped라는 글자 때문에 과거시제 해제에 성공해서는 안 된다.

### 13.3 50 유니버셜 그래머

HP 10000의 순수 화력전과 기존 턴 수를 유지한다. 새 실/퀴즈/필수 분사구문을 추가하지 않는다. 배운 분사구문·가정법을 자유롭게 조합해 고점을 만들 수 있다.

최종 지역 표시는 기존 확정 이름 ‘통사의 근원’, 보스 48~50의 한글 이름을 유지한다. raw 데이터의 과거 이름 때문에 이를 이전 표기로 되돌리지 않는다.

## 14. 버전·저장·기록·도감

이번에는 화면만 바꾸는 패치가 아니다. 새 원정은 새 문법/캠페인 정책 식별자를 사용한다. 앱 버전만 0.14.0으로 올리고 run.version은 옛 값으로 두어 새 보스를 구버전 검증기에 넣는 구현은 금지한다.

- 기존 원정은 기존 43~47 목표/예견/점수/공급 정책으로 계속 진행한다.
- 새 원정만 쉼표·분사구문·새 이름·세 실 보스를 사용한다.
- 언어 레지스트리·콘텐츠 manifest·문법 capability·후반 저항·룬 공급·50전투 경계·최종 보스 영수증의 버전 조건을 모두 점검한다.
- 기존 allowlist에 새 버전을 누락해 저항이 사라지거나 47전투에서 끝나는 회귀를 막는다.
- 새 최고 점수/클리어 기록은 바뀐 규칙을 구분한다. 구기록을 재계산하거나 같은 ruleset으로 몰래 합치지 않는다.
- 새 공격 기록에는 실제 쉼표 위치와 실제 제출 문장을 보존한다. 표시 문자열은 `you, I`처럼 쉼표 앞 공백 없이, 뒤에는 한 칸으로 포맷한다.
- 정상·감점·미지원·불성립의 원인을 짧게 기록하고 필요한 경우 상세 구조를 기존 공격 기록에서 확인한다.
- 43~46 이름/목표는 새 정책의 도감·전투 준비·진행 목록과 동일하다. 구기록명은 스냅샷대로 유지한다.

구버전 분기 전체 재작성이나 과거 저장 마이그레이션 프로젝트로 확대하지 않는다. 새 레지스트리/새 기믹 분기를 현재 구조에 추가하고 오래된 분기는 동결하는 최소 변경을 우선한다.

## 16. 검증 범위 — 문법/보스는 정확하게, 시각 폴리싱은 짧게

별도 `ACCEPTANCE.md`와 `GRAMMAR_CASES.json`을 기준으로 한다. 테스트용 지정 상태는 개발 검사에만 쓰고, 플레이 화면에 ‘fixture’, 테스트 점수, 데모 버튼을 추가하지 않는다.

### 필요한 검사

- 새 문법/쉼표 긍정·오류·미지원과 기존 문법 비오인정을 빠른 단위검사로 묶는다.
- 쉼표의 카드/점수/봉인 집계 제외와 24단어+쉼표를 확인한다.
- 47 실 해제/HP 1/동일 공격 중복/세 번째 해제 공격 격파/저장 재구성을 확인한다.
- 48 후보 가능성·기존 두 겹·49 주절 시제·50 무추가조건을 확인한다.
- PC 창모드 또는 패드 가로 1종, 스마트폰 가로 1종에서 실제 탭·드래그·형태·쉼표·공격을 짧게 확인한다.
- 실제 UI 경로로 43~47의 대표 짧은 흐름을 한 번 확인하되 지정 시작 덱이면 지정 상태 검사라고 표시한다.
- 기존 저장 1개와 새 저장 1개 왕복을 확인한다.
- 최종 변경본에서 저장소 필수 `npm test`, `npm run build`; 언어/데이터 변경에 필요한 `npm run validate:data`와 관련 브라우저 검사를 수행한다.

### 요구하지 않는 것

50전투 자연 완주, 대량 시드/덱 시뮬레이션, 전 브라우저·전 기기 순회, 수백 장 캡처, 새 효과 갤러리, 아트 완성, 완전한 영어 구문분석기. 다만 테스트 실패를 삭제하거나 검증 미완료를 PASS로 바꾸지는 않는다.

실기기 접근이 없으면 모바일 터치·오디오 청취는 `NOT RUN`으로 적고 구현을 인계한다. 에뮬레이터의 레이아웃 성공을 실제 기기 성공으로 보고하지 않는다.
