## 1. 작업 목표와 완료된 플레이 흐름

새 원정에서 다음을 실제로 플레이할 수 있어야 한다.

`이름/원정 설정 → 여행자 시작 → 시작의 초원 3전투 → Stage 1 보상/해금 → 전달의 항구 소개 → 보스 실루엣과 공략 힌트 → 입장 재료 처리 → 첫 상점 → Stage 2 일반전 3회 + 보스전 1회 → 0.2 제공 구간 완료`

- 공개 플레이 범위: Stage 1과 Stage 2, 총 7전투.
- Stage 2 이름: **전달의 항구**.
- 이번 핵심 새 문법: **현재형 평서문의 4형식(S+V+IO+DO)** 및 등록된 동사에 대응하는 **SVO+to/for+NP** 표현.
- 첫 상점은 Stage 2 시작에 정확히 한 번 방문한다.
- 기존 10종 룬에 **토파즈 룬(`rune.svoo`)** 1종을 추가한다.
- 플레이어는 기본 문법 경로로 성장할 수 있고, 강한 다른 빌드로 보스를 압도할 수도 있어야 한다.
- 버전 완성은 ‘샌드박스에서 4형식 하나가 성공함’이 아니다. 7전투, 정산, 지역 전환, 상점, 기록, 저장, 다음 원정까지 이어져야 한다.

## 5. 4형식: 학교 기본 문장 구조를 실제로 판정

### 5.1 지원 동사와 범위

기존 ID와 기본 Sense를 보존하면서 다음 대표 용법만 명시적으로 확장한다.

| 동사 | 현재 유지 | 이번 추가 | 등록된 대응 표현 |
|---|---|---|---|
| give | SVO | SVOO | SVO + to + NP |
| show | SVO | SVOO | SVO + to + NP |
| make | SVO | SVOO(누군가를 위해 만드는 용법) | SVO + for + NP |
| send | 기존 항목이 있으면 재사용, 없으면 최소 신규 SVO | SVOO | SVO + to + NP |

- 새로 필요한 `send`, `for`가 기존 레지스트리에 없으면 형태·뜻·품사·테스트를 갖춘 항목으로 추가한다. 수십 개 동사를 함께 확장하지 않는다.
- `send` 신규 카드의 초기 등급은 UNCOMMON, `for` 신규 카드는 COMMON을 제안값으로 사용한다. 기존 정의가 있다면 기존값을 보존한다. 신규 항목은 보상/입장/상점 후보로 쓰되 starterEligible은 기본 false로 두어 기존 시작 덱 역할 분포를 보존한다.
- `give/show/make/to` 등 기존 카드의 ID·희귀도·현재형을 재발급하거나 바꾸지 않는다. send/sends, for처럼 실제 이번 문법에 필요한 형태만 활성화한다.
- 현재 `futureFrameBindings`에 보이는 read/take/keep/find/play 등을 cap.svoo를 켠다는 이유로 모두 한꺼번에 활성화하지 않는다. 이들의 후속 범위는 별도다.
- make+목적어+형용사/원형은 여전히 미지원 5형식이다. SVOO 구현에 끌려 들어오지 않게 한다.
- 이번 버전에서도 `to + 동사`는 미지원 to부정사다. 전치사 to를 지원하는 것과 별개다.

### 5.2 파싱 계약

`NP(S) + 현재 유한동사 + NP(IO) + NP(DO) + 허용된 부사어`를 기존 NP/PP/수식 규칙으로 합성한다.

- IO와 DO를 단어 두 개라고 가정하지 않는다. `my friend`, `a very good book` 같은 여러 카드의 NP를 받는다.
- 전체 입력을 소비한 실제 후보만 인정한다. 앞부분만 파싱하고 나머지 카드에 점수를 주지 않는다.
- 문장 첫 주어와 유한동사에 기존 일치 규칙을 적용한다. IO와 DO의 대명사에는 목적격을 적용한다.
- AI 호출, 정답 예문 lookup, 입력 순서 자동 교정, 없는 단어 삽입을 사용하지 않는다.
- 목적어의 생물/무생물 같은 자연스러움은 전투 실패 조건으로 사용하지 않는다.
- 기존 bounded parser의 작업량/후보 수 제한을 지키고, 무차별 카드 순열 탐색으로 늘리지 않는다.
- `frame.svoo`, `FRAME.SVOO`는 현재 이름 체계와 일치시켜 한 번만 등록한다.
- 결과에 IO/DO 각각의 node/card 범위와 head 역할을 기록한다. 기존 `OBJECT`를 전부 IO로 바꾸어 SVO 회귀를 만들지 않는다.
- UI는 `주어 S / 동사 V / 간접목적어 IO / 직접목적어 DO`를 문법 이벤트와 동기화해 잠깐 보여준다.
- 등록된 SVO+to/for 구조의 학교 문형은 **3형식**이다. 두 NP가 있다는 이유로 4형식으로 계산하지 않는다.
- 일반 PP와 등록된 수여 대응 PP의 차이는 추가 구조 metadata로 표현할 수 있으나, 같은 PP를 두 번 점수화하지 않는다.

### 5.3 유효성·보너스·의미의 구분

- 새 0.2 원정 및 샌드박스에서는 Stage1에서 우연히 4형식을 만들더라도 정상 판정하고 기본 4형식 콤보를 준다. 문법 정오를 stage 번호나 해금 팝업에 종속시키지 않는다.
- Stage1 지역 보너스는 기존 1~3형식 조건 그대로다. 이른 4형식 사용이 자동으로 Stage1 지역 보너스를 받지는 않는다.
- 구버전 저장 원정의 지원 범위는 §14의 레거시 정책을 따른다.
- 일치·관사·대명사 격처럼 구조가 유지되는 오류는 기존 부분감점으로 처리하고 4형식 뼈대는 보존한다.
- `INVALID_CORE`, `UNSUPPORTED`, `ENGINE_ERROR`를 구분한다. 기술적 예외나 미등록 구문을 정상 문장으로 위장하지 않는다.
- 동일 문장의 정상 복수 분석은 대표 결과로 정규화하고 같은 구조의 보너스는 한 번만 준다.
- 과거 초안의 `give ... for ... = 무조건 WRONG_DATIVE_MARKER` 식 전역 규칙을 도입하지 않는다. `for`가 다른 수식 역할을 할 수 있는 정상 구문은 기존 PP 분석으로 살린다. 다만 등록된 TO 대응 구문으로 잘못 표기하지 않는다. ‘특정 변환 규칙과 다름’과 ‘문장 전체가 비문법적’은 다르다.

## 6. 점수 계약과 토파즈 룬

### 6.1 계산값

기존 기본점수10, 연마단계당+5, 완전문장+20, 감점, S/V/C/O 배율과 PP+10은 유지한다.

- 새 `frame.svoo` 기본 문형 배율: **×2**.
- Stage2 지역 보너스: **주절 SVOO이면 ×1.25, 공격당 한 번**.
- SVO+to/for는 기존 3형식×1.5와 유효 PP+10을 받는다. 이번 Stage2 지역 보너스와 토파즈는 받지 않는다. 두 공략을 몰래 동등 점수로 바꾸지 않는다.
- ‘전환 표현’이라는 이유로 별도의 +점수/×배수를 추가하지 않는다. 구문 metadata/도감 안내가 필요하면 비점수 정보로 둔다.
- 계산 순서는 기존 `카드/감점 → 완전문장 → 주절 문형 → 수식 → 룬 → 지역 → 보스 → 최종`을 유지한다.
- 모든 배수는 정수/유리수, 단계마다 내림. 최종위력과 실제 HP 감소량·오버킬을 구분한다.

### 6.2 토파즈

- ID: 기존 예약 ID `rune.svoo` 그대로.
- 이름: **토파즈 룬**. 등급: UNCOMMON(고급).
- 조건: 주절 4형식이 인정된 공격. 공격당1회.
- Lv1 ×1.5 / Lv2 ×2 / Lv3 ×2.5.
- 주절 구조와 무관한 작은 정확성 오류가 있다고 정상 복원된 SVOO까지 모두 무효로 하지 않는다. 기존 문형 룬과 동일한 부분점수 철학을 적용한다.
- 신규 플레이어: Stage1 클리어 milestone으로 영구 해금. 장착/레벨 지급이 아니라 후보풀 추가.
- 이미 구버전에서 `rune.svoo`를 해금한 프로필: 새 0.2 원정에서는 처음부터 후보에 들어갈 수 있다.
- 이미 공개한 보상·상점은 해금 때문에 바뀌지 않는다. 레거시 원정의 후보풀에도 소급 삽입하지 않는다.
- `RUNES.map(...)` 전체를 자동 해금 목록으로 넣거나 eligibleRunes가 runtimeReady만 보고 모든 룬을 허용하는 기존 단순화는, **기본10종 항상 허용 + 토파즈는 실제 run eligibility 확인**으로 좁혀 보완한다.
- Stage1 보스의 새 보상을 생성하기 전에 이번 원정의 Stage1 해금을 반영해 토파즈가 후보가 될 수 있게 한다. 해금은 반드시 선택·획득과 구분한다.
- 기존 10종 효과, 최대3레벨, 같은 ID 재획득 강화, 위→아래 슬롯 순서, 만석 교체 취소 규칙은 유지한다.
- 산호·혜성 등 이미 기록된 다른 미래 해금 ID는 지우지 않되, 이번에 runtimeReady를 켜지 않는다.

### 6.3 산술 고정 사례

| 입력/가정 | 기대 최종위력 |
|---|---:|
| She gives me a book. / 룬없음 / Stage2 일반 적 | (50+20)×2×1.25 = 175 |
| 동일 + 토파즈Lv1 | floor(floor(140×1.5)×1.25) = 262 |
| 동일 + 토파즈Lv2 | 350 |
| 동일 + 토파즈Lv3 | floor(350×1.25) = 437 |

| She is happy. / 룬없음 / Stage2 | 기존 문장점수60, 지역보너스 없음 |

## 7. Stage2 전투와 보스

### 7.1 초기 콘텐츠 설정

| 지역 내부 라운드 | 전역 전투 번호 | 역할 | HP 초깃값 |
|---|---:|---|---:|
| 2-1 | 4 | 일반 적 | 220 |
| 2-2 | 5 | 일반 적 | 300 |
| 2-3 | 6 | 일반 적 | 380 |
| 2-4 | 7 | 지역 보스 | 640 |

위 HP는 **이번 작업의 테스트 시작값**이지 검증 완료 밸런스가 아니다. Stage1은 변경하지 않는다. 아래 실제 플레이 검증으로 Stage2 값의 조정이 필요한 경우 Stage2 데이터만 작게 조정하고 전후 값·근거를 기록한다. 현재 덱·직전 공격력에 따라 숨은 동적 HP를 적용하지 않는다.

- 모든 Stage2 전투의 중점: 주절 4형식. 일반 전투는 이를 강요하지 않는다.
- 적 이름/이모지: 항구 분위기로 소규모 지정 가능(예: 부두 갈매기, 짐꾼 게, 파도 문어, 항구 수문장). 기능과 ID가 우선이며 외부 이미지를 가져올 필요 없다.
- 배경은 기존 테마 설정을 이용해 초원과 다른 청록/바다색으로 구분. 기존 화면을 전면 재디자인하지 않는다.
- 별도 플레이어 HP·몬스터 공격 턴·새 전투 자원은 만들지 않는다.

### 7.2 대표 보스: 일회 해제 장막

보스 예고 문구:

> **보호 장막: 일반 공격의 피해를 75% 줄입니다. 주절 4형식 공격을 한 번 맞히면, 그 공격부터 장막이 해제됩니다.**

정확한 동작:
1. 최초 장막 활성 상태.
2. 장막 활성 + 비SVOO 공격: 기존 점수/룬/지역 처리 후 **×1/4, 내림**.
3. 장막 활성 + 인정된 주절 SVOO: **피해 계산 전에 장막을 해제**하고 그 공격에는 감쇠를 적용하지 않는다.
4. 장막 해제 후: 이후 모든 문형의 유효 공격이 감쇠 없이 피해를 준다.
5. 새 보스 전투를 시작할 때만 장막 초기화. 룬 재정렬·페이지 재표시·연출 callback으로 장막을 복구하거나 다시 해제 보상을 주지 않는다.
6. 장막 해제 이벤트 자체는 추가 재화/정체불명의 점수를 주지 않는다.
7. 강한 비SVOO 공격도 돌파 가능하다. 절대면역·피해상한·다중 체력바·강제 최소 공격 횟수는 넣지 않는다.
8. `frame.svoo` 기본 뼈대가 유지된 부분감점 공격도 장막 해제를 허용한다. 완벽한 정확성이 별도 필수조건인 보스가 아니다.
9. 전치사 대응형 SVO+to/for는 3형식이므로 장막을 깨지 않는다. 예고와 도감 문구를 일치시킨다.
10. 최종 행동에서 처치했다면 승리가 우선이며, 남은 턴 보너스는 처치 후 남은 값0이다.

합성 방어 검증 예: 장막이 살아 있을 때 비SVOO 입력위력2560→실제최종640이면 한 방 처치가 가능해야 한다. 이 합성 검사는 고점 경로 규칙 검증이며 실제 게임에서2560 빌드를 달성한 증거로 보고하지 않는다.

## 8. 지역 진행 상태를 안전하게 확장

다음 전환을 실제 상태로 구분한다. 새 상태 이름은 기존 naming에 맞춰 최소한으로 추가해도 된다.

`Stage1 보스 공격/연출 → 승리 정산 → Stage1 클리어 milestone/해금 → 고정된 보스 보상 → 보상 선택/넘기기 → 지역 클리어 표시 → Stage2 소개/보스 예고 → 입장 지급 → SHOP → 상점 종료 → Stage2 첫 전투 셔플/드로우`

- Stage1 clear를 `status===CONTENT_COMPLETE`에만 매달아 두지 않는다. 0.2에서는 Stage1이 더 이상 최종 제공 경계가 아니어도 milestone·qualifiedRunIds·해금이 정확히 한 번 발생해야 한다.
- `roundIndex===2`가 곧 지역 보스/Stage1 clear라는 가정을 제거한다. Stage2의 roundIndex2는 **일반전 세 번째**이고 보스는 roundIndex3이다.
- 지역/전투 구분은 stageId와 encounter definition으로 결정한다. 보스 보상 여부도 실제 enemy kind를 기준으로 한다.
- 첫 룬 소개는 전역 battleNumber2, 즉 Stage1-2에만 적용한다. Stage2-2(전역5)에 잘못 재발동하지 않는다.
- 지역 전환 시 기존 combat을 닫고, 소유 덱·카드 강화·룬·재화·runId·RNG 스트림을 유지한다. 새 원정을 몰래 생성하지 않는다.
- 전투 밖의 지급·구매·제거는 activeCardIds/instances만 변경한다. 이전 전투 pile에 남은 카드와 새 덱의 합계가 맞지 않는 중간 상태를 live state로 만들지 않는다.
- 필요하면 combat=null인 합법적인 STAGE_INTRO/SHOP 상태를 지원하도록 invariants/validator/UI를 함께 수정한다.
- 플레이어가 이름·로비 화면으로 돌아갔다고 입장 보상이 중복 지급되지 않는다.
- 연출에 의존하지 않는 상태 커밋, 실패·탭 전환 시 최종 표시 수렴, commandId/revision 검증을 유지한다.

## 9. Stage2 입장 재료: 한 번의 기본 준비, 지속 자동구제 금지

목표는 ‘현재 덱으로 4형식 경로를 준비할 수 있게 하는 것’이지 완성 정답 덱을 매번 만들어 주는 것이 아니다.

권장 정책을 다음처럼 구현한다.

1. 상점 전에 현재 active deck에서 위 네 동사의 **실제 runtime SVOO binding을 가진 카드**가 있는지 확인한다.
2. 없으면 `give` 한 장을 기본 fallback으로 지급한다. 존재하면 해당 역할의 동사를 추가하지 않는다. 다른 후보를 쓰려면 정렬된 검증 목록+기존 시드 스트림으로 고정하고 trace에 남긴다.
3. 현재 이용할 대표 경로를 정하고, give/show/send 경로는 to, make 경로는 for 중 해당 연결 카드가 없을 때 한 장만 추가한다. 둘 다 불필요하게 지급하지 않는다.
4. 총 자동 지급은 통상 0~2장. `stage.02.entryGrant`에 지급 내역과 적용 여부를 저장한다.
5. 실제 주어·IO·DO와 필요한 사본 수까지 확인할 수 있는 제한된 witness 검사를 수행한다. 검사를 통과하기 위해 동일 카드 ID를 두 위치에 쓰지 않는다.
6. 플레이어가 앞에서 필수 재료를 심하게 제거해서 완전 경로가 없으면 짧은 덱 준비 경고와 이미 정해진 상점/보상 기회를 제공한다. 여러 장의 숨은 추가 구제 카드를 만들어 넣지 않는다.
7. 지급 뒤 새 카드가 덱으로 들어가는 짧은 연출을 보여주고 원정 사전에 등록한다. 상태 지급은 연출 callback이 아니다.
8. 상점을 나온 뒤 제거/선택 때문에 경로가 없어졌더라도 다시 지급하지 않는다.
9. 이후 매 턴 정답 카드 삽입, 보스 직전 자동 수리, 모든 전투의 첫 손패를 강제로4형식 정답 패로 고정하는 일을 하지 않는다. 기존 일반적인 첫패 접근성 검사는 유지한다.

초회/익숙하지 않은 학생은 지급 재료와 도감으로 정석을 시험하고, 숙련자는 이를 무시하거나 기존 빌드와 결합할 수 있어야 한다.

## 10. 첫 상점: 실제로 사용 가능한 작고 명확한 화면

### 10.1 일정·재진입

- 전체 roadmap 일정은 `Stage2/4/6/8/10 입장 + 최종전48 직전`, 총6회 유지.
- 0.2에서는 Stage2 입장 상점 **한 번만 실제 구현**한다. Stage2 클리어 뒤에는 상점이 없다.
- 보스 실루엣·규칙·입장 지급을 본 후 열고, 상점을 나와야 첫 전투를 시작한다.
- 이때까지 첫 셔플/손패/RNG deck 소비가 일어나지 않도록 한다.
- 정보창을 닫는 것과 상점 방문을 끝내는 것을 구분한다. 최종 `상점 나가기` 확정 후 무료로 재방문하지 않는다.

### 10.2 상품·초기 가격

첫 상점은 **룬1칸 + 단어카드2칸 + 카드 연마 + 카드 제거**로 구현한다. 향후2/3칸을 데이터로 수용하되 지금은 복잡한 상품 수 추첨을 하지 않는다.

| 내용 | 0.2 실행 초깃값 |
|---|---:|
| 일반 카드 | 6 |
| 고급 카드 | 10 |
| 희귀 카드 | 14 |
| 일반 룬 | 18 |
| 고급 룬 | 24 |
| 희귀 룬 | 32 (예약 가격; 실제 runtime 후보가 없으면 등장하지 않음) |
| 연마 +1 | 8 |
| 제거 | 해당 원정의 첫 유료 제거6, 이후 유료 제거 성공마다 다음 가격+2 |

**이 가격은 이번 통합 테스트의 시작값이다.** 옛 ‘첫 상점 룬10 할인’은 자동 확정하지 않는다. 0.1.1에는 남은 턴 재화가 있으므로 도착 재화가 항상10이라는 전제가 틀리다. 실제 첫 상점 소지금 분포와 구매 가능 항목을 보고하라. 필요하면 Stage2 체력/첫 상점 가격 데이터만 근거를 남겨 작게 조정한다. 검증 없이 전 상품가격이나 처치 재화를 일괄 변경하지 않는다.

### 10.3 상품 생성

- 상품·가격·상품ID·구매여부는 최초 생성 시 ShopState에 고정한다. 재표시/덱보기/사전/취소/저장복원으로 재추첨하지 않는다.
- 카드2칸은 지역 관련 후보1칸과 구현된 전체 풀 후보1칸으로 구성한다. 카드 등급 추첨이 필요하면 기존 카드유형 가중치50:10:5를 카드 내 상대가중치로 재사용한다. 실제 보상3칸 확률표와 혼동하지 않는다.
- 지역 후보는 동일 등급 안에서 현재 Stage2 문법과 관련된 재료를 우선하며, 없으면 같은 등급의 일반 후보로 fallback하고 trace를 남긴다. 희귀도를 몰래 승격/강등하지 않는다.
- 룬은 해금되고 runtimeReady이며 최대레벨 전인 풀에서 생성한다. 토파즈 확정 판매를 강요하지 않는다. 기본 룬만 있어도 정석 공략이 가능해야 한다.
- 상점 후보에는 시작 어휘 난도 제한을 걸지 않는다. 어휘 난도로 가격·점수 가산을 하지 않는다.
- 카드 추가 사본 구매는 정상적으로 허용하되, 화면 두 상품이 불필요하게 같은 ID로 중복되는 것은 피한다.
- 가격·선택지 추첨은 `rng.shop`만 사용한다. 덱 RNG·보상 RNG·시각 RNG와 분리한다.
- 조건부 후보 생성은 본인이 실제로 만든 상품을 새로 검사하면서 예산에 맞춰 몰래 할인하거나 무료 지급하는 방식이 아니다.

### 10.4 거래 원자성

- 명령은 live state를 직접 수정하지 않고 Controller의 제안 clone에서 검증/적용한 뒤 한 번에 커밋한다.
- 카드구매: 유효 shop/item, 미구매 상태, 비용, instance ID를 검사하고 재화 차감+카드 생성+소유목록+사전+구매완료를 함께 커밋한다.
- 룬구매: 동일ID 보유는 Lv+1, 신규는 빈슬롯 또는 교체대상 선택. 대상을 정하기 전에 돈을 빼지 않는다. 최대Lv/동일상품 중복 구매 차단.
- 만석 룬교체 취소 시 기존 룬·돈·상품 상태 유지. 같은 상품을 늦게 처리한 중복요청도 무손실로 거절한다.
- 연마: 한 카드 +1단계, +3상한, **상점당1회**. 처음부터 +3인 카드는 대상 제외. 취소/실패는 횟수 소모 없음.
- 제거: 소유 카드 한 장, **상점당1회**. 강화와 별개이므로 비용이 있으면 둘 다 가능. 마지막 핵심 동사 등의 경고는 가능하지만 사용자 확인을 몰래 복구 카드 지급으로 바꾸지 않는다.
- 강화/제거는 현재 버전의 서비스만 제공한다. 황금/공명은 이번에 추가하지 않는다.
- 보상 무료 제거는 유료 제거 횟수나 다음 가격을 올리지 않는다.
- 구매/서비스에 부족한 재화, 오래된 revision, 없는 cardId, 닫힌 shop, 중복 commandId가 오면 모든 상태/RNG를 보존한다.

### 10.5 UI

- 보스 규칙, 소지금, 덱 크기, 상품가격, 연마/제거 사용완료가 즉시 구분된다.
- 상품의 한 줄 설명과 룬의 현재→획득 후 레벨/효과를 표시한다.
- 단어 카드 앞면을 한국어 뜻으로 채우지 않는다. 기존 상세/사전 방식 사용.
- ‘내 덱’, ‘단어 사전’, 룬 설명 조회는 상점 안에서 가능하고 보상을 소비하지 않는다.
- 태블릿에서 상품/서비스 대상 모달의 스크롤과 버튼이 겹치지 않는다.
- 연마 선택/취소는 기존 보상 대상 UI를 재사용할 수 있으나, 보상 횟수와 상점 서비스 횟수를 하나의 전역 변수로 합치지 않는다.

## 11. Stage2 보상과 경제

| 3칸 각각의 기본 가중치 | 일반전 | 지역보스 |
|---|---:|---:|
| 일반 카드 | 50 | 0 |
| 고급 카드 | 10 | 10 |
| 희귀 카드 | 5 | 10 |
| 카드 연마 | 15 | 25 |
| 카드 제거 | 10 | 5 |
| 룬 | 10 | 50 |

- 한 번 ‘카드 보상’을 뽑은 뒤 동일종류3개를 만드는 옛 방식으로 돌아가지 않는다.
- 유효 후보 필터·중복 서비스 필터·최대Lv 필터·고정된3칸·취소 무소비는 현재 구현을 유지한다.
- 유효성 필터 이후의 실측 분포와 원래 기본 가중치의 차이를 구분한다. 필터를 빼고 무효 룬/서비스를 제시하지 않는다.
- Stage2 전역4~6은 일반전 표, 전역7은 보스 표. Stage1의 예외는 전역1·2에만 적용한다.
- 지역 관련 카드 후보 기준을 Stage1 BASIC_FRAMES 하드코딩에서 현재 stage focus로 확장한다. 모든 후보를 무조건4형식용으로 바꾸지는 않는다.
- 일반승리2, 보스6, 처치 이후 남은턴×1을 유지. 지역이 바뀌어도 턴재화가 누락되지 않는다.
- 혼합 보상 넘기기는 현재 규칙 유지: 카드칸이 하나라도 있으면 +3, 없으면 +2, 팝업당 한 번.
- 사용자 선택 이후 기존 룬·카드·돈을 무의미하게 초기화하지 않는다.

## 12. 점등·룬·도감: 새 문법을 기존 손맛에 연결

- 공격 전에 정답/예상점수/IO·DO를 보여주지 않는다. 지역설명의 일반 예시와 공개된 보스 규칙은 허용한다.
- 공격 확정 후 SVOO 영역을 점등하고 `4형식! ×2`를 표시한다. IO/DO 전체 NP의 경계를 눈으로 볼 수 있어야 한다.
- 토파즈 룬은 오른쪽 슬롯의 고유색 빛이 문장/점수판에 도달하는 기존 흐름을 재사용한다. 효과의 적용 여부/순서/숫자는 같은 AttackResolution에서 온다.
- 장막형 보스의 before/after 장막 상태는 공격 해제 이벤트에서 바뀌고 HP바는 타격 순간에 표시한다. 계산 상태를 먼저 커밋했다고 채점 시작과 동시에 장막·보스가 사라지게 하지 않는다.
- 전체 입력을2초로 압축하거나, 새 역할 표시 때문에 기존 읽기 시간을 줄이지 않는다. 긴 이벤트·백그라운드 복귀·Skip/finalize 시 한 번만 종료한다.
- 파티클·화면진동은 visual RNG, 게임 추첨에는 영향 없음. 효과 감소/동작 줄이기에서도 문법명 읽기 시간은 남긴다.
- Stage2 첫 소개는 짧은 지역 안내+공개 공략 힌트. Stage1의 장황한 조작 가이드를 재시작하지 않는다.
- 도감은 기존 첫문장/최고문장/사용횟수/점수/한글 의미참고를 보존하고 FRAME.SVOO 항목을 추가한다.
- 도감 한 줄 예시: `4형식은 주어+동사+간접목적어(~에게)+직접목적어(~을) 순서로 만든다.`
- to/for 안내는 지원 동사에 한정한 짧은 대표규칙만 제공한다. 모든 전치사 문장의 의미를 단정하지 않는다.
- 명확한 SVOO 템플릿의 한글 참고는 `S가 IO에게 DO를 준다/보여준다/보낸다/만들어 준다` 형태로 소규모 추가한다. 선택된 Sense·현재형/격/NP를 사용한다.
- 불확실한 번역은 성분별 뜻 fallback. 번역 실패 때문에 문법 성공이나 공격을 취소하지 않는다. 영어 오류를 한글로 조용히 교정해 ‘완벽한 정답’처럼 표시하지 않는다.

## 13. 내용 완료와 영구 진행

- 새0.2 원정은 Stage1에서 CONTENT_COMPLETE로 끝나지 않는다.
- Stage2 보스 보상 선택/넘기기 후 `CONTENT_COMPLETE / STAGE2_END`로 끝난다.
- 학생 표시: `전달의 항구 완료 — 0.2 제공 구간을 모두 플레이했습니다.`
- Stage3은 후속 안내만. 미구현 지역 이동 버튼/빈 화면/가짜 전투를 만들지 않는다.
- 7전투 완료는 전체48전투 스토리 클리어가 아니다. `storyClearCount`를 올리거나 다회차 보스풀·난이도2·다른 캐릭터를 해금하지 않는다.
- Stage1 milestone은 해당 runId당 한 번 유지. Stage2 클리어로 qualifiedRunIds를 한 번 더 추가하지 않는다.
- Stage2 클리어 자체의 최고도달지역/완료 기록은 별도 idempotent 사건으로 남길 수 있다. 후속 문법/룬 ID를 기록해도 runtimeReady는 자동 활성화하지 않는다.
- 플레이 중 해금은 그 원정과 개인 프로필에 반영하되 이미 공개한 보상/상점은 변경하지 않는다.

## 14. 저장·구버전 호환: 이번의 명시적 정책

### 14.1 저장소와 프로필

- IndexedDB 이름 `sentence-balatro-v0-1`, 기존 profiles/slots, playerId, 기존 DB version/store를 이유 없이 바꾸지 않는다.
- 프로필의 설정·해금·도감·최고기록·기존 슬롯을 지우지 않는다. 닉네임을 바꾸었다고 새 identity로 덮지 않는다.
- 원정 자동저장/클라우드 저장은 추가하지 않는다. 개인 실적의 가벼운 로컬 보존과 원정 수동 저장은 계속 별개다.

### 14.2 0.2 새 저장

- 버전 validator에 새0.2를 추가하고 Stage2의 stageId, roundIndex0~3, 전역4~7 대응, SHOP/입장 안전상태와 STAGE2_END를 검증한다.
- `SHOP`은 거래/대상모달 처리가 끝난 안정상태에서 저장 가능. 대상 선택 도중·상태변경 중 저장 금지.
- 입장 지급 전/후를 저장할 수 있으면 각각 정확한 subphase와 entryGrantId로 중복을 막는다. 단순화가 필요하면 소개 완료 후 안정된SHOP에서만 저장을 열어도 된다.
- shopId, generatedInventory/price, purchased 상태, 강화/제거 사용횟수, 유료제거 누적수, 입장지급 이력, 보스기믹 정의, runtime content manifest와 RNG를 보존한다.
- 상점 저장 시 combat=null일 수 있다. 이를 훼손된 저장으로 오판하지 않는다.
- 보스 공격 중에는 종전대로 저장하지 않는다. 장막이 있는 combat 데이터의 형식 검증·직렬화는 포함한다.
- 기존 수동3슬롯과 transaction 완료 후 성공 알림을 유지한다. 저장 실패 시 성공으로 표시하지 않는다.

### 14.3 이전0.1.0/0.1.1 원정

이번에는 **이전 원정을 자동으로0.2 캠페인으로 확장하지 않는다.**

- 이전 저장은 기존 Stage1 구간으로 열리고 완료 경계도 STAGE1_END를 유지한다.
- 기존 카드 수(30 또는28), HP, 명시형태, 공개 보상, 룬, 재화, 난수, 사용횟수를 유지한다.
- 기존 저장에 새 send/for/토파즈를 소급 섞지 않는다. 이미 기록된 미래 해금ID는 삭제하지 않는다.
- 이후 미생성 보상/전투도 레거시 manifest/활성 후보 범위를 유지한다. 같은 저장에서 새 registry 항목 때문에 후보 순서와 RNG 사용이 바뀌지 않게 한다.
- 범위별 capability/후보 view 또는 작은 legacy dispatch를 사용해 보존하되, 게임 전체를 또 복제하는 대규모 아키텍처를 만들지 않는다.
- 새 문법 기대값과 옛 미지원 기대값이 다르면 버전/능력 context별 테스트를 남긴다. 옛 테스트를 일괄 삭제해 새PASS 수를 만들지 않는다.
- 안내: `이 저장은 이전 버전의 시작의 초원 구간입니다. 0.2의 새 지역은 새 원정에서 시작할 수 있습니다.`
- 같은 개인 프로필로 새0.2 원정을 시작하면 기존 영구기록·토파즈 해금 등은 이어받는다. 재튜토리얼/고정첫룬을 강제로 반복하지 않는다.

버전 간 seed 결과가 완전히 동일해야 한다고 주장하지 않는다. 동일 버전·설정·초기해금·선택·난수 상태에서 재현되어야 한다. 다른 슬롯의 새 해금을 진행 중인 원정에 소급 적용하지 않는다.

### 15.4 시드·밸런스 검사

- 기존 네 어휘 모드×2,500시드=10,000 시작덱/첫손패 검사를 유지한다.

- 실제 Controller 명령을 사용하는 통합 완주 검사: 고정 명시된 최소20seed×4어휘모드=80원정 이상을 권장한다. 매 행동은 현재 손패·합법교환·공개보상·상점만 사용한다.

- 기술오류0이 목표다. 모든 플레이전략·모든seed 무조건승리는 목표가 아니다. 정석 정책이 광범위하게 막히면 카드 접근성/정책 자체/Stage2 HP 순서로 원인을 검토하고 작은 데이터수정만 한다.

## 부록 A. 코드 검토로 확인한 ‘그대로 두면 0.2에서 깨지는 지점’

4. rewards.js는 전투번호 [1,2,3]만 허용하고 전역3만 보스 표로 선택한다.
