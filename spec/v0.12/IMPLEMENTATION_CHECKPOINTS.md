# 0.12.0 구현 중 확인할 핵심 연결점

이 파일은 본명세의 요약이다. 추가 범위를 만드는 문서가 아니다.

## 1. 단어 카드가 보이기만 하는 구현을 피한다

새 단어 하나는 card definition, primary/secondary lexeme, 실제 활용형, sense/frame binding, registry 색인, 형태 선택, 사전, 획득 경로, 문법 근거, 채점/룬 근거까지 연결되어야 한다. `watch`라고 적힌 카드가 있어도 예전 registry가 그 ID를 모르면 미완성이다.

0.12에서 0.11의 기존 언어 base를 상속하고, 새 capability만 추가한다. 이전 registry 객체를 mutate하지 않는다. 실제 파일 구조가 다르면 개념상 같은 경로를 찾아서 처리한다.

## 2. 28장 동사 교체에서 빠지기 쉬운 것

- 생성기뿐 아니라 품사수/고정동사/다양성 검사와 repair/fallback도 새 정책에 맞춘다.
- `be2 + have1 + make1 + 대응동사3 + go/run1 = 8`.
- 겸용 plan의 기본 품사는 명사이므로 명사6 슬롯에서 하나로 센다.
- 초기 평서문 성공 경로와 튜토리얼 복원을 명령문 판정으로 대체하지 않는다.
- FREE는 이번에 새 확정 세트를 임의로 부여하지 않는다.

## 3. 명령문에서 주어 처리

분석상 암시된 you와 물리 주어 카드가 다르다. 데이터 모델은 둘을 구분해야 한다. 검증된 명령문에서만 암시 주어를 허용하고, 평서문 주어 검사까지 해제하지 않는다. SVOO 보스 검사처럼 실재 subjectNodeId를 요구하던 곳은 이 구분을 읽게 한다.

명령문은 시제 없는 기본 명령으로 판정하며 단순현재 과제의 편법 정답이 아니다. 명령문 전용 점수 항목은 만들지 않는다.

## 4. 겸용에서 표면형과 보안 경계

`plans`와 `changes`는 실제 구조로 명사 복수/동사3인칭을 구분한다. 내부 선택 ID가 뜻을 강제하지 않게 하되, 등록되지 않은 lexeme/형태를 카드에 끼워 넣을 수는 없게 한다. 한 사본의 점수/연마/사용후 이동은 한 번만 처리한다.

## 5. 프리뷰에서 게임 상태를 진행시키지 않는다

`BETWEEN_BATTLES`의 다음 상대, 초기화된 새 전투의 상대, 최종 다음 페이즈, 지역 입장 뒤 첫 상대를 구분한다. 화면을 읽는다고 draw/보상/봉인 추첨을 다시 하지 않는다. preview 표시가 controller command를 중복 호출하지 않도록 한 경로만 진행을 소유한다.

## 6. 점수 overlay는 새로운 채점 엔진이 아니다

숫자는 확정 timeline의 정수값이다. overlay가 피해/가산/배율을 다시 계산하지 않는다. 시각 state 예시는 아래와 같으며 그대로 구현해야 하는 API가 아니다.

```js
{
  attackId,
  displayedScore,
  currentTier,
  crossedThresholds: new Set(),
  anchor,
  visible,
  cancelToken
}
```

- 새 공격에 초기화, 동일 공격에는 중복 등록하지 않음.
- tier는 현재 after에 맞춰 상승/하강.
- 돌파 축하는 같은 attack에서 한 경계당 최대 한 번.
- 실제 값이 800→3200이면 목적 tier로 한 번 도약.
- 감소/회복/0피해/오버킬은 다른 사건.
- 효과 끄기는 숫자를 없애는 설정이 아님.

## 7. 레이어에서 확인할 것

패널 안의 `overflow:visible` 하나만으로 '화면 overlay' 요구를 충족했다고 가정하지 않는다. 실제 clipping ancestor, transform containing block, fullscreen root와 modal 우선순위를 확인한다. 숫자는 panel 위에 그려지고 입력은 통과한다. 기존 점수 슬롯의 공간은 유지한다.

## 8. 실제 사용성 확인을 작게 수행

대표 PC 창모드/전체화면, 태블릿 가로 한 구성을 본다. 작은 정상 공격 하나, 복합 정상 공격 하나, 고점 표시 fixture 하나로 크기·화염·감점·돌진 연결을 확인한다. 전투 전체 자연 완주 대신 50전투 경계는 기존 계약을 활용한 작은 상태 검사로 확인한다.

장식의 수치·스크린샷 양을 늘리는 것보다 '사용자가 카드를 놓고, 형태를 고르고, 공격한 뒤 다시 조작할 수 있는가'를 우선한다.
