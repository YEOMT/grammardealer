## 0. 이 문서의 사용법과 범위

이 문서와 동봉 시작 프롬프트가 이번 패치의 통합 계약이다. 예전 ZIP은 소스 복원본이 아니며 과거 UI 변경을 처음부터 다시 실행하지 않는다. 작업 시 실제 최신 main과 작업 브랜치를 비교하고, 이후 수정이 있으면 보존하며 아래 변경만 통합한다. 현재 작업 트리의 미커밋 변경을 폐기하거나 강제 reset하지 않는다.

### 0.1 이번에 새로 구현할 여섯 묶음

| 묶음 | 구현할 결과 |
|---|---|
| A. 시작 덱 | 28장 유지. 초급/기본/심화에 대응하는 핵심 동사 네 종류와 go/run 중 한 장 보장 |
| B. 어휘·겸용 | watch·notice·allow·try·remember를 필요한 실제 용법까지 연결. plan·work·change 명사/동사 겸용 |
| C. 명령문 | 기본 긍정 명령문을 정상 문장으로 판정. 명령문 전용 추가 배율·감점 없음 |
| D. 전투 준비 | 실제 몬스터를 더 잘 보이게 하고, 목표 문법·형태·짧은 뜻·예문·효과만 선명하게 제공 |

### 0.2 이전 패치에서 반드시 보존할 묶음

같은 전투의 배경/몬스터 DOM 지속성, 12×2 조합대와 장수별 카드 확대, 손패/더미 정렬·하단 여백, 라이브 채점 무스크롤, 감점/방어 구분, 카드 집결→돌진→타격, 상단 소리 조절, 패드 오디오 복구, 지역 BGM 3초 유예 후 크로스페이드, 전체화면 실패 안내, 전투 전 실제 몬스터 이미지 연결.

PR #27이 병합됐다는 사실과 각 실제 환경에서 모든 문제가 해결됐다는 주장은 다르다. 정상 동작은 재작성하지 않고, 이번 변경에 의해 깨진 경로 또는 남아 있는 같은 문제만 좁게 보완한다.

### 0.3 금지 사항

- 전투 전체 재배치, 로비/상점 리디자인, 단어 카드 리디자인, 새 폰트 도입 금지.
- 영어 단어의 두 줄 표시·말줄임표·철자 생략 금지. 긴 단어를 삭제하거나 이름을 바꾸지 않는다.
- HP·턴·손패 한도·드로우·연마·룬 성능·기존 희귀도·기본 카드 점수·기존 문법 배율·보상 경제를 임의 변경하지 않는다.
- 새 지역/보스/승천/랭킹 서버/PWA/네이티브 앱/외부 이펙트 팩을 추가하지 않는다.
- 의미가 어색하다는 이유로 정상 구조를 0점 처리하지 않는다. LLM 문법 판정·문장 정답 문자열 목록·무료 누락 단어 삽입 금지.
- 편집 중 정답/예상 점수를 보여주지 않는다. 준비 화면 예문은 고정 교육 자료이며 현재 손패의 해답이 아니다.
- 이전 저장의 덱·카드·정산·RNG·보상을 새 규칙으로 몰래 바꾸지 않는다.
- 장식이 게임 상태를 변경하거나 애니메이션을 봐야만 피해/승리가 확정되는 구조로 바꾸지 않는다.

### 0.4 확정값과 구현 기본안을 구분한다

**사용자 확정:** 28장, 수준별 핵심 동사, make 공통, go/run 중 하나, 세 겸용 카드, 명령문 전용 보너스 없음, 간결한 준비 문구, 형태 선택/버리기 가독성 개선, 점수 독립 오버레이 및 100·300·600·1000·1500·2000·3000·4000·5000·6000·10000 경계.

**조정 가능한 구현 기본안:** go/run 동등 추첨, 신규 카드의 동역할 기존 카드 등급 참조, 팝업 픽셀 범위, 숫자 단계별 확대 비율·색·불꽃·타이밍. 실전 밸런스 검증값으로 주장하지 않는다. 문법·게임 규칙은 미세 시각 조정을 이유로 바꾸지 않는다.

동봉 JSON은 이 문서의 기대 계약과 시각 시작값이다. 소스를 자동 덮어쓰는 파일도, 이미 통과한 테스트 결과도 아니다. 의미상 불일치가 발견되면 본문/사용자 확정 사항을 우선하고 함께 정정한다.

## 3. 28장 시작 덱

### 3.1 총 장수와 기본 품사 배분

| 기본 품사 슬롯 | 장수 |
|---|---:|
| 명사 | 6 |
| 대명사 | 4 |
| 동사 | 8 |
| 형용사 | 3 |
| 부사 | 2 |
| 한정사 | 3 |
| 전치사 | 2 |
| 합계 | **28** |

명사/동사 겸용 카드는 **기존 기본 품사 슬롯 하나에서만** 센다. plan 한 장을 명사1+동사1로 중복 집계하지 않는다. 시작 덱에 임의의 운영 카드·추가 to 카드·보충 단어를 붙여 29장 이상 만들지 않는다. 이후 보상/상점/기존 운영 카드 지급으로 성장하는 것은 별개다.

### 3.2 동사 8장 — 세 수준의 확정 구성

| 종류 | 초급 BEGINNER | 기본/중급 STANDARD | 심화 ADVANCED |
|---|---|---|---|
| be | 2장 | 2장 | 2장 |
| have | 1장 | 1장 | 1장 |
| 공통 핵심 | make 1장 | make 1장 | make 1장 |
| 지각동사 자리 | see 1장 | watch 1장 | notice 1장 |
| 목적어+to 확장 자리 | need 1장 | want 1장 | allow 1장 |
| to/-ing 확장 자리 | like 1장 | try 1장 | remember 1장 |
| 짧은 1형식 자리 | go 또는 run **중 1장** | 동일 | 동일 |
| 총계 | **8장** | **8장** | **8장** |

- go/run은 게임의 기존 seeded 덱 RNG에서 하나를 고른다. 기본안은 1:1. `Math.random()` 금지.
- 핵심 네 종류는 **시작 덱에** 보장한다. 첫 손패/매 턴에 모두 제공하거나 숨은 드로우를 조작하지 않는다.
- be를 제외한 지정 동사는 이 초기 동사 슬롯에서 정확히 한 장씩이다. 이전 무작위 동사 슬롯을 추가 유지하여 중복시키지 않는다.
- 비동사 20장의 기존 수준별 분포·품사 구성·관사/대명사 고정 정책·최대 사본/다양성 제약은 유지한다.
- 초급이 '뜻이 쉽지만 문장 조립이 어려운 카드'에 치우치는 문제는 핵심 동사 보장으로 개선한다. 이번에 사용자 미지정 전체 명사/형용사 풀까지 전면 개편하지 않는다.
- 자유 FREE는 사용자에게 세트가 지정되지 않았다. **기존 FREE의 28장 생성 분포를 유지**하는 것이 이번 보수적 기본안이다. 임의로 심화 세트를 강제하거나 별도의 새 확률표를 만들지 않는다. 새 원정 문법 정책은 사용할 수 있다.

### 3.3 go의 주의사항과 교육 원칙

`I go.` / 기존 `I go home.` 경로는 유지한다. 학교 목적지를 뜻하는 `I go school.`은 정상 구조로 풀어주지 않는다. 자동 to 삽입·go to 합성 카드·보이지 않는 무료 토큰은 만들지 않는다.

사전의 정적인 사용 메모에 `go to + 장소`, `go home`의 차이를 짧게 표시할 수 있다. 편집 중 조합을 검사해 정답 위치를 알려주는 새 기능으로 확장하지 않는다. 시작 전치사 두 자리는 이번 패치에서 유지하며 to의 기존 획득/입장 지급 정책도 보존한다.

### 3.4 생성/검증/복원의 연결

- 새 동사표만 바꾸고 구검사의 'go/come/run/live 중 두 종류'를 남기지 않는다.
- 생성기가 반환한 실제 cardDefinition/instance/selection으로 짧은 평서문 1·2·3형식 경로를 확인한다. 명령문 한 단어가 통과했다고 초급 평서문 재료 검증을 대체하지 않는다.
- 검증 실패 repair가 사용자 확정 동사를 몰래 다른 카드로 교체하지 않는다. 부족한 비고정 슬롯만 기존 예산 안에서 수리하고 생성 trace를 남긴다.
- 새 동사 metadata 누락은 분명한 데이터 오류다. 고정 watch를 see로 대체해 조용히 성공 처리하지 않는다.
- 새 0.12 안에서 같은 seed·같은 mode는 같은 덱과 RNG 결과를 재현한다. 구버전과 **동일한 새 덱 결과**를 강제하지 않되, 이미 저장된 구버전 RNG는 보존한다.

## 4. 수준 대응 동사: 단어 이름만 교체하지 않는다

### 4.1 최소 지원 범위

아래 표는 이번 구현의 **검토한 활성 용법**이다. 모든 사전 의미를 다 구현하라는 요구가 아니다. 기존 단어의 이미 지원되는 용법은 삭제하지 않는다.

| 동사 | 간단한 출발점 | 함께 연결할 확장 |
|---|---|---|
| see / watch / notice | S + V + 명사구 | V + 목적어 + 동사원형 / -ing의 지각 구조 |
| need / want / allow | S + V + 명사구 | V + 목적어 + to + 동사원형 |
| like / try / remember | S + V + 명사구 | V + to + 동사원형 / V + 동명사구 |
| make | 기존 SVO | 기존 SVOO, SVOC 형용사/명사, 사역 원형 등 기존 범위 보존 |

실행 예: `I watch you.`, `I notice you.`, `I allow games.`, `I try food.`, `I remember you.`. 이 예들은 임의 정답 목록으로 넣지 않는다. 실제 어휘의 동사 결합 규칙으로 분석해야 한다.

- watch/notice를 see의 모든 sense·수동태·보어 허용 목록의 통째 복사본으로 만들지 않는다.
- 지각동사 원형/진행분사 구조에 기존 PERCEPTION/분사/목적격보어의 실제 근거를 연결한다. 단지 문법 통과만 하고 룬·지역 보너스가 영원히 발동하지 않는 반쪽 구현 금지.
- allow의 기본 확장에는 목적어+to가 필요하다. `allow + 목적어 + 원형`을 사역 make처럼 허용하지 않는다. `allow + 동명사`는 확인된 일반 용법으로 최소 지원에 포함할 수 있으나 새로운 과제/보너스를 만들지는 않는다.
- try/remember를 like의 보어 목록으로 그대로 덮지 않는다. 특히 `try + 목적어 + to`, `remember + 목적어 + to`를 이 묶음 때문에 일반적으로 허용하지 않는다.
- try to와 try -ing, remember to와 remember -ing의 뜻 차이는 사전 메모에 짧게 남긴다. 뜻 차이를 자동 의미 감점으로 사용하지 않는다.
- 신규 카드의 수동태 경로는 실제 타동 용법에 한해 기존 수동태 시스템에 연결한다. 지각 보어의 수동화는 동사별 검토된 범위만 사용한다. 게임 진행을 위해 틀린 문형을 추가하지 않는다.
- 기존 학습 해금/콤보 해금과 문법적 성립은 구분한다. 핵심 동사를 처음부터 갖는다는 이유로 모든 후반 배율을 시작부터 해금하지 않는다.

### 4.2 형태 데이터

| 원형 | 3인칭 단수 | 과거 | 과거분사 | -ing |
|---|---|---|---|---|
| watch | watches | watched | watched | watching |
| notice | notices | noticed | noticed | noticing |
| allow | allows | allowed | allowed | allowing |
| try | tries | tried | tried | trying |
| remember | remembers | remembered | remembered | remembering |
| plan의 동사 용법 | plans | planned | planned | planning |

불규칙/철자 생성 규칙을 무턱대고 적용해 `trys`, `tryed`, `noticeing`, `planed`, `planing`을 만들지 않는다. 과거와 과거분사의 철자가 같아도 역할 후보·선택 ID를 적절히 보존한다.

### 4.3 획득·희귀도·용어

어휘 수준(BEGINNER/STANDARD/ADVANCED)과 카드 희귀도(COMMON/UNCOMMON/RARE)는 별개다. '심화 단어'라고 기초 점수/배율/희귀도를 자동 상향하지 않는다.

기존 단어의 등급은 유지한다. 새 카드에 별도 확정 등급이 없으므로 기본안은 watch/notice→see, allow→want, try/remember→like의 **현재 정의 등급·동역할 획득 정책을 참조**한다. 이미 최신 소스에 명시적 정의가 있다면 보존하고 보고한다. 신규 등급을 강한 밸런스 확정값으로 주장하지 않는다.

새 카드가 시작 덱뿐 아니라 도감/사전/형태 선택/연마/제거/해당되는 상점·보상 후보에서 실제로 작동하게 한다. 보상 전체의 등급 확률·가격 공식을 다시 맞추는 작업은 하지 않는다. 어휘 수준 제한은 현재 규칙에 맞게 유지하고 모든 보상을 새 시작 세트로 강제하지 않는다.

## 5. plan·work·change 겸용 카드

### 5.1 물리 카드는 하나, 분석 후보만 둘

| 카드 | 유지할 기본 품사/색 | 추가 또는 보존할 명사 용법 | 동사 용법 |
|---|---|---|---|
| plan | 현재 명사/파랑 | 계획: 가산, plan/plans | 계획하다: 기본 SVO·to부정사 목적어 중심 |
| work | 현재 동사/빨강 | 일·작업: 불가산 work | 현재 지원되는 일하다/작동하다 용법 유지 |
| change | 현재 동사/빨강 | 변화: 가산/불가산 모두, change/changes | 현재 변하다/바꾸다 용법 유지 |
| help | 기존 그대로 | 도움의 기존 불가산 용법 | 기존 도움 동사 용법 |

change의 '변화' 뜻 자체가 가산·불가산 모두 가능하므로 `I need a change.`와 `I need change.`를 모두 지원한다. work의 작품/저작물 의미의 가산 works, change의 잔돈 의미, plan의 전문 의미 등은 이번 확장 범위로 새로 만들지 않는다. 범위 밖 용법이 영어 전체에서 틀렸다고 설명하지 않는다.

### 5.2 UI와 데이터

- 기존 cardDefId, 사본 ID, 연마, 점수, 희귀도, 소유권을 유지한다. 명사판/동사판 카드를 따로 생성하지 않는다.
- 기본 품사색 유지. 왼쪽 위 겸용 배지 사용: plan은 `명·동`, work/change/help는 `동·명`처럼 기본 품사를 먼저 표시한다. 오른쪽 위는 점수 자리다.
- 품사색 반반 나누기, 조합 전에 명사/동사 모드 토글 강요, 카드 외형 전면 변경 금지.
- 상세 설명·예문·가산성·형태 메모를 카드별 메타데이터에서 읽는다. help 설명 하드코딩을 다른 카드에 재사용하지 않는다.
- 형태 선택창에 실제 허용되는 모든 형태를 제공한다. plan/plans뿐 아니라 planned/planning에 접근할 수 있어야 한다.
- 같은 표면형의 후보는 실제 문장 구조로 결정한다. `plans`를 명사 복수로 선택했다는 숨은 ID만으로 문장 안의 동사 해석을 막거나, 반대로 명사 해석을 막지 않는다.
- 그렇다고 모든 외부 lexeme의 selectionId를 받아들이지는 않는다. 카드에 명시적으로 연결된 primary/secondary lexeme와 일치하는 surface만 허용한다.
- `planned`, `planning`을 명사 '계획'으로 자동 허용하지 않는다. 동명사/분사 판정은 기존 비정형 동사 엔진을 통한다.

### 5.3 판정·채점·사전·생성기

- 한 물리 카드가 그 문장에서 맡은 역할로만 채점된다. 두 품사라는 이유로 카드 기본점수·명사/동사 룬을 이중 지급하지 않는다.
- 형태·관사·수·주어동사 일치 검사에 실제 선택된 용법을 사용한다.
- primary 기준 초기 슬롯 집계와 제출 후 실제 역할 집계를 구분한다.
- 사전과 도감은 겸용 의미를 보여주되 두 개의 소유 카드처럼 표시하지 않는다.
- text fixture 편의 함수가 동형이의 lexical 후보를 만났다고 전부 unsupported로 버리지 않도록 보완한다. 실제 플레이 카드 기반 테스트를 최우선으로 한다.
- `historicalReceipt`나 구원정 해석에서는 새 용법으로 과거 점수를 바꾸지 않는다.

## 6. 명령문: 옳은 문장으로, 별도 보너스 없이

### 6.1 이번 지원 범위

기본 **긍정 명령문 주절**을 지원한다. 실물 주어 없이 동사원형으로 시작하며, 해당 동사가 요구하는 목적어/보어와 기존 허용 수식어를 검사한다.

| 예시 | 해석/표시 |
|---|---|
| Run. / Go. | 명령문 · 1형식 구조 |
| Be happy. | 명령문 · 2형식 구조 |
| Help me. | 명령문 · 3형식 구조 |
| Give me a book. | 명령문 · 4형식 구조 |
| Make me happy. | 명령문 · 5형식 구조 |
| Make him work. | 명령문 + 기존 사역 구조 |

부정 명령문, let's, 강조 do, 주어가 명시된 특수 명령문, 여러 명령절 연결을 이번 필수 범위로 추가하지 않는다. 이들에 대한 기존 지원이 실제로 있다면 퇴행시키지 않는다. 새 범위 밖 영어를 무조건 틀린 문장이라고 설명하지 않으며 기존 UNSUPPORTED 정책을 따른다.

### 6.2 파서 계약

- `mood: IMPERATIVE` 또는 동등한 명시적 근거를 반환한다. 표시는 '명령문'으로 구분한다.
- 듣는 사람 you는 **비물리적인 암시 주어**다. cardInstanceId를 생성하지 않고 원본 snapshot/token 배열에 you를 삽입하지 않는다.
- 주절에만 허가된 경로로 처리한다. 주어 없는 평서문, that절, 부사절, 명사구 파편을 명령문으로 무조건 구조 복구하지 않는다.
- base be는 명령문에서 허용하되 `I be happy.`의 기존 오류를 없애지 않는다.
- `read`처럼 원형과 과거가 같은 surface는 실제 원형 후보를 사용할 수 있다. 반대로 runs/went/running을 원형이라고 간주하지 않는다.
- 동사에 필요한 보어/목적어, 관사, 대명사 격, 전치사 등은 그대로 검사한다. 잘못된 구조를 '주어 생략 가능'이라는 이유로 모두 통과시키지 않는다.
- 기존 완전한 평서문/의문문 해석이 있을 때 명령문이 불필요하게 우선하지 않도록 분석 우선순위를 명시한다.
- 파서 탐색 범위는 유한하게 유지한다. 비어 있는 주어 때문에 무한 재귀/토큰 없는 반복이 생기지 않게 한다.

### 6.3 채점·지역·룬·보스 연동

- 정상 문장 보너스와 실제 제출 카드 점수, 기존 문형·수식·룬 계산을 적용한다.
- **명령문 전용 가산/곱셈/감점은 모두 없음.** 누락 you의 점수도 없음.
- 구조가 SVOO이면 기존 주절4형식 룬/항구 지역 보너스/보호 장막 해제 대상이 될 수 있다. 검증된 명령문에 한해서 허가된 암시 주어를 인정한다.
- 기존 `subjectNodeId` 실재 검사만 느슨하게 삭제하지 않는다. 평서문은 실재 주어, 명령문은 검증된 implicitSubject 근거라는 공통 판정 helper로 연결한다.
- 실제 주어 **카드**를 요구하는 룬은 숨은 you 때문에 발동시키지 않는다. 물리 주어·인간 명사 카드 근거를 만들어내지 않는다.
- 동사원형 명령문을 자동 `현재시제`로 분류하지 않는다. 주절 tense를 요구하는 골렘/딥 스트럭처 과제에 단순 명령문으로 편법 통과하지 않게 한다.
- 서피스 스트럭처의 문형 과제, 직조자의 문형 기억 등은 명령문의 실제 주절 문형을 일관되게 사용한다. 다른 타입의 목표는 해당 실제 근거가 있어야 한다.
- 목적어 내부 관계절 등 기존 근거가 실제로 성립하면 그 범위의 기존 콤보를 유지한다. '명령문이라서 전체 시제/관계절 기록 삭제' 식의 처리 금지.
- 짧은 명령문이 유용하다는 이유만으로 임의의 반감/최소 카드수 제한을 새로 만들지 않는다.

### 6.4 튜토리얼과 도움말

초보 안내의 기본은 주어+동사 평서문 조합을 유지한다. 정적인 도움말에 `명령문은 동사원형으로 시작합니다. 주어 you는 보통 쓰지 않습니다.` 정도만 보완한다. 명령문이 가능해졌다고 튜토리얼의 기존 행동 단계/초기 손패/설명을 전면 재작성하지 않는다.

## 7. 전투 준비 화면 — 몬스터와 필요한 문법만

### 7.1 지역 입장과 역할 구분

지역 입장 화면은 기존처럼 풍경·지역명·짧은 소개·하단 진행 버튼 중심으로 유지한다. 여기에 다시 몬스터 목록·HP 표·긴 문법 강의를 붙이지 않는다.

전투 준비 화면에서 **다음 상대의 실제 idle 이미지, 이름, 목표 문법과 최소 안내**를 제공한다. 같은 종류의 안내 화면을 여러 번 연달아 추가하거나 강제 타이머/퀴즈를 끼우지 않는다. 첫 라운드 안내가 필요한 경우 기존 시작 흐름에 같은 컴포넌트를 재사용하되 지역 입장 풍경 화면 자체는 오염시키지 않는다.

### 7.2 4형식 확정 문구

- 목표 문법: **4형식**
- 형태: **주어 + 동사 + 간접목적어 + 직접목적어**
- 뜻: **~에게 ~를 주다.**
- 예문: `I give you a book.`
- 전투 효과: **4형식 문장 사용 시 보너스 배율 적용**

이 '뜻'은 바로 이해하는 대표 해석 틀이다. 4형식의 가능한 모든 의미를 정의하는 긴 문장으로 늘리지 않는다. 사용자 문구를 '누가 누구에게 무엇을 주거나 만들어 주는 표현입니다' 등으로 다시 길게 윤문하지 않는다.

현재 일반전의 지역 배율이 실제 적용되는 범위를 존중한다. 숫자를 따로 노출한다면 데이터에서 읽은 작은 배지만 허용하고 위 문구를 긴 계산 설명으로 만들지 않는다.

### 7.3 공통 정보 계약

`targetLabel / patternKo / meaningKo / example / effectLabel / optionalBossHint` 정도의 읽기 전용 데이터로 구성한다. 예문 role 범위는 표시를 위한 자료이지 정답 문자열 판정에 쓰지 않는다.

- 목표 문법은 해당 라운드의 교육 목표다.
- 보너스는 실제 엔진의 적용 조건이다. 예를 들어 진행형 연습 라운드여도 지역 배율이 다른 시간 표현까지 받는다면 '진행형만 보너스'라고 잘못 제한하지 않는다.
- 보스는 보너스와 별도로 꼭 필요한 실제 기믹 한두 줄을 표시한다. 모든 보스에 '목표 문법을 쓰면 피해 증가'를 무조건 붙이지 않는다.
- 최종1페이즈의 아직 추첨하지 않은 과제를 소개 화면에서 미리 추첨하거나, 최종2페이즈 룬 봉인을 UI가 결정하지 않는다. 확정 전에는 기믹의 일반 설명만 표시한다.
- 현재 손패/덱을 분석해 정답 문장을 계산하지 않는다. 고정 예문은 실제 등록 어휘와 문법에서 정상인지 확인한다.
- 예문이 손패에 없다고 그 카드를 무료 지급하지 않는다. 새로운 빙정 지원 규칙도 없다.
- 다음 전투 번호와 적은 실제 다음 encounter와 일치해야 한다. 완료한 1전투 숫자 아래 2전투 몬스터를 혼동되게 표시하지 않는다.
- 프리뷰를 여는 행위로 RNG·셔플·보상·카드 지급이 두 번 실행되지 않는다. read-only preview와 실제 전투 시작 command를 분리한다.
- 저장/로드 후 같은 준비 화면을 다시 보더라도 다음 적·목표·덱이 변하지 않는다.

### 7.4 간결한 문구 편집 기준

다른 라운드도 아래처럼 짧은 해석 틀을 사용한다. 최종 문구의 목표·효과는 실제 `battleLearningGuide`/지역/보스 데이터와 대조한다.

| 유형 | 짧은 뜻의 예 |
|---|---|
| 1형식 | ~하다. |
| 2형식 | ~이다. / ~한 상태이다. |
| 3형식 | ~를 …하다. |
| 4형식 | ~에게 ~를 주다. |
| 5형식 | ~를 …하게 하다. |
| 과거 / 진행 / 현재완료 / 미래 | ~했다. / ~하는 중이다. / ~해 왔다·해 본 적이 있다. / ~할 것이다. |
| to부정사 / 동명사 | ~하는 것. (다른 용법을 다루는 라운드는 ~하기 위해·~할 로 구분) |
| 수동태 | ~되다. / ~받다. |
| 관계절 | ~하는 … / ~한 … |
| 비교급 / 원급 비교 | …보다 더 ~하다. / …만큼 ~하다. |
| 가정법 과거 | 만약 ~라면, …할 텐데. |
| 가정법 과거완료 | 만약 ~했더라면, …했을 텐데. |
| 간접의문문 | 어디서·언제 ~하는지. |
| whether | ~인지 아닌지. |
| 가주어·진주어 | ~하는 것은 …하다. |

이 표는 짧은 표시 예시이지 모든 시제/문형의 의미를 하나로 축소하는 문법 규칙이 아니다. 자세한 용법과 예외는 기존 사전/도움말에 남긴다. 일반 목표 한 줄, 형태 한 줄 또는 필요한 두 줄, 뜻 한 줄, 짧은 예문, 효과 한 줄을 기본으로 한다.

### 7.5 크기·배치

- 기존 준비 화면의 기본 틀을 활용해 한쪽에는 실제 몬스터, 다른 쪽/아래에는 간결한 문법 카드 하나로 묶는다.
- 준비 화면의 몬스터가 작은 아이콘처럼 보이지 않게 기존 프리뷰보다 확대한다. 투명 여백이 아닌 실제 몸체 기준으로 맞춘다.
- 정확한 배율은 프리뷰 영역과 체형에 맞춰 정한다. 실제 전투 화면의 이미 잘 조정된 몬스터 크기까지 다시 일괄 확대하지 않는다.
- 기본 이미지 사용. 그림 미등록/로딩 실패만 이모지 fallback. Stage1~2의 정상 파일은 이모지 대신 반드시 그림.
- 기존 지역 배경/색을 활용할 수 있으나 긴 전투배경을 세로로 늘이거나 새 이미지를 생성하지 않는다.
- 덱·룬·골드는 한 줄 보조 정보. 큰 숫자 상자 세 칸을 유지할 이유가 없으면 간결하게 정돈한다.
- 전투 시작을 주 버튼, 저장을 보조 버튼으로 유지. 긴 셔플/보존 설명을 되살리지 않는다.

## 8. 형태 선택창과 버리기 버튼

### 8.1 형태 선택 팝업

전투의 손패 카드와 조합대 카드 외형을 다시 바꾸는 작업이 아니다. **형태 선택 팝업 안의 선택 카드/버튼과 글자**만 넉넉하게 만든다.

| 요소 | PC/태블릿 가로 구현 시작값 |
|---|---|
| 팝업 폭 | 640~760px 범위, 실제 viewport 안으로 제한 |
| 선택지 높이 | 약 64~80px |
| 형태 영어 단어 | 약 24~28px |
| 형태 라벨 | 약 14~16px |
| 내부 여백 | 약 12~16px |
| 선택지 간격 | 약 8~12px |
| 버리기 버튼 높이/글자 | 약 40~44px / 14~16px |

- 글꼴 계열은 기존 그대로다. 원형/과거/과거분사/-ing 그룹의 시각적 질서와 단정한 간격을 유지한다.
- `과거분사 · p.p.`를 잘 읽히게 표시한다. p.p.만 작고 흐린 장식으로 붙이지 않는다.
- 예를 들어 made가 과거와 과거분사에 각각 있을 때 실제 형태 ID와 설명을 보존한다. UI 편의를 위해 언어 역할을 하나로 뭉개지 않는다.
- 현재 선택은 배경/테두리/체크 등으로 명확히 표시한다. 넓어진 버튼 안에서 단어와 라벨은 균형 있게 정렬한다.
- 팝업만 커지고 선택지는 그대로이거나, 글자만 키우고 테두리에 붙는 결과는 불합격이다.
- 긴 단어에는 충분한 버튼 너비를 제공하고 열 수를 줄인다. 철자 줄바꿈/말줄임표 금지.
- 짧은 가로 화면에서는 버튼을 다시 아주 작게 만들기보다 viewport 내 팝업과 선택 목록의 제한적 내부 스크롤을 허용한다. **채점 숫자 영역의 스크롤 금지와는 별개**다.
- 선택·닫기·Escape·포커스 복귀·터치 조작이 정상이어야 한다. 열고 닫을 때 뒤의 배경/몬스터/조합대 레이아웃을 다시 만들지 않는다.
- CSS 적용은 `.form-dialog` 범위로 제한해 로비/상점/손패의 모든 버튼을 함께 확대하지 않는다.

### 8.2 버리기

손패 선택 카드를 버리는 **확정 버튼**을 조금 더 크고 분명하게 한다. `조합대 비우기`는 다른 동작이므로 명칭/기능을 혼동하지 않는다.

현재 버린 카드 더미 왼쪽 위의 위치와 이미 적용된 세로 보정은 유지한다. 버튼의 배경·테두리 대비, 가로 padding, 선택 장수 표시를 정돈한다. 확대 때문에 카드 줄을 아래로 밀거나 기존 하단 여백을 없애지 않는다. 보이지 않는 큰 hitbox로 주변 화살표/더미를 덮지 않는다.

공격 확정보다 강한 금빛 주 버튼으로 만들지 않는다. 비활성 상태도 글자는 읽혀야 하고, 선택되면 사용할 수 있다는 상태 차이를 선명하게 한다.

## 9. 핵심 Game Feel: 실제 점수 기반 독립 오버레이

### 9.1 사용자 의도

요구는 작은 숫자의 매번 같은 pulse가 아니다. **100점을 넘으면 100점 단계의 크기가 유지되고, 300점을 넘으면 더 커진 기본 크기로 정착하고, 높은 점수일수록 더 뜨거워지는 숫자**다.

점수는 주변 UI 선/패널에 잘리지 않는 독립 연출이되, 화면 구역을 밀거나 카드·몬스터 전체를 가리지 않는다. 채점은 공격의 힘이 쌓이는 과정이며 최종 집결·타격으로 연결되어야 한다.

### 9.2 레이어와 좌표

- 기존 점수 자리의 **숫자 중심점**을 기준점으로 삼는다. 숫자+설명 묶음의 중앙을 맞추는 방식은 금지한다.
- 기존 점수 슬롯의 높이는 그대로 예약한다. 숫자를 overlay로 옮겼다고 슬롯을 접어 카드와 상단 무대를 이동시키지 않는다.
- 화면에 같은 점수 숫자를 패널 안/overlay 두 곳에 중복 표시하지 않는다. 기존 자리의 공간과 접근성 상태는 보존하되 주 시각 출력은 하나로 통일한다.
- overlay host는 패널의 overflow, border, clip-path, transform/contain에 잘리지 않는 공통 presentation 레이어에 둔다.
- 일반 화면과 실제 fullscreen root 안에서 모두 보여야 한다. fullscreen 밖 body에만 붙여 사라지는 문제를 만들지 않는다.
- 실제 표시 중심/안전 영역은 DOM 좌표에서 계산한다. viewport 크기·전체화면이 바뀌면 좌표를 갱신하되 게임 상태를 재생성하지 않는다.
- 게임 모달/설정/튜토리얼 팝업보다 위로 뚫고 나와 조작을 방해하지 않게 레이어 우선순위를 유지한다.
- pointer-events:none, 장식 aria-hidden/inert. 같은 실제 카드 ID나 버튼을 복제하지 않는다. 점수의 접근성 읽기는 의미 있는 결과에 한 번 제공하고 매 프레임 알리지 않는다.
- 숫자·짧은 현재 효과·delta는 같은 중심 기준의 고정 상대 위치를 사용한다. 부연 문구 길이가 숫자를 옆으로 밀지 않는다.
- score 이벤트가 없거나 편집 중이면 overlay는 숨기고 기존 도움말 표시를 유지한다. 예상 점수를 계산/노출하지 않는다.

### 9.3 실제 점수 경계

`score >= 경계값`에서 새 단계로 진입하는 것을 구현 기준으로 한다. 경계값은 사용자 확정, 아래 상대 크기와 효과는 튜닝 시작값이다.

| 단계 | 점수 하한 | 정착 크기(기준 대비) | 시각적 성격 |
|---:|---:|---:|---|
| 0 | 0 | 1.00 | 선명한 상아색, 약한 빛 |
| 1 | 100 | 1.06 | 첫 확대, 따뜻한 윤곽 |
| 2 | 300 | 1.13 | 금빛 강조, 더 뚜렷한 광채 |
| 3 | 600 | 1.22 | 황금/주황, 작은 불티 |
| 4 | 1,000 | 1.32 | 화염 오라가 명확하게 생김 |
| 5 | 1,500 | 1.41 | 더 풍성한 상승 화염 |
| 6 | 2,000 | 1.50 | 밝은 중심·붉은 주황 외곽 |
| 7 | 3,000 | 1.60 | 바깥으로 뻗는 오라와 돌파 감각 |
| 8 | 4,000 | 1.69 | 추가 광채, 힘찬 불티 |
| 9 | 5,000 | 1.78 | 고점 색조, 두 겹의 오라 |
| 10 | 6,000 | 1.88 | 응집된 강한 빛과 화염 |
| 11 | 10,000 | 2.02 | 가장 강한 빛·외곽 광채·한 번의 큰 파동 |

- 같은 단계 안에서도 가산/배율 순간의 짧은 pulse가 가능하지만 **끝나면 그 단계의 커진 크기로 돌아온다.** 늘 작은 기본 크기로 돌아오지 않는다.
- 점수 기준은 현재 확정 `ScoreEvent.after`다. 콤보 개수, 상대의 남은 HP, 실제 HP 감소량을 숫자 단계로 사용하지 않는다.
- 고점의 숫자 본체는 계속 읽힌다. 불꽃·색 변화는 주로 외곽에 두고 숫자 내부를 복잡한 무늬로 덮지 않는다.
- 색 흐름은 기본빛→금빛→화염→고점의 초월적 광채로 일관되게 한다. 임의의 무지개색 순환/빠른 점멸 금지.
- 글꼴 패밀리와 모든 단어 카드 폰트는 유지. overlay 숫자에만 굵기·외곽선·그라데이션·그림자·transform을 적용한다.
- 숫자의 기준 크기는 기존 화면과 어울리게 시작한다. 예시 desktop46px, tablet38px, compact32px는 고정 요구가 아니다.
- 넓이와 자릿수를 고려해 화면 안전 영역 안에서 상한을 둔다. 숫자가 최대 크기에 도달하면 이후 효과는 광채/불티/파동 차이로 강화한다.
- 10,000보다 높은 점수도 정확히 표시한다. 이번에는 최상위 상태를 유지하고 자릿수에 맞게 fit한다. 새 20,000/100,000 임계값을 임의의 게임 규칙으로 추가하지 않는다.
- 상한을 이유로 모든 기기에서 전 단계를 같은 크기로 축소하지 않는다. 대표 PC와 태블릿에서 단계 차이가 보여야 한다.

### 9.4 돌파·누적·재진입

1. 카드 점수/콤보/룬의 엔진 이벤트 순서를 그대로 읽는다.
2. 현재 이벤트 before→after를 표현하고, after가 속한 tier로 정착한다.
3. 같은 공격에서 처음 넘은 경계에만 강한 돌파 연출을 한다.
4. 800→3200처럼 여러 경계를 한 번에 넘으면 **최종 tier로 한 번에 도약**하고 하나의 강화 효과만 낸다. 중간 네 효과를 순차 대기시키지 않는다.
5. 점수 tween이 중간 숫자를 표시할 수는 있으나 임계 이벤트는 실제 before/after로만 판단한다. 실제 계산에 없는 가짜 콤보를 만들지 않는다.
6. 같은 경계를 다시 넘으면 정착 크기는 현재 점수에 맞추되 대형 축하 효과는 중복하지 않는다. 통과한 모든 경계를 attack-local Set에 기록한다.
7. 새로운 attackId에서 상태/잔상/불꽃/통과 경계를 초기화한다. 같은 공격의 DOM 재렌더를 새 공격으로 오인하지 않는다.

### 9.5 콤보와 점수의 역할 분리

- 근거 카드 '또잉', 문법 이름, 룬 빛의 이동은 **어떤 효과가 작동했는지** 알려준다.
- overlay의 크기/기본 화려함은 **현재 공격이 얼마나 강한지** 보여준다.
- 콤보가 많아도 실제 점수가 낮으면 최상위 화염을 주지 않는다.
- 반대로 한 번의 큰 룬 배율로 높은 점수가 나오면 실제 점수 tier로 바로 강화된다.
- 카드 가산·문법 보너스·룬 배율의 강약은 유지한다. 모든 카드마다 최상위 폭발을 쓰지 않는다.

### 9.6 감점·방어·0점

기존 음수 피드백을 overlay에서도 보존/강화한다.

| 사건 | 처리 |
|---|---|
| 문법/형태 감점 | 붉은 주황의 경고, 짧은 수축, `−N`과 실제 이유 |
| 보호막/저항 | 청회색 방패·차단, `−N`과 방어 이유; 학생의 문법 오류로 표시하지 않음 |
| 예견 등 전면 차단 | 차단 표시/피해0, 상승 축하 없음 |
| 단순 재표시/0변화 | 중립, −0/가짜 콤보 없음 |
| 오버킬 | 큰 최종 위력 유지, 실제 피해/초과량을 별도 표시 |
| HP1 보호 | 실제 기믹 이유 표시; engine 점수가 줄지 않았으면 숫자를 임의 차감하지 않음 |
| 적 턴종료 회복 | 적 HP 회복 표시; 플레이어 점수 감소와 혼동하지 않음 |

6000→3000이면 감소 반응 후 3000 tier로 정착한다. 6000의 불꽃을 그대로 유지하지 않는다. 이후 상승 시 해당 단계의 정상 색으로 돌아간다. 원인을 모를 때 '위력 감소'라고 하고 문법 오류라고 지어내지 않는다.

### 9.7 타격까지의 연결

마지막 확정 위력은 약350~500ms를 시작값으로 선명하게 보여준 뒤 기존 카드 집결→돌진→타격에 연결한다. 최고 숫자가 곧바로 사라져 읽을 수 없거나 오버레이가 날아가는 카드들을 전부 가리지 않게 한다.

큰 문장이라도 score tier 돌파 때문에 새 대기 단계를 수없이 추가하지 않는다. 타이밍 변경은 기존 timeline·배속·watchdog 계산에 반영한다. 2배속에서도 핵심 집결·돌진은 식별 가능해야 한다.

### 9.8 성능·접근성

- 큰 연출은 transform/opacity 중심이며 레이아웃 속성의 매 프레임 변경을 피한다.
- 기존 bounded particle pool을 재사용한다. 시작 상한은 데스크톱 동시48개, 터치/작은 화면24개이며 **새 불꽃과 기존 효과의 합계 예산**으로 관리한다.
- 고점이라고 particle 수를 점수에 비례해 무한히 늘리지 않는다. 지속 오라는 가벼운 제한 레이어로 구현한다.
- main game RNG를 시각 효과에 사용하지 않는다. 시각 전용 결정적 배치 또는 별도 시각 시드 사용.
- effectsOff/reducedMotion에서는 반복 불꽃·큰 비행·흔들림을 줄이고 읽기 쉬운 정적 숫자·단계색·현재 효과/감소 이유를 남긴다.
- abort/로비/다음 전투/전체화면 변경 시 취소·정리를 안전하게 처리한다. 렌더 취소가 정산 재실행으로 이어지지 않는다.

## 10. 이전 폴리싱 보존 계약 — 누락/회귀만 보완

### 10.1 고정된 전투 UI와 손패

헤더·상단 무대·좌측 상태·중앙 조합대·우측 룬·하단 손패의 외곽 위치와 크기는 같은 viewport에서 유지한다. 배경 로딩, 0장 손패, 카드6/10/12장 경계, 2줄 문장, 공격 연출에서 접히거나 늘어나지 않는다.

손패 아래 실제 여백은 최소8px, 현재 합의된 약12~16px의 시각적 여유를 보존한다. 새 margin을 계속 누적하지 않는다. 카드의 선택 영역과 그림자를 포함해 실제 바닥이 보이는지 확인한다. 카드 위의 여유가 다시 아래를 밀어내면 구역 내부 간격만 조정한다. 드로우/버린 더미·화살표는 현재 카드 줄 중심에 맞춘다.

같은 전투 카드 편집으로 배경/몬스터를 재마운트하거나 idle 애니메이션을 처음부터 재생하지 않는다. 실제 전투 전환/저장 복원처럼 명확한 수명 변경에서만 재초기화한다.

### 10.2 기존 카드 집결·피격

제출 카드의 시각 복사본만 모여 날아간다. 실제 조합대·손패·버튼은 움직이지 않는다. 기존 일반/피격 두 이미지와 사망 페이드를 그대로 사용한다. 0피해에서는 방어 반응, 양수 실제 피해에서 피격. 격파 후 cleanup이 idle을 잠깐 복구하지 않는다.

### 10.3 BGM·오디오

- 로비/Stage1~2의 실제 파일과 자산 경로를 유지한다. 이번에 새 음원/이미지를 요구하지 않는다.
- 같은 지역에서 입장→전투→보상→보스후 상점까지 곡과 재생 위치 유지.
- 실제 다음 지역 소개가 나타난 때부터 이전 곡3초 유지, 이후 기존 약1.5초 크로스페이드. 3초 무음이 아니다.
- 빠른 입장 버튼/화면 재렌더로 deadline을 다시 시작하지 않는다. 새로운 route/저장으로 이동하면 낡은 예약/비동기 로드만 취소한다.
- 원본 기준 BGM gain `0.8 × 사용자 설정` 유지. 80%를 두 번 곱하지 않는다. 효과음 버스는 기존 값 유지.
- 터치/click에서 audio start/resume, 중단상태 복구, 상단 소리 패널, 명시적 소리 확인/재시도 유지.
- 사용자 mute/0볼륨을 몰래 해제하지 않는다. visual reducedMotion은 오디오 mute와 별개다.
- 패드 실기기를 쓰지 않았다면 청취 성공을 주장하지 않는다.

### 10.4 전체화면과 카카오톡

실제 기능 지원과 요청 결과로 처리한다. 실패 시 주소 복사/수동 복사와 현재 화면 계속하기를 유지하고 강제 외부 앱 실행/가짜 전체화면 성공 표시를 만들지 않는다. fullscreen host 안에서 새 score overlay/카드 FX가 보이는지만 이번에 집중 확인한다. 외부 브라우저로 로컬 저장이 자동 공유된다고 안내하지 않는다.

### 10.5 clearly 회귀

PR #27의 `clearly + 형용사` 보완을 보존한다. `I was a clearly big student.`의 구조를 새 registry/명령문 분기가 다시 망가뜨리지 않게 비교문장 하나를 재확인한다. 이번 작업 때문에 부사 정책 전체를 새로 완화하지 않는다.

### 12.1 검증 예산

- 최종 변경본에서 `npm test`, `npm run validate:data`, `npm run build` 실행. AGENTS의 관련 브라우저 검사도 수행하되 변경 영역에 맞게 선택한다.
- 기본 자동 검사에 실패하면 원인을 확인한다. 테스트 삭제/skip/기대값을 무근거로 낮추기 금지. 변경된 계약의 기대값은 이유와 함께 갱신한다.
- **50전투 자연 완주, 대량 seed, 전체 OS/브라우저 조합, 수백 장 캡처는 완료 조건으로 요구하지 않는다.**
- 10,000점 UI를 보기 위해 정상 덱으로 장시간 고점을 노리지 않는다. 기존 개발용 재생/표시 fixture에서 확정 timeline을 공급해 시각 표시만 확인할 수 있다. 이를 자연 플레이 점수/승률로 보고하지 않는다.
- 실제 게임 공격도 별도로 1~2종 확인해 fixture에서만 동작하는 연출을 피한다.
- 태블릿 에뮬레이션은 실기기 오디오 검증이 아니다. 기기 없으면 NOT RUN. UI 구현 완료 인계를 불필요하게 막지 않는다.
- 대표 캡처는 3~5장, 동작 확인이 필요한 경우 짧은 채점→타격 클립 1개 또는 실제 관찰 기록이면 충분하다. 촬영 자체를 별도의 대규모 프로젝트로 만들지 않는다.

### 12.2 완료 판단
