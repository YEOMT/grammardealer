# 0. 구현 전 절대 원칙

1. 최신 `origin/main`과 `AGENTS.md`를 유일한 코드 기준으로 사용한다.
2. 과거 ZIP, 번들, 다른 DS 게임 코드를 현재 소스 위에 덮어쓰지 않는다.
3. Vanilla JS + ES Modules + Vite, `RunController` 단독 상태 커밋, Grammar → Scoring → Rune → Stage → Presentation 경계를 유지한다.
4. 새 문법은 해금 전에도 구조적으로 옳으면 정상 문장이다. **해금은 문법 정답 여부가 아니라 콤보 점수와 보상 풀을 연다.**
5. 편집 중 정답·예상 점수·보스 충족 여부를 미리 계산해 보여주지 않는다.
6. 의미의 자연스러움은 참고 정보이며 문법·점수·보스 조건으로 역의존하지 않는다.
7. 0.5.1의 정상 기능과 frozen legacy view를 보존한다.
8. 빙정 카드는 새 운영 카드가 아니다. **문법 엔진에는 정상 WORD 카드**다.
9. 조합대에 비교 패턴을 고정하거나 빈칸 학습지처럼 강제하지 않는다.
10. 합성 fixture·지정 상태·자동 정책·production UI 실제 완주를 구분해 보고한다.

# 1. 사용자 확정 사항 / 구현 초깃값 / 이번 범위 밖

## 1.1 사용자 확정 사항

- Stage 6의 이름은 「거울의 설원」이다.
- 6-1은 눈토끼·비교급, 6-2는 설원 늑대·최상급, 6-3은 눈꽃 정령·as ~ as, 6-4는 북극곰·too/enough, 6-5는 거울뿔 사슴이다.
- than/as/more/most/too/enough/twice 등은 Stage 6 전투에 한정해 공급되는 ‘빙정 단어 카드’로 먼저 도입한다.
- 빙정 카드는 조합대에 정상적으로 올라가는 WORD 카드이며, 운영 카드나 고정 슬롯이 아니다.
- 빙정 카드는 사용하면 깨져 그 전투에서 사라지고, 사용하지 않아도 전투 종료 시 모두 제거된다. 영구 덱을 비대하게 만들지 않는다.
- 보스 위에는 빙결핵 5개가 있으며, 모두 깨기 전에는 보스 HP가 1 아래로 내려가지 않는다.
- 보스 결정은 정해진 비교 구조만 요구하지 않는다. 문법적으로 성립한 공격에서 실제 빙정 카드를 소비했다면 물리 카드 수만큼 결정이 깨진다.
- 마지막 결정을 깨는 공격부터 HP 1 제한이 해제되며, 충분한 위력이면 그 공격으로 격파할 수 있다.
- 기존 형용사 카드에는 비교급·최상급 형태를 추가한다. -er/-est는 별도 단어 카드가 아니다.
- 기존 0.5.1의 전투 자원, 점수·룬 고점, 운영 카드, 보스, 튜토리얼, 저장 호환을 보존한다.

## 1.2 구현·검증용 초깃값

- Stage 6 HP: 760 / 830 / 900 / 970 / 1,280.
- 비교급 ×1.8, 최상급 ×1.9, as ~ as ×1.8, too/enough 정도 표현 ×1.5.
- twice as ~ as의 추가 효과는 +20.
- Stage 6 지역 보너스는 대상 비교·정도 구조가 성립했을 때 공격당 한 번 ×1.25.
- 6-1 빙정: than, more. 6-2: most, the. 6-3: as×2, twice. 6-4: too, enough, to.
- 6-5 빙정: than×1, as×2, more×1, most×1, too×1, enough×1, twice×1(총 8장).
- 일반전은 빙정 1장이 첫 손패에 보이도록 하고, 보스는 첫 손패 2장 + 초기 3개 드로우 구간에 각 1장씩 접근 가능하도록 배치한다.
- Stage 6 진입에는 세 번째 상점이 열리며 Stage 4 상점과 같은 2룬/3카드 구성을 사용한다.
- Stage 6 클리어 뒤 빙정 단어의 일반 카드 버전을 보상·상점 후보로 해금한다.

초깃값은 구현자가 임의로 낮추거나 기존 룬/점수에 숨은 상한을 넣어 맞추지 않는다. 실제 플레이 결과가 과도하면 후속 밸런스 패치에서 조정한다.

## 1.3 이번 범위 밖

- Stage 7 콘텐츠, 신규 캐릭터, 룬 대개편.
- 최종 배경·몬스터·보스 이미지와 BGM.
- 부정문·일반 의문문·일반 조동사의 공통 기반 확장.
- 실제 iPad Safari·Android 실기기 검증은 별도이며 Playwright WebKit으로 대체하지 않는다.

# 3. 빙정 카드 시스템

## 3.1 정체성

빙정 카드는 **전투에만 존재하는 임시 WORD 인스턴스**다.

- 문법 분석: 일반 WORD와 동일
- 조작: 클릭, 드래그, 형태, 교환 등 기존 WORD 규칙
- 수명: 현재 전투 한정
- 영구 덱: 포함하지 않음
- 보상·상점·연마·제거: 현재 임시 인스턴스는 대상이 아님
- 디자인: 같은 카드 크기 + 청백색 테두리 + `빙정 · 이번 전투 한정`

새 `cardKind`를 만들지 않는다. `OPERATION`으로 위장하지 않는다.

## 3.2 권장 상태 계약

영구 소유 카드는 계속 `run.activeCardIds`다. Stage 6 전투에는 다음을 추가한다.

```js
combat.temporaryCardIds: string[]
combat.temporaryCardMeta: {
  [instanceId]: {
    source: 'MIRROR_SNOWFIELD',
    battleId: string,
    cardDefId: string,
    crystalBearing: boolean,
    supportOnly: boolean,
    supplyIndex: number
  }
}
combat.shatteredTemporaryIds: string[]
combat.frostSupplyTrace: object[]
```

임시 인스턴스 자체는 `run.cardInstances`에 존재하되 `activeCardIds`에는 들어가지 않는다. 전투 종료 후 해당 인스턴스를 모두 제거한다.

## 3.3 카드 보존식

영구 카드:

```text
activeCardIds
= draw + hand + sentence + discard + exhausted(operation)
  (단, temporaryCardIds 제외)
```

빙정 카드:

```text
temporaryCardIds
= draw + hand + sentence + discard + shatteredTemporaryIds
  중 temporaryCardIds에 속한 ID
```

한 ID가 두 영역에 동시에 있거나, 다른 전투의 임시 ID가 들어오거나, 영구 카드가 shattered 영역에 들어오는 저장은 거절한다.

## 3.4 전투별 공급

| 전투 | 기본 임시 빙정 WORD |
|---|---|
| 6-1 | `than`, `more` |
| 6-2 | `most`, `the` |
| 6-3 | `as`, `as`, `twice` |
| 6-4 | `too`, `enough`, `to` |
| 6-5 | `than`, `as`, `as`, `more`, `most`, `too`, `enough`, `twice` |

현재 영구 덱에 비교·정도 구조에 쓸 수 있는 형용사/부사가 한 장도 없다면 검수된 `good` 임시 지원 카드를 추가한다.

지원용 `the/to/good`는 보스의 결정 대상 카드와 구분한다.

## 3.5 섞기와 접근성 보정

빙정 카드는 영구 덱과 함께 deck stream으로 섞는다. 단, 6턴 안에 지역 문법을 실제로 시도할 수 있도록 아래의 **가시성 보정**을 적용한다.

- 6-1~6-4: 핵심 빙정 최소 1장을 첫 손패에 배치
- 6-5: 결정 대상 빙정 최소 2장을 첫 손패에 배치
- 6-5: 남은 결정 대상 빙정 중 최소 3장을 첫 세 개의 turnDraw 창에 1장씩 배치
- 초기 전체 shuffle 뒤 안정적인 swap/reorder로 처리
- 보정 때문에 reward/shop/encounter RNG를 소비하지 않음
- 보정 결과를 `openingTrace`와 `frostSupplyTrace`에 기록
- 손패가 가득 차 draw가 잘리면 기존 정책대로 끝이며 별도 draw credit 없음

## 3.6 수명과 이동

| 행동 | 결과 |
|---|---|
| 손패→조합대 | 정상 배치, 아직 소비 아님 |
| 조합대→손패 | 정상 회수 |
| 교환 | discard로 이동, 아직 소비 아님 |
| 보급 | 정상 draw |
| 탐색 | 드로우 더미에서 선택 가능 |
| 공격 확정 | 제출된 빙정은 shattered 영역으로 이동 |
| INVALID_CORE 제출 | 카드도 깨짐, 보스 결정은 깨지지 않음 |
| 전투 종료 | 남은 빙정과 깨진 빙정 모두 완전 제거 |
| 다음 전투 | 새 battle-scoped 인스턴스를 생성 |

빙정 카드가 포함된 문장 공격의 정산은 한 번만 이루어진다. Presentation은 확정된 `consumedTemporaryCardIds`를 읽어 깨짐 연출만 수행한다.

# 4. 비교·정도 문법 데이터

## 4.1 0.6 언어 view

`campaign05Registry`를 복제한 `snowLanguage` 계층을 추가한다.

- version: `0.6.0`
- validationScope: `snow.0.6`
- 과거 registry 객체를 변형하지 않음
- 기존 Form ID를 삭제하거나 재사용 의미를 바꾸지 않음

신규 lexeme/card:

- `than`
- `as`
- `more`
- `most`
- `too`
- `enough`
- `twice`

`the`와 `to`는 기존 정의를 재사용한다.

## 4.2 신규 일반 카드의 보상 속성

| 단어 | 정규 카드 등급 | Stage 6 전 |
|---|---|---|
| as | COMMON | 보상/상점 잠금 |
| than | COMMON | 보상/상점 잠금 |
| too | COMMON | 보상/상점 잠금 |
| more | UNCOMMON | 보상/상점 잠금 |
| most | UNCOMMON | 보상/상점 잠금 |
| enough | UNCOMMON | 보상/상점 잠금 |
| twice | RARE | 보상/상점 잠금 |

정규 카드 정의는 `runtimeReady=true`, `starterEligible=false`지만 `requiredUnlockId:'pack.snowWords.reward'`를 만족하기 전에는 reward/shop pool에서 제외한다.

빙정 임시 공급은 이 보상 잠금을 우회해 물리 임시 사본을 생성할 수 있다.

## 4.3 형용사·부사 비교 정책

각 활성 형용사/부사에 검수된 정책을 둔다.

```js
comparisonPolicy: {
  strategy: 'INFLECTED'|'PERIPHRASTIC'|'IRREGULAR'|'BOTH',
  comparativeFormId?: string,
  superlativeFormId?: string,
  allowMore?: boolean,
  allowMost?: boolean
}
```

자동 문자열 규칙만으로 전체 단어를 생성하지 않는다. 최소 필수 검수:

- good → better → best
- bad → worse → worst
- big → bigger → biggest
- small → smaller → smallest
- happy → happier → happiest
- sad → sadder → saddest
- kind → kinder → kindest
- young → younger → youngest
- old → older → oldest
- new → newer → newest
- easy → easier → easiest
- hard → harder → hardest
- safe → safer → safest
- strong → stronger → strongest
- clear → clearer → clearest
- fast → faster → fastest
- well → better → best

다음 계열은 원칙적으로 `more/most + 원급`:

- interesting, difficult, beautiful, important, necessary, possible
- useful, different, serious, tired, ready
- quickly, slowly, carefully, clearly 등 `-ly` 부사

애매한 단어는 audit 문서에 채택 정책과 이유를 기록한다.

## 4.4 형태 메뉴

형용사/부사 카드의 형태 메뉴은 다음 순서로 표시한다.

```text
원급
[big]

비교급
[bigger]

최상급
[biggest]
```

periphrastic 전용 단어는 원급만 보이며, `more/most`는 별도 WORD를 사용한다. 학생이 형태를 고르는 것이 의미 있는 `read` 등의 동일 철자 Form ID는 기존대로 구분한다.

# 5. Grammar Engine 지원 범위

## 5.1 문법 hit

```text
COMPARISON.COMPARATIVE
COMPARISON.SUPERLATIVE
COMPARISON.EQUALITY
COMPARISON.MULTIPLIER
DEGREE.TOO
DEGREE.ENOUGH
QUANTIFIER.MORE
QUANTIFIER.MOST
QUANTIFIER.ENOUGH
ADVERB.TWICE
```

모든 hit는 실제 카드 범위, marker 카드, parent clause, head를 보존한다.

## 5.2 비교급

지원:

- `S + be + comparative adjective (+ than + NP/clause)`
- `S + V + comparative adverb (+ than + NP/clause)`
- `more + periphrastic adjective/adverb (+ than + NP/clause)`

예:

- `I am bigger than you.`
- `This book is more interesting than that book.`
- `She runs faster than me.`

`than` 없는 `I am bigger.`도 정상 비교급이지만, 별도 than marker 증거는 없다.

## 5.3 최상급

학교 문법의 기본 범위:

- `the + adjective-est + noun`
- `the most + adjective + noun`
- 검수된 불규칙 `the best/worst + noun`

예:

- `This is the biggest book.`
- `She is the most beautiful student.`

허용된 소유 한정사 등은 audit에서 명시한다. `most students`는 최상급이 아니라 수량 표현으로 분석한다.

## 5.4 as ~ as

- 실제 as 카드 두 장 필요
- 가운데에는 원급 형용사/부사
- 뒤에는 지원 가능한 NP 또는 절
- `twice + as ~ as`는 배수 비교

예:

- `I am as strong as you.`
- `This book is twice as big as that book.`

`as stronger as`는 issue이며 equality 콤보 자격이 없다.

## 5.5 too / enough

지원:

- `too + adjective/adverb`
- `too + adjective/adverb + to-infinitive`
- `adjective/adverb + enough`
- `adjective/adverb + enough + to-infinitive`
- `enough + noun`

예:

- `I am too tired.`
- `I am too tired to run.`
- `I am strong enough to help you.`
- `I have enough time.`

## 5.6 대체 보스 공략 용법

보스 결정은 비교 hit를 요구하지 않으므로 다음도 정상적인 빙정 소비가 된다.

- `I need more water.`
- `Most students like music.`
- `I have enough time.`
- `I read books twice.`

다만 표면 단어를 억지로 붙인 INVALID_CORE나, 해당 빙정 카드가 unlicensed/excluded된 분석은 결정 자격이 없다.

## 5.7 대표 정확성 이슈

```text
COMPARISON_FORM_MISMATCH
DOUBLE_COMPARISON_MARKING
AS_REQUIRES_POSITIVE_DEGREE
SUPERLATIVE_FORM_OR_DETERMINER
COMPARISON_STANDARD_REQUIRED
```

이슈는 학교 문법의 핵심 오개념만 다룬다. 의미상 이상함은 감점하지 않는다.

## 6.2 점수 초깃값

| 구조 | 효과 |
|---|---:|
| 비교급 | ×1.8 |
| 최상급 | ×1.9 |
| as ~ as | ×1.8 |
| too/enough | ×1.5 |
| twice as ~ as | +20 |
| 거울의 설원 지역 | ×1.25 |

각 태그는 공격당 한 번만 적용한다. 정상적인 서로 다른 구조가 한 문장에 함께 있으면 각각 적용할 수 있다.

점수 순서:

```text
카드
→ 정확성
→ 완전문장
→ 주절 문형
→ 시제
→ to부정사/동명사
→ 비교/정도
→ 절·구 연결
→ 기본 수식
→ 룬
→ 지역
→ 보스
→ 최종 공격력
```

수량 `more/most/enough`와 일반 부사 `twice`는 문법적으로 정상이어도 비교·정도 배수를 자동으로 받지 않는다.

## 6.3 무룬·무연마 산술 기대값

| 문장 | 기대 위력 |
|---|---:|
| `I am bigger than you.` | 287 |
| `This book is more interesting than that book.` | 395 |
| `This book is the most beautiful book.` | 386 |
| `I am as strong as you.` | 323 |
| `This book is twice as big as that book.` | 462 |
| `I am too tired to run.` | 376 |
| `I am strong enough to help you.` | 420 |
| `I need more water.` | 126 |
| `I read books twice.` | 131 |

모든 수치는 단계별 floor 정책을 따른다. `more water`, 문장 끝 `twice`는 보스 결정 대체 경로지만 설원 지역 배수는 받지 않는다.

# 7. 거울뿔 사슴 보스

## 7.1 상태

```js
bossMechanic: {
  id: 'FROST_CRYSTAL_LOCK',
  crystalsMax: 5,
  crystalsRemaining: 5,
  brokenCount: 0,
  appliedAttackIds: [],
  totalPreventedDamage: 0
}
```

## 7.2 결정 파괴 조건

한 공격의 결정 파괴 수:

1. 분석 상태가 `VALID` 또는 `VALID_WITH_ISSUES`
2. 최종 공격력이 1 이상
3. 제출한 카드 중 `crystalBearing:true`인 Stage 6 임시 빙정 WORD
4. 해당 카드가 unlicensed/excluded되지 않음
5. 같은 물리 ID와 attackId를 중복 계산하지 않음

```text
breakCount = min(eligiblePhysicalFrostCards, crystalsRemaining)
```

**비교 hit는 필수가 아니다.**

## 7.3 HP 1 잠금

- 공격 처리 전후로 결정 상태를 계산
- 공격 후에도 결정이 남으면 HP를 최소 1로 clamp
- 막힌 피해는 `preventedDamage`로 기록
- 다음 공격으로 이월하지 않음
- 이 상태는 overkill로 기록하지 않음
- 마지막 결정을 깨는 공격은 제한 없이 피해를 적용
- 결정이 이미 0이면 일반 보스처럼 처리

예:

```text
HP 300 / 결정 3
위력 900 / 빙정 2장 정상 소비
→ 결정 1
→ HP 1
→ preventedDamage 기록
```

다음 공격:

```text
HP 1 / 결정 1
위력 100 / 빙정 1장 정상 소비
→ 결정 0
→ HP 0, 격파
```

## 7.4 8장 중 5장

보스는 결정 대상 빙정 8장을 제공하지만 5개만 정상 소비하면 된다.

- 특정 단어 순서 없음
- 특정 비교 구조 5종 강제 없음
- 한 문장에서 2~3장을 정상 사용하면 그만큼 동시에 파괴
- 3장의 여유분은 드로우·실수·덱 구성에 대한 완충 역할
- 4장 이상을 INVALID_CORE로 낭비해 공략이 어려워지는 것은 플레이 결과이며 자동 무한 재공급하지 않음

# 8. UI·도감·연출

## 8.1 빙정 카드

- 기존 WORD 카드와 동일 크기
- 청백색 얇은 테두리
- 눈결정/균열의 가벼운 장식
- `빙정 · 이번 전투 한정`
- 품사·단어·점수·버리기 버튼은 항상 읽을 수 있음
- 효과 감소에서도 수명 표식은 사라지지 않음

## 8.2 깨짐 연출

공격 확정 후 제출된 빙정 카드의 복제 이미지가 짧게 금이 가고 흩어진다.

- Presentation은 `consumedTemporaryCardIds`만 읽음
- 실제 pile 이동이나 결정 파괴를 다시 계산하지 않음
- reduced motion에서는 이동 대신 밝기/균열 플래시
- finish/cancel에서 effect node를 회수
- 연출 오류가 전투 상태를 되돌리거나 이중 정산하지 않음

## 8.3 보스 UI

보스 상단 또는 HP 주변:

```text
빙결핵  ◇ ◇ ◇ ◇ ◇
```

상태:

- 남음: 밝은 청백색
- 파괴: 균열/회색
- 마지막 파괴: 짧은 강조
- HP 잠금: `빙결핵이 남아 있어 체력이 1 아래로 내려가지 않습니다.`
- 전부 파괴: `모든 빙결핵이 깨졌습니다!`

## 8.4 도감 항목

기존 0.5.1의 짧은 문구 원칙을 유지한다.

- **비교급(-er / more ~ than)**  
  둘을 비교해 한쪽의 정도가 더 큼을 표현합니다.
- **최상급(the -est / the most)**  
  셋 이상에서 가장 높은 정도를 표현합니다.
- **원급 비교(as ~ as)**  
  두 대상의 정도가 같음을 표현합니다.
- **정도 표현(too / enough)**  
  지나치거나 충분한 정도를 표현합니다.

플레이어 문장·피드백 색상·학습 순서는 기존 정책을 유지한다.
