## 2. A — 쉼표 도구와 조합대 세로 바

### 2.1 손패 도구

PC·태블릿의 현재 갈색 쉼표 도구는 유지한다. **스마트폰의 도구만 현재 ‘버린 카드’ 버튼과 비슷한 체격으로 조금 줄인다.** 크기 비교는 실제 렌더링 결과를 기준으로 한다.

- 손패 오른쪽의 독립 보조칸과 모든 손패 페이지에서 접근하는 기능을 유지한다.
- 손패 장수·선택 개수·페이지 카드 목록에 도구를 넣지 않는다.
- 배치/이동/회수/위치 목록을 여는 기존 탭 경로를 보존한다. 좁은 표식을 정확히 드래그하는 조작만 강요하지 않는다.
- 현재 모바일 너비 44px, 높이 64px인 구현을 확인했다. 실제 버린 카드의 높이를 비교해서 높이 약 56~60px를 **조정 시작값**으로 삼을 수 있다. 정확한 숫자는 사용자의 확정 수치가 아니다.
- 작은 도구를 만들기 위해 손패 줄을 더 내리거나 하단 여백을 없애지 않는다. 터치 영역이 이웃 버튼과 겹치지 않아야 한다.

### 2.2 조합대의 모습 — 확정 방향

**옆 단어 카드와 같은 높이, 훨씬 좁은 너비의 갈색 세로 바를 단어 사이에 끼운다.** 바의 가로 중앙·세로 중앙보다 조금 아래에 상아색 쉼표를 놓는다.

| 요소 | 기준 / 조정 시작값 |
|---|---|
| 높이 | 옆 단어 카드의 현재 전체 표시 높이. 형태 버튼이 그 카드 상자에 포함되면 함께 기준으로 삼음 |
| 너비 | PC·패드 18~22px, 스마트폰 14~18px부터 비교 |
| 바탕 | 짙은 밤색. 기존 쉼표 팔레트와 일관되게 유지 |
| 테두리 | 얇은 밝은 갈색/황동색. 눈부신 금빛·상시 발광 금지 |
| 기호 | 밝은 상아색 `,`, 작은 화면에서도 또렷한 굵기 |
| 기호 위치 | 실제 기호의 잉크가 가로 중앙, 세로 약 60~70% 위치. baseline 때문에 바닥에 붙지 않음 |
| 삭제할 표시 | 품사·희귀도·연마·점수·0점·형태 버튼 없음 |

갈색 바는 **놓인 쉼표 자체**이고, §6의 **청색 바는 드래그 중 임시 위치 안내**다. 두 표현의 의미와 색을 혼동하지 않는다.

### 2.3 단어 배치·줄 경계

- WORD 배열에 쉼표를 삽입하지 않는다. CSS grid의 9번째/13번째 카드처럼 취급하지 않는다.
- 쉼표가 있는 경계 한 곳에 필요한 폭을 확보한다. 현재의 조합대 내부 여백/간격을 우선 재배분하되 **쉼표 하나 때문에 모든 줄·모든 카드의 글씨를 추가 축소하지 않는다.** 전체 조합대나 외부 UI 구역은 늘리지 않는다.
- 한 줄 8/12개의 단어와 마지막 경계의 쉼표를 함께 표시할 수 있어야 한다. 끝자리에는 필요한 작은 trailing 여유를 확보한다. 물리적으로 확보가 불가능한 viewport는 기존 제한적 스크롤 정책을 존중하고 겹침을 숨겨 통과시키지 않는다.
- 앞 단어에 연결된 쉼표는 앞 단어와 같은 줄에 둔다. 줄바꿈 후 다음 줄 첫 칸에 쉼표만 떠서는 안 된다.
- 문장 맨 앞/맨 끝 쉼표는 기존 규칙대로 표시하고 제출 후 진단한다. 화면이 알아서 문법적으로 올바른 위치로 옮기지 않는다.
- 카드 회수·재정렬·맞교환 시 쉼표의 기존 anchor 계약을 유지한다. 새 좌표 저장 방식이나 문장 스냅샷 스키마를 도입하지 않는다.
- 조합대 스크롤·카드 크기 계산·전체화면·주소창 변화 뒤에도 높이와 위치가 옆 카드에 맞아야 한다.
- 기호가 카드 단어·형태 버튼·정보 버튼·스크롤 화살표를 가리면 실패다.
- `.word-card` 집계, 드래그 대상, 절 경계 계산은 계속 실제 단어 ID만 사용한다. 바를 클릭해 인접 단어가 회수되지 않도록 한다.

### 2.4 표시 수명

쉼표는 편집·제출·연출에서 기존 데이터가 지시하는 때만 보인다. 제출 시 제거/복원, 오류 공격, 저장/불러오기, 비소비 오류는 기존 v0.14.0 계약 그대로다. 이번 변경으로 초기화 시점을 바꾸지 않는다.

## 3. B — ‘지역 보너스’와 ‘목표 문법’으로 정보 통합

### 3.1 몬스터 왼쪽의 기본 표시

```text
지역 보너스
4형식 ×1.25

[목표 문법]
```

- 첫 줄은 **지역 보너스**라는 제목만 표시한다.
- 그 아래는 **실제 지역 보너스 대상의 짧은 요약 + 실제 배율**을 표시한다. `×` 표기를 통일한다.
- 행동 버튼의 문구는 **목표 문법**만 둔다.
- 현재의 **보너스 조건 / 문법 도움말 / 상시 노출된 이번 전투의 문법 카테고리**를 이 버튼 안으로 통합한다. 중복 제목과 설명을 전투 화면에 다시 붙이지 않는다.
- 현행 별도 ‘보스 공략’ 도움말의 정적 설명도 같은 창의 해당 섹션에서 접근 가능하게 해 중복 버튼을 최소화한다. **기존 실시간 보스 상태 표시는 옮기거나 없애지 않는다.**
- 배율이 없는 최종전 등은 실제 정책에 따라 ‘추가 배율 없음’ 또는 현행 ×1 표기를 사용한다. ×1.25를 모든 지역에 고정하지 않는다.
- 보너스 대상과 이번 전투 추천 목표는 다를 수 있다. 하나를 다른 하나로 축소/대체해서 설명하지 않는다.

### 3.2 목표 문법 창

기존 modal 구조·닫기·스크롤을 재사용한다. 별도의 새 도움말 화면/탭 시스템을 만들지 않는다.

```text
목표 문법
이번 전투: 4형식
형태: 주어 + 동사 + 간접목적어 + 직접목적어
뜻: ~에게 ~를 주다.
예문: I give you a book.

지역 보너스
[현재 원정에서 실제 적용되는 정확한 조건과 배율]

보스 공략 / 추가 설명
[해당 전투에 이미 있는 설명이 필요할 때만]
```

- `battleLearningGuide`, 기존 준비 화면 안내/보너스 도움말 등 현재의 검증된 안내 데이터를 재사용한다. 가능한 항목은 표시하고 없는 예문을 임의 생성하지 않는다.
- 이번 지역의 문법 카테고리, 이번 전투의 구체 목표, 보너스 범위, 필요한 기존 설명을 여기에서 확인한다. 긴 기술 용어·내부 태그·개발용 문구를 추가하지 않는다.
- `뜻`은 기존 짧은 해석 틀을 유지한다. ~에게 ~를 주다처럼 직관적으로 쓴다.
- 현재 편집 문장을 읽어 정답·점수·다음 보스 성공을 예측하지 않는다. 도움말은 기존 학습 안내다.
- 창 열기/닫기는 카드·쉼표·선택·손패 페이지·룬 순서·턴·RNG·음악 재생 위치를 변경하지 않는다. 기존 공격 잠금 규칙을 우회하지 않는다.
- 실·봉인·HP 1 보호 같은 **현재 상태**는 원래 표시를 유지한다. §0.2의 보류 항목을 이번에 새로 디자인하지 않는다.

### 3.3 조합대 주변의 중복 안내

기존 조합대의 상시 문법 설명이 같은 내용을 반복한다면 목표 문법 창으로 모은다. 다만 **점수 앵커, 점수 영역의 예약 크기, 실제 계산 라벨, 오류 안내**는 제거하지 않는다. 긴 안내를 줄이려다 점수 오버레이의 위치나 전투 외곽 높이가 바뀌지 않게 한다. 튜토리얼의 필요한 행동 안내는 삭제하지 않는다.

## 4. C — 용어와 빈 룬 슬롯

| 대상 | 최종 화면 문구 |
|---|---|
| 드로우 더미 / DRAW라는 묶음 이름 | **뽑을 카드** |
| 버린 카드 더미 / DISCARD라는 묶음 이름 | **버린 카드** |
| 빈 룬 슬롯 | **비어 있음** |

표시 예: `뽑을 카드 · 18장`, `버린 카드 · 6장`. 기존처럼 숫자가 별도 행에 있어도 된다. 영문 묶음 제목과 불필요한 ‘더미’ 표현은 빼고, 슬롯의 장식용 ◇와 ‘비어 있는 슬롯’ 같은 문구는 ‘비어 있음’으로 단순화한다.

- 전투 버튼, 해당 상세창 제목, 관련 도움말·툴팁·접근성 이름을 일관되게 맞춘다.
- 내부 `draw`, `discard`, 카드 ID, 저장 키, 명령 이름은 바꾸지 않는다. 일반 영어 단어 카드나 과거 기록을 전역 문자열 치환하지 않는다.
- 동작을 설명할 필요가 있으면 ‘카드 2장 뽑기’처럼 풀어 쓸 수 있으나, 이번에 새 규칙이나 광범위한 문체 개편을 하지 않는다.
- ‘내 덱’과 전체 보유 카드 개념은 그대로 둔다.
- 이름만 바꾼다. 다음 드로우 순서를 공개하거나 버튼을 누르면 무료 뽑기가 실행되게 하지 않는다.
- 빈 룬 슬롯의 크기·개수·발동 순서·순서 조작 기능은 바꾸지 않는다.

## 5. D — 모바일 턴·교환·골드 위치

모바일 전투의 상단 오른쪽 텍스트 HUD에서 자원 세 항목을 제거하고, **몬스터 왼쪽 기존 정보 영역 안에서 지역 보너스의 왼편**에 세 줄로 둔다.

```text
턴      4/6   │ 지역 보너스
교환    2회   │ 4형식 ×1.25
골드    120   │ [목표 문법]
```

예시 숫자를 하드코딩하지 않는다. 현재 전투 상태의 값과 기존 단위/의미를 사용한다.

- 왼쪽은 자원 열, 오른쪽은 지역 보너스/목표 문법. 새 큰 사이드 패널이나 하단 바를 만들지 않는다.
- 자원 라벨·숫자의 열을 맞추고 숫자가 변해도 몬스터/HP/UI가 좌우로 튀지 않게 한다.
- 상단 오른쪽은 소리·전체화면·메뉴 등 기존 조작 기능만 유지한다. 남아야 하는 로비 기능의 접근 경로도 보존한다.
- 기존 PC/넓은 패드의 자원 패널은 옮기지 않는다. 기존 스마트폰 레이아웃 분기를 기준으로 하며 ‘터치 기기니까 모두 모바일’로 판정을 바꾸지 않는다.
- 압축된 가시 높이에서도 세 값과 목표 문법 버튼에 접근할 수 있어야 한다. 글자를 무작정 축소하거나 중앙 몬스터 영역을 밀어내지 않는다. 기존 극소형 viewport의 내부/전체 스크롤 안전장치는 유지한다.
- 갱신은 실제 Controller 상태를 읽는다. 턴/교환을 낙관적으로 미리 감소시키거나 화면에서 별도로 세지 않는다.

**현재 코드 주의점:** retained combat 갱신에 `.mobile-battle-hud`를 직접 조회하는 경로가 있다. 헤더의 노드를 지우면서 이 참조를 남기면 다음 카드 조작에서 오류가 날 수 있다. 최초 렌더와 retained 업데이트를 함께 수정하고, 새 자원 영역의 갱신 및 도움말 이벤트도 누락하지 않는다. 몬스터 이미지 subtree를 다시 만드는 것으로 회피하지 않는다.

## 6. E — 반투명 청색 삽입 위치 바

### 6.1 확정 시각 방향

**드래그 중 실제로 삽입될 단어 경계 한 곳에만 반투명 청색 세로 바**를 표시한다.

- 예시 시작값: 폭 3~4px, 약 55~70% 불투명도, 청색/하늘색 계열. 주변 단어 카드 높이에 맞춘 얇은 bar.
- 사용자 확정은 ‘반투명 청색’이다. 구체 색상값/px는 실제 배경 위에서 조정 가능한 구현값이다.
- 눈부신 번쩍임, 펄스, 화살표 문구, 빈 가짜 카드, 커다란 광원은 넣지 않는다.
- **현재 드래그 복사본은 위치·크기·그림·오프셋 모두 그대로 둔다.** 손가락 위로 띄우기 안을 적용하지 않는다.
- hover 중 카드 크기/순서/줄 배치를 바꾸지 않는다. drop 후 실제 명령이 성공했을 때만 기존 방식으로 배치한다.
- 실제 쉼표 바는 갈색으로 남고, 쉼표를 놓는 중의 후보 위치도 청색으로 일관되게 안내한다. 추가 갈색 가상 카드 미리보기는 만들지 않는다.

### 6.2 정확한 위치를 표시하는 조건

- 기존 hit-test가 반환하는 **INSERT의 최종 대상**을 재사용한다. 시각 바만 별도로 최근접 문법 위치를 추측하지 않는다.
- 손패 → 조합대, 조합대 내 순서 변경, 쉼표 배치/이동의 각 경계는 실제 drop 명령 결과와 일치해야 한다.
- **SWAP은 삽입이 아니다.** 현재 맞교환 영역/임계값/조작은 그대로 유지하고, SWAP일 때는 청색 삽입 바를 숨긴다. 필요한 기존 대상 카드 강조만 유지한다.
- 가득 찬 조합대에 추가할 수 없거나 봉인·잠금·잘못된 영역 등으로 불가한 동작에는 성공할 것 같은 삽입 바를 표시하지 않는다. 수용성 판단은 현재 규칙/상태를 재사용하고 문법 분석은 실행하지 않는다.
- 처음/끝/빈 조합대/8·12장 줄 경계/모바일 마지막 줄에서도 정확한 위치를 보여준다. 표시 때문에 카드 수를 다르게 세지 않는다.
- 다른 줄의 최근접 카드가 잘못 선택되지 않도록 **보이는 영역의 좌표·스크롤 위치**를 반영한다.
- `pointerup`의 실제 최종 좌표를 기존 방식으로 재판정한다. 오래된 hover 값으로 drop을 강행하지 않는다.
- 삽입 바는 layout에 참여하지 않는 pseudo-element/absolute/fixed 표시 등 작은 방법으로 구현한다. 별도 UI 프레임워크나 DnD 라이브러리는 도입하지 않는다.

### 6.3 취소·레이어

- 바는 입력을 가로채지 않는 장식이다. `pointer-events:none`, 비포커스·보조기기 숨김을 적용한다.
- drop, 영역 밖 이동, pointercancel, lostpointercapture, 다중 터치 취소, 화면 전환, 정상 viewport 변경에 따른 기존 드래그 취소, 모달 열기, cleanup 때 정리한다.
- 전체화면의 현재 FX 호스트 및 좌표 규약을 따르며 다른 overlay 뒤로 숨지 않는다. 단, 열린 dialog보다 위에 강제로 띄우지 않는다.
- 8px 등 기존 drag 시작 임계값과 input guard를 변경하지 않는다. 짧은 탭, 드래그 후 중복 click 차단, 운영/장애물 카드 제약을 보존한다.
- CSS로 충분한 부분은 CSS로 수정한다. 두 개의 drag engine이나 중복 document listener를 만들지 않는다.

## 7. F — 형태 변경 뒤 아주 짧은 확인

형태 선택을 확정하고 실제 `SET_FORM`이 성공했을 때, 해당 카드의 현재 자리에서 **테두리/외곽 광택이 한 번 지나가듯 짧게 강조**한다.

- 조정 시작값: 약 180~260ms. 고정된 보조 반응이며 게임 입력을 잠그지 않는다.
- 카드·단어의 이동/확대/높이 변경, 주변 카드 흔들림, 새 팝업/토스트/효과음은 없다.
- 기존 폰트·색상·카드 정렬을 유지한다. 선택창의 현재 선택 표시는 기존 구성을 활용한다.
- DOM이 교체되는 구조라면 **성공한 명령의 실제 cardInstanceId**로 새 렌더의 해당 카드를 찾아 한 번 표시한다. 옛 DOM 노드나 카드 배열 index에만 기대지 않는다.
- 취소, 실패, readonly, 공격 잠금, 같은 선택을 다시 누른 무변경에는 성공 반응을 내지 않는다.
- 같은 철자의 과거/과거분사처럼 선택 설정만 달라지는 경우도 기존 명령이 실제 변경으로 처리했다면 확인 반응을 줄 수 있다. 판정 용법을 UI에서 강제하지 않는다.
- 빠른 연속 변경은 해당 카드의 이전 강조만 정리하고 최신 1회로 갱신한다. resize/도움말/로드 때 재실행하지 않는다.
- effects off/reduced motion에서는 움직임 없이 짧은 정적 테두리 변화로 대체하거나 장식 애니메이션을 생략한다. 형태 변경 결과는 항상 보인다.

## 8. G — 감점 계산과 실제 오류 위치 강조

### 8.1 새 진단 기능 대신 기존 결과 사용

**오류 분석을 추가하지 않고**, 현재 확정된 ScoreEvent/Analysis의 실제 감소량·이유·관련 카드·문장부호 근거를 표시한다. 특히 v0.14.0의 `PUNCTUATION.COMMA` 이벤트는 이미 감소량·reasonKo·highlightCardIds를 전달하는 구조다.

### 8.2 감점 순간의 글자와 숫자

- 문법·형태·쉼표 감점 시 현재 계산 라벨/감소량/계산식은 분명한 붉은색 계열로 표시한다. 현재 서체 계열을 유지하고 기존보다 필요한 만큼 굵게 한다.
- 표시 예: **‘쉼표 위치 오류 · −30’**. 실제 전후 점수로부터 나온 값을 사용한다. 예시 숫자를 적용하지 않는다.
- 중앙 숫자도 같은 이벤트 동안 짧게 손실 색을 사용할 수 있다. 다음 계산/최종 위력에서는 현재 점수 단계의 기존 스타일로 복귀한다.
- 숫자 중심·자릿수 정렬·점수 앵커·계산 단계·표시 시간 계약은 유지한다. 별도 긴 감점 화면이나 누적 로그·스크롤을 만들지 않는다.
- 같은 감소량을 라벨과 amount에 반복해 `−30 · −30`처럼 출력하지 않는다. 기존 라벨에 이미 감소량이 포함되는 경우를 고려한다.
- 실제 차이가 0이면 거짓 감소량을 만들지 않는다. 필요한 기존 진단만 표시한다.

### 8.3 잘못된 위치만 짧게 강조

- 해당 감점 이벤트의 실제 cardInstanceId에 대응하는 **제출 당시 조합대 카드** 테두리/배경에 짧은 붉은 강조를 준다. 위치·폭·높이를 바꾸거나 카드를 흔들 필요는 없다.
- 쉼표 위치 오류는 **놓인 갈색 쉼표 바**를 먼저 강조한다. 엔진 근거에 연결된 단어가 있으면 그 카드들만 함께 표시한다.
- 바가 없는 ‘쉼표 누락’ 등은 엔진이 제공한 경계/관련 카드가 있을 때만 그 위치에 작은 정적 오류 표시를 준다. 정답 쉼표를 자동 삽입하지 않는다.
- 원정 카드가 내부적으로 이미 정산됐더라도 현재 공격의 제출 시각 자료를 사용한다. 새 손패의 같은 자리나 다른 카드에 표시하지 않는다.
- 모바일에서 오류 근거가 스크롤 밖에 있으면 억지로 화면을 점프시키지 않는다. 보이는 라벨을 유지하고, 같은 공격의 해당 표시를 실제 카드에 연결한다. auto-scroll/새 기록 UI는 이번에 추가하지 않는다.
- 근거가 없다면 아무 카드나 추측해 강조하지 않는다. 기존 짧은 이유만 표시한다.
- 여러 오류를 모두 크게 깜빡이지 않는다. 현재 재생 중인 감점 이벤트의 근거만 일관되게 표시하고 다음 이벤트로 전환한다.
- 문장 불성립/0점은 기존 진단 흐름에서 해당 근거만 표시한다. 이를 위해 감점 이벤트를 인위적으로 생성하지 않는다.

### 8.4 원인 구분은 유지

| 결과 | 표시 기준 |
|---|---|
| 문법·형태·쉼표 오류 | 붉은 손실 라벨 + 실제 오류 근거 위치 |
| 일반전 저항·보호막·보스 차단 | 기존 청회색/방어 계열 + 실제 방어 원인. 정상 단어를 오류색으로 칠하지 않음 |
| 오버킬·HP 1 보호로 실제 HP 감소가 작음 | 문법 감점으로 오표시하지 않음 |
| 문장 불성립 | 기존 0점/진단. 정상 공격 성공 연출이나 가짜 감소량 추가 금지 |

현재 `scoreFeedback()`의 읽기 전용 분류를 보완하는 방식으로 연결한다. `scoring`, `punctuation`, `stage`, 룬/보스 계산의 수치·순서는 바꾸지 않는다.

강조의 시간 초깃값은 약 250~400ms, 반복 점멸은 하지 않는다. 기존 감점 읽기 시간이 더 길면 그 안에서 자연스럽게 끝낸다. effects off/reduced motion에서도 **손실 색·실제 감소량·이유 같은 정보**는 남기고 움직임만 없앤다.

## 9. H — 배경·몬스터 표시 준비와 화면 전환 안정화

### 9.1 목표

준비 화면과 실제 전투에 들어갈 때 **작은 몬스터/이모지 → 뒤늦게 큰 몬스터 → 배경 등장 → 레이아웃 재배치**처럼 여러 번 바뀌는 인상을 줄인다. 새 전환 연출을 만드는 작업이 아니다.

기본 순서:

> 현재 화면에서 가능한 다음 이미지 준비 → 다음 화면의 최종 공간 예약 → 이미지 준비와 배치 계산 완료 → 그 크기로 표시.

**이미지 로딩 때문에 게임 명령·시작 버튼·진행을 기다리게 하지 않는다.** 네트워크가 늦거나 이미지가 없는 경우에도 정보를 읽고 다음 행동을 할 수 있어야 한다.

### 9.2 최종 기하를 먼저 고정

- 배경·몬스터의 로딩 여부와 관계없이 기존 scene metadata의 원본 비율, idle/hit 공통 bounds·앵커를 이용해 최종 표시 영역을 예약한다.
- 준비 화면은 이미 합의한 **파노라마 원본 비율 전체 + 중앙 몬스터 + 하단 정보/버튼**을 유지한다. 새 cover crop이나 비율 왜곡으로 로딩 문제를 덮지 않는다.
- 전투의 무대·손패·조합대/헤더 높이는 기존 viewport 계산을 따른다. 이미지의 naturalHeight로 부모를 늘리지 않는다.
- 보스는 현재의 일반 몬스터 대비 확대 목표와 안전 한계를 보존한다. 로드 후 다시 거대해지며 정보창을 덮어서는 안 된다.
- 보이는 첫 이미지부터 가능한 한 최종 fit을 적용한다. `ResizeObserver`/rAF 등 기존 측정 흐름을 활용하되 동일 치수 반복 갱신으로 루프를 만들지 않는다.

### 9.3 준비 대상과 규모

작은 이미지 준비 유틸리티가 필요하면 현재 asset resolver를 재사용해서 추가할 수 있다. 독립 아트 파이프라인이나 새 엔진은 만들지 않는다.

- 현재 장면에서 필요한 배경, 현재 몬스터 idle과 hit가 우선이다.
- 준비 화면에서는 **곧 시작할 동일 전투의 combat 배경·idle·hit**를 우선 준비한다. 경로를 알고 있다는 이유로 새 전투 명령을 미리 실행하지 않는다.
- 전투/보상에서 다음 대상이 이미 데이터로 확정돼 있으면 인접한 다음 1장면 정도만 추가 준비할 수 있다. 보상 추첨·상점 생성·보스 과제 추첨·시드를 소비해 다음 장면을 알아내지 않는다.
- 아직 없는 지역 이미지·몬스터는 현재 manifest의 부재로 판단하고 기존 지역 팔레트/대체 표시를 사용한다. 없는 파일 경로를 계속 추측하지 않는다.
- 50전투 전체 에셋·오디오를 한꺼번에 받거나 전체 해상도 비트맵을 무제한 보관하지 않는다. 네트워크 절약 신호가 있으면 다음 장면의 투기적 준비는 생략할 수 있다.
- URL 단위 진행 중 요청을 합쳐 중복 준비를 피하고, 현재/바로 다음 장면을 벗어난 JS 참조는 정리한다. 실패한 Promise를 영구 성공처럼 저장하지 않고 재시도는 사용자 재진입 등 명확한 시점으로 제한한다.

### 9.4 이미지 준비·실패 처리

- `HTMLImageElement.decode()` 지원 시 디코딩 완료를 확인한 뒤 표시하는 방법을 우선 검토한다. 미지원/실패는 load/error와 유효한 intrinsic 크기를 확인하는 대체 경로로 처리한다. `complete`만 보고 무조건 성공 판정하지 않는다.
- 배경과 idle이 준비된 정상 경로에서는 같은 장면의 최종 배치로 함께 드러나도록 한다. hit 준비 완료는 다음 화면 진입의 필수 대기 조건이 아니다.
- 처음부터 충분히 준비돼 있으면 즉시 보여준다. 불필요한 최소 대기시간을 붙이지 않는다.
- 배경/idle이 늦으면 지역 팔레트와 이미 예약된 공간·이름·정보·버튼을 즉시 표시한다. 짧은 표시용 묶음 대기 후 준비된 자산과 대체 화면으로 진행할 수 있다. 예: 최대 600ms는 **시각 묶음 전환의 조정 가능한 시작값**이며 입력/Controller 지연 시간이 아니다.
- 자산 등록이 있고 잠시 로딩 중인 경우는 작은 이모지를 먼저 띄워 나중에 점프시키기보다 같은 공간의 차분한 대체 상태를 사용한다. 진짜 미등록/실패는 기존 이모지 등 안전한 fallback을 유지해도 된다.
- 오류 시 spinner만 영원히 유지하거나 다음 전투 버튼을 막지 않는다. 개발 경고는 같은 URL마다 과하게 반복하지 않는다.
- idle만 준비된 첫 공격에서 hit가 늦으면 현재 idle + 기존 안전한 피격 피드백으로 처리할 수 있다. hit가 늦게 도착했다고 종료된 피격을 다시 재생하지 않는다.

### 9.5 경합·수명·상태 보호

- scene key/epoch 또는 동등한 소유권을 사용한다. 준비 중 로비로 나가거나 다른 지역·저장으로 바뀌면 늦은 callback이 새 화면에 옛 몬스터/배경을 덮지 못하게 한다.
- 같은 URL 요청을 공유해도 각 view의 적용 여부는 자기 scene key와 현재 포즈·생존 상태로 따로 확인한다.
- 몬스터가 이미 죽었거나 피격/소멸 중이라면 로딩 완료가 idle을 다시 보이게 하지 않는다. 늦은 ready 이벤트가 `reset(false)` 같은 초기화를 유발해서는 안 된다.
- 같은 전투에서 카드 추가/회수/형태 변경/쉼표 조작/도움말 때문에 배경과 몬스터를 재로드하거나 대기 동작을 처음부터 시작하지 않는다.
- 카드 집결·돌진·점수 overlay의 현재 viewport/전체화면 좌표와 cleanup을 보존한다. 이미지 준비 완료가 새로운 공격을 실행하거나 제출 시각 자료를 제거하지 않는다.
- 전체화면/오디오 unlock에 필요한 기존 실제 사용자 제스처 경로 앞에 이미지 `await`를 끼우지 않는다. 이미지 준비는 독립적으로 실행한다.
- BGM 전환 시작점과 1초 무음은 현재 music director가 관리한다. 이미지 준비 시점으로 재시작/지연/중복 전환하지 않는다.
- 서비스워커·영구 캐시·기기 저장 구조를 추가하지 않는다. 이번 캐시는 표시 준비용 메모리 참조와 기존 브라우저 캐시 활용 범위다.

## 11. 구현 순서와 범위 관리

1. 현재 정상 화면과 기존 명령 흐름을 짧게 확인한다. 최신 branch/AGENTS/관련 문서만 읽고 전체 프로젝트 재설계로 확장하지 않는다.
2. 문구 통합·빈 슬롯·모바일 자원 정보와 retained 업데이트를 같이 수정한다.
3. 쉼표 바와 모바일 도구 치수를 수정하고 8/12열 끝자리 및 마지막 단어 접근을 확인한다.
4. 기존 drag target에 청색 바만 연결한다. 맞교환·회수·취소가 그대로인지 확인한다.
5. 성공한 형태 변경의 짧은 강조, 감점 라벨 및 근거 위치 강조를 연결한다.
6. 기존 asset/monster 수명 위에 제한된 이미지 준비와 최종 크기 예약을 연결한다.
7. 관련 빠른 검사와 마지막 기본 test/build를 수행하고 즉시 인계한다.

수치/문법/새 콘텐츠가 필요해 보이면 이번 패치에 임의 추가하지 말고 별도 메모로 남긴다. v0.14.0의 문법 문제를 발견해도 이번 UI 패치 속에서 광범위하게 고치지 않는다. 단, 현재 변경이 만든 회귀는 고친다.

## 13. 검증 예산 — 필요한 곳만

### 13.1 7개 짧은 확인 묶음

| 묶음 | 한 흐름 안에서 확인할 내용 |
|---|---|
| T1 정보/레이아웃 | PC·패드·스마트폰의 목표 문법/보너스/자원/용어/빈 룬, 도움말 한 번 열고 닫기 |
| T2 쉼표/행 경계 | 1·8·9·12·13·24단어 중 각 레이아웃의 필요한 경계, 앞/중간/끝 쉼표 배치·이동·회수 |
| T3 입력 | 삽입/맞교환/재정렬/회수, 취소/마지막 pointerup, 실제 청색 바와 명령 순서 비교 |
| T4 형태/감점 | 정상 형태 변경 및 무변경, 실제 문법·쉼표 감점, 방어 감소 한 사례씩과 올바른 근거 강조 |
| T5 이미지 | 캐시가 준비된 진입, 늦은 이미지/404, 준비 중 로비 이동, hit 지연, 같은 전투 편집 때 무대 유지 |
| T6 가시 영역/효과 | 스마트폰 가로에서 주소창으로 높이 축소, 전체화면 왕복·효과 끄기, 마지막 카드/버튼 접근 |
| T7 회귀/인계 | 기존 저장 읽기, 정상 공격 2~3회 중 필요한 사례 결합, 최종 test/build와 결과 정리 |

대표 크기는 기존 검사에서 쓰는 PC 1280×720(또는 1920×1080), 패드 1024×768, 스마트폰 844×390 및 약 310px 가시 높이를 재사용하면 된다. 모든 조건을 모든 크기에 곱해서 검사하지 않는다. 보이는 치수와 내부 스크롤을 짧게 측정한다.

### 13.2 자동검사와 실기기 구분

- `AGENTS.md`가 요구하는 **최종 `npm test`, `npm run build`**, 이번 UI/입력/연출에 해당하는 브라우저 검사를 수행한다.
- 이미 있는 focused 검사 또는 해당 section을 재사용한다. 겹치는 전체 브라우저 세트를 습관적으로 여러 번 돌리지 않는다.
- 단어·문법 데이터/수치 정책은 변경하지 않으므로 새 대규모 언어 검증표나 밸런스 시뮬레이션을 만들지 않는다. 저장소의 필수 CI는 예외 없이 따른다.
- **50전투 자연 완주, 대량 seed, 전 기기 순회, 100장 단위 캡처를 요구하지 않는다.** 상태를 지정해 마지막 줄·보스·감점 표시를 확인한 경우 그 사실을 명시한다.
- 테스트 fixture는 자동검사 내부에서만 사용할 수 있다. 일반 게임에 가상 점수·테스트 버튼·개발 라벨·데모 화면을 넣지 않는다.
- 터치 emulation은 실제 iPad/iPhone/인앱 브라우저 확인과 구별한다. 실기기가 없으면 해당 항목만 `NOT RUN`으로 남기고 구현을 인계한다.
- 화면상 명백한 겹침·사라짐·잔여 입력 잠금·중복 정산은 남겨두고 통과 처리하지 않는다. 미실행은 통과가 아니다.

### 13.3 인계 산출물

변경 파일 요약, 구현/미구현/미실행 구분, test/build 결과, PC/모바일 대표 화면 합계 **3~5장 이내**를 기본으로 한다. 드래그·형태·감점·진입 흐름은 한 짧은 시연으로 묶을 수 있으며 새 영상 제작 도구를 만들 필요는 없다.

개발 브랜치와 요청된 범위의 PR로 인계한다. **별도 승인 없이 main 병합·Pages 설정 변경·공개 배포는 하지 않는다.**

## 14. 최종 완료의 의미

> 쉼표가 문장 안에서 또렷하게 보이고, 설명은 목표 문법 버튼 하나로 모이며, 모바일 자원 정보는 몬스터 왼쪽에서 읽힌다. 카드를 놓을 곳은 청색 바가 알려주고, 형태 변경과 감점은 해당 위치에서 짧게 확인된다. 배경과 몬스터는 준비된 크기로 자연스럽게 나타난다. 그 외 게임은 그대로다.

사용자가 승인한 것은 이 범위다. 보스 완료 표시·기록 구조 해설·대형 이펙트 작업은 다음 논의로 남긴다.

소스와 기술 참고의 구분은 동봉한 `SOURCE_NOTES.md`에 적었다. 구체적인 시간·픽셀·불투명도는 사용자 확정 수치가 아닌 조정 가능한 구현 시작값이다.
