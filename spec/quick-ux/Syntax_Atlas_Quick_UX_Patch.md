# Syntax Atlas — UI·편의성 소규모 패치

## 작업 원칙
최신 실제 작업 소스와 `AGENTS.md`를 확인하고, 현재 정상화된 UI를 보존하며 아래 변경만 적용한다. 과거 ZIP이나 0.10.0 파일로 덮어쓰지 않는다. 새 레이아웃을 설계하거나 전면 리팩터링하지 않는다. 이 문서는 이번 소규모 패치의 범위이며, 과거 대규모 명세의 전체 재구현·재검증을 요구하지 않는다.

**목표: 플레이 가능한 수정본을 먼저 인계하고, 미세한 디자인은 사용자의 직접 플레이 피드백으로 다듬는다.** 버전명은 실제 최신 버전을 확인해 다음 패치 번호로 정하며 임의로 과거 버전으로 되돌리지 않는다.

## 1. 손패 확대 — PC·태블릿
- 현재 손패 카드의 실제 표시 너비·높이를 기준으로 **각각 약 1.2배 이상** 확대한다. 특히 세로 공간과 단어·형태 선택·교환 선택의 누르기 편한 영역을 확보한다.
- **조합대 카드 크기·영어 글자 크기는 변경하지 않는다.** 이전의 손패/조합대 동일 크기 조건은 이번 지시로 대체한다.
- 손패는 항상 한 줄이다. 확대 후 너비가 부족하면 기존 좌우 페이지 기능으로 표시 장수를 조절한다. 화면에 맞추려고 다시 카드를 축소하거나 두 줄로 만들지 않는다.
- 기본 손패 한도 10장과 룬 등으로 증가한 실제 한도를 보존한다. 페이지를 바꿔도 카드 ID와 선택 상태를 유지한다.
- 손패 내부 여백을 먼저 정리하고, 기존 상단 정보·조합대·버튼을 잘라내거나 크게 재배치하지 않는다. 휴대전화의 기존 가로 전용 정책도 유지한다.

## 2. 조합대 — 가로·세로 중앙정렬
- 한 줄은 가로·세로 중앙에 놓는다. 두 줄은 두 행 전체를 세로 중앙에 묶고, 각 행을 독립적으로 가로 중앙정렬한다.
- 기존 **한 줄 최대 12장 / 두 줄 최대 24장**과 타이트한 외곽 크기를 유지한다. 이번에는 문장 한도를 다시 변경하지 않는다.
- 장수가 늘면 필요한 행 간격·상하 여백만 조정한다. 카드 너비·영어 글자 크기를 바꾸거나 조합대가 다른 정보 영역을 밀어내게 하지 않는다.
- 줄바꿈·정렬은 표시만 바꾸며, 문장 순서·드래그·삽입·형태 선택은 기존대로 작동해야 한다.

## 3. 버튼과 카드 회수
### 턴 넘기기
- `준비 · 다음 턴 …` 버튼의 주 문구를 **`턴 넘기기`**로 바꾼다.
- 기존 턴 소모, 드로우, 턴 종료 보스 효과, 마지막 턴 판정은 그대로다. 드로우 설명이 필요하면 실제 규칙 값으로 짧은 보조 설명만 제공한다.

### 조합대 비우기
- `편집 되돌리기` 버튼을 **`조합대 비우기`**로 교체한다. 이름만 바꾸고 기존 UNDO를 실행하는 것은 금지한다.
- 누르면 **손패 빈자리만큼 조합대의 가장 오른쪽 카드부터 순서대로 손패로 회수**한다. 두 줄이면 제출 순서상 마지막 카드부터 처리한다.
- 회수 수 = `min(조합대 카드 수, max(0, 실제 손패 한도 - 현재 손패 수))`.
- 예: 한도 10장·손패 8장이라면 오른쪽 2장만 회수한다. 나머지 조합대 카드의 상대 순서는 그대로다.
- 손패가 가득 차면 상태를 바꾸지 않고 `손패에 빈자리가 없습니다`를 안내한다. 빈 조합대에서는 비활성 또는 무동작 처리한다.
- 턴·교환 횟수·재화를 소비하지 않는다. 카드 ID·선택형·연마·빙정 등 속성을 보존한다. 회수는 버리기나 빙정 사용·소멸이 아니다.
- 기존 안전 입력 처리를 재사용한다. 연출 중에는 실행하지 않으며, 연속 클릭으로 카드 복제·소실이 생기지 않아야 한다.
- 짧은 설명: `손패 빈자리만큼 오른쪽 카드부터 회수합니다.`

### 버리기 위치 / 사용 완료 버튼
- 손패 아래의 `버리기(선택 장수)` 버튼을 **오른쪽 버린 카드 더미의 왼쪽 위**로 옮긴다. 잔여 교환 횟수와 선택 해제도 필요하면 같은 작은 조작 묶음에 둔다.
- 페이지 화살표·카드·버린 카드 더미 열기와 겹치지 않게 하고, 기존 선택 후 버리기/교환 규칙은 바꾸지 않는다.
- 왼쪽 상시 기능 패널에서 **`사용 완료` 버튼만 제거**한다. 사용 완료 카드 기록, 중복 사용 방지, 카드 보존·저장 로직은 유지한다. 대체 메뉴는 새로 만들지 않는다.

## 4. 카드 집결·돌진·피격 표시 복구
- 사용자 제보: PC에서 채점 후 제출 카드를 모아 적에게 타격하는 모션이 보이지 않는다. 원인은 아직 확정되지 않았다.
- 정상 효과 설정에서 **채점·룬 발동 → 제출 카드 집결 → 적을 향한 돌진 → 피격·피해 표시**가 보이도록 기존 구현을 복구한다.
- 먼저 기존 효과 호출, 좌표, clipping, 레이어, 조기 정리/중단을 확인한다. 새 연출 시스템이나 추가 파티클을 만들지 않는다.
- 창모드와 전체화면에서 표시가 정상이어야 한다. 사용자 효과 끄기·모션 감소 설정을 강제로 해제하지 않는다.
- 점수·HP·턴 정산은 바꾸지 않는다. 연출 복구나 화면 전환으로 공격이 다시 정산되지 않게 한다.

## 5. 지역 입장 화면 정돈
- 지역 안내·전투 목록·핵심 규칙을 **클릭해 펼치지 않아도 기본 표시**한다. 긴 안내문을 새로 늘리지 않고 기존 정보를 간결하게 정돈한다.
- 입장 화면의 몬스터 목록에는 **이름과 해당 원정의 실제 HP만 표시**한다. 몬스터 이모지·그림·초상은 숨긴다. 전투 화면의 몬스터 표시는 유지한다.
- 큰 개별 박스 대신 짧은 목록 또는 작은 셀을 사용하고, 불필요한 내부 여백을 줄인다.
- 상단은 지역명·짧은 소개, 중앙은 배경 감상 공간, 하단은 컴팩트한 정보와 그 아래 **`초원에 들어가기` 같은 입장 버튼**으로 정리한다. 버튼은 하단 안전 여백 안에 둔다.
- 기존 입장 선택·카드 지급·상점 진입·저장 기능은 그대로 보존한다. 실제 선택이 필요한 항목을 설명 정리와 함께 삭제하지 않는다.
- 이번에는 배경/몬스터 원화 제작, 테마 팔레트 전면 개편을 하지 않는다.

## 변경하지 않는 범위
문법 판정, 카드·룬 성능/희귀도, HP, 보스 기믹, 보상·상점·경제, 손패/문장 한도, 저장 형식·기존 원정 호환, 스테이지 수를 변경하지 않는다. 최종 보스 3연전은 별도 기획이며 이번 범위 밖이다. 기존 가로 전용·페이지 손패·콤보 가독성·룬 발동 효과는 보존한다.

## 최소 확인과 완료 기준
**새 대규모 검증을 만들지 않는다.** 변경한 동작과 대표 화면에만 집중한다.

1. **카드 회수:** 손패 빈자리 0 / 2 / 충분한 경우와 증가한 실제 한도를 짧은 검사로 확인한다. 회수 전후 총 카드와 속성, 오른쪽부터 회수, 턴·교환 불변을 확인한다.
2. **전투 화면:** 대표 PC 창모드·전체화면, 태블릿 가로에서 손패 확대/한 줄/페이지, 조합대 한 줄·두 줄 중앙정렬, 이동한 버튼의 클릭·잘림을 확인한다. 가능한 모든 크기를 순회하지 않는다.
3. **공격·턴:** 정상 공격으로 집결·돌진·피격을 확인하고, 턴 넘기기가 기존 동작을 유지하는지 확인한다. 효과가 안 보였던 현상을 재현하지 못하면 그 사실을 보고한다.
4. **입장 화면:** 일반 지역 1곳과 기존 입장 선택이 있는 지역 1곳에서 기본 정보·이름/HP·이미지 숨김·하단 입장·진행을 확인한다. 기존 저장 하나가 정상 열리는지도 확인한다.

저장소 `AGENTS.md`가 요구하는 필수 검사와 빌드는 **최종 변경본에서 한 번 실행**한다. 통과 후 영향 없는 동일 검사를 반복하지 않는다. 실패하면 실제 진행·계산·저장·입력 결함을 수정하고 관련 검사만 재실행한다. 실패 삭제·강제 PASS는 금지하며, 무관한 기존 실패는 근거와 함께 구분 보고한다.

**제외:** 47전투 자연 완주, 전 브라우저×전 해상도 검사, 대량 스크린샷, 새 성능 벤치마크, 수십/수백 항목의 인수표, 미세 간격·색감의 반복 폴리싱. 단, 필수 버튼 잘림·카드 소실·진행 불가는 미세 디자인 문제가 아니므로 고친다.

## 인계
현재 변경을 보존한 작업 브랜치에서 구현한다. 보고는 **수정 내용 / 실제 검사 결과 / 남은 문제 / 브랜치·PR**만 간단히 한다. 대표 캡처는 필요 범위의 2~3장으로 충분하다. 하지 않은 검사는 `NOT RUN`으로 쓴다. 권한이 없으면 로컬 변경·커밋과 제한을 보고한다. 사용자 승인 없이 main 병합·공개 배포하지 않는다.
