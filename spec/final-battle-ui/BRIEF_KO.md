# Syntax Atlas — 최종 전투 UI 레이아웃 복원 및 폴리싱 패치

첨부한 **Syntax Atlas 최종 전투 UI 시안 이미지**를 이번 작업의 최우선 시각적 기준으로 사용하라.

현재 게임은 v0.10.1까지 구현되었으나, 반응형·전체화면 UI 패치 이후 기존의 균형 잡힌 공간 구성이 무너지고 불필요한 여백, 정보 패널의 잘못된 위치, 지나치게 큰 조합대 등 사용자 경험상 문제가 발생했다.

**이번 작업의 목적은 기능 추가나 새로운 디자인 창작이 아니라, 첨부한 시안의 UI 구조를 현재 게임에 충실히 적용하여 깔끔하고 짜임새 있는 최종 전투 화면을 완성하는 것이다.**

## 1. 최우선 작업 원칙

1. 첨부한 이미지는 단순한 분위기 참고 자료가 아니다. **각 UI 영역의 위치, 크기, 비율, 여백, 정렬과 시각적 위계를 결정하는 기준 시안**이다.
2. 이미지에 등장하는 배경 그림·몬스터 일러스트·임의의 문구·가상 카드·가상 룬 수치를 그대로 구현하지 않는다.
3. 기존 게임의 카드 디자인, 품사 색상, 문법 판정, 룬, 보스 기믹, 저장, 보상, 공격 연출을 보존한다.
4. **v0.10.0의 안정적이었던 PC 화면을 기본 참고 구조로 삼되, 첨부 이미지의 공간 배분을 반영한다.**
5. PC 일반 창, PC 전체화면, 태블릿 가로에서 동일한 UI 구성 원칙을 유지한다.
6. 새로운 장식과 효과를 추가하기보다, 기존 UI 요소를 올바른 위치에 정돈하는 데 집중한다.

## 2. 전체 화면 구조

화면을 다음 다섯 영역으로 분리한다.

### A. 최상단 헤더

- 왼쪽: SYNTAX ATLAS
- 화면의 정확한 중앙: 현재 스테이지 번호 및 지역명
- 오른쪽: 전체화면 버튼, 로비 버튼
- 기존처럼 얇고 간결하게 유지한다.
- 전체화면 전환 여부에 따라 헤더의 요소가 움직이거나 겹치지 않도록 한다.

### B. 상단 몬스터 영역

첨부 시안처럼 **몬스터를 상단 중앙의 주인공으로 배치**한다.

- 몬스터 이미지(현재는 이모지)는 상단 중앙에 적당한 크기로 표시한다.
- 몬스터 이름과 체력 바는 몬스터 바로 오른쪽에 배치한다.
- **지역 보너스와 간단한 몬스터·보스 공략법은 몬스터 왼쪽**에 배치한다.
- 보스 기믹, 보호막, 페이즈 등 중요한 상태는 몬스터 정보와 가까운 곳에서 확인할 수 있어야 한다.
- HP 바는 적 정보 영역에 적합한 길이로 제한한다. 화면 전체 너비로 늘리지 않는다.
- 향후 몬스터 일러스트가 들어갈 공간을 고려하되, 지금부터 과도하게 큰 무대를 만들지 않는다.
- 상단 영역과 조합대 사이에는 자연스러운 시각적 구분을 둔다.

### C. 중앙 전투 영역 — 3열 구성

**왼쪽 상태·기능 패널 / 중앙 조합대 / 오른쪽 룬 패널**

세 영역은 같은 높이에서 시작하며 시안처럼 균형 있게 나란히 배치한다.

**왼쪽 패널**

- 남은 행동 턴과 시각적인 턴 표시
- 남은 교환 횟수 및 보유 재화
- 사전, 도감, 저장, 내 덱, 설정
- 각 기능은 명확한 버튼 형태로 제공한다.
- 좌우 돌출, 글자 잘림, 작은 버튼의 겹침을 방지한다.

**오른쪽 패널**

- 장착 룬과 장착 수
- 룬 이름, 레벨, 짧은 효과 설명
- 룬 관리 및 기존 순서 변경 기능
- 최대 4슬롯까지 균형 있게 표시
- 내용이 길면 내부 정보 배치를 정리하되, 패널을 화면 바깥으로 확장하지 않는다.

좌우 패널은 조합대와 수평으로 정렬하고, 몬스터 양옆으로 흩어 배치하지 않는다.

### D. 중앙 문장 조합대 — 가장 중요한 영역

**조합대는 12장 × 2줄, 총 24장이 들어가는 공간으로 설계한다.**

- 한 줄에 최대 12장의 카드가 들어간다.
- 두 줄에 총 24장을 조합할 수 있다.
- 손패와 조합대의 카드 가로 너비, 단어 글자 크기, 기본 카드 디자인을 통일한다.
- 카드 개수에 따라 카드가 좌우로 늘어나거나 찌그러지지 않는다.
- 카드가 몇 장이든 해당 행은 중앙정렬한다.
- 첫 번째 줄과 두 번째 줄을 각각 중앙정렬한다.
- 카드 수가 적어도 조합대 전체를 과도하게 넓히거나 높이지 않는다.
- 카드가 두 줄이 될 때는 세로 여백을 줄여 공간을 효율적으로 사용한다.
- 조합대 높이는 카드 두 줄과 필요한 조작 공간에 맞춘다. 남는 화면 높이를 모두 조합대에 할당하지 않는다.

**조합대 크기는 사용 가능한 공간의 크기가 아니라, 카드 12×2배치를 기준으로 결정한다.**

조합대의 가로 폭과 높이를 제한하고, 회수한 공간은 상단 몬스터 정보와 양쪽 상태·룬 패널의 가독성에 사용한다.

기존 카드 조립·드래그·삽입·순서 변경·형태 선택·되돌리기 기능은 모두 유지한다.

### E. 하단 손패

**손패는 반드시 한 줄만 사용한다.**

- 현재의 카드 디자인과 읽기 쉬운 단어 크기를 유지한다.
- 손패 카드를 두 줄 이상으로 줄바꿈하지 않는다.
- 화면 너비보다 손패가 많으면 **좌우 페이지 이동 버튼**으로 다른 카드를 표시한다.
- 현재 페이지와 전체 페이지 수를 명확히 표시한다.
- 손패의 페이지를 전환해도 선택 상태와 카드 ID가 유지되어야 한다.
- 카드 드래그, 선택 후 버리기, 형태 선택 및 손패 교환이 정상적으로 작동해야 한다.
- 드로우 덱은 왼쪽, 버린 카드 덱은 오른쪽에 표시한다.
- 화면 너비가 넓다는 이유로 손패 카드를 과도하게 늘리거나 카드 사이 간격을 크게 벌리지 않는다.

## 3. 점수 및 콤보 표시

현재의 어색하게 분리된 점수 영역을 정리한다.

- 점수 숫자와 콤보 이름을 하나의 중앙 시각 그룹으로 묶는다.
- 공격 전에는 해당 라운드의 목표 문법을 간결하게 표시한다.
- 공격 후에는 문법 콤보, 룬 발동, 점수 증가가 명확하게 보이도록 한다.
- 콤보 누적에 따른 글로우, 파티클, 카드의 짧은 탄성 반응은 유지한다.
- 문구가 길어진다고 조합대나 손패 위치가 움직이지 않도록 한다.
- 전체화면을 켜지 않은 PC에서도 카드 반응, 룬 발동, 공격 돌진, 몬스터 피격 효과가 정상적으로 보여야 한다.

시각 연출의 새로운 종류를 추가하는 것보다 **기존 연출을 제대로 표시하고, 가독성을 높이는 것**이 우선이다.

## 4. PC와 태블릿의 레이아웃

**PC 일반 창이 기본 화면이다. 전체화면은 같은 화면의 더 넓은 상태여야 한다.**

- PC 창 높이가 낮아졌다고 모바일용 압축 규칙을 일괄 적용하지 않는다.
- 로비 소개 문구, 버튼, 정보가 임의로 숨겨지지 않도록 한다.
- 태블릿 가로에서도 상단 몬스터, 중앙 3열 구성, 하단 한 줄 손패라는 배치 원칙을 유지한다.
- 작은 가로 화면에서는 장식·패딩·간격부터 줄이고, 핵심 글자를 읽지 못할 정도로 줄이지 않는다.
- 12열과 카드 가독성을 물리적으로 동시에 충족할 수 없는 화면은 임의로 숨기거나 왜곡하지 말고, 가능한 레이아웃과 남은 제약을 보고한다.
- 모바일은 기존 결정대로 가로 플레이 전용이다.

**모든 화면에서 불필요한 빈 공간을 최소화하면서, 게임에 필요한 정보와 카드의 가독성을 유지한다.**

## 5. 다른 UI 화면도 함께 간결하게 정돈

전투 화면 정리와 함께 다음 화면도 점검한다.

**상점**

- 상품 영역의 불필요한 세로 길이를 줄인다.
- 아이템 그림, 이름, 효과, 가격, 구매 버튼이 서로 자연스럽게 묶이도록 한다.
- 카드 글자가 카드 경계를 벗어나지 않아야 한다.
- 카드 연마·제거 기능도 불필요하게 큰 여백 없이 정리한다.
- 기존 상품·확률·가격은 변경하지 않는다.

**형태 선택창**

- 과도하게 큰 빈 여백을 제거한다.
- 형태 선택 카드들을 컴팩트하고 읽기 쉽게 배치한다.
- 해당 형태를 선택하는 행동, 좌우 이동, 손패 복귀 등의 버튼은 접근하기 쉬운 위치에 둔다.

**로비·사전·도감·저장**

- 기존 문구와 주요 기능을 숨기지 않는다.
- 패널의 폭, 정렬, 여백, 글자 크기를 일관되게 유지한다.
- 작은 화면에서 내용이 길면 해당 보조 창의 내부 스크롤을 허용한다.

## 6. 이번 패치에서 변경하지 않을 것

- 게임의 문법 판정과 점수 계산
- 기존 카드와 룬의 성능·희귀도
- 몬스터 HP 및 보스 기믹
- 보상·상점 확률과 게임 경제
- 저장 데이터 및 원정 진행 규칙
- 전투 턴 제한과 기존 24장 문장 한도
- 신규 몬스터·배경 이미지 제작
- 새로운 대규모 UI 디자인 시스템

이번 작업은 **UI 배치, 여백, 가독성, 표시 안정성의 복원과 개선**에 한정한다.

## 7. 구현 및 검증 원칙

먼저 현재 최신 소스와 기존 0.10.0 UI 코드를 비교하고, 현재 소스를 덮어쓰거나 전체 게임을 재작성하지 않은 상태에서 수정한다.

**중요한 것은 빠른 구현과 실제 화면 검수다.**

- PC 일반 창, PC 전체화면, 태블릿 가로 화면을 대표 기준으로 확인한다.
- 조합대 0장, 7장, 12장, 13장, 24장 상태의 배치를 확인한다.
- 손패 10장과 한 줄을 초과하는 경우의 페이지 전환을 확인한다.
- 정상 문장 제출 한 번으로 콤보·타격·HP 표시가 제대로 실행되는지 확인한다.
- 저장, 카드 배치, 턴 진행 등 핵심 기능만 필수 회귀 검증한다.
- 기존 필수 테스트와 빌드를 실행하되, 단순한 디자인 문제로 불필요하게 광범위한 검증을 반복하지 않는다.
- 소소한 색감, 장식, 픽셀 단위의 미세 조정은 사용자의 실제 플레이 피드백으로 추후 수정한다.

**가장 중요한 최종 검증은 첨부 시안과 실제 게임 스크린샷을 나란히 비교하는 것이다.**

최소한 PC 일반 창과 태블릿 가로 화면의 실제 캡처를 남기고, 위치·영역 크기·정렬·여백을 비교한다.

시안과 다른 부분이 있다면 사유를 보고하고, 쉽게 수정할 수 있는 배치 오류는 인계 전에 수정한다.

## 8. 완료 및 인계

최종적으로 다음 상태를 목표로 한다.

**"조합대는 12×2 카드 크기에 맞춰 타이트하고, 좌우에는 정보·기능·룬이 정돈되어 있으며, 상단 몬스터와 하단 한 줄 손패가 균형을 이루는 전투 화면."**

작업 완료 후 실제 변경 사항, 대표 스크린샷, 간단한 테스트 결과, 남아 있는 시각적 개선점을 보고한다.

별도 작업 브랜치에 커밋하고 PR을 생성하되, 사용자 승인 없이 main 병합이나 공개 배포는 하지 않는다.

**이번 패치의 성공 기준은 방대한 검증 보고서가 아니라, 사용자가 실제로 플레이했을 때 첨부한 시안처럼 정돈되고 편안하게 느껴지는 게임 화면이다.**
