# 신텍스 아틀라스 0.9 — 이미 확정한 밸런스·카드 UI 동반 명세

이 문서는 Stage 9 외에 같은 0.9에서 적용하기로 한 변경이다. 0.8.1을 재작성하거나 미완료로 되돌리는 지시가 아니다. 최신 사용자 수정까지 포함했다.

## 1. 기존 보스 HP 최종값

**0.9 새 원정**의 해당 보스 시작 HP·최대 HP·표시·테스트 기대값을 함께 변경한다.

| Stage | 보스 | 0.9 최종 HP | 특수 사항 |
|---|---|---:|---|
| 1 | 초원 수호자 | **400** | 기존 입문 전투·튜토리얼의 독립 fixture와 구분 |
| 2 | 항구 수문장 | **800** | 중간안 1,000은 사용하지 않음 |
| 3 | 시간의 골렘 | **840** | **과거·현재·미래 각 280** |
| 4 | 하늘길의 문지기 | **1,200** | 버전별 POLISH_HP 덮어쓰기까지 반영 |
| 5 | 소원의 스핑크스 | **1,300** | 버전별 POLISH_HP 덮어쓰기까지 반영 |
| 6 | 거울뿔 사슴 | **1,600** | 빙결핵 5개·기존 빙정 공급·HP 1 보호 유지 |
| 7 | 잠든 잿불룡 | **1,900** | 기존 비늘·방해 카드 규칙 유지 |
| 8 | 청동 수문장 | **2,200** | 이중 연결 인장·HP 1 보호 유지 |

골렘은 총 HP 표기만 840으로 바꾸고 실제 부위는 240으로 남기는 오류를 막는다. 각 부위 maxHp/hp가 280이며 합계가 840이어야 한다. 순서, 한 공격 한 부위, 초과 피해 미이월은 그대로다.

초원·항구·하늘섬을 모두 무조건 ‘1.5배 이상’으로 다시 계산하지 않는다. **최신 숫자표가 우선**이며 항구 800은 사용자가 별도로 낮춘 최종값이다.

일반 몬스터 HP, 턴 제한, 보호막 배율, 보스 조건, 기존 빙정 지급량, 각종 입장 재료, 룬 슬롯 수를 같이 바꾸지 않는다. 특히 Stage 9 보스 무빙정 규칙을 기존 사슴전에 소급하지 않는다.

구버전 저장은 해당 버전의 수치를 유지한다. 기존 플레이 중 보스 HP를 일괄 비례 조정하거나 저장을 초기화하지 않는다.

## 2. 운석 룬 → 희귀 다이아몬드 룬

### 확정 변경

- 표시 이름: **다이아몬드 룬**.
- 희귀도: **RARE / 희귀**.
- 기존 내부 ID `rune.longSentence`는 유지한다. 같은 기능의 새 룬을 병렬 생성하지 않는다.
- 조건과 레벨별 배율은 0.8.1의 실제 적용값을 유지한다.

| 레벨 | 유효 카드 5~9장 | 유효 카드 10~16장 |
|---|---:|---:|
| 1 | ×1.8 | ×2.4 |
| 2 | ×2.2 | ×2.8 |
| 3 | ×2.6 | ×3.2 |

별도의 피해 상향·배율 하향·새 발동 조건은 넣지 않는다. 기존 소유 사본·레벨·순서를 보존한다. 같은 ID 재획득은 기존 레벨업이며 최대 레벨 제외 규칙도 유지한다.

### 획득 확률 — 승인된 1차 조정안

모든 등급에 유효한 후보가 있는 ‘룬 후보 한 칸’의 기준 분포를 다음과 같이 한다.

- 희귀 3%.
- 나머지 97%를 일반:고급 = 2:1로 분배.
- 정확한 정수 가중치 예: **COMMON 194 : UNCOMMON 97 : RARE 9** (합계 300).

이는 전투마다 다이아몬드를 획득할 확률 3%라는 뜻이 아니다. 먼저 룬 항목이 뽑혀야 하고 실제 획득은 사용자의 선택이 필요하다. 후보 중복 제외, 잠금, 최대 레벨, 등급 후보 소진 뒤에는 기존의 유효 후보 재정규화 정책과 실제 trace를 기록한다. 모든 상황에서 무조건 3%라고 안내하지 않는다.

전투 보상에서 룬 항목 자체의 가중치와 3칸 1선택 규칙은 유지한다. 상점의 룬 후보 추첨도 같은 버전별 등급 가중치를 사용한다. 실제 0.8.1 상점의 희귀 룬 가격 체계를 따른다(작성 시 확인값 32). 신규 상점·다이아몬드 확정 슬롯은 만들지 않는다.

초회 고정 룬 소개, 이후 두 BASIC 후보 등 기존 예외는 유지한다. BASIC 전용 슬롯에 다이아몬드를 끼워 넣지 않는다. 일반 전체풀 슬롯에서는 위 정책을 따른다.

`RUNES`, `POLISH_RUNES`, `runesForVersion`, RUNE_BY_ID, 후보 생성, offer의 rarity/ownedLevel/offeredLevel, 가격, 상세 UI가 서로 다른 버전 데이터를 읽지 않는지 검사한다. 구버전 원정의 실제 보상·수치 정책은 보존한다.

### 외형·연출

다이아몬드의 여러 면이 보이는 형태, 흰색·옅은 청색 반사광, 희귀 등급 장식을 사용한다. 평상시에는 판독 가능한 형태를 유지하고 획득·선택·발동 순간에 특별한 빛을 강조한다. 발동 시 다이아몬드 면을 따라 짧게 빛이 움직인 뒤 점수에 전달되는 연출을 추가한다.

배율·레벨 숫자를 가리거나 상시 번쩍임으로 손패 조작을 방해하지 않는다. 기존 점수 연출 시간을 불필요하게 늘리지 않는다. 효과음은 기존 음소거 설정을 따른다. 접근성 모션 감소 설정이 있으면 준수한다. 새 VFX가 피해나 획득 확률을 변경하지 않는다.

기존 미구현 로드맵에 다이아몬드라는 이름이 예약되어 있더라도 미래 룬을 구현하지 않는다. 현재 표시의 혼동만 정리하고 미래 이름 문제는 기록한다.

## 3. WORD 카드 희귀도 최종 분류

| 카드 | 0.9 목표 등급 |
|---|---|
| have | **RARE** |
| that | **RARE** |
| to | **UNCOMMON** |
| make | **UNCOMMON** |
| help | **UNCOMMON** |
| be | **UNCOMMON** |
| want | **UNCOMMON** |

다른 WORD 카드를 범용성이 높다는 이유로 자동 승격하지 않는다. 영어 난도나 단어 길이로 등급을 일괄 산출하지 않는다. 희귀도 변경을 기본 점수·연마 수치 상향으로 연결하지 않는다.

등급과 시작 덱 입수 가능 여부는 별도 속성이다. **have를 희귀로 바꿨다고 기존 시작 덱의 have 정책을 자동 삭제하지 않는다.** 28장 구성, 품사별 수량, be 두 장 등 기존 생성 계약은 유지한다. 그와 별개로 help는 기존 0.8.1의 시작 덱·상점 제외 및 전투 보상 전용 정책을 유지한다.

보상·상점·도감·손패·상세에서 목표 희귀도와 실제 후보군·가격이 일치해야 한다. 기존 저장 사본을 삭제하거나 새 카드 ID로 교체하지 않는다. 순수 표시만 새 등급인데 실제 상점 비용·보상 후보는 예전 등급인 불일치를 막는다.

## 4. 고급 메탈릭 은색 테두리

고급은 흐린 회색선이 아니라 **분명한 메탈릭 은색**으로 표현한다. 밝고 어두운 은색의 정돈된 대비로 광택을 만들고, 기존 희귀 카드의 박음질/세공 계열처럼 고급에도 섬세한 장식을 넣는다.

희귀는 금빛 세공 체계를 유지하고, 고급보다 한 단계 화려하게 구분한다. 고급 테두리를 금색에 가깝게 만들거나 희귀 금빛을 은빛으로 덮지 않는다. 최종 문양과 픽셀 치수는 기존 실제 UI에 맞춰 구현한다.

상아색 카드 바탕, 기존 품사색, 카드 크기, 점수 위치, 손패 공간을 유지한다. 구별을 위해 글자와 카드를 무리하게 축소하지 않는다. 희귀도와 품사, 연마를 다른 정보로 읽을 수 있어야 한다.

## 5. 운영 카드에도 같은 희귀도 표현 적용

고급 운영 카드는 같은 메탈릭 은색·고급 장식, 희귀 운영 카드는 같은 금빛 세공·희귀 장식을 사용한다. 이는 **시각 체계의 통일**이며, 운영 카드 기능·등급·연마 한도·사용 후 목적지를 WORD와 같게 바꾸는 요청이 아니다.

WORD와 운영 카드의 렌더링 경로가 달라도 같은 희귀도 스타일 원천을 사용한다. 임시 빙정 표시, 사용 완료·봉인·선택·드래그 상태가 희귀도 테두리를 가리거나 역할을 혼동시키지 않는지 검사한다.

## 6. help 겸용 배지 위치

- `동·명` 배지는 **카드 왼쪽 위**에 배치한다.
- 오른쪽 위는 기존 **점수/수치 영역**으로 유지한다.
- 상단 품사색은 기존 동사색 단색을 유지한다. 반반 배색·대각선 분할·보조색 띠를 넣지 않는다.
- 겸용 설명은 상세, 실제 사용 품사는 제출 후 피드백에 표시한다.
- 카드명·희귀도·연마 배지·봉인·빙정 상태와 겹치지 않는다.
- 손패·조합대·보상·덱 보기·상세의 해당 카드 컴포넌트에서 일관된 규칙을 적용한다.

기존 0.8.1 문서에 ‘우측 상단’이라고 적힌 것은 이번 변경으로 대체한다. 명사 자동 판정과 동사 활용형 분리 등 help 기능은 변경하지 않는다.

## 7. 보존과 검증

시작 덱 축소안·다른 룬 너프·일반 적 일괄 HP 증가·운영 카드 성능 개편은 이번 범위에서 제외한다. 버전별 HP 실제 적용과 골렘의 부위 합계를 코드에서 조회해 확인한다.

다이아몬드의 룬 후보 조건부 분포는 고정 seed 대량 추첨으로 검증하되, 전투 보상·상점·초회 예외·후보 고갈을 분리한다. 단순 1회 당첨 여부로 확률 구현을 판정하지 않는다. 테스트에서 RNG를 조작한 결과를 자연 원정 드롭 통계라고 보고하지 않는다.

시각 검증은 일반/고급/희귀 WORD, 고급/희귀 운영, 연마별 카드, help, 임시·선택·봉인·드래그 상태를 포함한다. 실제 플레이 크기에서 고급 은빛과 희귀 금빛이 구별되는 스크린샷을 남긴다. 코드의 색상값 변경만으로 시각 개선 완료를 주장하지 않는다.
