## 0. 범위와 결정 수준

### 0.1 이번에 승인된 변경

1. 운명의 직조자: 예전 ‘예견’을 다시 사용하면서, 세 실을 ‘분사구문 / 가정법’ 두 실로 통합한다.
2. 튜토리얼: 전투 행동 중심으로 축약한다. 사전·내 덱·뽑을 카드·버린 카드를 의무적으로 열고 닫는 단계를 제거한다. 모바일 안내 대상을 바로잡는다.
3. 형태 선택창: 반복적인 작동 설명을 제거하고 형태·현재 선택·선택 버튼을 중심으로 정리한다.
4. 사전: 한글 뜻을 영어 단어 옆의 주요 위치로 이동하고 품사는 단어 아래에 작게 둔다. 사전의 희귀도·연마 정보와 보유 수를 제거한다.
5. 버리기·턴 넘기기: 실제 카드 이동을 짧은 시각 효과로 보여준다. 선택 카드가 버린 카드로, 실제로 뽑힌 카드가 손패로 이동한다.
6. 상점·연마: 개발용 반복 설명을 정리한다. 성공한 구매는 골드 변화와 구매 완료 상태로, 연마는 정확한 전후 변화로 보여준다.
7. 보상으로 받는 연마도 상점 연마와 같은 표시 원칙을 사용한다. 보상 선택 구조와 지급 규칙 자체는 바꾸지 않는다.

### 0.2 이 문서에서 구체화한 구현 기본안

- 예견을 통과한 양수 위력 공격만 실을 해제한다. HP 1 보호로 실제 HP 감소가 0인 것은 예견 차단과 다르다.
- 두 실을 해제한 후에도 예견은 계속 적용한다. 정상 가정법은 기존 예견 우회 능력을 유지한다.
- 새 정책은 새 원정에만 적용한다. 기존 원정은 당시의 예견 단독 또는 세 실 규칙으로 계속 진행한다.
- 카드 이동 효과는 정상 속도 기준 전체 300~500ms 안팎을 출발점으로 하며, 여러 장은 겹쳐 이동시킨다. 성능·가독성에 따라 좁게 조정 가능한 연출값이지 확정 밸런스가 아니다.
- 사전 글자 크기·간격은 7절의 조정 시작값을 참고한다. 기존 글꼴과 색상 체계를 보존한다.

### 0.3 범위 밖

## 2. 패치·원정·튜토리얼 버전 분리

### 2.1 새 정책의 적용

앱 표시 v0.15.0은 작업명이다. 새 원정은 예견+두 실 정책을 명시적으로 기록한다. 기존 저장을 로드한 순간 규칙이 바뀌면 안 된다.

권장 정책 명칭(동등한 기존 구조 사용 가능):

- 새 보스 ID: `FATE_FORESIGHT_THREADS`.
- 보스 정책: `fate.foresight-two-threads.v1`.
- 튜토리얼 정책: `guided.combat-first.v1`.
- 실 키: `PARTICIPIAL`, `COUNTERFACTUAL`.

기존 `FATE_FORESIGHT`, `FATE_CLAUSE_THREADS`를 같은 ID에 다른 의미로 덮어쓰지 않는다.

### 2.2 규칙 상속

새 원정 버전을 만들 경우 현재 0.14.0 언어·카드·공급·보상·연마·쉼표 규칙을 명시적으로 상속한다. 앱 버전 문자열만 전역 교체하지 않는다.

버전 allowlist와 분기 점검 대상은 최소한 다음과 같다.

- 시작 덱 생성·언어 registry·해금·지역 보너스·일반전 저항.
- 문법/룬 점수 근거·카드 공급·보상·상점 가격·운영 카드 연마 한도.
- 전체 전투 경계·최종 3페이즈·클리어 기록·저장 검증.
- 쉼표 해금·두 분사구문 해금·최종전 문법 과제 후보.

원정 버전, 언어 버전, 튜토리얼 버전을 이미 분리할 수 있다면 그 구조를 재사용한다. 언어 자체가 바뀌지 않는 이번 패치를 위해 기존 문법 전체를 복사하지 않는다.

### 2.3 기존 기록

- 기존 0.14.0 원정은 세 실을 그대로 사용한다. 그 이전 예견 원정은 예견 단독 규칙 그대로다.
- 옛 공격 영수증·랭킹·학습 기록을 새 규칙으로 다시 계산하지 않는다.
- 신규 클리어에는 실제 정책을 구분할 수 있는 식별자를 남기되, 순위 정렬·Top20·랭킹 화면은 임의 변경하지 않는다.
- 기존 튜토리얼 저장이 존재하면 당시 진행 정책으로 재개한다. 새 순서에 숫자만 끼워 맞추지 않는다.
- ‘연출 적용’은 기존 원정에도 가능하지만, 이동/구매/연마는 반드시 해당 원정의 실제 결과를 표시한다.

## 3. 운명의 직조자 — 예견 + 두 실

### 3.1 유지할 수치와 학습 흐름

47전투의 이름·외형·HP 5000·현행 턴 수·지역 배율·보상·무료 재료 미지급 정책은 유지한다. 43~46전투의 개별 학습은 그대로다.

| 전투 | 이름 | 학습 목표 |
|---|---|---|
| 43 | 춤추는 광대 | 현재분사 분사구문 |
| 44 | 추방당한 왕자 | 과거분사 분사구문 |
| 45 | 망상의 순례자 | 가정법 과거 |
| 46 | 후회의 기사 | 가정법 과거완료 |
| 47 | 운명의 직조자 | 예견을 넘으며 분사구문·가정법의 실 해제 |

보스는 두 분사구문을 모두 강제하지 않는다. 보유 덱에 맞는 쪽 하나를 사용할 수 있다.

### 3.2 두 실

| 실 | 정상 해제 근거 |
|---|---|
| 분사구문의 실 | 현재분사 또는 과거분사 분사구문. 기존의 유효한 구조 근거를 사용한다. |
| 가정의 실 | 가정법 과거 또는 가정법 과거완료. 주절과 조건절이 연결된 기존 유효 근거를 사용한다. |

순서 자유, 공격 사이 성공 누적, 해제 상태 영구 유지. 반복해서 같은 실을 풀어 보상·추가 점수를 얻는 기능은 없다.

- 일반 현재완료·수동태·명사 수식·동명사·현실 조건절을 각 실의 대체 정답으로 취급하지 않는다.
- 쉼표의 존재, -ing/p.p. 철자, if/would 단어가 있다는 사실만으로 해제하지 않는다.
- 현재 규칙에서 점수 근거로 인정되는 올바른 구조와 해당 주절 연결을 사용한다.
- 한 정상 공격에 두 근거가 실제로 함께 존재하면 미해제 실 둘을 함께 풀 수 있다. 이를 성립시키려고 새 복합 문법을 추가하거나 한 문장에 두 구조를 강요하지 않는다.
- 실 해제는 무료 정답 카드·자동 문장 생성·편집 중 판정으로 보장하지 않는다.

### 3.3 예견

- 첫 적격 공격 전 기억은 `null`이다.
- 기억 대상은 기존 `mainFrameEvidence`에 해당하는 실제 주절 1~5형식이다. 문두 분사부의 동사를 주절로 오인하지 않는다.
- 직전 적격 공격과 같은 주절 문형이면, 정상 가정법이 아닌 공격을 피해 0으로 차단한다.
- 정상 가정법 과거/과거완료는 같은 문형이어도 예견을 무시한다. 이 우회는 가정의 실을 이미 푼 이후에도 유지된다.
- 올바른 분사구문이라는 이유만으로 예견을 우회하지 않는다.
- 적격 공격은 유효한 주절 근거와 보스 처리 전 양수 위력이 있는 공격이다. 문장 불성립·분석 오류·보스 처리 전 0위력·턴 넘기기는 예견 기억을 갱신하지 않는다.
- 예견 우회 공격은 그 공격의 실제 주절 문형으로 기억을 갱신한다. 차단된 동일 문형 공격도 적격이면 같은 문형을 기록하므로 기억은 사실상 그대로다.
- 턴 넘기기·도움말 열기·화면 회전·저장/불러오기·앱 복귀로 기억을 초기화하지 않는다.
- 두 실을 모두 해제해도 예견은 남는다.

### 3.4 단일 정산 순서

기존 두 resolver를 차례대로 호출하여 HP를 두 번 깎지 않는다. 예견의 순수 판정과 실의 구조 근거를 재사용하고, 최종 HP는 하나의 통합 resolver가 산출한다.

1. 기존 문법 → 점수 → 룬 → 쉼표 감점 → 지역 등의 경로로 보스 처리 전 위력 `P`를 확정한다.
2. 공격 직전의 기억과 실 상태로 주절·가정법·분사구문 근거를 확인한다.
3. 예견 판정: 차단이면 `Q=0`, 통과 또는 정상 가정법 우회이면 `Q=P`.
4. `Q>0`이고 해당 구조가 유효할 때만 아직 남아 있는 실을 해제한다.
5. 해제 **후** 실이 하나라도 남으면 `floor=1`, 없으면 `floor=0`.
6. `actualHpLoss = min(Q, max(0, hpBefore - floor))`.
7. `hpAfter = hpBefore - actualHpLoss`. 해제 상태·기억·영수증·피해를 RunController가 한 번만 커밋한다.
8. 마지막 실을 해제한 공격부터 바로 격파할 수 있다.

예견은 최종 위력을 0으로 만드는 방어다. 실의 HP 1 보호는 위력을 줄이는 문법 감점이 아니다. `finalPower=Q`와 `actualHpLoss`를 구분하고, 잠긴 상태에서 보호된 피해를 오버킬로 계산하지 않는다.

HP가 이미 1일 때에도 예견을 통과한 `Q>0` 공격은 실을 풀 수 있다. ‘실제 체력 감소가 0이므로 해제 불가’라는 조건을 넣지 않는다.

### 3.5 예시 판단표

여기서 SV/SVO와 구조 근거는 엔진 분석 결과를 뜻한다. 수치는 계산 예시이지 밸런스 변경이 아니다.

| 직전 기억 | 이번 주절/구조 | 예견 | 실 처리 |
|---|---|---|---|
| 없음 | SV / 현재분사 분사구문 | 통과 | 분사구문의 실 해제 |
| SV | SV / 현재분사 분사구문 | 차단 | 해제 없음 |
| SV | SVO / 과거분사 분사구문 | 통과 | 분사구문의 실 해제 |
| SVO | SVO / 가정법 과거 | 우회 | 가정의 실 해제 |
| SVO | SVO / 현실 조건절 | 차단 | 가정의 실 해제 안 됨 |
| SVO | SV / 분사구문, HP=1, 다른 실 남음 | 통과 | 해당 실 해제, HP는 1일 수 있음 |
| SV | SVO / 남은 마지막 실 정답, HP=1 | 통과 | 같은 공격으로 격파 가능 |
| SV | SV / 일반문, 두 실 모두 해제됨 | 차단 | 해제 완료를 이유로 예견 제거 금지 |

### 3.6 저장·검증

권장 상태 예시(실제 저장 구조와 조정 가능):

```text
bossMechanic = {
  id: FATE_FORESIGHT_THREADS,
  policyVersion: fate.foresight-two-threads.v1,
  rememberedFrame: null | SV | SVC | SVO | SVOO | SVOC,
  threads: { PARTICIPIAL: null | receipt, COUNTERFACTUAL: null | receipt },
  appliedAttackIds: [...]
}
```

영수증에는 공격 식별자, 처리 전후 기억·실·HP, 차단/우회, 근거 참조, P/Q/실제 피해를 검증 가능하게 남긴다. 기존 별도 보스 영수증·전투 시작 카드/룬 스냅샷 방식을 확장한다.

- 최근 12개 공격 표시 목록 삭제에 의존하지 않는다.
- 중복 attackId는 재정산·재해제·보상 중복 없이 기존 계약에 맞게 거절 또는 멱등 처리한다.
- 예견만 따로 HP를 적용하거나, 단순히 ‘실 개수 2’를 저장하고 해제 근거를 생략하지 않는다.
- 기존 세 실 영수증 검증기를 느슨하게 풀지 말고 정책별로 분기한다.
- 최종 공격·승리·턴 소모·보상은 기존 순서로 한 번만 처리한다.

## 4. 보스 안내는 같은 정책에서 가져오기

상점은 현재 전투가 아니라 **그 방문에서 준비하는 대상 지역의 보스**를 확인한다. 준비 화면·전투의 ‘목표 문법’·기존 상태 표시·도감/기록의 표시도 버전과 맞춘다.

새 정책의 기본 공략 문구:

> 직전과 같은 주절 문형은 예견에 막혀요. 가정법은 예견을 무시해요.
> 분사구문과 가정법으로 두 실을 풀면 쓰러뜨릴 수 있어요.

필요한 상세에만 ‘분사구문은 현재분사/과거분사 중 하나, 가정법은 과거/과거완료 중 하나’, ‘예견에 막힌 공격은 실을 풀지 못함’을 넣는다.

- 구 원정 예견 단독 / 0.14.0 세 실 / 새 예견+두 실 설명을 각각 맞춰 제공한다.
- `FORESIGHT_HINT` 한 상수를 모든 원정에 무조건 붙이지 않는다.
- 화면에 설명 버튼·패널을 더 늘리지 않는다. 기존 HP 옆 상태 영역에서 기억 문형과 두 실의 실제 상태만 간결하게 읽히게 한다.
- 새 대형 완료 UI는 만들지 않는다. 기존 세 실 상태를 두 항목으로 바꾸고 예견의 현재 기억 표시를 함께 수용한다.
- 예견 피해 0은 기존 방어 피드백, HP 1 보호는 보호 상태, 문법 오류는 기존 붉은 감점으로 구분한다.
- 임의 텍스트 줄이기로 실제 공략 조건이나 버전 차이를 지우지 않는다.

## 5. 튜토리얼 — 전투를 해보는 짧은 흐름

### 5.1 핵심 체험 유지

기존 고정 카드와 첫 전투를 최대한 재사용한다. 다음 학습 블록은 남긴다. 이것은 노출할 단계 번호가 아니다.

| 블록 | 실제 행동/결과 | 안내 원칙 |
|---|---|---|
| 시작 | 몬스터와 공격 목적 파악 | 한 문장으로 시작 |
| 올리기·회수 | 카드 탭/드래그와 되돌리기 | 지금 누를 대상만 |
| 교환 | 체크 → 버리기 → 새 카드 | 실제 이동 효과로 결과 설명 |
| 문장 순서 | 주어를 앞으로 이동/동사 삽입 | 청색 삽입 바 재사용 |
| 첫 공격 | 기존 형태 미변형 사례의 감점 확인 | 새 오답을 강제로 추가하지 않음 |
| 턴 넘기기 | 남은 턴 감소·실제 카드 받기 | 조합대와 손패가 유지되는 것을 보여줌 |
| 형태 변경·재공격 | 기존 He/run→runs 경로를 살려 정상 결과 확인 | 형태 선택·테두리 피드백 재사용 |
| 마무리 | 정상 원정으로 복귀 | 완료 확인 한 번과 기존 정상 덱 복원 |

기존 I/be 사례를 설명하는 것과, 실제 다음 형태 선택 대상이 He/run인 것을 혼동하지 않는다. 새 고정 손패·새 점수표를 만들기보다 현재 정상 작동 스크립트를 축약한다.

### 5.2 제거/병합

- 사전·내 덱·뽑을 카드·버린 카드 의무 방문을 진행 조건에서 제거한다.
- ‘14/32’ 등 전체 단계 카운터를 화면에서 제거하고 현재 행동 제목만 표시한다.
- 카드 기본점수 → 문장 보너스 → 구조 보너스마다 확인 버튼을 누르게 하지 않는다. 계산은 이어서 보여주고 필요한 최종 확인을 최대 한 번 둔다.
- 룬 소개·남은 턴 설명처럼 연달아 확인만 받는 단계는 관련 행동의 짧은 안내에 병합한다. 룬을 새로 지급하지 않는다.
- 한 말풍선은 한 행동 위주로 한다. 작은 화면을 이유로 설명 글자를 지나치게 축소하지 않는다.
- ‘건너뛰기’는 계속 쉽게 접근 가능하게 한다. 다시 시작·나가기의 기존 기능은 보조 메뉴에서 유지해도 된다.

### 5.3 UI만 숨기는 구현 금지

`expectedActions`, `ackSteps`, `tutorialPanel`, `guidedAllowed`, `recordGuided`, `validateTutorial`, `showScoreGate`, `FINISH_PRESENTATION`, 정상 덱 복원, UI의 튜토리얼 분기를 같은 정책으로 수정한다.

- 숨긴 패널의 OPEN/CLOSE를 기다리며 진행이 멈추면 안 된다.
- 없어진 학습을 학생이 수행한 것으로 허위 기록하기 위해 숨은 ACK 명령을 연속 발행하지 않는다.
- 새 정책은 실제 남아 있는 단계/전이만 기록한다. 기존 저장 검증은 이전 정책으로 보존한다.
- 새 튜토리얼에서 학생이 원해 사전·내 덱을 열면 읽기 전용으로 열고, 닫으면 같은 단계로 돌아온다. 열었다고 진도가 자동 변경되지 않는다.
- 공격 연출 중 기존 입력 잠금은 유지한다. 최종 점수 gate를 없앴다고 FINISH_PRESENTATION이 누락되거나 두 번 실행되면 안 된다.
- 완료/건너뛰기/재시작/나가기 각각에서 기존 28장·parked RNG·통계 복원 정책을 유지한다. 튜토리얼 카드가 영구 덱에 섞이거나 보상이 중복되지 않는다.

### 5.4 모바일 안내 대상

화면에서 실제로 표시 중인 남은 턴, 공격, 버리기, 손패 카드, 형태 버튼을 선택한다. 같은 정보를 PC와 모바일에 렌더링했더라도 숨겨진 첫 번째 DOM을 무조건 잡지 않는다.

- display/visibility/실제 사각형과 가시 뷰포트 교차 여부를 확인한다.
- 필요하면 해당 내부 스크롤 영역이나 손패 페이지만 조정하여 이미 존재하는 대상에 접근하게 한다. 카드 자체를 재배열하거나 게임 상태를 변경하지 않는다.
- 회전·주소창 변화·모달 열림/닫힘·손패 페이지 변경 후 다시 맞춘다.
- 화살표·강조·말풍선이 터치를 가로채거나 눌러야 할 대상을 덮지 않는다.
- 대상이 순간적으로 없으면 잘못된 화살표를 띄우지 않고 재렌더 후 재탐색한다. 진행을 영구 잠그지 않으며 건너뛰기/나가기는 유지한다.
- 기존 실제 가시 영역 좌표계를 재사용한다. innerHeight만으로 별도 계산하여 모바일 대응을 되돌리지 않는다.

## 6. 형태 선택창

- 삭제: ‘카드 한 장의 형태만 바꿉니다’, ‘문장 검사는 공격 확정 뒤에 진행합니다’와 같은 매번 반복되는 작동 설명.
- 기본 표시: 영어 형태(크게), 원형/과거/과거분사·p.p./-ing형 등 필요한 라벨, 현재 선택 표시.
- 긴 일반 -ing 설명은 기존 도움말 경로에 보존한다. 형태마다 필요한 뜻·구분까지 삭제하지 않는다.
- 실제 선택지가 없는 그룹은 제목과 빈 공간 모두 숨긴다.
- 기존 폰트·버튼 크기·여백·형태 변화 테두리를 유지한다. 설명 삭제를 이유로 버튼을 다시 작게 만들지 않는다.
- 좌우 이동·맞교환·회수 등 대체 조작은 계속 접근 가능하게 한다. 드래그만 가능한 UI로 바꾸지 않는다.
- 같은 철자여도 과거/과거분사처럼 필요한 형태 구분을 임의 병합하지 않는다.
- 선택 성공·취소·동일 형태 재선택에 대한 기존 처리와 카드 ID/연마/순서를 유지한다.

## 7. 사전은 뜻을 먼저 읽을 수 있게

### 7.1 지정 배치

```text
remember                         기억하다
동사
remember · remembers · remembered · remembering
[기존의 필요한 용법·예문]
```

- 기존 품사 배지가 차지하던 주요 위치에 한글 뜻을 둔다. 영어 단어와 뜻이 같은 항목의 첫 시선 영역에서 함께 보이게 한다.
- 품사는 영어 단어 아래, 현재보다 작은 글씨로 배치한다. 작되 대비가 부족하거나 8~9px 수준으로 읽기 어렵게 하지 않는다.
- 좁은 화면에서는 뜻을 같은 항목의 바로 다음 줄로 내려도 되지만, 아래 용법 설명에 묻히지 않게 한다.
- 긴 한글 뜻은 뜻 영역에서 자연스럽게 줄바꿈한다. 영단어를 쪼개거나 잘못된 품사와 뜻이 연결되게 하지 않는다.

조정 시작값: PC/패드의 뜻 16~18px, 모바일 14~16px, 품사 11~12px, 제목/품사 사이 3~5px, 형태·용법 블록 간 6~10px. 실제 기존 글꼴과 화면을 보고 조정할 수 있으며 전역 카드 타이포그래피를 바꾸지 않는다.

### 7.2 사전에서 제거

- 희귀도·카드 기본점수·연마 단계 계산 설명 행.
- 연마 단계별 요약 행(여러 줄이면 전부).
- ‘보유 n장’, ‘현재 보유하지 않음’ 등의 소유 상태 행.

단어 뜻·품사·활용형·필요한 용법·예문은 유지한다. 실제 언어 데이터를 변경하지 않는다.

### 7.3 겸용 단어와 공유 화면

- answer/watch/show, plan/work/change/help, hard/fast/well 등의 현재 지원 의미와 품사를 유지한다.
- 대표 뜻만 크게 보이더라도 보조 품사의 뜻이 사라지거나 전혀 다른 품사의 뜻처럼 표시되면 안 된다.
- `openDeck('all')`과 사전이 공유하는 렌더러에 명시적인 보기 모드 등을 두어 구분한다. ‘사전답게’ 만드는 삭제가 내 덱의 카드 관리 정보까지 제거해서는 안 된다.
- 내 덱·실제 카드 상세의 연마/보유 수는 보존한다. 사용자 요청 없이 새로운 덱 관리 화면을 설계하지 않는다.
- 검색(영어/한글/겸용 뜻), 기존 정렬·필터, 만난 어휘만 공개하는 범위를 유지한다. 미공개 카드/덱 순서를 노출하지 않는다.

## 8. 실제 이동을 보여주는 카드 연출

### 8.1 이벤트별 동작

| 행동 | 보여줄 사실 | 보여주면 안 되는 것 |
|---|---|---|
| EXCHANGE | 선택한 손패 → 버린 카드, 실제 DRAW → 손패 | 미선택 손패 전체 버리기 |
| PREPARE | 턴 감소와 실제 DRAW → 손패 | 기존 손패/조합대 단어가 사라지는 연출 |
| 재섞기 | 버린 카드 묶음 → 뽑을 카드, 그 뒤 실제 DRAW | 앞으로 뽑을 카드의 표면/순서 예고 |
| 손패 포화·덱 소진 | 실제 변화만 표시, 뽑은 수 0이면 카드 비행 없음 | 규칙상 지급되지 않은 가짜 카드 |
| 마지막 턴 넘김으로 패배 | 기존 패배 흐름 | 다음 턴 드로우를 꾸며서 보여주기 |

턴 넘기기 시 쉼표 배치가 정리되는 현행 규칙과 단어 카드의 유지 여부는 별개다. 이번 패치는 쉼표·턴 규칙을 변경하지 않으며 쉼표 도구를 버린 카드나 뽑을 카드로 보내지 않는다.

공격의 기존 집결·돌진·타격은 보존한다. 공격 뒤 정상 드로우에 같은 표시 도구를 재사용할 수는 있으나, 공격 중 이동·피해 정산을 재작성하지 말고 기존 효과와 이중 재생하지 않는다. 보급/재활용 등 기존 운영 카드 연출도 중복시키지 않는다. 이번 필수 대상은 EXCHANGE와 PREPARE다.

### 8.2 전후 집합 차이가 아닌 이동 로그

단순 `before.handIds`와 `after.handIds` 차이만으로는 부족하다. 같은 카드가 버려지고 재섞기 후 다시 뽑히면 최종 손패가 같아도 이동은 실제로 일어났다.

권장 일회성 표시 자료:

```text
{
  actionKey, runId, battleId, beforeRevision, afterRevision,
  events: [
    {type: DISCARD, ids: [...]},
    {type: RESHUFFLE, count: n},
    {type: DRAW, ids: [...]}
  ]
}
```

- 실제 함수가 실행된 순서를 기록한다. 현재 drawCards의 반환값·선택 카드 목록을 재사용하고, 필요한 경우 선택적인 collector/표시 결과를 최소 추가한다.
- RNG를 한 번 더 호출하여 ‘어떤 카드가 움직였을지’ 재현하지 않는다. 셔플도 두 번 돌리지 않는다.
- 성공한 Controller 명령의 결과에만 붙이는 일회성 자료를 우선한다. 단순 연출을 위해 원정 저장 전체에 대형 애니메이션 기록을 추가하지 않는다.
- 게임 데이터 반환 계약 변경은 모든 소비자를 확인하고, 기존 카드 ID·영역·RNG·revision·정산 결과가 동일한지 비교한다.
- 재섞기는 숫자와 뒷면 묶음으로 표현한다. 실제 DRAW되어 이미 알려진 카드 외의 단어는 보여주지 않는다.
- 명령 실패·취소에는 이동 로그도 연출도 없어야 한다.

### 8.3 표시 수명과 배치

1. 성공 처리 전 화면에서 시작 사각형과 필요한 카드 외형을 캡처한다.
2. 기존 Controller가 실제 이동을 한 번 수행한다.
3. 최종 레이아웃을 확정하고, 필요한 실제 카드만 잠시 visibility 처리하며 별도 표시용 복사본이 이동한다.
4. 완료/취소/오류 시 복사본을 정리하고 최신 실제 화면을 보여준다. 상태를 다시 정산하지 않는다.

동등하게 안정적인 현재 before/after 표시 방식을 재사용해도 된다. 단, 화면의 임시 크기가 카드 개수에 따라 바뀌면 안 된다.

- 손패·조합대·상단 몬스터 구역은 고정한다. 카드가 날아간 빈자리를 애니메이션 중 다시 접어 무대를 키우지 않는다.
- 단어의 실제 손패 자리나 버린/뽑을 카드 묶음을 도착점으로 사용한다. 화면 전체를 가로지르는 과도한 궤적은 피한다.
- 기존 드래그 복사본 구현과 별도로 표시 복사본을 관리한다. 드래그 고스트의 위치/크기는 바꾸지 않는다.
- 묶음 이동은 1장당 직렬 지연을 누적하지 않는다. 정상 속도 전체 300~500ms 안팎을 출발점으로 하고, 많은 카드도 보통 600ms 안을 목표로 한다.
- 기존 배속을 반영한다. effect-off/reduced-motion은 이동을 없애거나 짧은 정적 강조로 대체하며 결과는 같다.
- 효과 중 필요한 중복 게임 명령만 짧게 막는다. 별도의 긴 클릭 지연은 두지 않는다. 표시 실패 후 영구 입력 잠금이 남으면 안 된다.
- 타이머/animationend만 믿지 않고 finally·abort 경로에서 정리한다. 늦게 끝난 이전 동작이 새 화면/새 원정을 덮지 않도록 actionKey와 화면 소유자를 확인한다.
- 화면 크기·전체화면·주소창 변화 시 좌표를 갱신하거나 현재 이동을 안전하게 끝내고 실제 상태를 표시한다. 닫기/나가기/숨김/앱 복귀에서 같은 카드를 다시 받지 않는다.

### 8.4 손패 페이지

- 사용자가 보고 있던 페이지와 기존 손패 순서를 원칙적으로 유지한다. 새 카드 때문에 자동으로 마지막 페이지로 넘기지 않는다.
- 현재 페이지에 보이는 새 카드는 그 자리로 이동한다.
- 다른 페이지의 카드에는 손패 페이지 표시/영역으로 짧은 도착 반응만 준다. 숨은 카드가 현재 페이지에 있는 것처럼 가짜 슬롯을 만들지 않는다.
- 교환으로 현재 페이지 자체가 없어지면 기존 페이지 clamp 규칙만 적용한다.
- 숨은 페이지의 선택 카드도 실제 교환에 포함된다. 보이지 않는 시작 카드 때문에 예외·유령 카드가 남지 않도록 안전한 묶음 표시를 사용한다.
- 점수·턴·교환 수·카드 묶음 수치는 최종 실제 값과 일치해야 한다. 같은 이동을 두 번 카운트하는 숫자 애니메이션은 금지한다.

## 9. 상점 — 상품·효과·가격을 우선

### 9.1 문구 정리

삭제하거나 꼭 필요한 짧은 표현으로 바꾼다.

| 기존 성격 | 변경 원칙 |
|---|---|
| 현재 지원하는 단어 카드 한 장 | 카드가 보이면 중복 문장 제거 |
| 실제 카드 한 장 / 확정 전에는 처리하지 않음 | 제거 대상·확인 행동을 명확히, 구현 설명 삭제 |
| 상품과 가격은 이 방문에 고정됩니다 | 반복 상시 안내 제거. 재추첨 기능은 추가하지 않음 |
| 빙정 WORD | 빙정 카드 또는 빙정. 임시/영구 차이는 필요한 곳에 짧게 유지 |
| 구매는 교체 대상을 확정한 뒤 한 번만 처리합니다 | 교체할 룬과 비용·취소 버튼으로 전달 |
| CHAPTER/FIFTH SHOP 등 장식 | 현재 지역명·상점 중심으로 간결하게. 새 번호 장식 추가 금지 |

골드 부족, 연마 상한, 상점당 사용 한도, 임시 카드 제한, 보스전 무료 지원 없음, 필수 문법 재료 제거 경고, 룬 교체 확인은 선택에 영향을 주므로 없애지 않는다. 조건이 필요한 대상 옆에 짧게 둔다.

### 9.2 구매 피드백

- 이미 존재하는 `item.purchased`, 거래 ID, commandId·revision 중복 방지 구조를 재사용한다.
- 성공한 구매 직후 해당 상품의 테두리/배경이 짧게 반응하고 ‘구매 완료’로 전환한다.
- 구매 완료 상품은 원래 진열 자리에 남는다. 나머지 상품을 당겨 위치를 바꾸지 않는다.
- 골드는 실제 차감된 값으로 한 번 반응한다. 부족·실패·교체 미확정·취소는 차감/완료 연출을 하지 않는다.
- 새 단어 카드 구매는 원정 덱에 추가된 것이다. 전투 손패로 즉시 날아가는 효과를 만들지 않는다.
- 룬 신규 장착/중복 강화/교체는 실제 결과가 보이는 기존 룬/상품 영역만 짧게 강조한다. 새 룬 장착 규칙을 도입하지 않는다.
- 구매 성공 toast와 큰 모달을 추가하지 않는다. 기존 상점의 변화로 이해되게 한다.
- 구매 도중 뷰가 재렌더되더라도 안정된 itemId/instanceId로 대상에 피드백을 연결한다. 화면을 다시 열었다고 성공 효과를 재생하지 않는다.
- 가격은 읽히는 한곳에 명확히 둔다. 버튼은 ‘구매’, 완료 상태는 ‘구매 완료’처럼 기능 중심으로 유지한다.

## 10. 연마 — 정확한 전후 값

### 10.1 선택 전

단어 카드에는 ‘현재 실제 카드 점수 → 연마 후 실제 카드 점수’를 보여준다. `10 → 15`는 예시일 뿐 고정 문자열이 아니다.

- 현재 원정의 카드 정의·연마 수준·상한·정책으로 계산한다.
- 예: `카드 점수 15 → 20`. `기본 10 + 연마 ...` 같은 반복 계산 설명은 펼쳐두지 않는다.
- 같은 단어 여러 장은 실제 instanceId로 구분한다. 한 장의 연마가 모든 사본에 적용되는 것처럼 보여주지 않는다.
- 운영 카드는 기존 `operationPolishPreview` 등의 실제 효과 변화로 표시한다. 뽑는 수가 늘면 그 수의 전후를, 다른 효과면 해당 변화만 보여준다.
- 이는 카드 자체의 확정된 업그레이드 미리보기다. 편집 중 문장 점수 예측은 추가하지 않는다.

### 10.2 성공 후

- 정확히 그 카드의 값이 바뀌고, 기존 테두리 강조 계열로 한 번 반응한다.
- 상점이면 서비스의 실제 사용 완료 상태와 골드 차감도 반영한다.
- 보상 연마이면 보상 선택의 실제 결과를 반영한다. 골드를 지불하지 않았는데 차감 연출을 넣지 않는다.
- 정보 전달을 위한 강제 ‘연마 완료 → 확인’ 모달은 기본 경로에서 제거하고, 기존 결과 영역 또는 대상 카드의 짧은 비차단 피드백으로 대체한다.
- 이미 필요한 대상 선택·되돌릴 수 없는 선택의 확인은 유지한다. 확인이 필요하지 않은 정상 완료 후 확인 버튼만 반복시키지 않는다.
- 보상 선택 후 즉시 다른 화면으로 이동하는 경로에서는 해당 카드의 작은 결과 표시 또는 기존 결과 영역을 재사용한다. 새로운 전체 화면을 만들지 않는다.
- 취소·최대 연마·잔액 부족·stale revision·중복 클릭에는 성공 강조가 없어야 한다.
- 표시를 위해 공격 피해·골드·연마 수치를 다시 커밋하지 않는다. 예외 경로도 presenting이 해제되게 한다.

### 10.3 화면 간 일관성

상점/보상/카드 상세는 같은 전후 계산 자료를 사용한다. 사전에는 이 강화 정보를 다시 넣지 않는다.

세 보상 선택지와 상점 상품의 선택/구매 버튼은 가능하면 같은 기준선에 둔다. 이 작업은 설명 삭제 후의 간격 정돈이며, 모든 상품을 세로로 늘리거나 새로운 진열 레이아웃을 만드는 작업이 아니다.

## 11. 짧은 표시·안전한 상태의 공통 원칙

- 변경 순간만 짧게 강조한다. 상시 발광·계속 흔들리는 카드·큰 ‘완료’ 문구를 추가하지 않는다.
- 청색은 삽입 위치, 갈색은 실제 쉼표, 붉은색은 문법 감점이라는 기존 시각 의미를 유지한다.
- 실제 카드 이동과 튜토리얼/상점 성공 강조가 동시에 실행되더라도 동일 대상을 과도하게 중복 강조하지 않는다.
- root/공격/운영/카드 이동/모달의 입력 소유권을 명확히 한다. 새 전면 투명 레이어가 모든 터치를 가로채지 않는다.
- 이미지 프리로드와 카드 이동 때문에 다음 전투·전체화면 사용자 제스처·오디오 unlock 호출을 늦추지 않는다.
- 판정·배율·HP·골드·재료 공급은 표시 장치가 아니라 기존 소유 모듈이 결정한다.
- 사용자용 테스트 버튼·fixture·가짜 고점·자동 문장 채우기를 제품에 추가하지 않는다. 내부 검사용 입력은 생산 화면과 분리한다.

| 튜토리얼 | game/guidedTutorial.js, ui/guidedCoach.js, main.js 및 presentation gate 연결 | 실제 단계 축약·대상 가시성 |
| 형태 선택 | ui/cards.js, formView.js, 관련 CSS | 반복 문구 제거·빈 그룹 처리 |
| 사전/내 덱 | ui/overlays.js, dictionary 관련 CSS | 보기 모드 구분·뜻 우선 배치 |
| 카드 이동 | game/deck.js, runController.js, main.js, 기존 presentation/UI 모듈 | 최소 일회성 이동 자료·표시 수명 |
| 상점/연마 | ui/shop.js, progression.js, models.js, main.js, 기존 거래/보상 결과 | 실제 전후 값·완료 반응 |
| 모바일 보존 | visualViewport.js, visibleLayout.css, mobile.css, mobileBoard.css | 필요한 지역 CSS만 조정 |

경로는 기준 커밋의 탐색 가이드다. 새 파일명은 필요하면 소규모로 정한다. 다른 UI/엔진을 통째로 대체하지 않는다.

### 12.2 한 번의 통합 패치 안에서의 구현 순서

1. 최신 main/작업 차이와 AGENTS, 현행 보고서를 읽고 기존 결과를 보존한다.
2. 새 보스 정책·영수증과 구버전 분기를 구현한다. 단일 정산 경계 테스트부터 짧게 확인한다.
3. 같은 정책을 상점/전투 안내/기존 상태 표시로 연결한다.
4. 튜토리얼 진행과 게이트를 축약한 다음 가시 대상 선택을 수정한다.
5. 형태창·사전·상점 문구와 연마 미리보기를 정리한다.
6. 실제 이동 자료를 만들어 EXCHANGE/PREPARE 표시를 붙인다. 기존 공격·운영 연출은 보존한다.
7. 거래·연마 성공 강조와 비차단 결과를 연결한다.
8. 관련 회귀·최종 테스트·빌드 후 하나의 패치/PR로 인계한다.

커밋을 보스/튜토리얼/표시 연출로 나누어 원인을 추적할 수 있게 하되, 사용자에게 여러 개의 미완성 패치를 따로 실행하라고 요구하지 않는다.

## 13. 최소 충분 검증

자세한 인수 조건은 ACCEPTANCE_CHECKLIST.md, 보스 경계값은 BOSS_CASES.json을 사용한다. 모두 실행 전 기준 자료다.

### 13.1 필수 검사 묶음

A. 보스: 예견 차단/우회/문형 변화, 두 실 OR 조건, HP 1과 마지막 실, 중복 공격, 구 정책 재현.
B. 튜토리얼: PC와 작은 가로 화면에서 축약 흐름 완료, 필수 메뉴 방문 없음, 점수 확인 축약, skip/restart/exit 복원.
C. 사전·형태: 뜻/품사 위치, 보유·연마·희귀도 행 제거, 내 덱 정보 보존, 겸용 단어와 빈 그룹.
D. 카드 이동: 한 장/여러 장 교환, 재섞기와 같은 카드 재드로우, 손패 포화, PREPARE, 마지막 턴 패배, 페이지와 쉼표 제외.
E. 상점·연마: 구매/중복강화/교체취소/잔액부족/연마상한/보상연마의 실제 상태와 표시 일치.
F. 기존 기반: 짧은 가시 높이·전체화면/주소창 변화·효과 끄기·배속·중단 뒤 입력 복구, 공격과 이미지/BGM 경로 회귀.

대표 PC, 태블릿 가로, 휴대폰 가로를 사용한다. CSS 치수는 테스트 조건일 뿐 실제 기기 성공으로 보고하지 않는다. 최소한 한 실제 공격과 교환/턴 넘기기는 정상 UI 명령을 통해 진행한다.

### 13.2 명령과 범위

- 최종 `npm test`, `npm run build` 필수.
- 정책/데이터 변경에 맞춰 `npm run validate:data` 및 해당 보스·튜토리얼·UI 브라우저 검사를 실행한다.
- 같은 검증을 여러 번 전면 재실행하기보다 수정 중에는 집중 검사, 마무리에서 전체 기본 검사 1회를 원칙으로 한다. 실패 수정 후 필요한 재실행은 한다.
- 50전투 자연 완주·대량 시드·전 브라우저/전 기기 순회·수백 장 캡처를 이번 인계 선행 조건으로 요구하지 않는다.
- 보스 공략은 합법적인 영구 카드로 만든 대표 지정 상태에서 실제 Controller 제출을 짧게 확인한다. 이를 자연 원정 완주/일반 승률 증거라고 하지 않는다.
- ‘모든 덱에서 필승’은 보장하지 않는다. 다만 두 필수 구조를 구성할 수 있는 대표 덱에서 경합 기믹 때문에 불가능해지지 않는지 확인한다. 실패를 숨기려고 HP·기믹을 임의로 완화하지 않는다.
- 실기기 미보유/실제 청취/모바일 앱 전환 검사는 NOT RUN으로 남기고 구현 결과를 인계한다.

### 13.3 최종 인계

변경 요약, 보존 항목, 기준/작업 커밋, 실제 명령·종료 코드, AC 결과, 대표 화면 또는 짧은 동작 증거, NOT RUN/남은 제한을 제공한다.

특히 ‘구현 완료’, ‘자동화 검사 통과’, ‘실기기 확인’, ‘main 병합’, ‘공개 배포’를 따로 보고한다. 별도 승인 없이 main 병합·자동 병합·Pages 변경·배포하지 않는다.

## 14. 완료의 기준

직조자는 **같은 주절 문형을 기억하는 예견**과 **분사구문/가정법 두 실**이 함께 작동한다. 첫 튜토리얼은 메뉴를 순회하는 대신 실제 전투 행동으로 이어진다. 사전에서는 뜻을 먼저 읽고, 형태창에서는 형태를 먼저 고른다. 카드를 버리고 받는 흐름과 구매·연마 결과는 실제 변화로 전달된다.

현재 게임의 배치·문법·카드 규칙을 넓게 다시 만들지 않고, ‘설명은 줄고 결과는 보이는’ 상태가 이번 패치의 완료 기준이다.
