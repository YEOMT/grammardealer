A. 비어 있지 않은 실제 카드 조합의 제출을 허용한다. 핵심 문장 실패도 0피해로 정산하고 카드·턴을 소모한다.

## 3. 제출 계약 — 시도 자체가 선택이다

### 3.1 UI 허용

일반 전투의 편집 상태이며 실제 조합대 카드가 1장 이상이고 자원이 유효하면 확정 가능하다.
제출 전에 파서를 실행해 버튼을 비활성화하거나 예상 점수/오류/자동정답을 미리 노출하지 않는다.
빈 조합대, 전투 종료, 진행 중인 공격, 잘못된 카드 ID, 중복 명령, 0.2.1 실습의 현재 단계 제한은 정상적인 동작 가드다. 이러한 UI/입력 검증 실패는 문법 실패와 다르다.

### 3.2 결과별 정산

| 의미 | 제출 완료 | 카드/턴 | 점수·피해 | 공개 피드백 |
|---|---|---|---|---|
| 완전한 문장 | 예 | 제출 카드 전부 버린 더미, 행동1 소모 | 기존 계산 + 해금된 효과 | 완전한 문장과 발동 효과 |
| 뼈대가 성립하나 형태·관사·격 등 오류 | 예 | 동일 | 기존 감점 규칙, 인정 가능한 해금 효과 | 정확한 오류 설명 + 실제 점수 |
| 기본 판정 성공, 전용 콤보는 미해금/미제공 | 예 | 동일 | 기본 점수 + 완전문장/수식/허용 효과, 잠긴 전용 배수 없음 | 일반적인 정상 공격. 미지원/잠금 경고 없음 |
| 핵심 문장 구조 불성립 | 예 | 동일 | 모든 공격 기여 최종0, HP 감소0 | 지정 실패 안내 |
| 실제 기술적 실패 | 아니오 | 카드·턴·교환·RNG·기록 보존 | 정산하지 않음 | 간단한 오류 복구 안내 |

**고정 실패 안내**

> 문장을 완성하지 못하면 데미지를 줄 수 없습니다.
> 주어와 동사의 위치를 다시 확인해 보세요.

엔진이 구체 원인을 확실하게 찾은 경우 한 줄 보충할 수 있으나, 미해석이라는 이유만으로 ‘목적어 필요’ 등 특정 오답을 지어내지 않는다.

### 3.3 `I book happy run` 인수 흐름

- book 카드는 이번 Lexeme에서 명사다. 등록하지 않은 동사 용법을 즉석에서 붙여 성공시키지 않는다.
- 확정 1회 → 실제 Snapshot 생성·분석 → 핵심 실패 결과 생성.
- `accepted=true`의 의미는 ‘제출 거래가 성립’이며 ‘영어가 옳음’과 동일하지 않다. 명명 충돌이 있으면 submissionAccepted와 grammaticality를 분리한다.
- 쓰인 카드4장 모두 DISCARD로 이동. 덱에서 영구 제거하지 않는다.
- turnsRemaining 1 감소, actionSequence/제출 횟수 1 증가. 교환 횟수는 변하지 않는다.
- 실패 결과와 0피해를 짧게 표시한 후, 행동이 남으면 기존 +3 드로우 규칙으로 다음 턴 진행. 손패 한도와 더미 재셔플은 기존 규칙 그대로.
- 마지막 행동이었다면 실패 연출 후 패배. 숨은 추가 턴/드로우/무료 재수정 없음.
- 제출 후 편집 Undo로 턴·카드를 복원할 수 없다.
- 더블클릭·동일 attackId/revision 재전송·FINISH_PRESENTATION 재호출로 추가 소모되지 않는다.

### 3.4 0피해의 원인을 구분

- `INCOMPLETE_SENTENCE`: 핵심 문장 실패 → 위 지정 안내, 공격 조립체가 힘을 잃는 짧은 연출.
- `ACCURACY_ZERO`: 정상 구조이나 기존 감점 계산으로0 → 정확성 피드백. 완전한 문장 자체가 없었다고 거짓 안내하지 않음.
- `BOSS_BLOCKED`: 문장은 성립했으나 실제 보스 규칙에 막힘 → 방어 연출. 문법 실패 안내 금지.
- `TECHNICAL_FAILURE`: 제출 미확정 → 무소모 복구.

finalPower===0만으로 ‘장막에 막혔습니다’를 표시하는 코드는 제거/분기한다. 기존 면역 합성 테스트도 올바른 원인으로 유지한다.
INVALID_CORE에는 카드 연마 점수, 완성/부사/일반 덧셈 룬, 지역 배수, 처치 재화를 붙이지 않는다. 계산 단계에서 +점수를 쌓아 놓고 마지막에 임의로0으로 덮는 긴 가짜 콤보 연출도 하지 않는다.

## 4. 기본 판정과 콤보의 분리

### 4.1 서로 다른 세 축

1. **validationSupport**: 이 카드/형태/구조를 실제 규칙으로 분석할 수 있는가.
2. **comboImplemented**: 전용 점수·연출 콘텐츠가 존재하는가.
3. **comboUnlocked**: 해당 원정의 자격에 전용 효과가 열려 있는가.

Grammar는 원정 스테이지·룬·재화·한국어 뜻을 읽지 않고 문장 구조를 판단한다.
Scoring/ComboEligibility가 Grammar 증거와 원정의 해금 Snapshot을 읽어 발동 효과를 고른다.
이 두 역할을 나눈다고 외부 NLP 엔진을 새로 도입하지 않는다. 기존 파서·스코어러를 확장하고 필요한 작은 resolver만 추가한다.

### 4.2 해금 자격

기본1·2·3형식은 처음부터 활성. 전용4형식은 `pack.svoo`에 대응한다.
자격은 기존 `runStartUnlockBaseline ∪ runOwnUnlocks`를 사용한다. UI에서 stageIndex로 임의 추측하거나 프로필의 모든 변경을 저장 중인 원정에 실시간 덧씌우지 않는다.

- 신규 프로필의 첫 Stage1: 4형식 성립은 인정, 4형식 전용×2는 아직 없음.
- Stage1 클리어 사건을 원정·프로필에 한 번 기록: 4형식 콤보가 열림. Stage2로 정상 진행.
- 이전 원정에서 해금한 프로필의 새 원정: Stage1부터 4형식×2 가능. 다회차에 다시 잠그지 않는다.
- 이전 실패 원정이라도 Stage1을 클리어해 얻은 영구 해금은 유지.
- 공격 도중 해금이 바뀌더라도 이미 확정한 공격 점수는 다시 계산하지 않는다.
- 토파즈 자격과 Grammar4형식 자체를 혼동하지 않는다. 토파즈가 없으면4형식이 틀린 문장이 되는 것이 아니다.

### 4.3 잠긴 구조의 점수

원정에서 잠긴 **그 전용 효과만** 제외한다.
- 카드 기본10+연마, 기존 정확성 감점, 완전문장+20, 실제로 인정된 일반 수식은 그대로.
- 잠긴 주절 문형의 배율은 중립값×1. 다른 문형으로 위장해1형식/3형식 배율을 주지 않는다.
- 주절이3형식이고 목적어 안에 아직 잠긴 관계절이 있다면, 입증된 주절3형식 효과는 사용 가능. 관계절 전용 배수만 비활성.
- 일반적인 카드 기반/정확성 룬은 자기 조건대로 가능. 잠긴 문법에만 의존하는 효과를 우회 발동하지 않는다.
- Stage1 기본문형 지역보너스는 실제1~3형식에만 적용. ‘보너스 없음’을 감추려고 잠긴4형식을1형식으로 넣지 않는다.
- 전투·도감에 ‘미지원’, ‘4형식은 다음 스테이지에서 가능’, 잠긴 내부 이름 등으로 흐름을 막지 않는다. 완전문장 등 실제 발동한 이름만 표시한다.

### 4.4 확정 산술 사례(연마0, 해당 룬 외 다른 룬 없음)

| 입력·조건 | 계산 | 최종 |
|---|---|---:|
| I give my friend a book. / 첫 프로필 Stage1,4형식 잠김 | 6×10+20, 잠긴4형식×1, 초원 지역보너스 없음 |80|
| I give my friend a book. / 4형식 영구해금된 Stage1 | 80×2, 초원 지역보너스 없음 |160|
| She gives me a book. / Stage1,4형식 잠김 | 5×10+20 |70|
| 같은 문장 / Stage1,4형식 해금 |70×2|140|
| 같은 문장 / Stage2,룬 없음,첫 장막 해제 공격 |70×2×1.25|175|
| 같은 문장 / Stage2,토파즈 Lv1 |70×2×1.5×1.25, 각 곱셈 후 내림|262|
| I be happy. / 기본 초원,룬 없음 |(30−10)×1.2×1.25|30|
| He runs very fast. / 기본 초원,룬 없음 |(40+20)×1+5+5 → ×1.25|87|
| I book happy run / 어떤 덧셈 룬·연마가 있어도 |핵심 구조 실패|0|

수치는 본 명세의 기대값이다. 구현 결과에 맞춰 기대값을 조용히 고치지 말고 차이가 있다면 원인·기존 계약을 먼저 확인한다.

## 5. 기존 UNSUPPORTED 처리의 실질적 개편

### 5.1 목표

‘콤보가 아직 없음/잠겨 있음’을 이유로 정상 영어를 반려하지 않는다. 정상 구조는 실제 기본 판정을 거쳐 일반적인 완전한 문장으로 공격한다.
단, `if (status === 'UNSUPPORTED') status = 'VALID'` 같은 변경은 **요구사항을 충족하지 않는다**. 임의 배열에도 완전문장 보너스를 주어 오개념을 만들기 때문이다.

기본 판정에는 다음 증거가 필요하다.
- 실제 사용 카드 전체를 소비하는 유효 구조. 앞부분만 맞고 뒤에 남은 카드를 무시하지 않는다.
- 올바른 동사 용법/필수 성분/구·절 경계.
- 형태·격·일치 등 이번 학교문법 정책에 맞는 진단.
- 카드ID/범위와 연결된 구조 증거. 단어 존재 여부만으로 문법을 인정하지 않는다.

### 5.2 범위 조사부터

실제 런에 공급 가능한 카드/현재 활성 형태를 열거하고, 기존 UNSUPPORTED 경로를 분류한다.
A. 단순히 콤보 미해금 때문에 발생 → Grammar에서 제거.
B. 실제로 정상적인 현재 기본 Frame 누락 → 등록하고 테스트.
C. 현재 카드로 만들 수 있는 to/that/목적격보어의 대표 구조 → 아래 ‘기본 판정 전용’ 범위 구현.
D. 존재하지 않는 카드·조작된 Snapshot·상한 초과·예산 초과·실행 예외 → 기술/입력 처리. 정답으로 둔갑 금지.

### 5.3 이번 패치의 최소 ‘기본 판정 전용’ 범위

후반 콘텐츠를 개방하는 것이 아니라 이미 존재하는 카드로 만드는 다음 대표 구조를 분석해 일반 공격을 가능하게 한다. 현재형·현재 활성 어휘·조합대16장 범위를 유지한다.

| 범위 | 최소 정상 사례 | 반드시 구별할 것 |
|---|---|---|
| 기존1~4형식 | They develop. / I give her a book. | 등록 Frame과 해금 자격의 분리 |
| 목적격 형용사/명사 보어 | I make you happy. / I find the book interesting. / I keep the room clean. | 4형식의 NP+NP와5형식의 O+C는 같지 않음 |
| 동사 뒤 to부정사 | I want to read. / I need to work. / I like to read books. | to+BASE, 동사별 결합 허용; I want to reads.는 무오류 정답 아님 |
| 목적어+to/원형 | I want you to read. / I help you read. / I help you to read. / I see the dog run. / I make you read. | want와make/see의 결합 형태 차이 |
| that 제한적 관계절 | The dog that runs is happy. / I like the book that you read. | 선행사 연결, 주절/관계절 완성, 주격 관계사 생략 금지 |
| 목적격 관계사 생략 | I like the book you read. | 앞뒤 단어를 무작정 두 문장으로 잘라 정상 처리하지 않음 |

위 표의 단어가 최신 소스에서 없거나 형태가 바뀌었으면 기존 카드로 동등한 fixture를 구성한다. 표의 대표 구조 자체를 빼지는 않는다. 후반 전용 룬·콤보 점수·해금 콘텐츠는 이번에 만들지 않는다.

- 준비된 규칙이 어휘 여러 개에 일반화되어야 한다. 예문 문자열 비교/정규식 몇 줄의 화이트리스트는 금지.
- 기본 비정형 동사 연결과 관계절은 기존 NP/AP/PP·Frame을 재사용한다. 파서 전체를 교체하지 않는다.
- be 원형을 to be의 실제 BASE로 사용하는 것과 I be happy의 활용 미선택 오류를 구분한다. 단순히 be는 언제나 −10으로 처리하지 않는다.
- 관계절의 주어 역할/목적어 빈자리를 제한된 규칙으로 처리한다. 주격 관계사를 무조건 생략 허용하거나, 중복 목적어까지 허용하지 않는다.
- 이번 기본 판정 전용 구문들의 전용 콤보는 비활성. 정확한 주절 문형 중 이미 해금된 효과는 정상 적용한다.
- 과거·완료·수동·의문문 등 아직 활성 형태/필수 카드가 없는 후속 전체 Pack을 열지 않는다. 미래 메타데이터만으로 새 카드를 공급하지 않는다.

### 5.4 정말로 판단할 수 없는 경우

목표는 공급 범위에서 이런 사례를 줄이고 배포 전 필수 사례를 해소하는 것이다. 파서가 알아내지 못했다는 사실을 ‘오답’이나 ‘정답’으로 가장하지 않는다.
실행 예외·예산 초과·해석기 자체의 미해결 실패는 내부 진단으로 남기고, 실제 게임 오류와 동일하게 자원 보존 후 짧은 복구 안내만 한다. ‘아직 채점하지 않는 구조’라는 상시 게임 기믹을 두지 않는다.
**이 안전 경로를 구현하지 않은 필수 구문의 대체 수단으로 남겨 놓고 완료라고 보고하면 실패다.** 어떤 미지원 문자열에도 점수를 주는 무조건 통과보다, 정해진 기본 판정 범위를 실제 구현하는 것이 핵심이다.

## 6. 활성 동사 전체 Sense·Frame Audit

### 6.1 대상

최신 registry의 실제 공급 대상 VERB 전체를 기계적으로 열거한다. 과거 ‘45개 핵심동사’ 설계표를 현재 구현 목록이라고 착각하지 않는다.
조사한0.2.0의 대표 대상은 be/have/do/go/come/run/live/work/play/eat/read/like/want/need/make/give/see/help/feel/become/look/take/keep/find/show/create/improve/develop/change/send이며, 실제 최신 목록을 정답으로 삼는다.

### 6.2 산출 표

`docs/VERB_FRAME_AUDIT_0.2.2.md`에 각 동사별로 다음을 작성한다.
- 기존 활성 Sense·Frame, 이번 유지/수정 항목.
- 검증된 주요 한국어 뜻과 현재형 형태.
- SV/SVC/SVO/SVOO/SVOC/준동사/명사절별: 기본 판정 가능 / 미보너스 기본 지원 / 실제 범위 밖.
- 정상 예문, 형태 오류 예문, 필수 성분 누락·틀린 결합 사례.
- 바꾼 용법의 사전/문법 출처. 의미가 비슷하다는 추측으로 자동타동 판정을 붙이지 않는다.
- 모든 희귀 용법을 넣지 않는다. 기본 학습 가치가 큰 실제 용법을 빠뜨리지 않는 것이 목적.

### 6.3 develop 필수 수정

- 발전하다·발달하다 의미의 SV.
- ~을 개발하다·발전시키다 의미의 SVO.
- `They develop.`와 `They develop technology.`를 모두 실제로 판정한다.
- `He develops.`는 정상, `He develop.`는 기존 일치 오류 정책대로 부분감점.
- 카드 희귀도·가격·점수·시작 수량은 변경하지 않는다.

Cambridge는 develop의 grow 용법을 I or T로 제시한다. 이번 정리는 실제 어휘 근거가 있는 수정이다.

### 6.4 복수 Sense의 실제 탐색

Sense만 DB에 추가하고 파서는 senseIds[0]만 읽는 구현이면 실패다.
등록된 후보 Sense/Frame 중 전체 문장이 성립하는 분석을 탐색하고, 동일한 정상 분석은 교육용 대표 결과로 정규화한다. Sense 등록 순서를 바꿔도 같은 문장의 정오·점수가 변하지 않아야 한다.
가능한 분석을 합쳐 서로 양립할 수 없는 콤보를 모두 주지 않는다. 4형식/5형식처럼 점수에 영향이 있는 중의성은 검증된 후보 중 **고정된 교육용 우선순위**를 기록하고 한 분석으로 정산한다. 현재 해금/룬으로 문법 정답이 바뀌지 않아야 한다.

### 6.5 잘못된 일반화 금지

- 모든 동사를 SV로 허용하지 않는다.
- 모든 SVO 동사에 NP가 하나 더 붙으면4형식으로 인정하지 않는다.
- ‘한국어로 ~에게’라고 옮길 수 있다는 이유만으로 간접목적어라고 표시하지 않는다.
- give + for가 나왔다고 문장 전체를 무조건 비문 처리하지 않는다. 일반 수혜 전치사구로 다른 정상 분석이 가능한지 먼저 확인하되, give의 대표 전달 전환 to로 잘못 라벨링하지 않는다.
- 명사 semantic tag로 상상적 문장을 감점하지 않는다. 영어 구조의 정확성과 의미의 자연스러움은 분리한다.
- 누락 어휘 용법을 단순 UI 경고 제거로 덮지 않는다.

## 7. 나의 덱·단어 사전

### 7.1 위치와 구성

전투 화면의 `나의 덱` 진입을 유지하고 그 안에 현재 소유 카드 목록과 단어 설명을 연결한다. 기존 별도 사전 버튼은 같은 단어 보기 탭으로 연결할 수 있다. 중복된 독립 데이터는 만들지 않는다.
DRAW/DISCARD는 실제 더미 조회 기능으로 유지한다. 뽑을 순서는 공개하지 않고 기존 단어순 정렬 정책을 보존한다.
필터는 필요 최소한: `보유 카드` / `이번 원정에서 만난 단어`. 제거한 단어는 보유하지 않았다고 표시하되 사전 이력에는 남는다.

### 7.2 사전 항목

- 표제어, 학생용 품사명, 검증된 주요 한국어 뜻.
- 현재 제공된 형태와 해당 형태의 기능. I/me/my를 모두 ‘나는’으로 표시하지 않는다.
- 동사별 핵심 사용 틀을 필요하면1줄과 짧은 검수 예문으로 제공.
- 카드 희귀도·기본점수·연마·보유 장수 등 기존 카드 정보 유지.
- 언어적 사용 틀과 콤보를 혼동하지 않는다. 사용 가능한 정상 형태를 콤보 미해금 때문에 숨기지 않는다.
- 후속 미구현 조동사/시제 형태를 한 번에 전부 활성화하지 않는다.
- 최종 문법 지침을 자동 생성하거나 런타임 AI로 설명하지 않는다.

표시 예:

**develop · 동사**
발전하다, 발달하다 / ~을 개발하다, 발전시키다
형태: develop · develops
예: They develop. / They develop technology.

사전 어휘 의미가 런타임에 없으면 `senseId`, `undefined`, raw POS를 노출하지 않는다. 개발 검증에서 누락을 잡고, 학생 화면은 중립적인 한국어 레이블을 사용한다.

## 8. 문장 도감 — 영어 원문과 실제 기록

### 8.1 역할·진입

주 진입은 로비와 원정 종료 화면이다. 전투 중에는 나의 덱 사전을 우선하고, 기존 최근 공격 내역이 필요하면 읽기 전용으로 유지한다. 전투 중 새 장문 교육 창을 추가하지 않는다.

### 8.2 표시할 정보

- 실제 제출한 영어 원문(자동 문법 교정 금지).
- 실제 발동한 문법/완전문장 배지. 아직 안 열린 문법을 도감이 자동으로 가르치거나 보너스를 받은 것처럼 표시하지 않는다.
- 검증된 해당 문장/구간의 역할 표기. S/V/IO/DO/C 등의 학습용 약어와 한국어 역할명은 허용.
- 당시 위력·실제 피해·처음 사용·최고 기록 등 증거가 있는 값만.
- 틀린 제출은 ‘실패한 시도’, 부분 오류는 ‘형태 확인 필요’처럼 구분. 완전한 문장 예문 선반에 섞지 않는다.
- 같은 문장에 여러 효과가 사용됐다는 사실과 특정 문법의 누적 사용 횟수를 구분. 여러 문장을 합친 횟수를 ‘이 문장 3회’로 쓰지 않는다.

### 8.3 완전히 제거할 것

- 자동 한국어 문장 번역.
- 성분별/단어별 한국어 뜻·번역 tooltip.
- `VALID`, `VALID_WITH_ISSUES`, `INVALID_CORE`, `UNSUPPORTED`, `ENGINE_ERROR`, `UNKNOWN`, capability/frame/sense ID.
- ‘뜻 참고 생성 실패’, ‘현재 의미 모듈 버전’ 같은 개발 구현 설명.
- 영문 문장을 읽어 즉석에서 생성하는 문법 설명.

한국어를 모두 금지하는 것이 아니다. **문법명·역할명·짧은 고정 설명·기록 UI는 한국어**이며, 어휘/문장 번역만 사전으로 한정한다.
이 원칙은 최근 공격·도감 미리보기·과거 기록의 툴팁에도 적용한다.
손패 카드에 한글 뜻을 추가하지 않는다. 보상 등 이번 범위 외 정상 화면은 불필요하게 재디자인하지 않는다.

### 8.4 표준 학생용 상태 문구

| 내부 의미 | 학생용 표현 |
|---|---|
| 정상 무오류 | 완전한 문장 |
| 부분 정확성 오류 | 형태 확인 필요 또는 실제 오류명 |
| 핵심 구조 실패 | 문장 미완성 · 피해0 |
| 정상 문장이나 보스에 막힘 | 방어에 막힘(실제 보스 규칙 설명) |
| 과거 기록에 증거 부족 | 이전 기록(문형 모범 예문으로는 미노출) |

기술 오류는 문장 도감에 오답 기록으로 넣지 않는다. 개발용 진단은 기존 dev-only 도구로만 남기고 production에서 `?debug=1`만 붙여 노출되지 않게 한다.

## 9. 검수용 고정 문법 설명 데이터

기존 RULES의 책임을 작고 별도인 `grammarGuideData` 계열 파일에 모은다. 아래는 이번 명세의 교육용 초안이며 사용자 교사 검토와 자동 fixture 검사로 유지한다. ‘교사 검수 완료’ 표시를 임의로 만들지 않는다.

| 항목 | 고정 설명 | 대표 예문 |
|---|---|---|
|1형식 S+V|주어와 동사를 중심으로 이루어지며 목적어와 보어가 없는 문장입니다.|I run.|
|2형식 S+V+C|보어가 주어의 상태나 정체를 설명합니다.|I am happy. / I am a student.|
|3형식 S+V+O|목적어가 동사가 나타내는 행동이나 관계의 대상을 나타냅니다.|I like books.|
|4형식 S+V+IO+DO|간접목적어는 보통 받는 대상이나 수혜자를, 직접목적어는 전달하거나 제공하는 대상을 나타냅니다.|She gives me a book.|
|간접목적어 IO|주거나 보여주거나 만들어 주는 행동에서 보통 받는 대상이나 수혜자를 나타냅니다.|She gives **me** a book.|
|직접목적어 DO|그 행동에서 직접 전달하거나 제공하는 대상입니다.|She gives me **a book**.|
|주격보어 C|주어가 어떤 상태인지 또는 무엇인지를 설명합니다.|I am **happy**.|
|전치사구|전치사와 명사구가 함께 쓰여 위치나 대상 등의 관계를 나타냅니다.|I am **at school**.|
|수여 표현|give/show/send는 to, make는 for를 사용한 대표 대응 표현도 만들 수 있습니다.|She gives a book to me.|

- ‘IO=사람, DO=사물’이라는 절대규칙을 만들지 않는다.
- to me는 이 게임의 학교5문형 기준에서 PP이며 me는 전치사의 목적어다. 4형식 IO라고 표시하지 않는다.
- 목적어 자리에 한국어 ‘~에게/~을’이 붙는지만 보고 역할을 정하지 않는다.
- C에 명사가 들어가도 무조건 O로 분류하지 않는다.
- 전체 명사구 경계를 보여 준다: `I / give / my friend / a book` = S/V/IO/DO. friend와book만 동떨어져 표시하는 것보다 구 전체를 묶고 중심 단어를 보조 강조한다.
- 검수 예문과 ‘플레이어의 실제 문장’을 서로 다른 출처로 표시한다. 예시를 실제 획득 기록처럼 삽입하지 않는다.
- 대표 문법 설명은1줄, 필요한 예문1~2개. 심화 통사론과 자동 한글 번역을 다시 늘리지 않는다.

### be 문형의 교육용 기준

| 문장 | 이 게임의 표시·기록 |
|---|---|
|I am happy.|2형식, happy=C|
|I am a student.|2형식, a student=C|
|He is kind.|2형식|
|They are students.|2형식|
|I am very happy.|2형식, very의 정도 수식 별도|
|I am happy at school.|2형식 + 장소 전치사구|
|I am at school.|1형식 · 위치/존재 + 장소 전치사구|
|He is in the room.|1형식 · 위치/존재 + 장소 전치사구|
|I am.|이번 독립 기본 문장 범위에서는 필수 성분 미완성. SV로 무조건 채우지 않음|

`I am`이라는 문자열, be 카드의 존재, 한글 뜻만으로1형식에 넣지 않는다.

**개발자용 구분:** 장소 PP를 보어로 분석하는 다른 문법 체계도 있다. 여기서는 사용자가 채택한 한국 학교5문형용 위치·존재 표기 규칙을 일관되게 유지한다. 이를 모든 영어 문법 이론에서 유일한 정답이라고 문서화하지 않는다. 학생에게 불필요한 이론 논쟁은 보여 주지 않는다. location 예문은 일반1형식의 대표 I run.과 구분해 표시한다.

## 10. 학습 기록의 정확성·과거 기록 정리

### 10.1 기록 종류

1. 최근 제출 이력: 정상·부분 오류·0피해 실패를 담되 상태를 정확히 표시. 기존 최근12개 등 한도를 유지한다.
2. 문법별 실전 사용: 실제 검증된 구조와 실제 적용 효과를 구분해 센다.
3. ‘완전한 문장’ 대표 기록: 무오류이고 전체 입력이 검증된 공격에서만 고른다. 튜토리얼 scripted 공격·샌드박스·기술오류 제외.
4. 별도 고정 학습 예문: 검수 데이터. 실전 기록과 혼합 금지.

### 10.2 새 기록에 보존할 최소 증거

기존 Snapshot과 중복되지 않게 `recordId/attackId`, 영어 원문, 토큰/선택형태, 기준 버전, 문형/구간/역할, 정확성 요약, 실제 scoreable hit IDs, 당시 위력·피해를 저장한다.
도감을 열 때마다 점수·피해·사용 횟수를 다시 정산하지 않는다.
같은 공격의 GrammarHit 상·하위 태그 또는 복수 분석을 각각 새 성공으로 중복 기록하지 않는다.

### 10.3 이미 저장된 잘못된 예문

자동 번역 표시를 지우는 것만으로 잘못된1형식 분류 문제가 해결되지는 않는다.
- 영어 원문과 충분한 토큰 증거가 있는 기록은 현재 검수된 판정으로 교육용 분류를 재검증할 수 있다.
- 학습용 표시/태그만 버전1회 보정한다. 당시 점수·최고점·재화·승리·해금 실적을 소급 변경하지 않는다.
- firstSentence/bestSentence 문자열만 남아 정확한 토큰/다의성/전체 구조를 복원하기 어렵다면, 확실하게 판정되는 경우에만 분류하고 불확실한 것은 일반 이전 기록으로 보존한다. 잘못된 예문 슬롯에 계속 노출하거나 내용 없이 전체 기록을 삭제하지 않는다.
- 과거 집계 횟수는 원공격 목록이 없으면 임의로 재분배하지 않는다. 필요 시 누적 수치는 유지하되 새로 검증한 대표 예문만 교체한다.
- 과거 해석 필드는 저장 호환용으로 남길 수 있지만 학생 화면·새 저장 생성에서는 사용하지 않는다.
- 재검증/마이그레이션은 추첨·드로우·HP·장막·해금·랭킹에 영향을 주지 않는다.

## 11. 상태·버전·실습 회귀

### 11.1 원자적 제출

Snapshot→실제 판정→점수/실패 결과→revision/attackId 검증→RunController에서 카드·턴·HP·장막·로그를 한 번 커밋→동일 결과 연출.
INVALID_CORE에도 이 정산 경로를 사용하되, 문법 실패용 해상도는 finalPower0/HP unchanged/killed false/consumeTurn true/제출카드 전부 discard이다.
모든 downstream이 mainFrameId 존재를 강제하지 않도록 무효 제출 결과의 스키마를 명시한다. 오류를 숨기려고 가짜 FRAME.SV를 넣지 않는다.
엔진 실패는 커밋 전 제안 상태를 폐기한다. draw/reward/shop RNG를 미리 소비했다면 원상태를 보존한다.

### 11.2 저장 호환의 기본 정책

이번의 새 제출비용·콤보 해금 정책은 **새0.2.2 원정**에 적용한다. 이미 진행 중인 이전 버전 원정의 규칙·RNG·보상·HP를 몰래 재작성하지 않는다. 기존 프로젝트의 버전별 원정 보존 정책을 유지한다.
- 구버전 원정이 원래 제공하던 범위는 그대로. 0.1 저장을 Stage2로 확장하지 않는다.
- 새로운 학습 UI의 번역 제거·내부코드 숨김·검수된 고정 설명은 구버전 기록 조회에도 적용한다.
- 로드 시 ‘이전 원정 규칙으로 이어합니다. 새 규칙은 새 원정에 적용됩니다.’ 정도를 저장 선택 화면에서만 안내할 수 있다. 공격마다 미지원 문구를 띄우는 것과 다르다.
- 저장 validator는0.2.2 및 이전 허용 버전을 명시한다. `isCurrentCampaign`의0.2.0 equality로 Stage2/상점이 사라지지 않게 한다.
- IndexedDB 이름 `sentence-balatro-v0-1`, profiles/slots, 수동3슬롯을 보존한다. 필요한 마이그레이션은 백업·검증·1회 적용으로 처리한다.
- 새 `comboEligibility`/learningRecord 버전을 저장하되 기존 공개 offer/shop/owned card를 다시 만들지 않는다.
- 프로필 baseline과 runOwnUnlocks 스냅샷, 누락 필드의 버전별 기본값을 테스트한다. 모든 미래 룬이 자동 해금되는 wildcard 기본값 금지.

### 11.3 실습 보존

- 첫 실습 `I be happy`는 INVALID_CORE가 아니라 기존 형태 오류의 부분점수 공격. 기대 위력30.
- 두 번째 `He runs very fast` 기대87. 실습 적77HP의 두 공격 흐름을 유지한다.
- 실습 중 목표 이외 행동을 막는 입력가드는 유지. 일반 전투의 ‘무조건 제출 가능’을 실습 단계 스킵 수단으로 쓰지 않는다.
- 확인 대기 watchdog 제외·탭 전환 복귀·오디오/효과 감소·동작 줄이기를 보존한다.
- 사전 통합 후 실습의 덱/사전 열기 타깃과 성공 조건도 연결한다. 이름/DOM 변경 때문에 단계가 멈추면 실패다.
- scripted 실습은 문법 성공·최고 피해·특별 룬 해금 실적으로 새로 들어가지 않는다.

## 12. 테스트 예문 묶음

아래는 실제 카드 Snapshot을 구성하여 파서·점수·Controller까지 연결하는 회귀 입력이다. 등록되지 않은 단어를 테스트 때문에 일반 런에 대량 추가하지 않는다.

### A. 실제 제출 비용

`I book happy run` / `happy` / `the book`처럼 핵심 절이 없는 카드열: accepted submission,0피해,카드/턴 소모. 빈 조합대만 무료 가드.
`I be happy` / `She give me a book`: 뼈대 인정·부분감점·정산.
조작된 카드ID/형태ID·강제 예외·candidate budget초과: 기술/입력 실패,무소모,정답화 금지.

### B. 자동·타동과 be

They develop. / They develop technology. / He develops. / He develop.
I read. / I read books. / I eat. / I eat food. / I help. / I help her.
I am happy. / I am a student. / I am at school. / I am happy at school.
They are students. / I am.

### C. 4형식·간접목적어

I give my friend a book. / She shows us the book. / She sends me a book. / She makes me a game.
She gives a book to me. / She makes a game for me.
She gives I a book. → 목적격 오류. NP2개 있다는 이유로 무오류 처리 금지.
I like you a book. → 해당 결합 불성립. 모든 SVO동사 자동4형식 금지.
I make you happy. → 4형식 아님, 미보너스5형식 기본 판정.

### D. 기본 판정 전용

I want to read. / I want you to read. / I like to read books.
I help you read. / I help you to read. / I see the dog run. / I make you read.
I find the book interesting. / I keep the room clean.
The dog that runs is happy. / I like the book that you read. / I like the book you read.
I want to reads. / I see the dog to run. / The dog runs is happy.
→ 틀린 결합은 무오류 정답·후반 콤보로 인정하지 않는다. 확실한 국소 형태 오류로 복구 가능한 것과 핵심 결합 실패의 심각도는 기존 Issue 정책에 맞춰 fixture별 명시한다.
`I like the book that you read it`는 목적어 중복을 올바르게 판정할 수 있을 때만 활성 fixture에 포함한다. 등록되지 않은 it 때문에 생긴 오류와 관계절 중복 오류를 혼동하지 않는다.

### E. 의미와 문법의 분리

The book likes music. → 구조적으로 정상. 의미 어색함 점수 감점 금지.
I am a student. → student를 직접목적어로 표시하지 않음.
과거 번역이 들어 있는 저장 → 새 문장 도감에서 문장/성분/단어 번역 모두 없음.

### E. 통합 검증

개발 중에는 바꾼 모듈의 관련 테스트 위주로 실행한다. 매 문구 수정마다 모든 seed·브라우저 suite를 돌리지 않는다.
최종 코드가 안정되면 `AGENTS.md`가 요구하는 검사와 이번 영향 영역을 전체1회 실행한다. 재수정하면 관련 검사를 재실행하고 최종 상태의 필수 npm test/build를 다시 확인한다.

필수 최종 검사:
- `npm test`, `npm run validate:data`, `npm run build`.
- 신규 제출/Grammar/콤보해금/기록/마이그레이션 테스트.
- 실제 production UI: 신규 프로필 고정 실습→일반 전투→첫 룬→초원 보스→항구 상점→Stage2 완주.
- 일반 전투의 무효 제출 최소1회, 마지막 턴0피해, 보스 장막, 저장/불러오기, 로비/종료 도감, 단어 사전 직접 조작.
- 기존 `test:browser`/`test:e2e` 중 관련 스위트. 실행 불가이면 사유와 NOT RUN.
- Grammar/어휘를 변경하므로 시작 덱 검사(`test:decks`) 최종1회. 기본28장·SV접근성·튜토리얼 고정패를 보존하고 새Frame 때문에 시작 구성의 RNG가 불필요하게 달라지지 않는지 확인.
- 실제 명령 기반 원정 검사(`test:runs`): 최소 각 어휘모드×10개 고정seed, 총40개. 합법 손패/교환/준비만 사용. 모든 seed 승리를 강제하지 않고 실패 원인·입력 오류·수동 해금 차이 구분. 기존 suite가 더 넓으면 그대로 이용하되 중복 반복 금지.
- 1366×768,1920×1080,1024×768,1180×820의 UI. touch emulation은 실제 iPad Safari로 표기하지 않는다.
- 속도1/1.5/2,효과감소,오프라인 초기로드 후 플레이를 점검.

테스트를 지워 PASS수를 만들지 않는다. ‘무효제출은 카드/턴 무소모’·‘4형식은 처음부터 배수’·‘도감 번역 존재’ 같은 옛 기대값은 이번 사용자 변경 이유를 적고 수정한다.
이 문서의 기대값/체크리스트는 실제 통과 결과가 아니다. PASS/FAIL/NOT RUN/범위밖을 분리한다. 합성 fixture, 실제 UI 완주, 자동 행동 시뮬레이션을 혼합 집계하지 않는다.

1. 일반전투에서 일부러 잘못 제출해카드/턴/0피해확인.
2. 새프로필과기존해금프로필의4형식공격비교.
3. develop자동사와be명사/형용사/장소구확인.
4. 나의덱에서한국어뜻확인, 문장도감에서는영어/문법/위력만확인.
5. 고정실습·첫룬·첫상점·항구보스의정상진행확인.

이 문서는 작업 요청이다. 지금까지의 문서·설정검사는 구현된 게임의 PASS가 아니다.
