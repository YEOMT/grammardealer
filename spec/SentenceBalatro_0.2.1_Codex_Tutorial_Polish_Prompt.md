## 0. 작업 지시와 범위

설명만 작성하고 끝내지 말고 실제 코드·데이터·테스트를 수정한다. 기존 0.2를 처음부터 다시 만들지 않는다.

이번 변경은 아래 네 가지로 제한한다.

1. 기존 Stage 1-1을 고정 실습 전투로 만들어, 교환·준비·형태 선택·두 번의 공격까지 실제 행동으로 안내한다.
2. 손패의 굵고 돌출된 버리기 선택 원을 카드 디자인에 자연스럽게 통합한다.
3. 강한 공격의 충돌 순간, 전투판 반동, 소리, 처치 연출을 강화한다.
4. 시작의 초원 HP를 최초 0.1 개발값의 **110%**로 조정한다.

새 스테이지, 새 룬, 새로운 화폐, 서버, 로그인, 랭킹, 상점 개편, 고급 문법, 새로운 렌더링 프레임워크는 추가하지 않는다. 튜토리얼의 `fast` 부사 처리를 위해 필요한 최소 언어 데이터·수식 규칙만 예외적으로 보완한다.

`AGENTS.md`와 더 가까운 하위 지침을 먼저 읽고 따른다. 미커밋 파일을 삭제·덮어쓰기하지 않는다. main에 직접 커밋·push하거나 자동 merge하지 않는다. 별도 브랜치에서 변경하고 검증 후 push·PR 생성까지만 수행한다. Pages 설정 변경·승인 없는 공개 배포·과거 Work ZIP 복원은 하지 않는다.

## 1. 반드시 보존할 기준

- Vanilla JS + ES Modules + Vite. 기존 모듈과 스타일을 확장한다.
- Grammar → Scoring → Rune → Stage/Boss → RunController 커밋 → Presentation 경계.
- 상태 커밋은 RunController만 담당한다. UI 콜백이 직접 카드·HP·재화를 바꾸지 않는다.
- 일반 시작 덱 28장, 첫 손패 6장, 손패 한도 10장, 다음 턴 3장, 교환 4회, 행동 6턴, 조합대 16장.
- 카드 본체 클릭/드래그/회수/삽입/재배열/맞교환/형태 선택, 선택 후 버리기, 가능한 Undo.
- be 원형 표시와 실제 am/is/are 선택. 자동으로 주어에 맞춰 정답 형태를 골라주지 않는다.
- 혼합 3칸 중 1개 보상, 취소 시 후보 고정, 전역 2번째 전투 뒤 첫 룬 선택.
- 기본 처치 재화 + 처치 행동을 소비한 뒤 남은 턴 재화. 한 사건당 한 번 정산.
- 느려진 채점 읽기 시간, 오른쪽 룬 색상 연출, 연마 표시, 최대 손패/조합대 UI와 사이드 글자 크기.
- 4형식 실제 판정, 토파즈 룬, 항구 입장 카드, 첫 상점, 주절 4형식으로 그 공격부터 해제되는 장막.
- 기존 도감·한글 의미 참고·개인 설정·해금·수동 저장 3슬롯.
- 미지원 문법은 가짜 성공 처리하지 않는다. 한글 뜻을 문법·점수에 역으로 사용하지 않는다.
- 총 제공 콘텐츠는 여전히 3+4=7전투, 최종 경계 STAGE2_END. 48전투 roadmap과 상점 위치를 바꾸지 않는다.
- 다른 DS 게임·배틀로얄 코드는 열어 참고하거나 가져오지 않는다.

## 3. HP 변경: 원래 수치의 1.10배

정확한 대상은 과거 1.30배 상향을 적용했던 시작의 초원 3전투이다.

| 전투 | 최초 0.1 | 0.1.1/0.2 | 새 0.2.1 원정 |
|---|---:|---:|---:|
| Stage 1-1 | 70 | 91 | **77** |
| Stage 1-2 | 120 | 156 | **132** |
| Stage 1-3 보스 | 220 | 286 | **242** |

- 신규값은 `(originalHP × 11) / 10`에서 한 번 계산한다. 이 세 값은 정수다.
- 현재값에서 10% 차감하는 것이 아니다. 현재값에 1.10을 다시 곱하지도 않는다.
- 초기화·입장·로드마다 배율을 거듭 적용하지 않는다. hp/maxHp/표시/검증이 같은 encounter snapshot을 사용한다.
- 고정 실습 Stage 1-1도 기본 HP **77**을 사용한다. 아래 두 공격이 실제 계산으로 성립하므로 별도의 숨은 무적·잔여 HP 보정이 필요 없다.
- 항구는 0.2에서 새로 설정된 별도 밸런스다. 작성 시 HP `220/300/380/640`은 **유지**한다. 최초 70/120/220과 대응하지 않으므로 근거 없이 11/13을 일괄 적용하지 않는다.
- Stage 2의 장막·가격·지역 배수·턴·보상·룬 수치는 바꾸지 않는다.
- 0.1.0 저장은 70/120/220, 0.1.1·0.2.0 저장은 91/156/286이라는 기존 버전 규칙을 보존한다. 현재 전투뿐 아니라 그 옛 원정의 이후 초원 encounter도 보존한다.
- 새 0.2.1 원정에만 77/132/242를 적용한다. UI 연출·선택 디자인은 기존 원정에도 개선된 것으로 표시할 수 있다.

## 4. 튜토리얼의 위치와 의무 정책

### 4.1 기존 1-1을 사용

새 튜토리얼 라운드를 앞에 추가하지 않는다. 초원은 여전히 3라운드다.

`1-1 고정 실습 → 1-1 보상 → 1-2 자유 전투 → 첫 룬 선택 → 1-3 보스`

### 4.2 새 실습을 한 번은 반드시 완료

- 새 실습 버전을 완료하지 않은 프로필이 **새 0.2.1 원정**을 시작하면 고정 실습을 진행한다.
- 예전 `guideSeen=true`나 `skipped=true`는 새 실습 완료로 취급하지 않는다.
- 첫 공격만으로 완료하거나 ALTERNATIVE_PLAY로 나머지 단계를 우회할 수 없다.
- 실습 내부에는 ‘안내 건너뛰고 완료’ 버튼을 두지 않는다. 실제 행동과 두 번째 공격, 종료 안내까지 완료해야 완료 기록을 남긴다.
- 게임을 나가기·실습 다시 시작하기는 명시적 확인 후 가능하다. 중단·닫기·실패는 완료가 아니다.
- 새 실습을 이미 완료했다면 이후 새 원정의 1-1은 일반 랜덤 전투다. **매 원정 강제 반복은 하지 않는다.** 이는 반복 플레이를 보존하기 위한 이번 구현 결정이다.
- 설정의 ‘조작 연습’에서는 같은 시나리오를 다시 할 수 있지만 별도 임시 Controller/프로필을 사용한다. 실제 원정·재화·저장·완료 실적을 변경하지 않는다.
- 진행 중인 구버전 저장이나 Stage 2 저장을 불러왔다고 강제 실습으로 전환하지 않는다.

### 4.3 보여줄 안내

실습 시작: “첫 전투는 정해진 카드로 진행하는 조작 연습입니다. 다음 전투부터는 이번 원정의 덱으로 도전합니다.”

완료: “이제 모험이 시작됩니다. 카드를 모으고, 룬을 조합하고, 완전한 문장으로 앞길을 열어 보세요.”

## 5. 고정 카드 계획 — 숨은 카드 생성 금지

### 5.1 실습 규칙

- 시작 손패 6장 / 손패 한도 10장 / 다음 턴 3장 / 행동 6턴 / 조합대 16장.
- **실습 교환 행동만 1회**. 일반 전투 기본 교환 4회를 변경하지 않는다.
- 실습에는 장착 룬·연마·특수 효과가 없다. 프로필의 영구 해금은 장착 효과가 아니다.
- 실습 속도는 표시상 1배속을 사용한다. 기존 개인 속도 설정을 덮어쓰지 않고 완료/종료 시 원래 설정으로 돌아간다.

### 5.2 고정 순서

첫 손패, 왼쪽부터:

`be / happy / run(A) / really / small / good`

뽑을 더미 앞부분, 이 순서 그대로:

`I / he / very / fast(부사) / run(B) / book / a`

- run(A)를 교환하면 맨 위 I가 들어온다.
- 첫 공격 후 다음 턴의 +3장은 he / very / fast다.
- 그다음 준비 후 +3장은 run(B) / book / a다.
- run(A)와 run(B)는 서로 다른 물리 카드 ID다. run(A)는 끝까지 버린 더미에 있어야 한다.

나머지 15장은 사용 가능한 기존 카드로 명시해 28장 실습 덱을 완성한다. 제안 tail:

`be(두 번째) / you / they / like / go / come / give / show / dog / cat / music / friend / the / in / with`

단어 정의 ID가 실제 코드와 다르면 해당 기존 ID를 참조한다. 누락을 가짜 토큰으로 보충하지 않는다. 첫 13장의 역할과 순서는 변경하지 않는다. tail에 필요한 기존 단어의 이름 변경은 실제 registry 근거를 기록한다.

### 5.3 일반 원정 덱과 분리

- 사용자가 선택한 어휘 수준과 seed로 **정상 28장 원정 덱을 한 번 생성**하고 실습 동안 보관한다.
- 실습은 위의 고정 28장과 별도의 결정론적 실습 드로우 상태를 사용한다. 별도의 문법/점수 엔진은 만들지 않는다.
- 일반 덱의 IDs/강화/어휘/생성 기록/난수 위치는 실습 중 변화시키지 않는다.
- 실습 완료 뒤, **1-1 보상 후보 생성·선택 전에** 정상 덱을 원자적으로 복원한다. 그런 다음 기존 전역 첫 전투 보상 흐름을 실행한다.
- 보상으로 받은 카드를 덱 전환에서 지우지 않는다. 실습 전용 카드가 정상 덱·원정 사전에 섞이지 않는다.
- 보관한 정상 덱은 활성 전투 piles에 동시에 들어 있지 않다. 활성 실습 덱의 28장은 언제나 DRAW/HAND/SENTENCE/DISCARD 중 정확히 한 곳에 있다.
- 일반 원정의 reward/shop/encounter RNG를 실습 클릭·드래그·패널 확인 때문에 소비하지 않는다. UI 효과는 별도 Visual RNG다.
- 상태 구조는 작은 `tutorialSession`과 보관용 순수 데이터 필드 정도로 해결한다. 범용 미션 DSL이나 별도 전체 게임 복제본을 만들지 않는다.

### 5.4 fast를 실제로 지원

작성 시 main의 부사 정책 표에는 fast가 없다. 런타임 registry에 실제 부사 용법이 존재하는지 먼저 확인한다.

없다면 **fast(부사, 빠르게)**의 Lexeme/Sense/Form/Card를 최소 추가하고, `run fast`, `run very fast`가 기존 수식 엔진으로 정상 분석되게 한다.

- fast를 형용사 카드인데도 몰래 부사로 점수화하지 않는다.
- 기존 같은 철자의 Lexeme/Card/Form ID를 덮어쓰지 않는다. 중복 ID를 검사한다.
- 이번 추가 카드는 실습/샌드박스용으로만 공급하고 일반 시작 덱·보상·상점 후보에 새로 섞지 않는다. 기존 후보 순서와 레거시 RNG를 보존한다.
- `very + fast`의 부사 수식 연결을 정상 처리한다. 단순히 모든 형용사를 부사로 허용하거나 정답 문장을 문자열 비교로 특례 처리하지 않는다.
- 비교급·최상급·다른 문법은 활성화하지 않는다.

## 6. 행동 기반 전체 시나리오

다음은 표시할 문구와 단계 완료 조건이다. 문구는 길이·줄바꿈만 다듬되, 의미와 순서는 보존한다. 단계는 시간 경과나 클릭 횟수가 아닌 **성공한 명령과 실제 카드 상태**로 전환한다.

| ID | 안내·강조 대상 | 실제 행동과 완료 조건 |
|---|---|---|

### 진행 UI 원칙

- 조작 단계에는 의미 없는 ‘다음’ 버튼을 두지 않는다. 설명 단계만 확인 버튼을 사용한다.
- 현재 행동 외의 공격·준비·교환·형태·Undo·룬 변경은 상태에 따라 잠근다. 체크는 정확한 대상만 허용한다.
- 잘못 누른 행동은 무손실로 거절하고 현재 목표를 다시 표시한다. 학생을 벌주지 않는다.
- 단순히 CSS overlay로 막는 것만으로 끝내지 않는다. Controller의 실습 명령 guard도 현재 단계/카드 ID/형태/공격 ID를 검증한다.
- 동시에 여러 단계를 건너뛰거나, 두 번 누른 버튼으로 다음 단계의 자원을 쓰지 못하게 한다.
- 안전한 음소거·설정·지정 패널 닫기·명시적 나가기 경로는 남긴다. escape로 조작 단계가 완료되어서는 안 된다.
- 카드 덱/사전 패널은 가짜 이미지가 아니라 실제 데이터를 보여주는 기존 UI다. 실습용 어휘 목록임을 구분한다.
- 엄격한 필수 실습은 이번 고정 시나리오에만 적용한다. 일반전의 자유 편집을 제한하지 않는다.

## 7. 실제 점수로 두 번의 공격을 검증

이 계산은 현 main의 점수 규칙으로 산출한 **기대값**이며 아직 구현 테스트 결과가 아니다.

| 문장 | 기대 판정·계산 | 최종 위력 |
|---|---|---:|
| I be happy | 카드30 − BE_FORM_REQUIRED 10 → 완전문장 보너스0 → 2형식 ×6/5 =24 → 지역 ×5/4 | **30** |
| He runs very fast | 카드40 + 완전문장20 → 1형식 ×1 → 정상 부사 카드 very/fast 각각 +5 → 지역 ×5/4, 내림 | **87** |

실습 적 HP: 77 → 첫 공격 후47 → 두 번째 공격 후0.

- I be happy는 핵심 2형식 구조를 복구한 VALID_WITH_ISSUES이며, BE_FORM_REQUIRED가 한 번만 발생해야 한다.
- He runs very fast는 fast 부사 지원 후 VALID, 1형식, 부사 두 카드의 정상 기여로 계산한다.
- 첫 공격을 일부러 1점으로 만들거나, 두 번째 공격에 실습 전용 배수를 붙이거나, 강제로 killed=true를 넣지 않는다.
- 두 문장은 카드 수와 구조도 다르므로 전체 점수 차이가 전부 be 오류 하나 때문이라고 설명하지 않는다. 실제 감점과 보너스 이벤트를 가리킨다.
- 두 번째 강한 피격은 기존 실제 위력/적 최대 체력 기반 강도와 새 충돌 연출로 보여준다. 튜토리얼 전용 가짜 위력은 없다.
- 점수 규칙이 작성 이후 main에서 달라졌다면 먼저 실제 결과와 차이를 기록한다. 연출을 맞추려고 점수식을 바꾸지 않는다. 이 요청과 충돌하는 선행 변경은 명확히 보고한다.

## 8. 실습 정산·기록·재연습

- 실습 성공 시 1-1 기본재화2 + 실제 남은턴3 =5를 원정에 한 번 정산한다.
- 아직 지원되지 않은 황금카드 기능을 이 패치에서 추가하지 않는다.
- 고정 실습 공격은 실제 원정의 최고피해, 문법 사용 실적, 피해량 기반 희귀 룬 해금, 개인 첫/최고 문장 기록으로 누적하지 않는다. 화면의 최근 실습 결과로는 볼 수 있다.
- 실습 완료는 조작 학습 플래그다. Stage1 클리어·qualifiedRunIds·storyClearCount 증가와 혼동하지 않는다. Stage1 전체 클리어 사건은 기존대로 보스를 잡았을 때만 발생한다.
- 실습 전투 종료·정상 덱 복원·재화 정산·완료 플래그·보상 생성은 식별자로 멱등 처리한다. 같은 확인·타격·FINISH·로드를 재전송해도 두 번 지급되지 않는다.
- 새 실습을 위해 기존 firstRuneIntroSeen/guideSeen을 임의로 지우지 않는다. 처음 보는 프로필의 전역 2번째 전투 첫 룬은 고정3후보, 기존에 본 프로필은 기존 랜덤 정책을 보존한다.
- 설정 재연습은 원래 원정과 저장을 건드리지 않고 재화·카드·실적을 일절 지급하지 않는다.
- 실습을 다시 시작할 때 보관한 정상 덱을 불필요하게 재생성하거나 난수 소비를 늘리지 않는다.

## 9. 말풍선·스포트라이트·화살표 UX

말풍선만 추가해서 기존 자유 가이드처럼 끝내지 않는다. 실제 따라 할 위치와 진행 상태가 보여야 한다.

- 현재 단계에 필요한 요소만 은은하게 밝히고, 나머지 화면은 과도하지 않게 어둡게 한다.
- 대상 클릭·드래그 출발점·도착 삽입선을 각각 표시한다. 드래그 고스트/화살표는 짧게 반복하되 무한 시끄러운 파티클은 없다.
- DOM의 실제 bounding rect를 사용하고 resize/방향전환/scroll/패널 열기 후 다시 배치한다. 고정 픽셀 위치를 외우지 않는다.
- 말풍선은 카드·형태 선택 항목·확인 버튼을 덮지 않는다. viewport 안에서 방향을 뒤집거나 위치를 조정한다.
- 1~2문장 중심의 한글 문구, 최소 약16px 읽기 글자. 카드의 기존 영단어 폰트와 최대 카드 배치는 유지한다.
- ‘단계 n/N’ 진행도를 작게 표시한다. 기능을 다시 처음부터 설명하는 중복 팝업을 만들지 않는다.
- 키보드로 타깃에 접근하고 Enter/Space로 조작할 수 있게 한다. 드래그 대체 경로는 같은 실제 reorder/insert 명령을 사용한다.
- 오디오 없이도 모든 지시를 이해할 수 있어야 한다. 감소된 모션에서도 정적 강조·화살표·명시 텍스트로 진행할 수 있다.
- 대상 요소가 사라졌을 때 무한 대기하지 않는다. 같은 단계를 재렌더하거나 명확한 기술 안내와 실습 재시작/나가기 경로를 제공한다.
- 재렌더 뒤 예전 이벤트 리스너가 누적되거나 다른 카드에 붙지 않게 정리한다.

## 10. 사용자 확인을 기다리는 연출 gate

기존 ‘전체 예상시간 + 여유’ watchdog과 같은 wall-clock 타이머만으로 실습을 처리하면 안 된다.

1. 일반전 timeline은 현재 읽기 시간과 완료 정책을 유지한다.
2. 실습에서만 실제 이벤트 ID/phase에 연결된 확인 gate를 넣는다. 문장 문자열에 따른 가짜 score 이벤트를 추가하지 않는다.
3. Gate는 이미 확정된 AttackResolution을 읽는다. 확인할 때 SUBMIT이나 resolveAttack을 다시 호출하지 않는다.
4. Gate 대기와 튜토리얼 탭 비활성 시간은 watchdog의 **실행 예산에서 제외**한다. 60초 이상 읽어도 정상이다. 타임아웃 값을 무작정 크게 하는 것으로 대체하지 않는다.
5. 애니메이션이 실제 실행 중인데 멈춘 경우의 timeout/예외 처리는 유지한다.
6. 실습 중 document.hidden이면 자동 FINAL_POWER/impact/FINISH로 건너뛰지 않는다. 복귀 후 같은 미확인 gate 또는 안전한 표시 지점에서 이어간다.
7. 일반전에서 기존 hidden 시 빨리 종료하는 정책은 이번 요구와 무관하게 전역 변경하지 않는다.
8. 대기 중의 attackId/cueId/sessionId를 검증한다. 예전 gate의 두 번째 확인이 다음 gate를 닫거나 중복 타격을 만들면 안 된다.
9. 나가기·재시작·route 전환·실제 에러 시 gate Promise, 타이머, Animation, 임시 DOM, 포커스 잠금을 모두 정리한다. 완료 플래그는 세우지 않는다.
10. 이미 커밋된 실습 공격을 다시 표시해야 한다면 같은 resolution만 재생한다. 게임 점수·HP·턴을 재적용하지 않는다.
11. 의도적 중단 경로에서는 기존 finally의 ‘강제 impact 후 FINISH’가 안내 완료로 이어지지 않게 분리한다. 기술 오류를 학생의 실패로 처리하지 않는다.
12. 실제 게임 상태와 표시 HP를 분리한다. 사용자 확인을 기다리는 동안 적이 미리 사라지거나 승리 보상 화면이 먼저 뜨면 안 된다.

## 11. 카드 선택 표시 개선

기존 카드 밑으로 튀어나온 굵은 원을 제거하고 카드 하단 모서리/푸터에 어울리는 얇은 체크 영역으로 바꾼다.

- 비선택: 얇은 테두리, 낮은 강조, 작은 체크 모티프와 필요시 ‘선택’ 단서. hover가 없는 태블릿에서도 발견 가능해야 한다.
- 선택: 카드가 약간 들림, 선명한 체크, 테두리 강조. 색 하나만으로 상태를 구분하지 않는다.
- 보이는 체크는 작게 해도 실제 터치 타깃은 약44×44 CSS px을 목표로 한다. 카드 본체/형태 버튼과 타깃 영역이 겹치지 않게 현재 푸터 공간을 활용한다.
- `aria-pressed` 또는 적절한 checkbox 의미, 카드명을 포함한 접근 가능한 이름, 키보드 focus 표시를 제공한다.
- 본체 클릭은 조합, 선택 영역은 선택, 형태 버튼은 형태 메뉴라는 기존 의미를 유지한다.
- 체크 클릭이 부모에 전파되어 카드 이동/드래그를 동시에 실행하지 않는다. pointercancel 뒤 잔여 선택·drag ghost가 없어야 한다.
- selectedCardIds는 현재 실제 손패와 교집합으로 유지한다. 제출·이동·교환·로드·새 전투 뒤 유령 선택이 남지 않는다.
- 버리기 버튼에 선택 장수와 잔여 교환을 표시하고 0장/교환0이면 적절히 비활성화한다.
- 상점·보상·도감의 읽기 전용 카드에는 실전 버리기 체크를 노출하지 않는다.
- 기존 카드 크기·영단어 크기·룬 패널 위치·14장 손패와16장 조합대 대응을 유지한다. 별도 UI 테마 재작성은 금지한다.

## 12. 타격감 강화

목표: 점수 계산을 다시 빨라지게 하지 않으면서, 계산이 끝난 힘이 충돌하는 순간 확실히 느껴지게 한다.

### 12.1 기본 흐름

`짧은 응축 → 빠른 돌진 → 접촉 순간 충격음/피해 표시 → 시각적 hit-stop → 전투판 반동과 적 반동 → 감쇠/처치 퇴장 → 다음 상태`

- Hit-stop은 UI/애니메이션의 짧은 정지이며 JS busy loop, 메인스레드 sleep, 서버/게임 시간 조작이 아니다.
- 현재 score/rune 읽기 구간은 유지한다. 강도에 따라 마지막 charge/lunge/impact/settle만 조정한다.
- 접촉 순간 소리·HP 변화·충격 링이 같은 semantic impact 이벤트에 연결된다. 피해를 다시 계산하지 않는다.

### 12.2 강도 초안

기준 비율은 이미 확정된 최종위력 / **적의 최대 HP 또는 기존 버전의 안정적인 기준 체급**이다. 현재 남은 HP만 분모로 쓰지 않는다. 어떤 기준을 사용했는지 한 곳에 고정한다.

| 등급 | 기준 비율 예시 | hit-stop | 전투판 반동 예시 | 반응 길이 |
|---|---:|---:|---:|---:|
| 약한 공격 | 0 이상 ~ 0.5 미만 | 0~25ms | 0~2px | 약160~220ms |
| 강한 공격 | 0.5 이상 ~ 1 미만 | 60~90ms | 약5~8px | 약240~320ms |
| 압도적 공격 | 1 이상 | 100~120ms | 약8~12px, 상한 고정 | 약320~420ms |

위는 연출 초기 조절값이다. viewport와 모바일 폭에 맞춰 제한할 수 있으나 점수·피해량을 바꾸어 강도를 맞추지 않는다.

- 첫 실습 30/77은 약한 반응, 두 번째 87/77은 확실한 강한 반응이 나오는지 실제로 비교한다.
- 정상 약한 마무리를 했다고 killed 플래그만으로 최고 등급을 강제하지 않는다.
- 보스 장막/면역으로 최종 피해가 줄거나0이면 실제 결과에 맞춘 약한 피격/방어 연출을 한다. 계산 전 거대 점수만 보고 처치 연출을 하지 않는다.

### 12.3 화면·소리·처치

- 전투판에 첫 반동 한 번을 크게 준 뒤 빠르게 감쇠한다. 좌우 메뉴·말풍선·입력 버튼은 안정적으로 유지한다.
- 레이아웃을 재계산하는 top/left 이동보다 짧은 transform 기반 효과를 사용한다. 카드 돌진 transform과 카메라 transform을 서로 덮어쓰지 않는다.
- 적은 방향성 있는 밀림, 약한 squash/stretch, 회전 후 복원. 압도적 처치는 밀려나며 퇴장한다.
- 현재 적이 퇴장하는 동안 opacity를 즉시0으로 만들어 애니메이션을 안 보이게 하지 않는다.
- 소리는 기존 AudioService/볼륨·음소거를 재사용한다. 접촉음과 짧은 저음층을 조합하되 과도한 출력/겹침을 제한한다. 외부 BGM·효과음 다운로드나 새 플러그인은 필요 없다.
- 충격 링·잔상은 작은 DOM/CSS/SVG 효과를 재사용하고 개수·수명을 제한한다.
- 대형 전면 백색 섬광이나 빠른 반복 점멸은 쓰지 않는다. 색 대비와 국소 충격으로 표현한다.
- effectsOff/reducedMotion에서는 카메라 흔들림·플래시·크기 변화를 끄거나 줄인다. 숫자·문법 읽기 시간·완료 가능성은 보존한다.
- 필수 recoil/death animation이 끝나기 전에 FINISH_PRESENTATION/다음 화면/cleanup으로 잘라 버리지 않는다. 유한한 타임아웃과 예외 fallback은 남긴다.
- cleanup에서 모든 transform/filter/opacity의 잔여값, effect node, timer, audio schedule 참조를 정리한다. 다음 전투에 흔들림이 남지 않는다.

## 13. 저장·버전·호환

- IndexedDB 이름 `sentence-balatro-v0-1`, 기존 stores/프로필 ID/3슬롯을 유지한다.
- 0.2.1을 단순 version 문자열 치환만으로 구현하지 않는다. 현재 `=== '0.2.0'` 등 정확 일치 분기의 registry, stage, reward, manifest, validation을 모두 점검한다.
- 0.2.1도 Stage2/상점/토파즈를 제공한다. 새 버전이 레거시 Stage1 전용 경로로 잘못 떨어지면 안 된다.
- 기존0.1.0/0.1.1/0.2.0 원정은 본래 카드·HP·미래 encounter·상품·보상·해금 기준·RNG를 유지한다.
- 새 실습 완료는 별도 버전 플래그로 기록한다. 예전 tutorial 객체의 skipped/completed 기록을 없애지 않는다.

- 실습 도중 일반 중간턴 자동 저장을 새로 만들지 않는다. 원정 시작 실습 안전 지점과 완료 후 고정 보상 화면만 기존 수동 저장 범위에서 지원한다.
- 실습 시작 저장에는 고정 시나리오와 보관한 정상 덱·난수 위치가 들어 있어야 한다. 로드로 정상 덱을 새로 뽑지 않는다.
- 프로필에서 나중에 완료했다고 과거 미완료 실습 저장의 상태를 몰래 건너뛰지 않는다. 저장된 원정 진행은 그 저장을 기준으로 복원한다.
- gate 대기·공격 연출·대상 모달·거래 중 저장은 비활성화하고 이유를 표시한다.
- 저장 실패는 완료/재화 사건을 반복 재실행하는 방식으로 재시도하지 않는다. 기존 프로필 저장 실패 처리와 분리한다.

## 14. 구현 순서와 검증 비용 관리

A. main/미커밋 변경/AGENTS/현재 테스트 확인, 범위와 baseline 기록.

B. HP 버전 테이블과 단일 실습 시나리오 데이터. fast의 최소 지원과 두 문장의 실제 분석·점수 단위 테스트.

C. Controller 실습 guard·단계·고정 카드 이동·정상 덱 보관/복원·완료/기록/정산.

D. 실제 말풍선·패널 안내·드래그 경로·동작 확인 gate, 중단/hidden/재시작 처리.

E. 카드 체크 디자인, 충돌·반동·소리·퇴장. 시각 요소를 실제 화면에서 확인.

F. 새 프로필 실습→정상 1-2→첫 룬→초원 보스→항구 상점→Stage2의 회귀, 구버전 저장, 최종 빌드·PR.

개발 중에는 변경 영역의 작은 테스트를 먼저 돌린다. AGENTS가 요구하는 npm test/build와 필요한 전체 회귀는 변경 묶음과 PR 전 최종 상태에서 수행한다. 매 CSS 수치 변경마다 10,000 seed·전체 UI 캡처를 반복하지 않는다.

- 정상 덱 생성/보상 RNG/registry 후보가 바뀌지 않았다면 고정 정상 시드 회귀로 보존을 확인한다.
- 공유 덱 생성·후보 필터·일반 드로우 로직까지 변경했다면 전체 `test:decks`/관련 시뮬레이션도 최종 상태에서 실행한다.
- 이번 작업은 입력·연출 변경이므로 브라우저 검증은 필수다. 테스트를 생략해서 시간을 줄이지 말고 중복 실행을 줄인다.
- 오래 걸리는 검사는 실행 명령·시작·완료·진행을 간단히 기록하고 정체 시 원인을 확인한다. 이미 통과한 단계를 불필요하게 다시 구현하지 않는다.

시각 증거는 최소한 다음을 포함한다.

1. 고정 첫 손패와 be/happy 실습.
2. 새 카드 선택 표시와 run 교환.
3. I be happy의 실제 감점.
4. 준비 후 조합대 유지와 runs 형태 선택.
5. 점수 확인 gate와 두 번째 강한 타격.
6. 최대 카드 레이아웃과 reducedMotion.

정적 스크린샷만으로 타격감이 검증되었다고 하지 않는다. 가능한 경우 짧은 브라우저 녹화나 trace를 같이 남긴다. 게임용 GIF 에셋이나 영상 생성 플러그인을 추가하라는 뜻은 아니다.

완료 후 작업 브랜치를 push하고 main 대상 PR을 생성한다. main 직접 push, 자동 merge, 공개 배포는 금지한다. PR 본문에 시작 SHA, 변경 범위, 실제 검증, 남은 문제, 사용자 플레이 확인 순서를 적는다.

권한 문제로 push/PR이 막히면 로컬 변경과 검증 기록을 보존하고 어느 단계까지 했는지 정확히 보고한다. 성공했다고 가정하지 않는다.
