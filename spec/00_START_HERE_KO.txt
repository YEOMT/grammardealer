센텐스 발라트로 0.1 — Work 시작 지시문

첨부한 인계 묶음을 읽고 실제 코드를 작성하라.
기준 문서는 01_WORK_SPEC_v0_1.md이다. 02~05 파일은 실행 설정 초안·룬 데이터·단어 제작목록·인수조건이다. 기존 설계 대화와 이전 문서가 충돌하면 이 최신 명세의 범위/우선순위를 따른다.

목표는 '프로젝트 골격 + 실제 문장 샌드박스 + 여행자 Stage 1 세 전투'가 작동하는 센텐스 발라트로 0.1이다. 문서 재요약이나 추가 설계 제안만 하고 끝내지 않는다.

반드시 지킬 것:
- 실수로 첨부된 배틀로얄 HTML 및 다른 DS 게임의 코드를 열어 분석하거나 기반/참고 코드로 사용하지 말라. 새 Vanilla JS + ES Modules + Vite 프로젝트로 시작한다.
- 30장 랜덤 덱, 시작 6장, 손패 10장, 다음 턴 3장, 교환 4회(여러 장 동시 교환·같은 수 즉시 드로우), 전투 6턴을 유지한다.
- 문장 클릭/드래그/형태변경을 편하게 만들고, 제출 전에는 예상 점수·문법 정오·콤보를 보여 주지 않는다.
- 등록된 기본 영어를 실제로 분석한다. 정답문장 화이트리스트나 가짜 점수로 게임이 작동하는 것처럼 보이게 하지 않는다.
- 문법/점수/룬/스테이지·보스/연출은 책임을 분리하고, RunController만 실제 상태를 변경한다.
- 제출 뒤 한글 문법명·해당 카드 점등·오른쪽 보석 룬·누적 숫자·돌진·충격이 한 흐름으로 이어져야 한다.
- 룬은 최신 보석 이름을 사용한다. 0.1은 명세의 10종만 실제 구현한다. 첫 룬은 매 원정 1-2에서 제공하며 최초 후보는 수정/호박/구리다.
- Stage 1 완료는 0.1 제공 구간 완료이지, 전체 스토리 48전투 클리어가 아니다. 2스테이지·상점·다른 캐릭터·고급 문법·랭킹을 가짜로 열지 않는다.
- 로컬 개인기록과 안전지점 수동 3슬롯 저장은 최소 실제 구현한다. 실행 중 네트워크가 끊겨도 진행/저장은 된다. PWA 설치·오프라인 재시작·Firebase는 후속 범위다.
- 사용자가 복잡한 개발환경을 익히지 않아도 되도록 소스 ZIP과 빌드 완료된 배포 ZIP을 각각 제공한다. 실제 저장소/배포를 승인 없이 덮어쓰지 않는다.

진행:
골격/계약 → 실제 데이터와 샌드박스 → 단일 전투 → Stage 1/룬/보상 → 저장/배포/인수검사 순서로 작업하라. 단계마다 테스트하되, 명세에 답이 있는 문제를 계속 되묻거나 사용자 승인 대기로 멈추지 않는다. 설계한 문법을 모두 한꺼번에 구현하지 않는다.

첨부 05의 138개 사례는 테스트 기대사항이지 통과 결과가 아니다. 실제 구현으로 다시 검사하고, 생성덱 검사·브라우저 조작·저장·서브경로 배포 검사 결과를 남겨라.
