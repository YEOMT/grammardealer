## 1. 최신 사용자 지시 — 단일 -ing 형태가 최우선

> **동명사와 분사는 형태 메뉴에서 따로 고르지 않는다. 한 동사의 -ing 형태는 하나만 두고, 제출 후 문장 전체에서의 역할을 분석한다.**

`reading (동명사)`와 `reading (현재분사)`라는 두 버튼을 만들지 않는다. `form.read.ing` 같은 기존 형태 ID를 재사용한다. 학생은 **형태를 선택**하고, 엔진은 **그 형태가 하는 일**을 판정한다.

| 레이어 | 책임 |
|---|---|
| Lexeme / Form | read / reading이라는 단어·실제 표기·형태 정보 |
| 카드 편집 | 어떤 물리 카드가 어느 위치에 놓였고 어떤 Form을 선택했는가 |
| Grammar | 동명사구의 주어/목적어/보어/전치사 목적어, 진행 동사구, 명사 수식 분사 등 역할 |
| Combo eligibility | 실제 분석 중 현재 원정에서 보너스를 주는 요소 |
| Scoring / Presentation | 같은 증거의 점수와 한글 역할을 한 번 계산·표시 |

영어에서 -ing형은 명사적·수식적 사용과 동사구의 일부로 쓰인다. 단순한 글자 위치가 아니라 **지배 동사·전치사·보어·절 구조**까지 함께 판정해야 한다. 어떤 분석이든 합법이면 인정하되, 중의적 구조는 검수한 대표 분석 하나로 정규화하고 같은 역할 보너스를 중복하지 않는다. [G1][G2]

## 2. 완성 범위와 기존 기능 보존

새 0.5 원정: 초원3 + 항구4 + 협곡5 + 하늘섬5 + 사막5 = **22전투**.

- 전역 18~22가 Stage 5이다. 5-5 처치·보상 이후 `CONTENT_COMPLETE / STAGE5_END`.
- Stage 4 보스 이후 `STAGE4_END`로 조기 종료하지 않고 Stage 5로 연결한다.
- 실제 상점은 Stage 2와 Stage 4 입장 두 번이다. **Stage 5 상점은 추가하지 않는다.** 다음 예정 상점은 Stage 6 입장이나 이번에는 실행되지 않는다.
- 시작 룬 슬롯은 3, Stage 3 완료 후 4. Stage 5 완료로 5번째 슬롯이나 난이도·캐릭터를 추가 해금하지 않는다.
- 전체 48전투 클리어, 무한 모드, 다회차 보스·추가 캐릭터·서버 랭킹은 미구현 상태를 유지한다.
- 기본 카드 점수10, 연마+5/최대+3, 완전문장+30, 1~4형식×1.3/1.6/1.8/2.2와 기존 시간·연결 배수는 보존한다.
- 기존 룬 배율·희귀도·운석 문턱·순서 계산과 장문 고점을 유지한다. 새 희귀 룬 대개편을 끼워 넣지 않는다.
- 28장 WORD 시작 덱의 be2, have 고정 슬롯, I/you/they와 he 또는 she, 품사 할당과 첫패 정책을 유지한다. be/have/I/you 고급도 유지한다.
- 보급/탐색은 조합대 불가, 전투당 사본별 1회, EXHAUSTED 후 다음 전투 복귀. 연마 불가·제거 가능을 유지한다.
- 문법 실패 제출은 카드·턴 소비와 0피해, 기술 오류만 무소모. 봉인된 카드의 **불법 배치 클릭은 제출이 아니므로** 비용 없음.
- UI는 Syntax Atlas / 신택스 아틀라스 명칭을 유지한다. 저장소·배포 base·IndexedDB 이름을 바꾸지 않는다.

## 4. 단일 -ing 형태 계약

### 4.1 형태 데이터와 UI

각 동사 lexeme의 기존 `.ing` form ID·표기를 유지한다. `form.run.ing`은 `running` 하나다. 새 `.gerund`, `.presentParticiple` 복제 Form을 만들지 않는다.

새 view에서 필요하면 `morphologicalForm:'ING'` 같은 역할 중립적 속성을 덧붙인다. 기존 `grammaticalFeatures.tense:'PRESENT_PARTICIPLE'`는 레거시 호환 정보일 수 있으므로 **그 문자열만 보고 모든 쓰임을 분사/진행으로 확정하지 않는다.** 공통 helper로 ING 형태인지 확인하고 용법은 분석 노드에 둔다. 레거시 view 자체는 변형하지 않는다.

- 메뉴 제목/라벨은 **`-ing형`**. `진행 전용`, `동명사 전용`, `진행형으로만 사용` 같은 설명 금지.
- 현재/원형 전체 줄 → 과거 전체 줄 → 과거분사와 -ing 두 칸 배치를 유지한다.
- 현재형/원형 선택, 과거형과 p.p.의 동형이의 형태 구분은 유지한다. 이번 통합은 **-ing 사용 역할**에 한정하며 `read`의 현재/과거/p.p. 구분까지 없애지 않는다.
- will에는 will 자체의 ing나 p.p.를 만들지 않는다. 기존 interesting 같은 형용사 단어를 끝 철자만 보고 동명사로 바꾸지 않는다.
- 카드의 기본 품사 색은 lexeme 기준을 유지한다. 편집 중 위치를 보고 실시간으로 명사색/분사색을 바꾸는 자동 판정은 하지 않는다.
- 학생이 역할 모드나 ‘동명사로 사용’ 체크박스를 선택할 필요가 없어야 한다.

### 4.2 같은 Form을 쓰는 필수 사례

| 문장 | 선택 형태 | 판정 |
|---|---|---|
| Reading books is good. | read의 기존 `reading` | `Reading books` 전체가 동명사구 주어. SVC |
| I enjoy reading books. | 같은 `reading` | 동명사구 목적어. SVO |
| My hobby is reading books. | 같은 `reading` | 동명사구 주격보어. SVC |
| I am good at reading books. | 같은 `reading` | 전치사 at의 목적어인 동명사구. SVC+PP |
| I am reading books. | 같은 `reading` | be와 결합한 진행 동사구. SVO. 동명사 보너스 없음 |
| The running dog is happy. | run의 기존 `running` | 명사 dog를 수식하는 현재분사. SVC. 동명사/진행 보너스 없음 |
| I want to be reading books. | be 원형 + 같은 `reading` | to부정사 내부 진행. 바깥 절의 현재진행으로 오인하지 않음 |

분사는 Stage7의 집중 주제이지만 **간단한 명사 수식 사용의 기본 판정**은 단일형태 원칙을 위해 이번에 지원한다. 별도의 분사 팩/보스/수동태/지각동사 O+ing 대규모 확장은 하지 않는다. `The dog running in the park is happy`처럼 간단한 후치 분사 수식도 같은 유한 구 조립으로 판정한다.

### 4.3 중의적인 be + -ing 처리

`be + -ing`의 겉모양만으로 항상 진행형을 택하거나 항상 동명사 보어를 택하지 않는다. `I am reading books`와 `My hobby is reading books`가 모두 문법적으로 성립할 수 있는 데이터 범위를 유지한다.

대표 분석은 점수가 아니라 등록된 교육용 구조 우선순위로 결정한다. 예: 새 hobby의 활동명사 Sense와 be의 명사적 서술 관계를 사용하는 경우 SVC/GERUND 대표 분석, 일반 행위주체+be+동작 V-ing는 PROGRESSIVE 대표 분석. 이런 제한된 어휘·구조 힌트는 **대표 Tag 정규화**용이지 상식에 어긋난 주어를 오답으로 배제하는 장치가 아니다. 동점은 고정된 production/Sense 순서로 정한다. 두 분석을 모두 점수에 더하지 않는다. [G1][G6]

‘위치에 따른 판정’은 단순 인덱스 규칙이 아니라 전체 구조 판정이다. 이 구별을 구현할 수 없을 때 임의의 높은 점수를 택하는 방식으로 넘기지 말고 관련 테스트와 기준을 보강한다.

## 5. Stage 5 기본 문법 지원 범위

### 5.1 to부정사

| 역할 | 필수 범위 | 예 |
|---|---|---|
| 명사 역할 | 주어·동사 목적어·주격보어 | To read books is good. / I want to read books. / My plan is to help you. |
| 명사 설명 | 명사 뒤 to구, 검증 가능한 목적어·전치사 목적어 공백 | I need a book to read. / I need a friend to play with. |
| 목적 표현 | 앞/뒤 목적 to구. 일반 사막 플레이는 뒤 위치 중심 | I go to school to read books. / To help you, I read books. |
| 형용사 연결 | 등록한 happy/ready 등 + to구 | I am happy to help you. / I am ready to read. |
| 기본 가주어 | It + be + 검수한 형용사 + to구 | It is easy to read books. |
| 목적격보어 | 등록한 동사 + 목적어 + to구 | I want you to read books. / She needs me to help her. |

- `to` 전치사와 부정사 표지를 구조로 구분한다. `I go to school`의 to에 부정사 보너스를 주지 않는다.
- 목적어/보어가 필요한 본동사의 Frame을 안쪽에서도 검사한다. 부정사라고 필수 목적어를 무조건 생략할 수 있는 것이 아니다.
- 명사 후치 to구의 공백은 실제 선행명사와 연결한다. `a book to read`의 book을 가상 카드로 두 번 계산하지 않는다. `a friend to play with`의 끝 with도 실제 카드가 필요하다.
- 모든 명사/형용사에 아무 to구나 붙이는 범용 통과 규칙을 만들지 않는다. 단, 가능한 분석이 있으면 목적/후치 수식 중 대표 하나로 정규화하고 의미가 어색하다는 이유만으로 감점하지 않는다.
- 가주어/의미상 주어 심화, 모든 tough-construction, 독립분사구문, 비교+too/enough, 가정법은 이번 집중 확장 밖이다. 위 기본 가주어 사용은 인정하되 전용 고급 배수/튜토리얼은 나중에 한다.
- 목적 to구의 앞배치는 기존 구두점 정책을 따른다. 학생에게 쉼표 카드를 구매하게 하거나 쉼표 유무만으로 실패시키지 않는다. 표시용 구두점은 점수 없는 표현이다.

### 5.2 동명사

같은 ING 형태로 만들어진 구가 명사 역할을 할 때 인식한다. 내부 목적어·부사·전치사구·지원하는 관계절/내용절을 기존 규칙으로 조합한다.

필수: 주어, 직접 목적어, 주격보어, 전치사 목적어. 단일 동명사구 주어는 일반적으로 3인칭 단수 일치를 요구한다. 정상적인 등위 동명사구 주어는 기존 등위 주어 규칙을 재사용한다.

`Reading books is good`에서 reading 앞에 관사가 없다고 감점하지 않는다. `I enjoy reading books`에서 books가 enjoy의 직접 목적어라고 잘못 표시하지 않는다. 바깥 목적어는 **reading books 전체**, 안쪽 read의 목적어는 **books**다.

- `like`는 to와 ing 둘 다 기본 지원한다.
- `need + ing`의 수동적 용법은 필요하면 바깥 주어를 안쪽 행동의 생략된 대상으로 연결하는 별도 Frame binding을 사용한다. 이 공백은 실제 문법 관계이지 가상 카드가 아니며, 일반 gerund의 필수 목적어를 무제한 생략하는 규칙으로 확대하지 않는다.
- 새 `enjoy`, `finish`는 NP/동명사 목적어를 지원한다. `enjoy to read`를 to목적구로 우회해 정답 처리하지 않는다.
- want/need의 기본 to/목적어+to 용법을 보존한다. need는 실제 `need + ing`(~될 필요가 있다) 용법도 별도 Sense/Frame으로 인정하되 상세 의미 강의·수동태 콤보는 추가하지 않는다. 대표 예: `The book needs reading`. [G2][G5]
- 모든 동사에 gerund Frame을 무조건 부여하지 않는다. 이미 등록한 Sense와 소수 신규 동사의 결합만 검수해 추가한다.
- `Reading books`만 제출하면 문장의 유한 동사가 없으므로 0피해 실패 제출. 동명사구 자체를 완성 문장으로 취급하지 않는다.

### 5.3 기본 5형식

학교문법 표기 `S + V + O + C`를 사용한다. 다음이 핵심이다.

- want / need / 기존 like·help의 검수된 `O + to V`.
- 기존 make / keep / find의 이미 지원되는 `O + AP/NP`.
- 목적격보어가 목적어의 상태·정체·행동을 설명함을 표시한다. IO/DO 두 목적어로 잘못 분류하지 않는다.
- `I want to read books`는 SVO, `I want you to read books`는 SVOC.
- `She gives me a book`은 SVOO, `She makes me happy`는 SVOC, `She makes me a book`은 SVOO.
- 기존 기본 판정이 있는 사역·지각 bare 경로를 지우지 않는다. 이미 성립하는 5형식이라면 해금 후 **일반 5형식 배수**를 줄 수 있으나, 새 사역/지각 전용 콤보·동사 확장·수동 전환은 Stage7에 남긴다.
- 새 가넷 룬 등 전용 룬을 이번에 무단 추가하지 않는다. 일반5형식 배수는 룬의 소유와 무관한 문형 효과다.

### 5.4 복합·연결 사용

기존 시간 동사구, finite 절 연결, 상대절과 결합되어도 문장 전체를 소비하는 분석을 만든다.

- I wanted to read books. — 과거는 wanted의 바깥 절, 부정사는 to read.
- I have wanted to read books. — 완료 바깥 절 + 부정사.
- I want to have read the book. — 부정사 내부 완료. 그 자체로 과거 절을 만들지 않음.
- I enjoy being happy. — being은 동명사구의 동사. be+ing 진행으로 오인하지 않음.
- I enjoy reading books and playing games. — 동명사구 등위 연결, LINK.PHRASE 가능. 독립절 두 개로 오인하지 않음.
- I want to read books and play games. — shared to 아래 동사구 연결. 실제 to 카드 추가 생성 금지.
- I enjoy reading books because they are interesting. — finite 이유절 연결과 동명사 모두 실제로 분석.

비정형 안쪽의 완료/진행은 구조적으로 가능한 범위에서 재사용하되, **유한 절 시간 증거만 기존 TIME/골렘 조건에 기여**한다. `to have played`의 played나 `having played`만으로 과거 갑옷을 깨지 않는다. 그 안의 별도 유한 관계절에 실제 과거 동사가 있으면 기존 골렘 규칙대로 인정한다.

## 6. 데이터와 역할 증거

### 6.1 소수 신규 데이터

`enjoy`, `finish`, `hobby`가 최신 DB에 없으면 추가한다. 이미 있다면 재사용해 이중 ID를 만들지 않는다.

| 단어 | 품사/등급 제안 | 기본 뜻 | 형태/지원 |
|---|---|---|---|
| enjoy | VERB / COMMON | 즐기다 | enjoy, enjoys, enjoyed(과거/p.p.), enjoying; SVO NP/GERUND |
| finish | VERB / COMMON | 마치다 | finish, finishes, finished(과거/p.p.), finishing; SVO NP/GERUND |
| hobby | NOUN / COMMON | 취미 | hobby, hobbies; COUNT, 활동을 이름 붙이는 명사 Sense |

모두 새 원정 보상 풀에 들어가되 **기존 시작 덱 생성 후보에는 넣지 않는다.** 시작 어휘 모드별 역할·등급 비율과 28장 구성은 유지한다. 기존 to의 희귀도, want/need/like의 희귀도는 이번에 변경하지 않는다.

want, need, like, make, keep, find, help 및 이미 지원한 핵심 동사별로 관련 Frame 변경 전/후와 정상·오류 사례를 표로 남긴다. 모든 활성 동사를 다시 거대한 사전으로 작성할 필요는 없지만 **이번 gerund/infinitive 확장에 닿는 Frame은 검수**한다. [G2][G3]

### 6.2 권장 내부 증거

새 타입명은 실제 코드와 맞춰도 되지만 다음 구분이 사라지면 안 된다.

```text
Form.morphologicalForm = ING                 // 하나의 형태
NonfinitePhrase.formKind = TO_INFINITIVE | ING
NonfinitePhrase.function = SUBJECT | OBJECT | SUBJECT_COMPLEMENT
                         | PREPOSITION_OBJECT | NOUN_MODIFIER
                         | PURPOSE | ADJECTIVE_COMPLEMENT | OBJECT_COMPLEMENT
NonfinitePhrase.interpretation = GERUND | PARTICIPLE | INFINITIVE
NonfinitePhrase.headCardId / cardIds / parentNodeId / issueIds
NonfinitePhrase.controllerNodeId / gapRole / antecedentNodeId (필요할 때만)
Clause.objectNodeId / subjectComplementNodeId / objectComplementNodeId
```

필드가 없으면 저장 가능한 `null` 또는 생략을 스키마대로 일관되게 사용한다. `undefined`가 프로필 전체 저장을 실패시키는 이전 회귀를 되풀이하지 않는다.

- 새 `.ing`의 역할은 Form이나 영구 CardInstance에 써 두지 않는다. 그 제출의 분석 노드에만 둔다.
- 관계사/명사절/준동사구의 노드가 겹쳐 있어도 물리 카드 점수는 한 번만 센다.
- 역할 범위를 UI나 한국어 뜻으로 역추론하지 않는다. 도감·연출은 실제 Grammar 증거를 읽는다.
- 목적어·보어의 head와 전체 span을 둘 다 유지한다. “you = 목적어, to read books = 목적격보어”를 표시할 수 있어야 한다.
- `primaryScoringClauseId`는 동명사구 속 동사가 아니라 기준 주절을 가리킨다. `Reading books is good`에서는 is가 바깥 유한 동사다.
- `to`와 ing만 찾는 정규식/접미사 개수로 hit를 만들지 않는다. string fixture를 production 판정 lookup으로 사용하지 않는다.

## 7. 정오·오류·비지원 경계

| 상황 | 처리 |
|---|---|
| 정상 문장 | 실제 문형·역할 분석 후 허용된 점수 |
| 일치·관사 등 기존 작은 오류 | 기존 부분점수, 완전문장 보너스 없음 |
| to구에서 본동사 활용만 틀림 | 복구 가능한 같은 슬롯이면 `INFINITIVE_BASE_REQUIRED` 등 -10 한 원인. 해당 잘못된 to구 보너스는 제외 |
| gerund 주어와 be의 수 불일치 | 구조 유지, 일치 오류 -10. 주어구를 가짜 복수 명사로 바꾸지 않음 |
| enjoy가 요구하는 목적어 자체를 만들지 못함 | 핵심 실패 제출, 0피해·카드·턴 소비 |
| 필수 유한 동사 없는 구, 엉킨 어순 | 핵심 실패 제출, 0피해·카드·턴 소비 |
| 문법적으로 맞지만 아직 보너스 미해금 | 완전문장/기존 허용 효과로 자연스럽게 공격 |
| 코드 예외·잘못된 스키마·실행 한도 등 기술 실패 | 실제 상태·카드·턴·RNG 보존 후 복구. 학생 문법 실패로 위장하지 않음 |

정확한 실패 제출 안내:

> 문장을 완성하지 못하면 데미지를 줄 수 없습니다.  
> 주어와 동사의 위치를 다시 확인해 보세요.

`I want to reads books`는 읽다의 실제 명사/동사 카드와 선택형을 토대로 제한적으로 복구할 수 있지만, `I enjoy to read books`를 학생 몰래 reading으로 바꾸지는 않는다. 이번 지원 기준에서는 enjoy의 필수 명사적 목적어가 성립하지 않아 핵심 실패로 처리한다. 사전에는 **“enjoy 뒤에는 동명사(-ing)를 씁니다.”** 한 줄로 설명한다.

어떤 문장이 사전·실제 용법상 합법적인 다른 분석을 갖는다면 그 분석을 검토한다. **명세의 부정 예문이라고 해서 합법적인 분석을 일부러 제거하지 않는다.** 기술 한계를 정상 정답으로 바꾸는 fallback도 금지한다.

## 8. 해금과 점수 계산

### 8.1 해금 사건

0.5에서 Stage4 보스 승리를 확정하면 `STAGE4_CLEAR`를 한 번 기록하고, 사막의 세 효과 자격을 원정 자체 해금과 프로필에 반영한다. 보스 보상 생성 전 원정 해금이 적용되어야 한다.

권장 ID: `pack.infinitive`, `pack.gerund`, `pack.svoc.basic`. 기존에 같은 의미의 안정 ID가 있으면 그것을 재사용하고 매핑을 문서화한다.

- 이미 정규 Stage4 클리어 증거가 있는 프로필은 새 0.5 원정 시작 시 이 세 자격을 복원할 수 있다. 이름이나 최고 데미지로 클리어를 추정하지 않는다.
- 새 초회 원정은 Stage4 승리 전에도 정상 구조를 제출할 수 있다. 기본 판정은 열려 있지만 새 전용 배수만 잠겨 있다.
- 다른 저장 슬롯의 새 클리어가 현재 원정의 시작 해금 snapshot을 바꾸지 않는다. 현재 원정에서 실제로 이룬 해금만 추가한다.
- Stage5 완료는 `STAGE5_CLEAR`만. 전체 스토리 클리어/난이도/캐릭터 해금으로 대체하지 않는다.

### 8.2 연산 순서

```text
모든 WORD 카드 기본/연마 점수
→ 정확성 감점·기여 제외·0 하한
→ 완전한 문장 +30 (정확할 때만, 제출당 1회)
→ 기준 주절의 문형 배율 (5형식이면 ×2.5)
→ 기존 시간 배수 (기존 순서)
→ to부정사 ×1.4 (자격 있는 실제 hit가 있으면 1회)
→ 동명사 ×1.4 (자격 있는 실제 hit가 있으면 1회)
→ 기존 절 연결 ×1.6
→ 기존 구 연결 +10 / 형용사·부사·PP 수식 가산 (기존 상대 순서 보존)
→ 기존 룬 슬롯 순서
→ 지역 보너스 ×1.25 (Stage5 대상이 있으면 1회)
→ 기존 해당 보스의 피해 규칙
→ 최종 위력·실제 HP 감소·오버킬
```

유리수 `{num,den}`, **각 곱셈 직후 내림**, 안전 정수 검증을 유지한다. 배율 문구는 실제 operand에서 표시하고 5형식·to·동명사 숫자를 UI에 별도로 하드코딩하지 않는다.

- mainFrame 배수는 기준 주절에 한 번. 안쪽 read가 SVO라고 원래 want의 SVO 배수에 또 곱하지 않는다.
- 여러 to구/동명사구가 있어도 각 새 계열의 배수는 공격당 한 번. hit와 노드 자체는 도감/강조용으로 모두 남긴다.
- 하나의 ing 출현에 GERUND와 PROGRESSIVE/분사 역할을 겹쳐 지급하지 않는다. 서로 다른 물리 카드/구가 각 역할을 하면 해당 다른 효과는 함께 가능하다.
- 단순 분사 수식은 기본 형용사 수식 가산(+5) 수준으로 처리할 수 있으며 특별 분사 배수는 없다. 중복된 AP/분사 분석으로 +5를 두 번 주지 않는다.
- 모든5형식이 to부정사는 아니다. `I make you happy`에는 5형식만, `I want you to read`에는 5형식과 to 효과.
- 모든준동사구가 절 연결 콤보는 아니다. to·동명사구만 추가했다고 `LINK.CLAUSE`를 자동 생성하지 않는다. 실제 finite 연결은 기존 Stage4 규칙 유지.
- 운영 카드는 분석/문장 카드 수/운석/연마 점수의 대상이 아니다.
- `INVALID_CORE`는 새 배수/덧셈 룬으로 0이 되살아나지 않는다.

### 8.3 지역 적용

다섯 사막 전투 모두, 자격 있는 정상 to부정사/동명사 노드 또는 기준 주절의 기본5형식 중 하나가 사용되면 지역 ×1.25를 한 번 준다. 권장 문법별 배타 제한은 없다. 주절만이 아니라 지원하는 하위 구조의 실제 to/동명사도 지역 대상이 될 수 있다.

Stage5 보스에는 **추가 문법 면역이나 갑옷이 없다.** 봉인에 대응하면서 이전 지역 빌드로도 온전한 피해를 줄 수 있다. 지역 보너스를 못 받는 것과 피해를 반감하는 것은 다르다.

### 8.4 골렘·하늘섬 회귀

- `Reading books is good`는 현재 바깥 절이며 과거/미래 없음. gerund의 ing는 현재진행이 아니다.
- `I wanted to read books`는 과거 바깥 절이 있어 골렘 과거 부위를 공격 가능.
- `I want to have read books`는 바깥 일반현재. 비정형 read.p.p.는 골렘 과거 조건을 충족하지 않는다.
- `I will enjoy reading books`는 미래 바깥 절.
- `I want to read books`만으로 하늘섬 접속사 보호막을 깨지 않는다. to는 그 기믹의 finite 절 접속사가 아니다.
- 사막 보스는 어느 문법으로든 정상 피해. 봉인 때문에 자동으로 위력0/반감 결과를 만들지 않는다.

## 10. Stage5 입장·필수 재료·보상

진행 순서:

`Stage4 보스 실제 승리 → STAGE4_CLEAR/사막 효과 해금 → 기존 보스 보상 → STAGE_CLEAR → 사막 예고 → 부족한 입장 카드 한 번 지급 → 5-1`

### 10.1 최소 입장 지급

현재 실제 소유 WORD 목록을 본다. 사전에만 남은 제거 카드·운영 카드·가상 witness는 소유로 세지 않는다.

1. to가 없으면 to 1장.
2. want/need 중 하나도 없으면 want 1장. 둘 다 무료로 주지 않는다.
3. 기본 동명사 직접 목적어 경로를 제공하는 like/enjoy/finish 중 하나도 없으면 enjoy 1장. need의 특수 수동 의미 ing는 이 입문 보장의 대표로 삼지 않는다.

최대 3장. `entryGrants['stage.05']`에 사본ID·지급사유·적용 여부를 기록한다. 동일 화면/로드/다음 전투에서 다시 지급하지 않는다. 확정 보상이나 기존 RNG를 다시 뽑지 않는다. 보유 덱과 vocab 사전, 사본 목록을 원자적으로 갱신한다.

입장 때 **실제 파서 기반 최소 문장 경로**를 제한된 탐색으로 검사할 수 있지만, 이는 QA와 재료 확인용이지 편집 중 정답 추천 기능이 아니다. 경로가 없다고 임의의 완성 문장 카드 세트를 무한히 추가하지 않는다. 기존 사용자 제거 때문에 경로가 없어질 수 있음은 보고하되 일반 진행을 막지 않는다.

### 10.2 드로우·보상·상점

- 신규 단어는 새 원정의 보상/상점 후보에서 어휘 모드와 별개로 기존 희귀도 원칙을 따른다. 해금되지 않은 콤보라도 정상 언어 사용은 가능.
- Stage5 관련 후보는 to, want/need, like/enjoy/finish, 실제 검수된 SVOC 동사, 주어·목적어·보어 재료로 구성한다. OPERATION은 기존 지역 필수 슬롯을 대체하지 않는다.
- 일반/보스 보상 외부 가중치, 세칸 혼합·한선택·취소·skip재화, 운영 내부 확률·최대 한칸 정책은 0.4를 유지한다.
- 새 상점 없음. Stage4 상점의 상품·서비스·가격을 Stage5에서 다시 초기화/재방문하지 않는다.
- 특별한 스킬·보스 면역 파괴용 카드를 새로 추가하지 않는다. 보급·탐색·교환·현재 조합대 활용이 기존 대응수단이다.

## 11. 스핑크스 봉인 — 정확한 규칙

### 11.1 무엇을 봉인하는가

보스의 매 실제 행동 턴 시작에 **현재 손패의 WORD 카드 중 한 물리 사본**을 선택한다. 봉인은 그 사본을 이번 턴 조합대에 새로 넣지 못하게 하는 상태다.

- 이미 조합대에 놓인 카드, 드로우·버린 더미·EXHAUSTED는 신규 선택 후보가 아니다.
- OPERATION 카드 보급·탐색은 후보가 아니다. 원래 조합대에 못 올라가는 운영을 봉인하는 무의미한 추첨을 하지 않는다.
- 같은 단어 카드 두 장이 있으면 각각 별개 후보. 봉인된 `card.to` 사본 하나 때문에 다른 to 사본도 금지되지 않는다.
- 카드 뜻·형태·연마·점수를 바꾸지 않는다. 봉인 때문에 언어 자체를 오답으로 만들지 않는다.
- 조합대에 미리 놓아 다음 턴까지 유지한 카드는 봉인의 대상이 되지 않는다. 이는 정상적인 덱 운영 선택이다.

### 11.2 언제 추첨하는가

**첫 턴:** 실제 첫 손패 생성/운영 룬 반영 이후, 플레이어가 입력하기 전에 1회.

**다음 턴:** 직전 봉인 만료 → 기존 규칙으로 턴Index 갱신 및 3장 드로우(한도 적용) → 새 손패에서 새 대상 1회 → 편집 가능 상태.

공격과 준비 모두 턴을 소비하므로 다음 턴을 시작하면 봉인이 교체된다. 핵심 실패 0피해 제출도 같은 규칙이다.

반면 다음은 **턴 경계가 아니다**:

- 카드 클릭/드래그/회수/형태 선택/순서 조정
- 교환 사용 및 교환으로 새 카드를 받음
- 보급·탐색 사용/취소/종료
- 룬 재정렬, 덱/사전/도감 열기
- 같은 연출 재생·skip·watchdog·숨김 탭 복귀
- 저장 또는 불러오기

이런 행동에서 다시 뽑거나 봉인을 해제하지 않는다.

### 11.3 ‘다른 카드’를 고르는 규칙

후보 WORD가 2장 이상이면 **직전 턴 봉인된 물리 사본을 후보에서 제외**한 뒤 균등 추첨한다. 직전 사본이 새 손패에 없다면 그대로 전체 후보에서 뽑는다.

- WORD 1장뿐이면 그 사본이 다시 봉인될 수 있다. 이 사실을 ‘다른 대상’이라는 허위 안내로 숨기지 않는다.
- WORD 0장이면 이번 턴은 `sealedCardId=null`이며 RNG를 소비하지 않는다. 이후 운영으로 WORD를 뽑았다고 중간 봉인을 새로 만들지 않는다.
- 사본별 후보 순서는 기존 소유목록 등 결정론적 기준으로 고정한다. `localeCompare`/DOM 순서/랜덤 runId에 따라 바뀌는 순서를 시드 재현 기준으로 삼지 않는다.
- 후보가 있으면 기존 `pick(rng.encounter,candidates)` 방식으로 정확히 1회 난수를 소비한다(한 후보도 같은 규칙). 새 전역 RNG 알고리즘/스트림 배열은 변경하지 않는다.

### 11.4 봉인 카드도 교환할 수 있다

이 보스는 **배치 금지** 보스이지 교환 금지 보스가 아니다. 봉인 카드는 선택 체크·교환이 가능하다. 교환으로 손에서 없어지면 당장 손패에는 봉인 카드가 없어질 수 있다. **다른 손패 카드를 즉시 대체 봉인하지 않는다.**

단, 상태는 물리 사본 ID에 이번 턴 동안 유지된다. 같은 턴 재셔플/보급/탐색으로 그 사본이 손에 다시 들어오면 여전히 봉인이다. 이 때문에 봉인ID가 잠시 DISCARD/DRAW에 있을 수 있다. 검증 코드가 ‘봉인ID는 언제나 HAND여야 한다’고 강제하면 안 된다.

턴이 바뀌면 옛 봉인은 완전히 만료한다. 뒤늦게 과거 봉인 카드를 뽑아도 자동 재봉인하지 않는다.

## 12. 모든 배치 경로를 막고 나머지 조작은 보존

| 입력/명령 | 봉인된 손패 WORD에 대한 처리 |
|---|---|
| 본문 클릭·Enter/Space로 조합대 이동 | 차단, 자원·RNG·Undo 비변경 |
| 손패→조합대 드래그 삽입 | 차단, 원래 손패 위치로 되돌림 |
| 손패→조합대 카드 몸통 맞교환 | 차단, 양쪽 카드 유지 |
| 형태 메뉴의 맞교환·키보드 대체 이동 | 같은 공통 guard로 차단 |
| 여러장 자동 이동/추후 helper | 지금 존재하는 경로를 전수 확인해 동일 guard 적용 |
| 손패에서 버리기 체크·선택 해제 | 허용 |
| 선택 후 교환 | 허용. 기존 교환1회 소비 |
| 덱·사전 읽기 | 허용 |
| 이미 조합대의 다른 카드 편집·제출 | 허용 |
| 보급/탐색 사용·취소 | 기존 규칙 허용, 이번 턴 봉인 유지 |
| 룬 순서 변경 | 기존 상태 제한 안에서 허용, 봉인 재추첨 없음 |
| 편집 Undo | 카드 배치만 되돌림. 봉인·턴·RNG·거래를 되돌리지 않음 |

DOM만 막지 않는다. **Controller의 `ADD_CARD`, `SWAP_CARDS` 등 실제 배치 경로에서 검사**하고, 커밋 전 불변검사로 활성 봉인 카드가 조합대에 들어가지 못함을 확인한다.

UI에서 봉인 카드 전체에 `disabled`/`pointer-events:none`을 주어 버리기 체크나 사전까지 막지 않는다. 드래그/클릭 충돌과 모바일 터치 취소도 검사한다.

불법 배치 안내:

> 이번 턴에는 봉인된 카드를 조합대에 올릴 수 없습니다. 교환하거나 다른 카드로 문장을 만들어 보세요.

보스 상시 규칙:

> 매 턴 손패의 단어 카드 1장을 봉인합니다. 봉인된 카드는 이번 턴 조합대에 올릴 수 없지만, 교환할 수 있습니다.

카드 위 짧은 표식:

> 봉인 · 이번 턴 배치 불가

## 13. 봉인 상태·멱등성·UI 연출

### 13.1 권장 직렬화 상태

기존 bossMechanic 객체를 확장하는 작은 모델로 충분하다. 새 프레임워크나 범용 상태이상 엔진 전체를 만들지 않는다.

```text
bossMechanic = {
  id: 'TURN_HAND_SEAL',
  sealedCardId: string | null,
  sealedForTurnIndex: integer,
  previousSealedCardId: string | null,
  sealSequence: integer,
  lastAppliedTurnKey: '<battle-id>:<turn-index>',
  history: [
    {turnIndex, selectedCardId, candidateIds,
     encounterCursorBefore, encounterCursorAfter}
  ]
}
```

history는 최대 전투 턴 수 정도의 작은 증거다. UI 타이머/DOM/실행중 Promise를 저장하지 않는다. 봉인은 **별도 카드 더미가 아니며** activeCardIds의 소유를 바꾸지 않는다.

### 13.2 커밋

상태 복사본에서 드로우와 선택, invariants를 성공시킨 후 한 번 커밋한다. 동일 `lastAppliedTurnKey`를 다시 호출하면 무작위 선택 없이 기존 결과를 반환한다. 기술 실패 때는 드로우·봉인·RNG까지 한꺼번에 롤백한다.

- 일반 전투 `_beginBattle`에는 봉인 RNG 소비 없음.
- 적 처치/마지막 턴 패배로 전투가 끝나면 다음 턴 드로우나 봉인을 하지 않는다.
- 마지막 공격으로 적이 죽으면 승리가 턴소진 패배보다 우선한다.
- 스핑크스전 종료 후 다른 전투·로비·새 원정에 봉인 외형이나 상태를 누출하지 않는다.
- 공격·운영 연출이 끝났다고 자체적으로 seal state를 다시 계산하지 않는다. 확정된 턴 시작 결과만 표시한다.

### 13.3 연출

턴 시작에 스핑크스의 문양이 잠깐 빛나고, 선택된 카드에 얇은 금빛/보랏빛 봉인 문양·가벼운 사슬/금지 아이콘을 표시한다. 단어·형태·점수·체크는 읽을 수 있어야 한다. 활성 대상이 손에 없으면 보스 표시에서 그 단어가 이번 턴 봉인 대상이었다는 사실만 보여주고 새로 막지 않는다.

기본은 짧은 250~450ms 정도의 nonblocking 표시값으로 시작하되, 상태를 커밋하기 전에 학생이 클릭할 수 있는 틈을 두지 않는다. 애니메이션은 게임 상태 결정이 아니다. 모션 감소에서는 페이드/아이콘만, 숨김 탭에서는 장시간 대기시키지 않는다. 기존 느린 점수 읽기와 강한 타격감은 그대로 둔다.

새 대규모 캐릭터 이미지·BGM은 이번 납품의 전제 조건이 아니다. 현재 자산 슬롯과 fallback만으로 봉인을 확실히 구분할 수 있어야 한다.

## 14. 저장·레거시 호환

0.5 새 원정에서만 새 언어/점수/Stage5/봉인이 동작한다. **0.4 이하 원정을 자동으로 새 덱이나 22전투로 개조하지 않는다.**

- `registryForVersion`, score/rune/catalog/stages/operations selectors에 새0.5 경로를 추가한다. 레거시0.4 view의 Form·단어·Frame·카드순서/확률은 변경하지 않는다.
- 새0.5의 시작 생성기는 실제 변경이 없으면 검증된0.4 generator 규칙/버전을 재사용할 수 있다. 게임버전과 generator 버전을 혼동하지 않는다.
- 기존 `.ing` ID는 유지하며 레거시 저장의 form selection을 강제 변경하지 않는다. 새 UI의 역할 중립적인 -ing 문구는 표시상 개선으로 적용할 수 있지만 당시 분석/점수 이력을 소급 수정하지 않는다.
- Stage5 입장 지급 후 안정된 `BETWEEN_BATTLES`/`STAGE_INTRO` 등 실제 앱이 지원하는 안전 지점에서만 저장한다. 저장 지점을 무작정 늘리지 않는다.
- 스핑크스 첫손패/첫봉인 후 안전 저장은 봉인 대상·rng.encounter·turnKey를 함께 보존한다. 복원 때 재추첨하지 않는다.
- 기존 0.4가 허용하는 안정된 중간 상태 저장이 있다면 같은 정책에서 봉인/운영 history까지 직렬화한다. 허용하지 않는 중전투 저장을 이번에 새로 추가할 필요는 없다. serializer roundtrip 단위검사와 실제 UI 저장 검사를 구분한다.
- 종료 상태에 뒤늦은 FINISH/드래그/운영 콜백이 도착해도 피해·드로우·새봉인·보상을 실행하지 않는다.
- IndexedDB 이름, 프로필ID/닉네임 분리, 3개 수동 슬롯, transaction 완료 확인, 공개 보상·상품 고정, 제거 이력과 운석/룬 슬롯 기록을 유지한다.
- 작은 한국어 교육 표시 외에는 구버전의 card/baseHP/score/RNG/unlock/content boundary를 소급하지 않는다.

### 저장 검증의 핵심

봉인 state가 있으면 실제 스핑크스전인지, turnKey/turnIndex가 일치하는지, 선택사본이 원정 소유 WORD인지, 후보 이력에 있었는지 확인한다. OPERATION ID·알 수 없는 ID·미래 턴·중복 적용·봉인사본의 조합대 진입은 거절한다.

봉인 사본이 교환되어 DISCARD/DRAW에 있는 **정상 상태**는 거절하지 않는다. 다음 전투에서는 bossMechanic이 없는 일반 상태가 정상이다.

## 15. 사전·문장 도감·교육 피드백

- 단어 뜻은 나의 덱 사전에만. 문장 도감에 전체 번역·단어 번역을 되살리지 않는다.
- -ing 설명: **“-ing형은 문장 속 쓰임에 따라 동명사·분사로 사용되고, be와 결합해 진행형을 만들 수 있습니다.”**
- to부정사 설명: **“to와 동사 원형으로 행동을 문장의 재료로 쓰거나 다른 말을 설명합니다.”** 세부 역할을 원할 때 한 줄로 표시한다.
- 동명사 설명: **“-ing형으로 된 구가 주어·목적어·보어 등 명사 역할을 합니다.”**
- 5형식 설명: **“목적격보어가 목적어의 상태·정체·행동을 설명합니다.”**
- enjoy 안내: **“enjoy 뒤에는 동명사(-ing)를 씁니다.”**
- need 특수 ing Sense: **“need + -ing는 '~될 필요가 있다'의 뜻으로도 씁니다.”** 기본 의미 구별은 한 줄이면 충분하다.
- `to부정사=항상 미래`, `동명사=항상 과거`, `ing=언제나 진행`, `be 뒤는 언제나 2형식`, `to 뒤는 항상 동사` 같은 오개념을 넣지 않는다.
- 사용자가 만든 첫/최고 완성문장을 밝은 흰색·볼드로, 오류 피드백을 연한 적색으로 구분한 현재 UX 유지.
- 고정 학습 예문 펼침 영역은 계속 숨긴다. 검수용 examples 데이터는 내부/테스트용으로 유지 가능하다.
- 실제 효과는 scoreableHitIds, 문법 증거는 원본 analysis에 근거해 기록한다. 미해금 구조를 다른 문형으로 바꾸거나 실패 문장을 완전문장 모범으로 저장하지 않는다.
- 교육문구 검토표를 납품하되 실제 교사 검수가 없으면 ‘교사 검수 완료’라고 표시하지 않는다.

## 18. 검증 계획 — 증거 수준을 나눈다

### 18.1 필수 명령과 효율

실제 package의 스크립트를 확인한다. 작성 기준의 `npm test`, `npm run validate:data`, `npm run build`, `npm run test:browser`, `npm run test:e2e`, `test:decks:sky`, `test:runs:sky`가 존재한다. Windows에서는 같은 의미의 `npm.cmd`를 사용할 수 있다.

- 개발 중 관련 node test 파일과 새 grammar/seal 검사를 반복한다.
- 최종에는 `npm test`·data validation·build, 기존 공식browser 전체+새desert browser를 실행한다.
- generator를 바꾸지 않았더라도 새 언어/소유카드 통합이 첫패에 영향을 줄 수 있으므로 최종 한 번 4모드×2,500=10,000 새덱/첫패 검사를 수행한다. 매 작은수정마다 반복하지 않는다.
- 자동 원정은 기존 command-policy를 확장해 4모드 합계80개 고정seed를 실행하고, 도달지역·성공·정상패배·기술실패·준비/교환/봉인 대응을 기록한다. 인간 승률로 부르지 않는다. 0.4 원본 정책의 재실행 여부와 이번 새정책을 구분한다.
- 최소 한 번, 로드된 production build를 실제 UI로 22전투 완주한다. 전체 신규공격/보상/두상점/골렘/문지기/스핑크스/완료사건을 기록한다. HP·카드 주입, 보유하지 않은 패 생성, 드로우 순서 선독, 무료 연마를 사용하지 않는다.
- 자연 획득 운영 사용이 해당 완주에서 없으면 솔직히 0회로 보고하고, 지정 상태의 실제 UI 운영+봉인 검사를 별도 근거로 제출한다.
- 출시 UI 보안/debug차단, 외부 런타임 API0, 로드 뒤 네트워크차단 계속플레이도 점검한다. 이것을 PWA 새로드 지원이라고 표현하지 않는다.

### 18.2 화면과 입력

1024×768 / 1280×800 / 1366×768, 손패10/14, 조합대16, 룬4, 긴한국어 안내·긴단어에서도 핵심 버튼/봉인/체크가 겹치거나 가려지지 않는지 검사한다. 최소 Chromium mouse/keyboard/touch emulation은 실행하고 실제 기기와 구분한다. 실제 iPad/Android·다른브라우저·스피커 검사를 못 했으면 NOT RUN.

### 18.3 숫자와 구조의 검증

첨부 Grammar fixture는 기대 영어/role/status, Score fixture는 독립적 수학 기대값이다. 모두 production 분석·정산 경로에 연결해서 검사해야 한다. fixture문장을 lookup으로 반환하는 방식, parser를 건너뛰고 가짜 hit를 넣은 것을 언어검증으로 보고하는 방식은 금지다.

봉인 fixture의 지정상태·난수값은 계약검사용이며 자연드로우 완주가 아니다. 경계검사를 위해 deterministic state를 만들 수 있으나 이를 사람 플레이 접근성 증거로 보고하지 않는다.

- -ing 동일 Form ID로 동명사/진행/분사/보어 모두 테스트.
- 새 문장의 실제 모든 카드가 등장했는지, 내부목적어/보어 범위가 맞는지 검사.
- 깨진문장 하나 뒤 정상문장·원정완료를 이어 개인기록 저장되는지 확인.
- 기술오류 주입 후 카드를 소모하지 않았는지 검사.
- 초원 실습40/126와 기존0.4 golden을 그대로 비교. 기대를 새로 생성해 맞추지 않는다.
