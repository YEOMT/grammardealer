## 0. 작업 기준과 범위

### 0.1 현재 작업 위에 추가한다

최신 `main`과 현재 작업 브랜치·미커밋 변경을 먼저 비교한다. v0.15.0 이후 변경이 있다면 보존한다. 과거 ZIP, 배포 번들, 오래된 main으로 현재 구현을 덮어쓰지 않는다. 먼저 `AGENTS.md`, `README.md`, `docs/PROJECT_HANDOFF.md`, `docs/ARCHITECTURE.md` 및 해당 UI 테스트를 읽는다. Vanilla JS + ES Modules + Vite 구조를 유지한다.

이번에 구현할 것은 다음 다섯 작업이다.

1. **중복 `내 덱` 메뉴 제거 및 `사전` 정돈:** 조합대 왼쪽을 포함한 일반 메뉴의 `내 덱` 진입은 삭제하고 기존 `사전`만 남긴다. `카드`라는 새 통합 버튼이나 `내 덱 / 사전` 탭은 만들지 않는다. 사전의 영어·뜻 정렬, 품사색, 검색, 활용형 표시를 개선한다. 기존 하단 `뽑을 카드`·`버린 카드` 검사 기능은 유지한다.
2. **보스 뒤 상점의 장소 일치:** 상점 이름·팔레트·기존 배경·음악은 떠나는 지역, 상품·해금·구매 정책은 다음 지역 준비용 그대로 둔다.
3. **지역 첫 전투 준비 화면:** 일반 원정의 지역 입장 후 첫 전투도 기존 파노라마 준비 화면으로 안내한다. 실제 첫 조작 튜토리얼은 중복 안내를 건너뛴다.
4. **목표 문법 팝업의 정보 위계:** 제목·형태·예문을 먼저 읽히게 하고, 조건·예외·공략을 구분한다.
5. **설정 전용 컴팩트 팝업:** 용도에 맞는 폭과 소리/화면·연출 그룹, 가까운 라벨·조절부, 접근 가능한 토글을 구성한다.

이는 현재 전투 UI를 다시 디자인하는 작업이 아니다. 팝업 세 종류와 상점 장소 표현, 첫 전투로 진입하는 표시 흐름을 좁게 수정한다.

### 0.2 확정 방향과 구현 기본값의 구분

## 2. 공통 팝업 규격 — 한 가지 거대한 창을 공유하지 않는다

### 2.1 용도별 폭

| 팝업 프로필 | 충분히 넓은 PC에서의 시작값 | 레이아웃 |
|---|---:|---|
| `settings` | 560px, 조정 범위 520~600px | 한 열의 설정 행, 두 내용 그룹 |
| `grammar` | 720px, 조정 범위 640~800px | 읽기 중심 한 열. 긴 구조는 내용 단위로 줄바꿈 |
| `dictionary` | 1080px, 조정 범위 960~1160px | 사전 단일 보기, 단어 뜻·형태 목록 2열 |

모든 폭은 실제 가시 너비와 안전 여백을 상한으로 삼는다. PC 폭을 모바일에 강제로 유지하지 않는다. `dialog`의 목적 클래스/속성 또는 선택적 size 프로필을 사용하며, **기존 모든 `.app-dialog`의 width를 일괄 변경하지 않는다.** 기존 확인창·저장·기록·보상·형태 선택창에는 뜻하지 않은 크기 변경이 없어야 한다.

### 2.2 높이·스크롤·초점

- 기존 가시 영역 계측과 안전 영역 계산을 재사용한다. `100vh`만 기준으로 주소창 뒤를 덮거나 safe area를 두 번 차감하지 않는다.
- 높이는 내용에 맞추며 사용 가능한 높이 안에서만 제한한다. `height:100%`와 `space-between`으로 빈 공간을 채우지 않는다.
- 제목/닫기와 필요한 검색 도구는 접근 가능한 위치에 둔다. 본문/목록 하나가 세로 스크롤을 소유하게 하고 불필요한 중첩 스크롤은 피한다.
- PC에서 화면이 충분한데도 설정 기본 상태에 스크롤바가 생기면 고정 최소 높이·행 간격부터 점검한다. 모바일 짧은 화면의 정상 내부 스크롤은 허용한다.
- 닫기·Escape·Tab·포커스 복귀를 유지한다. 모달 내 버튼이 뒤 전투 카드에 입력을 전달하지 않게 한다.
- 전체화면/설치형/주소창 높이 변화 중에도 현재 모달이 실제 가시 사각형 안에 남는다. 기존 top-layer 동작을 임의로 body 확대/transform으로 대체하지 않는다.
- 문구가 짧아져도 실제 클릭·터치 대상은 충분히 유지한다. 글자를 극단적으로 축소하여 항목을 모두 한 화면에 넣지 않는다.

### 2.3 공통 시각 기준

기존 녹색 배경·상아색 본문·절제된 금빛 강조·폰트·모서리 체계를 유지한다. 제목/본문/보조 정보의 크기·굵기·대비를 구분한다. 모든 글자를 금색/굵게 만들지 않는다. 반대로 핵심 내용인 뜻·형태를 `small`과 저대비 회색으로 밀어내지 않는다. 색 이외에도 제목·라벨·배치로 내용을 식별할 수 있어야 한다.

## 3. `내 덱` 메뉴 삭제 · `사전` 단일 진입

### 3.1 합의한 최종 UX — `사전` 하나만 남긴다

이번 R2가 원래 R1의 **`카드` 통합창, `내 덱/사전` 탭, `내 덱` 기본 탭, 보유 카드 관리 모드 화면** 제안을 **명시적으로 취소한다.** 아래처럼 두 가지를 동시에 지킨다.

```text
전투 조합대 왼쪽: [사전]    (기존 [내 덱] 버튼 삭제)
전투 하단 카드 묶음: [뽑을 카드]                  [버린 카드]

사전                                         닫기 ×
[영단어 또는 뜻 찾기 …………………………]          42개
[단어/뜻 목록 · 기존 품사색]
```

- 전투의 조합대 왼쪽 상태 패널/컴팩트 메뉴에서 **`내 덱` 버튼을 삭제**하고, **기존 `사전`을 유지**한다. 제거된 버튼 공간은 다른 옵션의 간격을 정돈하는 데만 사용한다. 새로운 큰 버튼으로 빈칸을 채우지 않는다.
- 상점·보상·지역 입장·전투 준비·모바일 메뉴 등에서 기존에 일반 진입으로 노출된 **`내 덱` 버튼도 삭제**한다. **새 `카드` 통합 버튼을 만들지 않고**, 단어 참고가 필요하면 명칭은 `사전`으로 통일해 기존의 사전 접근성을 유지한다.
- **`카드`라는 통합 메뉴·새 팝업·`내 덱/사전` 전환 탭은 금지**한다. 사용자가 `사전`을 누르면 곧장 기존 사전의 단일 화면을 열어야 한다. 기존 모달 창 크기는 2열 사전을 읽기 좋은 너비로 정돈한다.
- `openDeck(state, 'all')`, `openDictionary(..., {mode:'management'})` 등 기존 중복 연결은 호출자를 확인해 UI에서 제거한다. 다른 역사적 경로 때문에 함수 자체를 남겨야 한다면 **일반 사전으로 안전하게 연결**하되, 사용자에게 `내 덱` 탭·관리 모드를 노출하지 않는다.
- 메뉴 삭제는 **실제 카드 삭제를 의미하지 않는다.** `activeCardIds`, 소유 카드 인스턴스, 연마, 룬, 운영 카드, 카드 위치·드로우·정산·저장 데이터는 그대로 유지한다. 사용자 화면의 불필요한 입구만 줄이는 작업이다.
- 사전 열기·검색·닫기는 표시 전용이다. 게임 command·턴·골드·RNG·해금·점수·학습 이력을 바꾸지 않는다. 프로필/원정 변경 후 이전 원정의 단어가 섞이지 않게 한다.

### 3.2 사전 본문 — 사전답게

- **이번 원정에서 실제로 만난 단어**를 보여주는 기존 범위를 유지한다. 카드 제거 후에도 이미 만난 단어는 남긴다. 새 원정을 시작하지 않았을 때에는 짧은 빈 상태를 표시한다.
- 영어 표제어·한글 뜻·실제 품사색·작은 품사명·필요한 활용형·지원되는 용법이 핵심이다. **보유 n장, 현재 보유하지 않음, 희귀도, 연마 수준/분포, 카드 점수·연마 계산은 표시하지 않는다.**
- 기존 `보유 카드 / 이번 원정에서 만난 단어` 드롭다운도 제거한다. 사전은 **만난 단어 목록**이라는 한 가지 범위만 사용한다. 새 탭 또는 ‘내 덱’ 보기의 우회 필터를 만들지 않는다.
- 검색창을 가장 편하게 찾을 수 있게 두고, 검색 전 `42개`, 검색 중 `검색 결과 3개`처럼 짧게 표시한다. 사전의 고유 표제어 수와 물리적 카드 수를 혼동하지 않는다.
- “이번 원정에서 소개·획득하거나…” 같은 긴 상시 안내는 없애고 필요하면 작은 도움말에서 확인하게 한다.
- 겸용 단어·활용형·검색 정확도 및 품사색의 추가 기준은 4절을 따른다. 내 덱용 카드 관리 정보를 다른 곳의 사전에 재삽입하지 않는다.

### 3.3 하단의 기존 카드 묶음은 그대로

- 왼쪽 아래 **`뽑을 카드`**, 오른쪽 아래 **`버린 카드`**의 숫자·터치·내용 확인 기능을 유지한다. 기존 `사용 완료` 등 특수 카드 목록 역시 실제로 제공되는 경로를 보존한다.
- `뽑을 카드`는 **현재 뽑기 묶음의 카드 목록**이다. 손패·조합대·버린 카드까지 합친 전체 보유 목록인 것처럼 설명하거나 데이터를 확장하지 않는다. 학생은 손패/조합대에 놓인 카드를 직접 보고, 뽑을/버린 묶음은 해당 버튼으로 본다.
- 뽑기 순서 비공개, 버린 카드 목록 정렬, 되돌리기/셔플/카드 보존·불러오기 동작을 그대로 유지한다.
- `내 덱`을 없앴다는 이유로 기존 하단 버튼을 새로운 덱 관리 UI나 상세 사전 탭으로 바꾸지 않는다.

## 4. 사전 항목 가독성

### 4.1 영어와 뜻을 같은 첫 줄에

현재처럼 `영어 + 작은 품사`의 두 줄짜리 묶음을 뜻과 가운데 정렬하지 않는다.

```text
[품사색] change       변하다·바꾸다
          동사

과거  changed     -ing  changing     p.p.  changed
```

이 예는 정렬을 보여주는 도식이다. 실제 겸용 단어는 아래 4.3의 전체 용법을 표시한다.

- 첫 행: 영어 표제어 + 한글 뜻. 두 텍스트 자체를 같은 첫 줄/기준선에 맞춘다.
- 다음 행: 품사 이름. 영어 아래에 작게 배치한다. 뜻의 세로 위치 계산에 품사 행을 포함하지 않는다.
- 충분한 폭에서는 항목 내 영어 열을 일관된 범위로 두고 뜻의 시작선을 정돈한다. 출발점 약 112~168px이되 실제 긴 영어도 읽을 수 있도록 조정한다. 영어와 뜻을 박스 양끝으로 벌리지 않는다.
- 단어가 길거나 항목 폭이 좁으면 헤더를 순서대로 쌓는 반응형을 허용한다. 영어를 글자 단위로 쪼개거나 한글 뜻을 가로로 압축하지 않는다.
- 영어는 현재 폰트로 우선 강조하고 뜻은 거의 동등한 정보로, 품사는 그 아래 보조로 둔다. 시작값: 영어 22~24px, 뜻 19~22px, 품사 12~13px, 활용형/용법 14~16px. 가용 화면에 따라 작은 조정은 허용하지만 지금처럼 본문을 극소형으로 몰아넣지 않는다.

### 4.2 품사색 복원

- 영어 바로 옆에 작은 품사색 표식(얇은 세로선 또는 작은 색칩)을 두고, 품사명에도 같은 팔레트를 적용한다.
- 실제 단어 카드가 사용하는 **같은 품사색 토큰/클래스**를 참조한다. 사전 전용 별도 색상표를 복제하지 않는다.
- 명사 파랑, 대명사 진한 파랑 등 기존 구별을 유지한다. 한글 뜻은 밝은 본문색으로 둔다.
- 색 면적은 작게 유지한다. 항목 전체를 색으로 채우거나, 모든 카드 테두리를 화려하게 빛내지 않는다.
- 색만으로 식별하지 않고 품사 글자도 남긴다.

### 4.3 겸용 단어

`change`, `work`, `plan`, `help`, `answer`, `watch`, `show` 등은 **현재 원정의 registry가 실제 지원하는 품사·뜻만** 가져온다. 두 품사의 의미가 있다면 한쪽을 숨기지 않는다.

- 대표 표제어는 한 번 표시한다. 뜻을 `동사 … / 명사 …`처럼 연결하거나 같은 헤더 아래 두 의미 줄로 나눈다.
- 작은 품사색 표시도 해당 용법과 연결되어야 한다. 지원하지 않는 새 뜻/품사를 외부 사전에서 추가하지 않는다.
- 검색은 지원되는 보조 뜻도 찾을 수 있어야 한다.
- 표면형 중복은 정돈하되 **문법 역할이 다른 동일 철자**는 구별한다. 예: `changed`의 과거/과거분사 구별을 지우지 않는다.

### 4.4 활용형과 용법의 정보량

- 제목과 똑같은 단일 기본형을 반복하는 `at (기본형)`, `clearly (기본형)` 행은 생략한다.
- `a (a) · an (an)`은 `a · an`처럼 중복 라벨을 제거한다.
- be는 `원형 be`, `현재 am · is · are`, `과거 was · were`, `-ing being · p.p. been`처럼 묶는다. 필요하다면 실제 사용에 도움이 되는 주어 구별을 짧게 유지한다.
- 일반 동사는 실제 제공 형태에 따라 현재/3인칭·과거·분사를 짧게 묶는다. `p.p.`만 다음 줄에 혼자 남지 않도록 형태+라벨을 한 단위로 감싼다.
- 명사 단복수, 대명사 격, 불규칙 형태 등 실제 선택에 필요한 정보는 생략하지 않는다.
- 기본 활용형은 바로 볼 수 있게 둔다. 그것을 보기 위해 매번 새 팝업을 열게 만들지 않는다.
- 긴 예외·여러 줄 주의사항은 항목의 `용법` 접기 영역으로 옮길 수 있다. 검증된 짧은 용법 한 줄은 그대로 노출해도 된다.
- `0.1에서는 제공하지 않음`, 지원 엔진/정산 방식 등 개발용 표현은 학생 화면에서 제거한다. 현재 원정에서 정말 제공되지 않는 형태라면 필요할 때 정확한 짧은 안내를 사용한다.
- 예문/뜻의 전면 재작성은 하지 않는다. 기존 승인 자료와 버전별 문법 범위를 유지한다.

### 4.5 항목 높이·검색 영역

- 넓은 화면의 사전은 2열을 기본으로 한다. 좁으면 1열로 전환한다. 영어순, 왼쪽→오른쪽→다음 줄의 순서를 유지하고 masonry 형태는 만들지 않는다.
- 카드형 항목에 불필요한 큰 고정 높이를 두지 않는다. 같은 행 높이가 맞는 것은 허용하되 아래쪽 공백이 과도한 최소 높이를 없앤다.
- 항목 안쪽 14~18px, 항목 간 12~16px 정도에서 시작한다. 제목/품사는 가깝게, 활용형은 8~12px 정도 떨어뜨린다.
- 폭이 충분하면 **검색창·단어 수**가 한 개의 얇은 도구 행 안에 들어간다. 탭·보유 필터는 두지 않는다. 검색 도구가 단어 목록을 화면 절반 아래로 밀어내면 안 된다.
- 모바일 키보드가 올라오면 기존 가시 영역 처리로 검색 입력·닫기·결과 일부가 접근 가능해야 한다. 입력칸을 작게 만들어 자동 확대 문제를 재발시키지 않는다.

## 5. 상점의 지역 소속 바로잡기

### 5.1 장소와 상품 정책을 분리

보스 뒤 상점에서는 **방금 떠나는 지역**이 상점의 장소이다. `shop.stageId`는 다음 지역의 공급/상품을 위해 사용될 수 있으므로, 이를 표시를 위해 덮어쓰지 않는다.

| 상품/준비 대상 ID | 보스 뒤 상점의 표시 지역 ID | 제목 예시 |
|---|---|---|
| `stage.02` | `stage.01` | 시작의 초원 · 상점 |
| `stage.04` | `stage.03` | 시간의 협곡 · 상점 |
| `stage.06` | `stage.05` | 소원의 사막 · 상점 |
| `stage.08` | `stage.07` | 해당 원정의 7지역 이름 · 상점 |
| `stage.10` | `stage.09` | 해당 원정의 9지역 이름 · 상점 |
| `stage.final` | `stage.10` | 별의 회랑 · 상점 |

지역 이름은 `stageDisplayName`과 원정 버전별 데이터로 얻는다. 과거 기억에 있는 별칭을 임의로 넣지 않는다. 마지막 상점에도 `통사의 근원 · 상점`으로 앞서 도착한 것처럼 표시하지 않는다.

### 5.2 일관된 표시 컨텍스트

표시 전용 `resolvePresentationRegion` 또는 동등한 함수로 제목·테마·배경이 같은 지역을 참조하도록 한다.

- `usesPostBossShop(run)`인 `SHOP`, 그리고 해당 상점 전에 발생하는 4·8지역 입장 선택 준비 화면은 이전 지역 컨텍스트를 사용한다.
- 위 표의 매핑을 사용한다. `stage.final`을 숫자에서 1 빼는 방식으로 처리하지 않는다.
- 예전 지역-시작 상점 정책의 구저장은 **그 당시 위치**를 유지한다. 모든 `SHOP`에 무조건 이전 지역을 적용하지 않는다.
- 저장한 상점/선택 준비를 바로 로드해도 동일하게 도출되어야 한다. “마지막으로 틀었던 곡/봤던 화면”이라는 메모리에 의존하지 않는다.
- `progress.stageId`, `shop.stageId`, `shopId`, `entryGrantId`, `shopHistory`, 상품/가격/구매 상태/서비스 횟수를 바꾸지 않는다.

### 5.3 테마·배경·음악

이전 지역의 팔레트와 현재 사용 중인 상점 배경/장식 계층을 일치시킨다. 배경 이미지가 없다면 그 지역의 팔레트를 사용하며 새 이미지를 임의 생성하지 않는다. 큰 전투 배경을 새로 깔아 상품 가독성을 해치거나 상점 전체 배치를 바꾸지 않는다.

기존 `resolveMusicContext`는 보스 뒤 상점에서 이미 이전 지역을 반환한다. 이를 유지하거나 동일한 표시 resolver를 재사용하되, 오디오 엔진과 전환 시퀀스는 건드리지 않는다. 상점 내부의 상세 열기/구매로 음악이 재시작되면 안 된다. **새 지역 입장 화면을 실제로 열 때** 새 지역 컨텍스트로 바뀐다.

### 5.4 다음 지역 준비 정보와 4·8지역 선택

- 상품/추천 재료/해금과 공략은 다음 지역용 그대로 유지한다. 다음 지역을 위한 공략은 `다음 지역 준비`처럼 장소와 헷갈리지 않게 작은 접기 제목으로 구분한다.
- `시작의 초원 · 상점`에서 항구 수문장 준비 안내가 나오는 것은 정상이다. 이를 이미 초원의 현재 보스 공략처럼 표시하지 않는다.
- 4·8지역의 필수/선택 입장 카드 UI를 삭제·자동 선택하지 않는다. 기존 보상·지급·NONE 확인·상점 생성 순서를 유지한다.
- 선택 화면의 장소는 떠나는 지역, 선택 대상은 다음 지역으로 명확히 한다. 선택 후 상점, 상점 종료 후 새 지역 입장이라는 현재 정책을 보존한다.
- 나가기 버튼·확인과 복귀 가능 여부는 기존 계약을 유지한다. 이 작업을 이용해 상점 수를 늘리거나 상품을 다시 굴리지 않는다.

## 6. 지역 첫 전투 준비 화면

### 6.1 정상 흐름

현행 보스 뒤 상점 정책의 일반 원정에서 다음 순서로 보인다.

```text
(필요한 경우 이전 지역 상점)
→ 새 지역 입장: 배경과 지역 소개
→ 첫 전투 준비: 파노라마·몬스터·이번 목표
→ 전투 시작
```

- 1~10지역의 첫 전투와 최종 지역 첫 페이즈(서피스 스트럭처)에 적용한다.
- 실제 첫 조작 튜토리얼 세션은 중복 준비를 건너뛰고 기존 행동 기반 안내를 시작한다. **튜토리얼을 하지 않는 일반 1-1은 준비 화면을 보여준다.**
- 49·50전투와 같은 기존 전투 사이 준비 화면은 그대로 사용하며 준비를 두 번 겹치지 않는다.
- 최초 준비의 주 버튼은 `전투 시작`. 기존 전투 사이의 `다음 전투`, `저장`, 필요시 `사전`은 해당 문맥을 유지한다. `내 덱` 또는 새 `카드` 버튼을 다시 만들지 않는다.
- 지역 입장 화면에 문법/몬스터 정보를 다시 얹어 풍경을 가리지 않는다.

### 6.2 공통 준비 렌더러와 정확한 대상

기존 파노라마 준비 렌더러가 `roundIndex + 1`만 가정한다면, 표시할 encounter를 명시적으로 전달받도록 작은 공통화를 한다.

| 진입 종류 | 표시 대상 | 확인 뒤 실행 |
|---|---|---|
| 첫 전투 준비 | 현재 지역의 `roundIndex = 0`에 해당하는 실제 encounter | 그 원정 상태에서 기존에 전투를 시작하던 명령 1회 |
| 전투 사이 준비 | 기존 다음 encounter 계산 | 기존 `NEXT_BATTLE` 1회 |
| 활성 전투 저장 복구 | 저장된 전투 그대로 | 전투 초기화/새 준비 생성 없음 |

준비 화면도 실제 표시 이름/영문명/보스 여부/목표 문법/지역 점수 보너스를 공통 자료에서 읽는다. 시작 시에 정해지는 랜덤 과제·봉인·덱 순서를 미리 생성하거나 공개하지 않고, 아직 확정되지 않은 기믹은 승인된 정적 개요만 안내한다. 보스 표식은 기존 붉은 `BOSS`, 뜻 없는 행 생략, 전체 전투 수 숨김을 유지한다. 파노라마 비율과 몬스터 안전 크기, 지연 이미지 처리는 기존 구현을 재사용한다.

### 6.3 부작용 없는 UI 게이트를 우선

이 패치에서는 **기존 전투 시작 명령을 호출하기 전에 표시하는 UI 하위 화면**을 우선한다.

- 지역 입장 버튼은 실제 시작 준비가 끝난 경우에만 첫 전투 미리보기로 이동한다. 이때 Controller 상태·revision·RNG·카드·골드는 그대로다.
- 첫 준비의 `전투 시작`에서 기존 `START_BATTLE`/`ENTER_STAGE` 등 실제 상태에 맞는 기존 명령을 한 번만 실행한다.
- `ENTER_STAGE`는 상황에 따라 상점/선택 준비로 갈 수도 있다. 명령 이름만 보고 항상 전투 시작으로 가정하지 않는다. 현행 준비된 상점 이후 입장과 상점 없는 3·5·7·9지역을 구분한다.
- 입장 선택이 남았거나 상점이 아직 안 끝났으면 먼저 기존 선택/상점 흐름을 끝낸다. 준비 화면으로 우회하지 않는다.
- 미리보기에서 `_beginBattle`, `drawCards`, `createShop`, 지급 함수, Controller의 복제본 dispatch를 호출해 장면을 만들지 않는다.
- 첫 전투 수동 준비를 위해 `RunState`에 새 전투 상태를 무조건 추가하거나 저장 스키마를 올리지 않는다. UI 게이트로 처리할 수 없는 구경로가 있다면 기존 계약을 유지하고 좁은 변경과 사유를 보고한다.

### 6.4 뒤로가기·재렌더·저장·중복 입력

- 준비 하위 화면의 식별자는 최소 `runId + stageId + encounterId`로 관리한다. 관련 없는 resize/설정 닫기에서 지역 입장 화면으로 튀지 않아야 한다.
- 뒤로가기/로비/저장창을 열어도 카드를 지급하거나 전투를 시작하지 않는다. 다른 원정/불러오기/프로필 전환 시 이전 준비의 콜백을 폐기한다.
- 저장 허용 여부는 기존 `canSaveRun`을 따른다. 미리보기를 저장하려고 전투를 강제로 초기화하거나 원래 불가능한 상태를 강제 저장하지 않는다.
- 새로고침/저장 복구 시 UI 하위 화면 표시가 유실되면 원래 지역 입장에서 다시 준비로 갈 수 있어도 된다. 이를 핑계로 정상 전투 저장을 초기화해서는 안 된다.
- 버튼 연속 탭/Enter/빠른 화면 전환은 준비 컨텍스트의 유효성을 검사하여 한 번만 시작한다.
- 준비 화면에는 새 카운트다운·필수 설명 확인·자동 진행을 추가하지 않는다.
- 같은 지역의 입장→준비→전투에서 BGM이 다시 시작하지 않는다. 오디오/전체화면은 기존 사용자 제스처 경로를 유지한다.

## 7. 목표 문법 팝업 — 한 가지 목표를 읽는 화면

### 7.1 기본 위계

```text
목표 문법                                      닫기 ×

4형식                            지역 점수 보너스 ×1.25
주어 + 동사 + 간접목적어 + 직접목적어
~에게 ~를 주다.

I give you a book.
나는 너에게 책 한 권을 준다.

보너스 조건
주절을 4형식으로 완성하면 적용됩니다.
▸ 자세한 조건
```

이 예는 배치 기준이다. 고정 문구를 전투 전체에 복사하지 않는다.

- 목표 제목은 24~28px, 형태 18~20px, 예문 영어 22~26px, 짧은 의미·예문 해석·본문 15~17px에서 시작한다. 모바일에서는 읽기 가능한 범위로만 조정한다.
- 형태는 별도의 차분한 배경/구분 영역으로 표시할 수 있다. 긴 형태를 한 줄에 맞추기 위해 과도하게 줄이지 않고 구성요소 단위로 줄바꿈한다.
- 제목/형태/예문이 상단에서 먼저 읽힌다. `이번 전투:` 같은 접두어를 큰 제목마다 중복하지 않는다.
- 예문은 현재 승인된 정적 학습 데이터에서 가져온다. 해석은 기존 데이터가 있으면 사용하고, 없으면 해당 승인 예문의 표시용 번역을 별도 필드에 명시해 검토한다. **실행 중 자동 번역/API 호출은 금지**한다.
- 품사색을 예문에 적용한다면 정적 검증된 토큰 정보와 기존 품사색만 사용한다. 주어/목적어라는 문장 성분을 단일 품사색과 동일시하지 않는다. 확정 정보가 없으면 깨끗한 단색 예문으로 둔다.

### 7.2 자세한 조건과 공통 설명

- 짧은 조건은 1~2줄로 유지하고, 판정 범위/예외/다른 보너스 대상은 `자세한 조건`에 정확하게 남긴다.
- 예: 춤추는 광대의 첫 목표는 현재분사 분사구문이지만 지역 전체에 다른 유효 구문이 존재한다면 전체 조건은 그대로 알 수 있어야 한다. **요약 때문에 실제 보너스 범위를 좁혀 안내하지 않는다.**
- `카드를 놓는 동안에는 판정하지 않습니다`, 중복 주절/형태 설명 등 공통 작동 문구는 기본 화면에 반복하지 않는다. 실제 동작은 변경하지 않는다.
- 뜻/예문이 없는 일반 지시를 억지로 `뜻`이나 예문 해석으로 채우지 않는다.
- 원정 버전별 다른 문법 범위를 현재 버전의 설명으로 덮지 않는다.

### 7.3 현재 전투와 보스 공략

- 현재 보스일 때 실제 기믹의 핵심을 `보스 공략` 한 영역에 모은다. `지역 공략 참고`에 같은 설명을 다시 이어 붙이지 않는다.
- 일반전의 기본 화면에는 해당 지역 미래 보스의 긴 설명을 상시 노출하지 않는다. 필요한 미리보기는 명확히 구분된 접기 영역으로 한 번만 제공한다.
- 실제로 반드시 필요한 조건은 짧은 요약에서도 빠지면 안 된다. 예견+두 실처럼 두 규칙이 함께 적용되는 보스는 두 규칙을 짧게 모두 알린다.
- 정적 도움말을 재구성하는 작업이지, 새 보스 상태판을 만드는 작업이 아니다. 전투의 실시간 HP/봉인/실 표시를 제거하거나 도움말 안으로 숨기지 않는다.

## 8. 설정 전용 컴팩트 팝업

### 8.1 기본 구성

```text
설정                                      닫기 ×

소리
배경음악       ━━━━━━━●━━                100%
효과음         ━━━━━━━●━━                100%
음소거                                  [꺼짐]

화면·연출
화면                               [전체화면]
연출 속도                             [1× ▾]
효과 감소                               [꺼짐]

               [튜토리얼 다시 보기]
▸ 홈 화면·접속 안내
```

출발점 너비 560px, 높이는 내용 기준이다. 화면이 넓다는 이유로 조절부가 오른쪽 끝까지 벌어지지 않는다.

### 8.2 행 정렬과 크기

- PC 한 행은 `라벨 / 조절부 / 값`의 일정한 열로 만든다. 슬라이더 둘의 시작·끝·백분율 기준선을 맞춘다.
- 라벨 열 약 96~120px, 백분율 열 약 44~52px, 나머지는 조절부에 둔다. 실제 폰트/번역 길이에 맞춰 조정한다.
- 각 행 조작 높이 44~48px, 그룹 내부 간격 8~12px, 그룹 사이 20~24px, 창 안쪽 20~24px에서 시작한다. 각 값은 작게 조절 가능한 시작값이지 콘텐츠를 잘라내는 고정 높이가 아니다.
- `전체화면`은 다른 설정과 같은 행의 명확한 버튼이다. 위쪽 큰 빈칸 한가운데 텍스트만 놓지 않는다.
- 백분율은 슬라이더 위에 따로 띄우지 않고 같은 행 오른쪽에서 읽히게 한다. 화면이 좁아 두 줄이 필요하면 라벨+값과 슬라이더를 논리적으로 묶는다.

### 8.3 상태와 동작

- 음소거/효과 감소는 기존 boolean과 연결된 스위치 스타일로 표시한다. 기존 native checkbox를 스타일링하거나 동등한 키보드/접근성 동작을 제공한다.
- 라벨도 누르면 해당 설정이 바뀐다. 이중 클릭 핸들러 때문에 한 탭에 두 번 전환되지 않게 한다. 상태는 색뿐 아니라 스위치 위치/켜짐·꺼짐으로 구별한다.
- BGM/SFX 0~100 값, 연출 속도 선택값 1/1.5/2, 사용자 저장·즉시 적용은 기존 계약 그대로다. 새로 열 때 기본값으로 리셋하지 않는다.
- BGM 100% 표시는 사용자 상대 볼륨이다. 기존 원본 대비 기본 출력 배율을 이 패치에서 변경하지 않는다. 음소거 해제 시 임의로 100%로 올리지 않는다.
- `효과 감소` 아래에는 필요한 경우 “공격·피격 표시는 유지됩니다.” 정도의 짧은 구분을 둔다. OS 동작 줄이기가 적용된 경우 기존 안내는 유지한다.
- 설정을 적용하기 위한 별도 `저장/적용/확인` 버튼은 추가하지 않는다. 닫기만으로 충분하다.
- `튜토리얼 다시 보기`는 적당한 보조 버튼으로 하단에 둔다. 실제 허용 조건과 기존 콜백을 유지한다.
- `홈 화면·접속 안내`는 하단에 접힌 상태로 배치한다. 공식 링크 복사/PWA/브라우저별 저장 분리/현재 창 계속 등 기존 기능을 삭제하거나 지원하지 않는 전체화면을 보장하지 않는다.
- 상단의 별도 소리 팝업과 같은 설정 소스를 사용한다. 두 창에서 서로 다른 저장값을 관리하지 않는다.

### 8.4 짧은 휴대폰 가로 화면

- 충분한 가로폭(출발점 약 720px 이상)과 짧은 가시 높이에서는 소리/화면·연출 그룹을 2열로 배치할 수 있다. 이때 settings 최대 폭을 해당 모드에 한해 약 720~800px 안에서 허용한다.
- 이것은 그룹을 나란히 놓는 것이지, 항목 라벨을 화면 왼끝·조절부를 오른끝에 다시 벌리는 것이 아니다.
- 각 그룹 안의 슬라이더·라벨이 읽기 어려우면 1열 + 본문 스크롤로 돌아간다.
- 보조 설명을 펼치거나 키보드/주소창으로 높이가 줄면 본문만 스크롤한다. 닫기/제목은 접근 가능해야 한다.
- 스크롤바 외관을 조정하더라도 기능을 숨기거나 터치 스크롤을 막지 않는다.

## 11. 검증 범위 — 필요한 경로를 묶어서 확인

### 11.1 필수 명령

최종 변경 뒤 `npm test`, `npm run build`를 실행한다. 표시 데이터/자료를 바꾸었다면 기존 `npm run validate:data`도 실행한다. 새 검사 파일 이름은 최신 저장소 규칙을 따른다. 이 문서에 적힌 파일명이 현재 존재한다고 가정하지 않는다.

기존 테스트를 제거하거나 무조건 skip하여 통과시키지 않는다. 문구·버튼 통합·준비 단계로 인해 기대값을 변경하면 이유를 기록한다. 게임 수치/난수 결과가 달라지는 것을 UI 변경의 정상 결과로 허용하지 않는다.

### 11.2 여섯 집중 흐름

1. **사전·메뉴:** 전투 조합대 왼쪽/모바일 메뉴/상점 등에서 `내 덱`·새 `카드` 통합 버튼이 없고 `사전`이 정상 열리는지 확인한다. 영어·한국어 검색, 겸용 단어, 제거된 단어, 품사색, 초점·스크롤, 하단 뽑을/버린/사용 완료 목록과 드로우 순서 비공개를 점검한다. 여러 연마 사본·운영 카드의 실제 데이터가 메뉴 삭제 전후 일치해야 한다.
2. **문법·설정:** PC/패드/짧은 가로 화면에서 폭·정렬·닫기·스크롤 확인. 4형식/분사구문/직조자 및 없는 뜻/예문. 슬라이더/토글/속도/전체화면 도움말/PWA 안내 왕복.
3. **상점:** 실제 소스 정책으로 6개 매핑을 단위검사하고 첫 상점·4 또는 8지역 선택 준비·최종 준비 상점을 브라우저에서 대표 확인. 상점 저장 복구/상품/구매/골드/음악 컨텍스트 비교.
4. **첫 준비:** 일반 1-1, 상점 후 지역 첫 전투, 상점 없는 지역 첫 전투, 4·8지역 선택, 최종 지역 첫 전투. 미리보기 중 무변경 및 시작 명령 1회, 재진입/연속 탭/기존 전투 저장 복구, 실제 guided 예외.
5. **전투 기반 보존:** 8/12열·24단어·쉼표·손패 페이지·선택·삽입 표시·공격/감점/카드 이동·보스 예견+두 실·설정 복귀.
6. **라이프사이클:** 주소창에 의한 가시 높이 변화, 전체화면 왕복, 회전, 앱 복귀, 미디어/이미지 지연. 참조 노드/리스너/모달/콜백 중복 없이 다음 조작 정상.

권장 대표 가시 영역: PC 1440×900, 패드 1024×768, 휴대폰 가로 844×390 및 실제 가시 높이 약 310px. 각 조건에 모든 장면을 곱해 대량 검사하지 말고 핵심 조합으로 묶는다. 실제 기기/인앱/청취를 못 했다면 `NOT RUN`을 분리한다. 에뮬레이션을 실기기 검증이라고 보고하지 않는다.

새 브라우저 캡처는 **사전(PC), 전투 왼쪽 메뉴(내 덱 삭제 확인), 목표 문법, 설정, 보스 뒤 상점, 첫 전투 준비**의 대표 6장 정도로 충분하다. 캡처는 실제 렌더를 열어 확인한다. 파일이 생성됐다는 것만으로 가독성 합격 처리하지 않는다. 필요한 경우 짧은 모바일 사전/설정 화면 1~2장을 더 확인한다.

**자연 50전투 완주, 대량 시드, 모든 기기/브라우저의 전수 조합, 수백 장 캡처는 이번 선행 조건이 아니다.** 대표 경로와 데이터 무변경 검증으로 마무리하고 미확인 한계를 기록한다.

### 11.3 화면 합격의 실질 기준

- 영어와 뜻이 한 제목 줄로 읽히고 품사는 별도 아래줄에 있다.
- 뜻·형태를 읽으려고 확대할 필요가 없으며 품사색이 실제 카드와 연결된다.
- 검색 도구 때문에 넓은 화면의 첫 단어가 중앙 아래로 밀리지 않는다.
- 목표 문법에서 이름→형태→예문→조건 순서가 크기/간격으로 구별된다.
- PC 설정은 넓은 화면에서도 작은 중앙 팝업이며 라벨과 컨트롤이 가까이 있다.
- 상점 이름/팔레트/곡의 장소가 같고, 다음 지역 상품은 바뀌지 않는다.
- 첫 전투가 준비 없이 시작되지 않고, 준비를 열었다고 게임 자원이 변하지 않는다.

## 12. 완료 보고와 인계

변경 파일/역할, 실제 기준 SHA/브랜치, 다섯 범위의 구현 결과, AC별 근거, 실행 명령·종료 코드, 대표 캡처와 실기기 미확인을 보고한다. 이미지·UI 검사와 단위검사를 구별한다. 저장/정책 버전을 그대로 보존했는지 명시한다.

완성 후 개발 브랜치와 PR로 인계한다. **별도 승인 없이 main 병합·자동 병합 설정·GitHub Pages 설정 변경·공개 배포를 수행하지 않는다.**

문서 기본값에서 벗어난 조정은 이유를 적는다. 남은 문제를 임의로 “전체 정상”이라고 묶지 않는다. 결과 화면이 문제 스크린샷의 긴 문단/전체 폭/거대 여백을 그대로 반복하면 테스트 통과 여부와 별개로 미완료다.
