## 2. 공통 문구 표준

다음은 사용자에게 보이는 명칭이다. 내부 command, enum, DOM 식별자, 저장 키를 같은 이유로 바꾸지 않는다.

| 현재 표현 | 새 표현 / 처리 |
|---|---|
| 남은 행동 턴 | **남은 턴** |
| 공격 확정 | **공격** |
| 턴 넘기기 · 다음 턴 +3 (실제 숫자가 다른 경우 포함) | **턴 넘기기** |
| 공격 기록 | **기록** |
| 여기서 저장 | **저장** |
| 장착 룬 | **나의 룬** |
| 전투 효과 / 지역 보너스 — 지역 배율을 설명하는 UI 제목 | **지역 점수 보너스**로 통일 |
| 가로 전체화면 시작 | **전체화면** |
| 1·2·3형식 복습 | **1·2·3형식** |
| 비어 있는 슬롯 등 | **비어 있음** 유지 |
| 뽑을 카드 / 버린 카드 | 이 명칭 유지. 아래 수량은 숫자만 표시 |

전체화면 활성 상태에서는 기존처럼 `전체화면 종료`를 사용할 수 있다. 단순 라벨 변경으로 전체화면 요청·오디오 unlock·거절 안내·홈 화면 웹앱 동작을 바꾸지 않는다.

`기록`은 전투 메뉴에서 기존 공격 기록 화면을 여는 버튼의 명칭이다. 로비의 기존 기록 기능과 무리하게 통합하지 않으며, 전투 기록은 필요하면 모달 제목을 `이번 원정 기록`으로 구분할 수 있다. 이 보조 제목은 구현 기본안이며 새 기록 시스템을 뜻하지 않는다.

`지역 점수 보너스`는 **점수에 적용되는 지역 배율**의 명칭이다. 보스 방어막, 봉인 해제, 자원 보상 등 다른 효과까지 모두 같은 이름으로 바꾸지 않는다.

## 3. 전투 준비 화면: 이름·문법·진행 버튼 중심

### 3.1 정체성 및 헤더

- 보스 이름 옆의 `보스 전투`를 **BOSS**로 바꾼다. 눈에 띄는 붉은색과 기존 글꼴의 굵기로 강조하되 깜빡임·과한 광채·별도 큰 배너는 넣지 않는다.
- `BOSS`라는 글자로도 보스임을 알 수 있어야 한다. 색만으로 상태를 전달하지 않는다.
- 일반전에는 BOSS를 붙이지 않는다. 기존 `일반 전투` 표시는 새 강조를 하지 않고 유지할 수 있으나, 일반/보스 구분을 다른 설명으로 더 늘리지 않는다.
- 상단 `지역명 · 다음 전투 3 / 50`은 **`지역명 · 다음 전투`**로 바꾼다. 전투 이름은 기존 이름 영역에서 표시한다.
- 큰 몬스터, 배경 파노라마, 하단 진행 버튼 구조는 그대로 유지한다.
- `다음 전투` 버튼은 그대로, `여기서 저장` 버튼은 `저장`으로 바꾼다.

### 3.2 목표 문법과 뜻

- 초원 수호자의 목표는 `1·2·3형식`이다. `복습`이라는 교사용 진행 표현을 붙이지 않는다.
- `뜻`은 실제 문법의 **짧은 해석 틀**일 때만 표시한다. 예: `~에게 ~를 주다.` / `~하면서 / ~해서` / `~되어 / ~을 받아`.
- `완성한 문장으로 공격해 적의 체력을 모두 줄이세요.` 같은 플레이 지시는 뜻이 아니다. 초원 수호자의 이 문구와 `뜻:` 행 자체를 제거한다. 빈 행도 남기지 않는다.
- 모든 문법의 의미를 임의로 새로 집필하지 않는다. 현재 자료에서 실제 해석 틀이 있는 것은 보존하고, 전략 설명을 의미로 대입한 항목만 표시용 데이터에서 구분한다.
- 현재 `preparationGuide()`는 일반 경로에서 `meaningKo:g.description`을 사용한다. 이 값을 무조건 출력하지 않게 한다. 표시용 `meaningKo`를 명시하거나, 뜻과 플레이 안내를 별도 필드로 나누되 파서·채점 정책은 건드리지 않는다.
- 초원 준비 화면에 무조건 붙는 명령문 설명을 제거한다. 명령문 지원과 사전/도움말의 관련 설명은 삭제하지 않는다.
- 기타 안내도 해당 전투와 실제 관계가 있는 것만 남긴다. 기존 보스 필수 공략 조건은 일반 삭제 대상이 아니다.

### 3.3 지역 배율 표시는 한 번

- `전투 효과: 지역 보너스 · ...`처럼 제목이 중첩되지 않게 한다.
- 준비 화면의 지역 배율 줄은 **`지역 점수 보너스: {구체적 대상} ×{실제 배율}`** 한 번으로 표시한다.
- 배율은 현재 원정/지역 데이터에서 가져온다. 모든 지역에 1.25를 하드코딩하지 않는다.
- 추가 지역 배율이 없는 최종전은 `지역 점수 보너스: 없음`으로 표시한다. 실제 보스 공략 효과는 별도 공략에 유지한다.
- 준비 화면과 전투 화면/목표 문법 창이 같은 표시 데이터를 사용하도록 한다.

초원 수호자 예시(배율은 실제 데이터 사용):

```
시작의 초원 · 다음 전투
[파노라마와 중앙 보스]
초원 수호자   BOSS
목표 문법: 1·2·3형식
형태: 기존의 해당 문형 설명
예문: 기존의 유효한 예문
지역 점수 보너스: 1·2·3형식 ×{실제 배율}
[다음 전투] [저장]
```

`뜻: 처치 지시`, 불필요한 명령문 안내, 전체 전투 수를 이 예시에 다시 끼워 넣지 않는다.

## 4. 전체 전투 수를 공개 화면에서 숨기기

- 로비, 전투 준비, 전투 헤더, 지역 클리어, 결과·저장 목록 등 실제 플레이 UI에서 `총 50전투`, `/50`, `FIFTY BATTLES` 같은 **총 전투 수를 예고하는 표시**를 제거한다.
- 전투 준비의 전역 번호 `다음 전투 3/50`은 지역명/다음 전투만 남긴다. 기존 지역 내 진행 번호가 다른 화면에 있으면 그대로 유지할 수 있으나 새 전역 카운터를 만들지 않는다.
- 로비의 `01–10 + FINAL`, `열 지역과 최종 성역을 잇는 모험`, `총 50전투 · 통사의 근원 · 마지막 세 전투`는 제거한다.
- 내부 `battleNumber`, `campaignBattleCount()`, 47전투 뒤 상점, 마지막 전투 판정, 저장·랭킹 계약은 그대로 둔다.
- 문자열 `50` 자체를 전역 치환하지 않는다. HP·점수·카드 수·개별 기록 수치에 포함된 50은 정상 데이터다. 과거 확정 기록도 재작성하지 않는다.
- 문서/테스트/개발 로그의 실제 전투 수까지 삭제하거나 은폐하는 작업은 아니다.

## 5. 전투 행동과 손패 정보

### 5.1 짧은 버튼명과 기능 보존

- 버튼명만 `공격`, `턴 넘기기`, `저장`, `기록`으로 바꾼다. 버튼의 주요 터치 영역과 위치를 글자 길이에 맞춰 과도하게 줄이지 않는다.
- `턴 넘기기`로 실제 다음 턴 카드 수/행동 비용을 변경하지 않는다. 필요한 상세 규칙은 기존 도움말에 남기고 상시 버튼 문구에서는 제거한다.
- 마지막 턴을 넘길 때의 기존 확인/패배 경고는 보존한다. 짧은 버튼명과 안전 경고는 별개다.

### 5.2 버리기 표시: 의미를 고정

표시 형식: **`버리기 ({선택 장수}) {남은 교환 횟수}/{실제 교환 한도}`**.

사용자의 `버리기 (0) 1/3` 예시는 이 형식을 따른다. 분자 의미는 기존 `잔여`와 일치하도록 **남은 횟수**로 결정한 구현 기본안이다.

- 시작에 선택 0, 남은 교환 3/한도3이면 `버리기 (0) 3/3`.
- 2장 선택, 교환 1회 남았으면 `버리기 (2) 1/3`.
- 소진 시 `버리기 (0) 0/3`. 비활성 조건은 기존과 같다.
- 분모를 항상 3으로 쓰지 않는다. 기존 전투 규칙/수정자로부터 실제 한도를 가져온다. 자원 회복·추가 사용권이 존재하면 기존 원천값을 표시하고 표시를 위해 자원을 잘라내지 않는다.
- 선택 장수는 현재 손패 페이지뿐 아니라 모든 페이지의 선택 상태 합계다. 쉼표 도구는 제외한다.
- `장`, `잔여`, `회`, 가운데점 같은 반복 단위는 보이는 버튼에서 제거한다. 접근성 이름에는 `2장 선택, 교환 1회 남음`처럼 풀어 설명할 수 있다.
- 사용 횟수 누적처럼 분자가 증가하는 별도 카운터를 도입하지 않는다.

### 5.3 손패 제목 하나로 통합

- 손패 상단은 **`나의 손패 {현재 장수}/{손패 한도}`** 하나로 통일한다. 예: `나의 손패 8/10`.
- `나의 손패 · 체크 후 버리기`, 중복 `9/10장`, 페이지 상태에 반복되는 전체 장수/선택 장수 문구를 제거한다.
- 페이지 이동은 유지한다. 페이지가 둘 이상이면 `‹ 1/2 ›`처럼 짧은 페이지 번호를 보조 표시하되 손패 장수와 혼동하지 않게 위치를 구분한다.
- 쉼표 도구는 손패 카운트에서 계속 제외한다. 한도는 실제 규칙을 사용한다.
- 독립적인 `선택 해제` 버튼은 상시 화면에서 제거한다. 선택한 카드의 체크를 다시 누르면 해제되는 기존 동작과 PC의 기존 Escape 동작을 보존한다.
- 버튼 제거 후 남은 변수/disabled 갱신/튜토리얼 앵커 참조로 오류가 나지 않게 정리한다. 필요하면 기존 튜토리얼의 해당 안내 대상을 체크 해제로 연결한다. 새 강제 튜토리얼은 만들지 않는다.
- 핸드가 비어도 구역 높이와 하단 여백을 축소하지 않는다.

### 5.4 카드 묶음

```
뽑을 카드        버린 카드
   18               6
```

제목은 유지하고 하단 수량에서 `장`만 제거한다. 카드를 뽑는 기능/순서 공개/클릭 동작을 변경하지 않는다. 접근성 이름에는 단위를 유지해도 된다.

## 6. 나의 룬과 작은 도움말

- 패널 제목을 **나의 룬**으로 변경한다. 기존 장착 수/슬롯 수 표시는 유지할 수 있다.
- 제목 옆에 **동그라미 안의 ?** 버튼을 둔다. 보이는 원은 작게, 실제 터치/키보드 포커스 영역은 손가락으로 누를 수 있게 유지한다. 모양의 시작값은 원 18~20px, 조작 영역 28~32px이며 확정 치수는 아니다.
- 접근성 이름은 `룬 도움말` 등 의미가 명확한 이름으로 한다. hover만으로 여는 UI는 금지한다.
- 누르면 기존 모달/도움말 체계를 사용한다. 패널이나 손패를 밀어내는 새 영역을 상시 펼치지 않는다.
- 상시 하단 설명 `공격 룬은 위에서 아래로 발동합니다. ▲▼ 또는 손잡이로 순서를 바꾸세요.`를 화면에서 제거하고, 그 정보를 도움말로 옮긴다.
- 도움말은 룬의 역할, 실제 발동 조건, 공격 룬의 위→아래 적용 순서, 효과 확인 및 허용되는 때의 순서 변경 방법 정도로 짧게 작성한다. 모든 룬이 항상 발동한다고 설명하지 않는다.
- 룬 슬롯·현재 순서·드래그·▲▼·레벨·봉인·발동 강조는 유지한다. 빈 슬롯은 `비어 있음`만 유지한다.
- 보스 진행 완료 표시를 새로 추가하는 패치로 확장하지 않는다.

## 7. 몬스터의 영문 이름

- 전투 화면의 몬스터 이름 위에 있는 `GRASSLAND ENCOUNTER`, `HARBOR ENCOUNTER`, `REGION BOSS` 등의 지역/종류 장식을 **그 몬스터의 영문 이름**으로 교체한다.
- 한국어 몬스터 이름은 기존 위치와 크기를 유지한다. 영어는 보조 위계로 읽기 쉽게 표시한다. 카테고리 문구와 영어 이름을 둘 다 쌓지 않는다.
- 실제 표시용 `nameEn`이 있으면 재사용한다. 없으면 명시적인 **표시용 번역 맵**으로 관리한다. 런타임 번역 API·로마자 자동 변환·게임 ID 변경은 하지 않는다.
- 현재 `enemyDisplayName()`의 한국어 별칭과 원정 버전 차이를 반영한다. 같은 enemyId의 구원정/신원정 이름이 다르면 버전 또는 실제 표시명으로 구별한다.
- 다음은 이번 패치용 번역 시작안이지, 기존에 확정된 영어 명칭이라는 뜻이 아니다. 기존 확정 영어 이름이 있으면 우선한다.

| 한국어 | 표시용 영어 제안 |
|---|---|
| 초원 수호자 | Grassland Guardian |
| 춤추는 광대 | Dancing Jester |
| 추방당한 왕자 | Exiled Prince |
| 망상의 순례자 | Deluded Pilgrim |
| 후회의 기사 | Knight of Regret |
| 운명의 직조자 | Weaver of Fate |
| 서피스 스트럭처 | Surface Structure |
| 딥 스트럭처 | Deep Structure |
| 유니버셜 그래머 | Universal Grammar |

- 다른 기존 몬스터도 현재 한국어 명칭에 대응하는 영어를 같은 방식으로 채운다. 이름/이미지/전투 번호를 재배열하지 않는다.
- 원본 한국어 명칭과 컨셉은 그대로다. 영어를 넣기 위해 한글 제목을 축소하거나 몬스터를 밀어내지 않는다. 긴 영어만 허용된 공간에서 줄바꿈한다.

## 8. 지역 점수 보너스 박스: 정확한 이름, 타이트한 간격

기본 전투 표시:

```
지역 점수 보너스
현재분사 분사구문 ×1.25
[목표 문법]
```

### 8.1 구체적인 요약

- `regionBonusSummary()`의 글자 수 초과 시 `학습 구문`으로 치환하는 처리를 제거한다. `학습구문`, `해당 문법` 같은 무의미한 대체어를 넣지 않는다.
- **이번 전투의 실제 목표가 지역 배율 적용 대상인 경우** 그 목표를 요약에 사용한다.
- v0.14.0 신규 규칙의 별의 회랑은 아래를 기본 표시안으로 한다. 실제 지역 배율은 데이터에서 읽는다.

| 전투 | 화면 요약 |
|---|---|
| 춤추는 광대 | 현재분사 분사구문 ×1.25 |
| 추방당한 왕자 | 과거분사 분사구문 ×1.25 |
| 망상의 순례자 | 가정법 과거 ×1.25 |
| 후회의 기사 | 가정법 과거완료 ×1.25 |
| 운명의 직조자 | 분사구문·가정법 ×1.25 |

- 표는 표시 제안이다. **실제 보너스 범위를 이번 목표에만 한정하도록 엔진을 바꾸지 않는다.** 별의 회랑에는 다른 유효 조건절/과거완료 등 기존 적용 대상도 있으므로, `목표 문법` 창의 `지역 점수 보너스` 절에서 전체 적용 조건을 정확히 설명한다.
- 화면 요약에 `오직`, `필수`, `이 문법만` 같은 배타 표현을 붙이지 않는다. 보스 처치 조건과 지역 점수 배율도 혼동하지 않는다.
- 추천 목표가 보스 이름/기믹명처럼 문법이 아니면, 해당 지역의 구체적인 문법 범위를 짧게 사용한다. 전체 목록을 숨길 때도 현재 목표 자체를 감추지 않는다.
- 표시용 텍스트를 고치기 위해 진행 중 문장을 파싱하거나 정답/예상 점수를 미리 알려주지 않는다.

### 8.2 내부 여백

- 박스 안은 `제목 → 요약 → 목표 문법 버튼` 순서로 자연스러운 간격을 준다. `space-between`으로 내용을 위아래 끝에 벌리거나 삭제한 행의 높이를 남기지 않는다.
- 출발점: PC/패드 안쪽 여백 8~12px, 휴대폰 6~8px, 요소 사이 4~6px. 절대값 강제가 아니라 현재 스타일 안에서 비교할 조정값이다.
- 짧은 안내 박스가 무대 전체 높이까지 불필요하게 늘어나지 않게 한다. 긴 문법명은 최대 2줄 등 자연스러운 줄바꿈으로 처리하고 글자를 지나치게 줄이지 않는다.
- 모바일의 `남은 턴/교환/골드`는 v0.14.1에서 정한 보너스 박스 왼쪽 세 줄 배치를 유지한다. 헤더로 되돌리지 않는다.
- 박스 내부만 정돈한다. 전투 전체 행 높이, 몬스터 그림 크기, 조합대와 손패 위치를 다시 설계하지 않는다.

## 9. 로비: 문구 선택 및 불필요한 정보 제거

### 9.1 최종 로비 문구

| 위치 / 기존 내용 | 적용 내용 |
|---|---|
| WORDS BECOME POWER | **SENTENCE BECOMES POWER** |
| 게임 설명 | **영단어 문장 조합 덱빌딩** |
| 아름다운 지역을 탐험하며 나만의 문장을 만들어가는 모험 | 삭제 |
| 여행자 밑 28장의 단어로 시작하는 나만의 문장. | 삭제 |
| 01–10 + FINAL / FIFTY BATTLES / 총 50전투 소개 | 삭제 |
| 지역 소개 영역 | 현재 1~10지역 이름만, 진행 순서대로 표시 |
| 과거 · 현재 · 미래로 이어지는 문장 모험 | **The more complete your sentence, the more powerful it becomes.** |
| 어휘 수준 선택 | **초급 / 중급 / 고급 / 자유** |
| 가로 전체화면 시작 | **전체화면** |

- `SENTENCE BECOMES POWER`는 사용자가 선택한 타이틀용 문구로 그대로 사용한다.
- 영문 하단 문구는 사용자의 제안을 자연스러운 비교 구문으로 다듬은 **편집안**이다. 다른 홍보 문구를 추가하지 않는다.
- 새 게임 설명은 기존 설명/기능 강조 위치 중 한 곳에만 놓고 중복 출력하지 않는다. `◇ 문장 조합 덱빌딩`, `◇ 로컬 싱글 플레이` 같은 병렬 홍보는 해당 한 줄에 통합한다. 저장 위치 차이 등 실제 사용 주의는 기존 설정/저장 도움말로 접근 가능하게 유지한다.
- 실제 로비 배경, Syntax Atlas 제목, 기존 미리보기 카드, 원정 시작·불러오기·설정 동작은 유지한다.
- 삭제한 소개 블록의 고정 높이를 비워 두지 않는다. 남은 제목·게임 설명·지역 이름·설정 양식의 간격만 정돈한다. 제목을 새로 거대하게 만들거나 카드 외형을 바꾸지 않는다.

### 9.2 지역 이름 10개만

- 현재 활성 표시 데이터에서 `stage.01`부터 `stage.10`까지의 **실제 한국어 지역명**을 순서대로 가져온다. 과거 메모리의 지명으로 덮어쓰지 않는다.
- 숫자 01~10, FINAL, 총 전투 수, 최종전 사전 설명은 붙이지 않는다.
- `stage.final`(통사의 근원)은 열 개 지역 이름 목록에 추가하지 않는다. 이 제외는 로비 미리보기 범위만의 정책이며 실제 최종전은 그대로다.
- 같은 길이의 칩이나 짧은 구분점 목록 등 기존 테마의 단정한 텍스트 목록으로 배치한다. 새 지도/진행 트리/배경 일러스트는 만들지 않는다.
- 좁은 가로 화면에서는 지역명만 자연스럽게 줄을 바꾸고 원정 시작 버튼을 가리지 않는다.

### 9.3 어휘 수준은 이름만 변경

| 내부 값 | 새 표시 |
|---|---|
| BEGINNER | 초급 |
| STANDARD | 중급 |
| ADVANCED | 고급 |
| FREE | 자유 |

기존 선택값/프로필 설정을 유지한다. 단어 풀·희귀도·채점·난이도는 바꾸지 않는다. `고급`은 여기서 어휘 수준의 표시명이며 카드 희귀도 enum을 변경하라는 뜻이 아니다.

## 10. 기존 프로필의 이름 고정

### 기존 프로필 선택

- `여행자 이름` 영역에 선택된 프로필의 실제 이름을 즉시 표시한다.
- 편집용 빈 입력칸이나 `이름을 입력하세요` placeholder를 보여주지 않는다. 이름은 일반 표시 요소 또는 읽기 전용 필드로 고정한다.
- A→B 프로필 전환 시 이름도 B로 갱신된다. 이름이 같더라도 profileId로 대상을 식별한다.
- 원정 시작은 **선택한 profileId와 그 프로필의 기존 displayName**을 사용한다. 숨겨진 입력값, 이전 새 프로필 입력값, 기본값 `여행자`로 기존 이름을 덮어쓰지 않는다.
- 현재 `startRun()`의 기존 프로필 분기는 `config.displayName`으로 이름을 갱신할 수 있다. 기존 프로필로 시작하는 경로에서는 이름을 변경하지 않게 보완한다. 어휘 설정 등 기존에 저장하던 비이름 설정은 계속 저장한다.
- 이것은 기존 프로필의 이름 변경 기능 추가가 아니다. 이름 변경을 위한 별도 UI를 새로 만들지 않는다.

### 새 프로필 / 정보 없음

- `새 프로필`을 누르거나 선택된 프로필이 없을 때만 편집 가능한 이름 입력을 보여준다.
- 새 입력에는 `이름을 입력하세요`를 사용할 수 있다. 기존 이름 길이·입력 제약·빈 값 처리 정책은 임의 변경하지 않는다.
- 새 프로필 입력 중 기존 프로필을 선택하면 신규 임시 입력은 기존 프로필에 저장되지 않는다.
- 실제 기존 프로필 데이터가 이름 없이 불완전한 예외에서는 이름 입력을 허용하되, 단순 로비 렌더로 새 프로필을 중복 생성하거나 기존 기록을 버리지 않는다. 현재 저장 검증의 허용 범위에 맞게 명시적으로 처리한다.
- 로비 재렌더·다른 모달 왕복·불러오기 후에도 선택된 프로필 이름이 일치해야 한다.
- 이름 고정 과정에서 전체화면과 오디오가 필요한 사용자 제스처 경로를 비동기 작업 뒤로 미루지 않는다. 원정 시작의 이중 제출 방지도 유지한다.

- 현재 남은 교환/선택 장수/손패 수/프로필 이름은 렌더마다 최신 상태로 갱신한다. retained view 때문에 초기값이 남지 않게 한다.
- 몬스터의 retained image subtree, 이미지 예약, 삽입 표시와 점수/공격 FX는 이 패치의 새 설계 대상이 아니다.
- 과거 저장의 점수 이벤트·보스 영수증·확정 문장을 재계산하지 않는다. 총 전투 수를 숨기는 것은 표시에서만 한다.

## 12. 짧은 검증 계획

### 필수 실행

- 최종 변경 후 `npm test`, `npm run build`.
- 이번 변경과 직접 관련된 로비/프로필/준비/전투 UI의 기존 브라우저 검사 또는 좁은 추가 검사.
- 표시 데이터만 수정했다면 모든 문법·50전투 시뮬레이션을 반복하지 않는다. 저장소 규정 또는 실제 수정 파일이 요구하는 검사는 준수한다.
- 아래 확인을 5개 흐름으로 묶는다. 전체 브라우저 순회·대량 캡처·대량 시드·자연 50전투 완주를 이번 UI 패치의 선행 조건으로 만들지 않는다.

### 5개 확인 흐름

1. **로비/프로필**: 정보 없음→새 이름 입력→기존 A/B 전환→이름 고정→원정 시작→저장 이름 유지. 어휘 4개 라벨 및 enum 확인.
2. **준비/정보**: 초원 수호자, 춤추는 광대, 최종 보스 지정 상태. BOSS·뜻 행 제거·목표 이름·지역 배율·총 전투 수 숨김 확인.
3. **전투 조작**: 카드 선택/해제·페이지 왕복·교환·턴 넘기기·공격·기록·저장. 숫자 의미와 버튼 기능 확인.
4. **룬/레이아웃**: 나의 룬 ? 모달, 기존 룬 순서·발동·봉인 유지, 빈 슬롯, 타이트한 목표 문법 박스. PC/패드/모바일 대표 화면과 낮아진 가시 높이 확인.
5. **회귀**: 24단어+쉼표, 청색 INSERT/SWAP, 형태 반응·감점·공격, 이미지 표시, 전체화면 왕복, 기존 저장 불러오기 중 대표 1회씩.

자동 검사에 필요한 지정 상태는 테스트 내부에서만 사용한다. 일반 게임에 fixture/테스트 버튼/가짜 점수는 추가하지 않는다. 실기기에서 하지 못한 항목은 NOT RUN으로 보고한다.

## 13. 인수 조건 — 총 20개

- AC01: v0.14.1 실제 구현을 포함한 기준에서 시작했고 이전 패치가 소실되지 않는다.
- AC02: 보스 준비 화면에 붉은 BOSS가 있고 `보스 전투` 문구는 해당 위치에서 없다. 실제 보스 판정과 일치한다.
- AC03: 초원 수호자는 `1·2·3형식`이며 무관한 명령문 설명과 처치 지시 `뜻` 행이 없다.
- AC04: 준비/전투/목표 문법 창의 지역 배율 명칭이 `지역 점수 보너스`이고 중복 라벨이 없다.
- AC05: 플레이 UI에 총 50전투·/50·FIFTY BATTLES·01–10 + FINAL 예고가 없고 내부 진행·HP 수치·기록은 변조되지 않는다.
- AC06: 공격/턴 넘기기/기록/저장/남은 턴/전체화면 이름이 요청대로 짧고 기존 기능과 경고가 유지된다.
- AC07: 버리기는 `(선택 수) 남은 교환/실제 한도`, 서로 다른 손패 페이지의 선택과 현재 자원 변화를 정확히 반영한다.
- AC08: 손패 제목은 `나의 손패 현재/한도` 하나이며 페이지 조작은 남고 불필요한 선택 해제 버튼/중복 장수가 없다.
- AC09: 체크 재탭과 기존 Escape 해제가 동작하고 삭제된 버튼 참조로 오류가 없다. 손패 빈 상태에서도 구역이 유지된다.
- AC10: 뽑을 카드/버린 카드 아래 수량은 숫자만이며 실제 카드 수와 일치한다.
- AC11: 나의 룬 옆 ?가 터치/키보드로 열리고 상시 발동 설명은 도움말 안으로 옮겨졌다. 룬 기능은 같다.
- AC12: 몬스터별 영어 이름이 표시되고 GRASSLAND ENCOUNTER 등 generic 지역 장식이 남지 않는다. 한국어/원정 버전과 대응한다.
- AC13: 춤추는 광대의 요약은 현재분사 분사구문과 실제 배율을 보여주며 `학습 구문` 대체어가 없다. 실제 보너스 허용 범위는 그대로다.
- AC14: 지역 점수 보너스 박스에 과한 빈 높이·벌어진 간격·빈 행이 없고 모바일 자원 위치와 중앙 몬스터가 보존된다.
- AC15: 로비 확정 카피와 다듬은 영문 한 줄이 적용되고 삭제 요청 문구가 중복/숨은 다른 위치에 재출력되지 않는다.
- AC16: 로비 지역 목록은 현재 1~10지역 이름만이며 FINAL/전체 전투 수를 덧붙이지 않는다.
- AC17: 어휘 라벨 초급/중급/고급/자유가 기존 enum·선택값·풀과 연결된다.
- AC18: 기존 프로필 선택 시 실제 이름이 고정 표시되고 원정 시작으로 이름이 덮어써지지 않는다. 새/없음만 입력 가능하다.
- AC19: PC·패드·휴대폰 대표 크기 및 줄어든 가시 높이에서 버튼/팝업 접근, 기존 쉼표·입력·연출·저장 기능에 회귀가 없다.
- AC20: 필수 검사/빌드 결과, 수정 파일, 미실행 항목, 코드/PR/배포 상태를 구분하여 인계한다. 무승인 main 병합·배포는 없다.

## 14. 완료 보고 형식

1. 시작 기준(브랜치/커밋, PR #36 포함 여부).
2. 변경한 문구/프로필 동작/표시 영역 요약.
3. 실제 실행한 명령과 결과, 대표 UI 확인 환경.
4. 실제 실행하지 않은 실기기 항목과 남은 문제.
