## 1.3 이번 명세가 정한 구현 세칙(별도 사용자 발언으로 위장하지 말 것)

- 품사 탐색은 기존 논의대로 드로우 더미의 **현재 순서**에서 일치하는 물리 카드를 자동 선별한다. 임의 랜덤/직접 선택으로 바꾸지 않는다.
- 연결어 탐색 대상은 `and,but,or,because,when,if,that`. `to,as,than,more,most`는 제외한다.
- 대상이 0장이면 버튼 비활성/실행 거절, 무소모·RNG 불변. 적으면 있는 만큼. 손패 한도는 지킨다.
- 재사용 운영은 **효과를 해결한 다음** 사용한 사본을 discard에 넣는다. 그 사용 자체로 자신을 즉시 뽑지는 않는다. 다음 별도 행동으로 다시 뽑아 사용하는 것은 허용한다.
- 상점의 고정 운영 칸은 7종 중 중복 없는 정의 1개를 같은 가중치로 추첨하는 초기 정책. 등급별 가격은 기존 6/10/14를 따른다. 일반 보상은 기존 희귀도 추첨 뒤 20/80 운영 분기를 유지·확장한다.
- 보스 임시 탐색은 연마 불가(+0), WORD 아님, 빙결핵 파괴 자격 없음. 기존의 기본 손패를 만든 뒤 1장을 추가하되 최종 손패 한도를 넘기지 않는다.
- 아래 색상·미세 연출값은 출발점이다. 시각 검증을 거쳐 조정할 수 있지만 카드 크기·가독성·사막 외관을 훼손하지 않는다.

# 2. 관찰 기록과 출발 코드의 실제 제약

## 2.1 사실과 미확인을 분리

사용자 실전 관찰:
- 정상 문장 후보 `A room was too hard to show.`가 0점으로 제출됨.
- `A person be often giving you a beautiful environment with small problems.`는 4형식 장막을 풀지 못함. be 활용 오류는 사용자가 인정했으나 문형 판정과 분리하기로 합의.
- `they are giving her a friend because I enjoy eating today and you want a child`가 당시 최대 8,618점. **당시 룬 레벨/연마/시드 전체가 없으므로 8,618을 새 산술 테스트 정답으로 고정하지 않는다.** 16카드 복합문 회귀 문장으로 쓴다.
- 골렘은 6턴·세 시제의 긴장감이 적절. 사슴도 난이도 자체는 유지하되 수급 수단을 보강하기로 최종 결정.

작성 시 소스 읽기로 확인한 제약:
- `operations.js`: SUPPLY 2/SEARCH 1만 처리, source는 무조건 exhausted.
- `operationHistory.js`: 같은 sourceCardId 재등장 거부, 획득 수 1~2장, exhausted와 전체 source history가 같은 집합이라는 가정.
- `invariants.js`, rewards/shop/localStore: 운영의 polishLevel=0 또는 운영 연마 제외를 전제로 함.
- `operationPool.js`: 일반 카드 희귀도 추첨 후 조건부 OPERATION20/WORD80, `pool[0]` 방식. 새 여러 고급 운영이 모두 등장하도록 확장 필요.
- `skyIslands.js`: 부족하면 and/because/think/that 최대4장 지급.
- `parser.js`/`verbPhrase.js`: degree to부정사 호출에 외부 주어의 목적어 연결 정보가 없고, 조동사 연속성/부사/문형 경계가 점검 대상.
- `styles.css`: 빙정은 주로 border/shadow로 구분. 사막은 이미 별점·금빛 모래/남색의 layered gradient 사용.

**이는 정적 코드 확인이다. 작성자가 동일한 현재 main 실행환경에서 두 사용자 문장을 재현했다고 주장하지 않는다.** Codex가 수정 전 재현 테스트와 실제 결과를 남긴다. 현재 파일이 바뀌었다면 문제를 다시 검증하고 불필요한 수정은 하지 않는다.

모든 영구 운영 카드 `polishMax=1`. 다음과 같은 과거안을 금지한다:
- 품사 탐색 +2/+3, 4~5장 획득.

## 3.1 정의와 파생 효과의 단일 출처

정의 또는 versioned helper에서 다음 값을 파생한다. UI·실행·보상·저장 검증이 각자 수치를 하드코딩하지 않는다.

```text
operationSpec(cardDefId, polishLevel, instanceLifetime, operationVersion)
  -> type, sourcePile, targetFilter, selectionMode,
     requestedCount, afterUseDestination, polishMax
```

- `cardKind='OPERATION'` 유지. lexeme·품사·문법 Form·공격 기본 점수는 없다.
- `polishLevel=0|1`만 허용. WORD는 여전히0..3.
- 임시 빙정 탐색은 같은 기존 SEARCH 효과를 재사용하되 instance lifetime 제한으로 polishMax0.
- 알 수 없는 type은 SEARCH처럼 처리하는 else로 빠지지 않게 명시적 dispatch를 사용한다.
- 이미 구현한 stage/group/version capability helper를 필요한 범위에서 확장한다. 모든 곳에 `version==='0.6.0'`만 남아 0.6.1 기능이 꺼지는 회귀를 점검한다.

## 3.2 모든 운영의 공통 사용 규칙

사용 가능한 실제 손패의 source 사본, BATTLE/EDIT, 최신 revision/battle/effect/command 식별자를 확인한다. 형태/조합대에 올리기는 계속 금지한다.

```text
빈자리 = max(0, rules.handLimit - (사용 직전 손패 장수 - 1))
실제 획득 = min(요청 장수, 유효 대상 수, 빈자리)
```

source를 손에서 제거하여 생긴 자리도 사용한다. 예: 손패10/한도10에서 보급2를 쓰면 **최대1장**, 사용 뒤 손패10. 2장을 얻으려고 한도를 일시적으로 넘기지 않는다. 부족분을 미래 드로우 크레딧으로 남기지 않는다.

- 실제 획득0이면 source/자원/난수/통계/사용횟수/Undo 모두 불변. 원하면 쓸모없는 운영을 **교환**할 수 있다.
- 운영 사용 자체는 턴·교환 횟수·골드를 소모하지 않는다.
- 사용 성공 후 편집 Undo로 source/받은 카드를 되돌리는 것은 금지. 다음 공격/턴/저장 흐름은 기존대로.
- 운영을 교환으로 버리는 것은 사용 아님. 미사용 카드 그대로 discard에 간다.
- source 자신은 자기 효과의 획득 목록에 포함될 수 없다. 물리 ID 중복도 금지한다.
- 자동으로 다음 운영을 사용하거나, 드로우→사용→드로우 연쇄를 자동 실행하지 않는다.

## 3.3 보급과 직접 탐색

**보급**: 일반 drawCards 정책 유지. DRAW가 비면 기존 DISCARD를 deck RNG로 재셔플할 수 있다. WORD/OPERATION/아직 안 깨진 임시카드 모두 정상 드로우 대상.

**직접 탐색**: 현재 DRAW의 WORD 중 사본1개를 선택. 획득 카드를 새로 만들거나 discard를 뒤져 주지 않는다. 목록은 현재처럼 공개 정렬(이름/연마/ID)이며 숨은 드로우 순서를 노출하지 않는다. 임시 WORD도 선택 가능.

- 선택창 열기·취소는 RNG/원정상태/Undo 불변.
- 성공 시 선택한 ID만 DRAW에서 빼서 손에 추가하고 나머지 순서는 보존한다. RNG 소비0.
- +1에서는 사용 후 source가 discard로 간다. 나중에 드로우/재활용으로 되찾으면 같은 턴이라도 다시 사용 가능.
- 재사용을 연마의 보상으로 제공하므로 별도 쿨다운·턴당1회·전투당 횟수 제한을 임의로 추가하지 않는다.

## 3.4 품사 탐색

현재 DRAW의 정렬되지 않은 실제 순서를 앞에서부터 스캔해서 대상 최대N장을 가져온다. 선택 팝업 없음, RNG 소비0, 남은 DRAW의 상대 순서 보존.

| 카드 | 실제 대상 |
|---|---|
| 명사 탐색 | canonical lexeme.pos가 NOUN 또는 PRONOUN인 WORD |
| 동사 탐색 | canonical lexeme.pos가 VERB인 WORD. be/have 등 포함 |
| 형용사 탐색 | canonical lexeme.pos가 ADJECTIVE인 WORD |
| 연결어 탐색 | WORD이면서 canonical lemma가 and/but/or/because/when/if/that |

보이는 형태나 이전 문장에서 맡은 역할로 필터를 바꾸지 않는다. 예: her는 PRONOUN, bigger는 ADJECTIVE, reading은 VERB lexeme다. 동명사라고 명사 탐색에 reading을 넣거나, 분사라고 형용사 탐색에 넣지 않는다.

DRAW에 대상이 없으면 재셔플해서 찾아주지 않는다. 보급은 재셔플할 수 있지만 **품사 탐색/직접 탐색은 DRAW만** 본다. 단어 수 부족을 자동 생성으로 보정하지 않는다. 지원하지 않는 전체 FUNCTION을 연결어라고 한꺼번에 가져오지 않는다.

## 3.5 재활용

현재 DISCARD에 있는 실제 물리 사본 중 최대1/2장을 **중복 없이 균등 무작위**로 선택한다. RNG는 deck stream만 소비한다. DRAW는 건드리지 않는다. 제거되지 않은 나머지 DISCARD의 상대 순서를 보존한다.

대상:
- 공격에 썼던 일반 WORD.
- 교환으로 버린 미사용 운영.
- 사용 뒤 버려진 **+1 보급/탐색**.
- 교환으로 버린 미사용 빙정 WORD 또는 미사용 임시 운영.

제외:
- 사용 완료(EXHAUSTED)의 기본 운영 및 신규 운영.
- 깨진 빙정(SHATTERED).
- 이전 전투의 임시 카드/삭제된 카드/기록에만 있는 사본.

선택 순서·RNG 전후값·가져온 ID를 영수증으로 남긴다. 후보0에서는 RNG 소비0. 같은 seed와 행동이면 같은 결과다.

## 3.6 +1 재사용 카드의 원자적 정산 순서

1. 전체 사전조건/빈자리/대상/기술 오류를 검사한다.
2. source의 손패 제거를 **controller 소유 제안 상태**에서 수행한다.
3. 이 효과 이전의 DRAW/DISCARD를 대상으로 가져온다. SUPPLY 재셔플에도 source가 아직 없어야 한다.
4. 결과가 1장 이상임을 확인한 뒤 source를 목적지로 이동한다: +1 보급/탐색은 DISCARD 맨 앞, 나머지는 EXHAUSTED.
5. before/after 영수증·sequence·pendingEffectId·연출상태를 기록하고 불변식 통과 후 **한 번만 커밋**한다.
6. Presentation은 확정된 결과만 표시한다. FINISH가 카드를 추가 이동시키거나 드로우하지 않는다.

중간 제안에서 source가 일시적으로 pile 밖에 있어도, 외부에 그 상태를 커밋/저장하지 않는다. 구현상 resolving zone을 쓰면 정식 계약과 validator를 두며 finish에 실제 정산을 미루지 않는다.

예외: +1 보급밖에 없고 DRAW/DISCARD가 비어 있다면, 자기 자신을 먼저 버리고 다시 뽑는 방식으로 사용을 성립시켜서는 안 된다. 이는 유효 대상0인 무소모 거절이다.

반면 서로 다른 +1 보급이 합법적으로 다른 사본을 뽑는 순환은 허용한다. 강한 순환을 무한정 자동 실행하지 않으며, 무소모 무효행동·중복 명령 방어와 수동 조작을 유지한다. 테스트 실행기의 행동 상한을 게임 플레이 횟수 제한으로 옮기지 않는다.

# 4. 운영 연마·보상·상점·저장까지 한 계약으로 연결

## 4.1 연마 처리

`canPolish(card, version)`와 `maxPolish(card, version)`를 공유한다. 새 0.6.1의 영구 OPERATION은 +0일 때만 연마 가능, +1이면 최대. WORD0..2는 기존처럼 가능, WORD+3은 최대. 임시카드는 종류와 무관하게 연마 불가.

다음 경로를 전부 수정한다:
- 혼합 보상에서 연마 선택지의 실제 대상 생성/공개 대상 snapshot/확정 검증.
- 상점 연마 서비스의 대상/가격/방문당1회/취소와 확정.
- 덱 사전의 연마 효과 및 보유/필터, 카드 footer, 설명 모달, 강화 전후 화면.
- 저장 validator, operationHistory, 런타임 invariant, 보상 해결 기록.

운영 연마 UI는 `기본 10 + 연마5점`을 표시하지 않는다. 예:
- `보급: 전투당 1회 → 사용 후 버린 더미로 이동`
- `명사 탐색: 최대 2장 → 최대 3장`
- `재활용: 무작위 1장 → 최대 2장`

상점 연마 비용은 기존 8골드와 방문당 1회 유지. 기존 보상 선택 확률은 그대로다. 거래 도중 취소/중복 확정은 재화·카드·서비스를 추가 소비하지 않는다.

## 4.2 상점 1칸 보장

| 상점 | 룬 | WORD | OPERATION | 서비스 |
|---|---:|---:|---:|---|
| Stage 2 | 1 | 1 | **1** | 연마1회/제거1회 |
| Stage 4 | 2 | 2 | **1** | 동일 |
| Stage 6 | 2 | 2 | **1** | 동일 |

카드 칸을 늘리는 대신 기존 마지막 카드 칸을 전용 운영 칸으로 쓴다. WORD 첫 칸의 지역 관련 역할은 보존한다. 나머지 WORD 칸에서는 운영 분기를 실행하지 않는다. 따라서 **각 방문에 정확히1개의 운영 상품**이다.

- 운영 전용 칸: 현재 version/manifest의 영구 7종에서 같은 가중치로1개. 상점 생성 시 shop stream에서 한 번만 뽑고 확정 저장한다.
- 가격: 재활용6, 보급/4품사 탐색10, 직접 탐색14. 보유 골드나 현재 덱 부족에 따라 가격을 바꾸지 않는다.
- 같은 운영의 여러 물리 사본을 보유·구매할 수 있다. 기본 전투당1회도 **사본별**이다.
- 보스 무료 빙정 탐색은 판매/보상 풀에 별도8번째 정의로 섞지 않는다.
- 재입장·보기·구매 취소·저장 로드로 상품을 재추첨하지 않는다.
- 이전 상점 history/누적 제거 가격/공개상품 고정성을 보존한다.

새 운영 7종을 모두 같은 고급/희귀 pool의 `pool[0]`로 선택하지 말 것. 전용 칸에서는 모두 도달 가능해야 한다. 동일 가중치는 초기 정책임을 문서화한다.

## 4.3 일반 전투 보상

기존 외부 타입/희귀도 가중치 및 혼합 3칸, 최초 룬 선택, 튜토리얼 보상 규칙은 유지한다.

일반 혼합 보상의 비보호 카드 칸에 한해 기존 OPERATION20/WORD80 분기를 유지하고:
- COMMON → 재활용 후보 가능.
- UNCOMMON → 보급/명사/동사/형용사/연결어 탐색 후보 가능.
- RARE → 기존 직접 탐색 후보 가능.
- 같은 희귀도의 운영 여러 종에서는 같은 가중치로 하나를 고른다.
- 한 보상 offer에는 운영 최대1개. `LOCAL_SYNTAX_RELEVANT` 보호 칸은 WORD 유지.
- 최초 전투의 명시적인 WORD-only 정책을 운영 카드로 깨지 않는다.
- 기존 가중치가 양수인데 WORD 후보가 비었다면 기존의 명시적 fallback/trace 규칙을 따른다. 운영을 핑계로 희귀도를 몰래 바꾸지 않는다.

이것은 단어를 자동 지급하는 기능이 아니다. 보상/상점에서 선택한 경우에만 영구 덱에 들어간다. starterEligible은 전부false.

## 4.4 같은 source의 재사용과 명령 중복은 다르다

0.6.1 operationHistory는 다음을 구분해야 한다.

- 같은 +1 보급 source를 나중에 다시 뽑아 새로운 operationSequence/effectId로 사용: **정상**.
- 같은 기본 보급 또는 신규 일회 운영 source를 같은 전투에서 두 번 사용: **거절**.
- 같은 commandId/revision/effectId의 재전송 또는 FINISH 재전송: **중복 정산 금지**.

새 영수증 최소 정보:

```text
operationVersion, effectId, commandId, runId, battleId, expectedRevision,
operationSequence, sourceCardId, cardDefId,
sourceSnapshot {polishLevel,lifetime,afterUseDestination},
requestedCount, actualDrawCount, drawnCardIds,
sourcePile, selectionMode, filterId, targetCardId|null,
before/after {handIds,drawIds,discardIds,exhaustedIds,shatteredTemporaryIds,rng},
postUseDestination
```

전체 history와 exhausted가 같은 집합이라는 구식을 제거한다. **exhausted는 사용 완료로 간 일회 source들의 집합**이며, 재사용 source 사용 이력은 여러 개여도 exhausted에는 없어야 한다.

저장 시 새 type별 허용 획득수·원본 source polish·필터·실제 전후 이동·난수 소비 규칙을 검증한다. 정의상 최대3장도 허용하지만 무조건1..3이면 되는 것이 아니라 실제 효과/잔여대상/빈자리와 일치해야 한다. 임시 인스턴스가 종료 후 삭제되어도 기록용 snapshot으로 해석할 수 있어야 한다.

# 5. Stage 4 연결어 3택1

## 5.1 지급 자격과 수량

현재 영구 `activeCardIds`의 WORD만 본다. 사전에서 본 적 있음, 제거된 카드, 임시카드, 과거 기록은 보유가 아니다.

| 현재 덱 | 무료 연결어 |
|---|---|
| and/but/or/because/when/if 중 하나 이상 | **0장**, 기존 것을 활용 |
| 위 직접 연결어가 없음 | and/but/because 고정3택 중 **1장** |

`that`은 지시사/관계사/내용절의 여러 역할이 있고 내용절 지배 동사가 필요하므로, 이 선택 자격에서 단독 직접 연결어 보유로 취급하지 않는다. 이는 구현 세칙이며 현재 문법 판정을 바꾸는 뜻이 아니다.

think/that은 현재 조건 그대로:
- runtimeReady인 `frame.svo.content` 동사가 없으면 think1장.
- 영구 that이 없으면 that1장.
- think 대신 know/say 등 해당 내용절 경로를 실제로 가진 동사가 있으면 think 추가하지 않는다.

따라서 최대 영구 지급3장, 직접 연결어 기존 보유 시 최대2장. 이번에는 매 라운드 지급/선택한 연결어 복사/추가 무료 명사·동사 지급을 하지 않는다.

## 5.2 입장 거래와 저장

권장 흐름:

```text
Stage3 완료 보상 → Stage4 소개/보스 예고 → ENTER_STAGE
  ├ 직접 연결어 보유: think/that 부족분 1회 처리 → 상점 생성
  └ 없음: STAGE_INTRO + entryChoice.pending 유지
          → and/but/because 선택 → 영구카드/think/that/entryGrant 원자 확정
          → 상점 한 번 생성
```

- 새 전역 status 남발보다 기존 STAGE_INTRO 안에 pending choice를 직렬화하는 방식을 우선한다.
- `CHOOSE_STAGE4_CONNECTOR`(제안명)는 choiceId/entryId/revision/commandId를 확인한다.
- 선택지3개는 고정. RNG 소비0. 별도 랜덤 보상 offer와 섞지 않는다.
- 창을 닫거나 로비로 갔다가 돌아와도 선택을 자동 완료하지 않는다. pending을 다시 표시하고 안전 저장 복원 가능하게 한다.
- 같은 선택 두 번 클릭/과거 revision/완료 후 선택 재실행은 무료카드나 상점을 복제하지 않는다.
- entryGrants.applied는 실제 지급 확정 시점에만true. 취소 중에는 카드가 미리 들어가지 않는다.
- 완료 후 상점에서 연결어를 제거해도 재지급하지 않는다.
- 기존 구버전 entry grant validation과 이미 고정된 상품은 바꾸지 않는다.

표시 문구는 `연결어 한 장을 선택하세요. 나머지 연결어는 보상과 상점에서 얻을 수 있습니다.` 정도로 짧게 한다. 단어 뜻/역할을 한 줄씩 보여주며 점수 미리보기는 하지 않는다.

# 6. 거울뿔 사슴의 임시 빙정 탐색

## 6.1 효과와 공급

- 보스 전투(6-5)에만 무료 `빙정 탐색`1장.
- 기존 탐색과 같은 DRAW WORD1장 직접 선택 효과. 새 단어를 생성하지 않는다.
- OPERATION/일회/현재 전투한정/polish0. 일반 탐색의 +1 재사용 정책을 상속하지 않는다.
- 영어 조합대에 올리지 못한다. 단어 개수/공격점수/운석 유효카드/빙결핵 파괴수에 기여하지 않는다.
- 사용 후 임시 EXHAUSTED로 이동, 화면에서 사용 완료로 구분한다. 전투 종료 시 제거한다.
- unused 상태로 교환하면 discard로 가며 재활용/일반 재셔플로 되찾을 수 있다. 사용 후에는 재활용 불가.
- 이미 영구 보급/탐색을 가졌어도 지급한다. 덱 또는 프로필 영구 보유 수 증가0.

## 6.2 첫 손패 처리

기존 영구카드+빙정 WORD shuffle/witness/빙정2장 보정을 먼저 수행한다. **기존 기본 6장에 지원운영1장을 더해 기본 첫 손패 7장**으로 만든다. 초기 손패 증가 룬이 있으면 그 증가를 보존하고 지원1장을 더한다.

최종 handLimit을 넘기지는 않는다. 이미 손패가 한도라면:
- 깨야 할 빙정 WORD와 가능한 witness를 우선 보호하고,
- 비빙정 비보호 카드 한 장을 결정론적으로 DRAW 맨 앞으로 이동,
- 임시 탐색을 HAND에 넣는다.
- 적절한 비보호 후보가 없으면 보호 우선순위를 완화한 마지막 일반 카드로 처리하되 기존 보스 첫패의 결정 대상2장은 유지한다. 카드 유실/추가 추첨 없음, trace 기록.

통상상태에서는7장 모두보여야 하며 지원운영을 “DRAW 맨 위에 넣었으니 첫 턴 지급 완료”라고 대체하지 않는다. 연출 중 자동 사용하지 않고 사용자가 고른다.

## 6.3 임시카드 타입 경계

기존 8장 빙정 WORD와 선택적인 good fallback은 그대로다. 여기에 임시 OPERATION1장만 추가한다.

- `temporaryCardMeta.cardKind/lifetime/source/crystalBearing/supportOnly`를 분명하게 기록한다.
- 기존 WORD 전용 `registry.cardById`로 운영을 조회해서 null이 되지 않도록 `cardDefinition` 경로를 사용한다.
- `shatterSubmittedFrost`는 조합대 WORD만 소비한다. OPERATION은 `useOperation`으로 처리한다.
- 보스 결정은 기존 `crystalBearing:true` WORD만 센다. 같은 파란색이어도 임시 탐색은false.
- 안전 저장/로드는 지원 지급·원래 pile/RNG를 그대로 복원한다. load/턴마다 재지급하지 않는다.
- 전투 종료 cleanup은 live pile/임시객체를 정리하되 보스 공격/운영 history의 스냅샷은 읽을 수 있게 보존한다.

## 6.4 카드 보존식

```text
영구 activeCardIds ∩ temporaryCardIds = ∅
영구 + 임시 인스턴스의 live partition
 = DRAW ⊎ HAND ⊎ SENTENCE ⊎ DISCARD ⊎ EXHAUSTED ⊎ SHATTERED

SENTENCE: WORD만
EXHAUSTED: 실제 사용 완료 일회 OPERATION만(영구/임시 모두 가능)
SHATTERED: 공격에 쓴 전투한정 WORD만
```

+1 영구 보급/탐색은 EXHAUSTED에 있으면 오류다. 현재 전투 임시 탐색은 +1이면 오류다. 이미 깨진 WORD가 DRAW/DISCARD에 들어오면 오류다. 어느 한 영역에도 없는 ID/두 영역에 중복된 ID는 커밋과 로드 모두 거절한다.

# 7. 문법 A — 주어와 부정사의 생략 목적어 연결

## 7.1 목표

단순히 `to show`에 목적어가 없다고 전체 문장을0점으로 처리하지 않는다. 실제 주어가 부정사 내부의 대상과 연결되는 학교 문법의 기본 경우를 구조 증거로 인정한다. 외부 문법 참고는 `11_Sources.md`의 G1/G2이며, 이 문서의 판정/점수는 **게임 설계 계약**이다.

필수 양성 사례:

| 문장 | 바깥 문형 | 연결 |
|---|---|---|
| A room was too hard to show. | 2형식 | show의 직접목적어 ↔ a room |
| The book is too hard to read. | 2형식 | read의 직접목적어 ↔ the book |
| The book is easy to read. | 2형식 | 동일 |
| The book is easy enough to read. | 2형식 | 동일 |
| The room is too small to live in. | 2형식 | 실제 in의 목적어 ↔ the room |
| The book is easy to give you. | 2형식 | give의 직접목적어 ↔ the book, IO=you |

기존에 제공되지 않은 carry/solve/light 등의 새 어휘를 이 테스트를 위해 대량 추가하지 않는다. 테스트 helper도 실제 cardDef/Form을 매칭해야 한다.

## 7.2 지원 범위

- 기본 허용 형용사 `easy / hard / difficult`의 `AP + to`에 주어-목적어 연결을 추가한다.
- `too + 검수된 gradable AP + to`, `gradable AP + enough + to`에서도 같은 연결을 허용한다.
- 주어가 행동 주체인 기존 `I am too tired to read books.`, `I am strong enough to help you.` 경로와 **별도 분석 후보**로 처리한다.
- 기존 `happy/ready/easy + to` 등 subject-control 지원을 지우지 않는다.
- 일반 `want/enjoy/give` 뒤에 목적어가 빠진 모든 문장을 “앞에 명사가 있으니” 허용하는 전역 복구는 금지한다.
- 실제 지배 형용사·실제 주어 NP·실제 to와 동사·등록된 valency를 확인한다.
- 이미 explicit object가 차 있으면 같은 슬롯에 gap을 추가하지 않는다.
- 전치사 목적어 gap은 실제 전치사가 카드로 있을 때만 허용한다. in/to/with를 자동 삽입하지 않는다.
- 같은 NP를 참조하더라도 새 물리 카드나 유령토큰을 만들지 않는다. 말뭉치 의미/사물상식으로 판정을 차단하지 않는다.

## 7.3 분석과 점수

```text
nonfinitePhrase:
  function = ADJECTIVE_COMPLEMENT 또는 DEGREE_COMPLEMENT
  formKind = TO_INFINITIVE
  gapRole = DIRECT_OBJECT 또는 PREPOSITION_OBJECT
  antecedentNodeId = 실제 바깥 주어 NP
  governorNodeId = 실제 AP/정도 구조
  cardIds = 실제 제출 카드만
```

내부 용어는 현재 schema에 맞게 조정할 수 있다. 학교용 화면에 tough construction, objectGap, controller 등의 메타 용어를 노출하지 않는다.

- 정상2형식 + 실제 시제 + to부정사 + 실제 too/enough 콤보를 기존 계수로 적용한다.
- 주어 NP를 참조했다고 기본 카드점수를 두 번 주거나 내부 give가4형식이라고 바깥 주절을4형식으로 바꾸지 않는다.
- `A room was too hard to show.`의 past는 was에서, to부정사는 to show에서 나온다. 비정형show는 독립 finite/time 근거가 아니다.
- 보스에서 too가 실제 빙정 WORD라면 정상 기여로 빙결핵1개 파괴가 가능해야 한다. 같은 문장을 WORD판정에서 통과시켰는데 소비/보스 단계에서 다시 거절하지 않는다.
- 사전에는 필요한 경우 `앞의 명사가 뒤의 to부정사의 대상이 될 수 있습니다.` 한 줄 정도만 추가한다. 새 장문의 교과서 설명/번역은 넣지 않는다.

## 7.4 오류 복구의 경계

없는 주어·유한 동사·목적어·전치사를 자동 생성하지 않는다. `A room too hard to show.`, `A room was too hard to.`, `The book is too hard read.` 등은 완전한 구조로 성공 처리하지 않는다. 반면 의미만 이상한 완전한 구문은 점수0으로 만들지 않는다.

# 8. 문법 B — 본동사 문형과 동사구 정확성 분리

## 8.1 기준

`I give you a book.`, `I am giving you a book.`, `I have given you a book.`, `I will give you a book.`는 모두 본동사give가 두 목적어를 가진4형식으로 분석되어야 한다. 진행/완료와 1~5형식은 배타적인 분류가 아니다.

지원하는 시제의 문장이 조동사be/have의 문형으로 잘못 내려가서는 안 된다. 문법이 잠겨 있어도 구조 자체는 판정하고 콤보 자격만 별도로 검사한다.

## 8.2 허용 부사의 중간 삽입

기존 등록 부사에 `auxiliaryPositions` 같은 검수 정책을 붙여 정상 위치를 읽는다. 첫 구현의 필수 경로는 often/always/usually/sometimes의 빈도, really 및 검수된 manner 부사다. **already 등 미등록 단어를 예문 때문에 새로 추가하지 않는다.**

필수:
- `A person is often giving you a beautiful environment with small problems.`
- `I have often given her a book.`
- `I will often give her a book.`
- `I will often have given her a book.`
- `They are usually reading books.`

조동사 첫 위치 뒤 부사 삽입은 일반적인 영어 부사 위치에 해당한다(G3). 구현은 단어별 위치 정책에 한정하고 아무 토큰이나 건너뛰지 않는다.

구현 주의:
- 기존 `i+1`만 다음 동사로 보는 연속체 탐색을, 허용된 ADVERB span을 통과하는 제한된 탐색으로 확장한다.
- `finiteIndex`, `lexicalIndex`, `verbCardIds`, `interveningAdverbCardIds`를 분리한다. 동사구 전체 span에 포함됐다고 often에 FINITE_VERB 역할을 주지 않는다.
- 기존 WILL → PERFECT HAVE → PROGRESSIVE BE → lexical verb의 순서와 verb 개수 한도를 보존한다. 허용 부사가 끼었다고 동사 수 제한을 토큰4개로 오인하지 않는다.
- 부사 카드 기본 점수/수식+5가 중복되지 않게 실제 modifier ID당 한 번만 적용한다.
- middle adverb가 있다고 두 목적어의 위치나 NP 연결이 흐트러지지 않아야 한다.

## 8.3 복구 가능 오류

| 입력 | 목표 |
|---|---|
| I am often giving you a book. | VALID, 주절 4형식, 정상진행 |
| I be often giving you a book. | VALID_WITH_ISSUES, BE_FORM_REQUIRED, **4형식 유지**, 해당 진행콤보 없음 |
| I have give you a book. | 허용된 VP 형태 복구로 VALID_WITH_ISSUES, 형태오류, 4형식 유지, 해당 완료콤보 없음 |
| I giving you a book. | 핵심 유한동사 없음. 자동 am 삽입 금지 |
| Giving you a book. | 독립 완전문장으로 만들지 않음 |
| I give a book to you. | 정상3형식+PP. 두 명사 발견만으로4형식으로 바꾸지 않음 |

기존 감점수치를 사용하고 오류를 없앤다거나 카드표면을 몰래 바꾸지 않는다. **형태오류가 있는 제출은 완전문장 +30 없음**. 동일 원인 중복감점 금지. 다른 절의 정상 문법까지 전부 박탈하지 않는다.

형태상 깨진 VP에는 정상 시제/상 콤보 및 골렘 시제 근거를 만들지 않는다. 별도 절의 올바른 VP는 유지한다. `was`처럼 유한시제는 올바르되 다른 부가표현에 오류가 있는 경우까지 무조건 시간 evidence를 지우지 않는다.

## 8.4 보스 장막

Stage2 장막은 **원본 분석의 실제 주절 4형식 구조 근거**로 해제한다. 작은 활용오류로 status가VALID_WITH_ISSUES여도 주어·본동사·IO·DO가 실제로 식별되면 해제한다.

- 점수용 eligibleAnalysis 때문에 형태 분류가 사라지는 일이 없도록 원본 구조 근거를 사용한다.
- 문형콤보는 기존 pack.svoo 자격을 따른다. 장막 조건과 점수 해금을 혼동하지 않는다.
- 문장 뒤에 give/NP 두 개가 어딘가 있다는 문자열 검색으로 해제하지 않는다. 주절이 아닌 종속절4형식은 이번 규칙에서 주절 4형식을 대신하지 않는다.
- 문지기·골렘·사슴의 원래 조건을 느슨하게 만드는 수정은 하지 않는다.

## 8.5 반드시 보존할 철학

모든 실제 제출은 기존 자원 규칙대로 처리한다. INVALID_CORE도 카드/턴을 소비하고0점 피드백을 준다. 기술오류·검증실패·중복 명령은 무소모. UNSUPPORTED라는 문자열만 보고 가짜정답으로 바꾸지 말고 필요한 구조의 실제 분석 경로를 구현한다. 대표분석은 점수가 높은 후보가 아니라 고정된 교육용 우선순위로 정규화한다.

# 10. 빙정/운영 카드 외형과 지역 색상

## 10.1 빙정은 전체 바탕으로 구분

기존 일반 WORD와 똑같은 바탕에 테두리만 다른 방식에서 벗어난다.

권장 출발 토큰:

```text
--frost-bg: #D9EEF6
--frost-bg-edge: #CAE3EE
--frost-text: #163746
--frost-muted: #315A6A
--frost-border: #497C91
```

- 실제 card body와 footer까지 푸른 바탕이 이어진다. 빈 주변 배경만 파랗게 칠하지 않는다.
- 단어·뜻/효과·숫자·품사 strip·형태버튼·체크의 대비를 지킨다.
- 선택 상태에서 전체 노란바탕으로 덮어 빙정 정체성이 사라지지 않게 outline/check로 선택을 표시한다.
- 빙정 WORD는 품사 표시 유지, 빙정 OPERATION은 품사 띠 대신 운영 표식/사용버튼 유지.
- 판정 후 강조·봉인·선택·hover·disabled·효과 감소에서도 유형과 수명 표식이 식별돼야 한다.
- HAND/조합대/DRAW/DISCARD/사용 완료/직접탐색 목록/읽기전용모달/연출복제의 동일 사본 모두 적용한다.

## 10.2 운영 카드 최소 폴리싱

새 이미지 자산은 만들지 않는다. 기존 카드 크기·조작부 위치를 지키며 다음 위계를 정리한다.

```text
운영 · 고급                         +1
명사 탐색
명사·대명사 최대3장
전투당 1회
[사용]                            [선택]
```

- `보급+1`: `2장 뽑기` + `사용 후 버린 더미 · 다시 뽑아 재사용`.
- `탐색+1`: `단어1장 선택` + 같은 순환 표식.
- 임시 탐색: `빙정 탐색` + `이번 전투 한정` + `단어1장 선택`.
- 긴명칭은 두 줄 내에서 자연스러운 줄바꿈을 허용한다. 너무 작은 폰트로만 맞추지 않는다.
- 유형은 색뿐 아니라 이름/텍스트/아이콘으로도 구분한다.
- 공격점수 배지 또는 +5점 연마 표식을 운영에 붙이지 않는다.
- 사용하는 운영이 EXHAUSTED로 갔는지 DISCARD로 갔는지 짧은 피드백으로 구별한다. 실제 상태 이동은 controller에서이미 완료.

## 10.3 Stage1~6 어두운 지역 테마

사막의 현재 CSS를 기준 스크린샷/색상 토큰으로 보존하고 다른 지역에 같은 설계방식의 낮은채도 그라데이션을 적용한다. 밝은 흰설원/파란화면으로 전체를 뒤덮지 않는다.

| 지역 | 저채도 base 출발점 | 은은한 accent | 연출 이미지 |
|---|---|---|---|
| 시작의 초원 | #14231F → #1D3027 | 짙은 녹색/약한 햇빛 금색 | 어두운 초록 안개 |

색은 구현 초깃값이다. 사막은 새로운 표의 근사색으로 교체하지 말고 기존 gradient/별점/패널색을 보존한다.

- 가능한 테마 token과 stage theme attribute/class를 사용해 분산된 override를 정리하되 전체 UI 리팩터링은 하지 않는다.
- 지역 소개/상점(해당지역)/전투/지역완료의 배경색이 일관되게 연결되게 한다.
- 로비나 다른 지역으로 돌아가면 이전 body theme가 남지 않는다. 저장 복원 시에도 해당 지역만 적용.
- 향후 배경이미지 layer 아래 base gradient, 그 위 readability scrim/실제패널을 둘 수 있게 준비한다. 이번에 이미지 fetch나 placeholder실패요청은 넣지 않는다.
- 패널/카드/텍스트에 화면 전체 opacity/filter/brightness를 걸지 않는다.
- 배경레이어 pointer-events:none, 입력 hitbox/드래그/스크롤 방해 없음.
- 무거운 CSS blur·연속 full-screen 애니메이션·매프레임 layout 읽기를 추가하지 않는다. 배경은 정적 그라데이션이면 충분하다.

## 10.4 가독성 검증

작은 본문/버튼 텍스트는 실제 바탕과 최소4.5:1, 큰 글자는3:1, 핵심 UI경계/상태는3:1을 기준으로 한다(W3C G4). 그라데이션은 가장 대비가 낮은 영역과 실제 합성배경을 검사한다. 색상 토큰이 통과했다고 최종브라우저가 자동 통과한 것으로 보고하지 않는다.

기존 효과 감소는 핵심 공격피드백을 지우지 않아야 한다. OS reduce/음소거는 기존 사용자설정을 존중한다. 새로운 운영/빙정/배경 때문에 과거 사라졌던 타격감 문제가 재발하지 않게 중간프레임 회귀를 유지한다.

# 11. 영구 소유·드로우 순서·기술 오류 정책

## 11.1 영구 덱 크기

영구 덱 변경은 명시적으로 선택/구매/연마/제거/입장지급한 결과로만 일어난다. 연마와 사용/재사용은 activeCardIds 길이를 바꾸지 않는다.

- 운영 사용으로 단어를 복사하는 것이 아니라 pile 간 같은ID를 이동시킨다.
- 임시 탐색은 영구 소유0. 전투 종료 후 모든 임시객체 제거.
- 명사/대명사 비중이 부족하다고 보상/드로우 순서를 몰래 바꾸지 않는다.
- 품사 탐색은 실제 유효대상 없으면 실패한다. 가짜 명사/동사 생성 금지.

## 11.2 기술 오류와 재시도

- 효과0·잘못된 대상·불일치revision·중복 명령은 no-op.
- 후보 목록 조회/설명/연마preview/상점보기/취소는 RNG중립.
- 정상 source 재사용은 새ID의 명령이며 과거 사용사실만으로 막지 않는다.
- 연출 실패/abort/탭숨김은 확정 상태를 표시 완료하고 입력잠금을 해제하되 효과를 재실행하지 않는다.
- 저장된 OPERATION_PRESENTING은 기존 안전저장 정책상 허용하지 않는다. 로드할 수 없는 중간상태를 몰래 EDIT로 수리하지 않는다.
- 정상 안전지점에서 reload하면 source위치·반복사용이력·빙결핵·연마·RNG·선택 완료 여부가 정확히 유지된다.

# 14. 구현 단계와 검증 전략

## 14.1 구현 순서

1. 최신 origin/main 동기화, 별도 브랜치 생성, 미커밋 변경 보존, 기준 SHA와 환경 기록.
2. 변경 전 `npm test`, `validate:data`, `build` 실행. 현재 언어·룬·상점·저장 golden과 사막 CSS 캡처 보존.
3. 사용자 두 문장과 현재 운영 연마·재사용 제약을 **실행으로 재현**하고 baseline 결과 기록.
4. 좁은 0.6.1 정책/view, 운영 7종 정의와 카드별 연마 상한 구현.
5. 운영 정산, 반복 source history, 저장, 카드 보존식과 단위 경계 검사 구현.
6. 상점 보장, 보상 후보, 연마 UI, Stage 4 선택과 저장 연결.
7. 사슴 빙정 탐색, 기존 빙정 카드와의 구분, cleanup과 표시 연결.
8. Grammar의 gap과 중간 부사, main frame과 오류 분리. 양성·음성·보스 연계 테스트.
9. 운석 수치, 지역 테마, 빙정 배경, 운영 UI와 기존 폴리싱 회귀 검사.
10. 관련 검사 → 전체 회귀 → production 실제 원정 → 보고서와 PR.

서로 독립된 작업은 병렬화할 수 있다. 다만 같은 파일의 동시 수정이나 테스트 도중 HMR reload로 결과를 오염시키지 않는다. 실패 원인, 수정 내용, 명세 변경에 따른 기대값 변경을 구분해서 기록한다.

## 14.2 필수 QA 범주

**단위·Controller:** 모든 효과의 +0/+1, 대상 0장/부분/충분한 경우, 가득 찬 손패, 정상 재사용과 중복 명령의 차이, 새·옛 저장, 정확한 grammar evidence, 운석 경계, 선택과 상품의 일회성을 확인한다.

**지정 상태 실제 UI:** 통제된 카드로 운영 7종 사용·연마·순환, 임시 빙정 탐색, gap 문장과 4형식 부사 문장의 형태 선택 → 제출 → 콤보 → 피해 → 기믹을 확인한다. 자료 이름에 `ASSIGNED`를 명시한다. 카드나 HP를 할당했다면 자연 원정이라고 부르지 않는다.

**Production UI 실제 카드 경로:** 실제 dist에서 새 원정 → 보상·상점·운영·빙정 → 27전투 완료를 최소 한 번 시도하고 모든 실행 결과를 남긴다. 성공했다면 실제 획득 카드로 운영 구매·연마·재사용, Stage 4 선택, 사슴 임시 탐색·결정 파괴·저장 복원이 포함된 대표 경로를 제시한다. 한 seed에 운영 7종을 모두 억지로 넣지 않는다. 부족한 개별 효과는 별도 지정 상태 UI 검사로 구분한다.

**0.6에서 남은 교육 경로 QA:** 6-1 비교급, 6-2 최상급, 6-3 as~as를 해당 전투의 실제 손패로 사용하는 코스는 별도 결과 칸으로 유지한다. 기존 27전투 완주나 지정 상태 검사로 이 코스까지 PASS라 하지 않는다. 실행하지 않으면 NOT RUN이다. 새 운영 학습 경로를 검증하며 함께 시험할 수 있지만, 없는 카드를 주입해 성공시키지 않는다. 이 공백을 기존 파서 오류의 증거로 과장하지 않는다.

**자동 원정 80회:** 과거 80회 실패 분석의 전면 재실행은 이번 명세의 필수 작업이 아니다. 새 수명·반복 사용에 대한 유한 행동 stress 검사는 수행한다. 자동 정책이 재사용 운영만 반복한다면 `QA_POLICY_NO_PROGRESS`로 분류하고 게임 오류나 사람의 패배율로 치환하지 않는다. 이를 막기 위해 게임 자체의 운영 사용 횟수를 제한하지 않는다.

## 14.3 필수 명령과 환경

```text

npm run test:browser
npm run test:browser:polish
```

현재 스크립트, Windows의 npm.cmd, OS 경로에 맞춰 실행한다. 새 집중 검사는 예컨대 `test:browser:061`, `test:ops:061`, `test:grammar:061`로 추가하되, 기존 명령을 의미 없게 교체하지 않는다. 이 패치를 이유로 dependencies·Node·Playwright를 무단 업그레이드하지 않는다.

- 페이지·콘솔·실패 리소스 오류를 기록하고 외부 runtime 요청이 없는지 확인한다.
